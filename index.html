Show HN: SQL-tString a t-string SQL builder in Python

作者: pgjones | 评分: 24 | 评论数: 6 | 发布时间: 2025-05-16 12:48
文章摘要

SQL-tString 是一个用于构建 SQL 查询的 Python 库，类似于 f-string，但能防止 SQL 注入。它通过 `t-strings` 来插入变量，并将这些变量转换为 SQL 占位符，同时支持预定义的表和列名。使用 `sql_context` 可以限制允许的列和表名，防止注入攻击。如果变量设为 `Absent`，库会自动移除相关参数，适用于可选更新或条件语句。此外，还支持 `IsNull` 和 `IsNotNull` 来处理 SQL 中的 `NULL` 条件。默认使用 `qmark` 参数样式，但也支持其他如 `asyncpg` 样式。对于 Python 3.12 和 3.13，可通过 `locals()` 使用该库。该项目基于 MIT 许可证，目前有 43 个星标。

评论摘要
主要讨论点：SQL解析库的设计与实现，包括词法分析、语法解析、参数化查询、t-strings的使用及其设计争议。 不同观点： • **schultzer** 认为手写解析器很好，但建议基于BNF语法构建词法分析器和解析器，并进行一致性测试。他提供了自己项目中的实现作为参考，并认为t-strings的设计不如他项目中的方案优雅。 • **sirfz** 指出该解析器强制执行参数化查询，返回特定数据库方言中的参数化查询语句和参数列表。他认为这有助于为不同的SQL数据库客户端创建统一的接口，避免记忆不同客户端的参数格式。不过，他也提到某些数据库客户端可以直接通过t-strings执行查询，无需额外传递参数。 • **jitl** 关心SQL解析器如何处理查询重写（如移除表达式），并对使用t-strings简化SQL查询表示赞赏，认为这使得SQL更加直观和可控。他询问是否支持将SQL模板嵌入另一个SQL模板中进行组合，并提到自己在TypeScript中经常使用类似的功能。 • **90s_dev** 对t-strings使用词法作用域进行占位符查找的设计提出批评，认为这种设计不好，应该明确通过字典传递参数。他对这种设计选择表示不解。 补充讨论： • t-strings的设计和使用是讨论中的一个争议点，部分开发者（如schultzer和90s_dev）对其设计持保留或批评态度，而其他人（如jitl）则认为其简化了SQL查询的书写和理解。 • 关于SQL解析的具体实现，schultzer和jitl都提到了复杂SQL查询和重写的处理问题，显示出对解析器处理能力的关注。 • sirfz提到了参数化查询的统一接口问题，强调了不同数据库客户端间参数格式的差异，显示出对跨平台兼容性的关注。

The average workday increased during the pandemic’s early weeks (2020)

作者: robtherobber | 评分: 93 | 评论数: 12 | 发布时间: 2025-05-16 09:43
文章摘要

一项由哈佛商学院Raffaella Sadun和Jeffrey Polzer等人进行的研究分析了300万人的工作模式，发现疫情期间远程办公导致工作日平均延长8.2%（约48.5分钟），员工参加的会议数量增加13%，但每次会议时间缩短20%。邮件数量也增加了5.2%，且有更多邮件在工作时间外发送。研究显示，远程工作模糊了生活与工作的界限，导致工作时间更长、更碎片化，员工感到疲惫。尽管会议时间缩短，视频会议的持续专注要求也让员工感到压力。研究还指出，较大的居家空间可能提升远程办公体验，而狭小空间则可能带来不便。总体而言，远程工作对员工的效率和情绪产生了复杂影响。

评论摘要
主要讨论点：远程工作与工作时长、生产力之间的关系，以及疫情对工作方式的影响 不同观点： • bachmeier认为，疫情期间虽然工作时长增加，但增加的工作内容（如处理邮件、学习技术、行政事务）是没有价值的，这让他做真正有意义的工作的时间减少了。 • PaulRobinson指出，人们的有效工作时间大约只有4-5小时，如果工作日延长，说明生产力在下降。他建议通过A/B测试来验证这一观点，并提到自己经历过的团队通过减少工时提高了生产力。 • Koshima认为，远程工作虽然节省了通勤时间，但工作时间变长了，这种转变的真正代价仍在显现，可能是由于日历的过度使用或管理者对员工状态的担忧。 • blitzar批评会议文化的失控，认为虽然工作时间延长，但很多会议是浪费时间，实际工作产出减少。 • tmckd提出，远程工作让一些人利用节省下来的通勤时间工作，从而提高了幸福感，尽管这只是个人观察，但这种模式在他认识的人中很普遍。 • kleiba引用研究数据，说明疫情初期工作日平均增加了48.5分钟，并提到欧盟有法律防止员工过度加班。 • davio分享了一个案例，某大公司通过咨询公司的评估，限制下午的会议时间，并将会议时间作为经理绩效考核指标。 • SirMaster认为自己的工作时间和会议数量没有明显变化，一直保持在每周2-3次会议的水平。 • bix6希望看到更长期的数据，以了解人们是否在适应后减少了工作时间。 • sublinear强调应关注工作产出而非工作时长，认为应通过质量而非时间来评估员工表现。他还指出，远程工作和文本/录音沟通的增加提高了生产力。 • bluedino质疑，平均工作时长的增加是否考虑了那些在工作时间做其他事情（如遛狗、看孩子）的人。 补充讨论： • 讨论中涉及的争议焦点在于远程工作是否真的提高了生产力，以及工作日延长是否意味着更高的效率。一些人认为延长工作时间导致更多无意义的任务和会议，而另一些人则认为远程工作节省了通勤时间，提高了生活质量和工作满意度。 • 会议文化的有效性和如何评估员工表现也是讨论的重要方面，有人建议通过限制会议时间和关注工作产出来提高效率。 • 此外，个人经历和观察（如tmckd和bluedino的评论）在讨论中也起到了一定作用，显示出远程工作影响的个体差异。
