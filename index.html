What are OKLCH colors?

作者: tontonius | 评分: 336 | 评论数: 27 | 发布时间: 2025-08-25 06:32
文章摘要

文章介绍了OKLCH这种新型色彩模型，它具有感知均匀性，能更准确地反映人眼对色彩的感知。OKLCH基于三个参数：明度（Lightness）、色度（Chroma）和色调（Hue）。相比传统色彩模型（如RGB、HSL），OKLCH能创建更均匀的色彩调色板，生成更准确的渐变，并支持更广的色域（如Display-P3）。此外，OKLCH在改变明度时能保持色调一致，避免了其他模型中常见的色彩偏移问题。虽然OKLCH支持定义超出实际显示设备色域的颜色，但使用时需注意色度最大值以避免色彩失真。目前OKLCH已得到现代浏览器的广泛支持。

评论摘要
主要讨论点：[OKLCH颜色模型的优缺点及其在CSS中的应用] 不同观点： • **支持OKLCH的观点** - OKLCH基于感知均匀的颜色空间（OKLab），能够提供更一致的色彩渐变（如`linear-gradient(in oklch, #f0f, #0f0)`）。 - 通过调整色相角度（Hue）和色度（Chroma），可以更直观地控制颜色（如`oklch(from var(--accent) calc(l + .1) c h)`）。 - 工具如oklch.com和开发者文档（MDN）提供了实用支持。 • **反对或质疑OKLCH的观点** - OKLCH在色相插值时可能产生超出sRGB范围的颜色，导致感知不一致（如红色部分变暗）。 - 色度（Chroma）的调整不够直观，可能引发意外结果（如绿色偏移明显）。 - 实际应用中，Oklab可能是更安全的默认选择（Tailwind v4最终改用Oklab）。 • **其他替代方案** - **Oklab**：直接线性插值（通过灰色），避免色相环绕问题。 - **XYZ颜色空间**：更适合模拟光线混合效果。 - **Munsell颜色空间**：通过用户测试定义感知均匀性，但未明确比较与OKLCH的差异。 补充讨论： - **争议焦点**： - OKLCH的“感知均匀性”是否被过度夸大（如渐变中的色彩失真）。 - 色度（Chroma）和色相（Hue）的调整是否真比HSL更直观。 - **工具与资源**： - 推荐工具：oklch.com、Evil Martians的文章和转换器。 - 需注意浏览器/OS层级的色彩转换可能影响显示效果（如Display-P3与sRGB差异）。 - **实用建议**： - 设计时需兼顾对比度和可读性（如使用APCA对比度工具）。 - 未来可能推出更友好的OKHSL/OKHSV模型，简化用户操作。

An Illustrated Guide to OAuth

文章摘要

这篇文章通过YNAB连接Chase银行的例子，简明介绍了OAuth授权协议的运行机制。OAuth诞生于2007年，旨在解决第三方应用安全访问用户数据的问题，避免了直接分享密码的风险。核心流程分两部分：1)用户授权流程：用户被重定向到银行登录，选择授权范围后生成授权码；2)令牌交换流程：应用通过安全后端请求用授权码换取访问令牌。关键创新点在于使用授权码间接获取访问令牌，避免了令牌直接暴露在URL中的安全隐患，确保了数据传输的安全性。整个过程实现了第三方应用无需知道用户密码就能获得特定权限的访问令牌。

评论摘要
主要讨论点：[OAuth 和 OIDC 的实现难度、安全性、类比和补充建议] 不同观点： • [实现难度] - gethly 认为 OAuth 和 OIDC 的概念虽然简单，但实际实现时缺乏具体的代码指导，最终只能依赖规范文档和 AI 工具（如 Grok）来填补信息空白。 - tiffanyh 提到 OAuth 和 Open Banking 的类比，认为两者本质相似，但未明确说明为何它们是不同的技术。 • [安全性争议] - TofuLover 对前端和后端通道的解释提出异议，认为 GET 和 POST 请求在 HTTPS 下都是加密的，前端和后端通道更多与信任边界和信息的公开性相关。 - fcpguru 补充了 OAuth 1.0 的历史漏洞（如会话固定/令牌劫持攻击），强调安全性问题的重要性。 • [补充建议] - politelemon 认为文章写得很好，但建议增加 PKCE（Proof Key for Code Exchange）的内容，因为它是当前广泛推荐的安全机制。 - languagehacker 和 ttb-2134 对文章的易懂性和类比（如啤酒园类比）表示赞赏，认为这是理解 OAuth 的良好入门材料。 补充讨论： - 争议焦点：前端/后端通道的定义（TofuLover 与其他可能存在的默认观点）。 - 历史背景：fcpguru 提到的 OAuth 1.0 漏洞事件（2008 年 Yammer 工程师的案例）为讨论增添了实践层面的警示。 - 类比争议：tiffanyh 提出的 OAuth 与 Open Banking 的相似性是否成立，可能需要进一步澄清技术差异。
