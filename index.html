Nx compromised: malware uses Claude code CLI to explore the filesystem

文章摘要

一篇关于NX构建工具被恶意软件入侵的安全警报。攻击者通过NX的安装后钩子执行恶意代码，窃取用户钱包、API密钥等敏感信息，并将其上传到GitHub上一个名为"s1ngularity-repository"的公共仓库。受影响的NX版本为21.5.0-21.8.0和20.6.0-20.12.0，这些版本已被npm下架。该恶意软件会检查系统是否安装Claude或Gemini CLI工具，并通过提示词来搜索敏感文件。建议用户检查GitHub账户、更新NX版本、删除可疑仓库并轮换所有可能泄露的密钥。

Object-oriented design patterns in C and kernel development

文章摘要

这篇文章主要介绍了在操作系统开发中如何利用C语言通过函数指针实现面向对象设计模式。作者受到Linux内核启发，使用包含函数指针的结构体（vtable）来实现多态性，使不同设备或服务能共享统一接口但执行不同功能。文章举例说明了在设备驱动、内核服务和调度器中应用这种模式的优势，包括运行时动态替换实现、模块化扩展等，同时也提到这种设计可能带来的调试复杂性和性能开销问题。

评论摘要
主要讨论点：[在C语言中实现面向对象编程的技术及其优缺点] 不同观点： • 第一种观点：支持显式传递对象指针（如C语言中的this指针） - 认为显式传递更清晰，可以明确区分实例变量和全局变量 - 反对C++中的隐式this传递方式 • 第二种观点：讨论Linux内核使用函数指针实现多态 - 指出这种技术实际上早于面向对象编程，被称为"抽象数据类型" - 比较了抽象数据类型与OOP的区别：前者允许未实现的函数，后者要求全部实现 - 建议在OOP中通过多重继承实现可选函数功能 • 第三种观点：区分接口与完整OOP - 认为使用函数指针(vtables)只是实现了接口 - 指出完整OOP特性(如类、继承)会带来更多复杂性 - 暗示接口实现已经足够，完整OOP可能不值得 补充讨论： • 争议焦点：显式vs隐式对象传递哪个更好 • 实际应用案例：有人提到tmux项目中使用这种模式 • 有用户分享了自己研究tmux代码中这种模式的笔记

Slowing down programs is surprisingly useful

文章摘要

这篇文章探讨了"减慢程序运行速度"的实际用途，主要包括三个应用场景：1) 检测竞态条件；2) 模拟优化效果；3) 评估分析工具的准确性。作者通过实验发现，在x86架构的处理器中，可以通过插入nop或mov regX, regX等无效指令来精确控制基本块的执行速度。这种方法比现有技术更精细，能够帮助开发人员更好地调试并发问题、预测优化效果以及验证分析工具的准确性。实验基于Intel Core i5-10600处理器进行，但指出不同微架构可能需要不同的处理方式。

评论摘要
主要讨论点：[通过减速模拟来评估优化效果的方法及其实现技术] 不同观点： • [avidiax] 支持通过减速其他程序部分来模拟优化效果的方法，认为这可以避免优化无效的函数。但对其在I/O操作中的适用性表示不确定，担心是否能准确模拟带宽或延迟的变化。 • [adrian_b] 反对使用NOP和MOV指令来减速，认为这些指令在现代CPU中被特殊优化，几乎不会消耗时间。建议使用更慢的指令如整数除法或RORX、BSWAP等来确保减速效果。 • [weinzierl] 从历史角度提供了类似减速工具的实例，如C64 Snail和PC的Turbo按钮，说明减速技术的实际应用已有先例。 • [initramfs] 补充了减速技术的另一个应用场景，即通过降低处理器速度来实现低功耗运行。 • [plandis] 将减速模拟方法扩展到复杂业务流程中，认为因果分析（causal profiling）可以帮助在大型工作流中评估优化效果，减少团队间的协调成本。 补充讨论： • [gwd] 对NOP指令减速的效果提出疑问，认为NOP在流水线中可能被优化掉，质疑其是否能有效减速。这一争议焦点在于不同CPU架构对NOP指令的处理方式是否一致。
