LLM function calls don't scale; code orchestration is simpler, more effective

作者: jngiam1 | 评分: 23 | 评论数: 2 | 发布时间: 2025-05-21 17:18
文章摘要

文章主要讨论了大型语言模型（LLM）在处理工具调用时的局限性，特别是当数据量较大时，将工具调用结果直接返回给LLM进行解析和处理既昂贵又低效。文章提出了一种替代方法，即通过代码编排来处理结构化数据，而不是依赖LLM解释大量JSON数据。通过使用代码执行来进行数据处理，可以避免LLM生成重复输出、提高效率并确保数据完整性。文章还提到，MCP服务器已经引入输出 schema，这将有助于更好地解析和操作数据。未来，结合代码执行的环境需要解决安全性问题，以确保用户和AI生成代码的可靠执行。

评论摘要
主要讨论点：AI任务执行环境中的状态管理和错误处理挑战 不同观点： • avereveard认为Hugging Face的smolagent在有效时表现良好，但当出现失败操作时，会增加回滚的难度。虽然理论上可以将整个执行块包装成分布式事务，但LLM（大型语言模型）生成的代码通常追求健壮性，这与分布式事务的模式相冲突，因为这种模式会让错误处理和失败原因变得难以理解。 • abelanger指出，大多数执行环境是有状态的（例如依赖于为每个用户会话运行的Jupyter内核），这在需要用户能够在多天后返回AI任务会话时，管理成本高且困难。abelanger强调无状态但持久化的执行环境对于长时间运行的任务至关重要。他还提到，许多AI初创公司正在艰难学习事件溯源和持久执行的价值，但这些模式在项目初期并不常见，并将此归咎于AI框架的问题。 补充讨论： • avereveard关注的是LLM生成代码的健壮性与事务回滚之间的矛盾，认为健壮的代码不易理解失败原因，这与事务处理的模式存在冲突。 • abelanger则从架构设计的角度出发，讨论了有状态和无状态执行环境的优劣，特别是对长时间运行任务的支持，并指出AI领域正在从传统大型科技公司的架构模式中汲取经验。 争议焦点：AI任务执行环境应该是无状态且持久化的，还是可以通过分布式事务处理失败回滚，这在实际应用中如何权衡。

文章摘要

Mistral AI推出了Devstral，这是一款专为软件工程任务设计的代理大型语言模型（LLM）。Devstral在解决现实世界软件工程问题方面表现优异，超越了所有开源模型，并在SWE-Bench Verified基准测试中获得了46.8%的成绩，比之前的最先进模型高出6%以上。它可以在本地部署，适合企业隐私敏感的代码库使用，并能通过API或平台如HuggingFace等获取。Devstral在单个RTX 4090或Mac with 32GB RAM上即可运行，非常适合本地和设备上使用。模型以Apache 2.0许可证发布，免费供社区使用，并支持定制和自主软件开发加速。未来几周将推出更大型的代理编码模型。

评论摘要
主要讨论点：围绕一个新模型（Devstral）的特性、运行要求、许可证、以及与其它模型的比较，用户展开了多方面的讨论。 不同观点： • [simonw] 认为模型的文件大小（14GB）可以作为运行时所需内存的近似参考，并提到在M2 Mac上运行时，额外需要约10%的内存。同时，他认为20GB以下的模型不会对其他应用程序造成太大影响，并对该模型表示期待。 • [solomatov] 对模型的许可证（Apache 2.0）表示赞赏，认为这是一个易于理解且条件较少的许可证，相比一些有诸多限制的“开放权重”许可证更为友好。 • [ManlyBread] 认为即使该模型能够在单张RTX 4090或32GB RAM的Mac上运行，但RTX 4090显卡的高价格（3000美元）使得这一要求仍然过高，暗示硬件成本可能是一个障碍。 • [ics] 提出希望找到适合在低性能机器（如MacBook Air）上运行的最新模型，并询问是否有工具或资源可以帮助判断给定机器配置下哪些模型是可行的。同时，提到希望找到一个在多任务下表现稳定的全能模型。 • [bravura] 对该模型与托管的LLM（如Claude 3.7）的性能比较表示关注，暗示用户可能在选择本地部署模型与托管模型之间进行权衡。 • [ddtaylor] 提到在使用LLamaIndex和尝试不同的模型时发现了这个新模型，但在让其代理系统使用该模型时遇到了问题，即模型无法使用指定的工具，尽管其他模型能够正常使用这些工具。 • [gyudin] 对模型的基准测试表示质疑，认为其结果有些奇怪。 • [abrowne2] 对该模型能够在4090或32GB RAM的Mac上运行表示好奇，并有意进一步探索。 • [AnhTho_FR] 对该模型的性能表示印象深刻，持积极态度。 补充讨论： • 讨论中涉及了模型运行所需的硬件条件和成本问题，尤其是高性能显卡（如RTX 4090）的高价格引起了关注。 • 许可证问题也被提及，反映出用户对开放性和使用限制的重视。 • 对模型性能的比较和在不同机器上的可行性也是讨论的一个重要方面，特别是对于那些希望在本地部署模型的用户。 • 一些用户遇到了技术上的困难，如[ddtaylor]在让模型使用工具时遇到的问题，这可能需要进一步的技术支持或文档参考。
