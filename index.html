Fun with uv and PEP 723

作者: deepakjois | 评分: 306 | 评论数: 30 | 发布时间: 2025-06-24 18:41
文章摘要

文章介绍了使用 **uv** 和 **PEP 723** 元数据简化 Python 脚本运行的新方法。 **uv** 是一个用 Rust 编写的高速 Python 包和项目管理工具，带有 **uvx** 命令，可自动处理虚拟环境、Python 版本和依赖包。 **PEP 723** 提出了一种在单文件脚本中嵌入元数据的方法，帮助启动器和 IDE 识别所需的 Python 版本和依赖。 结合 **uv** 和 **PEP 723**，可以轻松运行包含依赖的 Python 脚本，例如提取 YouTube 视频字幕的脚本。通过在脚本中加入 shebang 行 `#!/usr/bin/env -S uv run --script`，脚本可直接作为可执行文件运行，无需手动配置环境。这使得 Python 在处理一次性脚本时更加便捷和高效。

评论摘要

Subsecond: A runtime hotpatching engine for Rust hot-reloading

作者: varbhat | 评分: 82 | 评论数: 5 | 发布时间: 2025-06-24 18:58
文章摘要

Subsecond是一个用于Rust应用程序的热补丁库，允许在不重启应用的情况下更改运行中的代码，特别适用于游戏引擎和服务器等长时间运行的应用。它通过跳转表实现函数调用重定向，不修改进程内存，确保安全性。使用时需配合第三方工具如Dioxus CLI，通过`dx serve`命令启用热重载。当前版本仅支持对主crate的补丁，不支持跨工作区和结构体热重载，且对全局变量、静态变量和线程局部变量的处理存在限制。未来计划增加完整工作区支持并改进线程局部变量的处理。在调试模式下使用不会影响性能，适合开发阶段应用。

主要讨论点：Rust热补丁工具（Subsecond）的实现、优点、局限性及与其他解决方案的比较 不同观点： • [jkelleyrtp] 作为工具的创建者，强调了Subsecond的独特功能，包括手动驱动`rustc`编译、比较汇编代码的差异逻辑、以及处理传统动态库重载无法解决的问题（如TLS、静态变量、构造函数等）。他还展示了该工具在不同平台（macOS、Windows、Linux、iOS、Android、WASM）和不同项目（如Bevy、iOS应用、Axum后端等）上的应用。创建者还提到目前工具仍在开发中，更多细节即将发布。 • [mmastrac] 对该工具表示兴趣，并提到在他的Rust服务器工作中可能会尝试使用，尤其是在处理编辑-编译-运行周期较慢的项目时。他认为选择合适的代码切换点可能不难，但指出工具目前只允许对主crate进行热补丁，这虽然不理想，但便利性可能弥补了代码结构上的调整需求。 • [modeless] 指出文档中提到的限制，即需要提前将可能需要更改的代码用特殊包装函数包裹，这使得该工具相比其他语言的解决方案（无需特殊注解）吸引力降低。 • [weinzierl] 对工具表示赞赏，并提到在大型Java应用中的经验让他意识到热补丁的实用性。但他同样关注到每个需要热补丁的函数都需要在源代码中修改调用方式的限制，尽管这种修改对发布版本没有影响，但仍是一个需要考虑的重要因素。 • [prideout] 对工具表示认可，但个人更倾向于使用dylib来实现代码的重载功能，显示出对传统动态库重载方式的偏好。 补充讨论： • 工具的独特卖点在于解决了传统动态库重载无法处理的一些复杂问题，如TLS和静态变量。 • 主要争议点在于需要对代码进行预先修改以支持热补丁，这被一些用户视为额外的负担。 • 不同用户对工具的实际应用场景和个人偏好有所不同，有些用户关注便利性和跨平台支持，而另一些用户则更在意代码修改的必要性和对现有工作流的潜在影响。
