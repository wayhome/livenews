TIL: You can make HTTP requests without curl using Bash /dev/TCP

作者: mrshu | 评分: 196 | 评论数: 33 | 发布时间: 2026-06-16 16:40
文章摘要

这篇文章介绍了在没有 curl 或 wget 的精简 Docker 容器中，如何使用 bash 内置的 `/dev/tcp` 功能直接发送 HTTP 请求来测试服务连通性。 核心方法是通过 `exec 3<>/dev/tcp/host/port` 打开 TCP 套接字，然后手动构造 HTTP 请求并写入文件描述符。`/dev/tcp` 并非真实设备文件，而是 bash 内部处理的重定向机制。 需要注意：这不是真正的 HTTP 客户端，不支持 TLS、重定向、压缩等高级特性；必须添加 `Connection: close` 头避免连接挂起；这是 bash 特有功能，非 POSIX 标准；需要编译时启用 `--enable-net-redirections` 选项。 适用场景：在无法安装工具的精简容器中进行快速连通性测试，日常工作仍应使用 curl。

评论摘要
主要讨论点：Bash的/dev/tcp功能用于手动进行HTTP通信的实用性和局限性 不同观点： • **实用派**：多位开发者分享在受限环境中（Docker容器、安全限制的系统、极小存储空间的路由器）使用/dev/tcp成功解决问题的经验，认为这是curl/wget不可用时的有效替代方案 • **技术严谨派**（basilikum）：强调这不是"Bash会说HTTP"，只是Bash能打开TCP套接字，手动构造的HTTP请求不完整且易出错，建议用nc或完整的HTTP客户端，警告不应在生产环境中无人值守使用 • **历史溯源派**：指出这是KornShell 1997年的特性，并非Bash原创；也有人提到这是模仿Plan 9的/net目录设计 • **安全绕过场景**：部分用户提到在渗透测试、CTF竞赛中利用此功能绕过安全限制 补充讨论： • 有人感叹这种底层理解体现"没有魔法"的哲学，担心未来开发者过度依赖AI代理会失去对系统底层的理解 • 实际应用案例包括Docker健康检查、心跳服务、内部网络连接测试 • 技术细节讨论涉及HTTP/1.0 vs 1.1选择、example.com作为测试域名的适用性

Stop Using JWTs

作者: dzonga | 评分: 176 | 评论数: 33 | 发布时间: 2026-06-16 16:49
文章摘要

这篇文章主张停止使用JWT进行用户登录管理。核心观点包括： 1. **JWT不适合会话管理**：JWT设计用于5分钟以下的短期token，而会话需要更长生命周期。 2. **无状态认证不安全**：真正的无状态认证不可行，必须维护某种状态来保证安全，既然需要数据存储，不如直接使用传统会话。 3. **JWT规范本身存在安全问题**：安全专家不信任JWT规范，原始规范甚至允许伪造token。 4. **传统cookie会话更优**：更安全、更高效、更灵活。谷歌等大公司的浏览器用户会话也使用传统cookie，JWT仅用于单点登录的服务器间传输。 文章推荐使用PASETO作为短期token的替代方案，并建议避免在localStorage存储认证凭据。

评论摘要
主要讨论点：JWT在Web认证中的适用性及其安全性争议 不同观点： • **JWT适用但需正确使用**（littlecranky67, tracker1, himata4113, miiiiiike）：JWT撤销列表比session列表更小、成本更低；使用短生命周期（5-15分钟）配合刷新机制；适合服务间通信和作为认证缓存；采用RSA签名而非共享密钥；可通过minimum_issued_at实现"全设备登出" • **JWT存在根本性问题**（文章作者，rdegges支持）：无法撤销单个token是致命缺陷；既然需要撤销列表就失去了无状态优势，不如直接用session；规范本身不被安全专家信任；建议用PASETO替代 • **JWT完全可行且优越**（bijowo1676, Grollicus）：比cookies更优秀；在特定场景（如RabbitMQ权限控制）设置简单高效 • **争议被夸大**（solatic, ApolloFortyNine, Aeolun, bastawhiz, blixt）：反对文章引用的安全问题实际是实现bug而非标准缺陷；AWS STS等大规模系统成功使用JWT证明其可靠；"5分钟生命周期限制"缺乏RFC依据；标题过于耸人听闻 补充讨论：BlackFly总结核心矛盾——若需状态化撤销列表，JWT的无状态优势即消失；himata4113强调子服务隔离的安全价值；多人提到使用场景区分（浏览器session vs 服务间通信）是关键
