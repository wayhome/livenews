A special build of curl that can impersonate Chrome and Firefox

作者: mmh0000 | 评分: 74 | 评论数: 8 | 发布时间: 2025-04-03 15:24
文章摘要

`curl-impersonate` 是一个修改版的 curl，能够模拟 Chrome、Firefox、Edge 和 Safari 四大浏览器。它通过调整 TLS 和 HTTP 握手过程，使其与真实浏览器的表现完全一致，从而绕过网站对客户端进行的 TLS 和 HTTP/2 指纹识别。该工具可以像常规 curl 一样从命令行使用，也可以作为库集成到项目中替代常规的 libcurl。 为了实现模拟，`curl-impersonate` 做了以下修改： 1. 使用与浏览器相同的 TLS 库（如 Firefox 的 NSS 和 Chrome 的 BoringSSL）。 2. 调整 TLS 扩展和 SSL 选项。 3. 修改 HTTP/2 连接设置。 4. 使用特定标志运行，如 `--ciphers` 和 `--curves`。 该工具支持多个版本的浏览器，并提供了包装脚本方便使用。详细使用方法和支持的浏览器列表可以在文档中找到。

评论摘要
主要讨论点：围绕Ladybird浏览器和cURL在网络请求、TLS握手、指纹识别和反恶意机器人流量方面的能力和挑战的讨论。 不同观点： • jchw认为Ladybird使用cURL进行网络处理，虽然目前cURL在某些方面（如WebSockets over h2）仍有局限，但随着浏览器引擎的发展，可能会减少指纹识别带来的问题，因为合法流量将具有与原生cURL相同的指纹。 • VladVladikoff提出，如果TLS握手看起来不同，是否可以在nginx层面过滤那些声称是浏览器（如Chrome用户代理）但实际上是Python/PHP脚本的流量，以此来阻止大部分恶意机器人流量。 • Jotalea对几个问题进行了思考：1. 是否可以冒充Chrome和Firefox？这已经通过用户代理实现；2. 是否有JavaScript代码检测浏览器，而这个cURL版本可以运行它？3. 是否TLS握手与浏览器一致就足够了？最终认为这种工具可能有人需要，但不是他。 • ec109685指出，Chrome提供了一些API可以让服务器验证请求是否来自官方Chrome浏览器，这些API可以检测到cURL并非真正的Chrome。因此，希望有工具能支持cURL的参数但驱动一个真正的无头Chrome浏览器。 • pvg仅提供了一个与讨论相关的以前的新闻链接，没有详细观点。 • bossyTeacher认为这是一个很酷的工具，但客户端是否为浏览器不应该重要，对需要这种工具的现实世界感到遗憾。 补充讨论： • 争议焦点在于是否可以通过TLS握手等技术手段有效过滤恶意机器人流量，以及现有的工具（如cURL和无头Chrome浏览器）能否满足实际需求。 • 讨论中还涉及到指纹识别技术的局限性和可能的解决方案。 • 有人认为，通过技术手段冒充浏览器是可行的，但也有人认为需要更复杂的验证机制。

文章摘要

InitWare是一套中间件套件，用于将服务和系统资源作为逻辑实体（称为单元）进行管理。其主要组件是一个服务管理系统，能够在NetBSD、GNU/Linux及其他现代BSD系统上运行。InitWare通过作业调度器根据依赖关系自动调度单元，并提供用户会话管理器和系统日志。它可以作为init系统或辅助服务管理系统运行，源于systemd的分支，并在许多接口上保持与systemd的兼容性。当前为alpha版本，建议在生产环境中谨慎使用，直到发布首个稳定版本。InitWare根据LGPL-2.1许可证发布，支持多种平台，并提供了详细的构建和贡献指南。

文章摘要

C3是一种基于C语言语法和语义的编程语言，旨在进化C语言的同时保持C程序员熟悉的特性。C3强调与C语言的ABI兼容性，可以轻松在同一项目中混合使用C和C3代码。其设计原则包括保持C语言的核心特性，仅在必要时进行修改，并引入一些高层次的便利功能。C3没有强制性的头文件，采用基于模块的命名空间，支持切片、编译时反射、增强的编译时执行、基于泛型模块的泛型编程、基于"Result"类型的零开销错误处理、延迟执行（defer）、值方法、关联枚举数据等特性。C3的灵感来源于C2语言，旨在迭代C语言而不是创造一种全新的语言。预编译的二进制文件适用于Windows x64、Debian x64、Ubuntu x86和MacOS Arm64等操作系统。
