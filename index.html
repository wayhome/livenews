Voxel Space

作者: davikr | 评分: 65 | 评论数: 8 | 发布时间: 2026-05-30 14:25
文章摘要

这篇文章介绍了Voxel Space渲染引擎的工作原理。1992年NovaLogic发布的游戏《Comanche》采用了这项技术,在当时呈现出惊艳的地形图形效果。 Voxel Space是一种2.5D引擎,使用高度图和颜色图来表示地形。其核心算法非常简单:从远到近绘制,对每个距离的扫描线进行光栅化,根据透视投影计算高度,然后绘制垂直线条。这种"画家算法"能够自然处理遮挡关系。 文章提供了基础渲染算法和添加旋转功能的Python代码示例,展示了如何用极少的代码实现地形渲染。这种技术虽然无法表现复杂几何体,但在CPU性能有限的年代实现了出色的视觉效果。

评论摘要
主要讨论点：Comanche游戏的体素地形渲染技术及其历史意义 不同观点： • **技术定义争议**（nine_k）：这不是真正的体素技术，而是高度图（height map）加棱柱体，类似Doom地图，每个棱柱有固定大小的正方形底面。尽管如此，在1992年这仍然令人震撼 • **渲染算法争议**（Jare）：质疑文章中提到的"画家算法"说法，指出Comanche等体素地形引擎实际采用从前到后渲染，从不产生过度绘制（overdraw） • **实践应用**（a1o）：分享了将此方法移植到AGS引擎的游戏开发经验，当时需要做一些优化技巧来适配引擎性能 • **视觉技巧观察**（tdeck）：注意到颜色贴图内置了阴影效果，仅通过查看颜色贴图就能获得3D斜面效果 • **历史背景**（esafak）：揭示Comanche的突破性源于程序员在医疗行业（CT/MRI扫描）的经验 补充讨论：taneq提出优化建议——按列而非按行渲染可实现从近到远渲染，无需Y缓冲且零过度绘制

Openrsync: An implementation of rsync, by the OpenBSD team

作者: sph | 评分: 134 | 评论数: 8 | 发布时间: 2026-05-30 10:51
文章摘要

这是 openrsync 项目的 README 文档。openrsync 是一个采用 BSD 许可证的 rsync 实现，与现代 rsync（协议 27）兼容但仅支持部分命令行参数。该项目已合并入 OpenBSD 基础系统，最初为 RPKI 验证器 rpki-client 项目开发。 核心算法包含发送端和接收端两部分：发送端管理源文件，接收端管理目标文件。双方共享文件列表（包含文件名和元数据），独立按字典序排序后，通过"块交换"机制同步文件。接收端遍历文件列表向发送端请求更新，发送端扫描并返回需要更新的数据块。 项目支持 OpenBSD 及其他 UNIX 系统，提供完整的安装和使用文档。

评论摘要
主要讨论点：OpenBSD的openrsync项目及其安全特性、实现版本和"避免AI"的争议 不同观点： • **安全性必要性存在分歧**：Bender强调pledge(2)和unveil(2)是关键安全特性，质疑Linux上缺少这些功能的风险；tptacek则认为rsync通常在信任边界内运行，不像curl那样面对敌对方，安全警告有些过度 • **对"避免AI/slop"的态度**：triggis支持"无slop版本"；jmclnx担忧AI代码渗透（如postfix）；skeledrew则嘲讽这种避免AI的努力像"反向打地鼠游戏"，持观望态度 • **命名困惑**：WD-42质疑"openrsync"命名不当，因为原版rsync本就是GPL开源的，怀疑是否只是许可证更宽松而称"更开放" 补充讨论： • 存在多个实现版本：Go语言版本（Gokrazy团队）、macOS 15.0采用的版本 • 功能完善度：openrsync在OpenBSD 7.9已支持--exclude，但仍缺少-z压缩选项 • 核心技术争议：pledge/unveil在Linux上的可用性和必要性尚不明确

Zig: Build System Reworked

作者: tosh | 评分: 226 | 评论数: 16 | 发布时间: 2026-05-30 08:38
文章摘要

Zig编程语言在2026年5月26日对构建系统进行了重大重构。主要变化是将`build.zig`的编译过程分为两个独立进程：配置器（configurer）和制造器（maker）。配置器以调试模式编译用户的构建逻辑并生成二进制配置文件，制造器以发布模式编译并执行构建图。 这次改进带来三大性能提升：1) 每次修改只需重新编译用户的`build.zig`代码，而非整个构建系统；2) 当配置未变化时可跳过重新运行构建逻辑；3) 执行构建图的进程现在启用了优化。基准测试显示`zig build --help`命令的执行时间从150ms降至14.3ms，性能提升超过90%。此外，第三方工具如ZLS也能从序列化配置文件中受益。

评论摘要
主要讨论点：Zig 0.16.0 版本发布后的社区反馈和语言特性讨论 不同观点： • **积极派**：认为 0.16.0 是重大进步，新的 IO 机制高效且代码优雅，支持单线程/多线程/事件循环；编译速度出色；适合作为"车库修补"的工具语言，设计贴心不强制规范 • **观望派**：质疑语言稳定性，认为像异步 IO 这样的大特性变动说明语言仍不稳定，询问何时会有稳定版本发布 • **对比派**：Rust 用户询问是否值得尝试 Zig；Node.js/TypeScript 用户质疑 Zig 的优势在哪里 • **批评派**：认为字符串处理过于繁琐，希望有可选的 RAII 支持来简化字符串和容器的内存管理 补充讨论： 社区对 0.17.0 快速发布（几周内）感到惊喜，因为 0.16 用了超过一年；有用户因 Andrew Kelley 的访谈视频产生学习兴趣；也有人询问 MIT License (Expat) 的含义等基础问题。整体氛围积极，但对语言成熟度和某些设计选择存在不同看法。
