Saying Goodbye to Asm.js

作者: eqrion | 评分: 54 | 评论数: 11 | 发布时间: 2026-05-20 12:01
文章摘要

Firefox 148开始默认禁用asm.js优化，并计划在未来版本中完全移除相关代码。asm.js是Mozilla在2013年推出的技术，通过识别JavaScript的严格静态类型子集实现接近原生的执行速度，为WebAssembly的诞生铺平了道路。随着WebAssembly的成功和asm.js使用量的下降，继续维护asm.js会增加维护成本和安全风险。Mozilla建议开发者将asm.js内容重新编译为WebAssembly以获得更快的执行速度和更小的二进制文件。现有asm.js代码不会中断，仍可作为普通JavaScript运行。

评论摘要
主要讨论点：asm.js 被弃用，WebAssembly 成为主流编译目标的利弊权衡 不同观点： • **支持弃用派**：认为这是自然演进，asm.js 只是编译目标，没有遗留兼容需求，WebAssembly 是更好的替代方案 • **反对弃用派**：认为这是错误决定，asm.js 在某些场景下性能更优（如 SHA256 哈希），且能做 JS 能做的一切事情 • **实用主义派**：承认 WebAssembly 的隔离性是双刃剑——提供了安全性，但也带来了限制（无法直接调用 Web API、无法零拷贝传递缓冲区、运行时代码生成困难） 补充讨论： 多位评论者提到 Gary Bernhardt 2014 年的预言性演讲，感叹 12 年后其虚构场景成为现实。有人建议开发 asm.js 到 WASM 的转译器来解决遗留代码问题。核心争议在于：WebAssembly 的隔离设计虽然提升了安全性，但牺牲了与 JavaScript 生态的互操作性和某些性能优化场景的灵活性。

文章摘要

这篇文章论述了C/C++中未定义行为(UB)的普遍性和危险性。作者认为即使是最优秀的程序员也无法完全避免UB，因为它远比人们想象的更广泛存在。文章指出UB不仅限于内存安全问题，还包括许多微妙的情况，如未对齐的指针访问。关键观点是：UB与编译器优化无关，而是意味着编译器假定代码合法；在不同硬件架构上表现各异；甚至创建未对齐指针本身就是UB。作者强调，在2026年的今天，C/C++已不再适合现代开发环境，所有非平凡的C/C++代码都存在UB。

评论摘要
主要讨论点：C/C++语言中未定义行为(UB)的本质、影响范围及应对方式 不同观点： • **UB的技术本质派**：强调UB是C语言规范层面的问题，不是硬件问题。未对齐指针的类型转换本身就是UB，即使硬件不会崩溃。编译器优化器会假设UB不会发生，可能删除大段代码，导致意外行为。 • **实用主义派**：20年C开发经验者表示从未在实际工作中讨论过UB，遇到问题就调试修复。认为文章例子过于宽泛（任何函数调用都可能栈溢出），这种"危言耸听"对新手有害无益。 • **语言演进派**：指出文章中的C++代码已过时十多年，使用原始指针是代码异味。现代C++与C已相距甚远，不应混为一谈。 • **工具方案派**：反对用LLM检测UB，认为应使用ubsan等专业工具。也有人担心LLM生成的代码最终也会包含UB，需要更多专家而非AI。 • **编译器责任派**：认为现代编译器的行为使C比汇编更不安全，硬件语义其实是明确定义的。 补充讨论：有人用"悲伤五阶段"幽默总结学习UB的心路历程；生产系统依赖UB而不自知，直到编译器更新才暴露问题的风险引发关注。整数提升被认为是有符号溢出UB的常见来源。

主要讨论点：Eric Schmidt在大学毕业典礼上关于AI的演讲遭到学生嘘声，引发了关于AI技术、代际差异和科技精英责任的讨论。 不同观点： • **批评演讲者态度**：Schmidt的演讲语气居高临下，要求学生"接受现实"（deal with it），在学生面临就业困难时传递绝望信息，选择这样的演讲者本身就是错误 • **代际分歧明显**：GenAI是首个被年轻人抵制、却被55岁以上人群力推的技术；70多岁的精英认为自己比学生更有资格决定学生的未来 • **缺乏自我反省**：科技亿万富翁对自己造成的问题（就业市场恶化、气候危机、政治分裂）毫无自知，却要求年轻人"上车" • **学生虚伪论**：有人质疑嘘声的学生可能用AI写论文、做作业，AI作弊已成流行病 • **地缘政治角度**：若是美国对手，会鼓励年轻人反AI以获取战略优势 补充讨论：新毕业生就业困难部分源于AI替代（尤其是初级程序员岗位）、疫情期间过度招聘等多重因素；演讲内容陈词滥调，浪费了重要场合的发言机会。
