Whenever – typed and DST-safe datetimes for Python

作者: pkkm | 评分: 82 | 评论数: 10 | 发布时间: 2025-04-13 09:12
文章摘要

"Whenever" 是一个现代的 Python 日期时间库，旨在解决标准库 `datetime` 以及其他第三方库（如 Arrow 和 Pendulum）的不足。它支持 DST 安全的时间计算，并通过类型安全的 API 防止常见的错误。与标准库和其他库相比，Whenever 提供了更高的性能，并且能够明确区分简单和时区感知的时间类型，避免意外混用。此外，Whenever 还支持纳秒精度和多种时间运算，并提供了基于 Rust 的高性能实现，同时也有纯 Python 版本可供选择。该库文档完善、测试充分，且即将发布 1.0 版本。

文章摘要

Go channels are bad (2016)

作者: mpweiher | 评分: 49 | 评论数: 4 | 发布时间: 2025-04-13 05:43
文章摘要

这篇文章讨论了Go语言中通道（channels）的优缺点，作者承认Go是他使用过的“最不差”的编程语言，但认为通道存在设计缺陷，容易导致错误。文章首先澄清作者并不反对Go，而是反对过度使用通道。作者指出，虽然Go的并发模型基于霍尔（Hoare）的通信顺序进程（CSP）理论，具有很强的理论基础，但在实际使用中，通道往往不能单独解决所有同步问题，程序员常需要结合互斥锁、信号量等其他同步原语，从而偏离了纯CSP模型。作者通过一个简单的“高分记录”程序示例展示了通道的局限性，指出在实际应用中通道往往会成为一种反模式。最后，作者提到一篇研究表明，Go通道确实导致了大量并发错误。尽管如此，作者仍然认为Go是适合其项目需求的优秀语言。

评论摘要
主要讨论点：关于不同编程语言中并发同步原语的优缺点，特别是Go和Rust中的通道（channels）和其它同步机制（如锁、条件变量）的比较。 不同观点： • **[anarki8]** 认为Rust中的通道（channels）在异步编程中非常有用，能够有效避免死锁问题，并且可以通过组合子（combinators）轻松管理多个通道的状态循环。同时指出，Rust不存在Go中提到的“死去的goroutines”问题。 • **[t8sr]** 基于过去的Go开发经验指出，在大型复杂项目中使用CSP（通信顺序进程）模型（即Go的通道）容易引发问题，甚至在核心Go团队参与的项目中也是如此。他认为，虽然通道在某些情况下优于条件变量，但锁（mutexes）在互斥场景下通常更直观且高效。他还提到，所有同步原语本质上都可以看作是更底层机制（如futex和原子操作）的抽象，使用不当可能导致问题。 • **[regularfry]** 关注讨论的时效性，提出自2016年以来技术可能有所更新，询问当前是否仍然适用。虽然认可Go的向后兼容性，但对新工具或功能的引入情况不太清楚。 • **[ricardobeat]** 认为原始讨论中遗漏了一些解决Go中“死去的goroutines”问题的常见方法，比如发送关闭消息或使用Context实例的`ctx.Done()`方法。这些方法简单易实现，可以有效解决文章中提到的问题。 补充讨论： • 讨论中涉及了Go和Rust在并发编程中的不同设计选择，尤其是通道和锁的使用场景。 • 一些评论者分享了在大型项目中使用这些机制的实际经验，表明通道在某些场景下可能导致复杂性。 • 还提到了技术发展的时效性问题，部分讨论可能需要结合更新的工具和特性来理解。
