Quadlet: Running Podman containers under systemd

作者: gjvc | 评分: 144 | 评论数: 13 | 发布时间: 2025-03-24 00:27
文章摘要

本文介绍了如何使用Quadlet在systemd下运行Podman容器，替代已被弃用的`podman generate systemd`方法。Quadlet简化了将Podman容器作为systemd服务运行的过程，特别适用于需要在后台运行并希望在服务器重启后自动启动的容器。 过去的方法需要手动创建容器、生成systemd服务文件并进行配置，步骤繁琐且不易管理。而Quadlet通过在`~/.config/containers/systemd`目录中创建`.container`文件来定义容器配置，使用类似INI文件的格式，包含容器和systemd相关设置。这不仅简化了操作，还提供了更多灵活性，允许使用systemd的所有功能。 例如，创建一个PostgreSQL容器的配置文件`test-db.container`，可以指定镜像、自动更新、端口映射、卷和环境变量等。Quadlet使得Podman在功能和易用性上接近Docker Compose，同时更好地与systemd集成。

评论摘要
主要讨论点：Podman 和 Quadlet 的使用体验及其与 Docker Compose 的对比 不同观点： • **支持 Quadlet 的观点**： ◦ Quadlet 让容器像系统服务一样运行，无需学习额外的编排层，使用 systemd 单位文件即可管理，非常方便。 ◦ Quadlet 提供了自动更新和失败重启等功能，整体体验优于 Docker。 ◦ 支持 socket 激活等特性，在某些方面优于 Docker Compose。 ◦ 有人专门开发了用于管理 Quadlet 的 GitOps 工具，显示出对其的认可。 ◦ 有人使用 openSUSE MicroOS 和 Podman/Quadlet 组合，对其自动更新和无守护进程的设计表示满意。 • **对 Quadlet 的批评和保留意见**： ◦ Quadlet 不支持 Docker Compose 的许多特性，例如多 YAML 文件的堆叠。 ◦ Quadlet 在某些方面还不如 Docker Compose 成熟，特别是在本地开发环境中使用时显得笨重。 ◦ 有人认为 Quadlet 的命名和概念不够清晰，且相关信息和社区支持较少。 ◦ 有人直言 Docker Compose 非常优秀，Quadlet 无法替代。 • **关于 Podman 和 Docker 之间对比的观点**： ◦ 有人指出 Podman 没有为 Debian/Ubuntu 提供官方仓库，导致在某些系统上难以获取最新版本。 ◦ 有人认为 Podman 和 Quadlet 的组合在 rootless 模式下使用体验不佳。 ◦ 有人提到 Podman-Compose 项目不再活跃，且功能不完善，因此选择使用 Docker Compose 配合 Podman socket。 补充讨论： • 有人提议创建一个社区维护的 Quadlet 仓库，类似于 Docker 的生态系统。 • 有人提到 Quadlet 的开发历史较长，但成熟度仍未达到预期，并猜测可能存在一些技术或政治原因导致其发展缓慢。 • 有人分享了实际项目中的使用经验，例如使用 Quadlet 部署 inlets 隧道客户端，展示了其在 Kubernetes 环境中的应用潜力。 争议焦点： • Quadlet 是否能替代 Docker Compose，尤其是在本地开发环境中的使用体验上存在争议。 • Quadlet 的功能成熟度和命名问题也是讨论中的争议点。
