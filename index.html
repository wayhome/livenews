CVE-2025-48384: Breaking Git with a carriage return and cloning RCE

作者: dgl | 评分: 65 | 评论数: 2 | 发布时间: 2025-07-08 17:48
文章摘要

这篇文章讨论了CVE-2025-48384漏洞，该漏洞影响Unix类平台上的Git。当用户使用`git clone --recursive`克隆不受信任的代码库时，可能导致远程代码执行。漏洞源于Git处理配置文件时对回车符（CR）和换行符（LF）的处理不当。Git的配置格式支持DOS换行符（CR+LF），但在特定情况下，Git会错误地处理以回车符结尾的值，可能导致控制字符被引入文件路径中。攻击者可以利用此漏洞，在子模块路径中插入恶意控制字符，从而在克隆过程中执行任意代码。为避免此问题，用户应更新到Git的修复版本，并谨慎处理不受信任的代码库。

评论摘要
主要讨论点：Homebrew 中 Git 版本更新的等待和期望 不同观点： • therealmarv 表示期望 Git 2.50.1 版本能在 Homebrew 中尽快更新，但目前还没有看到更新，暗示了对更新延迟的不满或无奈。 • 隐含的观点是用户对软件包管理器（Homebrew）的更新速度有一定期望，希望常用软件如 Git 能及时更新到最新版本。 补充讨论： • therealmarv 没有提到具体的技术问题，仅表达了对版本滞后的关注。 • 评论中没有出现与其他用户的争议或进一步的讨论，更多是单方面的等待和期望。 • 隐含的另一个讨论点可能是开源软件生态中不同项目之间（如 Git 与 Homebrew）的版本同步问题，用户可能经常遇到类似的时间差。
