The Princeton INTERCAL Compiler's source code

文章摘要

《Forty-Four Esolangs》一书将于2025年9月23日发布，首次公开了普林斯顿INTERCAL编译器的源代码。INTERCAL由唐·伍兹和吉姆·里昂于1972年在普林斯顿大学创作，是第一个被称为“esolang”的编程语言，故意颠覆传统编程规则，以符号和独特设计（如“#”代表“mesh”）挑战程序员。该语言最具特色的功能是“PLEASE”命令，使用过多或过少都会导致程序被忽略，模仿了人类与算法之间的模糊关系。 尽管INTERCAL-72编译器从未广泛传播，但其影响深远，启发了如Chicken、Ook!等语言。最著名的“COME FROM”语句则是1990年由Eric S. Raymond添加的。通过最新技术，现在可以首次体验原版INTERCAL-72编译器，了解其独特的数学运算方式。

文章摘要

这篇文章介绍了使用线性反馈移位寄存器（LFSR）作为程序计数器的CPU实现，该项目基于VHDL语言，面向FPGA。与传统程序计数器相比，LFSR可以节省逻辑门数量，特别适用于7400系列IC或手动布局晶体管的场景。项目包含一个完整的Forth解释器，目前在仿真中运行成功，输出启动消息"eForth 3.3"并接受输入。该CPU资源占用小，运行频率可达151.768MHz，使用少量FPGA资源。项目提供构建指南，通过GHDL进行仿真，使用Xilinx ISE 14.7进行FPGA合成。CPU为累加器架构，指令长度16位，程序计数器由8位LFSR驱动。

How Can AI Researchers Save Energy? By Going Backward

作者: pseudolus | 评分: 24 | 评论数: 2 | 发布时间: 2025-06-02 02:29
文章摘要

文章讨论了人工智能研究中如何通过可逆计算节省能源。传统计算机在删除数据时会产生热量，造成能量损失，这是由物理学家罗夫·兰道尔在1960年代提出的理论。迈克尔·弗兰克等研究者探索了可逆计算，即通过不删除数据来避免这种能量损失。可逆程序既能向前也能向后运行，从而在理论上节省能源。尽管早期认为可逆计算不切实际，但查尔斯·班纳特在1973年提出了“非计算”概念，通过运行计算后存储结果并反向运行，以节省能量并保留必要数据。随着传统计算遇到物理极限，可逆计算有望在人工智能领域发挥重要作用，可能显著提升计算效率。

评论摘要
主要讨论点：计算过程的方向性及其可逆性 不同观点： • [MangoToupe] 认为计算的方向性不应该是指因果关系，即不能简单地通过输出反推输入。他质疑是否仅仅是通过默认保存状态来实现回溯，从而使计算看起来具有方向性。他提出，为了从输出推导输入，似乎必须先用已知输入运行程序，因此方向性似乎更多是为了方便状态保存和回溯，而不是计算本身的固有属性。 • [throwawaymaths] 更关注实际实现问题，尤其是可逆计算的具体操作。他质疑是否有人已经实现了类似矩阵乘法（matmul）这样的可逆计算。他指出，在这种计算中，信息在转换过程中被大量破坏，尤其是边缘处理时，这使得可逆计算的实现具有挑战性。 补充讨论： • [MangoToupe] 强调了对计算方向性的理解，认为自然解释应是因果关系，但计算方向性似乎更侧重于状态保存和回溯机制，而不是从输出反推输入的因果关系。 • [throwawaymaths] 则提出了实际的技术挑战，特别是关于信息破坏的问题，暗示可逆计算在具体操作（如矩阵乘法）上仍有待技术突破。 争议焦点：计算方向性的定义及其在实际计算操作中的可实现性。一方关注理论上的解释和理解，另一方则关心实际技术实现中的具体问题和障碍。
