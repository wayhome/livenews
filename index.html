Show HN: Bun-sqlgen – Type-safe raw SQL for Bun, no ORM

作者: ilbert | 评分: 37 | 评论数: 10 | 发布时间: 2026-06-23 14:20
文章摘要

bun-sqlgen 是一个为 Bun 环境提供类型安全 SQL 查询的代码生成工具。它无需 ORM，直接使用原生 `Bun.sql`，通过为查询添加标签名（如 `sql.GetUser`），在调用处自动生成完全类型化、空值安全的返回类型。 该工具基于迁移文件作为数据库 schema 的真实来源，在构建时对真实的 Postgres 或 SQLite 数据库验证查询（无需 Docker），将错误列名和无效 SQL 在构建阶段而非生产环境中捕获。生成的类型文件可提交至版本控制，运行时保持 100% Bun 原生实现。支持两种数据库方言、空值覆盖、事务等功能。

评论摘要
主要讨论点：bun-sqlgen 项目的评价，以及 SQL 类型安全解决方案的不同选择 不同观点： • **推荐成熟替代方案**：多位评论者建议使用 SQLc（giovannibonetti, rankdiff），认为它是更成熟的解决方案，支持多种语言包括 TypeScript • **质疑项目质量**：genshii 指出 README 明显由 LLM 生成，对项目质量表示怀疑 • **支持原项目理念**：作者 ilbert 详细阐述设计思路——保持原生 SQL 写法同时获得类型安全，不像 Drizzle/Kysely 那样将查询转为 TypeScript DSL • **推荐其他工具**：allthetime 简短推荐 Kysely • **技术兼容性关注**：psc007 询问与 Porsager-Postgres 和 PostGIS 的兼容性；sHooKDT 希望支持 Node.js，认为 Bun 不适合生产环境 补充讨论： 项目核心创新在于通过 codegen 从实际 SQL 查询推断类型（包括处理复杂的 nullability），使用 PGlite 避免 Docker 依赖。争议焦点是工具选择：成熟度（SQLc）vs 设计理念（保持原生 SQL）vs 运行时限制（仅支持 Bun）。
