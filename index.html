pg_durable: Microsoft open sources in-database durable execution

作者: coffeemug | 评分: 85 | 评论数: 6 | 发布时间: 2026-06-05 15:59
文章摘要

pg_durable 是微软开源的 PostgreSQL 扩展，在数据库内实现持久化执行（Durable Execution）。它让长时间运行的 SQL 函数具备容错能力，通过检查点机制在每步执行后保存状态，崩溃或重启后可从断点恢复，无需重新执行已完成的工作。 适用场景包括：向量嵌入管道、数据摄取、定时维护、并行聚合、外部 API 调用等。可替代 pg_cron + 状态表、外部编排器（Airflow/Temporal）、队列+工作者等传统方案，将工作流逻辑统一在 SQL 中管理，减少架构复杂度。 核心优势是消除部分失败后的手动恢复、避免长事务锁定、将重试和进度跟踪集中到 Postgres。不适合单条 SQL 语句、毫秒级同步请求，或需要复杂应用逻辑的场景。

评论摘要
主要讨论点：Postgres作为工作流/队列引擎的合理性 不同观点： • **支持派**（levkk）：认为2026年是Postgres队列的元年，社区贡献了DBOS和pgQue等工具，为开发者提供了新选择 • **质疑派**（oa335, faxmeyourcode）：不理解为什么要用数据库存储工作流，而不是使用独立的编排工具。认为控制流应该在代码中管理，而非数据库中。质疑相比Apache Airflow等成熟DAG调度器的优势 • **混合方案派**（jraedisch）：提到Absurd项目尽可能减少纯数据库方法，暗示可能需要平衡数据库和代码的职责 • **功能对比派**（kilobaud）：质疑该项目与Temporal等工具的可比性，特别是在处理跨多个异构系统的工作流时的局限性 补充讨论： cpursley提出技术实现问题，疑惑为何不基于pgmq构建，并分享了基于pgflow.dev的Elixir DAG包作为替代方案。核心争议在于**工作流逻辑应该存在于代码仓库（Git）还是数据库中**，以及Postgres方案相比现有成熟工具的实际优势。

Cooldown Support for Ruby Bundler

作者: calyhre | 评分: 88 | 评论数: 3 | 发布时间: 2026-06-03 05:15
文章摘要

Bundler 4.0.13 引入了"冷却期"(cooldown)功能，用于防御供应链攻击。该功能允许开发者设置一个时间窗口（如7天），拒绝解析过于新近发布的gem版本，优先使用已公开一段时间、经过审查的版本。 使用方法：在Gemfile中声明 `source "https://rubygems.org", cooldown: 7`，或通过命令行、配置文件、环境变量设置。该功能是可选的，基于rubygems.org v2索引提供的版本创建时间戳工作。当需要紧急更新（如安全漏洞修复）时，可用 `--cooldown 0` 临时禁用限制，立即获取最新版本。

评论摘要
主要讨论点：关于软件包版本冷却期（cooldown）机制的安全性和实用性问题 不同观点： • **冷却期失效论**（swader999）：认为一旦所有人都使用冷却期机制，攻击者也会适应这个规则，该防护措施将失去效果，需要重新设计解决方案 • **紧急补丁困境**（doctorpangloss）：指出冷却期与安全响应存在冲突——当1.0版本发现漏洞，1.1紧急修复版发布时，7天冷却期会强制用户继续使用有漏洞的版本，这是不可接受的 • **绕过漏洞质疑**（delichon）：发现对于不暴露created_at字段的版本源（旧版gem服务器、v2之前的历史记录、v1格式的私有仓库），系统会将其视为在冷却窗口之外并保持可解析——这可能成为攻击者轻易绕过冷却期限制的漏洞 补充讨论：三条评论共同揭示了该冷却期机制在设计上的根本性矛盾：既想通过延迟防范供应链攻击，又必须允许紧急安全补丁快速部署，同时还存在技术上可被利用的绕过路径。

YouTube上线了《C++: The Documentary》纪录片，讲述C++四十年发展史。从Bjarne Stroustrup在贝尔实验室创造C++开始，经历标准化需求、STL库诞生、C++98首个标准、2000年代低谷期、到C++11现代化复兴。纪录片展示了C++如何从实验室项目成长为全球广泛应用的编程语言，目前是全球增长最快的四大语言之一（2025年Q3数据显示3.5年用户增长90%）。片中采访了Bjarne、STL设计者Stepanov、ISO委员会成员等多位关键人物。

评论摘要
主要讨论点：关于C++纪录片发布及C++语言本身的多角度讨论 不同观点： • **C++难度观点分歧**：有人认为C++过于复杂，标准繁多难以记忆，维护C++项目令人疲惫（jdw64）；但也有人认为C++极其优雅，能提供精确的底层心智模型，适合系统化思维者（GodelNumbering） • **C++的地位评价**：有观点强调C++是互联网的真正底层语言，Web开发者只是在C++程序中工作（TonyAlicea10）；另有人惊讶于C++竟是增长最快的前四大语言之一，增长90%可能与AI发展相关（ElenaDaibunny, claiir） • **纪录片制作方式偏好**：部分观众喜欢这种由专家短句组成的叙事方式，但也有人表示难以集中注意力，更偏好旁白式讲解（neals） • **语法便利性**：有开发者认为C++过于冗长，希望有更简洁的语法糖，尽管承认其编程范式已相当通用（i_am_a_peasant） 补充讨论：多位评论者对纪录片阵容表示赞赏（Stroustrup、Stepanov、Kernighan等），感谢免费发布；有人好奇这是否是编程语言纪录片系列的趋势；Andrei Alexandrescu的《Modern C++ Design》被特别提及为经典著作。
