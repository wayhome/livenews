PEP 750 – Template Strings (t-strings) have been accepted

作者: grep_it | 评分: 323 | 评论数: 35 | 发布时间: 2025-04-10 20:24
文章摘要

PEP 750 引入了模板字符串（t-strings），作为自定义字符串处理的扩展，解决了 f-strings 的一些局限性。t-strings 使用 "t" 前缀，返回一个新的 `Template` 类型，允许开发者在字符串和插值结合之前访问和处理插值内容。这有助于在处理如 SQL 注入、跨站脚本（XSS）等安全问题时进行更灵活和安全的操作。例如，通过定义一个 `html()` 函数，可以自动对内容进行清理。此外，t-strings 还支持在复杂字符串处理任务中进行预处理和转换，为 web 模板、领域特定语言等提供了更强大的工具。PEP 750 基于 PEP 701，并进一步简化和推广了 PEP 501 中的插值模板字符串概念。

评论摘要
主要讨论点：Python 语言中字符串格式化的设计和实现，特别是 f-strings 和 t-strings 的引入及其争议。 不同观点： • Mawr 认为 Python 在字符串格式化上的设计平衡且实用，相较于 Java 的过度设计和 Go 的草率处理，Python 的开发者能够及时推出足够好的方案。 • nhumrich 作为 PEP 501 的贡献者，对 t-strings 的引入感到兴奋，并对该 PEP 的历史比较了解。 • kstrauser 指出 f-strings 的一个问题，即无法延迟计算，这导致在某些情况下仍然需要使用 str.format。 • ratorx 质疑是否有必要在语言层面引入 t-strings，认为可以通过函数返回 f-string 实现相同功能，并提到通过类型检查来增强安全性。 • spankalee 从 JavaScript 中的模板字面量得到启发，认为 PEP 750 的实现很有趣，并讨论了模板处理的紧凑性和潜在的歧义。 • simonw 支持 t-strings 的引入，认为其能像 JavaScript 的模板字面量一样处理 HTML 转义和 SQL 参数化。 • epistasis 对 Python 语言的发展速度和版本支持周期感到失望，认为过短的生命周期对科学计算领域的长期项目不利。 • throwawayffffas 对 f-strings 和 t-strings 的复杂性感到不满，认为 string.format 或 % 格式化已经足够好。 • callamdelaney 对 Python 不断添加新特性持保留态度，认为 Python 正在变得像一个委员会设计的语言。 • SuperV1234 支持这个 PEP，并提到其在 C++ 中类似的尝试。 • pansa2 对 PEP 中的冗长代码示例感到震惊，认为这违背了 Python 简洁的特性，并与 Ruby 的简洁实现进行对比。 • sgarland 认为 t-strings 像是更高级的 string.Template，尽管有用但并不新颖。 • pgjones 提供了一个实际的应用案例，展示了 t-strings 在 SQL 构建中的使用。 • illegally 认为 t-strings 没有必要，觉得简单的 f-string 已经足够。 • mortar 对 t-strings 延迟计算的功能感到困惑，希望得到更清晰的示例说明。 补充讨论： • 争议焦点在于是否有必要在语言层面引入新的字符串格式化特性，以及这些特性是否增加了不必要的复杂性。 • 支持者认为 t-strings 提供了更多的灵活性和安全性，反对者则担心 Python 因此变得过于复杂和难以维护。 • 讨论中多次提到 JavaScript 的模板字面量，作为支持引入 t-strings 的参考。 • 一些开发者对 Python 语言的演进速度和方向表示担忧，特别是对长期支持版本的缩短表示不满。 • 具体的代码示例和实现细节也引发了关于 Python 语言简洁性和可读性的进一步讨论。

本文介绍了Linux中通过shebang（#!）指定脚本解释器的基础知识，并深入探讨了内核如何处理脚本执行。shebang不仅用于shell脚本，还可用于Python等其他脚本，使脚本可以直接执行而无需手动指定解释器。文章通过对比`useradd`和`adduser`两个命令，展示了如何利用`file`命令查看可执行文件类型，并解释`adduser`实际上是一个Perl脚本。作者纠正了一个误解：shebang的处理由Linux内核直接负责，而非shell。文章进一步通过`strace`工具和内核源码分析，详细解释了`execve`系统调用如何通过`search_binary_handler`函数识别并执行不同格式的可执行文件，包括ELF、脚本和binfmt_misc等模块。其中，binfmt_misc允许自定义文件扩展名或魔数以指定解释器，从而扩展了Linux对非原生可执行文件的支持。
