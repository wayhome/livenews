RDNA 4's “Out-of-Order” Memory Accesses

作者: ingve | 评分: 116 | 评论数: 4 | 发布时间: 2025-03-23 22:18
文章摘要

AMD's RDNA 4 architecture introduces improvements in memory subsystem handling, particularly with "out-of-order" memory accesses. Previously, in RDNA 3, memory requests from different shader waves were processed in a strict order, causing delays if one wave had to wait for another's memory loads. This led to inefficiencies, as later requests couldn't bypass earlier ones, even if their data was ready. In RDNA 4, requests from different waves can be processed out-of-order, eliminating false dependencies and improving performance. Testing involved creating scenarios where "wave X" and "wave Y" had differing memory access patterns. In RDNA 3, wave X's accesses were unnecessarily delayed by wave Y's cache misses, as the memory subsystem waited for all wave Y's accesses to complete. However, in RDNA 4, both waves operate independently, preventing such delays and improving overall efficiency. This change aligns with multithreaded programming principles, enhancing performance scaling in GPU operations.

Quadlet: Running Podman containers under systemd

作者: gjvc | 评分: 113 | 评论数: 12 | 发布时间: 2025-03-24 00:27
文章摘要

本文介绍了如何使用Quadlet在systemd下运行Podman容器，替代已被弃用的`podman generate systemd`方法。Quadlet简化了将Podman容器作为systemd服务运行的过程，特别适用于需要在后台运行并希望在服务器重启后自动启动的容器。 过去的方法需要手动创建容器、生成systemd服务文件并进行配置，步骤繁琐且不易管理。而Quadlet通过在`~/.config/containers/systemd`目录中创建`.container`文件来定义容器配置，使用类似INI文件的格式，包含容器和systemd相关设置。这不仅简化了操作，还提供了更多灵活性，允许使用systemd的所有功能。 例如，创建一个PostgreSQL容器的配置文件`test-db.container`，可以指定镜像、自动更新、端口映射、卷和环境变量等。Quadlet使得Podman在功能和易用性上接近Docker Compose，同时更好地与systemd集成。

评论摘要
主要讨论点：Quadlet工具的实用性、优缺点以及与Docker Compose的比较 不同观点： • [sunshine-o] 认为 Quadlet 虽然关键，但经过多年尝试仍未感觉其足够成熟，预计2025年才能真正成熟。他质疑为什么简单的服务管理与容器集成花了近十年时间，并猜测其中可能有IBM/Redhat与Systemd之间的政治因素。 • [stryan] 高度评价 Quadlet，认为它使得容器可以像系统服务一样管理，并且不需要额外的编排层。他指出 Quadlet 比 Docker Compose 更简洁，但承认 Quadlet 并不适合 docker-compose 那样的本地开发场景，推荐使用 Podman 配合 Docker Compose。 • [eulenteufel] 喜欢 Quadlet 将容器作为系统服务使用，但指出 rootless 容器在用户系统会话中运行，而不是系统会话中，使用体验不佳，期望改进。 • [brirec] 对文中批评 Podman-Compose 不维护但同时推荐 Quadlet（同样长时间未更新）表示质疑，并指出 Quadlet 缺乏对多 YAML 文件叠加功能的支持。 • [aprilfoo] 支持 Quadlet，认为它值得更多关注，并建议建立类似社区维护的 Quadlet 存储库，以帮助推广使用。 • [mati365] 提供了 Quadlet 部署的 Ansible 模板，展示其易用性，并分享了具体的部署示例链接。 • [cvhc] 认为 Quadlet 的格式比 Podman 生成的 systemd 或 Kubernetes YAML 更清晰，且与 systemd 集成良好，但抱怨 Podman 没有为 Debian/Ubuntu 提供官方仓库支持，导致错过新功能，最终回到 Docker Compose。 • [alexellisuk] 提到 Quadlet 的应用实例，如使用 Quadlet 运行 inlets 隧道客户端，并认为 Quadlet 提供了良好的可移植性，使用 Kubernetes YAML 实现标准化。 • [muti] 分享了使用 openSUSE MicroOS 和 Podman 容器/Quadlet 的经验，对容器自动更新和使用 systemd 工具进行监控表示满意。但他承认 Quadlet 对本地开发场景支持不佳，仍倾向于 Docker Compose。 • [udev4096] 坚定支持 Docker Compose，认为 Quadlet 无法替代其功能，不值得花费时间尝试替代方案。 • [bityard] 对 Quadlet 的命名和其存在的必要性表示困惑，不明白为何需要一个特殊的名称来描述由 systemd 管理的容器。 补充讨论： - Quadlet 与 Docker Compose 的比较是讨论的核心，支持者认为 Quadlet 更简洁且与 systemd 集成良好，批评者则认为其功能不如 Docker Compose 全面，尤其在本地开发场景中。 - 有关工具成熟度和更新频率的争议，部分用户认为 Quadlet 仍不够成熟，且更新缓慢。 - 关于 rootless 容器的用户体验问题，一些用户希望改进 rootless 容器在系统会话中的运行方式。 - 社区对 Quadlet 的推广和支持，包括建立社区维护的存储库，也有一定讨论。

A USB Interface to the "Mother of All Demos" Keyset

作者: zdw | 评分: 247 | 评论数: 18 | 发布时间: 2025-03-23 15:31
文章摘要

Douglas Engelbart在1960年代初开始探索计算机如何增强人类智力，并开发了许多现代计算的特性，如鼠标、超文本、共享文档、窗口和图形用户界面。在1968年的联合计算机会议上，他通过一场开创性的演示（被称为“所有演示之母”）展示了这些创新。这场演示包括使用一种名为"keyset"的输入设备，但它并未普及。Engelbart的演示还展示了层次文档编辑、图形绘制以及通过远程连接与同事协作，预示了现代计算的许多功能。他的工作受到Vannevar Bush 1945年文章《As We May Think》的启发，旨在增强人类解决复杂问题的能力。Engelbart在斯坦福研究所创立了增强研究中心，并开发了名为NLS的系统，该系统支持交互式文档编辑、代码浏览和数据库检索。这场演示使用了当时先进的硬件和通信技术，连接了Menlo Park和旧金山的会场。

评论摘要
主要讨论点：关于弦键盘（Chorded Keyboard）的历史、应用及其优缺点的讨论 不同观点： • andrehacker认为，道格拉斯提出的弦键盘概念催生了一些相对成功的继承者，例如80年代荷兰的Velotype，它有更多的键， reportedly 使学习“弦”变得更加容易。他还提到了《Nerds 2.0.1》这本书及其相关的PBS系列，认为这是对该主题的有益补充。 • Animats指出，最早的弦键盘可以追溯到1897年Baudot的发明，最初的设计用于发送5位电传字符，并且已经实际部署，而不仅仅是一个原型。 • neilv讨论了Engelbart的演示中出现的键盘设备，指出弦键盘在“可穿戴计算”研究人员中很受欢迎，如Twiddler。其优点是只需要一只手操作，并且可以在没有稳定表面的情况下使用。 • jntun补充了历史细节，指出Engelbart演示中的桌子、办公室和椅子都是由Herman Miller专门设计的。 • peteforde提出了技术性建议，推荐使用RC网络和六角反相器来处理开关输入的反弹问题，而不是依赖100毫秒的延迟。 • GregDavidson分享了个人使用Twiddler与Android手机配合的经验，能够完全操作桌面应用程序，如Emacs。 • jarpineh对弦键盘的潜在优势提出了疑问，包括其在防止RSI（重复性劳损）和占用空间方面的效果，并询问了多语言用户如何适应这些弦键盘，是否需要为不同语言优化不同的弦。 • vagab0nd提到了一种有趣的实验，尝试在vim中设置类似于演示中的声音效果，但未能实现长时播放。 • spit2wind提到了Plover速记引擎，并询问了在欧洲或其他地方是否有制造这些键盘的厂家。 • DonHopkins详细介绍了Valerie Landau与Doug Engelbart的合作，以及他们共同开发的多项技术和专利，包括用于弦键文本输入的多点触控界面和iPhone上的“TipTapSpeech”应用程序。 • KennyBlanken对弦键盘的 ergonomic（人体工学）方面提出了批评，认为每次按键都需要多个手指的动作，可能会增加重复性劳损的风险。 补充讨论： • 评论中还涉及到了一些技术细节和历史背景的补充，例如对不同弦键盘设备的具体使用方法、技术实现和其在多语言环境下的适应性问题。 • XKCD被Animats引用作为一个幽默的补充，增加了讨论的趣味性。 争议焦点： • 主要争议点在于弦键盘的 ergonomic 可行性。KennyBlanken认为弦键盘可能导致重复性劳损，而其他如neilv和GregDavidson则强调了其在单手操作和便携性方面的优势。
