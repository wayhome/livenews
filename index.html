Can gzip be a language model?

作者: networked · 评分: 297 · 评论: 31 · 2026-09-22 06:08

文章摘要

文章介绍了一个有趣实验：利用 gzip/DEFLATE 的压缩能力进行语言建模。压缩器会优先编码与语料库相似的字节序列，因此可用压缩后长度衡量候选文本的“可预测性”。作者结合滑动窗口和 beam search，让 gzip 根据莎士比亚语料续写文本。结果虽不连贯，却能体现语料特征，说明压缩与预测在实践中确实等价。

展开评论摘要
主要讨论点：围绕“压缩是否等同于语言建模”，讨论利用压缩率进行文本分类、生成与评估，以及传统压缩算法和大模型的关系。 不同观点： • 支持压缩分类：可分别将测试文本与体育、政治、商业语料用 gzip 压缩，压缩后体积最小的类别即为判断结果；该思路与 Waikato 大学研究及 Hutter Prize 有关。 • 语言即压缩：语言模型通过压缩文本捕捉规律，预测与压缩存在联系；但自然语言高度有损、持续演化，因此这种等价关系不稳定。数学证明因歧义更少，可能更适合体现压缩—预测关系。 • 对“大模型≈压缩器”的谨慎态度：n-gram 或压缩模型与神经网络确有联系，但不能据此夸大二者性能接近；有人反问 LLM 相比 gzip 的实际压缩能力。 • “提示词压缩代码/文本”的设想：若固定、可复现地用一个提示生成完整代码库，提示词是否算压缩仍有争议；依赖 git clone 则只是索引或下载，不是真正压缩。 • 生成质量的质疑：gzip 搜索空间极大，beam search 是否接近全局最优并未说明，因此结果最多证明找到的序列可压缩，不能证明其最合理。文章还被批评未真正使用 gzip。 • 跨模态与算法扩展：有人询问 JPEG、视频压缩能否成为视觉模型；也有人提及 zip2zip、bzip2、zstd 等工作。 补充讨论：不同算法优化的是不同统计结构：bzip2 生成重复字符，zstd 偏好空格和换行，未必像人类语言；争议焦点是“可压缩性”究竟代表语义、预测能力，还是仅代表编码器的偏好。
