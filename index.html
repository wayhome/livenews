The first year of free-threaded Python

作者: rbanffy | 评分: 58 | 评论数: 7 | 发布时间: 2025-05-16 09:42
文章摘要

本文总结了Python社区在支持无全局解释器锁（GIL）的多线程版本方面所取得的进展。CPython 3.14.0b1的发布和PyCon 2025的召开标志着这一努力的重要里程碑。无GIL的Python能够更好地利用现代多核CPU和GPU的计算能力，但需要对许多依赖C扩展的包进行审核和修改以确保线程安全。 Quansight团队在多个方面做出了贡献，包括打包工具、绑定生成器、PyData生态系统的基础包及热门依赖包的支持。CPython核心开发者也进行了多项改进，如使warnings模块在无GIL构建中默认线程安全，修复asyncio和ctypes模块中的线程安全问题，以及提升垃圾回收器的性能。 一年前，Python包生态系统在无GIL构建中几乎完全无法运行，但现在情况已显著改善。本文还提到正在努力支持的其他流行包，并提供了一份详细指南以帮助其他开发者更新他们的包以支持无GIL的Python。

You're Right You Are Working Longer and Attending More Meetings (2020)

作者: robtherobber | 评分: 18 | 评论数: 4 | 发布时间: 2025-05-16 09:43
文章摘要

一项由哈佛商学院Raffaella Sadun和Jeffrey Polzer等人进行的研究分析了300万人的工作模式，发现疫情期间远程办公导致工作日平均延长8.2%（约48.5分钟），员工参加的会议数量增加13%，但每次会议时间缩短20%。邮件数量也增加了5.2%，且有更多邮件在工作时间外发送。研究显示，远程工作模糊了生活与工作的界限，导致工作时间更长、更碎片化，员工感到疲惫。尽管会议时间缩短，视频会议的持续专注要求也让员工感到压力。研究还指出，较大的居家空间可能提升远程办公体验，而狭小空间则可能带来不便。总体而言，远程工作对员工的效率和情绪产生了复杂影响。

评论摘要
主要讨论点：疫情期间工作时间增加的影响以及如何有效衡量工作表现 不同观点： • tmckd认为，疫情期间工作时间增加对某些人来说是净收益，因为他们节省了通勤时间，并且因此感到更快乐。他通过个人见闻支持自己的观点，指出很多人因不用通勤而提升了幸福感。 • kleiba引用了数据分析，表明疫情初期工作日平均增加了8.2%（约48.5分钟）。他还提到了欧盟的公司必须遵守时间追踪法律，以防止员工无偿加班，强调了法律对员工的保护作用。 • sublinear主张关注工作输出而非工作时间，认为难以精确追踪员工的工作时间。他们认为自2020年以来最重要的变化是更加注重工作质量，而不是工作时长。他们进一步指出，过去对工作时间的关注是因为很多人不喜欢他们的工作，而通过裁员后留下的员工反而提升了工作效率。此外，将多数交流转移到文字或录音电话也提高了工作效率。 补充讨论： • 讨论中涉及了工作时间与幸福感之间的关系，tmckd通过个人经验说明通勤时间的减少提升了工作满意度。 • kleiba强调了法律对工作时间的保护，特别是在疫情期间，员工可能面临更多无偿加班的问题。 • sublinear提出了工作质量与效率的重要性，并批评了过去对工作时间的过度关注，认为这种转变有利于提升整体生产力。 争议焦点： • 疫情期间增加的工作时间是否对员工有利，tmckd认为是净收益，而kleiba则通过数据指出工作时间的增加可能带来负面影响，需要法律保护。 • 如何有效衡量和评价员工的工作表现，sublinear主张关注输出质量，而非工作时间，反对传统的以时间为基础的评价方式。

A leap year check in three instructions

文章摘要

这篇文章介绍了一种通过位操作快速判断一个年份是否为闰年的方法。传统方法通过一系列的条件判断来确定闰年，而本文提出的优化方法可以在仅使用约3条CPU指令的情况下完成判断： ```cpp bool is_leap_year_fast(uint32_t y) { return ((y * 1073750999) & 3221352463) <= 126976; } ``` 文章首先回顾了典型的闰年判断实现，然后逐步优化，利用模运算的特性进行位操作优化，减少计算开销。接着，文章解释了如何使用乘法和位操作来替代模运算，详细介绍了魔术数字的来源和计算方法。最终的优化版本通过引入Z3求解器，找到合适的常数，使得判断过程无需分支预测，从而提高效率。 这种方法虽然不完全通用，但对于有限年份范围内的判断非常高效，适用于对速度要求较高的场景。
