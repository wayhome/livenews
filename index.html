TIL: You can make HTTP requests without curl using Bash /dev/TCP

作者: mrshu | 评分: 83 | 评论数: 14 | 发布时间: 2026-06-16 16:40
文章摘要

这篇文章介绍了在没有 curl 或 wget 的精简 Docker 容器中，如何使用 bash 内置的 `/dev/tcp` 功能直接发送 HTTP 请求来测试服务连通性。 核心方法是通过 `exec 3<>/dev/tcp/host/port` 打开 TCP 套接字，然后手动构造 HTTP 请求并写入文件描述符。`/dev/tcp` 并非真实设备文件，而是 bash 内部处理的重定向机制。 需要注意：这不是真正的 HTTP 客户端，不支持 TLS、重定向、压缩等高级特性；必须添加 `Connection: close` 头避免连接挂起；这是 bash 特有功能，非 POSIX 标准；需要编译时启用 `--enable-net-redirections` 选项。 适用场景：在无法安装工具的精简容器中进行快速连通性测试，日常工作仍应使用 curl。

评论摘要
主要讨论点：Bash的/dev/tcp功能及其在实际场景中的使用价值 不同观点： • **实用派**：多位用户分享实际应用案例，如在Docker容器中检查健康状态、内部网络连通性测试等，认为这是在缺少curl/wget等工具时的有效替代方案 • **谨慎派**（basilikum）：强调这只是TCP socket操作而非真正的HTTP客户端，警告这种方法不能正确解析HTTP协议，仅适合测试调试，在生产环境中会出问题，建议使用nc或curl等成熟工具 • **安全关注派**（dchest）：从攻击面角度分析，认为评论区大量讨论如何绕过安全限制，反映了GNU工具功能过载带来的安全隐患 • **怀旧派**：多位用户提到这让他们想起早年用telnet连接80端口发送HTTP请求的经历 补充讨论：有趣的是orthogonal_cube用此技术编写自动化脚本时被CrowdStrike误判为恶意软件，体现了这类底层网络操作的敏感性。simonw补充example.com是少数仍支持HTTP的测试域名之一。

SubQ 1.1 Small是一个采用亚二次稀疏注意力(SSA)架构的AI模型，专为处理超长上下文设计。核心特点包括： 1. **超长上下文能力**：支持最高1200万token，在针在草堆测试中接近完美检索，注意力计算量减少近1000倍 2. **计算效率**：在100万token时，相比密集注意力减少64.5倍计算量，速度比FlashAttention-2快56倍 3. **性能表现**：在RULER(128K)测试达99.12%，GPQA Diamond达85.4%，LiveCodeBench达89.7%，保持了强大的通用推理能力 4. **技术创新**：用线性扩展的稀疏注意力替代O(n²)密集注意力，通过内容相关性而非固定位置模式路由注意力 该模型旨在直接处理完整代码库、文档集等大型工件，无需传统的检索管道和分块策略。

评论摘要
主要讨论点：SubQ 1.1 Small模型发布引发的技术透明度与实际效果争议 不同观点： • **质疑透明度派**：批评该实验室不愿分享架构细节和代码，与中国实验室开放态度形成对比；认为这是第二次发布缺乏技术细节的报告，难以建立信任；指出自首次发布以来一直"只说不做" • **技术乐观派**：认可SSA稀疏注意力机制将O(n²)复杂度降至线性的突破；支持在模型架构层面解决上下文问题而非依赖外部内存；对1M到12M tokens的近乎完美检索能力表示赞赏，认为可以将整个小型代码库纳入单个提示 • **谨慎怀疑派**：质疑RULER基准测试仅到128k tokens而Needle测试却声称支持12M tokens的矛盾；质疑为何效果能从1M扩展到12M却不继续到24M或48M；认为与FlashAttention-2比较不诚实，因该技术已过时2年；认为宣传过于炒作化 • **实用关注派**：关注成本优化方向，希望降低高质量模型（如Opus 4.6）的使用成本；询问服务12M上下文所需硬件配置和极限速度表现 补充讨论：尽管有第三方评估，但整体透明度不足导致社区对其真实性能持保留态度，这与之前发布时的质疑如出一辙。
