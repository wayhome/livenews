OpenWrt Two Approval

作者: todsacerdoti | 评分: 123 | 评论数: 11 | 发布时间: 2025-03-29 03:34
文章摘要

本文主要介绍了OpenWrt项目成员John Crispin发起的一个投票结果，该投票旨在批准他开始开发OpenWrt "Two"。这款新设备将具备MT7988芯片、10G SFP接口、5G和多端口2.5G/1G铜缆接口，以及Tri-band Wi-Fi 7等升级功能。OpenWrt "Two"将由GL.iNet生产，并计划在美国和欧盟地区进行分销，预计价格在250美元左右，部分收益将捐赠给OpenWrt项目，预计2025年底上市。投票已结束并通过，获得了多位成员的支持。

Plain – a web framework for building products with Python

作者: brylie | 评分: 106 | 评论数: 21 | 发布时间: 2025-03-29 03:55
文章摘要

Plain 是一个基于 Python 的 web 框架，是 Django 的分支，旨在引入新想法并保留成熟的模式。它支持通过单个命令进行本地开发，并提供多种包以满足不同需求，如构建产品、身份验证、后台管理、开发工具和前端集成等。Plain 被设计用于创建新业务、内部工具或个人项目，其主要包包括： 1. **基础包**：如 URL、视图、模板、表单等核心功能。 2. **认证包**：包括用户认证、OAuth 支持、无密码登录等。 3. **管理包**：自定义管理后台、功能标志、客户支持等。 4. **开发包**：提供本地开发环境、测试、代码格式化等工具。 5. **前端包**：集成现代 CSS、JavaScript 工具，支持文件路由和资源自托管。 Plain 通过模块化设计，使主要功能可选并能独立演进。

评论摘要
主要讨论点：Plain框架作为Django框架的 fork，引发的社区反应和争议 不同观点： • danpalmer：认为Plain作为Django的fork可能会导致社区贡献的分裂，导致两个项目都无法充分受益。danpalmer希望Plain能以一种不分割社区的方式来贡献Django。 • miiiiiike：提到Django的REST框架问题，例如Bug追踪器变得私有以及项目正在寻找新的维护者。他指出Django社区存在一定的封闭性和贡献障碍，但也认为需要采取措施来改进Django，而不是简单地进行fork。 • phowat：支持开源软件的fork文化，认为fork可能带来更好的软件，即便fork最终没有成功，也能将一些好的想法反馈给原项目。 • jgb1984：明确表示会继续使用Django，对Plain没有兴趣。 • philips：建议Plain的“关于”页面应更针对已经熟悉Django的用户进行说明。 • librasteve：认为Plain在某些方面是正确的，比如针对Django的局限性进行创新，但也认为Plain在某些技术选择上可能走错了方向，并推荐了另一个项目。 • babuloseo：质疑Plain与django-ninja.dev的区别，不明白Plain的独特价值。 • sroerick：作为Django的深度用户，不理解Plain的“为什么”存在，认为Plain可能增加了复杂性，特别是在第三方生态系统不健全的情况下。 • petr25102018：理解Plain作为fork的原因，认为Django领导层无法突破旧有范式，每个fork或第三方应用都是有意义的尝试。 • mcdirty：认为使用Plain存在业务风险，因为相比Django，Plain的文档和维护者较少。 • JodieBenitez：在实际运行Plain的 starter kit时遇到技术问题，对Plain的开发体验提出质疑，特别是SSL证书设置。 • mychael：质疑Plain的独特价值，认为Plain只是对Django做了一些表面的名称替换。 • pknerd：偏题讨论了“llms.txt”的概念，建议为LLM（大型语言模型）设置类似robots.txt的标准。 • system7rocks：期待一个真正的跨平台Python框架，并对Plain框架的局限性感到失望。 补充讨论： • 社区对Django的贡献文化和维护者问题存在一定的争议，部分开发者认为Django的社区比较封闭，贡献难度大。 • 对Plain的fork行为存在分歧，一部分人认为fork会分裂社区贡献，另一部分人认为fork是开源文化的一部分，可能带来积极变化。 • Plain的独特价值和与现有Django扩展（如django-ninja.dev）的区别不够清晰，导致部分用户对Plain的存在意义感到困惑。 • 技术问题如SSL证书设置和文档不完善也影响了用户对Plain的第一印象。 • 有用户对Django本身的局限性提出批评，认为其在某些功能上（如REST API和任务管理）不如其他框架。 争议焦点： • Plain作为Django的fork是否会分裂社区贡献，从而对两个项目都产生负面影响。 • Plain是否提供了足够的独特价值以区别于Django和现有的Django扩展。

文章摘要

Xee是由Martijn Faassen开发的基于Rust的现代XPath和XSLT引擎。Xee代表"XML Execution Engine"，支持最新版本的XPath和XSLT。XPath是一种用于查询XML的编程语言，而XSLT则利用XPath进行XML文档的转换。Xee提供了一个命令行工具`xee`用于XPath查询，以及一个Rust库`xee-xpath`用于在Rust中执行XPath查询。 该项目始于2023年，由Faassen的客户Paligo发起，旨在用Rust实现现代XPath和XSLT。尽管XML技术已不如从前流行，但它仍在许多领域广泛使用，如SVG和MathML。Xee的Rust实现不仅为Rust生态带来现代XML技术，还可能通过WASM在浏览器中运行，并与其他语言（如PHP和Python）集成。 Xee实现了XPath的现代版本，具备功能性编程语言特性，如类型系统、变量、函数定义、条件和循环等。Faassen曾开发了Python的XML库lxml，重新进入XML领域后，他结合Rust和XML的专业知识开发了Xee。
