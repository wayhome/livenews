文章摘要

芬兰和英国研究团队首次发现，心肌梗塞可能是一种感染性疾病。研究显示，冠状动脉中的胆固醇斑块可能含有细菌形成的无症状生物膜，病毒或其他外部诱因可能激活这些休眠细菌，引发炎症反应，导致斑块破裂并形成血栓，最终引发心肌梗塞。这一发现挑战了传统观点，为心肌梗塞的诊断、治疗和疫苗研发提供了新方向。研究由坦佩雷大学等机构合作完成，成果发表于《美国心脏协会杂志》。

RIP pthread_cancel

作者: robin_reala | 评分: 142 | 评论数: 14 | 发布时间: 2025-09-13 17:20
文章摘要

curl团队在8.16.0版本中尝试使用pthread_cancel来中断getaddrinfo()调用，以解决DNS解析时的线程阻塞问题。但发现被取消的线程会在读取/etc/gai.conf配置时发生内存泄漏，因为glibc未处理这种情况下的资源释放。由于潜在的内存泄漏风险不可接受，团队决定在#18540中移除该功能，宁可接受DNS解析时的阻塞等待。建议用户可改用c-ares库进行异步DNS解析，但功能会有一定限制。

评论摘要
主要讨论点：`getaddrinfo` 缺乏标准化的超时设置机制及其替代方案的讨论。 不同观点： • **超时设置的缺失问题** - `getaddrinfo` 缺乏内置超时设置，导致开发者需要依赖系统配置（如 Linux 的配置文件）或外部库，灵活性不足。 - 不同应用场景对 DNS 查询的耗时容忍度不同，需要代码级配置。 • **现有解决方案的批评** - `pthread_cancel` 被批评为设计不良，因为它与正常的错误处理和堆栈展开机制分离，可能导致资源泄漏或状态损坏。 - 内核信号处理机制（如 `EINTR`）被提出作为更优的替代方案，但用户空间的实现复杂性较高。 • **替代方案的提议** - 使用异步 DNS 解析 API（如 `getaddrinfo_a`、`GetAddrInfoExW`）或第三方库。 - 将 DNS 解析移至操作系统服务层，利用本地缓存和 RPC 机制，避免线程控制问题。 - 使用 `io_uring` 或工作线程池实现异步解析，避免直接取消线程。 • **实现细节的争议** - `glibc` 是否应在每次调用 `getaddrinfo` 时解析配置文件（如 `/etc/gai.conf`），或仅在初始化时加载并监听变更（如通过 `inotify`）。 - 线程池或常驻工作线程的提议引发讨论，认为可以通过标志位控制线程退出，而非强制取消。 补充讨论： - **历史遗留问题**：从早期 `gethostbyname` 到现代 API，DNS 解析的阻塞问题长期未解决。 - **语言差异**：C++ 的异常处理可能与 `pthread_cancel` 更好地集成，但 C 缺乏此类机制。 - **维护者视角**：实现取消机制的复杂性使得 C 库维护者需要更多宽容，尤其是涉及资源泄漏时。

RFC9460: SVCB and HTTPS DNS Records

作者: codewiz | 评分: 3 | 评论数: 0 | 发布时间: 2025-09-14 00:26
文章摘要

RFC 9460定义了SVCB（服务绑定）和HTTPS两种DNS资源记录类型，旨在通过DNS查询获取连接网络服务（如HTTP源站）所需的配置信息。SVCB记录允许服务通过多个备用端点提供，每个端点可关联不同参数（如传输协议配置），并支持未来扩展用途（如加密TLS ClientHello的密钥）。HTTPS RR是SVCB针对HTTP的变体，通过预先提供连接信息，提升性能和隐私性。这两种记录还解决了CNAME无法处理的顶点域名别名问题，支持服务运营商通过DNS统一配置参数（如网络位置、协议及密钥信息）。标准适用于需要优化连接性能和实现灵活服务委派的场景。
