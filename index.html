An Empirical Study of Harness Design for Coding Agents

作者: wek · 评分: 62 · 评论: 5 · 2026-09-18 13:06

文章摘要

本文系统研究编码智能体框架中规划、动作空间和上下文管理三类组件。基于四个模型及两项基准测试发现：上下文管理在窗口受限时更重要，先规则删减再由模型总结最有效；规划对弱模型提升准确率、对强模型主要节省成本；预定义工具有利于不擅长Bash的模型，而强Bash模型使用纯Bash接口成本更低。研究为按模型与预算设计框架提供依据。

展开评论摘要
主要讨论点：AI Agent 的效果取决于模型、工具、规划、上下文管理等“整体组合”，而非单一模型能力；应针对任务和资源预算进行适配。 不同观点： • **组合优化观点**：gps372以汽车作比喻，认为性能不应归因于发动机（模型） alone，还取决于轮胎、变速箱、车身等；Agent 同样可通过 ReAct、Plan-and-Execute、混合架构，以及无状态/有状态/RAG 等方式，在准确率、分析深度与成本间取舍。 • **条件化工具观点**：研究结论显示，弱模型从规划和预定义工具中获益；具备较强 Bash 能力的模型使用 Bash-only 往往成功率更高、成本更低。上下文管理可延长执行轨迹，规划还能减少过早放弃或重复验证。 • **结论“直观但缺乏新意”观点**：embedding-shape认为上述发现大多符合常识，关键价值在于强调 Harness 应依据模型能力、任务类型和预算选择，而非采用默认配置；同实验室配套的模型与 Harness 往往更优，可能因为训练使用了自身执行轨迹。 • **研究代表性质疑**：vblanco指出研究基于 Nemotron 和 Mistral，未覆盖 Qwen、DeepSeek 等当前主流模型，因此对便宜中国模型及 Claude/GPT 的适用性有限。 • **前沿模型或不需规划工具**：themgt引用 Claude Code 的工具变更，认为 Anthropic 似乎判断前沿模型已不再需要会话内 Todo/规划工具，但这更像产品实践，未必能完全替代系统性实验结论。 补充讨论：争议焦点在于规划工具对强模型是否仍有必要，以及研究结论能否跨模型、任务和 Harness 泛化。
