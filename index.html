Public secrets exposure leads to supply chain attack on GitHub CodeQL

作者: cyberbender | 评分: 174 | 评论数: 6 | 发布时间: 2025-03-30 19:54
文章摘要

本文介绍了GitHub CodeQL潜在供应链攻击的发现过程。攻击始于一个公开暴露的秘密，有效时间仅1.022秒。利用这一秒，攻击者可以在使用CodeQL的GitHub Actions工作流中执行代码，影响GitHub云平台和GitHub Enterprise。攻击者可能借此窃取私有代码库的源代码、盗取GitHub Actions中的凭证、在内网基础设施上执行代码，并进一步发动供应链攻击。 研究人员通过自建的Actions Artifacts Secret Scanner工具发现了这一漏洞（CVE-2025-24362）。GitHub Actions工作流会生成GITHUB_TOKEN，用于与代码库交互，若权限过高，令牌泄露将导致严重后果。尽管发现了潜在风险，GitHub表示尚未发现其平台或系统受到实际攻击的证据。

评论摘要
主要讨论点：围绕不同话题的评论，包括姓名与域名、技术权限问题、对响应时间的评价、具体技术工具的影响以及网站性能问题。 不同观点： • 关于姓名与域名： - [helsinki] 表达了对拥有与自己姓氏相关域名（praetorian.com）的个人愿望，涉及到个人身份与域名所有权的关联。 • 关于技术权限问题： - [nyrikki] 质疑了一个临时 token 为什么拥有创建新部署和生成工件证明的权限，并对修复措施中仅禁用调试日志而不明确说明是否调整了 token 权限表示不满。 • 关于响应时间： - [junto] 对 GitHub 的响应时间表示赞赏，认为其反应速度非常 impressive。 • 关于具体技术工具的影响： - [ryao] 提到在 OpenZFS 的 Pull Requests 中使用 CodeQL 并没有问题，因为 OpenZFS 的代码是公开的，没有秘密，暗示该问题在代码公开的情况下不构成威胁。 • 关于网站性能问题： - [bloqs] 抱怨网站性能极差，滚动都成问题，直接影响用户体验。 补充讨论： - 评论中涉及多个不同话题，从个人兴趣到技术安全，再到用户体验问题，展示了讨论的多样性。 - 争议焦点可能在于技术权限的合理性及安全性，特别是临时 token 的权限问题，这是 [nyrikki] 提出的主要关切。

BreezeWiki 是一个让 Fandom 上的 wiki 页面更易读的工具。它移除广告、视频和推荐内容，提供简洁的页面，减少设备负担和数据消耗。用户只需将网址中的 "fandom.com" 替换为 "breezewiki.com" 即可使用。若希望自动重定向，可安装相关浏览器扩展。BreezeWiki 由多个独立运行的镜像网站组成，一个下线时其他仍可使用。它并非 Fandom 的替代品，不能编辑或创建页面，用户若需创建 wiki，可尝试 Miraheze。用户反馈显示，BreezeWiki 解决了 Fandom 页面因广告过载而加载缓慢的问题。

The surprisingly simple reason kids have imaginary friends

作者: domofutu | 评分: 27 | 评论数: 7 | 发布时间: 2025-03-28 07:22
文章摘要

文章探讨了孩子为何会有想象中的朋友，强调这种现象非常普遍，且多发生于幼年时期。根据心理学教授Tracy Gleason的研究，这些想象中的朋友可以是无形的人物、玩具、甚至是不寻常的物品，如一罐番茄糊。孩子们通过与这些虚构角色互动，可以在安全、无压力的环境中理解复杂的社交关系，同时也能从中获得乐趣。研究表明，65%的孩子在7岁前有过想象中的朋友。这些朋友有时会表现出一些小挑战，如争吵或拒绝玩耍，帮助孩子练习处理真实社交中的问题。文章总结，想象朋友的主要作用是为孩子提供娱乐，并帮助他们探索社交生活的规则和动态。
