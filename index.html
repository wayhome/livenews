Brush (Bo(u)rn(e) RUsty SHell) a POSIX and Bash-Compatible Shell in Rust

作者: voxadam | 评分: 52 | 评论数: 6 | 发布时间: 2025-05-06 18:47
文章摘要

**Brush** 是一个用 Rust 实现的兼容 POSIX 和 bash 的 shell，支持 Linux 和 macOS，并通过 WSL 在 Windows 上实验性运行。它功能齐全，可作为日常使用的交互式 shell，能执行大多数 sh 和 bash 脚本，但存在一些已知的兼容性限制，如部分 `set` 和 `shopt` 选项未完全实现。目前不建议在生产环境中使用，但欢迎贡献和反馈。安装方式包括通过 `cargo install` 或 Nix、Arch Linux 的 AUR 进行安装。项目采用 MIT 许可，主要通过与现有 shell 对比进行测试，拥有 550+ 个测试案例。

评论摘要
主要讨论点：不同Unix shell的实现及其特点，尤其是关于POSIX/bash兼容性和使用新语言（如Python、Rust）的讨论。 不同观点： • chubot认为OSH是目前最兼容POSIX和bash的shell，并提到OSH通过"可执行规范"的实现方式（先用Python编写，再转译为C++），提高了运行速度，同时具备内存安全性。此外，OSH项目中的YSH被设计为一种更现代的shell，支持JSON等功能，目标是成为终极的粘合语言。 • d4mi3n则偏好于Nushell，一个用Rust编写的shell，强调了其超越POSIX、支持更结构化数据处理的能力，认为这是对传统文本流处理的一种进步。 • Ericson2314关心的是跨平台兼容性，尤其是希望找到一个能在Windows上运行的bash兼容shell，以避免使用CygWin或MSYS2，并希望将其用于Nix on Windows项目。 • Pet_Ant指出了Fish shell，虽然也是用Rust类似的非传统语言编写，但并不兼容POSIX或bash，并提供了相关的设计文档链接。 • Muromec提出了OSH与fzf脚本的兼容性问题，指出其在使用某些fzf脚本时遇到不兼容的情况。 补充讨论： • 各shell在POSIX和bash兼容性上的差异是讨论的核心，尤其是OSH、Nushell和Fish在这些方面的不同设计选择。 • 不同用户对shell的需求不同，有的重视兼容性（如Ericson2314），有的则希望探索更现代的特性（如d4mi3n）。 • 性能和内存安全是chubot支持OSH的重要论据，而Muromec则提醒了实际使用中可能遇到的兼容性问题。 • 争议的焦点在于如何平衡传统兼容性和现代功能创新，以及不同实现语言对shell性能和功能的影响。
