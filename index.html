YAML: The Norway Problem (2022)

作者: carlos-menezes | 评分: 54 | 评论数: 8 | 发布时间: 2025-04-12 22:10
文章摘要

本文讨论了YAML中的一个常见问题，称为“挪威问题”。在YAML中，挪威的ISO 3166-1 ALPHA-2国家代码"NO"会被解析为布尔值"false"，导致数据错误。YAML的布尔值解析规则允许诸如"yes/no"、"true/false"、"on/off"等值被自动转换，因此像"NO"这样的缩写会引发问题。例如，一个包含国家代码的YAML列表在解析后会将"NO"转为"false"。解决方案包括将有问题的值用双引号转义，或使用如StrictYAML等库来避免自动转换。此外，YAML还会将某些版本号和姓氏如"Null"误转为数字或NULL。文章由比利时前端开发者Bramus撰写，他目前在Google担任Chrome开发者关系工程师。

评论摘要
主要讨论点：YAML 使用中的问题及其解决方案 不同观点： • [dissent] 认为如果有人因为 YAML 的问题而需要调试，那他们可能写了太多 YAML。他建议通过高层次语言的类型来生成 YAML，从而避免这些问题。 • [quechimba] 分享了一个实际案例，指出因为 YAML 问题导致挪威用户无法注册，且花费了较长时间才找到问题根源。 • [thyrsus] 提到在使用 Ansible 时，由于 YAML 类型不一致，需要频繁使用 "| bool" 过滤器来处理变量。 补充讨论： • [gnabgib] 提供了几个与 YAML 相关的讨论链接，表明 YAML 问题在社区中引起了广泛关注和讨论，包括 YAML 的复杂性和替代方案。 • [singpolyma3] 简单指出字符串应该用引号引起来，暗示这是避免某些 YAML 问题的一个方法。 • [ashishb] 质疑这个问题的普遍性，声称自己使用 YAML 超过五年从未遇到此类问题，并提到使用 `yamllint` 工具可以检测到此类问题。 • [firesteelrain] 详细解释了问题的原因，指出 PyYAML 的 `load()` 函数使用 YAML 1.1 标准，而 YAML 1.2 引入了不兼容的更改。他提到可以使用 `BaseLoader` 作为一种解决方案，并指出 PyYAML 因为维护模式而未支持 YAML 1.2，建议使用 `ruamel.yaml` 作为替代。 争议焦点： • YAML 是否真的带来了普遍的问题，以及是否有必要完全弃用 YAML 或采用其他工具和标准（如 YAML 1.2 或 `ruamel.yaml`）来解决这些问题。 总结：讨论围绕 YAML 在实际应用中的问题、解决方案以及社区对 YAML 复杂性的广泛关注展开。不同用户根据自身经验提出了不同的看法和建议，包括代码生成、工具使用和标准升级等。

CERN发布了一份关于未来环形对撞机（FCC）可行性的报告。该报告汇集了全球上千名物理学家和工程师的研究成果，旨在为欧洲粒子物理战略提供参考，并将在未来几个月由CERN理事会进行评估。FCC是一个 proposed 周长约91公里的对撞机，计划在2040年代接替目前的大型强子对撞机（LHC）。其科学目标包括研究希格斯玻色子及其他基础物理学问题。FCC计划分两个阶段实施：首先是电子-正电子对撞机，随后是质子-质子对撞机，碰撞能量高达100 TeV。报告涵盖了物理目标、地质、土木工程、技术基础设施、环境影响、研发需求、社会经济效益及成本等方面。电子-正电子阶段预计耗资150亿瑞士法郎，建设期为12年左右。CERN承诺该项目将遵循可持续发展原则，并尽量减少环境影响。最终决定将在2028年左右做出。
