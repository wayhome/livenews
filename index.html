Log level 'error' should mean that something needs to be fixed

作者因大量爬虫使用老旧浏览器（尤其是Chrome）的User-Agent抓取数据（可能用于LLM训练），为了保护个人博客和Wiki资源，实验性屏蔽了这些请求。误判用户可联系作者并提供浏览器信息。特别说明：archive.*等存档网站因行为类似恶意爬虫（使用旧版Chrome标识、IP地址混乱等）也被屏蔽，建议改用更规范的archive.org。

评论摘要
主要讨论点：如何合理划分日志级别（如 ERROR、WARNING 等）的标准及其实际应用中的争议。 不同观点： • **基于影响程度划分**（eterm） - Critical/Fatal：需立即人工干预（如系统不可恢复）。 - Error：可自动恢复但需尽快修复（如数据丢失）。 - Warning：可自动恢复但需后续跟进（如预期外的边缘情况）。 - 例子：JSON 解析失败是否属于 Error 取决于责任方。 • **部署环境决定论**（mfuzzey、AndroTux） - 日志级别需结合具体部署场景判断（如网络问题可能是本地或远程故障）。 - 争议焦点：程序无法自主区分错误来源（如配置错误 vs. 外部故障）。 • **操作结果导向**（teo_zero） - 以操作是否完成为标准： - 警告：可重试的临时问题（如连接超时）。 - 错误：彻底失败（如多次重试后仍无法连接）。 - 反对单纯区分错误来源（内部/外部）。 • **严格告警派**（jayofdoom、jillesvangurp） - ERROR 必须触发告警且零容忍，需明确文档定义（如 OpenStack 的规范）。 - 警告用于潜在系统性风险（如预测性故障）。 • **日志可操作性**（rwmj、HarHarVeryFunny） - 错误信息需包含具体修复动作，避免“狼来了”效应。 - 争议：是否所有 ERROR 都需人工干预（如 HTTP 429 可能应为 WARNING）。 补充讨论： - **日志滥用问题**（alexwasserman）：低级别日志混用高级别关键词（如 WARN 消息含“error”）会导致监控误报。 - **动态分类需求**（makeitdouble）：现代日志系统需结合外部工具（如 New Relic）进行异常检测，而非仅依赖基础级别。 - **模糊场景处理**（dnautics）：连续数据库超时可能是 trivial 或严重硬件故障，需上下文判断。

美国一项针对246名车祸死亡司机的6年研究发现，41.9%的司机血液中含有高浓度THC（平均30.7ng/mL），远超各州规定的驾驶限制标准。研究指出，大麻合法化前后这一比例（42.1% vs 45.2%）无明显变化，说明合法化并未影响吸食大麻后驾驶的行为。研究者呼吁加强"吸食大麻后禁止驾驶"的公共卫生宣传，应像对待酒驾一样重视大麻驾驶的危害。该研究将在2025年美国外科医生学会临床大会上发表。
