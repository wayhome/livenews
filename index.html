YAML: The Norway Problem (2022)

作者: carlos-menezes | 评分: 74 | 评论数: 10 | 发布时间: 2025-04-12 22:10
文章摘要

本文讨论了YAML中的一个常见问题，称为“挪威问题”。在YAML中，挪威的ISO 3166-1 ALPHA-2国家代码"NO"会被解析为布尔值"false"，导致数据错误。YAML的布尔值解析规则允许诸如"yes/no"、"true/false"、"on/off"等值被自动转换，因此像"NO"这样的缩写会引发问题。例如，一个包含国家代码的YAML列表在解析后会将"NO"转为"false"。解决方案包括将有问题的值用双引号转义，或使用如StrictYAML等库来避免自动转换。此外，YAML还会将某些版本号和姓氏如"Null"误转为数字或NULL。文章由比利时前端开发者Bramus撰写，他目前在Google担任Chrome开发者关系工程师。

评论摘要
主要讨论点：YAML 使用中的问题和争议 不同观点： • [kazinator] 认为在 Lisp 中可以通过切换到专用包来解决符号读取问题，例如将文件中的单词读取为符号，这样即使出现 "NIL"，也只会被视为该包中的一个普通符号，与特殊对象无关。 • [dissent] 认为如果有人非常担心 YAML 的问题，可能是因为他们写了太多 YAML。遇到类似问题时，应该将 YAML 映射到高级语言的类型，并从中生成 YAML，而不是手动调试 YAML。 • [firesteelrain] 指出问题源于 `pyyaml` 的 `load()` 函数使用了完整的 YAML 1.1 标准。虽然可以使用 `BaseLoader` 将所有内容解释为字符串，但这只是一种权宜之计。YAML 社区对于 PyYAML 不支持 YAML 1.2 感到不满，因为 YAML 1.2 引入了不兼容的改动。为了支持 YAML 1.2，可以使用 `ruamel.yaml`，它是从 PyYAML 分支出来的。 • [thyrsus] 提到在使用 Ansible 时，由于不同版本的 YAML 类型处理不一致，经常需要在逻辑语句中对变量应用 `| bool` 过滤器。 • [umanwizard] 引用 "宽以待人" 的原则，暗示 YAML 解析器在处理不规范输入时过于宽松，导致问题频发。 • [singpolyma3] 简单建议应始终引用字符串以避免混淆。 • [ashishb] 质疑这个问题是否常见，他使用 YAML 已有五年多，从未遇到过类似问题。他还提到使用 `yamllint` 工具可以提前发现此类问题，例如提示 "truthy value should be one of [false, true]"。 补充讨论： • YAML 1.1 和 1.2 版本之间的不兼容性以及社区对 PyYAML 维护状态的不满。 • 使用工具（如 `yamllint`）可以帮助提前发现和解决 YAML 中的潜在问题。 • 不同应用场景（如 Ansible）中 YAML 处理的不一致性，导致用户需要手动调整。 争议焦点：YAML 解析的宽松性以及不同版本之间的不兼容问题是否是用户使用中的主要困扰。

CERN发布了一份关于未来环形对撞机（FCC）可行性的报告。该报告汇集了全球上千名物理学家和工程师的研究成果，旨在为欧洲粒子物理战略提供参考，并将在未来几个月由CERN理事会进行评估。FCC是一个 proposed 周长约91公里的对撞机，计划在2040年代接替目前的大型强子对撞机（LHC）。其科学目标包括研究希格斯玻色子及其他基础物理学问题。FCC计划分两个阶段实施：首先是电子-正电子对撞机，随后是质子-质子对撞机，碰撞能量高达100 TeV。报告涵盖了物理目标、地质、土木工程、技术基础设施、环境影响、研发需求、社会经济效益及成本等方面。电子-正电子阶段预计耗资150亿瑞士法郎，建设期为12年左右。CERN承诺该项目将遵循可持续发展原则，并尽量减少环境影响。最终决定将在2028年左右做出。
