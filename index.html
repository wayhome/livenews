New Linux udisks flaw lets attackers get root on major Linux distros

作者: smig0 | 评分: 77 | 评论数: 4 | 发布时间: 2025-06-20 09:05
文章摘要

两项新发现的本地权限提升（LPE）漏洞可让攻击者在多个主流Linux发行版上获得root权限。第一个漏洞（CVE-2025-6018）存在于openSUSE Leap 15和SUSE Linux Enterprise 15的PAM配置中，允许本地攻击者获得"allow_active"用户权限。第二个漏洞（CVE-2025-6019）位于libblockdev中，通过udisks守护进程（大多数Linux发行版默认运行）使"allow_active"用户提升至root权限。利用这些漏洞可以快速完全控制系统，尤其第二个漏洞单独存在时也极具威胁。Qualys TRU已开发出概念验证（PoC） exploit，并成功在Ubuntu、Debian、Fedora和openSUSE系统上测试。管理员需立即打补丁以防风险。

评论摘要
主要讨论点：开源软件的安全问题及其影响范围 不同观点： • [udev4096] 认为该问题已经相当旧，并且只影响 openSUSE 系统，指出标题具有极大的误导性。该评论者强调了该漏洞的有限影响范围，并暗示讨论或报道存在夸大。 • [hbogert] 则从更广泛的角度谈论了 Linux 桌面使用的长期体验，指出 Linux 在功能和安全性上始终是一个“永恒的实验”。该评论暗示了对 Linux 系统在安全性和功能稳定性方面的持续担忧，似乎对开源软件的整体安全性持怀疑态度。 • [teddyh] 提供了具体的时间信息，指出该问题已经在 Debian 系统中于两周前得到修复，暗示问题并没有当前讨论所暗示的那么严重，至少在 Debian 系统上已经得到解决。 补充讨论： • 不同发行版之间的安全问题和修复时间差异，例如 openSUSE 和 Debian 的对比。 • 评论中的争议焦点在于该漏洞的实际影响范围和讨论的准确性，尤其是标题是否误导读者。 • 对 Linux 系统长期安全性和功能稳定性的哲学性思考，涉及 Linux 系统作为“永恒的实验”的性质。

Show HN: Ariadne – A Rust implementation of aperiodic cryptography

作者: ciphernomad-org | 评分: 24 | 评论数: 9 | 发布时间: 2025-06-23 03:54
文章摘要

Ariadne Protocol 是一个由 CipherNomad 提出的新型加密架构，旨在实现非周期性、状态依赖的加密转换。该协议基于 Labyrinth（一个大型确定性生成的二叉树）和 Thread（秘密的、非周期性的路径）两个核心概念。其主要创新在于通过加密虚拟机（CVM）动态计算每块数据的加密路径，而无需存储或传输路径信息。Ariadne Suite 是该协议的 Rust 实现，包含核心架构、加密原语和高层次协议等组件，如 `ariadne-core`、`ariadne-generator` 和多种 AEAD 协议。该项目为开源研究，作为公共资源发布，但仍处于实验阶段，尚未经过第三方安全审计，不建议用于生产环境。

评论摘要
主要讨论点：Ariadne密码方案的安全性、实现方式及其潜在问题 不同观点： • [willvarfar] 认为该方案可能在某些路径上使用不安全的密码（如2DES），从而导致更广泛的安全漏洞。具体而言，中间人攻击可能通过这些不安全状态大幅减少搜索空间，从而威胁整体安全。 • [kennethallen] 提出两个问题：首先，使用固定大小状态的PRNG不可能永远不重复，最终会周期性重复；其次，质疑该方案在实际和理论上的优势，认为其复杂性未必带来比传统认证模式（如AES+GCM）更好的保密性和防篡改保护，且后者有并行加密、硬件支持等实际优势。 • [vintermann] 认为将算法描述为“自修改”或“非周期性”并不能增加安全性，只是改变了模型的表述方式，使得分析更困难。但这种困难对攻击者同样适用，且如果攻击者找到更简洁的描述方式，这种安全性增益将不存在。 • [ramchip] 将该方案与Signal协议中的KDF链进行比较，指出该方案通过派生新密钥选择新函数的方式，类似于在函数族中选择新函数，质疑其独特性。 • [CharlieTrip] 作为密码学研究者，强调缺乏数学表述使得评估该协议的安全性变得困难。同时指出该方案的“OTP部分”看起来奇怪，需重点关注密钥扩展和加密路径重复的问题。 • [Asraelite] 关注该方案是否或如何适应后量子时代，提出是否有可能进行相关调整。 • [ur-whale] 对“该密码是非周期性的”这一声明表示怀疑，认为在有限物理机器上运行代码不可能真正实现理论上的非周期性。 补充讨论： • [stop50] 指出链接错误，提供了一个错误的链接地址，未直接参与安全性讨论。 争议焦点： • 该方案是否在某些路径上存在安全漏洞，特别是通过不安全状态（如2DES）导致中间人攻击。 • 该方案的实际与理论优势是否显著，特别是与传统加密模式（如AES+GCM）相比。 • 将算法描述为“自修改”或“非周期性”是否真正增加安全性，或只是增加了分析难度。 • 该方案的密钥扩展及加密路径重复问题是否会导致潜在的安全隐患。

Polystate: Composable Finite State Machines

文章摘要

**Polystate: 可组合的有限状态机** Polystate是一个用于构建和操作可组合有限状态机（FSM）的库，通过类型组合实现状态机的可组合性与类型安全。其核心设计理念包括： 1. **类型级状态记录**：通过类型系统记录状态机的状态。 2. **可组合性**：通过类型组合实现状态机的模块化与复用。 3. **简化复杂状态机构建**：通过简单的状态组合构建复杂的状态机，实现语义级别的代码复用。 4. **自动生成状态图**：基于声明自动生成状态图，帮助用户直观理解程序行为。 使用步骤： 1. 通过命令 `zig fetch --save git+https://github.com/sdzx-1/polystate.git` 添加依赖。 2. 在 `build.zig` 中声明依赖并导入模块。 3. 通过组合简单状态构建复杂状态机，定义全局行为。 Polystate提供了两个核心类型：FST（状态机类型）和GST（全局状态类型）。FST为枚举类型，定义状态机所有状态；GST为结构体，存储全局数据。状态处理函数可访问GST，但应仅使用与当前状态相关的数据。 该库旨在提高命令式编程的正确性和代码可组合性，是有限状态机编程的理想选择。
