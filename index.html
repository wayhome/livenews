Python's new t-strings

作者: tambourine_man | 评分: 242 | 评论数: 24 | 发布时间: 2025-04-21 04:31
文章摘要

Python 3.14将引入t-strings（模板字符串），以增强字符串处理的安全性和灵活性。t-strings是对f-strings的泛化，f-strings在格式化字符串时非常流行，但可能被不当使用，导致安全问题（如SQL注入和跨站脚本攻击）。t-strings返回一个`string.templatelib.Template`类型，而不是直接变成字符串，这确保了在处理动态内容时可以进行安全转义。开发者可以在处理代码中自定义转义逻辑，例如为HTML或SQL提供安全处理函数。t-strings还允许更灵活的字符串操作，如返回特定类型的对象。通过访问模板的`.strings`和`.values`属性，开发者可以精细控制插值过程。t-strings为Python的字符串处理提供了更强大、安全的工具，未来有望在各类库和框架中得到广泛应用。

评论摘要

Pipelining might be my favorite programming language feature

作者: Mond_ | 评分: 104 | 评论数: 27 | 发布时间: 2025-04-21 12:16
文章摘要

本文讨论了编程中的**管道化**（pipelining）或**方法链**（method chaining）的好处，重点比较了两种代码风格的可读性和编辑便利性。管道化允许省略单个参数，通过传递前一个值来实现链式调用，使得代码更易读和维护。例如： ```rust data.iter() .filter(|w| w.alive) .map(|w| w.id) .collect(); ``` 相比之下，非管道化代码需要嵌套函数调用，难以阅读： ```rust collect(map(filter(iter(data), |w| w.alive), |w| w.id)); ``` 作者认为管道化语法更直观，易于编辑和理解，因为每一步操作都清晰地串联在一起，而无需从内到外解析函数调用。虽然语法不如语义重要，但在可读性和编辑便利性上，管道化具有明显优势。文章最后提到，这种风格在现代编程语言中非常普遍，如结构体成员访问和方法调用都体现了这一原则。

评论摘要
主要讨论点：编程语言中的管道语法与链式调用优劣比较 不同观点： • bnchrch：支持语言保持小功能集，但希望所有语言能采用Elixir的`|>`管道语法，认为它能简化代码。 • SimonDorfman：指出R语言的tidyverse包早已使用类似的管道语法。 • 0xf00ff00f：C++23中的例子显示了类似的管道功能，可以通过过滤和转换操作符实现。 • RHSeeger：认为文章中对比的“不良”代码示例被故意丑化，实际链式调用并不一定比嵌套调用差，尤其是在合理换行和格式化的情况下。 • epolanski：支持effect-ts同时提供管道和命令式代码的写法，认为命令式代码在调试和维护上更具优势，社区也更倾向于使用命令式写法。 • kordlessagain：指出文章虽声称“语义胜于语法”，但实际讨论的却是语法偏好，且未解决长链调试困难的问题，同时文章对“管道”定义不明确。 • cutler：提到Clojure使用非OO的管道函数->和->>，无需点语法。 • osigurdson：C#在17年前就有了类似Linq的管道功能，认为Go缺少此类特性。 • dapperdrake：引用Richard C. Reverse engineering the obfuscated TikTok VM

作者: xfeeefeee | 评分: 293 | 评论数: 16 | 发布时间: 2025-04-21 01:59
文章摘要
