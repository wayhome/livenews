Zeroserve: A zero-config web server you can script with eBPF

作者: losfair | 评分: 80 | 评论数: 6 | 发布时间: 2026-06-06 14:59
文章摘要

zeroserve是一个零配置的高性能HTTPS服务器。其核心特点是：将整个网站打包成单个tar文件直接提供服务，无需解压；通过用户态eBPF脚本替代传统配置文件，脚本被JIT编译为本机代码，可在每个请求上执行路由、认证、限流等中间件逻辑；全程使用io_uring处理网络和磁盘I/O；内置现代TLS支持（TLS 1.3、HTTP/2等）；支持热重载。性能上单核可超越nginx，部署只需替换tar文件并发送SIGHUP信号。设计理念是用可编程脚本统一配置和逻辑，避免传统服务器配置文件与脚本层分离的复杂性。

评论摘要
主要讨论点：关于一个新的 Web 服务器项目的评价，该项目使用 LLM 辅助开发，采用代码配置而非声明式配置，支持 eBPF。 不同观点： • **配置方式质疑**（jarym）：认为"代码优于配置"的设计押注错误。用户长期以来更偏好声明式配置而非编写代码，nginx/Caddy 的内置功能已满足大多数需求，无需编写 C 代码。 • **技术实现建议**（mmastrac）：喜欢这个想法但提出改进方向 - 应使用 Rust 而非 C 编写 eBPF、期待真正的内核加速、应支持多线程（通过 SO_REUSEPORT 实现很简单）、如果用 io_uring 应该同时用 kTLS 简化设计。 • **应用场景质疑**（mmarian）：不应专注于静态文件服务，因为现在很少有人为此单独搭建服务器。 • **AI 生成内容的信任危机**（bflesch）：项目看起来不错但缺乏真实感。因为 README、博客等都是 AI 生成，无法判断指标是否造假、功能是否真实可用、是否有适当的安全加固。这种 AI 辅助开发模式让人怀疑文档中描述的命令行参数是否真的存在。 补充讨论：rashkov 质疑为何使用 tarball 分发；多位评论者认可 LLM 降低了探索新想法的成本。

Moving beyond fork() + exec()

作者: jwilk | 评分: 184 | 评论数: 21 | 发布时间: 2026-06-06 14:34
文章摘要

这篇文章讨论了Linux内核中进程创建的优化提案。传统的`fork()`和`exec()`模式存在效率问题：`fork()`复制整个进程状态成本高昂，而紧随其后的`exec()`又会丢弃这些复制的内存。Li Chen提出了"spawn templates"方案，通过预先缓存可执行文件信息来加速重复运行同一程序的场景，基准测试显示约2%的性能提升。但评审者Mateusz Guzik指出，真正的优化应该跳过`fork()`步骤，直接创建全新进程，而不是优化现有模式。该提案虽不会被采纳，但为未来的进程创建原语指明了方向。

评论摘要
主要讨论点：fork() + exec() 模型是否应该被废弃，以及如何设计更好的进程创建机制 不同观点： • **支持废弃 fork()：** fork() 是1970年代的产物，现已过时成为负担。它成本高昂（需复制整个进程状态），且通常紧随 exec() 调用会丢弃刚复制的内存。即使有 copy-on-write 优化，复制页表项仍是 O(N) 操作。概念上也不合理——启动新进程却要先克隆当前进程。 • **反对废弃 fork()：** fork() + exec() 的优雅在于分离关注点，fork 后可用所有常规 API 配置进程（如 dup2、设置进程组、信号处理、文件描述符、命名空间、seccomp 等）。任何试图用单一调用替代的方案都需要把所有配置选项作为参数，难以扩展且容易混乱。有经验的开发者认为这个模型经过时间检验，比线程编程更易理解。 • **Windows 模型对比：** CreateProcessW 更直接自然，但接口更窄、不灵活，通过结构体传递初始值限制了可扩展性。 补充讨论：posix_spawn 已提供类似 Windows 的接口；有提议创建空白进程后强制执行系统调用序列；或使用类似 eBPF 的钩子机制实现可定制的进程创建流程。

这篇文章解释了大型语言模型（LLM）的工作原理。现代LLM主要通过堆叠transformer块构建。文章涵盖核心机制： 1. **分词（Tokenization）**：将文本转换为整数ID序列，使用子词级别的词汇表 2. **嵌入（Embeddings）**：通过嵌入矩阵将token ID转换为有意义的向量表示 3. **位置编码**：让模型理解token的顺序 4. **注意力机制**：token之间如何共享信息 5. **多头注意力**：同时追踪多种关系 6. **前馈网络**：存储模型的大部分结构化知识 7. **残差流和层归一化**：使深层网络可训练 8. **下一个token预测**：模型的实际输出机制 文章强调，虽然不同LLM在训练数据、规模和配置上有差异，但它们共享相同的transformer架构骨架。
