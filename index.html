大型语言模型（LLM）接受的训练是生成自然语言。然而，多方面的证据表明，LLM 对外呈现的语言输出，以及通过机制性方法提取的语言特征，都可能成为理解模型内部计算的不可靠窗口。我们引入“语言不可读性”（linguistic illegibility）这一术语，用来广泛指代这样一类情形：LLM 对外呈现的语言产物，或通过机制探测得到的语言产物，无法反映模型实际上是如何进行思考的。 我们认为，对于那些内部计算并非直接通过语言表达，而是通过在激活空间上进行数学运算的 LLM 而言，语言不可读性的阴影是不可避免的；在这种情况下，激活空间与自然语言之间的转换发生在两端，并且是有损的。如果语言不可读性始终存在可能，那么依赖模型语言自我报告的安全机制（例如思维链监控、宪法式自我批评，以及针对以语言定义的特征向量进行的激活探测）就永远不可能具备完全可靠的安全性；模型沙箱始终需要采用其安全保证完全不依赖于读取模型语言状态的隔离技术。 我们认为，使用污点追踪来观测模型输出，是实现有效沙箱的一种有前景的方法：无论模型如何以语言进行自我报告，污点追踪策略都可以预先定义系统状态中的各种部分，使其永远不应受到模型生成数据的影响。我们还讨论了若干额外的沙箱机制（例如稳健的虚拟化，以及由第三方对沙箱配置进行审计）；这些机制共同构成了语言监控之下的一道关键底线，并且本可以缓解近期前沿模型实施的沙箱攻击。

竞赛编程已成为检验大型语言模型推理能力的关键测试，其中 IOI 和 ICPC 等国际竞赛代表了最具挑战性的场景。我们提出了一套端到端的专项化流程，将大规模题目整理、合成推理轨迹、监督微调（SFT）和强化学习（RL）相结合。我们使用 22,000 道精选题目，通过 SFT 和 RL 训练 Nemotron-3-Nano-CC（30B-A3B），并仅通过 SFT 训练 Nemotron-3-Ultra-CC（550B-A55B）。此外，我们还提出了 GenCorrect——一种由反馈驱动的测试时计算策略，通过迭代生成、评估和改进多样化的解法来提升性能。 在 IOI 2025 中，Nano-CC 的得分从 130 分提升至后训练后的 291 分，并在使用 GenCorrect 后达到 468 分，超过 438.3 分的金牌分数线；Ultra-CC 则达到 502 分。受这些结果的启发，我们开发了一个针对竞赛进行专项设计的 Ultra-CC 系统，并在 IOI 2026 期间对其进行了前瞻性评估。在与人类参赛者相同的时间、互联网访问权限和提交限制下，该系统在满分 600 分中取得了 535.4 分，超过了 361.12 分的金牌分数线以及人类最高分 498.27 分。据我们所知，这是首个在一套 IOI 赛题上超越最高分人类参赛者的人工智能系统。

UE5M3 FP4 Block Scaling for Stable Language Model Pretraining

Robert Hu, Carlo Luschi, Paul Balanca · cs.LG · 提交日期: 2026-09-02
展开中文摘要

稳定的 4 位浮点（FP4）预训练很困难，因为 E2M1 有效载荷只能表示范围较窄的数值幅度。NVIDIA 的 Transformer Engine \nv{} 配方通过张量级缩放、随机 Hadamard 变换（RHT）以及使用 bfloat16（BF16）的最终层来应对这一问题，但这些方法增加了 FP4 矩阵乘法之外的额外计算。与此不同，我们将 E2M1 有效载荷与无符号 E5M3（\ue{}）块缩放因子配对。其更宽的表示范围使得周期性张量缩放成为可能；同时，我们的配方对反向传播梯度采用选择性随机舍入，省略 RHT，并在所有符合条件的内部线性层中使用 FP4。我们对一个 Nemotron-H 8B 模型进行了近 1900 亿个 token 的预训练。 与 Transformer Engine \nv{} 相比，所提出的 block-16 配方在训练末期窗口取得了更低的最终训练损失；在各自的量化推理策略下，以留出负对数似然（negative log-likelihood）衡量的验证损失也更低。其量化推理下游任务的点估计结果在报告的三个聚合指标上也都更高。一次原生 \nv{} 执行消融实验同时移除了 RHT 和 BF16 最终块豁免，使测得的模型主体 token 吞吐量提高了 21.2%。这些结果展示了端到端的软件模拟 \uefp{} 预训练能够采用更简单的配方，并为原生支持 \ue{} 块缩放提供了动机。
