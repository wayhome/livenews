Bare metal printf – C standard library without OS

作者: todsacerdoti | 评分: 82 | 评论数: 8 | 发布时间: 2025-04-26 21:32
文章摘要

这篇文章讨论了如何在无操作系统的裸机系统上利用Newlib实现紧凑的C标准库，特别是实现`printf`功能。文章首先对比了在完整操作系统和裸机系统上运行`printf`的区别，指出裸机系统缺乏底层支持，需要手动实现基本I/O功能。Newlib作为一个可定制的C标准库工具包，通过实现如`_write`这样的基本函数 primitives，使得像`printf`这样的复杂功能可以在裸机环境中运行。文章还介绍了交叉编译工具链的概念，并解释了如何针对RISC-V等平台进行配置和编译。最终，通过实现UART等简单I/O设备的功能，开发者可以在裸机环境中使用`printf`输出信息。

评论摘要
主要讨论点：嵌入式编程中的基础架构与实现细节，特别是关于如何实现和定制类似 `printf` 的功能。 不同观点： • [ChuckMcM] 认为作者描述的软件架构很好，能够创建可移植的代码，并且详细解释了在“裸金属”环境下运行 C 程序所需的基本组件，如 crt0 启动代码和 I/O 驱动。他还提到设置 STDIN 和 STDOUT 钩子，以及 BIOS 的概念，认为这是学习计算机系统的好方法。 • [Neywiny] 提到在学校学习时，老师通常简化讲解，让学生以为操作系统负责 `printf`。实际在嵌入式编程中，`printf` 可能没有默认的输出路径，因此理解如何设置输出路径很重要。他还提到 SWO 和半主机（semihosting）技术，认为这些知识对实际工作有帮助。 • [smackeyacky] 提到使用 newlib 库时，从简单的 `printf()` 到复杂系统中需要输出到不同设备（如串口或位图显示）的转变。他质疑 newlib 是否支持在系统复杂度增加时进行不同的钩子设置。 • [saagarjha] 对简单的缓冲区溢出代码示例进行了批评，认为在现代编程中不应再出现这种低级错误，特别是在2025年这个时间点。 • [MuffinFlavored] 认为应该去掉 `stdio.h`，直接使用类似 `syscall` 的接口进行 `write()` 等操作，以实现更低层的控制。 • [sylware] 描述了在 RISC-V 汇编中编写代码的经验，并提到避免使用伪指令和寄存器别名，使用简单的 C 预处理器来保持代码的灵活性，以便在不同的汇编器上进行编译。 • [eqvinox] 对文章标题感到困惑，认为如果讨论的是解析格式字符串和处理可变参数的实现，应该叫“裸金属 `puts()`”或“裸金属 `write()`”，并提到 FreeBSD 的 `printf()` 实现很容易从其 libc 基础设施中剥离和定制。 补充讨论： • 争议的焦点在于“裸金属”环境下 `printf` 的实现细节以及如何在不同复杂度的系统中处理输出。 • 对 `newlib` 在复杂系统中的适用性存在疑问，尤其是如何处理不同设备的输出。 • 对学校教学简化某些概念的做法有不同看法，有人认为这有助于入门，但也有人认为这会导致实际工作中的误解。 • 讨论中还涉及到具体技术如 SWO、半主机技术以及汇编层面的实现细节，显示了参与者对底层编程的深入了解。

作者: saikatsg | 评分: 65 | 评论数: 13 | 发布时间: 2025-04-26 19:14
文章摘要

Tilt 是一个开源工具，用于简化在 Kubernetes 上开发微服务应用的过程。它允许开发者通过代码定义开发环境，并自动化从代码更改到环境更新的所有步骤，包括文件监控、容器镜像构建等。Tilt 类似于运行 `docker build && kubectl apply` 或 `docker-compose up`。其主要功能包括一键安装、多语言支持（如 NodeJS、Python、Go 等）、详细的 API 参考以及社区贡献指南。Tilt 遵循 Apache-2.0 许可证，并重视安全问题报告。通过 Tilt，开发者可以更高效地管理和开发基于 Kubernetes 的微服务应用。

An end to all this prostate trouble?

作者: bondarchuk | 评分: 352 | 评论数: 21 | 发布时间: 2025-04-26 08:39
文章摘要

文章讨论了前列腺引发的多种问题，包括在美国约40分之一的男性死于前列腺癌，以及大多数60岁以上男性面临的良性前列腺增生（BPH）问题。BPH导致排尿困难，并可能发展为恶性。尽管有人提出前列腺作为“守门人”抵御性传播疾病，但这种解释并不充分，因为前列腺并不过滤尿道。文章还提到一种理论，认为BPH由精索静脉无能引起，以色列医生Gat和Goren提出通过手术治疗，并在同行评审期刊发表了成果，但该理论未获广泛关注。尽管后续有小型研究支持，医学界对此仍持怀疑态度，担心重蹈其他未验证医疗理论的覆辙。

评论摘要
主要讨论点：与前列腺增生（BPH）相关的各种治疗方案、原理及相关争议 不同观点： • **支持创新治疗方法的观点**： - [tacon] 提到Vivifi Medical正在进行的基于静脉回流不足原理的临床试验，使用微创工具切断回流的静脉并重新连接到水平静脉，声称可以逆转BPH。该过程相对于现有的Urolift或TURP手术可能更有效，并计划于2028年获得FDA批准。 - [tpoacher] 分享了通过肌肉锻炼（如髂腰肌拉伸）缓解前列腺炎疼痛的个人经验，并提到这一方法可能与静脉回流问题有关，但未被广泛讨论。 • **对健康生活方式的重视**： - [raffael_de] 强调通过保持身体活跃、骨盆底肌肉锻炼和正确呼吸等方式，可以有效预防静脉回流问题，认为这是预防BPH的最佳选择。 - 他还质疑为什么不采用硬化静脉的方式来治疗，并希望了解其他可行方案。 • **对现有治疗和药物的讨论**： - [bawana] 提到像Prostamol uno（锯叶棕榈提取物）这样的草药，虽然价格便宜，但因成本问题未被广泛认可。同时提到PC-SPES这种曾被认为是奇迹药物的例子，后因掺杂药物被FDA召回。 - [Traubenfuchs] 支持使用Finasteride或Dutasteride控制BPH，并建议结合每日使用Tadalafil来抵消可能的性副作用，同时提醒使用这些药物前应考虑生育问题。 • **对进化和医学发展的反思**： - [blainm] 认为像BPH这样的问题反映了进化中的盲点，即生殖年龄后的选择压力下降，导致前列腺功能障碍等问题持续存在。 - [jasonthorsness] 质疑为何新治疗方法需要很长时间才能被测试和采纳，是否因为现有方案“足够好”。 • **对创新工具和筛查方法的兴趣**： - [elric] 对使用热像仪等简单工具进行筛查的方法表示兴趣，并提出是否可以通过类似的低成本工具筛查其他健康问题。 - [jakedata] 以幽默的方式建议开发带有温度、脉搏监测功能的智能手机连接设备。 补充讨论： • **对性别健康问题的比较**： - [begueradj] 提到前列腺问题与女性乳腺癌的比较，指出虽然两者死亡率相近，但男性每天使用前列腺，而女性并非每天哺乳，质疑是否可以简单类比。 • **对治疗和筛查工具的争议**： - 评论中对Vivifi Medical的临床试验、草药疗效、肌肉锻炼效果等都存在一定争议，焦点在于这些方法的科学依据和可行性。 • **对医学历史的回顾**： - [smitty1e] 通过一个关于表面对空导弹控制代码的类比，讨论了进化为何没有消除像BPH这样的设计缺陷，因为过去寿命较短，此类问题并未显现。 争议焦点： • 新治疗方法的科学性和可行性，尤其是微创手术和草药疗法。 • 不同治疗方法的性价比和副作用，如Finasteride与新疗法的对比。 • 生活方式干预（如肌肉锻炼）是否能有效预防或治疗BPH。

Anatomy of a SQL Engine

作者: ingve | 评分: 10 | 评论数: 0 | 发布时间: 2025-04-26 22:00
文章摘要

这篇文章总结了Dolt数据库中go-mysql-server（GMS）引擎的工作原理，描述了一个查询从解析到结果输出的整个过程。GMS作为SQL引擎，介于客户端和存储层之间，处理包括解析、绑定、计划简化、连接探索、计划成本计算和执行等步骤。当前，Dolt引擎默认使用基于行的本地执行策略。 文章详细介绍了查询解析的过程，首先通过网络接收查询，将其转化为抽象语法树（AST），以检查查询是否格式正确。Dolt采用左递归的Yacc语法，以提高执行效率，但调试复杂。解析成功后生成符合Yacc规则的AST，失败则返回错误。 接下来是绑定阶段，将AST中的标识符与数据库目录符号匹配，类似于编程语言中的变量定义和引用。表格定义和列定义是该过程的核心对象，用于提供和引用行/列数据。 文章还提到，查询处理包括计划简化、连接探索、成本计算和结果输出等步骤，每一步都对查询执行效率至关重要。
