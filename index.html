Piranesi's Perspective Trick (2019)

作者: amatheus | 评分: 154 | 评论数: 17 | 发布时间: 2025-03-27 11:41
文章摘要

本文探讨了18世纪艺术家乔凡尼·皮拉内西（Giovanni Battista Piranesi）在其“ vedute”蚀刻画中使用的独特透视技巧。这些作品细致地描绘了罗马的古典和现代建筑，尽管是手工绘制，但与现代摄影相比，透视上存在一些特别之处： 1. 这些图像提供了强烈的场所感，能够准确识别实地场景。 2. 它们展示了宽广的全景视角，而没有照片边缘的扭曲。 3. 现代观众可能觉得这些画的透视有些不对劲，但当时的人们对其技术能力高度赞赏。 作者通过研究开发了Hugin全景拼接软件中的“帕尼尼投影”（Panini projection），这种投影能呈现极宽角度而无明显边缘变形。然而，皮拉内西的透视技巧不同于帕尼尼投影，他在描绘一系列渐远的相似物体时，会将较近的物体画得比实际比例更大，以保持画面的可读性。这种技巧通过绘制平行线的收敛点可以识别。

评论摘要
主要讨论点：Piranesi投影及其在艺术、技术中的应用和意义 不同观点： • **Piranesi投影的艺术价值和主观体验**： - [bemmu] 认为Piranesi的书《Piranesi》中的世界——无尽的古典建筑、雕像和楼梯——带来了一种极其平静的体验，推荐其作为睡前的放松方式。 • **Piranesi投影与摄影写实主义的比较**： - [SamBam] 提出Piranesi的投影可能比摄影写实主义更接近人类的视觉感知，因为人类大脑在观察世界时会自动填补细节并调整颜色，而非像相机一样机械地呈现。 - 争议焦点：是否摄影写实主义真的更"逼真"？Piranesi的投影是否更符合人类的视觉体验？ • **技术实现与投影的数学原理**： - [01HNNWZ0MV43FF] 质疑是否能通过程序实现Piranesi投影，而[dust42] 提供了不同投影方法的比较链接，[jcalx] 则指出Panini投影在Unity和Unreal中的应用。 - [ibaikov] 进一步思考这种投影在视频和游戏中的应用潜力及其可能带来的视觉体验提升。 • **具体图像处理和工具开发**： - [rossdavidh] 提到在GIMP中实现Piranesi投影的工具需求，并呼吁有能力的开发者参与。 - [damnitbuilds] 对图像处理中的具体变形效果提出了技术性质疑。 • **Piranesi投影在设计中的应用与争议**： - [amelius] 批评设计师在修改透视时的不当操作，认为这种做法不合适，但未明确是否与本文讨论的Piranesi投影有关。 补充讨论： • **其他资源推荐**： - [bonoboTP] 提供了更多关于透视变形的文章链接，供感兴趣的读者进一步阅读。 • **Piranesi投影的艺术背景**： - [thewellis2] 提到Piranesi的“想象中的监狱”系列作品，指出其与文章中讨论的投影风格类似。 - [ChrisMarshallNY] 作为艺术家，表示Piranesi投影提供了新的视角，尽管传统透视法仍然在某些题材中有效。 • **几何与视觉效果的争议**： - [tobr] 质疑Piranesi投影中对角线的曲率问题，认为保持垂直线平行可能导致细微的曲率，但在建筑图像中不明显。 整体来看，讨论围绕Piranesi投影的艺术性、技术可行性及其在不同领域中的潜在应用展开，涉及艺术、技术和设计多个维度，并存在对投影真实性与视觉体验的争议。

Blasting Past WebP - An analysis of the NSO BLASTPASS iMessage exploit

作者: el_duderino | 评分: 94 | 评论数: 3 | 发布时间: 2025-03-27 12:49
文章摘要

本文分析了NSO集团利用的iMessage零点击漏洞（BLASTPASS）。2023年9月7日，Apple发布iOS安全更新，修复了两个被活跃利用的漏洞（CVE），这些漏洞由NSO集团的零点击漏洞利用程序引发，目标是一名在国际非政府组织工作的个人。该漏洞通过恶意PassKit附件，利用iMessage发送恶意图片，无需用户交互即可入侵运行iOS 16.6的iPhone。此前，Apple已向WebP项目报告该漏洞，并在随后发布修复。Google也在Chrome中修复了此问题。尽管Isosceles和Dark Navy博客详细分析了WebP漏洞的技术细节，但未解密如何在零点击场景中实现一键利用。本文作者Ian Beer通过与Amnesty International Security Lab合作，获取了BLASTPASS样本文件和崩溃日志，揭示了NSO如何实现零点击iOS漏洞利用。漏洞核心在于WebP解码过程中的Huffman编码处理不当，导致内存损坏，尽管问题触发后解析停止，但攻击者仍能利用此缺陷。

评论摘要
主要讨论点：iMessage的安全性、隐私保护以及系统设计缺陷，特别是关于陌生消息处理和潜在的安全漏洞。 不同观点： • [TheDong] 认为iMessage允许陌生人发送包含附件的消息是不合理的。他建议Apple应引入一种设置，允许用户仅接收互为联系人的消息，并要求陌生人先申请添加联系人。他还提到Signal有类似的“消息请求”功能，而iMessage没有，这导致其消息直接通过内核处理，增加了安全风险。 • [botanical] 关注的是更广泛的安全问题，提到了NSO Group等组织利用0点击、0日漏洞进行攻击，目标包括记者和非政府组织。他认为开放源代码是安全的关键，因为这样代码可以被公开审查，从而提高安全性。 • [cedws] 则从技术实现角度讨论，认为内存不安全语言（如C、C++）在处理媒体编解码等任务时容易导致安全漏洞，建议替换为更安全的编程语言。 补充讨论： • TheDong提出的iMessage“仅接收联系人消息”的功能建议，意在提高用户隐私保护，并通过减少未知来源消息的数量来降低潜在攻击面。 • botanical强调了开放源代码的重要性，认为这是确保软件安全的一种方式，因为公开的代码更容易被社区发现和修复漏洞。 • cedws指出了技术栈选择对安全的影响，特别强调了在处理复杂文件格式和编解码时，使用内存安全的语言可以有效减少漏洞的产生。 争议焦点： • iMessage是否应该引入类似Signal的“消息请求”功能，以限制陌生人的消息接收，从而提高安全性。 • 使用内存不安全的语言在系统级编程中的风险，是否需要替换为更安全的语言以减少漏洞。 这些观点共同构成了关于iMessage安全性和隐私保护的多维度讨论，涉及用户体验、技术实现和安全策略等多个方面。

Source code art in the Rivulet language

作者: cranbor | 评分: 73 | 评论数: 7 | 发布时间: 2025-03-27 11:55
文章摘要

Rivulet是一种基于流动链条的编程语言，使用半图形字符编写。它有四种链条，每种都有自己的符号和语法规则，共同构成紧密的代码块（glyphs）。Rivulet避免传统的分支和循环结构，所有链条都会执行且不会分裂。其设计灵感来源于迷宫和空间填充算法，同时具有手写友好的书法特点。 数据模型以包含零的列表组织数据，命令可以应用于单个单元格或整个列表，并可进行列表间操作。控制流方面，所有glyph都会执行，没有"if"语句，但可通过条件回滚实现分支。回滚是Rivulet中唯一的分支形式，循环在最后一次迭代回滚时结束。 语法上，glyph以╵开始，以╷结束，通过其开始的坐标顺序执行。Rivulet的语法初看复杂，但通过练习易于读写。

评论摘要
主要讨论点：用户对一种新编程语言的理解困难及其设计理念的讨论 不同观点： • vorbits：对如何建立对该编程语言的直观理解感到困惑，仅理解了部分符号（glyph start and end ╵ ╷），对整体理解有难度。 • rottytooth（语言创建者）：解释该语言的设计初衷是将自然语言的元素引入代码中，避免过于逻辑化的语法，追求紧凑和表现力，并提到之前创建的其他语言以及即将出版的相关书籍。 • QuadmasterXLII：将学习这种语言的困难与成年人学习编程的感受相比较，尽管自己对Brainfuck和APL等语言很熟悉，但仍觉得这种语言非常陌生。 • aredox：认为这是一种有趣的视觉编程尝试。 • mrbluecoat：以幽默方式将该语言与玛雅文化联系起来，暗示其视觉风格独特。 • aa-jv：对该语言的视觉美感表示赞赏，并联想到其可能被用于现实世界中的代码艺术和安全漏洞。 补充讨论： • 语言创建者rottytooth提供了该语言的背景信息，包括其与之前语言的联系以及即将出版的书籍，为理解该语言提供了更多背景。 • 用户QuadmasterXLII和aredox都表达了对该语言难以理解的感受，但也有用户如aa-jv和samchon对其美学和潜在应用表示欣赏。 • 讨论中涉及了该语言的视觉特性和可能的艺术应用，如graffiti和现实世界的黑客活动，表明该语言在编程之外的可能影响。 争议焦点： • 主要集中在用户对该语言理解的困难上，尤其是对有编程经验的人而言，这种新语言的设计显得尤为陌生和复杂。

文章摘要

Model Context Protocol (MCP) 是一种标准协议，用于向大型语言模型（LLM）提供工具和上下文，类似于USB-C接口为设备提供标准化连接。MCP定义了两类服务器：stdio服务器（本地运行）和HTTP over SSE服务器（远程连接）。通过Agents SDK，可以集成MCP服务器，每次运行Agent时调用`list_tools()`来获取工具列表，并通过`call_tool()`执行工具。为减少延迟，可启用工具列表缓存（`cache_tools_list=True`），并在必要时手动更新缓存。MCP操作可自动追踪，记录工具调用等信息。完整示例可查看相关文档。
