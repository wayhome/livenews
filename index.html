Native Secure Enclave backed SSH keys on macOS

作者: arianvanp | 评分: 294 | 评论数: 21 | 发布时间: 2025-11-23 17:55
文章摘要

这篇文章介绍了在macOS系统中如何利用安全芯片（Secure Enclave）生成和使用SSH密钥的方法。主要内容包括： 1. 通过`sc_auth`命令创建基于安全芯片的SSH密钥，支持生物识别验证（如TouchID）。 2. 使用`ssh-keygen`从安全芯片导出公钥/私钥对，私钥实际上是FIDO凭证的引用，不包含实际密钥材料。 3. 将生成的SSH密钥用于远程登录和`ssh-agent`。 4. 建议通过设置环境变量`SSH_SK_PROVIDER`来简化操作流程。 这种方法比传统方案更安全，因为私钥存储在硬件安全模块中，且支持生物识别验证。

评论摘要
主要讨论点：[如何在Secure Enclave中使用SSH密钥，以及相关工具和替代方案的优缺点] 不同观点： • **关于密钥备份的担忧** - jedberg指出，Secure Enclave中的私钥无法备份，如果设备丢失，密钥也会丢失。他质疑这是否是一个安全漏洞，但承认可能有其他恢复方式。 - daft_pink反问为何需要私钥文件，暗示Secure Enclave的安全性已足够。 • **替代工具和方案** - rkeene2提到可以通过修改的GPG和SSH代理实现ECDSA签名，并提供了相关工具链接。 - redleader55推荐了facebookincubator/sks，这是一个支持多平台硬件的SSH密钥库。 - wahern介绍了KeyMux，支持Secure Enclave密钥的多用途场景（SSH、SSL、PGP）。 - cedws和epistasis比较了Secretive和其他工具的易用性和可靠性，epistasis指出Secretive在Tahoe版本中存在bug。 • **技术限制和疑问** - watermelon0询问为何无法使用'p-384-ne'曲线，而只能使用'p-256-ne'。 - adastra22提问是否可以延长密钥的有效期。 - jcalvinowens质疑Secure Enclave是否仅支持NIST曲线。 - cube2222询问是否有类似方案支持GPG密钥（如用于提交签名）。 • **安全争议** - ikiris警告NIST曲线可能被NSA后门，建议避免使用。这一观点引发了关于加密算法安全性的潜在争议。 补充讨论： - euroderf提出了跨设备（如iPhone）使用同一密钥的需求，并询问iCloud是否能解决这一问题。 - procaryote猜测苹果是否改进了对Secure Enclave的支持，可能改善YubiKey等安全密钥的体验。

文章摘要

这篇文章回顾了互联网早期发展历程，重点讲述了DNS（域名系统）安全机制的演变。最初ARPANET使用简单的hosts文件进行地址解析，随着网络规模扩大发展出DNS系统。由于早期互联网用户群体有限且环境友好，DNS设计时未充分考虑安全性。1995年IETF开始开发DNSSEC安全扩展，但因部署复杂和可靠性担忧进展缓慢。直到2008年Kaminsky发现重大DNS漏洞后，DNSSEC才加速推广，2010年前后根域完成加密签名。ICANN建立了严格的安全框架，包括地理分散的密钥设施、多重认证机制和公开透明的密钥管理仪式，以增强系统可信度。作者本人也参与了这一信任体系建设。
