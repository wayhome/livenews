文章摘要

文章介绍了侵入式链表：将链表节点嵌入数据结构，通过成员偏移量反推所属对象，常用`offsetof`实现。相比普通链表，它减少内存分配并降低缓存开销。文章还讲解了双向链表和循环链表的特点，并指出Linux使用循环双向侵入式链表管理进程等对象。

展开评论摘要
主要讨论点：围绕侵入式数据结构（尤其是侵入式链表）的性能优势、内存管理方式、链表实现技巧及其历史称谓展开讨论。 不同观点： • **性能与结构优势**：侵入式结构减少一次间接访问；对象可同时挂入多个集合，避免额外指针；移动或在链表间转移对象无需复制，持有对象指针时可实现中间节点 O(1) 删除，适合大型状态结构且遍历较少的场景，相比 vector 等紧凑结构可能更快。 • **C 语言中的实用性**：传统链表若由节点拥有数据，需要为不同数据类型生成不同节点；C 缺乏方便的泛型，通常依赖宏或 `void*` 间接访问，因此更凸显侵入式链表的优势。 • **内存分配灵活**：元素由用户负责分配，可放在堆、栈、全局数组、专用 arena 中，甚至采用混合策略，例如栈上分配锚节点、堆上分配实际元素。 • **不同链表设计**：有人指出文章遗漏 AmigaOS 的“重叠链表头”技巧。该方案通过头部字段兼作哨兵，遍历时遇到空指针即可结束，无需保存链表头指针；代价是头部增加一个空指针语义。 • **历史与术语争议**：有人认为“intrusive”是 C++ 术语，文章把原本在 C 结构体中长期存在的嵌入式数据或数据与指针混合写法重新包装，涉嫌改写历史。 补充讨论：争议焦点在于“侵入式”究竟是新概念，还是对 C 语言传统实践的重新命名。
