Speculative KV coding: losslessly compressing KV cache by up to ~4×

文章摘要

这篇文章介绍了"推测式KV编码"技术，通过使用更小的预测模型来无损压缩大型语言模型的KV缓存，压缩率可达约4倍（在fp8有损压缩基础上，总压缩率约8倍）。 核心原理是：KV缓存本质上是确定性输出，可用熵编码压缩。方法借鉴推测解码，用廉价预测模型预测目标模型的缓存内容，然后用算术编码器根据预测准确度编码真实缓存。编码成本取决于预测模型q对真实KV缓存的拟合程度，采用高斯分布建模，成本包括分布宽度成本和预测偏差成本。这为处理超长上下文的AI应用提供了高效的缓存压缩方案。

这篇文章主要介绍16位Windows的内存管理机制。核心内容包括：Windows本质上是一个复杂的覆盖管理器，通过段(segment)机制管理内存，将不常用的段从物理RAM中丢弃和按需重载。Windows采用NE(New Executable)可执行文件格式，支持将程序分割为独立的段，每个段最大64KB。段通过句柄(handle)而非物理地址标识，类似于保护模式的选择子，使得段可以在内存中移动。这种设计源于8086实模式时代，并借鉴了Intel 286保护模式的思想。窗口过程等外部调用的代码需要导出，以便Windows进行数据段修正等处理。

Symbolica 2.0 是一个高性能符号计算框架，支持 Python 和 Rust。此次发布的核心主题是"可编程符号"，允许用户自定义数学对象的简化、微分、展开等行为。主要改进包括： 1. **更简洁的 Rust API**：增加运算符重载和构建器模式，减少导入和类型声明 2. **符号注册系统**：支持命名空间、别名、标签和自定义钩子 3. **重新设计的求值器**：支持双精度浮点运算和 JIT 编译 4. **丰富的输出格式**：HTML、LaTeX、Typst 输出，彩色打印和多行格式化 5. **新增内置函数**：Gamma、多对数、Bessel 函数、Riemann zeta 等 6. **可编程符号钩子**：可在规范化等代数生命周期的特定节点执行自定义操作 整体提升了易用性和可扩展性。

评论摘要
主要讨论点：关于Symbolica符号数学软件的讨论，涉及其定位、替代方案和使用体验 不同观点： • **质疑立场**：指出Symbolica网站缺少与其他计算代数系统的对比，且采用商业许可。同时提醒存在另一个同名但功能不同的符号执行项目，可能造成混淆 • **替代方案推广**：有开发者正在用Rust重新实现Wolfram Language/Mathematica（Woxi项目），声称许多Wolfram代码已经可以直接运行 • **积极评价**：长期用户（从0.1版本开始）高度赞扬Symbolica的进步，特别是构建器模式、宏命名空间、call trait等Rust特性的引入，以及表达式类型(Atoms)与标准类型的算术运算实现 • **开源替代质疑**：有人直接提出为何不使用现有的开源方案如Maxima、Reduce或Cadabra2 补充讨论：评论反映了符号计算领域的技术路线选择问题——商业vs开源、新项目vs成熟方案、Rust生态的优势。争议焦点在于Symbolica的商业定位是否合理，以及相比现有开源工具的独特价值是否足够明确。
