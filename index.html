Saving 100 terabytes of memory by optimizing 1.1.1.1's DNS cache

作者: TangerineDream · 评分: 662 · 评论: 37 · 2026-08-27 17:17

文章摘要

Cloudflare Big Pineapple DNS平台针对超过2500亿条缓存记录进行内存优化，通过将可变容器改为定长容器、合并DNS记录列表、压缩字段及减少分配等五项改进，使单条缓存占用降低超50%，全网释放约100TB内存。同时，插入吞吐量提升43%，查询延迟下降19%，实现了节省空间与提升性能的双重效果。

展开评论摘要
主要讨论点：围绕大规模 DNS 缓存的内存优化，讨论“先做出产品再优化”与“设计阶段就应重视效率”的取舍，以及 Rust 数据结构、内存布局和替代结构的技术方案。 不同观点： • 迭代优先派：先交付可用产品、验证商业模式并盈利，再优化成本；系统规模和收益明确后，优化更容易投入。 • 设计优先派：反对把优化无限推迟，认为长期不考虑内存布局会造成软件臃肿、浪费资源并增加缺陷，不能总靠增加硬件解决。 • 内存布局优化派：建议将记录紧跟在 CacheEntry 后、减少独立分配、调整结构体对齐；Go 示例显示结构体可由 24 字节降至 16 字节。MaraDNS 通过单次 malloc 将 237MB 降至 9.5MB，另有游戏案例从 20GB 降至 3GB。 • 数据结构替代派：可用基数树、压缩前缀的 B 树共享域名公共后缀（如“com.”），比 hashmap 更省空间；也有人质疑 Box 指针仍占 16 字节，认为可进一步压缩。 • Rust 权衡派：合并多个 Vec、依赖偏移量虽节省内存，却可能削弱越界检查；同时，避免堆和过度追求零间接并非总是最佳，单次间接有时更划算。 补充讨论：评论还涉及 Cloudflare DNS 预热、公共 Wi‑Fi 强制 DNS 可能影响门户认证，以及“优化是否属于常规、显而易见工作”的争议。
