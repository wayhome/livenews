文章摘要

Regolith 是一个基于 Rust 的 TypeScript/JavaScript 正则表达式库，旨在解决 ReDoS（正则表达式拒绝服务）攻击问题。它通过底层使用 Rust 的线性正则表达式引擎，将最坏情况时间复杂度从指数级降低到线性级，从而提高安全性。该库力求成为现有 RegExp 的直接替代方案，无需大量修改代码即可迁移。目前处于早期开发阶段，需要社区贡献和开发者采用。文章强调了 ReDoS 攻击的危害性，列举了实际案例（如影响 4250 万项目的 brace-expansion 漏洞），并指出采用此类免疫库可以节省大量修复漏洞的工程成本。

评论摘要
主要讨论点：[Regolith作为RegExp的替代方案的有效性及ReDos问题的解决方案] 不同观点： • **Regolith的有效性争议** - 支持观点：Regolith设计为RegExp的替代品，API兼容，最小化改动需求。 - 反对观点：Regolith不支持反向引用和环视（look-around），因此无法完全替代RegExp，且方言差异使其非“直接替代”。建议修改宣传文案。 - 替代方案提议：直接包装原生JS正则表达式，拒绝包含反向引用和环视的模式，可能更简单且效果相同。 • **TypeScript与JavaScript的关系** - 争议焦点：将TypeScript和JavaScript视为独立语言是否合理？ - 反对观点：TypeScript无独立运行时，其正则表达式实现依赖于JavaScript引擎，因此“TypeScript RegExp”的表述不准确。 • **正则表达式设计的根本问题** - 观点1：正则表达式语言本身存在缺陷（如计算时间爆炸），需通过限制特性（如反向引用）来避免ReDos。 - 观点2：应增加更多特性（如标记已匹配部分以防止回溯）来增强表达性和可调性，而非削减功能。 • **ReDos问题的社会影响** - 观点：ReDos漏洞被过度炒作，导致CVE追踪器噪声和无效的库更新。建议仅针对可能接收不可信输入的库提交CVE，而非所有工具。 补充讨论： - 争议焦点集中在Regolith的“直接替代”宣称是否成立，以及ReDos的解决方案是简化（移除危险特性）还是复杂化（增加控制特性）。 - 对TypeScript/JavaScript关系的讨论反映了技术表述的严谨性问题。 - 社会层面批评了安全研究的“滥发CVE”现象。
