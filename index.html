What happens when you run a CUDA kernel?

作者: mezark | 评分: 114 | 评论数: 6 | 发布时间: 2026-06-29 13:11
文章摘要

这篇文章详细解析了CUDA kernel的执行过程。以一个简单的向量加法程序为例，文章追踪了从源代码编译到GPU执行的完整流程： **编译阶段**：nvcc编译器将CUDA代码分为主机代码和设备代码两部分。设备代码先由cicc编译成PTX（虚拟ISA），再由ptxas转换为SASS（实际机器码）。PTX使用无限虚拟寄存器，SASS则针对特定GPU架构优化。 **执行流程**：程序通过CUDA驱动API分配GPU内存、传输数据、启动kernel。kernel启动涉及数百万条CPU指令、大量ioctl系统调用和内存映射的doorbell寄存器通信。GPU按照网格（grid）和线程块（block）组织线程，每个线程执行相同代码处理不同数据，最终将结果传回主机内存。 文章深入展示了GPU编程的底层机制和编译优化过程。

评论摘要
主要讨论点：CUDA编程的技术细节、学习资源和生态系统发展 不同观点： • **CUDA vs Vulkan设计哲学**：mschuetz认为CUDA的隐式同步设计优于Vulkan，因为CUDA默认处理命令同步，将并行执行作为可选项（通过streams），而Vulkan从一开始就把全部同步复杂性暴露给用户 • **学习资源价值**：kinow从HPC硕士学习者角度指出，这类深入文章（特别是关于warp调度的部分）对初学者极有帮助，应该作为CUDA、MPI+CUDA、OpenCL课程的前置阅读材料 • **Driver API vs Runtime API**：einpoklum提出不同技术路径，认为使用CUDA Driver API和运行时编译器比Runtime API能提供更好的可见性，减少"黑魔法"，并推荐了更现代化的C++ wrapper库作为替代方案 • **内核优化产业前景**：orliesaurus关注商业层面，质疑当前专注于内核优化的公司未来——是会被开源库或Nvidia官方工具取代，还是会作为推理加速的"护城河"被大厂收购 补充讨论：fooblaster补充了技术资源，指出Nvidia有开放的硬件文档，无需阅读内核源码即可了解method文档和qmd格式

Sandia National Labs SA3000 8085 CPU

这篇文章介绍了美国桑迪亚国家实验室在1980年代开发的SA3000抗辐射加固型8085处理器。桑迪亚实验室建立了自己的芯片制造能力，为核武器和太空任务提供商用市场无法获得的特殊器件。SA3000将Intel 8085从HMOS工艺转换为CMOS抗辐射工艺，晶体管数从6500个增至18000个，能承受高达300万拉德的辐射。该处理器被应用于W88核弹头的Trident II导弹控制系统以及深空探测器等极端环境，性能在强辐射下仍能保持60%以上。
