I built Zenith: a live local-first fixed viewport planetarium

文章摘要

Zenith 是一个实时显示头顶星空的网站，通过极小视场高倍率放大，让地球自转造成的恒星视运动可见。它可按用户位置展示对应天区，位置不上传；使用 Pan-STARRS 天文图像、SIMBAD 数据和地图瓦片技术。不同纬度看到不同“星空丝带”，同纬度东西方向仅时间不同。

O(x)Caml in Space

作者: yminsky | 评分: 178 | 评论数: 12 | 发布时间: 2026-05-15 10:55
文章摘要

文章介绍 Parsimoni 的纯 OCaml CCSDS 协议栈 Borealis 于 2026 年 4 月在低轨卫星成功启动。它在 DPhi Space 托管载荷上运行，通过 BPv7/BPSec 实现端到端加密、抗重放与后量子 OTAR 密钥轮换，展示 OCaml 在太空安全系统中的可行性。

评论摘要
主要讨论点：围绕 OCaml/OxCaml 在航天、低延迟系统与可靠软件中的适用性，以及它相对 Rust、Zig、C/C++、Ada、Haskell 等语言的取舍。 不同观点： • OCaml 已有航天实践：rho_soul_kg_m3 称 2016 年 GHGSat-D 低轨卫星载荷软件使用 OCaml，架构为 SystemD 服务通过 DBus 通信，并实现 CCSDS-to-DBus 桥接和对称加密；选择该架构是为兼容未来可能用 C/C++ 等语言开发的模块，但最终未发生。他认为行业常回退到 C/C++，带来“行业标准问题”，如今 Rust 也可覆盖类似场景。 • OxCaml 的性能与 GC 优势：avsm 强调默认 GC 带来便利，同时可用 stack/exclave 等注解减少堆分配；例子是热路径 p99.9 延迟从 29ns 降到 9ns，2500 万包中 minor GC 从 394 次降为 0。 • 对 GC 语言用于实时/低延迟场景的疑问：Decabytes 提到 Java/HFT 中通过预分配和关闭 GC 降低抖动，疑惑“把 GC 语言调成非 GC 行为”到底有多难。 • 协议与安全争议：dsab 认为 CCSDS 容易导致重复造轮子，内存安全未必是最大攻击面；相比自研加密，更倾向采用 TLS 等成熟方案。 • OxCaml 可作为 Rust/Zig 替代：noelwelsh 认为 HN 过度关注 Rust vs Zig，OxCaml 同时具备安全性和易用性，值得考虑。 • 语言选择比较：Maksadbek 询问为何选 OCaml 而非 Ada、Rust、Haskell；satvikpendem 关注 Rust 是否应引入类似 OCaml 5 的代数效应，并想比较两者适用场景。 • AI 编程辅助：kcsrk 称代理能很好生成 OCaml 5/OxCaml 代码，强类型和模式可作为可测试约束，甚至用于课程材料。 补充讨论：部分评论只是表达支持或调侃，如期待 OCaml 登月、“nice”、以及对 Jane Street 的玩笑。

文章摘要

Radicle 是基于 Git 的开源点对点代码协作平台，去中心化复制仓库，用户自主掌控数据与流程。它通过加密身份、签名数据、 gossip 协议和本地优先设计，支持离线使用、抗审查协作，并提供 CLI、Web、桌面端等模块化工具。

评论摘要
主要讨论点：围绕 Radicle 作为去中心化/本地优先代码协作平台的价值、适用场景、成熟度与文档表达展开。 不同观点： • 支持与看好：多位评论者认为 Radicle “Just Works”、被低估，相比 GitHub 更符合本地优先、私有仓库和分布式 forge 的方向；也有人看好其在 agent 工作流中结合加密身份、签名产物的潜力。 • 希望增强本地/私有部署：有人希望能像内网 GitLab 一样，只在几台机器间运行，不接入公共 Radicle 网络；但目前需要大量脚本，文档未覆盖该用例。 • 对替代中心化生态的期待：有人希望 Radicle 替代 crates.io，减少 Rust 对 GitHub/Microsoft 的依赖，并解决命名空间问题；但也担心许可证、生态控制和潜在“跑路”。 • 认可但指出不足：有用户认为其理念正确，优于当前 GitHub，但仍有 rough edges，例如 seeding 机制不理想。 • 质疑实用性与成熟度：有人关心高负载表现、CI 和 PR 流程是否完善。 • 传播与采用障碍：有人想尝试但难找到同伴，因为 GitHub 太流行；还提出网站字体、是否支持 Mercurial/SVN/Pijul 等问题。 • 文档批评：一位评论者认为 FAQ 没解释清楚 Radicle 是什么、与 Git/GitHub 的区别、“forge”含义及为何用户需要它。 补充讨论：有人提醒 Radicle 最近迁移了域名。争议焦点主要在：去中心化 forge 是否足以替代 GitHub/中心化生态，以及 Radicle 当前文档、部署和协作功能是否成熟。
