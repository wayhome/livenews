文章摘要

天文学家使用詹姆斯·韦伯空间望远镜（JWST）在距离地球约111光年的年轻恒星TWA 7周围发现了一个微弱红外光源，可能是一颗系外行星，名为TWA 7 b。这是JWST首次通过直接成像可能发现的系外行星。研究团队利用JWST的日冕仪阻挡恒星强光，从而识别出这颗潜在行星。TWA 7 b质量与土星相近，温度约120华氏度，位于恒星 debris 盘的间隙中，距离恒星约为地球到太阳距离的50倍。尽管存在该光源可能是背景星系的微小可能性，但模拟和观测结果强烈支持其为系外行星。这一发现有助于理解行星系统的多样性及形成过程。

c4wa – C compiler for Web Assembly

作者: 90s_dev | 评分: 54 | 评论数: 7 | 发布时间: 2025-06-24 15:52
文章摘要

**c4wa** 是一个将 C 语言的简化子集编译为 Web Assembly (WASM) 的编译器。它生成的 WASM 输出精简且高效，没有额外的嵌入库或不必要的开销，并且与任何 WASM 运行时完全兼容，不依赖 JavaScript 或 node。该编译器充分利用 WASM 的线性内存模型，支持动态内存分配，并且可以输出文本格式的 WAT，便于理解和手动编辑。 **c4wa** 支持 C 语言的基本特性如循环、条件、指针、结构体、数组和动态内存分配等，适用于日常编程任务。与其它编译器相比，它避免了生成臃肿的 WASM 代码，提供了一种介于高级语言和手写 WAT 之间的中间方案。 该工具需要 Java 11 或更高版本，使用预处理器时需要外部 C 编译器如 gcc。生成的 WASM 文件跨平台，可以在任何支持 WASM 的运行时中执行，包括浏览器。

主要讨论点：对不同WebAssembly（Wasm）工具和语言支持的比较与评价 不同观点： • **关于优化的重要性**：comex 指出，在对比 Emscripten 和 c4wa 时，作者忘记了开启优化选项。comex 认为，未开启优化（-O选项）会导致生成的代码质量极差，而开启优化后，Emscripten 可以生成与 c4wa 一样高质量的代码。 • **对Java依赖的批评**：lioeters 对 c4wa 需要 Java 11 或更高版本表示失望，认为如果 c4wa 能用 C 的子集编写并编译成 Wasm，会更有吸引力。 • **clang 的优势**：s-macke 提到 clang 通过 `--target=wasm32` 选项可以很好地编译成 Wasm，并且生成的二进制文件较小，例如其 16-Bit x86 模拟器项目大小不到 100kB。 • **对C语言特性支持的不足**：teo_zero 指出 c4wa 不支持 C99 引入的许多新特性，但同时也肯定了它不要求使用 K&R 语法。 • **对自由独立模块的支持**：apitman 认为 c4wa 提供了有吸引力的支持，尤其是在构建自定义 Wasm 应用 runtime 时，不需要实现整个 Emscripten 或 WASI API。apitman 还提到新的组件模型过于复杂，希望有更多工具可以利用 C/Rust 的标准库功能。 • **Zig语言的优势**：pyrolistical 提到 Zig 也可以编译成自由独立的 Wasm。 补充讨论： • **项目活跃度问题**：Anduia 指出 c4wa 的最近一次提交是在2022年1月29日，暗示项目可能缺乏活跃开发。 争议焦点： • **工具链的优化与功能支持**：comex 和 teo_zero 等人对不同工具链（如 Emscripten 和 c4wa）在代码优化和 C 语言特性支持上的表现存在不同看法。 • **对Java依赖的看法**：lioeters 对 c4wa 需要 Java 11 或以上版本表示不满，认为这影响了项目的吸引力。 总结：讨论主要围绕 Wasm 工具链的优化、C语言特性支持、Java依赖问题以及对自由独立模块的支持等方面展开，不同评论者根据自己的需求和经验提出了各自的看法和建议。
