作者: djoldman | 评分: 625 | 评论数: 25 | 发布时间: 2026-07-08 23:37
文章摘要

美国联邦贸易委员会(FTC)与多州总检察长周三与农业设备制造商约翰迪尔达成维修权和解协议。该协议要求约翰迪尔向农民和独立维修店开放设备维修权限,提供诊断和维修工具。 约翰迪尔长期因限制维修软件、强制客户使用授权经销商而遭投诉。这是该公司今年第二次维修权和解,此前4月已达成9900万美元的集体诉讼和解。 根据协议,约翰迪尔必须向设备所有者和独立维修店提供完整的诊断维修工具,禁止授权经销商对选择自行维修的客户进行报复。公司需向五州支付100万美元反垄断执法费用,并接受10年合规监督。 该案反映了维修权日益成为消费者关注的焦点,特别是在科技产品领域。

Meta reuses old RAM in new servers with custom bridge chip

作者: ihsw | 评分: 83 | 评论数: 6 | 发布时间: 2026-07-03 19:27
文章摘要

Meta开发了名为Vistara的定制CXL芯片，用于在新服务器中重复利用旧内存条。该公司发现约40%的服务器因内存不足而性能受限，但同时拥有大量退役服务器的旧内存（RAM寿命约为服务器其他部件的两倍）。 Vistara芯片通过CXL接口将旧内存解耦，使其能与新服务器的原生内存协同工作，且不会显著影响性能。这一创新解决方案针对当前内存市场困境：预计2026年底内存价格可能翻倍，短缺可能持续至2027年。 Meta在技术论文中详细介绍了从ASIC设计、操作系统支持到大规模部署的完整实现路径，为应对内存价格飙升提供了经济高效的解决方案。

评论摘要
主要讨论点：CXL内存扩展技术及当前RAM供应危机的应对策略 不同观点： • **技术普及派**：希望CXL内存扩展技术能推出消费者版本，让普通用户也能利用旧RAM硬件，而非仅限于数据中心使用 • **价格质疑派**：从晶体管数量角度分析，16GB内存条（128亿晶体管）售价60美元，而GPU芯片（930亿晶体管）售价2000美元，认为RAM价格虚高不合理，制造成本应该相近 • **危机机遇派**：认为RAM危机促使多方寻找替代方案，将带来创新突破。例如苹果转向中国制造商改变供需格局，厂商开始接受单通道内存等以前不被接受的"妥协"方案 • **技术解决派**：指出市面已有标准CXL内存扩展芯片（如Marvell产品），无需自研定制芯片即可实现内存扩展 补充讨论：有评论分享了CXL技术的学术研究论文，探讨从ASIC设计到大规模部署的完整路径，显示这是一个从理论到实践快速发展的领域

文章摘要

欧洲议会通过了"Chat Control 1.0"法规，允许无差别扫描私人通信直至2028年。尽管多数投票议员反对（314票对276票），但因未达绝对多数门槛而未能阻止。 该法规允许美国科技公司无需搜查令扫描Instagram、Discord、Gmail等平台的私人消息，但WhatsApp等端到端加密通信仍豁免。 批评者指出这种大规模监控效果不佳：自2022年报告量已下降50%，德国警方称48%的警报无刑事相关性，欧盟委员会承认没有证据显示这提高了定罪率或救助儿童数量。 民权活动家Patrick Breyer认为这是不民主的过程，呼吁采用针对嫌疑人的靶向监控而非无差别扫描，认为后者只是"安全幻觉"而非真正的儿童保护。

**主要讨论点：** 欧盟恢复Chat Control 1.0法规，允许科技公司扫描私人消息以检测儿童性虐待材料（CSAM），引发隐私保护与儿童安全之间的激烈争议。 **不同观点：** • **强烈反对派**：认为这是以儿童保护为名义侵蚀公民自由和隐私权，将欧盟比作奥威尔《1984》中的极权社会，质疑欧盟"强隐私保护"的承诺，批评保守派推动此类法规 • **程序正当性批评**：指出欧盟在夏季休会前最后一次会议上，使用"紧急程序"（需要绝对多数才能否决）强行通过投票，认为这种做法过于明目张胆，可能唤醒民众对欧盟结构性问题的认识 • **技术细节关注派**：重点讨论端到端加密（E2E）通讯是否受影响，指出WhatsApp等加密服务暂不受影响，但Instagram、Discord等非加密平台会被扫描；质疑"自愿扫描"的实际效果，因为违法者可能转移到不扫描的平台 • **平衡论者**：尝试呈现双方论据——支持方认为这填补了法律空白，维持现有CSAM检测系统的合法性；反对方认为即使是"自愿"扫描也开创了危险先例，私人通讯的保密性变成条件性而非基本权利，且自动扫描存在误报问题 • **技术对策派**：建议开发点对点（P2P）通讯系统规避监管，认为"需求是发明之母"，会有人开发规避方法 **补充讨论：** 有评论者想了解支持此法规的普通民众理由，但在评论区未找到明确支持声音，暗示这可能是精英层面推动而缺乏民意基础的政策。

文章摘要

cargo-nextest 是一个现代化的 Rust 测试运行工具，具有以下核心特性： **性能优势**：采用现代执行模型，速度比 cargo test 快3倍。 **强大功能**：提供表达式语言精确筛选测试；自动检测并终止慢速测试；支持压力测试和自动重试；可记录、回放和重新运行测试，导出 Perfetto 追踪进行深度分析。 **CI友好**：支持跨多个工作节点分区测试、导出 JUnit XML、配置文件和设置脚本。 **生态系统**：集成测试覆盖率、变异测试、调试器等工具。 **跨平台**：支持 Linux、Mac、Windows 等系统，开源（Apache 2.0），被各规模 Rust 项目广泛采用。 注意：目前不支持文档测试。

评论摘要
主要讨论点：nextest（Rust 测试工具）的使用体验、性能表现和技术特性 不同观点： • **积极评价派**：多位用户表达高度认可。mohsen1 展示了运行 32.5k 单元测试的实际案例，证明性能出色；satvikpendem 强调与 bacon 工具配合效果好；weinzierl 特别称赞"execution model"文档页面解答了 90% 的疑问 • **功能扩展派**：jtwaleson 分享了 fork 版本的创新实践——通过 sidecar 服务器模式复用同一服务器实例运行多个集成测试，显著提升了运行速度。已在 GitHub 讨论区提交相关建议（#3330） • **技术疑问派**：jstrong 指出 nextest 默认只运行 `--lib` 测试，而非像 `cargo test` 那样包含 doc tests，询问如何执行文档测试 • **命名质疑派**：patates 认为"nextest"作为名称不够直观，建议"next-test"可能更清晰 补充讨论：esafak 询问生产环境采用情况，体现出对工具成熟度的关注。整体讨论氛围积极，核心作者 sunshowers 在线回应，但未见明显争议或负面反馈。主要焦点在性能优势和实际应用场景。
