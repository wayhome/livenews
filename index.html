文章摘要

《Atari Mega ST：面向专业用户的计算设备》 Atari于1987年CES上发布了Mega ST，这是其首款针对专业用户的工作站级产品。Mega ST采用了低矮的“披萨盒”造型，内置720K双面软驱和可拆卸的樱桃轴键盘，质量可靠。虽然它增加了2MB或4MB内存，适合开发者和桌面出版，但整体技术规格与1040ST差别不大，仍运行于8MHz，且未配备内置硬盘。Atari将其与SLM804激光打印机捆绑销售，作为桌面出版解决方案，但因品牌形象和价格问题，销售并不理想。尽管如此，Mega ST的键盘和内存优势仍吸引了一些开发者用户。

Why DeepSeek is cheap at scale but expensive to run locally

作者: ingve | 评分: 184 | 评论数: 18 | 发布时间: 2025-06-01 07:31
文章摘要

文章主要讨论了AI模型在不同环境下的性能表现，特别是DeepSeek-V3这类模型在规模化服务时速度快且成本低，但在本地运行时却速度慢且成本高的问题。这主要源于**批量推理**（batch inference）的机制，以及**吞吐量**和**延迟**之间的权衡。 GPU擅长处理大规模矩阵乘法（GEMMs），一次处理大量数据比多次处理小数据效率更高。这是因为每次GPU操作都有一定的开销，且频繁的内存读取会降低效率。因此，推理服务器通常会将多个用户请求进行批量处理，以提高吞吐量，但这也增加了延迟。 对于像DeepSeek-V3这样的混合专家模型（mixture-of-experts），由于其结构包含多个子网络（专家），导致GPU计算效率低，必须依赖批量处理来提升实用性。这类模型在低批量情况下表现不佳，因此在本地运行时速度慢且成本高，而在规模化服务中通过批量处理能达到高吞吐量和较低成本。

评论摘要
主要讨论点：大语言模型（LLM）推理中的批处理（batching）和专家混合模型（Mixture of Experts, MoE）的优化与挑战 不同观点： • **ipieter**：认为推理过程中需要大 batch 是因为 LLM 推理受限于从显存（VRAM）加载参数的带宽，而不是计算能力。随着模型变大，模型权重无法完全放入 GPU 显存，需要跨 GPU 或跨节点分布。专家并行（expert parallelism）允许不同节点保存不同专家模型，减少节点间通信，从而允许更大的 batch 大小。 • **perching_aix**：指出批处理推理通过同时处理多个用户的 prompt 来节省时间，但也可能导致回复的差异，即使在温度参数设为 0 和种子固定的情况下。这种批处理可能引发数据泄露的风险。 • **bick_nyers**：认为软件优化仍有很大空间，尤其在具有适中 VRAM 的系统上运行大型模型时。通过专家模型的稀疏激活特性，可以在某些情况下优化性能。系统性能可能受到其他因素限制，例如 PCIe 带宽利用不充分。 • **DavidSJ**：简要解释高稀疏性模型需要大的 batch 以提高算术强度和利用率。但大的 batch 会导致每个用户请求的延迟增加，因此需要更多 GPU 来平衡性能。 • **angry_octet**：对 LLM 批处理的计算调度和优化表示兴趣，并提到在多 GPU 环境下需要考虑安全应用中的隔离问题。对第二级显存（如 DRAM）在 GPU 上的使用提出疑问，认为可能作为 HBM 缓存的补充。 • **jsnell**：对批处理的必要性和 MoE 模型的优势提出疑问，认为批处理的目的是通过内存带宽来提升计算效率，而不是增大输入矩阵。并质疑 OpenAI 和 Anthropic 模型的快速响应是否真的表明某些事实。 • **corey_moncure**：建议可以通过 PCI-E 带宽优化批处理，将专家模型流式传输到多个 GPU，并优化计算时间与上传时间的匹配，减少等待时间。 • **freehorse**：提到 Apple Silicon 的统一内存架构适合运行 MoE 模型，因为它们可以运行较大模型，尽管速度较慢。MoE 模型计算需求低，适合内存带宽较低的系统。 • **slavboj**：反驳 MoE 模型"慢且昂贵"的观点，指出在旧工作站系统上可以获得不错的推理速度。 • **comrade1234**：质疑 DeepSeek 模型的成本是否仍为其竞争对手的 1/100。 • **philipodonnell**：提出一种商业模式，即通过接受非时间敏感的推理任务，以较低成本获得批处理窗口的空闲处理能力，然后转售给不急需推理的用户。 • **gok**：认为 MoE 是一种"愚蠢的优化"，因为它需要大约 5 倍的参数才能达到与密集模型相同的建模能力，主要优势是市场宣传上可以列出巨大的参数数量。 • **yekanchi**：认为关于大参数模型的陈述适用于所有开放权重模型。 • **dist-epoch**：关心批处理中的各个请求是否会互相影响，尤其是在语义层面，是否会因为批处理导致一个请求的上下文信息泄露到另一个请求中。 补充讨论： - **内存带宽与计算能力**：讨论集中在大型模型推理中内存带宽是主要瓶颈，而非计算能力，因此需要批处理和并行策略来提高效率。 - **批处理与安全性**：批处理可能带来的请求间信息泄露风险以及在安全应用中的潜在问题。 - **MoE 模型的优缺点**：专家模型的稀疏激活特性减少了计算需求，但可能需要更多的参数来达到与密集模型相同的性能，并且在市场宣传上具有优势。 - **系统优化与硬件限制**：不同硬件配置下的性能优化问题，如 PCIe 带宽利用不充分等，以及对第二级显存使用的讨论。

Dear diary, today the user asked me if I'm alive

作者: obrajesse | 评分: 25 | 评论数: 6 | 发布时间: 2025-05-29 20:22
文章摘要
