Why Japanese companies do so many different things

作者: d0ks | 评分: 297 | 评论数: 24 | 发布时间: 2026-05-22 15:22
文章摘要

这篇文章探讨了日本企业极度多元化的现象。以Toto为例，这家以马桶起家的公司如今因生产半导体制造所需的静电卡盘(e-chuck)而利润暴涨230%。文章指出，几乎所有日本大企业都涉足多个看似毫不相关的领域：京瓷生产从陶瓷、打印机到人工宝石的各类产品；雅马哈制造钢琴、摩托车、高尔夫球杆等。这种独特的商业模式反映了日本企业文化中对技术能力和长期投资的重视，使它们能在意想不到的领域获得成功。

评论摘要
主要讨论点：日本企业多元化经营模式的成因、优劣及其文化根源 不同观点： • **结构决定论**（BJones12, claw-el）：日本企业多元化源于终身雇佣制度和股东压力缺失，公司为员工生存而非利润最大化服务；资本获取难度也促使大企业承担更多创新 • **文化决定论**（toephu2）：日本的工匠精神（Shokunin）和对卓越的执着追求才是根本，从威士忌到披萨都体现这种文化特质，而非仅是结构因素 • **批判现实主义**（jdw64, unsignedint, czhu12）：西方过度理想化日本模式，忽视了其阶级固化、僵化的等级制度、"僵尸企业"问题、40年经济停滞和就业市场流动性低等严重弊端 • **相对主义视角**（enaaem, dv_dt）：东西方分散风险方式不同——日本是企业层面多元化，美国是股东个人投资组合多元化；美国曾有类似传统（GE、AT&T）但金融化趋势瓦解了这种模式 • **务实怀疑论**（LZ_Khan, hennell）：缺乏盈利激励会导致资源错配；陶瓷厂做芯片工具并非真正"多元化"，只是同一专业领域的延伸 补充讨论：dmurray指出丰田肯塔基工厂案例实际反驳了"必须全盘移植"的论点；MetaWhirledPeas认为"为就业而存在"的企业理念值得赞赏；whall6提出深层文化差异——日本优化生存，美国优化增长。

Deno 2.8 发布，这是迄今最大的次要版本更新，新增多个子命令： **deno audit fix** - 自动升级有漏洞的 npm 包到最近的补丁版本 **deno bump-version** - 更新 deno.json 或 package.json 中的版本号，支持 patch/minor/major 增量，在工作区中可基于 Conventional Commits 自动推导版本变更 **deno ci** - 专为 CI 环境设计的安装命令，强制使用 lockfile 并在不匹配时报错 **deno pack** - 将 Deno/JSR 项目构建为可发布到 npm 的 tarball，自动转译 TypeScript、生成类型声明文件、重写模块说明符以兼容 npm 生态 升级命令：`deno upgrade`

评论摘要
主要讨论点：Deno、Bun、Node.js 三种 JavaScript 运行时的竞争格局和技术选择 不同观点： • **Deno 优势派**：强调 Deno 的权限模型、原生 TypeScript 支持、安全性和 Web 标准兼容性是核心优势，认为这些特性足以让它优于 Bun（dan_rock_wilson, survirtual, just123） • **Bun 崛起派**：认为 Bun 因速度快、标准库完整、被 Anthropic 收购而快速增长，尽管"混乱"但很有吸引力（vmsp） • **Node.js 稳定派**：Node.js 是稳定方案且会长期存在，现已支持 TypeScript 和单文件可执行打包，仍是主流选择（vmsp, turadg） • **npm 兼容性争议**：有人认为 Deno 默认支持 npm 是明智之举，因为 npm 是事实标准（mohsen1）；但也有人认为 Deno 过早妥协了初衷，应该坚持原有价值观，让 AI 代理来弥合技能差距（ale） • **实用主义观点**：建议至少用 Bun 替代 Node.js，在 AI 时代应优先使用 Rust 和 TypeScript 以获得类型安全和内存安全（survirtual） 补充讨论：有人质疑为何浏览器仍不原生支持 TypeScript；Deno 的沙箱机制优势已被商品化；部分用户关注 Deno 的生产环境使用情况和政府赞助可能性。
