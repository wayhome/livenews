Memory Integrity Enforcement

文章摘要

苹果公司发布了Memory Integrity Enforcement (MIE)技术，这是其历时五年研发的重大安全升级，通过结合Apple芯片硬件和操作系统安全功能，为用户设备提供全天候的内存安全保护，且不影响性能。MIE旨在防御复杂的高级威胁，特别是针对iOS系统的间谍软件攻击，这些攻击通常利用内存安全漏洞。苹果此前已通过Swift语言、安全内存分配器和Pointer Authentication Codes (PAC)等技术提升内存安全。该公司还参与了Arm的Enhanced Memory Tagging Extension (EMTE)规范的改进，以确保同步、强制性的内存安全保护，并通过深度硬件和操作系统集成实现突破性的安全机制。

评论摘要
主要讨论点：[Memory Integrity Enforcement (MIE) 的安全性和实用性] 不同观点： • **支持MIE的观点**： - MIE显著减少了攻击者的可利用策略，使内存损坏漏洞难以被串联利用（tptacek）。 - 这是苹果设备内存安全的重大进步，尤其是在内核和用户进程中（ysnp）。 - 尽管存在一些限制（如攻击者可能多次尝试），但剩余的攻击链将依赖逻辑漏洞，增加了攻击难度（pizlonator）。 • **对MIE的质疑或批评**： - 异步检查（如iOS 9的KPP）存在设计缺陷，可能被绕过（saurik）。 - MIE可能无法完全防止攻击者通过多次尝试绕过保护（pizlonator）。 - 商业计算限制了用户对设备的自由控制（superkuh）。 • **与其他技术的比较**： - MIE与IBM和Burroughs早期内存标记技术相似（rdtsc, EvanAnderson）。 - 与CHERI的比较未明确说明，但引发了对性能影响的疑问（brcmthrowaway）。 补充讨论： - **争议焦点**： - MIE的实际保护效果是否如宣传那样全面（pizlonator vs tptacek）。 - 商业计算与用户自由的平衡（superkuh vs 支持MIE的观点）。 - **其他讨论**： - 苹果未提及GrapheneOS的贡献（ysnp）。 - MIE是否仅限于iPhone 17（whitepoplar）。
