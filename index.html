Reinvent the Wheel

作者: zdw | 评分: 171 | 评论数: 37 | 发布时间: 2025-05-24 20:05
文章摘要

这篇文章讨论了“不要重复造轮子”这句常见建议的局限性，认为鼓励探索和好奇心更为重要。文章指出，通过亲手实现和创造可以加深对技术的理解，即使最终不使用自己的成果，过程中也能学到很多。作者以轮子为例，说明重新发明可以带来更好的解决方案、帮助学习、解决问题以及激发创新。文章最后建议，为了获得洞见可以重新造轮子，而在追求实际影响时则应重用现有成果。作者还推荐了CodeCrafters平台以提升编程技能。

评论摘要
主要讨论点：是否应该重新发明轮子（reinvent the wheel） 不同观点： • **支持重新发明轮子**： - **学习与理解**：重新发明轮子是深入理解技术概念的有效方法，尤其是从基础原理开始构建能够增强对技术的掌握（[megadragon9], [gfalcao], [richardjennings]）。 - **创新与创造**：重新发明轮子可以带来新的视角和创新，甚至可能创造出比现有技术更好的解决方案（[boricj], [gfalcao] 的引用）。 - **避免不必要的依赖**：通过重新发明轮子，可以避免引入过多的外部依赖，从而简化系统（[begueradj]）。 • **反对盲目重新发明轮子**： - **时间和资源限制**：在工作环境或创业公司中，重新发明轮子可能会浪费宝贵的时间和资源，尤其是在有现成且成熟的解决方案时（[mullingitover], [dustingetz], [kayodelycaon]）。 - **生产环境中的风险**：除非重新发明的轮子在质量和功能上能超越现有方案，否则在生产环境中使用可能带来风险（[wcfrobert], [kayodelycaon]）。 • **中立或条件支持**： - **时机和目的**：重新发明轮子应根据具体情况决定，特别是在学习或需要定制解决方案时是有意义的，但在商业项目中需谨慎（[wcfrobert], [richardjennings]）。 - **理性决策**：团队应合理评估是否需要重新发明某些组件，避免陷入“非我发明”（Not Invented Here）综合症，但同时也应考虑市场现有方案的兼容性和成本（[awinter-py]）。 补充讨论： • **哲学与社会批判**：有评论提到现代社会对冗余的过度排斥可能限制了个人创造力和多样性（[ppqqrr]）。 • **学习前人的工作**：在重新发明轮子之前，应先了解已有的工作，以避免重复劳动并从中获得启发（[cryptonector]）。 • **具体案例**：一些评论者分享了个人经验，如构建自定义机器学习库，展示了重新发明轮子的实际学习效果（[megadragon9]）。 争议焦点：重新发明轮子在学习和创新中的价值与其在实际项目中可能带来的时间和资源消耗之间的平衡。

Tachy0n: The Last 0day Jailbreak

作者: todsacerdoti | 评分: 140 | 评论数: 4 | 发布时间: 2025-05-24 19:50
文章摘要

本文介绍了作者Siguza在2020年发现并利用的一个iOS内核漏洞（tachy0n），该漏洞影响了iOS 13.0至13.5，并在unc0ver v5.0.0中发布。这是当时一个罕见的0day漏洞，因为苹果在一周后为此专门发布了补丁。作者解释了这个漏洞的发现过程，以及它如何通过回归测试被重新找到。漏洞存在于lio_listio系统调用中，涉及一个竞态条件，导致内核内存重复释放，从而可以被利用进行内核权限提升。这个漏洞的特殊之处在于它曾被当作1day使用过，但由于苹果的疏忽，它未被完全修复，最终成为0day。作者还回顾了类似漏洞的历史，如SockPuppet，强调了苹果在回归测试方面的不足。

评论摘要
主要讨论点：苹果公司在处理漏洞和回归测试方面的问题，以及与越狱开发者之间的关系。 不同观点： • [yjftsjthsd-h] 认为苹果在处理漏洞（如SockPuppet）时缺乏有效的回归测试机制，导致已修复的漏洞在后续版本中再次出现。他指出，苹果不擅长进行繁琐但必要的回归测试，并认为这是一个容易且可能非常有价值的缺口。他还提出疑问，是否有其他项目也在进行类似的历史漏洞自动化测试，特别是在Linux、FreeBSD等开源项目中。 • [weinzierl] 提到苹果现在为越狱漏洞支付高额奖金（高达一百万美元），这表明苹果认识到了越狱开发者发现漏洞的价值，并且通过这种方式激励外部人员帮助其发现和报告漏洞。 • [ivanjermakov] 认为苹果通过高额奖金激励越狱开发者发现和报告漏洞，是一种极为有效的策略。这不仅帮助苹果修补了漏洞，还通过锁定设备防止了进一步的入侵，相当于利用外部资源免费修复了自身的安全问题。 补充讨论： • 评论中提到了回归测试的重要性，尤其是在处理操作系统级别的漏洞时，如何确保修复后的漏洞不会再次出现。 • 苹果通过支付高额奖金获取漏洞信息的做法，被认为是一种成功的策略，但也引发了对越狱开发者角色的讨论，他们现在可以通过发现漏洞获得经济回报。 • 讨论中还提到是否可以在其他开源项目中应用类似的自动化漏洞测试方法，这需要资源和主动性，但可能带来显著的安全性提升。 争议焦点： • 苹果是否真正缺乏有效的回归测试机制，以及这种机制的缺失是否导致了漏洞的再次出现。 • 苹果支付高额奖金给越狱开发者的做法是否是一种最佳策略，或者是否存在其他更有效的方法来处理漏洞发现和修复过程。

I used o3 to find a remote zeroday in the Linux SMB implementation

文章摘要

这篇文章介绍了作者如何使用OpenAI的o3模型发现Linux内核中的一个零日漏洞。作者在审计ksmbd（一个实现SMB3协议的Linux内核服务器）时，利用o3模型发现了CVE-2025-37899漏洞，这是一个与SMB 'logoff'命令处理相关的释放后使用（use-after-free）漏洞。o3模型成功理解了并发连接如何共享对象，并找出了某个对象在释放后仍可被其他线程访问的问题。作者还提到o3模型重新发现了另一个漏洞CVE-2025-37778，这是一个在Kerberos认证路径中出现的释放后使用漏洞。文章强调，o3模型在代码推理能力上有了显著进步，能够帮助漏洞研究人员提高效率，特别是在处理少于10,000行代码的问题时。

主要讨论点：大型语言模型（LLM）在漏洞查找和自动化工程实践中的应用及其潜在影响 不同观点： • **nxobject**：认为作者的项目组织实践（如将系统提示、背景信息和辅助指令分开存放在不同的文件中）体现了良好的工程思维，类似于其他工程工具，LLM 也需要系统化和规范化的使用才能达到最佳效果。 • **Retr0id**：关注文章中提到的信号与噪声比率（1:50），认为作者对代码库的熟悉程度使得其能够有效区分信号和噪声。同时，强调自动化这一过程将是关键的优化方向。 • **iandanforth**：对作者对不同模型进行100次漏洞搜索的计算量印象深刻，并反思自己是否应增加对大型语言模型的计算投入，尽管 historically 不愿在这方面投入过多资源。 • **simonw**：引用作者在提示开发中的经验，强调许多提示开发过程具有试验性，缺乏足够的评估。作者也提到自己尚未进行足够的评估，因此当前的做法更像是主观愿望而非科学工程。 • **KTibow**：指出不同语言模型生成报告的风格差异，如 o3 生成类似人类书写的简要报告，而 Sonnet 3.7 则像是一连串思考或工作日志，这可能与提示设计有关。建议使用官方的“思考机制”来改善结果。 • **firesteelrain**：表达了对文章所述方法真实性的担忧，担心其可能类似于以往某些不当使用 LLM 的现象，并引用了一个相关博客链接。 • **martinald**：认为这是短期内 LLMs 最大的对齐问题之一，LLM 发现安全漏洞变得过于容易。担心大量长尾软件中的漏洞被自动化工具挖掘出来，可能导致严重的安全问题。 • **logifail**：对 ksmbd 在生产环境中的使用提出质疑，认为它是作为轻量级、高性能的替代方案，但对其使用场景和必要性表示疑惑。 • **zielmicha**：澄清自己不是文章的作者，只是文章标题以 "How I" 开头。 • **dboreham**：幽默地表示，由于 LLM 没有立即指出 "SMB implemented in the kernel, are you f-ing joking!"，因此觉得自己的工作暂时还算安全。 • **jobswithgptcom**：分享了自己使用类似方法开发工具的经验，通过索引 git changelogs 来识别升级过程中可能的风险，包括安全问题。 • **ape4**：建议需要类似具有内存保护的 kernel 模块，以应对当前漏洞查找中的问题。 • **empath75**：认为鉴于发现零日漏洞的价值，全球情报机构可能会投入大量资金用于自动化工具的开发，尤其是能够通过少量 API 调用可靠地发现漏洞的技术。 • **mezyt**：作为维护者，抱怨已经处理了大量误报的 CVE，而文章的方法可能让情况变得更糟。 补充讨论： • 争议焦点在于 LLM 自动化漏洞查找的有效性和潜在风险，部分人对其持乐观态度，认为可以带来显著效益，而另一些人则担心误报问题和潜在的安全隐患。 • 对 ksmbd 在生产环境中的使用及其合理性存在质疑，反映出对特定技术选择的分歧。 • 对提示设计和 LLM 使用的科学性与工程实践之间的差距也有一定讨论，强调了评估和试验的重要性。

Good Writing

作者: oli5679 | 评分: 69 | 评论数: 36 | 发布时间: 2025-05-24 15:03
文章摘要
