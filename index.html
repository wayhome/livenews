Any program can be a GitHub Actions shell

作者: woodruffw | 评分: 160 | 评论数: 17 | 发布时间: 2025-04-08 01:20
文章摘要

在GitHub Actions中，可以使用`shell`关键字指定运行`run`代码块的shell类型。虽然对于工作流而言，该关键字是可选的，但对于动作定义则是必须的。默认情况下，GitHub会根据运行环境选择合适的shell，如Linux和macOS使用bash，Windows使用pwsh。不过，用户也可以自行指定shell，并且GitHub会为某些shell自动添加特定标志，例如`bash --noprofile --norc -eo pipefail`。 值得注意的是，用户可以将`shell`设置为任何在`$PATH`中的可执行文件，而不仅限于GitHub预定义的shell类型。这允许一些非传统用法，例如使用C语言或动态修改`$PATH`。从安全角度看，这种灵活性可能带来潜在风险，因为文件写入操作可能导致意外的代码执行。 总体而言，GitHub Actions的shell执行机制比预期的更为灵活，但也因此可能引入一些安全隐患。

Deleting multiplayer from the Unreal engine can save memory

作者: mariuz | 评分: 43 | 评论数: 6 | 发布时间: 2025-04-06 10:23
文章摘要

这篇文章讨论了在Unreal引擎中移除多人游戏相关功能以节省内存的可行性。尽管Unreal引擎的多人游戏功能集成良好，便于开发，但对于单人游戏项目，这些功能会占用不必要的内存。文章详细分析了即使在单人游戏中，某些变量（如与网络复制相关的数据）仍会占用内存空间，如"bReplicates"变量和一些自定义结构体，分别占用了120和216字节。通过手动移除这些变量，作者成功将每个actor的内存占用减少了328字节。不过，这种优化不易实现，因为Unreal的头文件工具（UHT）不支持通过预处理宏动态排除这些变量。最终，作者通过手动注释相关代码完成了优化，但建议在生产环境中谨慎操作。

评论摘要
主要讨论点：ABZÛ游戏中对多玩家模式及相关组件的优化，以及对内存和性能的影响 不同观点： • [mwkaufma] 认为通过移除多玩家模式和AACtor、UPrimitiveComponent中的其他冗余部分（如内置重叠事件），不仅节省了内存，还减少了无效的读写操作。这些内置重叠事件被视为一种反模式。 • [bengarney] 则提出不同的看法，认为即便在有10万个actor的情况下，删除3-4个纹理就能节省更多的内存，暗示优化纹理可能比移除组件更有效。 • [joegibbs] 补充说，拥有成千上万甚至十万个actor本身可能不是理想的做法，建议通过实例化actor或使用处理UObjects的actor来减少数量，尽管某些情况下可能确实需要这么多actor。 • [out-of-ideas] 似乎偏离了主要讨论点，提到页面加载时循环加载大量请求的问题，并通过屏蔽特定URL加速了页面加载，这个问题与其他评论的技术讨论关系不大。 • [spockz] 关心性能提升的问题，询问移除组件是否仅仅节省内存，还是会带来性能上的提升，尤其是缓存行（cache line）方面的优化。 • [keyle] 则对生产环境中的实际效果表示质疑，询问这些改动是否会在最终的发布版本中产生实际影响。 补充讨论： • 争议焦点在于优化的方式及其有效性：[mwkaufma]强调移除组件和事件的优化效果，而[bengarney]认为纹理优化更有效，[spockz]进一步探讨了性能提升的可能性。 • [joegibbs] 提供了关于actor数量管理的替代方案，指出actor数量过多本身可能是个问题。 • [out-of-ideas] 的评论偏离了技术优化的讨论，但提出了与页面加载性能相关的实际案例。
