文章摘要

本文介绍了作者在NAB展会上意外发现的一个鲜为人知的GPS替代方案——BPS（Broadcast Pulse Synchronization）。BPS是一种实验性的时序标准，可能被纳入美国ATSC 3.0广播系统的推广中。该系统通过电视信号提供精确的时间同步，精度在±10纳秒以内，能作为GPS的地面备份，尤其在媒体、电力网和5G通信等需要高精度时间的领域具有重要意义。尽管目前只有少数电视台参与BPS测试，但其潜力巨大。作者还提到在ASUS展台看到的具有内置PPS同步功能的消费级主板，并计划在后续视频中深入探讨BPS。

YAML: The Norway Problem (2022)

作者: carlos-menezes | 评分: 96 | 评论数: 16 | 发布时间: 2025-04-12 22:10
文章摘要

本文讨论了YAML中的一个常见问题，称为“挪威问题”。在YAML中，挪威的ISO 3166-1 ALPHA-2国家代码"NO"会被解析为布尔值"false"，导致数据错误。YAML的布尔值解析规则允许诸如"yes/no"、"true/false"、"on/off"等值被自动转换，因此像"NO"这样的缩写会引发问题。例如，一个包含国家代码的YAML列表在解析后会将"NO"转为"false"。解决方案包括将有问题的值用双引号转义，或使用如StrictYAML等库来避免自动转换。此外，YAML还会将某些版本号和姓氏如"Null"误转为数字或NULL。文章由比利时前端开发者Bramus撰写，他目前在Google担任Chrome开发者关系工程师。

评论摘要
主要讨论点：YAML 使用中的问题与解决方案 不同观点： • **使用引号包裹字符串**：[raffraffraff] 建议始终使用引号来避免 YAML 中的类型混淆问题。[singpolyma3] 也持类似观点，强调引用字符串。 • **更改数据格式或内容**：[nnurmanov] 提出通过更改国家名称等数据内容来解决特定问题，而不是处理 YAML 格式本身。 • **专用工具与包**：[kazinator] 提到在 Lisp 中使用专用包来处理符号和文本读取，以避免如 NIL 等特殊对象的冲突。 • **使用标签明确类型**：[thund] 支持使用标签来明确数据类型，避免任何可能的混淆，特别是布尔值。 • **YAML 版本问题与替代方案**：[firesteelrain] 指出 PyYAML 的 `load()` 函数采用 YAML 1.1 标准，导致一些问题，并建议使用 `BaseLoader` 作为解决方案。同时提到 ruamel.yaml 是支持 YAML 1.2 的替代库。[riffraff] 也提到 YAML 1.2 在15年前发布，但很多库仍未支持。 • **YAML 问题的影响频率**：[ashishb] 认为 YAML 的问题并不常见，自己使用多年未遇到，并提到 `yamllint` 可以检测此类问题。[dissent] 则认为如果频繁遇到此类问题，可能是因为过度依赖 YAML，建议生成 YAML 而非手写。 • **实际案例与历史问题**：[quechimba] 和 [normie3000] 分享了在实际项目中遇到的 YAML 问题，如挪威用户注册问题和 Google App Engine 的环境变量转换问题。 • **YAML 的设计哲学争议**：[umanwizard] 批评了 YAML 的设计哲学“宽容接受各种输入”，认为这是问题根源。[thyrsus] 提到 Ansible 中 YAML 类型不一致的问题，需要频繁使用过滤器。 补充讨论： • **YAML 与其他数据格式的对比**：[TZubiri] 认为 YAML 的一些边缘情况是其简单和可读性的合理折衷，并将 YAML 与 XML 和 JSON 进行了比较。 • **YAML 社区的争议**：[gnabgib] 引用了多个与 YAML 相关的讨论链接，显示出社区对 YAML 问题的关注和争议。
