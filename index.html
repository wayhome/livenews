40 Years of the Amiga, from Commodore – By Paul Lefebvre

作者: rbanffy | 评分: 37 | 评论数: 10 | 发布时间: 2025-08-07 07:36
文章摘要

1985年7月，Commodore公司发布了Amiga电脑，这款电脑的诞生源于传奇芯片设计师Jay Miner的努力。最初，Amiga项目由Hi-Toro公司启动，旨在开发游戏机，但由于1983年游戏业崩溃，项目转向电脑系统开发。由于资金短缺，Amiga接受了Atari的50万美元投资。然而，1984年Commodore收购Amiga并注资2700万美元。随后，Commodore和Atari因之前的资金纠纷对簿公堂，导致Commodore一度无法公开讨论Amiga。 1985年7月23日，Commodore在纽约林肯中心高调发布Amiga，邀请了名人助阵。尽管早期营销避免直接使用Commodore品牌，但最终Amiga成为了Commodore Amiga。发布后，Amiga迅速引起关注，而其与Atari 520ST的竞争也成为当时话题。尽管发布盛大，作者本人从未实际使用过Amiga，仅通过传闻和评测了解。

Running GPT-OSS-120B at 500 tokens per second on Nvidia GPUs

文章摘要

本文介绍了如何在NVIDIA GPU上优化GPT OSS 120B模型，以在发布当天实现最先进的延迟和吞吐量。团队通过实验、修复错误和基准测试，成功在OpenRouter上实现了领先的性能。主要步骤包括：首先运行基准推理，利用TensorRT-LLM等框架进行测试；修复兼容性问题，确保模型在Hopper和Blackwell架构上的运行；选择张量并行策略以优化延迟，并采用TensorRT-LLM MoE后端提升性能。团队不断进行性能调优，实现了每秒500+ tokens的吞吐量，并在发布日提供了卓越的用户体验。优化过程依赖于灵活的推理堆栈和团队的丰富经验。

We replaced passwords with something worse

作者: max__dev | 评分: 233 | 评论数: 34 | 发布时间: 2025-08-07 02:19
文章摘要

文章指出，许多服务采用了一种不安全的登录方式：用户输入邮箱或电话号码，网站发送六位验证码进行登录。这种方法存在严重安全漏洞，攻击者可以向合法服务发送用户邮箱，获取六位验证码，进而欺骗用户输入码进行盗号。由于密码管理器无法防御此类钓鱼攻击，该方法已被用于成功盗取微软Minecraft账户。文章呼吁停止使用这种不安全的登录方式。

评论摘要
主要讨论点：基于电子邮件一次性验证码的登录流程及其替代方案的优缺点 不同观点： • DecoPerson认为，基于电子邮件的一次性验证码登录流程极易受到钓鱼攻击，用户容易被误导在恶意网站上输入验证码，从而导致账户被盗。DecoPerson推荐使用Passkey，认为其更安全且逐渐得到密码管理器的良好支持。 • StillBored批评了一些服务未经用户同意就更改密码和二次认证方式，导致用户在无法访问手机时被锁定在外。同时，StillBored指出通过短信或电子邮件发送的二次验证方式安全性不足。 • iEchoic描述了其Microsoft账户频繁收到密码重置请求的经历，指出攻击者可以通过大量猜测来窃取账户，但服务提供商并未将其视为安全漏洞。 • Angostura表示难以理解某些描述复杂的登录流程，特别是涉及将验证码输入到不可信界面的情况。 • rsanheim支持使用现代密码管理器，认为其比电子邮件验证码更安全、方便，且设置并不复杂，类似于管理物理钥匙。 • wkat4242认为电子邮件验证码流程不便捷，需要等待和手动输入，推荐使用更简单和安全的Passkey。 • FabHK指出，某些浏览器会自动填充用户名和密码，但对于仅提供电子邮件字段的网站则需手动填写，特别是使用多个邮箱的用户会更麻烦。 • clement_b批评某些产品强制使用验证码登录，而不允许用户使用长密码或社交登录方式。 • allears62抱怨Spotify的登录体验不佳，尤其是频繁生成和发送六位验证码到共享邮箱，既浪费资源又存在安全风险。 • ameliaquining总结了两点抱怨：验证码易被钓鱼和仅需入侵邮箱即可劫持账户。同时，提出通过使用类似Slack的登录链接代替验证码、推广Passkey等解决方案。 补充讨论： • pandorobo批评文章描述不清晰，未能提供更好的多因素认证（MFA）推荐。 • kazinator澄清文章批评的是需要用户手动输入验证码的流程，因其易受中间人攻击，而非基于电子邮件的URL登录方式。 • gregorvand认为服务提供商偏爱电子邮件验证码登录是因为能将风险和责任转嫁给Google/Gmail等邮箱服务提供商。 争议焦点： • 电子邮件一次性验证码登录流程的安全性与便捷性之间的平衡。 • 使用Passkey等新兴认证方式的推广难度与实际效果。 • 服务提供商在更改认证方式时未充分考虑用户体验和安全性。

文章摘要

Claude Code IDE for Emacs 通过 Model Context Protocol (MCP) 实现与 Claude Code CLI 的原生集成，构建了 Claude 与 Emacs 之间的双向桥梁。该工具使 Claude 能够利用 Emacs 的强大功能，如 LSP、项目管理及自定义 Elisp 函数，从而成为真正的 Emacs 感知 AI 助手。主要功能包括自动项目检测、终端集成、MCP 协议支持、工具扩展服务器、诊断集成、高级差异查看、标签栏支持及选择和缓冲区跟踪。通过与 LSP、Tree-sitter、Imenu 和项目管理集成，Claude 可以执行项目内搜索、重构及调用自定义 Elisp 函数。安装需 Emacs 28.1 及以上版本和 Claude Code CLI，并通过 `use-package` 进行配置。基本使用通过交互菜单 `M-x claude-code-ide-menu` 实现。

Herbie detects inaccurate expressions and finds more accurate replacements

作者: bwidlar | 评分: 39 | 评论数: 3 | 发布时间: 2025-08-03 15:54
文章摘要

Debounce

作者: aanthonymax | 评分: 33 | 评论数: 5 | 发布时间: 2025-08-04 16:04
文章摘要

本文简要介绍了编程中的去抖动（Debouncing）概念。去抖动通过在特定时间间隔内合并频繁触发的操作来避免过多执行，常用于处理用户输入，如在用户暂停输入后才执行搜索或过滤操作，以防止界面卡顿。去抖动与节流（Throttling）类似，但节流是限制连续操作的频率，而去抖动则是在操作暂停一段时间后才执行。去抖动分为"前缘"（leading edge）和"后缘"（trailing edge），通常在"后缘"执行函数，但具体实现可根据需求在"前缘"、"后缘"或两者上执行。去抖动确保操作至少间隔指定时间（如10毫秒）执行一次。

评论摘要
主要讨论点： debounce/throttle 在异步函数中的使用及其相关问题 不同观点： • achou 认为，在使用 debounce/throttle 处理异步函数时，可能会导致意外行为。这是因为 debounced/throttled 的异步函数通常返回上次调用时的结果，而这可能是一个之前调用产生的 Promise，导致违反因果关系的结果。他指出，典型的 lodash 风格实现不支持异步安全，需要特别注意实现细节以确保函数在实际调用时返回并解析 Promise。 • thomascountz 分享了其最近关于使用 timeouts 和 AbortController 进行 fetch 请求去抖动（debouncing）的写作和演示，提供了具体的代码示例和解释。他没有直接回应 achou 提出的异步问题，而是通过实际应用示例展示了 debouncing 的一种实现方法。 • kazinator 对 debouncing 的定义和应用场景提出了不同的看法。他认为，传统的开关信号去抖动（switch debouncing）与现代界面中的搜索去抖动（如输入自动完成）有本质区别。前者是为了处理开关接触抖动，而后者是为了减少频繁调用（如每按键一次就触发搜索）。他还指出，拥有更多计算资源时，可以不依赖去抖动技术，直接处理每次输入。这与 achou 的技术讨论侧重点不同，更多关注的是去抖动概念的适用范围和本质区别。 补充讨论： • fnord77 提供了关于开关接触抖动的维基百科链接，这可能是对 kazinator 提到的开关信号去抖动的一个补充资料，帮助理解传统去抖动概念。 争议焦点： • achou 和 kazinator 对于 debouncing 的适用场景和技术实现存在理解上的差异。achou 关注的是异步函数与去抖动结合时的潜在问题，而 kazinator 则认为去抖动在不同场景下的本质区别较大，特别是在处理开关抖动和现代界面输入行为时。 • kazinator 还质疑了去抖动技术的必要性，尤其是在拥有强大计算资源的情况下，这与 achou 强调的异步实现细节形成了对比。
