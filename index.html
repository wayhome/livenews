The RCE that AMD wouldn't fix

文章摘要

作者在AMD的自动更新软件中发现了一个严重的远程代码执行(RCE)漏洞:软件通过HTTP(而非HTTPS)下载可执行文件,且不验证签名,使攻击者可通过中间人攻击植入恶意程序。AMD的漏洞赏金平台最初以"中间人攻击不在范围内"为由拒绝,但在事件引发关注后改变态度,承诺发布CVE并修复,却不支付赏金。AMD要求作者撤下博客文章并延长保密期,但在87天后仍未修复。作者最终决定在披露100天后重新发布文章。

评论摘要
主要讨论点：AMD驱动更新程序存在严重安全漏洞，虽然AMD声称已修复，但实际修复方案仍然不足 不同观点： • **修复不彻底派**：认为仅添加HTTPS不够，必须增加数字签名验证。AMD声称的"签名验证"实际只是CRC-32校验，完全不具备加密安全性，无法防止服务器被入侵后的大规模感染 • **HTTPS可选派**：如果实现了真正的签名验证，HTTPS反而是可选的，签名验证才是关键防护措施 • **MITM威胁严重派**：认为中间人攻击必须纳入威胁模型，不应被排除在考虑范围外。DNS缓存投毒等攻击手段可能不需要完整的MITM就能利用此漏洞 • **AMD软件能力质疑派**：指出AMD在软件开发方面长期存在问题，从历史上看除了优化编译器外，其他软件产品质量堪忧 补充讨论：有评论建议AMD投入小团队实现CUDA兼容以提升市场份额；有用户表示受该弹窗困扰已久；也有人开玩笑称这是政府后门。整体氛围对AMD的软件能力表示失望和不满。

Software Is Made Between Commits

作者: jeremy_k | 评分: 135 | 评论数: 39 | 发布时间: 2026-06-11 16:28
文章摘要

Zed团队推出DeltaDB，一种新型版本控制系统，旨在取代传统的Git提交和Pull Request工作流。DeltaDB将代码变更记录为细粒度的"deltas"流，而非离散的提交快照，使得与AI代理的对话和代码编辑能够同步版本化。每条消息与其产生的代码修改并列记录，引用锚定在delta而非行号上，即使代码变动引用依然有效。这让团队成员和AI代理能实时协作，无需等待提交推送，对话本身成为软件的真正源头。Beta版即将发布。

评论摘要
主要讨论点：关于是否需要版本控制开发过程中的所有中间状态（包括AI代理的交互过程），以及这种做法的价值和隐私问题。 不同观点： • **反对派**：开发过程中的中间代码是"思考的过程"，充满混乱和死胡同，不应该被序列化和公开。提交应该是经过整理的原子化成果，而非真实的时间线记录。（tomjakubowski, Lindby, flerchin, Xotic007） • **技术怀疑派**：Git已经足够处理频繁提交，通过`--first-parent`和`--no-ff`等功能可以实现类似效果，不需要新工具。现有的issue tracker配合Git就能满足需求。（WorldMaker, pjm331, chrishill89） • **支持派**：代码审查应该更早介入，而非等到PR阶段。未来AI代理应该像团队成员一样协作，版本控制应该在后台透明进行。（Lindby部分观点, cbovis, sangeeth96） • **隐私担忧派**：这类工具会导致开发者监控问题，让人深感不适。Google已通过citc收集了十年的开发者数据。（mplanchard, jmole, tengbretson关于API密钥泄露的担忧） 补充讨论：有人认为代码库本身应该自解释，不需要额外的流程和文档（thom）；也有人担心市场竞争激烈，以及Zed可能被大公司收购（prodigycorp, mplanchard）。核心争议在于**开发过程透明度与隐私保护的平衡**。

文章摘要

macOS 27 "Golden Gate" 测试版破坏了 Asahi Linux 的启动能力。更新后，Asahi Linux 分区虽然仍存在且数据完整，但在启动选择器中不可见，无法启动。目前不清楚这是 Apple 的 bug 还是有意为之。Asahi Linux 已向 Apple 提交错误报告，并警告用户暂时避免升级到 macOS 27。建议保留 macOS 26 或更旧版本以便启动 Linux 分区。另外，Linux 7.2 将支持 Apple M3 设备启动。

评论摘要
主要讨论点：macOS 27 beta版本导致Asahi Linux（在Apple Silicon上运行的Linux）出现问题 不同观点： • **非故意破坏派**：认为这是bug而非Apple有意为之。理由包括：Apple曾为Asahi提供过帮助，且Apple本身允许了Asahi这类项目的存在；问题已修复或即将修复 • **监管呼吁派**：希望欧盟监管此类问题，要求Apple等大公司发布官方文档支持操作系统移植，让消费者有权在自己购买的设备上安装任意OS • **平台批评派**：指出Apple Silicon和高通两大ARM平台对Linux支持都很糟糕 • **实用主义派**：质疑同时安装Asahi和macOS beta的必要性，建议用VM运行beta版进行开发测试 补充讨论：评论者普遍认可Asahi团队的逆向工程工作，但也有人认为如果有官方文档支持，很多工作本可避免。整体氛围偏向理性，呼吁在事态明朗前不要过度批评Apple。
