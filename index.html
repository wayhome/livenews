文章摘要

Gatehouse是一个灵活的授权库，结合了基于角色的访问控制（RBAC）、基于属性的访问控制（ABAC）和基于关系的访问控制（ReBAC）策略。其主要特性包括：支持多范式授权、策略组合（通过逻辑运算符AND、OR、NOT）、详细的评估跟踪、流式构建器API、类型安全以及异步支持。核心组件包括策略 trait、PermissionChecker（用于聚合多个策略）和 PolicyBuilder（用于构建自定义策略）。库中还包含内置策略如 RbacPolicy、AbacPolicy 和 RebacPolicy，以及策略组合器如 AndPolicy、OrPolicy 和 NotPolicy。示例代码展示了如何使用这些功能。

作者: rbanffy | 评分: 24 | 评论数: 2 | 发布时间: 2025-03-24 21:20
文章摘要

本文主要讲述了1994年英特尔公司在其Pentium处理器中发现的一个浮点除法错误（FDIV Bug）以及P6处理器的发布。尽管英特尔在个人电脑微处理器市场占据了约75%的份额，并成功进入了其他多个领域，但Pentium处理器在处理某些浮点除法运算时出现了计算错误。1994年6月，林奇堡学院的教授Thomas R. Nicely在研究双素数倒数时发现该问题，并于10月确认是硬件错误。他通过邮件告知英特尔，但英特尔仅表示问题已知，未提供详细信息。Nicely进一步验证发现，Pentium处理器在计算如1/824633702441等数值时返回错误结果。尽管该错误只影响极少数用户，但因英特尔初期处理不当，最终导致召回和更换问题芯片，损害了公司声誉。与此同时，Pentium处理器在性价比上表现优异，与RISC CPU竞争有力。

评论摘要
主要讨论点：围绕计算机硬件历史上的两个特定 bug（FDIV bug 和 F00F bug）的讨论，包括它们在 Linux 内核中的检测方法以及相关的历史背景。 不同观点： • [rwmj 的观点] 提到 Linux 内核使用 1994 年的 "Coe's ratio" (4195835/3145727) 来检测 FDIV bug。他提供了 "Coe's ratio" 的定义链接以及在 Linux 内核代码中的具体实现链接，展示了该历史遗留问题在现代软件中的处理方式。 • [jmclnx 的观点] 提到了 F00F bug，并指出当年 IBM 停止出货有该 bug 的 PC，迫使 Intel 修复问题。他还表达了对当代 IBM 是否会采取类似强硬措施的怀疑。这里隐含的观点是，当年硬件厂商对质量控制更加严格，而现代厂商可能不如过去那么强硬。 补充讨论： • FDIV bug 是 Intel 奔腾处理器中的一个浮点除法错误，历史影响较大，至今在 Linux 内核中仍有应对措施。 • F00F bug 是另一个著名的 Intel 处理器漏洞，该 bug 曾导致系统崩溃。 • jmclnx 对现代 IBM 行为的质疑引发了一个有趣的讨论点，即科技公司对硬件缺陷的态度是否随着时间发生了变化。 争议焦点：虽然没有直接的观点冲突，但 jmclnx 对当代 IBM 行为的怀疑可能引发不同看法。有人可能认为现代公司对硬件缺陷依然严格，只是处理方式和过去有所不同。

《The Prospero Challenge》一文介绍了如何通过解析包含数学表达式的文本文件（prospero.vm）生成图像的挑战。该文件包含7866个数学表达式，通过计算(x,y)值并根据符号决定像素颜色，可以生成特定图像。挑战目标是以最快速度渲染出该图像。文章提供了一个基本的Python渲染器示例，利用Numpy实现像素并行处理，但该方法需要大量内存且耗时较长。 文章鼓励进一步优化，如预解析表达式、使用numba或GPU加速等。此外，还提出了多个优化思路和问题，如优化解释器或编译器设计、数学结构利用、图像大小与渲染时间的关系、以及交互式查看模型的策略等。 文章欢迎大家提交实验结果，并提供了提交方式和背景材料，以鼓励探索不同解决方案。虽然挑战没有丰厚奖励，但作者承诺对有趣的提交者在同城请喝咖啡。

MRubyD: A new mruby virtual machine implemented in pure C#

作者: ksec | 评分: 23 | 评论数: 1 | 发布时间: 2025-03-23 06:52
文章摘要

MRubyD 是一个用 C# 实现的 mruby 虚拟机，专为与 C# 游戏引擎无缝集成而设计，强调与 Ruby 的高兼容性。它利用 C# 的高性能特性，如托管指针和 .NET 运行时的垃圾回收与 JIT 编译器，以提高效率。目前处于预览阶段，支持所有 mruby 操作码，并通过 mruby 测试。但它仍在开发内建类型和方法，且不支持 `private` 和 `protected` 可见性。要编译 mruby 脚本，需使用原生的 mruby-compiler。未来计划包括支持内建 Ruby 库、Fiber、以及 Unity 集成等。使用示例展示了如何执行字节码、处理 MRubyValue、以及通过 C# 定义 Ruby 类和方法。
