A "Frozen" Dictionary for Python

这篇文章介绍了Python社区提出的一项新提案PEP 814，旨在为Python添加不可变的字典类型"frozendict"。主要内容包括： 1. 提案背景：当前Python字典可变性导致并发编程中共享数据存在风险 2. frozendict特性： - 不可变字典类型 - 与常规字典类似但不继承自dict - 可哈希(当所有值都不可变时) - 支持多种创建方式 - 保留键值插入顺序 3. 应用场景： - 提高并发安全性 - 可用于字典键、集合元素等需要不可变对象的场景 4. 讨论情况： - 社区反应总体积极 - 有人建议添加O(1)的原地冻结方法 - 提案已考虑标准库中多处可用frozendict替代dict的情况 该提案旨在提供语言级别的不可变字典支持，增强Python在并发编程中的安全性。

The Cost of a Closure in C

作者: ingve | 评分: 90 | 评论数: 11 | 发布时间: 2025-12-11 07:21
文章摘要

本文主要讨论了C和C++中闭包（closures）的性能问题及其设计缺陷，以及如何解决这些问题。闭包是一种编程语言构造，它包含了与输入参数和返回值无关的数据和指令。文章首先解释了闭包的概念，并指出几乎所有现代编程语言都支持闭包，但C和C++由于其“底层”特性，闭包的设计并不理想。 文章通过一个具体的例子（使用`qsort`函数时如何传递额外数据）展示了闭包在C语言中的常见问题，如静态变量的共享和线程安全问题。针对这些问题，文章列举了四种主要的解决方案： 1. 重新实现函数以接受用户数据指针（如`qsort_r`或`qsort_s`）。 2. 使用GNU嵌套函数直接引用所需数据。 3. 使用Apple Blocks直接引用所需数据。 4. 使用C++ Lambda表达式和一些额外代码来引用所需数据。 每种解决方案都有其优缺点，文章简要介绍了它们的实现方式，并指出了设计上的局限性。

评论摘要
主要讨论点：[关于C和C++中lambda、闭包、静态变量和函数性能的讨论] 不同观点： • [关于静态变量的误解] - 评论者unwind指出作者对C中静态变量的理解有误，认为静态变量在全局作用域下仅影响可见性而非持久性，而函数内的静态变量才会影响持久性。 - 争议焦点：静态变量的作用域和持久性。 • [C++ lambda的性能优势] - Rochus认为C++ lambda的性能优势来自于编译器优化，能够将闭包扁平化为直接成员访问，并指出std::function与std::function_ref的性能差异源于拷贝语义。 - 补充讨论：std::function的拷贝开销在递归中可能导致性能问题。 • [C语言的闭包扩展提议] - sirwhinesalot建议C语言应支持类似C++的本地函数和引用捕获，认为这是最合理的闭包实现方式。 - RossBencina提出“stateful”函数的概念，类似于静态变量但支持多实例，但指出可能难以实现分离编译。 • [测试方法和编译器优化的争议] - mgaunard质疑测试结果的有效性，认为性能差异更多源于测试方法和内联设置，而非语言特性本身。 - 争议焦点：性能测试是否真实反映了语言特性的优劣。 • [其他技术讨论] - nesarkvechnep提到在C++中使用静态模板lambda的优势，而Rust无法实现类似功能。 - ddtaylor提到喜欢使用GNU扩展的蹦床函数。 - Progge对C代码中参数解析的冗长方式提出疑问，认为可以更简洁。 补充讨论： - 评论者psyclobe和capestart分别表达了对C++的推崇和对C语言标准化闭包的支持。 - 整体讨论反映了对C/C++语言特性的深入技术探讨，尤其是性能、可移植性和语法设计的权衡。

How the Brain Parses Language

文章摘要
