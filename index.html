Oberon Pi

作者: tosh | 评分: 43 | 评论数: 2 | 发布时间: 2025-05-04 08:54
文章摘要

Oberon Pi 是 Richard Gleaves 将 Peter de Wachter 的 Oberon 系统模拟器移植到 Raspberry Pi OS 的版本。Gleaves 是前 UCSD Pascal 项目成员，并撰写了《Modula-2 for Pascal Programmers》一书。Oberon Pi 主要改进了用户界面，简化了新用户的学习曲线，同时保留了 Oberon 系统的核心特性。它还集成了 Andreas Pirklbauer 对 Oberon 编译器的修改，完全实现了 CASE 语句并修复了一些编译器错误。该项目提供了全面的文档和指南，包括新的用户指南和原始 Oberon 文档，并可在 Raspberry Pi 400 上运行。为在 64 位系统上运行，需对设置进行一些调整。所有资源可在 GitHub 上获取。

评论摘要
主要讨论点：Oberon操作系统在不同平台和版本上的实现 不同观点： • [xkriva11] 认为有一个基于Ultibo（bare metal）的Oberon版本，并提供了一个GitHub链接（https://github.com/MGreim/ultiboberon），展示了该版本的具体实现。 • [pdw] 指出，这个版本实际上是Oberon操作系统的一个早期版本的移植，该版本最初由Wirth在1992年的《Project Oberon: The Design of an Operating System, a Compiler and a Computer》一书中描述。他还提到，在Wirth退休后，他将系统移植到一个自定义的RISC架构上，而最初的版本是针对已经非常过时的NS32000处理器的。此外，[pdw] 猜测Oberon Pi可能是一个标准的Raspberry Pi Linux发行版，预装了该架构的模拟器。 补充讨论： • [pdw] 强调了Oberon系统的历史演变，区分了早期版本和后期版本的功能差异，指出了早期版本的简陋和后期版本的改进。 • [pdw] 还对Oberon Pi的技术实现进行了推测，认为其可能是在Raspberry Pi的Linux发行版上运行一个模拟器，而不是直接在bare metal环境中运行。 • [xkriva11] 提供的链接显示了一个具体的实现项目，该项目可能代表了Oberon系统的早期版本在现代硬件上的一个移植尝试。 争议焦点：Oberon Pi的具体技术实现方式及其与历史版本的关系。

文章摘要

本文简要探讨了无线USB技术的历史和其消亡原因，以及与Wi-Fi和蓝牙的比较。作者最初尝试通过Palm OS智能手表进行移动网络连接，但设备缺乏内置网络功能。作者设想通过无线USB解决这一问题，回顾了无线USB曾短暂存在的平行技术世界。无线USB基于超宽带（UWB）技术，旨在提供短距离高带宽通信。然而，由于竞争标准和Wi-Fi的普及，无线USB很快在市场上消失。文章还解释了窄带和宽带无线电传输的区别，以及UWB与雷达脉冲技术的渊源。最终，Wi-Fi和蓝牙的普及使得无线USB未能广泛应用。

评论摘要
主要讨论点：无线USB技术的发展、应用及未能广泛采用的原因 不同观点： • **variaga**：无线USB技术在2008-2010年期间实现了USB 2.0的全速无线连接，但由于USB接口同时提供电力，而无线方案仍需通过电缆供电或使用可更换电池，导致其价值主张不明确。此外，由于设备制造商和外设制造商之间的“鸡与蛋”问题，无线USB未能广泛普及。 • **m000**：无线USB的失败在于过度关注硬件解决方案，而忽略了软件解决方案（如USB over IP）的可能性。USB-IF在当时可能更倾向于硬件导向的解决方案，而未能预见ARM架构单板电脑和WiFi普及的趋势。 • **jauntywundrkind**：提到了802.11ad（WiGig）和其在视频及VR头显中的应用，指出这种技术在某些场景下可以减少电缆的使用。同时，也提到USB over IP的潜力和UWB（超宽带）技术的进展。 • **michelb**：指出无线USB信号需要多次翻转才能工作，增加了复杂性。 • **ElFitz**：分享了使用无线USB进行VR设备连接的实际经验，遇到芯片过热和抖动问题。 • **brudgers**：认为“无线USB”听起来很有吸引力，但实际上只是解决了一个USB电缆的问题，而无线USB所需的射频资源与WiFi相同，且没有显著改善在线体验。 • **shahzaibmushtaq**：认为在某些情况下，插拔接口比无线媒介表现更好。 • **kensai**：指出无线USB标准在与WiFi和Bluetooth的竞争中进展缓慢，未能提供足够的优势。同时，提出对不同无线标准的实际能耗比较的疑问。 • **londons_explore**：主张任何新的无线协议都应支持全IP网络，以增加连接的灵活性和可能性。 • **Liftyee**：对无线传输带宽限制表示兴趣，并希望进一步理解波形开关速度的限制。 • **ajross**：提到无线USB芯片在遥控车辆的DSMx协议中仍有应用，但并非市场最佳选择。 • **znpy**：回忆起英特尔CEO曾演示的无线供电和连接技术，认为这种技术若能普及会非常实用。 • **jajko**：质疑无线HDMI技术的发展及其在家庭中的应用潜力。 • **begueradj**：对文章内容表示赞赏，认为其总结了Wirth的工作。 • **RantyDave**：幽默地要求讨论WiMax技术。 补充讨论： - 无线USB未能广泛采用的主要原因包括供电问题、设备与外设制造商之间的“鸡与蛋”问题、以及与其他无线技术（如WiFi和Bluetooth）的竞争。 - 802.11ad（WiGig）技术在某些场景下提供了无线USB的替代方案，但其成本和性能限制仍存在。 - 对无线USB与其他无线技术（如WiFi、Bluetooth）在能耗和应用场景上的比较存在疑问和讨论。 - 有人提出全IP网络支持对于无线协议的重要性，以增加连接的灵活性和设备兼容性。 - 对无线传输技术基础原理（如带宽限制和波形开关速度）的兴趣和进一步理解的需求。
