Native Secure Enclave backed SSH keys on macOS

作者: arianvanp | 评分: 209 | 评论数: 17 | 发布时间: 2025-11-23 17:55
文章摘要

这篇文章介绍了在macOS系统中如何利用安全芯片（Secure Enclave）生成和使用SSH密钥的方法。主要内容包括： 1. 通过`sc_auth`命令创建基于安全芯片的SSH密钥，支持生物识别验证（如TouchID）。 2. 使用`ssh-keygen`从安全芯片导出公钥/私钥对，私钥实际上是FIDO凭证的引用，不包含实际密钥材料。 3. 将生成的SSH密钥用于远程登录和`ssh-agent`。 4. 建议通过设置环境变量`SSH_SK_PROVIDER`来简化操作流程。 这种方法比传统方案更安全，因为私钥存储在硬件安全模块中，且支持生物识别验证。

主要讨论点：[Emacs的导航和编辑效率，以及不同的编辑模式选择] 不同观点： • **avy-mode支持者**（dustfinger）：推荐使用avy-mode进行高效导航和文本移动，认为其体验无可替代。 • **Vim风格导航支持者**（nine_k, rickstanley）：建议使用evil-mode（Vim风格）或god-mode/devil-mode（Emacs风格）提升效率，强调模态编辑的优势。 • **鼠标使用的实用主义者**（mystifyingpoi）：认为鼠标在特定场景（如选择任意代码块）下更高效，反对完全禁用鼠标。 • **传统Emacs控件的捍卫者**（final_aeon）：认为不必拘泥于经典Emacs控制方式，支持使用CUA模式、箭头键等现代化操作。 • **对模态编辑的怀疑者**（OhMeadhbh）：对模态接口持保留态度，但仍愿意尝试以理解其优势。 • **搜索导航的忠实用户**（emil-lp）：长期依赖前后搜索导航，对学习新方法缺乏动力，因编码速度较慢。 • **对isearch的质疑者**（eichin）：质疑avy-mode是否真的比isearch更高效，建议通过外部计时验证。 补充讨论： • **编辑效率的争议**：主要集中在模态编辑与非模态编辑的优劣，以及鼠标是否应完全禁用。 • **工具选择的多样性**：如rickstanley提到尝试Lem作为Emacs的替代品，jmclnx对magit的复杂性和依赖包表示担忧。 • **学习成本与习惯**：emil-lp和OhMeadhbh提到长期习惯和新方法的学习成本问题。
