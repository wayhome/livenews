文章摘要

《地狱般的副业》讲述了作者Jacob Bartlett在一家初创公司Fixr被 exploited 的经历。2019年，作者怀着成为下一个科技巨头的梦想，加入了一个通过朋友介绍的初创公司，担任顾问。Fixr的目标是打造一个连接车主和本地认证技工的平台，尽管团队展示了一些早期成就，如获得启动资金、参加比赛获奖等，但作者很快发现，项目存在许多问题。 作者被要求解决应用开发中的大量bug，但这些应用远未达到发布标准，甚至界面还锁定在iPhone 4s的尺寸。在与海外承包商和代理机构沟通时，作者遭遇了gaslighting（心理操控），最终意识到自己被利用了。这段痛苦的经历让作者变得更加谨慎和明智，希望通过分享这个故事，能帮助其他人避免类似的遭遇。

Show HN: I built a hardware processor that runs Python

作者: hwpythonner | 评分: 309 | 评论数: 20 | 发布时间: 2025-04-28 11:44
文章摘要

PyXL是一种专为直接执行Python代码而设计的定制硬件处理器，无需解释器、JIT或虚拟机，运行速度远超MicroPython。在PyXL上，GPIO的往返时间仅为480纳秒，而PyBoard上的MicroPython则需要约15,000纳秒，这意味着PyXL的速度是MicroPython的30倍，若按时钟速度标准化则为50倍。PyXL通过自定义工具链将Python代码编译为CPython字节码，再转换为自定义汇编代码，最终在基于Zynq-7000 FPGA的硬件上运行。PyXL绕过软件栈，直接在硬件上执行Python代码，从而实现低延迟和高确定性。与传统Python运行时不同，PyXL不存在虚拟机带来的开销，能够实现亚微秒级的精确控制。

评论摘要
主要讨论点：PyXL处理器及其架构设计、性能和应用潜力 不同观点： • **赞赏与支持**：多个评论者（如[boutell], [thenobsta], [tuetuopay], [davidkwast]）对hwpythonner的项目表示赞赏，认为这是一个令人印象深刻的技术成就，尤其是在自定义硬件上直接运行Python的创新性。 • **硬件与语言专用处理器的历史与前景**：[TickleSteve]提到历史上有多种针对特定语言的CPU，但大多数未能广泛应用或随语言过时而转变方向，暗示PyXL也可能面临类似挑战。[thenobsta]则进一步联想到已失败的创新FPGA公司Tabula，暗示FPGA技术的应用限制。 • **与传统编译型语言的比较**：[boutell]提出PyXL是否比设计一种具有Python语法的类型安全语言并编译为原生代码更有优势的疑问，暗示可能存在其他技术路线。 • **技术细节与实现方式**： - [froh]询问PyXL是否是一个运行Python特定微控制器和微码的ASIC，并带有相应的编译器和支持基础设施，试图澄清技术架构。 - [tgtweak]建议在更快的FPGA上进行测试，以评估时钟频率对性能的影响。 - [boxed]建议将Python字节码直接集成到ISA中，以增加项目的酷炫程度。 - [swoorup]关心垃圾收集机制的具体实现。 • **与现有解决方案的比较**： - [Jean-Papoulos]指出PyXL无法使用C库，可能会影响大量现有的pip包。 - [gadys]询问PyXL与PyPy相比的性能和功能差异。 • **关于Python编译的讨论**：[obitsten]质疑为何Python通常不被编译，而是直接使用源代码，并希望了解为何编译的优势未被广泛采用。 补充讨论： • **项目未来发展**：[hermitShell]询问项目是否会永远停留在FPGA阶段，还是有可能进入硅芯片阶段，甚至扩展到RISC-V架构。 • **性能基准**：hwpythonner提供了PyXL在GPIO测试中的早期基准，显示出比MicroPython快30倍的性能，尽管运行在较低时钟频率下。 整体来看，讨论围绕PyXL的技术创新、实现细节、历史背景、性能比较及未来发展展开，展现了社区对这一项目的浓厚兴趣和多角度思考。
