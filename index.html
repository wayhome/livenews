A new PNG spec

作者: tbillington | 评分: 347 | 评论数: 21 | 发布时间: 2025-06-25 03:54
文章摘要

PNG图像格式在停滞二十年后迎来复兴，获得多家机构推荐，并进行了多项重要更新。首先，新版PNG增加了对HDR的支持，使用4字节实现未来验证的HDR图像显示。其次，正式支持动画PNG（APNG），现已广泛兼容。此外，新版还支持Exif数据，包含版权、拍摄地点等信息。其他更新包括修正错误、 clarification和规范整理。技术巨头如Adobe、Apple、Google等已参与新规范的开发，许多软件如Chrome、Safari、Photoshop等已支持新版PNG。未来更新将专注于提升压缩效率和并行编解码。PNG工作组正推动格式持续进步。

主要讨论点：PNG格式的新发展及其相关技术选择 不同观点： • **支持Exif数据**：qwertox认为PNG支持Exif数据是个好消息，并提出Exif是否包含磁力计和加速度计数据的问题，以帮助后期处理如水平校正和全景创建。 • **压缩算法的选择**：Dwedit比较了无损WEBP、无损JXL和无损AVIF的优缺点，指出WEBP在解压速度上有优势，但JXL在文件大小上可能有优势，而AVIF竞争力不足。 • **动画格式的替代**：albert_e提到动画PNG可以替代动画GIF，并具有透明背景和无损压缩的优势，同时对动画SVG的存在表示好奇。 • **时间/日期管理**：ggm提到需要一种统一的方式来处理图像的时间和日期信息，以避免混淆。 • **兼容性问题**：LeoPanthera担心新的压缩算法会破坏PNG的向后兼容性，导致出现非实际PNG文件的问题。 • **HDR支持**：LegionMammal978指出新的cICP chunk类型提供了简化的色彩空间信息，但并非全新的HDR支持。 补充讨论： • **对现有功能的认知**：snickerbockers对某功能的消失表示惊讶，质疑自己是否是唯一仍在使用该功能的人。 • **与JPEGXL的比较**：adgjlsfk1对PNG新发展与无损JPEGXL的竞争表示好奇。 • **动画PNG的实现**：iliketrains分享了自己11年前编写L-system生成器并导出动画PNG的经历，提到当时只有Firefox支持，并提供了相关资源链接。 • **libpng的现状**：hrydgard提到libpng的发展停滞问题，询问是否有新的“官方”C/C++ PNG库。 • **并行压缩/解压**：meindnoch指出通过Z_SYNC_FLUSH已经可以实现并行压缩/解压。 • **经济和技术推动力**：b0a04gl分析了PNG新发展的经济和技术背景，提到需要工具和分发力量的支持，并指出视频格式和SVG的局限性。 • **对格式变革的态度**：tonyedgecombe认为PNG已经成功运行20年，不应轻易改动。 • **JXL与PNG的结合**：jbverschoor建议将JXL融入PNG以增加支持度。 • **对PNG现状的谨慎乐观**：nektro对PNG目前的状态表示谨慎乐观，认为其冻结状态是其受欢迎的原因。 争议焦点： • **压缩算法与兼容性**：在选择新的压缩算法时，如何平衡压缩效率与向后兼容性是一个争议点。 • **PNG新功能的必要性**：部分用户认为PNG的现状已经很好，不应轻易改动，而另一部分用户则期待新功能带来的改进。

Reading NFC Passport Chips in Linux

作者: robin_reala | 评分: 127 | 评论数: 6 | 发布时间: 2025-06-25 07:33
文章摘要

文章描述了如何使用Linux系统读取护照NFC芯片中的数据，重点介绍了利用Python脚本重建机器可读区（MRZ）作为NFC芯片密码的过程。护照的NFC芯片受密码保护，密码由护照号码、出生日期和到期日组成，每个数据段都有校验码。由于作废护照的MRZ部分被剪掉，文章提供了生成MRZ的Python代码，利用已知的护照信息计算出完整的密码。 文章还探讨了护照NFC芯片的安全性，指出由于芯片没有计时器，无法记录读取次数，理论上可以通过暴力破解尝试密码。尽管破解过程可能需要几天时间，但并非不可能。此外，文章提到大多数NFC芯片支持无限次读取，这增加了被破解的风险。最终，文章提醒用户护照的安全性依赖于物理和密码学的多重保护。

评论摘要
主要讨论点：机器可读旅行证件的技术规范及其在现实中的应用 不同观点： • **tauntz**：认为国际民航组织（ICAO）的9303号文件提供了详细的证件验证和数据读取规范，但现实中各个政府在实施时往往会有各种创造性的解读和漏洞，导致软件开发者需要面对许多调试问题。 • **wkat4242**：指出许多护照包含数字化指纹扫描，但这些信息难以获取，因为只有政府才拥有访问所需的私钥。 • **SXX**：质疑规范中是否包含护照发行方的数字签名，以帮助其他国家验证护照的真伪，并指出相关信息不够透明。 补充讨论： • **stavros**：对护照解密过程中遗漏的校验和问题以及计算校验和的难易程度表示关注，认为原文中遗漏了这些有用的信息。 • **frelp**：提出是否可能创建一个能够破坏护照读取系统的芯片，并希望这种情况不存在。 • **dzhiurgis**：质疑是否可以通过在假护照中植入自定义照片和元数据来欺骗系统，对系统的安全性表示担忧。 争议焦点： • 护照验证过程中的安全性及其实际应用中的漏洞是讨论的主要争议点。例如，SXX和dzhiurgis对验证机制和防伪措施的有效性表示怀疑，而tauntz和wkat4242则指出了现实中存在的技术挑战和安全措施。 这些观点共同描绘了机器可读旅行证件技术规范在理论和实际应用中的复杂性和潜在问题。

Fun with uv and PEP 723

作者: deepakjois | 评分: 306 | 评论数: 30 | 发布时间: 2025-06-24 18:41
文章摘要

文章介绍了使用 **uv** 和 **PEP 723** 元数据简化 Python 脚本运行的新方法。 **uv** 是一个用 Rust 编写的高速 Python 包和项目管理工具，带有 **uvx** 命令，可自动处理虚拟环境、Python 版本和依赖包。 **PEP 723** 提出了一种在单文件脚本中嵌入元数据的方法，帮助启动器和 IDE 识别所需的 Python 版本和依赖。 结合 **uv** 和 **PEP 723**，可以轻松运行包含依赖的 Python 脚本，例如提取 YouTube 视频字幕的脚本。通过在脚本中加入 shebang 行 `#!/usr/bin/env -S uv run --script`，脚本可直接作为可执行文件运行，无需手动配置环境。这使得 Python 在处理一次性脚本时更加便捷和高效。

The probability of a hash collision (2022)

文章摘要

这篇文章讨论了哈希碰撞的概率问题。哈希函数将复杂输入映射为一个数字，用于数据存储和加密等领域。当两个不同的输入被哈希函数映射到同一值时，就会发生哈希碰撞，这可能导致问题。文章通过生日问题来解释哈希碰撞的概率。例如，在一个房间里有30个人，他们中有两人同一天生日的概率约为70.6%。类似地，计算哈希碰撞概率时，我们首先计算没有碰撞的概率，然后用1减去这个值。 具体来说，如果有N个盒子（如生日问题中的365天）和k个物品（如房间中的人），没有碰撞的概率是N/N × (N-1)/N × ... × (N-(k-1))/N。因此，至少有一个碰撞的概率是1减去上述结果。文章还提到，随着物品数量增加，碰撞概率逐渐增大，即使有大量盒子，碰撞也难以完全避免。
