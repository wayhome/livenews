Void: Open-source Cursor alternative

作者: sharjeelsayed | 评分: 148 | 评论数: 21 | 发布时间: 2025-05-08 16:35
文章摘要

Void是一个开源的代码编辑器，是Cursor编辑器的替代品，基于VSCode分支开发。该项目托管在GitHub上，拥有13.2k颗星和831个分支。Void提供完整的源代码，并欢迎社区贡献。项目包含多个文件和配置，支持开发者通过贡献指南（HOW_TO_CONTRIBUTE）参与开发。它还提供了代码库指南（VOID_CODEBASE_GUIDE）以帮助理解项目结构。Void支持多种编程语言，主要使用TypeScript开发。社区可以通过Discord频道或邮件与团队联系以获取支持或参与协作。

Fui: C library for interacting with the framebuffer in a TTY context

作者: Bhulapi | 评分: 43 | 评论数: 8 | 发布时间: 2025-05-08 22:05
文章摘要

`fui` 是一个用于帧缓冲区（framebuffer）的 C 语言库，能够在 tty 环境下进行图形界面操作。它支持： 1. 向多个图层绘制像素，然后合成并渲染到帧缓冲区。 2. 基本的图形绘制功能，如线、矩形和圆。 3. 使用位图字体进行文本渲染。 4. 利用 `libevdev` 处理键盘和鼠标事件，并实现了一个通用事件系统。 5. 使用 ALSA 实现简单的音频播放功能。 安装步骤包括运行 `make` 和 `sudo make install`，库是静态链接的。由于需要 root 权限访问视频和输入设备，建议将用户添加到 `video` 和 `input` 用户组。示例代码和简单的游戏（如 `asteroids`）包含在项目中。该项目使用 MIT 许可证。

文章摘要

本文介绍了水库抽样（Reservoir Sampling）技术，用于在不知道数据总规模的情况下进行公平随机抽样。文章解释了何时需要使用水库抽样，并通过简单的乘除运算展示了其背后的数学原理，而未使用复杂的数学符号。文章还模拟了一个日志收集服务在面对大量日志涌入时的场景，说明了如何通过水库抽样在日志流高峰期进行公平抽样，避免系统过载。水库抽样的优势在于，它能够在不确定数据总量的情况下，保证每个元素都有均等的被选中机会，同时避免内存过度消耗。文章最后提供了一种简单的实现方法。

Stability by Design

作者: potetm | 评分: 51 | 评论数: 5 | 发布时间: 2025-05-08 19:51
文章摘要

这篇文章讨论了动态类型语言中库的稳定性问题，并以Clojure为例，展示了其生态系统的稳定性。作者引用了Clojure社区对稳定性的赞誉，并通过Clojure及其库的代码引入和保留图表，以及Fusebox库的维护实例，证明了Clojure库的稳定性。文章指出，尽管Clojure是动态类型语言，但其惯例和实践使其具有类似静态语言的稳定性。Clojure程序主要由命名空间、函数和数据构成，避免了猴子补丁和对象序列化问题，这使得代码更易预测和维护。这种文化和实践使得Clojure在动态类型语言中显得与众不同，并保持了高度的稳定性。

评论摘要
主要讨论点：编程语言和库的稳定性及变更管理 不同观点： • [Animats] 认为Rust的3D图形栈不稳定，API频繁变更（包括重命名类型、更改函数参数、甚至重构事件循环等），导致相关组件（如Wgpu、Winit、Egui）必须同步更新，但各开发组之间缺乏协调，用户在遇到问题时难以回退到旧版本，最终导致项目停滞和用户流失。 • [RandomWorker] 则从Clojure的角度出发，认为Clojure的稳定性极佳，回访旧项目时仍能顺利运行。相比之前使用PHP、Perl、Java和Python的经验，Clojure的学习曲线虽然陡峭，但一旦掌握，项目维护变得非常轻松。 • [alexjurkiewicz] 提出不同语言的主要库都会面临代码积累的问题，并认为衡量生态系统稳定性的标准应包括主要版本发布的频率和代码替换的多少，而非单纯看代码变动量。 • [juancn] 对[alexjurkiewicz]的观点进行补充，认为开发者害怕更改代码才是导致库“看似稳定”的原因，并以Scala为例，指出某些语言由于安全性高，变更代码并不危险，因此更容易维持稳定。 • [simultsop] 总结认为，无论是静态类型还是动态类型语言，遇到API breaking changes时都需要进行重构，这是普遍存在的问题。 补充讨论： • Rust 3D图形栈的API频繁变更和缺乏协调导致用户体验较差，进而影响项目进展和用户信心。 • Clojure被认为是一个维护性好、稳定性高的语言，尤其适合长期项目。 • 衡量库稳定性的标准存在争议，有人认为应关注版本发布和代码替换频率，而非单纯依赖代码变动量。 • 不同语言（如Scala和Clojure）在处理代码变更时的表现和安全性有所不同，影响开发者的体验和选择。
