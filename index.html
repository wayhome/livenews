Faking a JPEG

作者: todsacerdoti | 评分: 214 | 评论数: 15 | 发布时间: 2025-07-11 22:57
文章摘要

本文介绍了一个名为Spigot的小型web应用程序，它通过马尔可夫链生成虚假的网页内容，以应对激进的网络爬虫。作者观察到一些爬虫伪装身份，可能通过僵尸网络非法利用他人设备。其中一个名为ImageSiftBot的爬虫不断请求不存在的图片。为应对这一情况，作者构思了一种生成假JPEG图片的方法，利用现有JPEG文件的模板，用随机数据填充图像数据部分，以低CPU消耗生成看似有效的JPEG文件。尽管这些文件包含错误，大多数JPEG查看器仍会显示图像，从而给爬虫增加负担。这种方法有效增加了爬虫的成本，尽管未完全实现最优的霍夫曼编码插入。

评论摘要
主要讨论点：围绕技术细节和网络爬虫相关问题的讨论，包括 robots.txt 文件的使用、JPEG 图片处理、网络流量来源、AI 输入抓取干扰等。 不同观点： • tomsmeding 提到目标网站的 robots.txt 文件禁止了爬虫访问 spigot 目录，但移除 URL 中的 /spigot/ 部分仍会导向 Spigot。此外，/~auj 命名空间未被禁止，可能导致爬虫陷入无限页面循环。 • kazinator 认为伪造 JPEG 文件不仅比正确制作更节省 CPU 资源，还能通过模糊处理潜在的恶意软件，使其崩溃。 • derefr 反驳了关于流量来源的假设，指出流量来自数千个住宅 IP 并不一定意味着存在非法 botnet，也可能是人们使用“免费 VPN 服务”或类似工具，成为出口节点。 • jandrese 提出可以通过给图片添加虚假说明来干扰 AI 输入抓取器，例如给随机图片加上不匹配的描述。 • mrbluecoat 对以积极态度应对激进的网络爬虫表示赞赏，而不是愤怒地在论坛上发泄。 • EspadaV9 对某张图片表示欣赏，认为其具有某种声明性质。 • marcod 回忆起 Project Honey Pot 的经历，提到其网站帮助捕捉垃圾邮件采集器的成就感。 • superjan 提到在 JPEG 流中插入特定字节以避免非法模式的问题，并表示如有兴趣可后续跟进。 • Modified3019 对项目表示赞赏，但指出图片偏向绿色，建议增加检查机制以识别异常抓取行为。 • 112233 询问如何设置类似的网络陷阱，是否需要个人博客或可以在 Cloudflare 上部署。 • lblume 认为当前的 LLM 已能有效区分半合理的垃圾信息和相关文本，因此不认为数据污染会对未来模型造成影响。 • bschwindHN 建议生成伪造但可信的 EXIF 数据以配合伪造 JPEG 图片。 • hashishen 对项目表达赞赏，认为其是应得的英雄。 • dheera 讨论了 JPEG 数据压缩和随机性问题，指出虽然 Huffman 编码的 JPEG 系数看似随机，但实际上并非如此。 • puttycat 质疑压缩是否会增加比特流的熵，认为加密才会增加熵。 补充讨论： • 讨论中涉及的技术细节包括 robots.txt 的使用、JPEG 文件处理、网络流量来源分析、爬虫干扰策略等。 • 争议的焦点在于流量来源的判断，derefr 反驳了关于 botnet 的假设，提出可能是“免费 VPN 服务”或类似工具导致。 • 另一个值得注意的讨论点是如何通过技术手段（如伪造图片、虚假说明、伪造 EXIF 数据）干扰爬虫和 AI 抓取器的行为。

Preliminary report into Air India crash released

作者: cjr | 评分: 154 | 评论数: 25 | 发布时间: 2025-07-11 20:23
文章摘要
