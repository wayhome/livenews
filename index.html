Genetic Code Enables Zebrafish to Mend Damaged Organs

作者: bookofjoe | 评分: 15 | 评论数: 0 | 发布时间: 2025-06-29 01:00
文章摘要

新研究由加州理工学院（Caltech）和加州大学伯克利分校（UC Berkeley）合作完成，发现斑马鱼能够修复和再生受损心脏的能力与其神经嵴细胞有关。这些细胞占斑马鱼心脏细胞的12%至15%，在心脏受损时启动再生过程。研究揭示了一组在再生过程中被激活的基因，这些基因在胚胎发育期间活跃，成年后休眠，再生时重新激活。研究团队希望通过CRISPR技术在人类心脏细胞中重新激活这些基因，以探索人类心脏再生的可能性。该研究发表在《美国国家科学院院刊》上。

The new skill in AI is not prompting, it's context engineering

作者: robotswantdata | 评分: 335 | 评论数: 60 | 发布时间: 2025-06-30 20:53
文章摘要

"Context Engineering" is emerging as a key focus in AI, surpassing the previous emphasis on "prompt engineering." It involves providing all necessary context to make a task solvable by large language models (LLMs). This includes not just the user prompt, but also instructions, conversation history, long-term memory, retrieved information, and available tools. The quality of this context determines an agent's success or failure. For example, a "magical" AI assistant uses rich context like calendar information, past emails, and contact details to generate helpful responses, unlike a "cheap demo" agent that provides robotic and unhelpful outputs. Context engineering is a dynamic, system-based approach that ensures the model receives the right information and tools in the appropriate format, highlighting that successful AI agents rely more on context quality than model complexity or code sophistication.

Donkey Kong Country 2 and Open Bus

作者: colejohnson66 | 评分: 202 | 评论数: 11 | 发布时间: 2025-06-30 15:01
文章摘要

《Donkey Kong Country 2》在旧SNES模拟器ZSNES中存在一个知名bug：某些关卡的旋转桶无法正常控制。具体表现为，当角色跳入桶中后，按方向键本应控制桶的旋转，但在ZSNES中，轻触方向键会导致桶无限旋转，直到按反方向键才会停止。这个bug使游戏难度增加，因为旋转桶常出现在尖刺等危险上方。 该问题源于ZSNES未正确模拟"开放总线"行为。这种行为发生在读取无效内存地址时，CPU会重新读取上次在数据总线上的值。SNES的CPU是65816，其复杂的内存分页和地址处理进一步增加了模拟难度。 这个问题曾在ZSNES论坛上讨论，但论坛已下线，而另一个模拟器Snes9x通过硬编码修复了此问题。ZSNES由于长期未更新（最后版本于2007年发布），该bug一直未被修复。

评论摘要
主要讨论点：围绕"开放总线"（Open Bus）的技术讨论，包括其定义、影响以及在不同硬件和仿真环境下的表现。 不同观点： • **deater的观点**：作为6502汇编程序员，提到忘记在立即值前加#号会导致内存访问而不是立即数操作，这种情况有时能偶然工作，但在不同DRAM芯片上可能会出错，尤其在演示活动上很难调试。 • **Dwedit的观点**：分享了在处理RetroArch的RunAhead功能时遇到的PPU开放总线问题，导致存档状态不匹配，强调了CPU执行跟踪日志的重要性。 • **userbinator的观点**：认为"开放总线"主要存在于早期系统中，现代系统在访问不存在的地址时通常会返回全零或全一，因为总线协议有握手机制。 • **anonymousiam的观点**：最初以为"Open Bus"是某种旧总线协议，后来理解为未连接任何设备的总线，并指出未注意到的立即数问题在仿真器上未表现出来。 • **nicetryguy的观点**：认为忘记使用#号的错误很常见，即使是汇编高手也难免犯错，建议通过IDE高亮提示来避免。 • **NobodyNada的观点**：详细解释了开放总线的硬件行为，包括寄生电容效应和不同游戏对开放总线的依赖，以及在速度运行和特定游戏中的利用。 补充讨论： • **开放总线的具体表现**：在不同游戏和硬件上，开放总线可能返回未定义值、上次传输的值或零，具体取决于硬件设计和DMA等功能的影响。 • **争议焦点**：在Super Metroid速度运行中，因HDMA与开放总线的交互导致某些策略仅在仿真器上可靠，而在原始硬件上可能崩溃，这在社区中引发了一些争议。 • **技术细节与实例**：提供了多个技术视频链接，展示开放总线和HDMA交互在实际游戏和速度运行中的应用。 • **个人体验与感受**：一些用户分享了使用仿真器和FPGA的体验，以及对经典游戏如DKC2的喜爱和赞赏。 总的来说，讨论围绕开放总线的技术细节、实际影响以及在游戏和仿真中的具体表现展开，并涉及了一些相关的个人经验和感受。

People Keep Inventing Prolly Trees

文章摘要

本文讨论了“多重发现”现象，即科学发现常由不同人在相近时间独立完成，例如牛顿和莱布尼茨同时发明微积分，以及达尔文和华莱士同时提出进化论。文章提出，多重发现可能是常态，发明常是社会条件的产物，当发现的前提条件成熟时，往往会迅速被多次发现。文章还以“概率树”（prolly trees）为例，说明这种数据结构在不同领域和名称下被独立发明了至少四次，显示其是既有概念的创新组合，而非全新创造。概率树结合了内容定义分块和Merkle树等已有技术，其发明是技术发展的自然结果。
