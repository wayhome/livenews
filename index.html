An Intro to DeepSeek's Distributed File System

作者: sebg | 评分: 307 | 评论数: 14 | 发布时间: 2025-04-17 12:50
文章摘要

** summary ** 3FS是DeepSeek发布的分布式文件系统，旨在提供大规模数据存储和高吞吐量。分布式文件系统将文件分布在多个机器上，但对用户而言操作如同本地文件系统。3FS包含四大核心组件：Meta管理文件元数据，Mgmtd管理集群配置和节点发现，Storage存储实际文件数据，Client负责与各节点交互。Mgmtd通过心跳机制监控节点状态，Meta使用FoundationDB存储元数据，Storage节点使用Rust编写的ChunkEngine管理数据块。3FS具有高容错性和冗余性，适合大规模并行处理和机器学习等应用。

评论摘要
主要讨论点：分布式文件系统的比较与选择 不同观点： • [jamesblonde] 认为 S3FS 具有两个重要特性：支持 FUSE 客户端和 NVMe 存储，使其在训练管道中不受磁盘 I/O 限制。他还提到 HopsFS 增加了分层存储功能，使用 NVMe 存储近期数据，并使用 S3 进行归档。 • [huntaub] 提出评估这些系统应从理论极限、效率和实际极限三个维度进行。他比较了 S3FS 和 FSx for Lustre 的成本效率，并指出管理集群的复杂性。 • [robinhoodexe] 对 SeaweedFS 和 S3FS 进行了比较，提到 SeaweedFS 用于存储 3 PB 数据，并询问两者的对比情况。 • [snthpy] 询问 S3FS 与 JuiceFS 的比较，特别是对于家庭实验室设置的适用性。 • [londons_explore] 认为复杂的分布式文件系统对于深度学习工作负载可能不必要，强调 PB 级别的存储、读写并行性和冗余更为关键，而一致性则可通过编程手段解决。 • [stapedium] 关注大数据分布式文件系统的备份和恢复问题，特别是小型企业和家庭实验室的使用场景。 • [seethishat] 作为 DeepSeek 新手，询问如何在确保数据不离开本地研究集群文件系统的情况下禁用 DeepSeek 的分布式文件系统。 • [randomtoast] 质疑为何不使用经过验证的 CephFS，并指出其在 PB 级别的可靠性。 • [nodesocket] 提出分布式文件系统是否能推动完全分布式的大语言模型部署，并认为使用 AMD EPYC 服务器集群可能比 Nvidia GPU 更具成本效益。 • [vFunct] 询问是否可以通过跨多台机器的 ZFS 驱动器实现类似的分布式文件系统。 补充讨论： • [dkkergoog] 和 [mertleee] 的评论带有偏见或阴谋论色彩，未提供实质性讨论。 • [jack_pp] 提到希望作者解释为何已有开源解决方案不适合他们的需求，这反映了对于选择理由的关注。 争议焦点： • 不同分布式文件系统在功能、效率和复杂性上的比较，特别是 S3FS 与其他系统如 SeaweedFS、JuiceFS 和 CephFS 的优劣。 • 分布式文件系统在特定场景（如深度学习、小型企业、家庭实验室）中的适用性和必要性。

Unauthenticated Remote Code Execution in Erlang/OTP SSH

作者: kimi | 评分: 100 | 评论数: 8 | 发布时间: 2025-04-17 13:29
文章摘要

CVE-2025-32433 是指 Erlang/OTP 库中的一个安全漏洞。在 OTP-27.3.3、OTP-26.2.5.11 和 OTP-25.3.2.20 之前的版本中，SSH 服务器存在漏洞，可能允许攻击者执行未经身份验证的远程代码执行（RCE）。利用 SSH 协议消息处理中的缺陷，攻击者可以未经授权访问系统并执行任意命令。该问题已在上述版本中修复。临时解决方法包括禁用 SSH 服务器或通过防火墙规则限制访问。该漏洞的 CVSS 3.1 评分为 10.0（严重），属于 CWE-306 认证缺失漏洞。

评论摘要
主要讨论点：Erlang/OTP SSH库的漏洞及其潜在影响 不同观点： • [aftbit] 认为该漏洞涉及Erlang/OTP内置的SSH服务器，而非在安装了Erlang的服务器上运行的OpenSSH。任何使用Erlang/OTP SSH库进行远程访问的服务，如OT/IoT设备和边缘计算设备，都可能受到攻击。 • [aposm] 表示他们正在内部推销一个基于Elixir的全新项目，虽然该漏洞默认不影响Elixir，但可能会让项目更难向管理层推销。 • [throwawaymaths] 指出大多数Elixir部署可能不受影响，因为SSH默认是关闭的。不过，仍建议仔细检查以确保安全。 • [qwertox] 关心该漏洞对ejabberd等服务器的影响，并询问该服务器最近的升级是否包含对该漏洞的修复。 • [bilekas] 对在即将关闭的存档网站上看到这则消息感到奇怪和不安。 • [formerly_proven] 详细解释了漏洞的补丁，指出问题在于可以在认证前请求通道并执行命令。并提到该问题是由RUB的研究人员发现的，他们致力于协议实现的验证研究。 • [rramadass] 提供了一个关于Erlang/BEAM语言安全方面的资源链接，即Erlang Ecosystem Foundation的安全工作组指南。 补充讨论： • 讨论中提到了具体的漏洞细节和补丁信息，并引用了相关的研究来源。 • 有人关心具体应用和服务器（如ejabberd）的更新是否包含漏洞修复。 • 提供了有关Erlang生态系统安全方面的进一步资源和指南。 争议焦点： • 该漏洞对不同应用和项目的实际影响程度存在不确定性，尤其是对Elixir项目和ejabberd服务器的影响。
