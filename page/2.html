EZRA是一个持久化任务队列系统，多个服务可以推送任务，多个worker可以拉取并处理任务。它基于SQLite存储，使用Erlang/OTP运行时，但worker可以通过任何Redis客户端连接（无需Redis本身）。 核心特点： - 每个任务必须被worker明确标记完成，不会静默丢失 - 单个Docker容器即可运行，无需集群配置 - 使用Redis RESP3协议，支持任何语言的Redis客户端 - 吞吐量可达1.5万-8万任务/秒（取决于磁盘） - 内存占用低（每个连接约2KB，基础20MB） - 所有数据持久化到SQLite文件 适用于需要后台任务处理（如发邮件、生成PDF）但不想维护复杂消息队列系统的场景。

主要讨论点：一个使用 Redis 协议的项目发布，涉及项目维护方式、技术选择和相关替代方案的讨论。 不同观点： • **项目维护建议**：bhaney 建议作者直接在 GitHub 仓库设置中禁用 PR 功能，因为项目声明不接受 PR，这样可以避免用户不阅读说明而提交 PR 的麻烦 • **技术认可**：abrookewood 称赞使用 Redis 协议是聪明的选择，并询问是否必须作为独立服务器运行，显示出对架构灵活性的关注 • **灵感来源探讨**：neoecos 提到 Oban（Elixir 生态的作业处理库），询问该项目是否受其启发，暗示可能存在功能或设计上的相似性 • **替代方案推荐**：cpursley 推荐了基于 Postgres 的替代方案 PgFlow（使用 pgmq），针对需要 DAG 工作流且希望使用 Postgres 的用户 补充讨论：评论整体氛围积极，没有明显争议。讨论聚焦在技术实现细节、灵感来源和生态系统中的类似工具，体现了开发者社区对不同技术栈解决方案的关注。
