DeepSeek-V4-Flash means LLM steering is interesting again

作者: Brajeshwar | 评分: 124 | 评论数: 12 | 发布时间: 2026-05-16 14:58
文章摘要

文章介绍“steering”：在本地大模型推理中直接调控激活向量以改变输出风格或能力。作者以 DwarfStar 4/DeepSeek-V4-Flash 为例，说明其原理、潜力与局限：相比提示词更直接，但受限于模型访问、成本和实际收益。

评论摘要
主要讨论点：围绕“steering vectors/控制向量”在本地模型中的用途、实践价值、安全争议及与其他“steering”概念的区别展开。 不同观点： • 去拒绝/解审查是核心用途：NitpickLawyer 指出 steering vectors 最大应用是移除模型拒答；早期模型中“拒绝”常集中在单一向量上，可削弱该向量实现 uncensoring，且运行时动态应用比直接改模型更灵活。 • DwarfStar 作者补充实践细节：antirez 称已用 DwarfStar 完全移除 DS4 拒答，但未公开 steering 文件；强调运行时 steering 优于发布修改版 GGUF，因为可按需、分阶段、按阈值施加，减少能力损伤。 • steering 是未来交互控制工具：kamranjon 认为这暴露了前沿实验室隐藏的“控制旋钮”，未来用户会期待模型提供这类细粒度控制能力。 • 应用潜力广泛：micahwhite 举例用 steering 改变模型政治倾向；potatoman22 将其与 control vectors/representation engineering 联系起来，即在推理时修改各层激活控制行为。 • 概念混淆：bel8 质疑“只适用于本地模型”，指出 Copilot 也有“steer with message”；其后认为这可能只是通过插入消息进行 agent steering，不同于激活向量 steering。 • 实用性存疑：amelius 认为更像深度学习研究工具，不一定适合实际使用。 • 本地性与硬件门槛：aswegs8 质疑需约192GB RAM 的模型是否还能称为“本地”。 • 模型选择争议：anonym29 不理解对 DeepSeek V4 Flash 的兴趣，认为其比 Minimax M2.7 更大、更低效、幻觉更多，且 M2.7 长上下文表现更好。 • prompt 控制有限：dominotw 反驳“提示词可细粒度控制”，认为提示无法真正克服训练和后训练偏置。 补充讨论：争议焦点集中在 steering 的安全边界、与提示/agent steering 的区别、以及其是否足够实用。

My Favorite Bugs: Invalid Surrogate Pairs

作者: meysamazad | 评分: 64 | 评论数: 12 | 发布时间: 2026-05-16 12:49
文章摘要

文章讲述作者最喜欢的一个协同编辑器 Bug：在 TipTap/ProseMirror + Yjs 中，插入相邻的特定 emoji 会导致内容停止同步且无报错。原因是某些 emoji 位于 U+FFFF 以上，在 JavaScript UTF-16 中需用代理对表示；底层 CRDT 在错误位置 splice，切断代理对，产生无效字符。文章借此解释 code units、code points、grapheme clusters 的区别，以及 JS 的 `slice()` 如何可能破坏 emoji。

评论摘要
主要讨论点：Unicode 字符处理、字符串切分单位、以及不同语言/运行时对非法编码的容忍度。 不同观点： • 有人认为按 code unit 切字符串很危险，CRDT 这类库若在此层操作“注定出错”；更合理的是按 grapheme cluster 或至少避免切断 emoji、代理对。 • 也有人反对把 `.slice()` 设计成按 grapheme cluster：UTF-16 的 code unit/code point 问题应单独看待，grapheme cluster 与 scalar value 的关系更复杂，不能简单等同“历史原罪”。 • 有人主张在特定场景直接按“二进制/字节”处理，放弃编码假设，反而能简化逻辑、减少乱码和边界错误；但前提是业务只关心 ASCII 或固定格式。 • 另一些评论更偏工程经验：Windows 文件名可含未配对 surrogate，Linux 允许非法 UTF-8；跨系统时如 WTF-8、LANG 环境变量变化、SSH 后“突然正常”等，都说明 Unicode 问题常由运行环境触发。 补充讨论： • 例子包括 emoji 被截断、Phanpy 处理不完整旗帜、Dart substring 产出非法符号。 • 共识是：处理字符串时应做属性测试、明确编码约束；争议焦点在“应按 code unit、code point 还是 grapheme cluster 操作”。

After 8 years, I rewrote my open-source PyTorch curvature library

作者: noahgolmant | 评分: 16 | 评论数: 1 | 发布时间: 2026-05-14 07:36
文章摘要

该仓库提供 PyTorch 工具 hessian-eigenthings，可高效计算模型 Hessian、GGN、经验 Fisher 的特征值/向量、迹和谱密度，支持 Lanczos、Hutch++ 等方法，避免完整 Hessian 的二次内存开销，并适配 Transformer/HuggingFace 大模型。

评论摘要
主要讨论点：发布并介绍 PyTorch 曲率分析库 pytorch-hessian-eigenthings 的 v1.0 重写版，征求相关研究建议。 不同观点： • 作者认为神经网络损失曲率指标（如 Hessian 特征值）对理解泛化、平坦极小值、低秩 Hessian 等问题有研究价值，但完整 Hessian 存储成本随参数量平方增长，实际不可行。 • 工程方案立场：通过 Hessian-vector product 结合 Lanczos、power iteration 等迭代方法，在近似线性内存下计算特征分解，适合较大 PyTorch 模型。 • 新版本强调可靠性与扩展性：新增 GGN、empirical Fisher 等曲率算子，以及 Hutchinson/Hutch++ 迹估计、SLQ 谱密度估计；并用线性/逻辑回归闭式解、与 curvlinops 交叉测试来验证正确性。 • 面向大模型应用：加入 fused Triton/torch.compile 的交叉熵 Hessian-vector kernel，解决大词表场景中标准实现内存或计算爆炸的问题。 • 后续研究方向：作者计划比较 Muon、K-FAC、自然梯度等优化器更新在 Pythia checkpoints 上的一致性，并希望社区提供近期文献和需求建议。 补充讨论：当前没有出现反对意见或争议，重点是工具更新、数值验证和潜在研究应用。
