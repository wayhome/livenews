Define policy forbidding use of AI code generators

作者: todsacerdoti | 评分: 264 | 评论数: 23 | 发布时间: 2025-06-25 23:26
文章摘要

QEMU项目当前政策拒绝接受包含或 derived from AI生成内容（如ChatGPT、Copilot等）的贡献。由于大型语言模型（LLM）生成的内容在版权和许可状态上不明确，存在法律风险，贡献者无法确保这些内容符合开发者原产证书（DCO）的要求。因此，QEMU要求贡献者避免在提交的补丁中使用AI内容生成工具。该政策不适用于AI在研究API、算法、静态分析或调试等非提交相关用途。该政策可能会随着AI工具和法律环境的发展而调整，但目前违规使用AI的贡献将被拒绝。例外情况需经项目维护者个案审核。

评论摘要
主要讨论点：开源软件和自由软件在面对AI生成代码时的版权和法律问题，以及技术实践中的挑战。 不同观点： • **benlivengood**：认为开源和自由软件在AI生成代码的版权问题上非常脆弱。如果AI生成的代码被视为侵权或公共领域，可能会导致法律纠纷。具体而言，AI生成的代码与人类编辑混合后，可能引发关于后续人类编辑是否构成侵权衍生作品的争议。此外，如果AI生成代码被视为公共领域，则开源项目的许可限制可能不再适用，增加项目被滥用的风险。 • **JonChesterfield**：对AI生成的代码持谨慎态度，不希望评审作者不理解的代码，也不希望合并双方都不理解的代码。相比LLVM的政策更加保守。 • **acedTrex**：指出AI生成的代码打破了传统开源项目依赖的隐性能力标志，提出社会证明等其他方式可能变得更为重要。 • **ants_everywhere**：认为RedHat等大公司关注的是AI生成代码可能包含来自其他项目的版权代码，尤其是涉及闭源和易诉讼公司的代码。 • **abhisek**：质疑如何区分AI生成代码和受未知来源影响的人类编写代码，认为AI生成代码目前只是人类工具，没有独立身份。 • **Havoc**：怀疑一些项目对AI生成代码的反感是否真的出于法律考虑，可能只是不喜欢评审低质量的AI提交。 • **hughw**：希望区分使用AI作为IDE中的超级自动完成功能和高层次指导生成实质性代码的区别，认为应允许使用AI节省劳动力的功能，但避免复制开源代码。 • **wyldfire**：认为拒绝AI生成内容的政策可能是个错误，建议指出AI生成内容可以使用的场景，例如非核心内容的CI设置等。 • **sysmax**：希望根据AI生成部分的大小和范围进行区分，认为小部分AI生成内容可以视为合理使用，类似于视频版权的5秒原则。 • **Aeolun**：认为这些政策无法执行，因为所有编辑器都提供AI辅助代码提示，无法区分代码是否由AI生成。 • **naveed125**：对讨论内容表示赞赏。 • **N1H1L**：使用LLM生成文档，自己编写代码。 • **BurningFrog**：建议包括生成代码的完整提示，以增加透明度。 补充讨论： - 争议焦点在于AI生成代码的版权归属及其对开源项目的影响。 - 技术社区对如何有效管理和评审AI生成代码存在分歧。 - 一些讨论者关注AI生成代码在实际开发中的应用和效率提升，而另一些则担心其法律和质量问题。

Howdy – Windows Hello style facial authentication for Linux

文章摘要

Howdy 是一个为 Linux 提供类似 Windows Hello™ 面部认证功能的软件。它利用内置的红外发射器和摄像头进行面部识别，通过 PAM 系统实现登录、锁屏、sudo 等场景下的密码替代。Howdy 支持 Debian/Ubuntu、Arch Linux、Fedora 和 openSUSE 等发行版，安装方式各有不同，部分需要额外配置。它依赖于 Python 3.6+、meson、ninja 等工具构建，并可通过命令行管理面部模型。安装后需运行 `sudo howdy add` 进行面部录入。如遇问题，可通过查看 Wiki 或 GitHub 上的类似问题进行排查。用户还可以通过贡献代码或提交功能请求参与项目。

评论摘要
主要讨论点：一个面部识别程序的功能、安全性及其技术实现 不同观点： • [aitchnyu] 认为程序应该增加处理反馈功能，例如在面部识别时显示处理状态，并在失败时提供重试按钮。此外，他提到对红外照片是否能欺骗模型表示担忧，同时也分享了使用红外摄像头观察物体在可见光和红外光下不同表现的趣味体验。 • [deafpolygon] 关注程序的技术依赖，特别指出该程序依赖于Python 2，质疑为何不能使用更现代的版本。 • [charcircuit] 指出该程序与"Windows Hello"的不同之处，认为该程序仅通过2D图像提取特征，而不进行深度重建，这使得它容易被纸张等简单手段欺骗。他还提到该程序的功能仅限于用户认证，而不能像Windows Hello那样用于其他安全功能（如磁盘加密和passkey管理）。此外，[charcircuit] 补充说程序会将面部特征点以明文形式保存，存在安全风险。 补充讨论： • 关于面部识别技术的安全性问题，特别是能否通过红外照片欺骗系统，存在一定的争议和技术讨论。 • 技术依赖性（如Python 2的使用）在用户中引起了不满，用户期望更现代化和维护性更好的技术选择。 • 程序在处理用户数据时（如面部特征的明文保存）的安全性设计引发了隐私和数据保护方面的担忧。
