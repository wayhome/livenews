Whose code am I running in GitHub Actions?

作者: ingve | 评分: 107 | 评论数: 13 | 发布时间: 2025-03-25 17:17
文章摘要

这篇文章讨论了GitHub Actions中使用可变引用（如标签）可能带来的安全风险。具体来说，有人在一周前向`tj-actions/changed-files` Action添加了恶意代码，导致秘密信息可能泄露。问题源于常用标签引用实际上是可变的，如果标签指向的提交被更改，Action将运行不同的代码。 为解决此问题，作者提供了一个shell脚本，用于检查本地仓库中所有使用的GitHub Actions，列出并统计每个Action的使用次数。作者建议使用不可变的提交ID来确保代码不变，并建议评估所使用Action的来源和必要性，优先使用来自大组织或自己编写的Action。 脚本通过Unix管道和一系列文本处理工具实现，具体步骤包括查找工作流文件、提取使用Action的行、清理和统计结果。作者最后对自己的项目进行了检查，发现大多数Action来自大组织，风险较小。

评论摘要
主要讨论点：GitHub Actions 的使用及其安全性，特别是关于可变引用、依赖管理和潜在滥用的问题。 不同观点： • dgl 认为使用短 commit ID 存在风险，可能会导致可变引用，因为如果有人找到冲突或者推送同名标签，可能会优先使用该标签。这种复杂性在不同服务间表现不同，比如 GitHub 禁止推送40个十六进制字符长的分支和标签，但其他服务可能不禁止。 • mmmaantu 指出，即使使用 SHA pinning 也可能无法完全解决问题，因为依赖项本身可能没有对自身的依赖进行 pinning，从而仍可能通过有漏洞的标签拉取内容。他期待 GitHub roadmap 中的一个相关功能改进。 • dietrichepp 分享了个人经验，选择自己编写 CI 构建驱动程序，而不是依赖公开的 GitHub Actions，从而减少对 GitHub Actions 的依赖。虽然更耗时，但这种方法让他在非工作项目中更具灵活性。 • ippem 提到 GitHub 正在开发不可变 Actions，未来的实现值得关注。 • bdcravens 指出 GitHub Actions 可能被滥用，例如用于网络抓取以绕过限制，因为 GitHub Actions 使用住宅 IP 空间。 • password4321 认为文章可能是对 Tj-actions/changed-files GitHub Action 被入侵事件的回应，虽然讨论的是检测工具，但相关性很高。 • donatj 解释了 GitHub Actions 的设计是可变的，即 Git 标签可以被更改以指向不同 commit，这是设计使然。作为 Action 维护者，需要删除并重新标记主要版本以确保一致性。 • Jenk 提到 GitHub 的文档中早已包含安全加固的建议，并提到有工具和 linters 可以警告未使用 SHAs 的情况。 • r3tr0 介绍了一种工具，可以审计和运行 GitHub Actions，并提供了一个可交互的平台。 • ohgr 认为整个软件生态系统都基于“下载任意网络内容并运行”的模式，因此 GitHub Actions 的问题只是其中一个小担忧。 • mystified5016 对人们直接使用和组合他人编写的 GitHub Actions 感到惊讶和不满，认为这是现代软件理念的一个表现。他更倾向于自己编写所有管道代码，以确保安全和控制。 补充讨论： • 争议的焦点在于 GitHub Actions 的可变性和安全性。一些用户担心可变引用和依赖管理问题，而另一些用户则分享了减少这些风险的策略，如自己编写代码和使用不可变引用。 • 用户对 GitHub Actions 的设计和潜在滥用问题表达了不同的看法，有人认为这是设计使然，有人则认为需要更强的安全措施。 • 有多个用户提到期待 GitHub 提供更好的解决方案，如不可变 Actions 和更强的安全加固功能。

VGGT: Visual Geometry Grounded Transformer

作者: xnx | 评分: 94 | 评论数: 14 | 发布时间: 2025-03-25 12:59
文章摘要

VGGT（Visual Geometry Grounded Transformer）是一个由牛津大学和Meta AI合作开发的前馈神经网络，能够在数秒内从一张或多张图像中推断出场景的关键3D属性，包括相机参数、深度图、3D点图和3D点轨迹等。该模型易于安装和使用，通过克隆代码库并安装依赖项即可运行。VGGT支持自动下载预训练权重，并可在Hugging Face上手动获取。用户可以根据需要选择预测不同的属性，如相机参数、深度图和点图，并通过提供的函数将深度图转换为3D点图，或跟踪特定点的3D轨迹。

评论摘要
主要讨论点：关于VGGT模型及其在3D重建中的应用和潜力的讨论 不同观点： • [正面评价] [w-m] 对论文持积极态度，赞赏作者的成果和呈现方式，尤其是模型在不同注意力机制和归一化方法上的处理。尽管肯定了模型的表现，但也提到该研究缺乏“顿悟”时刻，更多依赖大数据和大量计算资源，呼应了《苦涩的教训》一文中的观点。 • [应用建议] [sgnelson] 希望将此技术与传统摄影测量学结合，作为手机3D扫描的补充工具，而不是完全取代传统方法。 • [质疑] [bhouston] 对论文中户外示例的可靠性提出质疑，认为这些示例可能因为训练集中包含相关数据而存在偏差，尤其是著名地标如金字塔和罗马斗兽场。 • [实用性疑问] [davedx] 对该技术的实际应用场景感到困惑，特别是商业应用方面的具体用例不明确。 • [技术对比] [porphyra] 指出该研究与先前方法（如COLMAP、NERF、Gaussian Splatting）的对比，强调了使用Transformer可以从更少图像中重建场景的优势。 • [实验反馈] [jdthedisciple] 对模型在Huggingface上的表现提出批评，认为点云结果遗漏了输入图像中一半的特征，表现一般。 • [技术扩展] [vessenes] 关注模型在密集点云和splats上的应用潜力，建议通过微调或重新训练来提升模型在该领域的表现。 • [功能需求] [richard___] 强调需要在动态场景中使用相机姿态的技术。 • [术语批评] [amelius] 对使用电气工程领域的术语表示不满。 • [应用设想] [maelito] 询问该技术是否可用于构建类似Google Earth的3D场景。 • [AGI展望] [ninetyninenine] 认为AGI将是多种模型拼接而成，VGGT模型可能成为感知领域的一部分。 • [娱乐性评论] [fallingmeat] 以幽默方式要求看到视频演示，否则难以相信结果。 补充讨论： • 争议焦点在于模型的创新性和实用性。部分评论者如[w-m]和[bhouston]对模型的创新性持保留态度，认为更多依赖大数据和计算资源，而非新颖的算法设计。而[porphyra]则肯定了模型在减少图像需求方面的进步。 • 实际应用场景是另一个讨论重点。评论者如[sgnelson]和[davedx]对技术如何落地提出了疑问和建议，特别是对手机3D扫描和商业应用的潜力进行了探讨。 • 技术细节方面，评论涉及了模型在不同任务（如splats和动态场景）上的扩展和优化潜力，以及对实验结果的具体反馈。

Open-sourcing OpenPubkey SSH (OPKSSH): integrating single sign-on with SSH

作者: PranaFlux | 评分: 152 | 评论数: 22 | 发布时间: 2025-03-25 13:22
文章摘要

OPKSSH（OpenPubkey SSH）是一个开源项目，旨在通过集成单点登录（SSO）技术（如OpenID Connect）简化SSH密钥管理，无需手动配置SSH密钥。它利用OpenPubkey协议将公钥添加到ID Tokens中，使其能够像证书一样使用，从而支持SSH协议的SSO认证，而无需更改现有的SSH或SSO协议。OPKSSH的优势包括提高安全性，通过使用短期有效的SSH密钥减少密钥泄露风险，并提升便利性，用户只需登录身份提供商（IdP）即可生成SSH密钥。该项目解决了传统SSH密钥管理中的安全和使用难题，特别适用于需要频繁访问和权限管理的企业环境。

评论摘要
