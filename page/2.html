The Safari MCP server for web developers

作者: coloneltcb | 评分: 140 | 评论数: 14 | 发布时间: 2026-07-03 01:37
文章摘要

Safari MCP 服务器是苹果在 Safari Technology Preview 247 中推出的 Web 开发工具。它通过 Model Context Protocol 协议将 AI 代理连接到 Safari 浏览器窗口，让代理能够直接访问 DOM、网络请求、截图和控制台输出等信息。 这个工具旨在简化传统的调试流程，减少开发者在浏览器、编辑器和 AI 工具之间的反复切换。代理可以自主完成更多调试工作，包括检查代码渲染效果、测试 Safari 兼容性、分析性能、检查可访问性问题以及验证用户状态等。 Safari MCP 服务器提供了丰富的工具集，涵盖标签页管理、JavaScript 执行、网络监控、页面交互、截图等功能，帮助开发者构建更高效的开发工作流。

评论摘要
主要讨论点：Safari推出MCP（Model Context Protocol）devtools服务器，用于浏览器自动化测试和AI辅助开发工作流。 不同观点： • **工具选择分歧**：部分开发者已在使用Chrome/Firefox的MCP服务器进行跨浏览器测试，认为MCP比传统WebDriver更快更强大；另有开发者推荐Playwright-CLI，称其性能优于MCP服务器 • **Apple开发者体验质疑**：有评论指出Safari测试的核心痛点——必须拥有Apple设备才能测试，质疑Apple是否真正关心web开发者，建议提供简化的虚拟机方案 • **技术成熟度考量**：自建工具的开发者表示Safari的Safaridriver API与Chrome的CDP/Bidi相比功能不够完善，这是未包含Safari支持的原因 • **AI工作流争议**：有人讽刺2026年过度依赖AI代理写代码的风向，暗示手写代码反而被视为落伍 补充讨论：部分用户关注功能细节（是否支持Private Relay绕过反爬、是否支持移动模拟器），也有人认为devtools与LLM结合是合理方向。整体氛围是技术讨论为主，对工具选择和Apple生态存在不同看法。

Commodore 64 Basic for PostgreSQL

作者: hans_castorp | 评分: 22 | 评论数: 5 | 发布时间: 2026-07-03 09:08
文章摘要

PL/CBMBASIC 是一个 PostgreSQL 扩展，让数据库可以执行 Commodore 64 BASIC V2 代码。它使用1982年真实的 Microsoft/Commodore 解释器（通过 cbmbasic 项目将6502 ROM重新编译成C），直接编译进扩展库中。 开发者可以用 BASIC 编写 PostgreSQL 函数，包括强制使用行号、保留原始变量命名限制（如变量名不能包含关键字TO、OR等）。扩展的验证器会在创建函数时捕获这些历史问题。 最有趣的是设备8（原本是磁盘驱动器）现在映射到数据库——可以用传统的 OPEN、INPUT#、PRINT# 等 BASIC 命令执行SQL语句并读取结果，1985年写的读取循环代码可以原封不动地工作。 这是一个将怀旧计算机与现代数据库系统创意结合的项目。

评论摘要
主要讨论点：关于一个复古计算项目（涉及PostgreSQL和Commodore 64）的不同反应 不同观点： • **技术怀旧派**：rgacote表达了对项目的敬畏和怀旧之情，认为有些事物不需要追问"为什么"，只需欣赏其本身的价值 • **技术乐观派**：wewewedxfgdf将此视为开发者能够轻松创造任何软件的趋势体现，对这种现象在互联网上的普及表示赞赏 • **历史关注派**：sys_64738提出Commodore公司在计算历史中被"不断试图删除"，暗示其历史地位被低估或遗忘 • **质量批评派**：0x0批评文章充斥着"AI痕迹"（AI-isms），对AI生成内容的质量表示不满 补充讨论：RedNifre以幽默方式提出替代方案（为HP 15-C计算器编译Commodore 64 Basic），展现了复古计算爱好者社区的创造性和趣味性。整体讨论氛围较为正面，除了对文章写作质量的批评外，其他评论都对技术项目本身持肯定态度。

Reality has a surprising amount of detail (2017)

作者: vinhnx | 评分: 129 | 评论数: 20 | 发布时间: 2026-06-27 23:36
文章摘要

这篇文章通过作者年轻时建造地下室楼梯的经历，阐述了一个核心观点：**现实包含惊人的细节量**。 看似简单的建楼梯任务，实际上涉及大量子步骤和技术细节：计算角度、处理木材变形、确保螺丝钉正确安装等。每个层面都有无数具有实际后果的细节。 作者指出，这种"细节的丰富性"不是特定领域的特征，而是接近现实时的普遍属性。无论是木工、编程还是种菜，初次尝试时都会遇到大量"烦人的小问题"。人们常把这种复杂性误认为个人能力不足，而忽视了它是宇宙的基本特征。 这解释了为什么即使是领域内的顶尖专家也容易在智力上陷入困境——因为现实的细节远比我们想象的丰富。

评论摘要
主要讨论点：现实世界的复杂性远超我们的预期和规划，每个领域都充满了意想不到的细节 不同观点： • **理论与现实的差距**：多位评论者用实例说明了这一点。书架案例中，精心制作的直角书架遇到歪斜的墙面；房屋装修中，结构图纸详细但无法涵盖实际施工的所有细节和顺序 • **编程的特殊性**：编程虽然繁琐，但其细节是"可控的"——可以内省、撤销、测试、修复，且只需要一台电脑。相比之下，木工、电子等实体工作需要工具、空间、成本、物理努力，摩擦力更大 • **认知盲点的普遍性**：即使经过充分测试，代码仍会在他人使用时失败，因为无法预见所有使用场景。这不是愚蠢，而是人类认知的局限 • **细节的无限性**：从哲学角度看，现实的细节是无限的，我们只能感知其中一部分。任何单一领域都值得穷尽一生去钻研，且永远有改进空间 补充讨论：评论中隐含着对专业经验价值的认可——无论是施工顺序、临时固定方法，还是处理边缘案例的能力，这些"隐性知识"难以被简单替代（暗示AI替代的局限性）。同时，一些人享受探索细节的过程，另一些人则警惕陷入细节泥潭。
