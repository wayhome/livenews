RediShell: Critical remote code execution vulnerability in Redis

作者: mihau | 评分: 21 | 评论数: 7 | 发布时间: 2025-10-06 22:30
文章摘要

Wiz研究团队发现Redis内存数据库存在严重远程代码执行漏洞（CVE-2025-49844），命名为RediShell，CVSS评分为10.0最高风险。该漏洞源于存在13年的"释放后使用"内存错误，攻击者可发送恶意Lua脚本绕过沙箱执行任意代码，完全控制主机。Redis广泛应用于75%的云环境，约33万实例暴露在互联网中，其中6万无认证保护。风险最高的场景是：互联网暴露+无认证实例（占57%容器部署），其次是内网暴露实例。攻击者可窃取凭证、植入恶意软件、横向移动。Redis已发布补丁，建议用户立即升级。

评论摘要
主要讨论点：[Redis/Lua漏洞的安全影响及修复情况] 不同观点： • **安全意识不足** - fletchowns指出许多Redis实例暴露在公网且未配置认证，认为这是由于教程不当（如Docker Compose绑定到0.0.0.0）导致用户无意识暴露服务。 • **漏洞命名问题** - notnmeyer批评漏洞名称"RediShell"难以搜索，影响信息获取效率。 • **漏洞相似性与修复滞后** - reconditerose对比CVE-2021-32626，指出Lua5.4已修复类似问题，质疑Redis/Valkey仍使用旧版Lua。 • **响应速度争议** - champtar认为140天的修复周期对高危漏洞过慢。 • **衍生分支修复情况** - tracker1和gizzlon推测主流分支（如Valkey）可能已修复，但缺乏明确确认（gizzlon用问号表示不确定性）。 补充讨论： - secondcoming关联Ubuntu的redis-server自动重启事件与漏洞修复时间线，暗示实际影响范围可能更广。 - 争议焦点：漏洞修复的及时性（champtar vs. 未明确回应的维护方）及旧依赖的技术债务（reconditerose）。
