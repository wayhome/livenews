"Stuffed-Na(a)N" 是一个 JavaScript 库，利用 NaN（Not-a-Number）的特性进行数据编码和传输。通过将数据编码为 NaN 数组，该库能够在数学运算中保留和传递数据，且由于 NaN 的特性，这些数据难以被简单复制和粘贴，从而提供一定的隐私保护。该库具有紧凑、快速和隐私优先的特点，并提供企业版以支持更多功能和更好的压缩效率。安装通过 npm 进行，也可以直接在浏览器中使用。此外，文章还介绍了 IEEE 754 浮点数表示以及 NaN 的内部表示形式，并通过幽默的方式解释了该技巧的实现和应用。

The Friendship Recession: The Lost Art of Connecting

作者: 47thpresident | 评分: 192 | 评论数: 29 | 发布时间: 2025-04-26 11:41
文章摘要

文章讨论了美国社会正经历的“友谊衰退”现象，即人们越来越难以建立和维持亲密友谊。数据显示，自1990年以来，没有亲密朋友的美国成年人比例增加了四倍，达到12%。这种变化源于多种因素，包括郊区扩张导致物理距离增加、公共社交空间减少、零工经济和经济压力使得自由时间成为奢侈品。然而，文章指出，这些结构性因素并非唯一原因，文化转变也是关键。工作已成为美国人主要的社会身份，过度专注于事业导致个人生活孤立。同时，核心家庭尤其是子女成为优先事项，进一步压缩了友谊的空间。文章警告，若不重新调整优先级和学习如何建立有意义的关系，未来人们可能失去重要的幸福源泉。

HTTP Feeds: a minimal specification for polling events over HTTP

作者: sea-gold | 评分: 32 | 评论数: 4 | 发布时间: 2025-04-26 17:12
文章摘要

HTTP Feeds 是一种通过普通HTTP API实现异步事件流和数据复制的方法。它定义了一个简单的规范，通过HTTP GET请求轮询事件流，使用CloudEvents格式和`application/cloudevents-batch+json`媒体类型返回按时间顺序排列的事件序列。通过`lastEventId`参数支持从特定事件开始获取后续事件，实现无限轮询以订阅实时 feeds。HTTP Feeds 允许系统在没有消息代理（如Kafka或RabbitMQ）的情况下进行异步解耦。 客户端通过不断发送带有`lastEventId`的请求来获取新事件。如果返回空数组，表示没有更多事件，客户端可等待一段时间后重试。此外，还支持长轮询，服务器在超时或有新事件时返回响应，从而降低延迟。事件的唯一标识`event.id`用于追踪处理进度，建议使用时间排序的UUIDv6或数据库序列来生成，以确保事件顺序一致性。当连接数超过10K时，服务器处理并发连接的成本可能成为问题。

评论摘要
主要讨论点：关于使用Server-sent events（SSE）与轮询或分页API的对比，讨论其适用场景及优缺点。 不同观点： • [fefe23] 认为使用HTTP服务器发送事件（SSE）是更好的选择。其主要论据是SSE可以保持连接的开放状态，无需轮询即可获得实时更新，并且能够从上次中断的位置继续，提供了更高效的解决方案。他提供了MDN文档作为参考。 • [lud_lite] 对SSE的实现细节提出疑问，尤其是如何处理需要追赶的情况，例如是否通过循环调用并传递新的lastEventId来实现。他还质疑了该方法的实际应用场景，是用于社交媒体类型的信息流，还是用于数据同步（如数据库复制），并关注了事件存储的时长问题。 • [hombre_fatal] 建议增加一个关于高层次理由或灵感的部分，比较SSE与典型的分页API（通过afterId参数排序）的优劣，并质疑为何选择SSE而不是传统的分页API。 补充讨论： • [sea-gold] 提到该话题曾在2022年4月被讨论过，并附上了相关链接（https://news.ycombinator.com/item?id=30904220），暗示可能有更多有价值的观点和讨论可以参考。 争议焦点： • 选择SSE还是分页API的适用场景和理由。 • SSE在实际应用中的实现细节，如追赶机制和事件存储时长。 该讨论揭示了对实时数据更新技术选择的深层次考虑，包括具体实现、应用场景及技术限制。
