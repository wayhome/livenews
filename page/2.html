Whatever Happened to Cheap EReaders?

作者: blenderob | 评分: 33 | 评论数: 18 | 发布时间: 2025-06-02 11:28
文章摘要

文章讨论了为何电子墨水（eInk）阅读器价格居高不下，尽管技术应推动价格下降。2012年曾有一款txtr beagle阅读器定价仅£8，但并未广泛销售。目前，最便宜的Kindle售价约£100，而其他品牌如Kobo也在£100至£150之间。便宜的阅读器在AliExpress和Alibaba上能找到，但缺乏保修和软件更新。影响廉价阅读器普及的因素包括：阅读是 niche 爱好，电子墨水技术成本高，Android系统限制，以及电子书市场的封闭性。开源阅读器项目要么被放弃，要么成本过高。最终，文章认为短期内不太可能出现£8的阅读器，建议购买二手或等待专利到期。

评论摘要
主要讨论点：电子阅读器的价格是否合理以及相关技术和市场问题 不同观点： • Paxys和Joshstrange等用户认为，电子阅读器的价格已经非常便宜，尤其是考虑到设计、制造、营销、运输、软件支持等成本。他们指出，100美元左右的Kindle性价比很高，而且不是一次性产品，使用寿命长。 • Neom和Maccard则希望有更便宜的电子阅读器，价格接近硬皮书或平装书，这样可以不担心损坏或丢弃。他们认为当前的电子废物问题已经十分严重，低价电子阅读器可能加剧这一问题。 • Transcriptase质疑电子墨水屏模块的高成本，认为随着技术发展和大规模生产，成本应该已经大幅下降，质疑背后的经济理由。 补充讨论： • Semaphor和Zak讨论了电子阅读器在软件和系统上的限制，特别是与亚马逊和Google的生态系统相关的问题。Semaphor指出，虽然可以通过技术手段在Kindle上阅读非亚马逊商店的书籍，但对普通用户而言可能不够便捷。Zak补充，Google对Android设备的要求可能限制了彩色屏幕以外的设备，但也有制造商通过AOSP等方式绕过这些限制。 • Pliuchkin提到市场垄断问题，指出在某些国家如巴西，亚马逊Kindle几乎垄断了电子阅读器市场，导致消费者选择受限。 • Smeej提出了一种理论上的低成本电子阅读器模型，即功能极其简单，仅用于阅读预装书籍，但质疑这种设备的市场需求和优势。 • Mynegation和Yeul从经济和市场策略角度分析，指出亚马逊通过设备补贴希望在内容销售上获利，但并非所有消费者都会在亚马逊商店购买书籍。 • Woodpanel提醒大家回顾历史，指出技术变革往往伴随着对旧技术的悲观预测，但这些预测不一定准确，鼓励对新技术保持理性态度。 争议焦点： • 电子阅读器价格是否过高，以及是否应该有更便宜的选项以适应一次性使用或低成本需求。 • 电子阅读器市场的竞争和垄断问题，特别是在某些地区亚马逊几乎成为唯一选择的情况下。 • 电子墨水屏设备的技术和成本问题，以及背后的经济逻辑是否合理。

评论摘要
主要讨论点：不同操作系统和文件系统中对 inode 0 的处理及其在用户空间中的使用问题 不同观点： • the_mitsuhiko 认为，根据 OpenBSD UFS 文档和 Linux 内核的注释，inode 0 不能用于常规用途。例如，用户空间可能依赖于 inode 编号非零，像 glibc 会在 unlink() 等函数中忽略 inode 为 0 的文件。此外，macOS 也明确指出 d_fileno = 0 的条目应被跳过，因为这些条目代表已被删除但尚未从目录条目中移除的文件。 • nulld3v 指出，内核中正在努力推动用户空间不再依赖 inode 编号，因为很难保证 inode 编号的唯一性和跨重启的稳定性。他提供了一个 YouTube 视频链接，讨论了这一努力。 • Animats 认为，用户空间所看到的 "inode" 与文件系统内部的表示早已没有直接关系。这意味着用户空间对 inode 编号的依赖本身可能是一个过时的观念。 补充讨论： • 争议的焦点在于 inode 0 是否可以被使用以及用户空间是否应该依赖 inode 编号。the_mitsuhiko 提供了具体操作系统和内核的例子来支持 inode 0 不能被使用的观点，而 Animats 则质疑用户空间对 inode 编号依赖的合理性。 • nulld3v 提出的内核努力方向表明，inode 编号的稳定性和唯一性在实际应用中可能存在问题，进一步加剧了这一争议。 • 讨论还涉及到不同操作系统（如 OpenBSD、Linux、macOS）在处理 inode 0 上的具体实现差异，这显示了文件系统实现中的多样性和复杂性。

文章摘要

这篇文章介绍了使用线性反馈移位寄存器（LFSR）作为程序计数器的CPU实现，该项目基于VHDL语言，面向FPGA。与传统程序计数器相比，LFSR可以节省逻辑门数量，特别适用于7400系列IC或手动布局晶体管的场景。项目包含一个完整的Forth解释器，目前在仿真中运行成功，输出启动消息"eForth 3.3"并接受输入。该CPU资源占用小，运行频率可达151.768MHz，使用少量FPGA资源。项目提供构建指南，通过GHDL进行仿真，使用Xilinx ISE 14.7进行FPGA合成。CPU为累加器架构，指令长度16位，程序计数器由8位LFSR驱动。

评论摘要
主要讨论点：LFSR-PC（线性反馈移位寄存器程序计数器）在处理器中的应用及其历史和技术细节 不同观点： • howerj认为，这个LFSR-PC处理器是一个非常小众的工具，虽然有趣且具有实验价值，但在实际应用中并不实用。他还提到自己正在寻找合同工作，借机宣传个人资料。 • artemonster分享了自己在继电器CPU中的类似应用经验，使用LFSR-PC技巧减少了继电器的数量。他提供了具体的GitHub链接，展示了其项目，并详细说明了如何通过3个继电器实现3个XOR，从而节省资源。 • kragen对LFSR-PC的历史背景进行了详细分析，提到20世纪70年代的TMS 1000等处理器以及Atari 2600 TIA等设备中LFSR计数器的应用。他还引用了Ken Shirriff的逆向工程文章，说明LFSR在音调生成和自检电路中的应用。kragen进一步探讨了LFSR-PC CPU在条件跳转指令中无需地址字段的可能性，并对比了Data General's NOVA和HP's RPN计算器的类似设计。他指出，LFSR的特性使得跳转可能导致较大的地址变化，需要通过汇编器插入NOP指令来解决冲突。此外，他还详细描述了TMS 1000的页面地址机制及其局限性。 补充讨论： • 争议焦点在于LFSR-PC处理器的实际应用价值。howerj认为其不实用，而kragen则通过历史实例和技术分析展示了其潜在的应用场景和创新可能性。 • 技术细节的讨论，如artemonster对继电器数量的节省和kragen对LFSR跳转特性的分析，提供了深入的技术理解和实际应用参考。 • 历史背景的补充，如kragen对TMS 1000和其他处理器中LFSR应用的介绍，丰富了讨论的技术和历史维度。
