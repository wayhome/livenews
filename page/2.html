Kubernetes Ingress Nginx is retiring

作者: TheApplicant | 评分: 47 | 评论数: 8 | 发布时间: 2025-11-13 22:20
文章摘要

Kubernetes SIG Network宣布将于2026年3月停止维护Ingress NGINX，届时将不再提供更新和安全补丁。Ingress NGINX作为早期流行的Kubernetes流量入口控制器，因维护人力不足和遗留技术债务而面临淘汰。现有部署仍可运行，但建议用户迁移至Gateway API或其他Ingress控制器。官方提供了迁移选项清单，并感谢维护者多年的贡献。这一决定基于生态安全考量，旨在推动用户转向更现代的解决方案。

评论摘要
主要讨论点：[Ingress Nginx的退役及其对迁移到Gateway API的影响] 不同观点： • 支持迁移的观点： - Gateway API是未来的趋势，尽管Ingress尚未被废弃，但社区已经在讨论切换到Gateway API。 - 一些控制器（如Traefik）已经同时支持Ingress和Gateway API，迁移相对容易。 • 反对迁移的观点： - Ingress仍然有效且未被废弃，没有必要强制迁移。 - Ingress非常灵活且稳定，目前还没有完全等同的替代方案。 - 迁移可能对使用自定义Nginx属性的用户造成困难。 • 其他重要观点： - Ingress Nginx是Kubernetes历史上默认的Ingress控制器，其退役标志着一个时代的结束。 - F5收购Nginx后推出的Nginx Ingress并未获得广泛用户认可。 - 部分用户对迁移到Gateway API的安全背景表示关注。 补充讨论： - 争议焦点：Ingress Nginx的退役是否合理，以及是否有必要迁移到Gateway API。 - 部分用户对迁移的技术挑战和复杂性表示担忧。 - 社区对Ingress Nginx的贡献和可靠性表示感激，但同时也承认它并非最受欢迎的部分。

How to fix subsystem request failed on channel 0

作者: speckx | 评分: 23 | 评论数: 3 | 发布时间: 2025-11-06 20:50
文章摘要

OpenSSH 9.0版本默认改用SFTP协议进行文件传输，导致不支持SFTP但支持原始SCP协议的主机在传输时会报"subsystem request failed"错误。解决方法是在scp命令中添加-O参数，强制使用原始SCP协议进行传输，例如：scp -O a.txt user@host:/tmp/b.txt。
