Archaeologists Discover Tomb of First King of Caracol

作者: divbzero | 评分: 74 | 评论数: 5 | 发布时间: 2025-07-14 06:21
文章摘要

考古学家Diane和Arlen Chase在1980年代于伯利兹的卡拉科尔（Caracol）发现了古玛雅城市首位统治者Te K'ab Chaak的陵墓。卡拉科尔曾是玛雅历史上重要的政治中心，在公元560至680年间主导尤卡坦半岛南部，直到公元900年被遗弃。Te K'ab Chaak于公元331年登基，其陵墓中出土了陶器、骨管、玉器、马赛克面具、贝壳等陪葬品。陶器上描绘了玛雅统治者、神祇和俘虏的场景。该发现是卡拉科尔四十多年发掘中首个可辨识的统治者陵墓。研究显示，Te K'ab Chaak的陵墓是公元350年左右的三个主要墓葬之一，此时卡拉科尔与中美洲的联系已经非常广泛，甚至受到特奥蒂瓦坎的影响。另两个墓葬也显示出与特奥蒂瓦坎的联系，表明早期玛雅统治者在特奥蒂瓦坎事件前已融入广泛的中美洲交流网络。

Run TypeScript code without worrying about configuration

作者: nailer | 评分: 21 | 评论数: 8 | 发布时间: 2025-07-17 17:29
文章摘要

**tsx**（TypeScript Execute）是一个Node.js增强工具，用于直接运行TypeScript文件，类似于使用`node`命令运行JavaScript文件。用户可以通过`tsx file.ts`命令执行TypeScript代码，无需配置，且支持Node.js CLI参数和JavaScript文件。它解决了CJS和ESM模块之间导入的问题，并提供监视模式（Watch mode），在文件保存时自动重新运行代码，提高开发效率。 **tsx**简化了TypeScript的执行过程，支持`tsconfig.json`中的路径配置，并整合了esbuild以提升性能。目前项目依赖用户捐赠维持发展，呼吁企业赞助以支持长期维护和改进。

评论摘要
主要讨论点：TypeScript生态中关于文件命名和工具选择的争议及讨论 不同观点： • [chmod775] 认为 "tsx" 作为文件命名不合适，因为在 TypeScript 生态中，已经有另一种东西（TSX文件格式）使用了这个缩写，造成了混淆。 • [jauco] 提到较新版本的 Node.js 可以直接运行 TypeScript 文件，其中一种方式是剥离类型（strip types），这已经相对稳定，但不能使用 Node 不理解的语法（如 enums）。同时，他们指出开发团队正在努力使需要转译的特性也能直接运行。 • [fjcero] 简单直接地建议使用 "bun"（一个新兴的JavaScript运行时）作为替代方案。 • [molszanski] 表示自己喜欢使用 "tsx"，同时也开始使用 "bun" 来处理类似任务，暗示了对这两个工具的积极体验。 • [spankalee] 提出疑问，是否这种直接运行 TypeScript 的方式只是简单地向 Node.js 传递了 `--experimental-strip-types` 标志。 • [postalrat] 半开玩笑地建议，JavaScript 版本的文件可以叫 "jsx"，呼应了关于命名问题的讨论。 • [monarchwadia] 简单表达了对 "tsx" 的喜爱。 补充讨论： • 争议的焦点在于 "tsx" 这个命名是否会造成混淆，以及在 Node.js 中直接运行 TypeScript 的技术实现细节。 • 关于工具选择，评论中提到了 "bun" 作为新兴的替代方案，显示出社区对不同工具的接受度和兴趣。 • 技术细节上，讨论了 Node.js 直接运行 TypeScript 时的稳定性及限制（如无法使用某些语法特性）。

Game of Trees Hub

作者: todsacerdoti | 评分: 4 | 评论数: 2 | 发布时间: 2025-07-15 09:47
文章摘要

The Game of Trees Hub是一个基于OpenBSD和Game of Trees版本控制系统的Git仓库托管服务，支持与任何Git客户端互操作。用户通过Git的SSH协议安全访问仓库，并通过提交配置文件管理仓库空间，该文件控制账户、权限等。仓库默认为私有，可设为公开，所有数据有备份并可恢复。每个项目空间运行在OpenBSD的vmm虚拟机上，由gotd、gotwebd和gotsysd服务器实现。服务资金透明，通过Open Collective平台管理，用户可以赞助支持。目前不提供讨论、点赞等功能，未来可能加入问题跟踪等项目管理功能。项目所有者付费使用，受邀用户免费，欢迎自愿捐助。财务由Chirpy Software SRL管理，这是一家由项目创始人Stefan Sperling拥有的公司。

评论摘要
主要讨论点：对"Game of Trees"（Got）版本控制系统的评价及其与其他版本控制系统（如Git和Mercurial）的比较。 不同观点： • **Mercurial支持者的批评**：用户"openmarkand"自2009年以来一直使用Mercurial，并表示不理解Git的成功。他认为Git的命令选项、用户体验和文档都很混乱，每个命令功能过多且行为不一致。例如，在非Git仓库中运行`git diff -x`和`git switch -x`会产生不同的输出，这让他感到困惑。 • **对Got的兴趣与期望**：尽管"openmarkand"更偏好Mercurial，但他对Got感兴趣多年，特别是对OpenBSD上的应用。他提到希望某些特定代码（如framagit.org上的got.c文件）能够在未来被移除，暗示对Got的某些实现细节有改进期望。 补充讨论： • **Got与Git的比较**：评论中隐含了对Got和Git之间差异的关注，尤其是用户对Git复杂性的不满可能反映出对Got简化设计的期待。用户似乎希望Got能避免Git中存在的某些设计问题，提供更一致和简洁的用户体验。 • **社区关注度**：从不同时间点对Got发布的相关讨论链接来看，虽然Got引起了一些关注，但评论数量相对较少，表明其在更广泛的开发者社区中可能尚未获得显著的讨论热度。 争议焦点：Git的复杂性与Got的潜在简化设计之间的对比是讨论中隐含的争议点。一些开发者可能更偏好功能丰富但复杂的系统如Git，而另一些开发者则寻求更简洁和一致的解决方案如Got。

Wttr: Console-oriented weather forecast service

作者: saikatsg | 评分: 129 | 评论数: 23 | 发布时间: 2025-07-17 06:05
文章摘要

**wttr.in** 是一个面向控制台的天气预报服务，支持多种信息表示方式，如终端使用的ANSI序列、网页的HTML以及图形查看器的PNG格式。该项目最初是一个展示控制台服务力量的小型项目，现已发展为每日处理数千万次查询的流行服务。 使用方法： 1. 通过`curl wttr.in`获取当前位置天气，如`curl wttr.in/London`。 2. 使用三字母机场代码查询机场天气，如`curl wttr.in/muc`。 3. 查询特殊地理位置，如`curl wttr.in/~Eiffel+Tower`。 4. 通过IP地址或域名查询，如`curl wttr.in/@github.com`。 支持的输出格式包括ANSI、纯文本、HTML、PNG和JSON。可通过URL参数自定义单位和语言，如`curl wttr.in/Amsterdam?u`用于美制单位，`curl wttr.in/Amsterdam?m`用于公制单位。PNG格式可通过`_`连接参数，如`wget wttr.in/Paris_0tqp_lang=fr.png`。 详细帮助可通过`curl wttr.in/:help`查看。
