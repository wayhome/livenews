My Favorite C++ Pattern: X Macros (2023)

作者: ibobev | 评分: 42 | 评论数: 15 | 发布时间: 2025-03-25 14:57
文章摘要

本文介绍了C++中一种称为“X宏”的模式，该模式主要用于代码生成，特别适合处理大量重复代码的情况，如声明多个变量或类、执行相似操作等。作者以Chapel编译器中的字符串驻留（String Interning）为例，展示了如何使用X宏来简化和自动化代码编写。通过在一个头文件中定义宏列表，开发者可以在多个地方“迭代”该列表以生成所需的代码，从而减少手动编写和维护重复代码的工作量。文章还提到该模式在抽象语法树（AST）类层次结构中的应用，展示了其广泛的实用性。使用X宏不仅提高了代码的可维护性，还减少了添加新代码时的出错风险。

评论摘要
主要讨论点：X Macros 的使用及其在 C++ 和 C 语言中的优缺点 不同观点： • **支持 X Macros 的观点**： - **jchw**：X Macros 是 C++ 中一种经典但不如其他模式知名的技巧，尽管 C++ 宏功能不强，但 X Macros 仍然在大的代码库中很常见。其还提到编程语言开始支持文件嵌入作为第一类特性，简化了很多事情。 - **loeg**：尽管不喜欢 X Macros，但承认它在某些情况下非常有用，例如生成错误代码的枚举和字符串表，确保两者长度一致。 - **gibibit**：认为 X Macros 是非常巧妙的技巧，尤其在 C 语言中，类似于 Rust 的声明宏，但要注意避免过度使用。 - **kevin_thibedeau**：建议通过传递列表宏作为参数来避免一些 X Macros 的问题，如不需要使用 `#undef`。 • **对 X Macros 的批评和替代方案**： - **Blackthorn**：虽然理解 X Macros 的使用场景，但更倾向于使用外部代码生成步骤，例如外部脚本，而不是依赖预处理器中的宏。 - **webdevver**：强烈反对这种技巧，认为调试预处理后的 C++ 代码非常痛苦，建议使用 Python 等脚本语言作为预编译步骤生成代码。 - **KerrAvon**：认为 X Macros 是反模式，难以调试和维护，建议避免在 C++ 中过度使用预处理器。 - **randomNumber7**：一方面认可其解决实际问题的能力，但另一方面认为需要这些“hack”让人怀疑是否有更简单的语言可以实现同样的功能。 • **替代语言的建议**： - **sfpotter**：认为如果使用 D 语言，就不需要这些技巧。 • **历史背景和其他名称**： - **PaulHoule**：提到 X Macros 在 IBM 360 汇编语言中非常著名，特别是在 CICS 应用中用于构建基于数据模式的代码。 - **lowbloodsugar**：提到这种技巧被称为“fruit lists”。 • **对 C 和 C++ 的区分**： - **jdnxndnd**：认为 X Macros 是 C 预处理器（cpp）的特性，而不是 C++ 的。 补充讨论： - **改进建议**： - **wat10000**：建议通过更具描述性的宏名称、在头文件末尾 `#undef` 宏、使用 `#ifndef` 检查宏是否定义等方式来改进 X Macros 的使用。 争议焦点： - X Macros 是否是一种应避免的反模式，尤其是在 C++ 中，因为其难以调试和维护。 - 使用 X Macros 的必要性，是否存在更简单的语言或方法能达到同样的效果。

Hann: A Fast Approximate Nearest Neighbor Search Library for Go

作者: habedi0 | 评分: 52 | 评论数: 4 | 发布时间: 2025-03-25 11:57
文章摘要

Hann 是一个用于 Go 语言的高性能近似最近邻搜索库，支持在高维空间中进行高效的相似性搜索。它提供了多种索引数据结构，包括 HNSW（层次导航小世界图）、PQIVF（乘积量化倒排文件）和 RPT（随机投影树）。Hann 具有统一的索引接口，支持任意维度向量的索引和搜索，并利用 SIMD（AVX）指令加速距离计算。它还支持批量插入、删除、更新向量，以及将索引保存到磁盘和加载。Hann 适用于构建向量数据库或为 Go 应用添加快速的内存相似性搜索功能。安装需 Go 1.21 及以上版本、C/C++ 编译器和支持 AVX 指令的 CPU。

评论摘要
主要讨论点：围绕ANN（近似近邻搜索）库的性能、比较以及实现方式的讨论 不同观点： • [nikolayasdf123] 认为该库虽然使用了SIMD（AVX）指令来加速距离计算，但缺乏与Redis、Vertex、Elastic、FAISS等其他工具的基准比较。这暗示了对实际应用中性能对比的需求，以便更好地评估该库的优劣。 • [nikolayasdf123] 还指出该库需要C或C++编译，质疑其是否只是通过FFI（外部函数接口）调用C代码。这反映了对库实现方式的关注，尤其是对于非C/C++开发者的使用便捷性。 • [oldgregg] 对库的功能表示认可，但更关注如何在Go语言环境中从文本生成向量。这表明了对库功能扩展的需求，尤其是对Go原生支持的需求。 补充讨论： • 争议焦点在于库的实现方式和与其他类似工具的性能对比。开发者关心是否需要通过FFI调用C代码，以及该库在实际应用中与其他流行工具的性能差异。 • 另一个值得注意的点是[oldgregg]提出的对Go原生支持的需求，这反映了不同语言开发者对该库功能扩展的期待。 • 总体来看，讨论主要集中在性能、实现方式以及特定语言环境下的功能支持。

How 'animal methods bias' is affecting research careers

作者: LinuxBender | 评分: 10 | 评论数: 0 | 发布时间: 2025-03-21 19:51
文章摘要

文章讨论了在临床前研究中过度依赖动物模型的现象，称为“动物方法偏见”（animal-methods bias），即在已有非动物方法的情况下仍偏好使用动物模型。Catharine Krebs及其团队通过调查发现，许多研究人员和评审者认为某些动物实验不必要，特别是在计算研究中。这种偏见主要源于期刊和资助方的要求，导致研究人员，尤其是早期研究人员，感到沮丧。文章还指出，尽管动物研究有其局限性，药物早期试验中大量失败案例部分归因于过度依赖动物模型。虽然支持无动物研究的资助在增加，但相比传统资助仍较有限。Krebs及其同事正进行更大规模研究，以探讨这种偏见对研究人员职业生涯的影响。

A study reveals that deciduous trees' roots remain active in winter

作者: bryanrasmussen | 评分: 57 | 评论数: 10 | 发布时间: 2025-03-22 19:33
文章摘要

一项新研究发现，落叶树种如山毛榉和桦树的根系在冬季仍持续生长，挑战了此前根系在冬季休眠的认知。该研究发表于《Nature Ecology & Evolution》期刊，由安特卫普大学牵头，涉及多个温带森林和330株树苗。研究显示，即使在土壤温度低于3°C时，粗根仍在生长，这表明森林土壤的碳汇能力比之前认为的更强，因为树木全年都在固定碳。根系的持续生长为春季树木迅速恢复叶片生长和光合作用提供了储备，有助于树木应对气候变化。该研究强调了地上与地下部分生长周期的差异，根系在冬季生长，而地上部分在春季活跃。

评论摘要
主要讨论点：树木在冬季是否继续生长，以及这种生长对树木和森林生态系统的意义。 不同观点： • [y-c-o-m-b] 认为根系在冬季继续生长是常识，并通过观察自家门前的红枫树和矮株木兰树的生长情况来支持这一观点。 • [hoeoek] 作为一名林务员，对新研究表示兴趣，指出传统模型通常将树木生长与季节温度阈值挂钩，而忽略了“非季节性生长”的细节。他提到使用针叶/落叶物种作为随机效应模型可以揭示生长动态的差异。 • [mapt] 部分同意研究结果，特别是关于根和地上部分遵循不同生长日历的观点，但对森林土壤在冬季积累碳的能力提出质疑，认为这是通过储存的碳而非光合作用实现的。 • [mvdtnz] 认为这是常识，不值得投入时间和精力进行研究。 • [taeric] 提出落叶可能是树木降低冬季风影响的一种策略，并表示希望看到更多关于树木生长的研究。 • [londons_explore] 认为在地下温度较稳定的情况下，根系继续生长是合乎逻辑的结果。 • [jnellis] 通过冬季树根堵塞下水道的情况，间接支持冬季根系继续生长的观点。 • [damnitbuilds] 认为这一发现早应在数百年前就被揭示。 • [naikrovek] 感觉早就知道根系冬季生长的事实，回忆童年时的非正式实验支持这一记忆。 补充讨论： • 研究揭示的树木生长动态对理解森林生态系统碳循环具有重要意义，特别是在冬季碳积累方面。 • 不同背景的讨论者（如林务员和普通观察者）对该研究的价值有不同看法，有些人认为这是常识，而另一些人则认为揭示了新的科学细节。 • 个人经验和观察（如红枫树、矮株木兰树、下水道堵塞）为讨论提供了实际例子，增加了讨论的真实性和趣味性。 • 对树木落叶现象的多重解释（如生物战争、降低风影响）丰富了讨论的维度。
