Project Gutenberg – keeps getting better

文章摘要

Project Gutenberg提供7.5万多本免费电子书，可在线阅读或下载EPUB、Kindle格式，重点收录美国版权到期的经典作品。网站由志愿者维护，提供分类、榜单、搜索、阅读帮助、捐赠与志愿参与渠道，并推荐免费有声书资源。

评论摘要
主要讨论点：围绕 Project Gutenberg 的价值、历史、访问体验、格式质量及生态整合展开讨论。 不同观点： • 高度肯定 PG 的公共价值：多人称其为“互联网最好的事物之一”，赞赏其由使命驱动、长期免费提供公共领域书籍；有人分享父亲通过 Kindle 阅读 PG 书籍的个人经历，体现其现实影响。 • 关注历史与传承：评论指出 PG 起源于 1971 年，由 Michael S. Hart 数字化《独立宣言》开始，早于互联网普及，是电子书和开放知识的重要先驱。 • 期待更好整合到电子阅读器：有人认为 Kindle 等厂商没有内置“Gutenberg 商店”很可惜，下载仍有摩擦；但也有人提到新版网站在 Kindle 内置浏览器上反而不如旧版方便。 • 对格式与排版有分歧：部分用户偏好 PG 的文本资源，也有人认为其纯文本倾向、ePub 质量不稳定，不如 archive.org 扫描本或 Standard Ebooks 的精排版本。 • 访问与法律问题：意大利用户反馈 gutenberg.org 显示“司法扣押”页面，引发对公共领域作品跨国版权/封锁问题的疑问。 • 扩展生态与替代资源：有人提到 LibriVox 对齐有声书、ZIM 离线全集、FadedPage、Runeberg、加拿大/瑞典资源等。 补充讨论：有人质疑某些冷门书下载量异常，可能是机器人流量；PG 工作人员也表示网站仍在改进，并希望维基百科条目更新。

Show HN: Rocksky – Music scrobbling and discovery on the AT Protocol

作者: tsiry | 评分: 33 | 评论数: 7 | 发布时间: 2026-05-16 17:00
文章摘要

Rocksky 是一个基于 AT Protocol 的去中心化音乐记录与发现平台。它支持 Last.fm、ListenBrainz 兼容的 scrobbling API，可记录播放历史、展示实时动态、统计每日收听数据，并提供热门艺人、曲目、专辑等个人榜单。平台集成 Spotify、Jellyfin、Pano Scrobbler、WebScrobbler，支持 MeiliSearch 搜索。项目主要使用 TypeScript 和 Rust 开发，未来计划加入 Webhooks、个性化推荐、Last.fm 同步、远程播放、自建音乐库播放等功能。

评论摘要
主要讨论点：围绕 Rocksky/Atmosphere 类音乐社交与 scrobble 应用的功能、接入方式、推荐能力和使用场景展开。 不同观点： • 开发者集成关注：CharlesW 表示其应用 Poppy.fm 已支持 Last.fm 和 ListenBrainz，准备加入 Rocksky，但疑问在于用户是否必须手动获取 Rocksky API key，是否缺少类似“Sign in with Bluesky”的 OAuth 登录流程；焦点是原生 iOS 用户体验与认证方式。 • 积极支持与期待：tuvix 认为 Last.fm 曾帮助发现大量音乐，是优秀推荐模型和社交音乐平台，因此期待 Rocksky 能在此基础上改进。 • 功能入口补充：tsiry 直接提供 rocksky.app 链接，起到信息补充作用。 • 使用闭环疑问：jbk 关注“scrobble 后能获得新音乐推荐，但如何实际收听这些音乐”，指出推荐与播放之间可能存在断点。 • 社区生态认可：matteomrj 认为这是 HN 上难得的 Atmosphere 应用，并评价其很酷。 • 功能建议：phyzix5761 建议在站内嵌入 YouTube 歌曲视频，方便直接播放。 • 替代方案分享：tamimio 表示会尝试，但自己已用 navidrome+narjo 自建音乐服务，支持 FLAC、反向代理访问、无需 VPN，强调免费且可替代商业音乐服务。 补充讨论：争议焦点主要集中在“认证是否足够顺滑”和“推荐音乐后如何播放”；另有用户从自建音乐库角度提出替代路径。

Recreation of the 1956 IPL-I version of the Logic Theorist theorem prover

作者: abrax3141 | 评分: 7 | 评论数: 1 | 发布时间: 2026-05-13 01:54
文章摘要

该仓库用 Python 复现1956年首个公开版“逻辑理论机”（Logic Theorist），修复原 IPL-I 代码并提供解释器、运行与结果分析工具，用于按《数学原理》的命题逻辑公理、规则证明定理。

评论摘要
主要讨论点：围绕 David Moews 复现并运行 1956 年 Logic Theorist（LT1/LT56）原始 IPL-I 伪代码的意义，以及它与作者此前复现的 1963 年 IPL-V 版本（LT5/LT63）的差异。 不同观点： • 作者高度肯定 David Moews 的工作：认为其将“复古 AI”研究窗口又向前推进了 8 年，因为他直接依据 1956 年 RAND 报告中的原始 IPL-I 伪代码构建了解释器并成功运行。 • LT1/LT56 被视为更接近 Newell 和 Simon 早期认知理论的版本：1956 年报告中的描述更像是对人类定理证明认知操作的高层规范，而不完全是可直接执行的程序。 • IPL-I 从未真正被实现这一点很关键：原始程序当年是由 Simon 的学生甚至孩子“手工执行”，模拟假想机器。因此 LT1 依赖人的理解和灵活性来补足实现细节。 • 与 LT1 相比，LT5/LT63 更像真正可运行的工程实现：作者指出，后来 Shaw 将系统改写为 IPL-V 时，必须补全大量实现复杂性，因此代码规模从 LT1 的 400 多行扩展到 LT5 的近 3000 行。 • 作者强调 David 的成就并未因“问题更简单”而被削弱：虽然 IPL-I 未实际实现使复现某些方面更容易，但用 Python 搭建解释器并让伪代码运行仍是重要贡献。 补充讨论：争议不明显，主要焦点在于“高层认知模型/伪代码”与“真实可执行程序”之间的差异，以及早期 AI、Lisp 前史和自动定理证明研究中，这类复现工作的历史价值。

DeepSeek-V4-Flash means LLM steering is interesting again

作者: Brajeshwar | 评分: 124 | 评论数: 12 | 发布时间: 2026-05-16 14:58
文章摘要

文章介绍“steering”：在本地大模型推理中直接调控激活向量以改变输出风格或能力。作者以 DwarfStar 4/DeepSeek-V4-Flash 为例，说明其原理、潜力与局限：相比提示词更直接，但受限于模型访问、成本和实际收益。

评论摘要
主要讨论点：围绕“steering vectors/控制向量”在本地模型中的用途、实践价值、安全争议及与其他“steering”概念的区别展开。 不同观点： • 去拒绝/解审查是核心用途：NitpickLawyer 指出 steering vectors 最大应用是移除模型拒答；早期模型中“拒绝”常集中在单一向量上，可削弱该向量实现 uncensoring，且运行时动态应用比直接改模型更灵活。 • DwarfStar 作者补充实践细节：antirez 称已用 DwarfStar 完全移除 DS4 拒答，但未公开 steering 文件；强调运行时 steering 优于发布修改版 GGUF，因为可按需、分阶段、按阈值施加，减少能力损伤。 • steering 是未来交互控制工具：kamranjon 认为这暴露了前沿实验室隐藏的“控制旋钮”，未来用户会期待模型提供这类细粒度控制能力。 • 应用潜力广泛：micahwhite 举例用 steering 改变模型政治倾向；potatoman22 将其与 control vectors/representation engineering 联系起来，即在推理时修改各层激活控制行为。 • 概念混淆：bel8 质疑“只适用于本地模型”，指出 Copilot 也有“steer with message”；其后认为这可能只是通过插入消息进行 agent steering，不同于激活向量 steering。 • 实用性存疑：amelius 认为更像深度学习研究工具，不一定适合实际使用。 • 本地性与硬件门槛：aswegs8 质疑需约192GB RAM 的模型是否还能称为“本地”。 • 模型选择争议：anonym29 不理解对 DeepSeek V4 Flash 的兴趣，认为其比 Minimax M2.7 更大、更低效、幻觉更多，且 M2.7 长上下文表现更好。 • prompt 控制有限：dominotw 反驳“提示词可细粒度控制”，认为提示无法真正克服训练和后训练偏置。 补充讨论：争议焦点集中在 steering 的安全边界、与提示/agent steering 的区别、以及其是否足够实用。
