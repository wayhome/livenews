主要讨论点：如何定义"doing the thing"（做事情）以及与之相关的规划、策略和执行的关系。 不同观点： • **系统化观点**（saulpw）：引用Viable System Model，强调除了执行（System 1），还需要协调（System 2）、资源分配（System 3）、策略（System 4）和价值观（System 5）等元系统来确保长期成功。 • **深思熟虑优先**（andy99）：主张在行动前进行充分思考和准备，以减少实际执行时的困难和提高结果质量。 • **优先级管理**（nrhrjrjrjtntbt）：认为记录和优先排序（如创建Jira票）是高效工作的必要部分，而非拖延。 • **任务分解**（thomascountz）：提出"doing the thing"可能包含多个前置步骤（如研究、讨论），不能仅关注最终执行。 • **领导力视角**（RajT88）：区分"performer"（执行者）和"leader"（领导者），后者通过组织和协调使事情发生，而不仅是理解或执行。 • **学习即行动**（nagisa）：认为学习如何做某事（如阅读他人经验）本身就是"doing the thing"的一部分。 • **营销重要性**（johnfn）：强调营销等非直接生产活动也是"doing the thing"的关键部分。 • **批判性观点**（alentred）：批评文章作者忽视人类心理多样性，简化了 procrastination（拖延）的复杂性。 补充讨论： • **争议焦点**：什么构成"doing the thing"？是仅限直接执行，还是包括规划、学习等间接活动？ • **幽默反驳**（pac0, cadamsdotcom）：指出讨论"什么不是doing the thing"本身可能就是一种拖延行为。 • **心理准备**（tshaddox）：认为没有准备的行动要么不明智，要么不可能。 • **理想化与现实**（afandian）：反思"mental prototyping"（心理原型设计）是否算作"doing the thing"，以及其时间投入的价值。

评论摘要
主要讨论点：OpenBSD 的优势、劣势及其与 Linux（如 Debian）的比较 不同观点： • **支持 OpenBSD** - 默认安全性强（如默认禁用所有服务），系统易于理解 - 升级和维护简单，长期运行稳定（如用户提到服务器多年无需干预） - 文档集中且一致，构建系统从源码快速（如 10 分钟编译内核） - PF 防火墙配置语法优于 Linux 的 iptables • **批评 OpenBSD** - 性能较差（如 Web 服务器请求处理速度仅为 Debian 的一半，网络性能更低） - 部分软件生态支持不足（如 J 语言包缺失） - 用户认为 BSD 整体逐渐边缘化（如 PC-BSD 消失、NetBSD 性能落后于 Linux） • **中立或对比观点** - FreeBSD 用户因 OpenBSD 的兼容性问题转向，但仍使用其组件（如 obhttpd） - Linux（如 Debian）更灵活、用户基数大，已填补 BSD 的传统优势（如 FreeBSD 的过去特性） - 争议焦点：BSD 是否值得为“非主流”或安全牺牲性能/生态？ 补充讨论： - **社区与未来**：部分用户呼吁捐款支持 OpenBSD，但对其长期影响力存疑（如“濒临消亡的群体”）。 - **个人体验差异**：有用户报告 FreeBSD 无故崩溃，而 Linux 长期稳定；另一用户反驳此观点可能为个案。 - **意识形态选择**：部分用户偏好 OpenBSD 的“完全自由开源”构建流程，反对 Linux 的复杂构建文化。

Denial of Fuzzing: Rust in the Windows Kernel

作者: ndiddy | 评分: 4 | 评论数: 0 | 发布时间: 2025-11-12 14:51
文章摘要

Check Point Research（CPR）发现Windows新Rust内核组件GDI存在安全漏洞，该漏洞于2025年1月被发现并通过微软5月更新修复。研究团队使用WinAFL和WinAFL Pet工具对Windows图形组件进行模糊测试，重点针对EMF+格式的元文件处理漏洞。测试中系统频繁崩溃，发现了一个影响Windows内核的BugCheck问题。尽管主要关注用户空间测试，但该内核级漏洞在反复测试中重现，最终被确认为严重安全问题。相关技术细节另发表于《Drawn to Danger》报告中。
