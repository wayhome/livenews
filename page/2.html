Whenever – typed and DST-safe datetimes for Python

作者: pkkm | 评分: 220 | 评论数: 17 | 发布时间: 2025-04-13 09:12
文章摘要

"Whenever" 是一个现代的 Python 日期时间库，旨在解决标准库 `datetime` 以及其他第三方库（如 Arrow 和 Pendulum）的不足。它支持 DST 安全的时间计算，并通过类型安全的 API 防止常见的错误。与标准库和其他库相比，Whenever 提供了更高的性能，并且能够明确区分简单和时区感知的时间类型，避免意外混用。此外，Whenever 还支持纳秒精度和多种时间运算，并提供了基于 Rust 的高性能实现，同时也有纯 Python 版本可供选择。该库文档完善、测试充分，且即将发布 1.0 版本。

Implementing DeepSeek R1's GRPO algorithm from scratch

作者: xcodevn | 评分: 8 | 评论数: 0 | 发布时间: 2025-04-13 18:33
文章摘要

GRPO-Zero 是一个使用 Group Relative Policy Optimization (GRPO) 算法训练大型语言模型的项目，依赖最少，仅使用 tokenizers 和 PyTorch。相比原始 GRPO，GRPO-Zero 做了以下改进：1) 使用 token-level 的策略梯度损失，每个 token 权重相等；2) 移除 KL 散度，减少 GPU 内存使用；3) 增加过长 episode 过滤，默认关闭以观察模型在有限上下文长度下的学习情况。 训练过程是：对每个问题采样多个答案，计算每个答案的奖励及其均值和标准差，进而计算每个 token 的优势（advantage），并使用 PPO 替代目标进行策略梯度更新。 该项目在 CountDown 任务上训练 Qwen2.5 模型，任务是给定数字列表和目标数字，生成符合条件的数学表达式。奖励函数包括格式奖励和答案奖励。训练使用 Qwen2.5-3B-Instruct 模型，数据集和预训练模型从 Hugging Face 下载。 项目基于 DeepSeekMath、DAPO、TinyZero 和 nano-aha-moment 的工作。

The Manicule: The little hand that's everywhere

作者: bookofjoe | 评分: 38 | 评论数: 1 | 发布时间: 2025-04-10 01:01
文章摘要

《The Secret History of the Manicule》一文介绍了历史上一种常见的符号——手形指示符（manicule），其形状为一只伸出的手指，通常用于标记文本中的重要部分。文章追溯了这一符号的起源，指出它早在中世纪手稿中就已出现，由僧侣和学者用来强调或评论文本内容。尽管印刷术的发明本可能使其消失，但印刷商将其纳入印刷符号中，使其成为正式的排版元素，用于引导读者注意脚注或注释。随着时间推移，手形指示符不仅限于书籍，还广泛应用于19世纪的海报、报纸和广告中，成为吸引注意力的重要工具。文章强调了该符号从手工绘制到印刷排版的演变，以及它在不同时期所承载的文化意义。

评论摘要
主要讨论点：数字媒体中指针符号（manicule）的使用及其局限性 不同观点： • **gwern的观点**：指针符号在数字媒体中不常见，主要是因为数字环境的局限性。低分辨率屏幕和杂乱的页面设计使得指针符号难以清晰呈现。gwern认为在数字媒体中，使用箭头或背景高亮等方式更为有效。 • **对指针符号美学和实用性的质疑**：gwern指出，即使在物理媒体中精美的指针符号（如文中提到的橙色活字符号），在缩小并放入网页后，细节会丢失，变成模糊的黑色斑点，显得滑稽而不协调。这表明指针符号在数字环境中的美学效果不佳。 补充讨论： • **指针符号在当代设计中的使用情况**：gwern提到，尽管很多当代网页设计师知道指针符号，但实际使用者寥寥。他自己的经历显示，为了找到一个合适的指针符号用于网站，他不得不从多个来源（如Wikimedia Commons、Font Awesome、Google Images）中筛选数百个符号，最终才找到一个勉强满意的。 • **指针符号与emoji的对比**：gwern指出，OP在这个网页中没有使用指针符号，而是用了一个emoji作为例子。gwern认为这个emoji在视觉上很丑陋，并强调emoji原本是为SMS聊天信息设计的，不适合用作指针符号的替代品。 争议焦点：指针符号在数字媒体中的适用性和美观性是争议的核心。一方面，有人可能认为指针符号具有独特的视觉吸引力，适用于某些设计场景；另一方面，实际操作中，指针符号在数字环境中的表现往往不尽如人意，导致设计师更倾向于使用其他符号或设计元素。

Don't sell space in your homelab (2023)

作者: Wingy | 评分: 62 | 评论数: 21 | 发布时间: 2025-04-13 17:13
文章摘要

文章主要讨论了在个人家庭实验室（homelab）中出售服务器空间的风险和挑战，建议不要轻易尝试。作者列举了多个原因，包括硬件需求、网络连接要求、公共IP地址、合法保护、计费系统、定价策略、远程访问、保险和法律支持等。此外，处理用户数据和金钱交易可能带来法律风险，如涉及DDoS攻击、盗版、代理流量和加密货币挖掘等非法活动。若不具备完善的法律保护和合规措施，可能面临严重法律后果。文章强调，如果没有足够的技术能力和资源来解决这些问题，贸然尝试会带来高风险。

评论摘要
主要讨论点：个人将家庭网络中的计算资源出租给他人的可行性、风险和潜在收益 不同观点： • [LPisGood] 认为将家庭网络资源出租给陌生人风险高且收益有限，市场主要局限于业余爱好者、有不良企图的人以及社交圈内的人。潜在的法律和安全风险使得这种做法不值得。 • [rdegges] 分享了自己通过Storj网络出租未使用磁盘空间的经验，认为这是一种有效的补贴自己备份成本的方式，虽然收入不多，但足以支付自己的存储费用。 • [celsoazevedo] 指出通过像Storj或Sia这样的服务出租存储空间或通过NiceHash出租GPU的风险较小，因为这些服务对数据进行了加密和分布式存储，用户不会直接访问个人网络。 • [bigstrat2003] 强调将爱好变成收入来源可能会失去原本的乐趣，因为一旦开始盈利，就需要面对商业的复杂性和不那么有趣的部分。 • [neilv] 提到政府可能对某些内容进行打击，即使这些内容在本地并不违法，同时分享了自己早期托管朋友服务器的经历，强调了政治风险。 • [solardev] 建议通过分布式协调层解决许多问题，借鉴SETI@home和BOINC等项目，这样可以在不误导客户的情况下临时出租闲置资源。 • [a3FgH9Lp] 认为出租硬件资源的成本和折旧使得小规模的共置协议不划算，建议专注于个人项目或参与有基础设施的组织。 • [devrandoom] 开玩笑地说，只要在服务水平协议（SLA）中明确不保证任何服务质量，并且在联邦调查局突袭时做好解释准备就可以出租资源。 • [theandrewbailey] 提到曾有人计划将高性能GPU出租给AI工作负载，认为这种想法不切实际。 • [munchler] 质疑高可靠性服务器是否可能在个人地下室运行，认为这些服务器更可能位于数据中心。 • [actuallyalys] 认为只有在为朋友提供服务时，这种做法才可能不导致糟糕的结果，即便是社区内的出租也可能导致服务不满。 补充讨论： • 出租家庭网络资源的主要争议点在于潜在的法律、安全风险以及收入与风险的不对等。 • 通过第三方服务（如Storj）进行分布式存储出租被认为是一种降低风险的有效方法。 • 将爱好商业化可能导致失去原有的乐趣，同时小规模的硬件出租在经济上可能不划算。 • 政治风险和政府打击也是需要考虑的重要因素。
