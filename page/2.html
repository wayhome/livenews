Writing a Rust GPU kernel driver: a brief introduction on how GPU drivers work

作者: losgehts | 评分: 152 | 评论数: 5 | 发布时间: 2025-08-06 16:00
文章摘要

这篇文章简要介绍了GPU驱动程序的工作原理，特别是使用Rust编写的Tyr GPU内核驱动程序。文章通过VkCube程序（一个渲染旋转立方体的简单3D应用）讲解了GPU驱动的工作流程。GPU驱动分为用户模式驱动（UMD）和内核模式驱动（KMD）。UMD负责实现Vulkan等API，描述程序的工作负载，包括几何图形、纹理和着色器等数据。KMD则负责连接UMD和实际的GPU，进行内存分配、任务提交和设备初始化等工作。KMD还需要管理任务调度，确保并行任务的正确执行顺序和依赖关系，并通知用户任务完成。Tyr驱动旨在支持Linux内核，并与Panthor（C语言驱动）提供相同的API。文章强调了内存分配和任务调度在GPU驱动中的关键作用。

A fast, growable array with stable pointers in C

文章摘要

本文介绍了一种用C语言实现的动态数组数据结构——"段数组"（Segment Array），具有稳定指针且适用于 arena allocators。该结构将数据存储在多个连续段中，每段长度是前一段的两倍，新段仅在需要时分配，且段指针保存在固定大小的数组中。这种设计确保指针稳定，不会因数据移动而失效，且能在常数时间内访问任何索引。段大小为2的幂，便于使用位移操作快速计算索引。文章提供了该数据结构的单头文件C实现，并讨论了如何优化内存访问以减少缓存未命中。该结构不仅适用于C，也能在Zig、Rust或C++中实现。

主要讨论点：关于一种非传统数据结构是否应称为“数组”，以及其优缺点和应用场景的讨论 不同观点： • andrewla：认为该数据结构更应被称为“列表”而非“数组”，因为缺乏数组语义，函数在期望数组时会失效。同时提到通过虚拟内存系统来实现带保护页的数组结构，防止越界访问。 • Lichtso：提到另一种类似的数据结构——Rope，具有平衡树结构，可以在任意索引处高效插入和删除，且易于实现写时复制版本控制。 • zokier：指出当前计算机指针仅使用48位，并认为该结构类似于std::deque，具有双端队列的特点。 • variadix：支持使用虚拟内存实现稳定可扩展的向量，通过预留虚拟内存来控制物理容量增长。 • kazinator：反驳“内存是瓶颈”的观点，认为在L1缓存中的紧循环操作中，指令本身也会成为瓶颈。 • willtemperley：认为该结构类似于rust-array-stump，专为计算几何中的中间插入优化而设计。 • unwind：赞赏该技巧，但认为宏的使用过于复杂，并对`clz`指令未出现在反汇编中感到困惑。 • zoogeny：指出该设计在缓存预取方面可能表现不佳，因为地址不是可预测的变化，非连续内存布局对迭代不利。 • pfg_：提到Zig语言中有std.SegmentedList，可以动态调整段数组大小。 • listeria：质疑该结构作为哈希表后备数组的实用性，因为哈希表增长时需要重新哈希，无法提供稳定的指针。 • o11c：质疑该结构是否能被称为“数组”，因为其非连续或至少非固定步幅。 • leecommamichael：表示更愿意使用Odin语言实现类似功能。 • taminka：喜欢单一头文件项目，但指出该项目仅支持C23标准。 • tovej：建议增加最小段大小的控制参数或合并小段的函数，以优化缓存行为。 补充讨论： • 01HNNWZ0MV43FF：提到`plf::colony`作为相关数据结构，供读者参考。 争议焦点： • 该数据结构是否应被称为“数组”，以及其在不同应用场景下的实用性和性能表现。

Out-Fibbing CPython with the Plush Interpreter

文章摘要

本文讨论了作者正在开发的名为Plush的玩具编程语言及其解释器的性能优化。Plush具有基于actor的并行机制，并已能支持2D/3D图形和多核并行处理。作者特别关注Fibonacci微基准测试（fib），因为它强调函数调用的执行速度。在测试中，Plush运行fib(38)需要9.10秒，比CPython 3.13.5的5.70秒慢了60%。 为了优化性能，作者首先将bytecode指令中的`push`和`call`合并为`call_direct`，减少了指令分派开销，使时间缩短至8.44秒。接着，作者使用Linux的`perf`工具分析解释器的主要开销，发现延迟编译机制（即函数首次调用时才编译为bytecode）虽然节省了时间和内存，但也增加了函数查找的开销。 作者通过这些优化措施，旨在提升Plush解释器在fib基准测试上的性能，使其能够超越CPython。
