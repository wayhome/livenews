主要讨论点：[临床试验中患者代表性的问题及其对药物安全性和有效性的影响] 不同观点： • [RobotToaster] 指出临床试验排除了有自杀倾向的抑郁症患者，质疑试验对象的代表性。 • [randcraw] 认为小规模研究中排除异常患者是合理的，但大规模研究应包含更多类型的患者并分层报告结果，以避免增加药物失败的风险。 • [bikenaga] 提供研究数据，显示癌症药物试验中高风险患者（如高龄、合并症患者）更少参与试验，导致试验结果低估了药物对目标人群的副作用风险。 • [kerkeslager] 补充问题更严重，指出女性因月经周期被广泛排除在试验外，甚至动物试验也常排除雌性，导致女性用药风险被低估。 补充讨论： • [ortusdux] 提到试验中对安慰剂的使用和记录不规范，可能影响试验结果的解读。 • [nitwit005] 认为高风险患者被排除是因为他们更可能在试验中受到伤害，但未深入探讨伦理问题。 • [OutOfHere] 指出药物副作用的发生率在实际应用中可能高于试验报告的数据。 争议焦点： • 临床试验是否应更广泛地包含高风险患者以增加代表性，还是应优先控制试验的变量和安全性风险？ • 女性和其他特定人群（如抑郁症患者）被系统性排除是否合理，以及如何改进相关政策？

AI should only run as fast as we can catch up

作者: yuedongze | 评分: 99 | 评论数: 17 | 发布时间: 2025-12-08 17:38
文章摘要

文章通过两个朋友使用AI的经历，探讨了AI发展的关键问题：人类能否快速验证AI的工作以保障可靠性。工程师Daniel能高效检查AI生成的代码并快速部署，而产品经理Eric因缺乏技术背景无法有效验证，导致AI产出不可靠。作者指出，当验证难度远低于学习/创造时（如图像生成），AI能爆发式发展；反之则难以实用。因此，AI的发展速度应匹配人类的验证能力，才能真正发挥作用。

主要讨论点：[AI在编码及其他任务中的可靠性验证问题，以及AI在当前阶段的局限性] 不同观点： • [支持AI验证的重要性] - yuedongze强调让AI可靠执行任意任务的关键在于验证比生成更容易（成本不对称），建议寻找类似编码的结构化任务。 - jascha_eng指出AI生成代码看似合理但需强大测试系统和自动化验证（如预览部署、端到端测试）。 - trjordan补充组织层面的验证机制（如平台团队定义标准、测试基础设施）对控制AI生成代码的“混乱”至关重要。 • [质疑AI当前能力] - blauditore认为AI在复杂遗留代码库中表现不佳，仅适合简单绿场项目。 - diddid指出AI受限于训练数据质量，难以处理企业级应用等模糊领域。 - awesome_dude批评AI仍处于“模式匹配”阶段，缺乏真正理解能力（如基础算术错误）。 • [验证方法的争议] - pglevy提出用AI代理定期检查代码的设想，但未解决验证债务的根本问题。 - wasmainiac主张回归传统方法（如TDD），认为当前讨论是“重复造轮子”或AI炒作。 - Yoric从UI角度提出人类直觉（如语法高亮、缩进）可作为快速错误检测的补充。 补充讨论： - [技术与社会影响] yannyu提到资金推动下AI被强制应用，导致技术与社会脱节，甚至出现“自我修正”的伦理问题。 - [未来展望分歧] gradus_ad接受非确定性代码的普及，呼吁加强测试框架；而ambicapter则对“奇点”放弃态度，隐含对AI过度发展的警惕。 - 争议焦点： AI验证是否足以弥补其生成缺陷（如trjordan与wasmainiac的对立），以及AI是否具备本质理解能力（awesome_dude与支持者的分歧）。
