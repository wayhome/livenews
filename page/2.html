Obituary for Cyc

作者: todsacerdoti | 评分: 196 | 评论数: 32 | 发布时间: 2025-04-08 19:13
文章摘要

Douglas Lenat的Cyc项目旨在通过扩展符号逻辑构建通用人工智能（AGI），但历经40年最终失败。Lenat从博士期间的自动化数学发现项目开始，发现基于启发式搜索的系统初期表现出色，但很快因规则耗尽而停滞。其后继系统EURISKO虽以非传统策略赢得比赛，但仍面临类似限制。Lenat认为AGI需要海量的常识知识，于1985年启动Cyc项目，手动编码数百万常识规则，期望系统能通过阅读自然语言文本和自主实验实现机器学习。尽管Cyc耗资2亿美元，包含约3000万条断言，但始终未达到预期突破。 Cyc在商业应用中实现财务稳定，但未显示出比其他公司如Oracle和IBM的类似服务更具竞争优势。其封闭性和Lenat对其他AI方法的排斥也导致项目孤立于学术界。截至2025年，Cyc仍未实现通用人工智能，标志着符号逻辑方法的失败。

Linux Kernel Defence Map 是一个展示 Linux 内核中漏洞类别、利用技术、错误检测机制和防御技术之间关系的图形化工具。该地图不代表完全缓解，而是展示各概念间的关联，帮助开发者浏览内核文档和源码。它包含常见弱点枚举（CWE）编号，并聚焦于内核加固，不涵盖用户空间安全特性或Linux安全模块（LSM）策略。该项目在 GitHub 等平台上开源，使用 DOT 语言编写，并通过 GraphViz 生成 SVG 图，许可证为 GPL-3.0。此外，作者还创建了 kernel-hardening-checker 工具，用于检查内核配置的安全加固选项。

评论摘要
主要讨论点：内核安全加固工具及其相关技术比较 不同观点： • [anthonyryan1] 认为 kernel-hardening-checker 是一个非常有用的工具，能够分析个人内核配置文件并指出安全改进的领域。虽然比 KSPP 更全面，但有时建议禁用一些用户可能正在使用的内核功能。 • [Sponge5] 指出，该工具主要关注内核安全加固，而不包括减少攻击面的措施，比如没有涵盖 SECCOMP。 • [nine_k] 对工具中防御措施的数量印象深刻，尤其是针对 C 语言特定问题（如未定义行为、边界检查、释放后使用等）的措施相对较少。并提出与 OpenBSD 的安全功能进行比较的兴趣。 • [acje] 认为当前在系统层面分类漏洞的模型令人鼓舞，但对当前扩展 von Neumann 架构的策略持怀疑态度，认为该策略会导致软件分区的脆弱性、资源争用以及共享内存通信的问题，并提供了一篇文章链接以详细说明其观点。 补充讨论： • [chenhoey1211] 认为该图不仅对内核开发者有用，对使用 Rust、Zig 或其他低级系统代码的开发者也有帮助，并询问是否有人见过类似的关于 Wasm 运行时（特别是沙盒和隔离模型）的可视化分解图。 争议焦点： • 内核安全加固工具的建议是否过于激进，可能影响用户对某些内核功能的使用。 • 当前系统架构策略是否合理，是否会导致更多的软件复杂性和潜在问题。
