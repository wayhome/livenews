Content-defined chunking added to Bazel

作者: siggi | 评分: 24 | 评论数: 1 | 发布时间: 2026-05-13 20:57
文章摘要

文章介绍 BuildBuddy 远程缓存通过内容定义分块（CDC）让大型构建产物只传输变化字节而非整文件。对 Bazel 启用后，可减少上传与存储约40%。该技术尤其改善链接、打包、归档等传递性大输出的缓存效率，避免小改动导致大量近似重复文件被完整上传下载。

δ-mem: Efficient Online Memory for Large Language Models

作者: 44za12 | 评分: 193 | 评论数: 16 | 发布时间: 2026-05-16 09:30
文章摘要

论文提出 δ-mem：一种面向大语言模型的轻量在线记忆机制。它在冻结的全注意力模型上加入固定大小关联记忆状态，用 delta-rule 更新，并通过低秩修正影响注意力。仅 8×8 状态即可提升多项记忆任务表现，同时基本保留通用能力，无需扩展上下文或全量微调。

评论摘要
主要讨论点：围绕 δ-mem/固定大小记忆机制是否能让 LLM 获得长期、低成本、实用的“记忆”，以及模型评测与部署指标如何表达。 不同观点： • 乐观派认为，未来可通过固定大小状态加超长 token 历史/日志回看，实现几乎无限上下文；模型可在 GPU 上更好装载、长期运行，并通过引导注意力窗口等机制扩展外部记忆。 • 怀疑派指出，δ-mem 只是把过去信息压缩进固定矩阵，并未解决记忆容量上限；输入轻微变化会导致激活差异，难以可靠关联查询。真正需要的是语义层面的上下文搜索与缓存。 • 实用需求派关心是否能让 agent 记住代码仓库规范，避免每次会话重复喂入多份文档、浪费 token；也希望看到在编码 agent 中经过实践验证的有效记忆方案，而非概念或插件演示。 • 工程评测派希望模型发布时标准化报告运行所需 RAM、首 token 时间、吞吐和延迟；认为参数量会掩盖 FP16/INT4、MoE 内存占用等关键差异。 • 技术评价派认为该方法大体是在现有 LLM 中加入 DeltaNet 超网络，并非突破性创新；也有人担心成本未说明，或可能只是过拟合/训练集泄漏。 • 节能观点认为，应复用他人的历史搜索/任务结果，因为许多任务相似，重复计算浪费能源。 补充讨论：评论还纠正了标题中 Δ-Mem 与论文 δ-mem 的大小写差异，认为小写 δ 是有意使用，平台不应自动修改非 ASCII 字符大小写。

Kioxia与Dell合作，将40块245.76TB LC9 QLC NVMe SSD装入2RU PowerEdge R7725xd服务器，容量达9.8PB，支持5个400Gbps网卡，面向AI、数据湖和备份等高密度存储场景；满机柜可达196PB。

评论摘要
主要讨论点：围绕超高密度存储设备的实际用途、成本门槛、技术瓶颈及潜在影响展开讨论。 不同观点： • 太空/轨道应用派：认为相比“轨道数据中心”，轨道 CDN 更现实。可让 Starlink 等卫星缓存媒体内容，减少星座内数据传输；非实时内容可接受更高 RTT，甚至可用高轨/GEO 卫星做流媒体缓存。 • 成本质疑派：多位评论者关注价格，认为仅企业级 NVMe 硬盘成本就可能达 50万到100万美元以上，因此短期只适合 hyperscaler、大型国防或科研预算。“没人买得起”的吐槽也呼应了这一点。 • 技术瓶颈派：指出系统受 PCIe 带宽限制，SSD 与网卡共享通道，网络只能做到约 5×400Gbps；但也提到 PCIe 7.0/8.0 可能缓解瓶颈。有人关心散热问题，认为热设计是关键未解点。 • HDD 替代期待派：关注文中提到三星未来 nearline SSD，可能具备类似或更高容量，并有 1PB 单盘路线图。有人认为真正的“HDD killer”可能还需 5–10 年，并期待未来家庭 SSD NAS/AI 云。 • 消费者视角：希望类似技术下放到消费市场，认为每美元存储容量增长停滞；也有人担心数据中心大量采购会推高消费级硬盘价格。 • 实用/玩笑派：有人调侃可用于超大备份、升级 NAS、放在邮轮上“搬运数据”；另有人计算满速写满需约 666 分钟，称其为“Satan’s NAS”。 补充讨论：部分评论批评文章质量，如标题错误、首句混淆 TB/PB；也有人认为设备本身只是“把 Kioxia 硬盘装进 Dell 盒子”，新闻价值有限。另有评论从公共部门数据收集角度指出，10PB 足以存储中等国家公民的大量终身记录，引发隐私与治理层面的联想。
