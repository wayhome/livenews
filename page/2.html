How the US Built 5k Ships in WWII

作者: rbanffy | 评分: 34 | 评论数: 3 | 发布时间: 2025-05-08 20:58
文章摘要

在二战期间，美国实现了惊人的造船成就，共建造了5,000艘船只。战前美国造船业一度萧条，但战争压力下，美国从1939年至1945年建造了近4,000万总吨的商用货船和数百万吨的军用舰艇。政府资助造船并制定策略，私营企业则负责实际建造，通过焊接和预制等创新技术大幅提高效率。美国海事委员会（Maritime Commission）在1936年成立，旨在复兴美国商船队，其“长期计划”原本打算10年内建造500艘船，但随着战争逼近，该计划迅速扩展。在战争中，美国建造了超过3,600艘货船和700多艘油轮，极大地支持了战争胜利。

Show HN: Using eBPF to see through encryption without a proxy

作者: tylerflint | 评分: 190 | 评论数: 19 | 发布时间: 2025-05-08 16:49
文章摘要

Qtap 是一个基于 eBPF 的代理工具，能够在 Linux 内核中捕获加密前的网络流量，提供有关出口连接及其发起进程的详细上下文。它通过附着到 TLS/SSL 函数来截获加密前后的数据，并将其传递给灵活的插件，提供完整的可见性（进程、容器、主机、用户、协议等）。Qtap 无需修改应用程序、安装代理或管理证书，即可帮助理解出口流量的详细情况。它适用于安全审计、网络问题调试、API 开发、第三方集成故障排查、协议学习与探索、遗留系统调查和验证测试等多种场景。Qtap 要求 Linux 内核 5.10+ 并启用 BPF Type Format (BTF)，且需要提升权限来运行。项目目前处于早期开发阶段，欢迎社区反馈和贡献。

Podfox: First Container-Aware Browser

作者: pierremenard | 评分: 17 | 评论数: 0 | 发布时间: 2025-05-08 22:19
文章摘要

文章介绍了作者因端口冲突问题，决定 abolish 容器端口转发，开发了一种让浏览器直接与容器通信的解决方案，即 "Podfox"。文章首先讨论了容器的普遍使用，尤其是在开发环境中的应用，如使用 Docker Compose 启动多个服务。作者遇到的问题是，两个项目都需要使用 RabbitMQ，导致端口冲突（EADDRINUSE）。 为解决此问题，作者设想并实现了一种 "容器感知浏览器"（Podfox），它无需修改端口即可直接访问容器的网络。具体实现并非修改浏览器本身，而是在后台运行一个简单进程，利用 Podman 的 rootless 网络功能。Podman 使用 slirp4netns 和 pasta 等工具实现 rootless 容器的网络通信，通过创建虚拟网络接口对（veth pair）连接容器与主机的网络命名空间。 最终，作者通过进入容器的网络命名空间，使浏览器能够直接访问容器服务，从而避免端口冲突问题。
