F* file system – file search that reads SSD directly bypassing OS kernel

作者: neogoose | 评分: 8 | 评论数: 2 | 发布时间: 2026-06-21 20:44
文章摘要

FFS（F* File System）是一个用C语言编写的命令行文件搜索工具，约1500行代码。它的核心特点是绕过操作系统内核，直接读取磁盘原始数据进行搜索。 **主要特性：** - 直接读取磁盘块设备，跳过VFS缓冲层 - 支持Ext4、Btrfs和APFS文件系统 - 可搜索未挂载的卷（如.dmg、.iso文件） - 利用OpenMP实现多核并行处理 **性能表现：** 文件数量越多，相比ripgrep优势越明显。在325万文件的测试中，FFS用时36秒，而ripgrep需要75秒。 **局限性：** macOS主磁盘需禁用SIP保护、可能遗漏最近写入的文件、仅支持已实现的文件系统。本质上这是一个概念验证项目，展示直接磁盘访问可以超越内核VFS的性能开销。

评论摘要
主要讨论点：一个需要 sudo 权限的文件系统项目的实用性和技术局限 不同观点： • **项目作者立场**：承认项目实用性有限（需要 sudo 权限运行），但强调开发过程很有趣。项目支持多种文件系统（ext4、btrfs、apfs），具备多线程、压缩、嵌套卷等功能，能搜索未挂载的 .iso 和 .dmg 文件。特别指出 AI 代码助手无法帮助开发此类需要 sudo 的项目。 • **质疑者立场**：提出更深层的技术怀疑——项目能否绕过 SSD 控制器的底层操作？特别关注 flush 操作的可靠性问题，即无法确保数据真正写入物理存储介质，而非仅停留在控制器缓存中。 补充讨论：这是一个关于系统级编程局限性的讨论。作者关注应用层权限限制和开发体验，而评论者则指向更底层的硬件抽象问题——即使有 sudo 权限，软件也可能无法完全控制现代 SSD 的实际写入行为。这反映了存储系统中软硬件边界的固有矛盾。

Claude Tag 是 Anthropic 推出的团队协作新功能，目前在 Slack 上推出 beta 版。团队成员可以在频道中 @Claude 来委派任务，Claude 会自动规划并执行工作。主要特点包括：多人协作、持续学习频道上下文、主动提供信息更新、异步工作和任务调度。管理员可精细控制 Claude 访问的工具和数据范围，不同频道的权限和记忆相互隔离。目前 Anthropic 产品团队 65% 的代码由内部版 Claude Tag 创建。该功能面向 Claude Enterprise 和 Team 客户开放，使用 Opus 4.8 模型。

评论摘要
主要讨论点：Anthropic发布Claude Tag - 一个Slack集成功能，允许在Slack频道中标记Claude进行协作工作 不同观点： • **质疑产品质量**：多位用户指出Anthropic自己65%的代码由Claude生成，认为这反而暴露了其产品质量问题，不是卖点 • **认为过度宣传**：批评HN变成"Claude博客"，这只是一个Slack插件的小功能更新，不值得登上首页 • **肯定多人协作价值**：强调Claude Tag的核心创新在于多人共享一个AI助手，可以接续对话，像真正的团队成员 • **关注行业趋势**：指出AI实验室正在争夺客户界面控制权，不只是提供模型 • **技术实现挑战**：讨论构建企业级AI助手的难点：持久化记忆、访问控制、隔离运行环境等 • **与竞品对比**：提到Cursor已有类似功能，且在非技术人员需求规范化方面表现不错 补充讨论：有用户质疑这是否只是将Claude Web改为API计费方式；有人认为Anthropic可能会推出自己的Slack竞品；也有用户抱怨API过载问题，讽刺Anthropic在无法支撑的情况下继续推动增长。
