文章摘要

Electric motors with no rare earths

作者: bestouff | 评分: 492 | 评论数: 24 | 发布时间: 2026-06-12 22:08
文章摘要

雷诺集团是无稀土电动机技术的先驱，采用电励磁同步电机(EESM)而非永磁同步电机。自2012年起大规模应用该技术，目前已发展至第二代(6A系列)，应用于Megane、Scenic、Alpine A290和雷诺5等车型。第三代E7A电机将于2027年推出，功率达200千瓦，体积缩小30%，效率约92%，并支持800伏快充。采用绕线转子设计可避免依赖中国稀土供应(中国控制全球90%以上稀土和永磁体生产)。所有电机均在Cléon工厂生产。

评论摘要
主要讨论点：雷诺电励磁同步电机(EESM)技术的创新性和实用性 不同观点： • **技术创新质疑派**：认为无永磁电机并非新技术，工业电机早已广泛使用，大型电机一直采用线圈励磁。质疑雷诺的真正创新在哪里，是否只是在小型化和效率优化上有所突破 • **技术路线争议派**：关注雷诺是否使用有刷设计。有刷电机需要频繁维护更换电刷,虽然声称可用15-25万英里。部分人认为应采用感应电机+变频器,或质疑为何不用特斯拉早期的感应电机方案 • **实用价值肯定派**：认为92%效率虽不及永磁电机但已足够好,避免稀土供应链风险是合理妥协。EESM在高速工况效率更高,适合高速公路或重型卡车应用,且不受转子温度影响 • **技术细节分析派**：详细对比EESM与永磁电机优劣。优势包括不受稀土价格波动影响、高速工况效率高、可实现单位功率因数;劣势是转子冷却困难、轴向长度更长、电流控制复杂、功率密度受限 • **市场竞争视角**：指出宝马已有更先进的800V架构无稀土电机(功率达300kW),雷诺160kW显得落后。也有人期待配合钠电池降低成本 补充讨论：争议焦点在于这是否为真正创新,还是旧技术的汽车应用。稀土磁铁性能优越,美欧应自建产能而非放弃使用。

The state of building user interfaces in Rust

作者: mahirsaid | 评分: 97 | 评论数: 21 | 发布时间: 2026-06-10 16:44
文章摘要

这篇文章介绍了Rust语言在GUI开发领域的现状。虽然Rust适合构建用户界面，但缺乏成熟的跨平台解决方案和统一的最佳实践。目前主要通过以下方式实现GUI：与Electron集成使用HTML、使用图形API模拟组件、或绑定现有框架（如GTK、Qt、FLTK等）。文章列出了Rust GUI生态系统中的众多库和框架，包括Dioxus、Tauri、Iced等，涵盖即时模式、响应式、跨平台等不同开发范式，但整体生态仍在发展中。

评论摘要
主要讨论点：Rust GUI 开发的现状、不同框架选择及其利弊权衡 不同观点： • **Web技术派（rendaw）**：倾向使用 wasm-bindgen/web-sys + HTML，认为 Web UI 便携、可远程访问、无需安装，避免原生应用的多平台移植、应用商店审核和开发者费用问题 • **终端UI派（Surac）**：建议使用 TUI（终端用户界面），认为绑定非 Rust 生态系统需要大量 unsafe 调用，不符合 Rust 思想 • **原生框架支持者**：分为多个阵营 - EGUI（the__alchemist 认为其与 WGPU 集成好，但版本同步困难）、GPUI（segphault 称性能优秀但依赖庞大、编译慢）、Iced（neonstatic 深度使用，认为消息传递模型好但布局引擎难用） • **跨语言方案倡导者（chem83, Altern4tiveAcc）**：质疑为何不用 Avalonia、Flutter 等成熟方案，或期待 Qt 提供 Node.js 绑定以结合 Web 技术和原生组件 补充讨论： 社区共识是 Rust GUI 选择丰富但碎片化严重，缺乏明确赢家导致精力分散。实用建议包括使用 sccache 优化编译时间、ratatui 用于 TUI 开发。可访问性支持和文档可视化展示（如截图对比）被指出不足。框架成熟度问题突出，Iced 等仍在频繁变更中。
