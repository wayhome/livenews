Rust running on every GPU

作者: littlestymaar | 评分: 474 | 评论数: 20 | 发布时间: 2025-07-26 10:08
文章摘要

本文介绍了一个使用Rust编写的跨平台GPU计算演示，能够在多个主要GPU平台上运行，包括CUDA（NVIDIA GPU）、SPIR-V（Vulkan兼容GPU）、Metal（Apple设备）、DirectX 12（Windows）和WebGPU（浏览器），并为非GPU系统提供CPU后备。该项目通过结合Rust GPU、Rust CUDA和Naga等项目，实现了用标准Rust代码直接编译到多个GPU目标，避免了传统的专用着色器语言。 演示实现了一个简单的bitonic排序算法，计算逻辑在CPU和GPU上运行相同的代码。通过Rust特性标志和编译目标选择不同的后端和驱动API，如wgpu、Vulkan、CUDA等。尽管演示使用了单一计算内核，但底层工具支持多个内核和入口点。该项目展示了Rust在跨平台GPU计算方面的潜力，尽管仍有诸多待改进之处，但已是一个重要的里程碑。

评论摘要
主要讨论点：Rust和WebGPU等技术在GPU编程中的应用及其优缺点 不同观点： • [vouwfietsman] 认为GPU编程中抽象层会导致问题和性能损失，因为每个硬件目标都有显著差异。他强调需要由供应商提供的类似系统，但指出由于供应商未能解决他们的争议，平台差异可能很大。虽然有例外（如Angle），但这些例外通过限制功能集来实现稳定性，从而限制性能。 • [Archit3ch] 关注性能问题，特别是在音频应用程序中的应用。他质疑"Rust -> WebGPU -> SPIR-V -> MSL -> Metal"管道的稳健性，认为多重翻译阶段可能导致脆弱性和难以理解的性能问题。他还对比了"Julia -> Metal"的直接路径，后者利用了苹果芯片的原生优化。 • [chrisldgk] 作为web开发者，对GPU编程不熟悉，提出WebGPU是否通过单一API解决跨GPU后端兼容性问题。他认为WebGPU本身是对现有抽象的再抽象。 • [Voultapher] 详细列出了多层抽象，从Rust代码到硬件驱动，认为这些隐藏的复杂性可能影响性能优化的能力。 • [slashdev] 对打破GPU软件中的供应商锁定持积极态度，认为即使需要为最大性能打破抽象，拥有一个跨平台的内核仍然非常有价值。 • [piker] 对现有无分配（no alloc）的crate可以直接运行于GPU上表示惊讶，认为这 unlock 了很多有趣的想法。 • [tormeh] 认为Rust-GPU的主要用例是将CPU开发者转变为GPU开发者，并接受一定的性能损失。对于已经熟悉CUDA/Vulkan/Metal/DX的开发者，这种抽象可能不具吸引力。 • [hardwaresofton] 认为Rust GPU项目已经有很多，但仍需添加利用naga等的后端。他质疑是否只需使用wgpu即可。 • [ivanjermakov] 质疑这是否真的是"Rust"在GPU上运行，认为这更像是proc macro重语法下的着色器语言，可能导致某些优化无法实现。 • [gedw99] 对这项工作表示极大赞赏，认为它帮助开发者避免平台战争，专注于开发。 • [omnicognate] 提到Zig也可以编译到SPIR-V，但尚未尝试。 • [rbanffy] 认为多后端编译到单一二进制文件并在运行时选择特定平台代码路径是目标。 • [bobajeff] 对改善异构计算开发体验的努力表示赞赏，认为工作量巨大但非常有价值。 • [reactordev] 期待未来能够编写与用户程序语义相同的GPU程序，并预见其对推理的巨大影响。 • [melodyogonna] 关注实际项目中存储GPU IR的二进制模型可能导致的二进制文件膨胀问题，并质疑AOT编译对不同GPU的性能影响。他还提到Mojo通过JIT编译解决这些问题。 补充讨论： - 多个评论中反复提到抽象层与性能之间的权衡问题，以及不同硬件目标带来的挑战。 - WebGPU作为统一API的潜力及其在实际应用中的局限性被多次讨论。 - 对Rust在GPU编程中的创新应用表示出兴趣和担忧，特别是与传统着色器语言和JIT编译的对比。

文章摘要

Yahoo曾是互联网的“首页”，1994年由斯坦福大学学生杨致远和David Filo创立，最初名为“Jerry's Guide to the World Wide Web”，后改名为Yahoo。1995年公司正式成立，1996年IPO备受关注，市值迅速超过10亿美元。Yahoo早期是一个链接目录，随着搜索引擎不成熟，它成为用户查找信息的主要工具。为了保持流量，Yahoo开始生产内容并收购内容公司。尽管1996年首次盈利，并在互联网泡沫破裂后表现优于许多同行，但其股票在2001年跌至8.11美元。 Yahoo的收入依赖流量，因此不断收购流行网站以维持访问量，但未区分盈利与非盈利流量。其以100亿美元收购的Broadcast.com和Geocities.com均亏损并最终关闭。Yahoo在1997年至2015年间进行了114次收购，但多数未见成效，如以11亿美元收购的Tumblr最终以300万美元出售。相比之下，Google的收购如YouTube和Doubleclick则非常成功，显示出两家公司在收购策略上的差异。Yahoo错失了一些关键收购机会，如Google和Facebook，导致其最终在2016年以48亿美元卖给Verizon，结束了独立运营。

Tinyio: A tiny (~200 line) event loop for Python

作者: tehnub | 评分: 23 | 评论数: 7 | 发布时间: 2025-07-22 22:02
文章摘要

"tinyio" 是一个简化的 Python 事件循环库，约200行代码，旨在替代复杂的 `asyncio`，特别适用于简单场景。它使用 `yield` 而非 `await` 来暂停和恢复协程，支持同时等待多个协程，出错时会取消所有协程并传播错误。它允许在线程中运行同步函数，并提供简单的睡眠功能。`tinyio` 的 API 包括 `Loop`、`run_in_thread`、`sleep` 和 `CancelledError`，易于使用且无需复杂的 `futures` 或 `tasks`。出错时，所有协程都会收到 `CancelledError`，并有机会优雅地关闭。错误会传播到线程中，且可通过设置 `exception_group` 来收集错误。
