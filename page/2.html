Docs like code in basic terms

作者: DeborahWrites | 评分: 43 | 评论数: 12 | 发布时间: 2025-05-05 10:22
文章摘要

这篇文章简要介绍了“像写代码一样写文档”（docs like code）的概念，专为没有开发背景的读者编写。它解释了相关术语和工具，如文本编辑器（如VS Code）、Markdown语言和版本控制软件git。采用这种方法可以让文档编写与代码开发使用相同的工具和流程，便于开发者贡献文档，并支持社区协作。其优点包括工具熟悉度高、支持多人协作和低成本；缺点是需要一定的网页开发技能，且可能有隐藏的维护成本。文章还对比了其他文档工具，指出通过选择合适的静态网站生成器和主题，可以实现类似功能。最后，文章提供了一个工具和术语的快速参考，帮助读者理解相关组件。

Show HN: US Routing – Python library for fast local routing in the US

作者: ivanbelenky | 评分: 72 | 评论数: 8 | 发布时间: 2025-05-07 23:51
文章摘要

US Routing 是一个用于美国本地快速路由的 Python 库，基于北美道路数据集，支持通过城市名、邮政编码或坐标进行路由计算。主要功能包括快速路由、多种路由选项（最短距离、最快时间）、详细的路由信息（距离、时长、经过的州）。用户可以通过 pip 或 poetry 安装，并能自定义路由器。该库还提供了用于处理和下载北美道路数据的工具，并支持通过 geometries 构建自定义路由图。项目采用 MIT 许可，贡献者可通过提交 Pull Request 参与开发。

评论摘要
主要讨论点：关于一个非AI道路项目的技术讨论及其实现细节 不同观点： • jdelman认为这是一个不错的非AI项目，表达了对多样化项目的赞赏。 • simonw提到了在源代码中发现的一个282M的SQLite数据库，但无法读取，因为遇到了Esri专有的VSRS模块错误。 • svcphr比较了该项目与其他路由工具（如Graphhopper、OSRM）的轻量级优势，但指出该项目使用的Dijkstra算法在速度上较慢，并质疑为何描述为“近似”算法，猜测可能与数据集的不完整性有关。 • culopatin表示有兴趣帮助添加道路类型过滤功能，例如避免多车道高速公路。 • protocolture借题发挥，批评美国电信公司不愿实现动态路由，但对该项目关注道路领域表示欣慰。 补充讨论： • CamperBob2提出了在使用特定Python版本和uv工具时遇到的问题，并寻求解决方案。 - 争议焦点在于CamperBob2对uv工具的理解和使用，以及us-routing对Python版本的特定要求是否与uv工具兼容。 • VladVladikoff询问该路由项目是否适用于短距离城市内导航。 • dmitrygr简要指出该路由库与Google或Google Maps无关，可能是在澄清误解。 补充讨论点：该讨论还涉及技术细节如数据库读取问题、算法效率、Python版本兼容性问题以及实际应用场景的适应性。

Web search on the Anthropic API

作者: cmogni1 | 评分: 205 | 评论数: 12 | 发布时间: 2025-05-07 20:18
文章摘要

Anthropic推出了Anthropic API上的网页搜索功能，使Claude能够访问实时的网络信息。开发者可以利用这一工具构建基于Claude的应用程序和代理，提供最新的洞察。Claude能够根据需求自动进行网页搜索，生成有引用的回答，并进行多步搜索以完善答案。该功能支持多个应用场景，如金融服务、法律研究、开发者工具和生产力应用。组织可以通过允许或禁止特定域的搜索来控制信息来源。网页搜索现已在Anthropic API的多个Claude版本上可用，价格为每1000次搜索10美元，外加标准token费用。

评论摘要
主要讨论点：LLM（大型语言模型）应用中的网页搜索功能及其相关技术与成本问题 不同观点： • **多跳搜索与查询优化的挑战**：cmogni1指出，多跳搜索和基于先前上下文/搜索的查询优化是一个复杂且成本高昂的功能。虽然允许/阻止列表容易实现，但多跳搜索需要从URL中提取上下文信息，增加了复杂性。 • **搜索结果与LLM相关性的不匹配**：cmogni1还提到，现有的LLM网页浏览API难以根据丰富的上下文（如消息线程/提示）重新排序搜索结果，导致搜索结果的相关性不符合预期，例如在撰写关于药物副作用的文章时，优先显示研究文章而非博客帖子。 • **搜索成本的争议**：jarbus认为每次搜索的成本（$10/1000次搜索）过高，并质疑这些成本是否会下降。minimaxir则指出，与Google的Gemini相比，这种价格对于大量使用来说更便宜。 • **域限制功能的实用性**：benjamoon赞赏“允许域”列表功能，认为这使得API更具实用性，因为OpenAI的API不支持限制域。 • **自定义索引与向量嵌入的讨论**：simianwords询问是否使用自定义网页索引或Bing/Google API，并推测当前的LLM网页搜索工具可能不使用向量嵌入，而是依赖纯文本搜索。 • **永久存储搜索结果的合法性**：simonw关心是否可以永久存储搜索结果，并猜测其底层技术是否与Brave浏览器类似。 • **自建搜索工具的替代方案**：omneity介绍了一种自建AI搜索工具，可以连接到任意模型，并利用用户的搜索习惯定制结果，适用于个人使用。 • **搜索工具的组合使用限制**：lemming提到Gemini等平台的搜索工具在与其他工具组合使用时存在限制，这可能影响功能实现。 • **搜索提供商的可配置性**：aaronscott建议允许配置搜索提供商，如使用Kagi，以满足个性化需求。 • **搜索结果排序质量的比较**：zhyder指出大LLM提供商在网页搜索结果排序质量上的竞争，并提出未来最佳提供商可能是在排序质量上胜出的那家，类似于Google当初在搜索领域的成功。 补充讨论： • **成本结构的潜在影响**：potlee提到，如果每次模型决定搜索时都要为输入标记付费，成本将非常高，需要明确API的收费机制。 • **搜索广告收入模式的转变**：metalrain认为，AI聊天不会使网页搜索过时，但会将其嵌入更深的技术栈中，可能促使Google等搜索引擎的收入从广告转向B2B API使用费。 争议焦点： • **搜索成本与质量的权衡**：不同用户对搜索成本和结果排序质量的期望不同，部分用户认为高成本不合理，而另一些用户则关注如何获得更高质量的搜索结果排序。

文章摘要

2025年5月5日，作者推出了"Mac Themes Garden"网站，展示超过3000个经典Mac时代的Kaleidoscope主题，供用户浏览、下载和探索。网站还提供RSS订阅源，方便用户跟踪主题的更新。该项目源自作者运营的Mac Themes Bot，最初在Bluesky、Mastodon和Cohost上展示Mac OS X和经典Mac主题。由于原始数据获取困难，作者通过手动截图记录约4000个Kaleidoscope主题的信息，包括主题的作者和发布年份。由于过程复杂且耗时，目前网站建设尚未完成，但已上线供用户使用。

评论摘要
主要讨论点：围绕早期电脑主题（theming）文化，特别是Mac和Windows系统主题的怀旧与讨论，包括对现代操作系统缺乏类似自定义功能的批评和期望。 不同观点： • **怀旧与对现代 blandness 的批评**：[rf15] 认为过去的电脑主题文化充满创意和个性，而现在只有“企业赞助的乏味设计”和不再关心个性化表达的用户群体。用户仅仅将电脑当作浏览网页的工具。 • **Mac 和 Windows 主题文化的差异**：[rhet0rica] 强调Mac主题文化的多样性，尤其是单个艺术家（如Martha Royer）创作了数百个主题，展现了惊人的创造力。相比之下，Windows社区的用户更少进行深度系统修改，且风格较为单一，大多是RGB风。 • **对现代操作系统的期望**：[cosmic_cheese] 怀念经典Mac OS的超高自定义性，尽管当时存在安全问题，但认为现代操作系统在安全的前提下可以尝试复制这种灵活性，并提出了利用类似现代macOS的“app扩展”架构的想法。 • **对特定主题的怀念与需求**：[hoistbypetard] 和 [bix6] 表达了对经典Mac OS 8/9主题以及特定主题（如Monkey Paradise）的怀念，并愿意付费获取这些主题的现代可用版本。[milesskorpen] 和 [antfarm] 也分享了类似的怀旧情绪，提到他们曾通过Kaleidoscope等工具深度定制系统。 • **对特定功能的怀念**：[WillAdams] 怀念Mac OS 9中窗口标题栏在“window-shaded”时缩小至文字大小的功能，并希望这种功能能在现代系统中重现。 补充讨论： • **技术限制与错失机会**：[betterThanTexas] 提到由于过去没有root权限，无法对家庭电脑进行深度定制，并对Apple未能延续这种自定义文化表示不满。 • **现代可行性**：[ugh123] 直接询问这些主题是否能在现代Mac上安装，表明部分用户对过去主题在现代系统中的兼容性感兴趣。[egypturnash] 也表达了对Kaleidoscope类似现代工具的渴望，尽管最终发现该网站并非新工具。 争议焦点：现代操作系统是否应恢复或允许类似过去的高自由度主题和自定义功能，以满足用户的个性化需求。
