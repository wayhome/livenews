A Tour of Microsoft's Mac Lab (2006)

文章摘要

Async I/O on Linux in databases

作者: jtregunna | 评分: 150 | 评论数: 21 | 发布时间: 2025-07-20 06:20
文章摘要

本文描述了作者在开发简单键值数据库过程中，对I/O性能优化的探索。最初使用内存哈希表和简单的追加日志实现持久化，但性能不佳。之后，作者转向研究Linux的io_uring机制，它通过共享环形缓冲区在应用与内核间实现真正的异步I/O，大幅提升吞吐量。然而，异步I/O导致数据持久性和一致性问题，作者通过引入双写前日志（WAL）设计解决该问题：一个记录操作意图（异步写入），另一个记录操作完成，只有两者齐备时才在恢复时应用操作，确保一致性。最终，作者使用Zig语言实现了该方案，并通过实验验证其性能和可靠性。

评论摘要
主要讨论点：io_uring 与同步 API 的性能比较及其在数据库中的应用，特别是关于持久性（durability）和正确性的讨论。 不同观点： • **quietbritishjim** 认为文章中比较的是有 fsync 调用和无 fsync 调用的性能，而不是同步 API 和 io_uring 的真正性能对比。他认为如果同步代码中去掉 fsync，也能获得类似的性能提升。此外，io_uring 也可以通过某些方法实现 fsync 的功能，因此文章的比较是不对等的。 • **jorangreef** 指出 TigerBeetle 始终使用 fsync 来保证持久性，并且他们的设计目标不是性能而是正确性。TigerBeetle 的双 WAL（写前日志）设计是为了协议感知的恢复，而不是简单的性能优化。 • **sethev** 认为文章中的逻辑有误，指出如果第4步（等待完成记录写入 WAL）正确执行，那么第3步（等待意图记录持久化）就是多余的。他怀疑第4步可能没有正确执行，导致误解。 • **jmpman** 担心如果系统崩溃后，客户端收到成功的请求可能没有对应的完成记录，这违反了 ACID 原则。 • **avinassh** 同意 jmpman 的观点，认为如果完成记录是异步的且可能未完成，那么服务器的持久性保证就会有问题。 • **tlb** 和 **BeeOnRope** 都质疑意图记录的必要性，认为如果只有完成记录是持久化的，那么单独记录意图记录似乎没有意义。 • **leentee** 认为文章中的方案不能保证持久性，并且认为好的同步代码比坏的异步代码更可取，尤其是对于现代 NVMe 存储而言，同步 IO 已经足够快。 • **lstroud** 分享了在 Linux raid 驱动中遇到的死锁问题，并通过移除 lvm 解决了吞吐量问题。 • **ptrwis** 提到目前只有一个人在为 PostgreSQL 实现异步直接 IO。 • **tobias3** 对双 WAL 操作比单个同步 IOPS 更快的说法表示怀疑，认为这可能意味着数据库根本没有持久性。 • **jtregunna** 在更新中澄清了需要等待完成记录写入后再响应客户端，并指出双 WAL 方法在批量处理时有优势，但在接近单次写入时成本更高。 • **ozgrakkurt** 分享了自己实现 crash-resilient LSM 树的经验，并好奇双 WAL 方法与 append/rename 方法的 trade-off。 • **eatonphil** 提到目前似乎没有很多数据库在生产环境中默认使用 io_uring，并希望有人能做这样一个调查。 • **jasonthorsness** 质疑 NVME 存储接口是否应该比 Linux 抽象层更简洁，并提出某些高性能应用可能更适合作为特殊用途的 unikernels。 补充讨论： • 争议的焦点在于文章中比较的合理性和持久性保证，特别是 fsync 在异步和同步代码中的作用。 • 另一个值得注意的讨论点是双 WAL 设计的必要性和意图记录的作用。 • 一些评论者分享了实际操作中的经验和解决方案，比如 lstroud 的死锁问题和 ozgrakkurt 的 crash-resilient 方法。 • 还有评论者对 io_uring 在生产环境中的使用情况表示关注，并希望有更多调查和数据。

"The Bitter Lesson" is wrong. Well sort of

作者: GavCo | 评分: 9 | 评论数: 1 | 发布时间: 2025-07-20 16:33
文章摘要

文章主要讨论了AI研究中两种方法的平衡问题：基于“人类知识”的方法和依赖“数据+计算”的通用方法。作者反对Rich Sutton在“苦涩的教训”一文中提出的观点，即仅依靠数据和计算就能取得长期进展，认为人类知识和数据驱动方法需要相互补充和平衡。文章指出，没有纯粹依赖人类知识或完全无需人类指导的机器学习模型。人类知识在模型构建的各个阶段，从设计到评估，都发挥着重要作用。尽管随着技术发展，模型可能更多依赖“有影响力的”方法，但人类知识的直接应用仍然不可或缺。作者以大型语言模型为例，说明在模型生命周期的不同阶段，如何平衡这两种方法以构建有效的AI模型。

评论摘要
主要讨论点：Sutton与Pinhasi对AI进展的不同看法，以及手写编码知识在AI模型中的作用。 不同观点： • [rhaps0dy]认为Sutton讨论的是AI整体的长远进展，强调长期依赖纯粹的学习方法可能更有前景，而不是手写编码知识。Sutton的观点倾向于减少人为干预，更多依赖算法自我学习。 • Pinhasi（OP）则专注于当前生产环境中的AI模型构建，认为手写编码知识在实际应用中是不可或缺的，因为这能够帮助模型在短期内达到生产级别的要求。 • 关于手写编码知识的作用，[rhaps0dy]指出，虽然在短期内手写编码对模型生产有帮助，但从长远来看，这种方法对AI的持续进步贡献有限。这暗示着手写编码可能是一种权宜之计，而非长远解决方案。 • 评论中还提到了具体技术趋势的变化，例如卷积神经网络（CNNs）和群卷积神经网络（group-convolutional NNs）。这些技术试图通过编码不变性来提高效率，但仍然主要依赖学习方法。然而，这些技术似乎也正在逐渐过时，表明技术变化迅速，依赖特定的手写编码知识可能不是长期的最佳策略。 补充讨论： • 争议的焦点在于手写编码知识在AI模型中的作用及其长期有效性。一方面，它对当前生产模型至关重要；另一方面，从长远来看，它可能限制AI的自主学习能力和发展潜力。 • 不同的时间框架（短期与长期）也构成了讨论的重要背景，Sutton关注的是AI的长期发展，而Pinhasi则更注重实际应用中的即时需求。 • 技术趋势的变化，例如CNNs和group-convolutional NNs的兴衰，进一步丰富了讨论，展示了AI技术的快速演进。

Show HN: MCP server for Blender that builds 3D scenes via natural language

作者: prono | 评分: 117 | 评论数: 18 | 发布时间: 2025-07-20 06:01
文章摘要

Blender MCP（Model Context Protocol）是一个将大型语言模型（LLM）与Blender无缝整合的工具，通过简单的JSON指令让AI实时控制3D场景。它通过TCP连接实现，无需插件或手动操作，支持如Claude、ChatGPT等模型。Blender MCP使用轻量级的JSON协议，提供对3D场景、物体、材质和动画的全面控制，旨在简化AI驱动的3D创作流程。其架构包括TCP服务器、指令处理器和场景控制器。用户可以通过克隆GitHub仓库、配置Claude Desktop和安装Blender插件来设置MCP。该工具旨在让AI与人类创意无缝协作，实现自然语言和实时控制的结合。

I'm betting against AI agents in 2025, despite building them

作者: Dachande663 | 评分: 120 | 评论数: 20 | 发布时间: 2025-07-20 08:59
文章摘要

文章作者基于过去一年构建多个AI代理系统的经验，对2025年将成为“AI代理年”的炒作持怀疑态度。他指出三个关键现实问题： 1. **错误率复合增长**：在多步骤工作流中，即便每步的可靠性为95%，20步后的成功率仅为36%，而生产系统需要99.9%以上的可靠性。当前技术下，自主多步骤工作流在数学上是不可能的。 2. **上下文窗口的成本问题**：长对话导致代币成本呈二次方增长，使得会话代理在经济上不可行。一个100轮对话的成本可达50-100美元，无法大规模应用。 3. **工具设计挑战**：构建适用于代理的生产级工具是另一大工程挑战，大多数团队低估了这一难度。 作者总结，成功的代理系统并非完全自主，而是由离散、可验证的操作组成，并在关键节点加入人工确认。最有效的“代理”往往是简单、无状态的工具，而非持续对话的代理。

Laminar Flow Airfoil

作者: colinprince | 评分: 6 | 评论数: 0 | 发布时间: 2025-07-18 00:54
文章摘要

文章主要介绍了层流翼型及其在航空领域的应用。层流是指空气在飞机机翼或机身表面平滑、无干扰地流动，对飞行至关重要。如果流动被中断，会产生湍流，导致升力下降和阻力增加。层流翼型设计旨在保持边界层的平滑流动，以减少阻力。 北美P-51“野马”战斗机是首款有意采用层流翼型的飞机，但由于制造表面不够光滑，实际层流效果有限。贝尔P-63“眼镜王蛇”也有类似问题。层流理论可追溯到德国空气动力学家路德维希·普朗特的研究，他提出了边界层的概念。 尽管“ consolidated B-24解放者”的“戴维斯”翼型早于P-51就具有低阻力特性，但设计者并未意识到它是层流翼型。NACA在20世纪30年代末对一些飞机进行了层流翼型测试，如改装的B-18。 层流翼型的应用需要极高的表面光滑度，这在批量生产中难以实现。北美航空通过填充和涂漆来解决这一问题，以提供必要的平滑度。
