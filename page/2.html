Linux Kernel Rust Code Sees Its First CVE Vulnerability

作者: weinzierl | 评分: 30 | 评论数: 8 | 发布时间: 2025-12-17 17:30
文章摘要

Linux内核中的Rust代码首次出现CVE漏洞（CVE-2025-68260）。该漏洞涉及Android Binder的Rust重写部分，存在竞争条件可能导致内存损坏和系统崩溃，但不会造成远程代码执行等更严重问题。该漏洞影响Linux 6.18及更新版本。Greg Kroah-Hartman已公布这一情况。

评论摘要
主要讨论点：Rust在防止内存损坏方面的有效性及局限性 不同观点： • **Rust的unsafe操作仍有风险** - 示例：Rust Binder中的unsafe操作导致内存损坏，类似于C中的问题 - 争议焦点：即使有unsafe标记，仍需开发者确保线程安全，否则仍可能发生数据竞争 • **Rust的价值在于缩小问题范围** - 论据：unsafe块能隔离潜在问题代码，便于排查 - 反驳（bangaladore）：未定义行为可能影响安全代码，问题不一定直接源于unsafe块 • **Rust并非万能，但优于C** - 观点（drob518）：Rust不能消除所有漏洞，但提供了比C更高的安全性 - 补充：目标从来不是完全无漏洞，而是显著降低风险 • **其他语言（如Zig）可能更适合内核开发** - 观点（pa7ch）：语言吸引力取决于能否吸引熟练的内核开发者，而非绝对安全性 补充讨论： - 讽刺性评论（HumanOstrich/secondcoming）：对行业现状的悲观调侃 - 争议延伸（kahlonel）：多语言环境可能增加漏洞多样性

评论摘要
**主要讨论点：** 现代图形API（如Vulkan和DX12）的复杂性问题，以及是否需要更简化的API设计。 **不同观点：** • **支持简化API** - Vulkan和DX12过于复杂，包含大量冗余功能和历史包袱（如不支持现代GPU的指针功能）。 - 新API可以显著提升性能，例如模拟OpenGL时比现有Vulkan层更快（vblanco）。 - 硬件已转向通用SIMD设计，但API仍保留过多特定着色器类型，阻碍了库生态发展（starkparker）。 • **对简化API的质疑** - 文章本身过于技术密集，与“简化”目标矛盾（vegabook）。 - 作者声称的“150行API”是玩具原型，实际省略了大量必要功能（如枚举、错误处理），对比WebGPU时存在不诚实（jdashg）。 • **行业现状与替代方案** - 部分行业（如VFX）已转向硬件加速的软件渲染（如CUDA）（pjmlp）。 - 中间件（如Unreal Engine）可能削弱了底层API的重要性（ksec）。 - NVIDIA的NVRHI等抽象层能缓解API复杂性（klaussilveira）。 **补充讨论：** - **争议焦点**： - 简化API是否真能兼顾性能与易用性，还是牺牲了必要功能（如WebGPU的保守设计选择）。 - 移动GPU对Mesh Shader的兼容性问题（modeless）。 - **其他要点**： - 缺乏新手友好的学习资源是图形编程的痛点（starkparker）。 - DX12更新停滞可能源于微软策略或行业依赖引擎（ksec）。 - 文章被部分读者视为里程碑，但也被批评缺乏对从业者的实际价值（xyzsparetimexyz）。

Pricing Changes for GitHub Actions

文章摘要

**TL;DR - GitHub Actions 价格调整：** 2026年1月1日起，托管运行器（hosted runners）降价最高39%，但同年3月1日起将对自托管运行器（self-hosted runners）收取每分钟$0.002的平台费用。96%的用户账单不变，4%受影响用户中85%费用降低，仅15%月均增费约$13。公开仓库仍免费，企业版（GitHub Enterprise Server）不受影响。此次调整旨在平衡成本与价值，支持平台创新，并基于新架构提升性能（日均处理7100万任务，能力提升3倍）。

评论摘要
主要讨论点：[GitHub对自托管运行器（self-hosted runners）收费的合理性及用户反应] 不同观点： • **反对收费** - 收费不合理，尤其是对自托管运行器（用户已自行承担硬件成本）按分钟计费显得荒谬（[Someone1234]指出年成本高达$1051）。 - GitHub Actions功能问题多（如Kubernetes集成落后、缺乏SDK），却未改进产品就直接收费（[golovast]）。 - 微软收购后逐渐“恶化”（encrapification），类似Skype的命运（[amarant]）。 • **支持迁移到开源/替代平台** - 呼吁转向社区维护的自由软件（如Forgejo、GitLab），尽管功能可能不足，但避免被商业平台剥削（[throwaway150]）。 - GitLab CI被推荐为更优选择（[chrisweekly]），或探索Nix-based方案如Tangled（[verdverm]）。 • **质疑商业动机** - 收费是垄断后“榨取用户”的行为（[andsens]），可能针对第三方运行器服务（如WarpBuild）（[clintonb]）。 - GitHub通过此政策排挤生态合作伙伴（[mtlynch]）。 争议焦点： - 收费是否合理？支持者认为需覆盖平台成本，反对者认为这是对自托管用户的额外剥削。 - 功能缺陷与收费时机：用户不满在未解决现有问题的情况下收费（如[golovast]列举的GHA缺陷）。 补充讨论： - 有用户提出技术替代方案（如Zig已弃用GHA，[pixelpoet]）。 - 长期担忧：微软收购后的产品生命周期模式（[amarant]）。
