Backpressure is all you need

作者: lucasfcosta | 评分: 54 | 评论数: 18 | 发布时间: 2026-05-31 12:11
文章摘要

文章讨论了使用AI编程代理的三种方式。第一种是让AI无人监管运行，快速但危险，容易产生bug和难以审查的PR。第二种是人工审查每个步骤，安全但效率低下。作者提出第三种方法：让AI在人工介入前自我验证更多工作。 核心概念是"反压机制"——下游组件向上游发出无法接受更多工作的信号。在软件开发中，自动化测试和类型系统就是反压机制，迫使开发者在提交代码前修复问题。 目前AI开发的问题是**人类成为了反压机制本身**，需要手动审查AI输出。文章主张下一步应该建立自动化反压系统，让AI在提交给人类前通过测试和类型检查等机制自我验证，从而实现更长时间的安全无人值守运行。

评论摘要
主要讨论点：如何通过更强的验证/反馈机制降低AI编程代理对人工审查的依赖，以及这种做法是否新颖、有效、值得。 不同观点： • “这是常识/基础做法”派：多位评论者认为文章讲的是“agent 101”。论据是成熟做法早已包括开发环境拉起、构建、单测、集成测试、端到端使用、自主迭代达标；也有人给出固定流程，如先写简短spec、让代理分阶段执行并持续更新。 • “术语不准确”派：质疑把它称为“backpressure”。他们认为这更像固定限流或结构化反馈回路，并没有根据人工审查容量动态回传压力；争议焦点是“减少低质量提交”是否等同于真正的背压。 • “应靠hooks/确定性机制”派：主张不要依赖额外LLM解释长提示，而应把停止检查、git提交检查等做成hooks，让验证在代理结束时自动运行，避免遗忘，并在QA端重新引入确定性。 • “过度工程/收益存疑”派：认为行业在AI工作流上设计过重，真实高效方式往往是快速微迭代；大计划、复杂编排未必比轻量使用产出更高，也可能是过早优化。 • “成本与工程现实”派：指出API和自动化费用高、模型易无谓停顿、SDK差、定制harness难；因此理念虽对，但落地受成本和工具链限制。 • “怀疑上限”派：认为若系统约束与测试都已定义，本质接近“把程序再编程一遍”，类似TDD，工具未必真做到宣传效果。 补充讨论：有人补充现有先例/替代方案，如相关项目、GitHub工具，以及“介于智能补全和代理之间”的更轻量产品方向。

作者: algorithmsRcool | 评分: 37 | 评论数: 3 | 发布时间: 2026-05-31 15:46
文章摘要

Chibil 是一个基于 chibicc 用 C# 重写的 C 编译器，目标平台是 .NET IL（MSIL）。它能够编译 C 源文件生成与 MSVC /clr 模式兼容的 COFF OBJ 文件，通过 Visual Studio 的 link.exe 链接成可执行文件。该编译器功能完整，已能运行 DOOM 游戏。支持调试（行号和局部变量），但目前没有标准 C 库，仅提供最小运行时存根。未来计划开发自己的链接器以摆脱对 Windows 的依赖。

评论摘要
主要讨论点：将C代码编译为.NET IL字节码的技术方案 不同观点： • **CLR原生支持论**（whizzter）：CLR模型一直支持C/C++语言指令，理论上可以编译一次在多平台运行。但提到可能存在库的可移植性问题，建议如果只是想让C代码跨平台运行，从头开始可能效果更好。 • **项目本质说明**（le-mark）：澄清这是将chibicc（一个C编译器）移植到C#，并更新为生成.NET IL字节码的项目。 • **微软现有方案**（pjc50）：指出微软的"cl /clr"编译器已经实现了类似功能，但这是一个相对小众的应用场景。 补充讨论：三条评论形成了一个递进关系——从技术可行性讨论，到项目实现方式说明，再到指出已有的商业解决方案。核心共识是这类技术在.NET生态中已经存在，但应用范围有限。

文章摘要

文章认为，大公司里的“正常工作”对人的创造力和主动性并不自然。人类更适合在8到20人的小群体中协作，而大型组织虽拆成小团队，仍因层级和管理树结构压缩个人自由。作者据创业者观察指出，自己做创业虽更辛苦，却更符合人的天性，像野外生活之于狮子。

评论摘要
主要讨论点：大公司层级制度是否适合人性，以及扁平化组织的可行性 不同观点： • **支持扁平化结构者**：认为几十人的团队在扁平化管理下运作良好，大公司的官僚主义扼杀创新和个人主动性。创业公司环境更能激发工作热情，让人感觉"做自己"而非被消耗（musicale, phyzix5761, k_plankenhorn） • **质疑扁平化可行性者**：指出所有尝试无层级结构的公司最终都形成了"影子层级"，因为人性使然——不是每个人都能同时关注全局和自身职责。大规模协作（如金字塔建造、军队）本质上需要层级和流程（dentemple, zkmon） • **中立/现实主义者**：承认大公司有问题但也有优势——高薪、稳定、工作生活平衡。扁平化在小规模（35人以下）有效，但扩展到70人以上就会出现问题。创业公司也会复制相同的功能失调（lazy_afternoons, interludead, stephbook） • **批判"自然论证"者**：强烈反对用"人类本性"或"自然设计"来论证组织结构，认为这是自然主义谬误。人类文明本身就是超越"自然状态"的产物（stephbook, lordkrandel, hnhg） 补充讨论：有评论指出"不适合有老板"的创始人往往也不会管理他人，导致创业失败（Aurornis）。另有人批评富有的资本家谈论工作的"非自然性"却不推动实质性社会改革（dangus）
