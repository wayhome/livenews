主要讨论点：Herdr（一个新的终端复用器）与 tmux 的对比，特别是在 AI agent 管理场景下的优劣 不同观点： • **支持 Herdr 的观点**：运行多个 AI agent 时，Herdr 提供更好的可见性和状态管理。一位用户管理 10+ 个 agent，发现 tmux 难以追踪哪些 agent 在等待批准或已空闲数日。Herdr 的侧边栏和状态显示（idle/working）解决了这个痛点。 • **质疑 Herdr 价值的观点**：部分用户认为除了 agent 状态通知外，看不出相比 tmux 有何实质性优势。有用户满意于 tmux 的功能（如可在手机上使用），不认为需要切换。 • **功能特性讨论**：Herdr 的优势包括鼠标友好、display-popup UI、自动剪贴板复制、更好的嵌套会话支持、跨会话重连能力。但也存在问题：输入延迟、键盘复制粘贴在某些终端（wezterm）中不好用、缺少键位重绑定功能。 • **工作流集成需求**：开发者关注 git worktree 支持，希望在多个 worktree 中并行运行 agents。现有工具（Emdash、Nimbalyst）管理状态的方式不够灵活。 • **商业模式争议**：有评论质疑 Herdr 是否在向新手收费，而这些功能用 tmux 等免费工具也能实现。另有人指出其营销材料中使用公司 logo 可能存在法律风险。 补充讨论：TUI 工具的兴起被认为反映了现有 GUI 的不足；多位用户推荐了替代工具（belfry、terminai.app、Superset、Conductor）；Herdr 的目标用户似乎是需要同时管理大量 AI agents 的重度用户。
