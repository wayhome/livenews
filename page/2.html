DotnetSnes: Library allowing to use C# to create SNES ROMs

作者: ingve | 评分: 21 | 评论数: 0 | 发布时间: 2025-05-02 11:29
文章摘要

**DotnetSnes** 是一个允许使用 .NET 语言创建真实 SNES 游戏 ROM 的库。它通过一个 .NET 库（DotnetSnes.Core）抽象 SNES 游戏开发中的函数和全局变量，编译后的 DLL 通过 "Dotnet To C" 转译器（dntc）转换为 C 代码，再使用 PvSnesLib SDK 工具链生成可用的 ROM。由于 SNES 的限制，编写时需注意系统级类型支持、无动态内存分配、最小化堆栈变量等。开发环境建议使用 Linux 或 WSL，依赖包括 cmake、g++、dotnet-sdk-8.0 等。项目示例包括简单的 "Hello World" 和更复杂的 "LikeMario" 游戏示例，展示了对象管理、地图、音频和手柄输入。要创建新项目，需设置 .NET 类库，引用必要库，并配置 Makefile 以定义 ROM 构建过程。

A PostgreSQL planner semi-join gotcha with CTE, LIMIT, and RETURNING

作者: namanyayg | 评分: 28 | 评论数: 6 | 发布时间: 2025-05-04 01:24
文章摘要

文章描述了在PostgreSQL中使用CTE（Common Table Expression）结合`DELETE ... RETURNING`和`LIMIT`处理队列表任务时遇到的意外行为。尽管查询中明确使用了`LIMIT 1`，但有时会返回多条记录。这是因为PostgreSQL的查询规划器将查询优化为一个嵌套循环半连接（Nested Loop Semi Join），导致子查询（包括`LIMIT 1`）针对每个候选行执行多次，从而可能删除并返回多行。 问题的根源在于CTE没有被当作一个优化屏障，规划器自由地将其内联或转换。为解决此问题，作者建议避免在`DELETE`条件中使用CTE，改为直接在`WHERE`子句中使用子查询： ```sql DELETE FROM task_queue WHERE id = ( SELECT id FROM task_queue WHERE queue_group_id = 15 LIMIT 1 FOR UPDATE SKIP LOCKED ) RETURNING item_id; ``` 这样可以确保`LIMIT`在全局范围内应用，从而实现预期行为。

评论摘要
主要讨论点：Postgres查询中的潜在bug及相关SQL写法 不同观点： • [eknkc] 认为这听起来像是一个全面的planner bug，而非“gotcha”（陷阱）问题。 • [simonw] 不理解`item_id`的来源，推测它可能是`task_queue`表中未提及的列。 • [wordofx] 质疑为什么作者不直接使用`RETURNING *`，认为不需要用CTE（Common Table Expression）选择所有内容。 • [swid] 认为查询不应删除多行，但对Postgres查询计划的解释存在歧义，指出这个bug可能仍然存在。 • [Horffupolde] 建议使用`= ANY`代替`IN`，认为这是更好的做法。 • [abhisek] 关注如何防止查询优化导致意外结果，并提出在CI或linter中检测这些问题的可能性。 补充讨论： • [swid] 提到查询计划的模糊性可能导致不同的解释，虽然期望Postgres只使用单一解释，但实际情况可能并非如此。 • [abhisek] 进一步提出实际开发中的防护措施，比如使用linter工具或在CI中检测潜在bug，以避免这些问题进入生产环境。 争议焦点： • 查询是否会删除多行以及Postgres查询计划的解释是否存在歧义。 • 使用`RETURNING *`与CTE的选择问题，涉及查询的简洁性与可读性。 • 使用`IN`与`= ANY`的建议，涉及SQL写法的最佳实践。

文章摘要

一项新研究分析了2023年和2024年丹麦劳动市场，发现尽管像ChatGPT这样的生成型AI模型在一些工作场所迅速被采用，但对总体工资和就业尚未产生显著影响。这项由芝加哥大学和哥本哈根大学经济学家进行的调查，涵盖了25,000名工人和7,000个工作场所的数据，重点研究了AI聊天机器人对11个易受自动化影响的职业的影响，包括会计、软件开发人员和客户支持专员。研究显示，尽管64%到90%的用户节省了时间，但平均仅节省2.8%的工作时间，且只有3%到7%的时间节省转化为收入增加。研究还发现，AI实际上为8.4%的工人创造了新的工作任务，例如检查学生是否使用ChatGPT做作业。总体而言，研究表明生成型AI对劳动市场的短期影响有限，但长期影响仍需进一步研究。

Run LLMs on Apple Neural Engine (ANE)

作者: behnamoh | 评分: 223 | 评论数: 18 | 发布时间: 2025-05-03 15:29
文章摘要

ANEMLL是一个开源项目，旨在加速大型语言模型（LLM）向张量处理器的移植，最初专注于苹果神经引擎（ANE）。其目标是提供从模型转换到推理的完整开源管道，支持常见LLM架构在ANE上的设备端推理，适用于低功耗的边缘设备，确保隐私和安全。主要组件包括LLM转换工具、Swift参考实现、核心推理引擎、Python示例代码和iOS/macOS示例应用。当前的0.3.0 Alpha版本支持从Hugging Face模型转换为CoreML格式，主要支持LLAMA 3.1等模型，未来将支持更多模型。项目提供了示例应用和模型下载，并包含性能测试工具。用户可以通过Swift CLI运行模型，并使用TestFlight测试iOS/macOS应用。
