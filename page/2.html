I built Zenith: a live local-first fixed viewport planetarium

作者: surprisetalk | 评分: 43 | 评论数: 5 | 发布时间: 2026-05-15 15:45
文章摘要

Zenith 是一个实时显示头顶星空的网站，通过极小视场高倍率放大，让地球自转造成的恒星视运动可见。它可按用户位置展示对应天区，位置不上传；使用 Pan-STARRS 天文图像、SIMBAD 数据和地图瓦片技术。不同纬度看到不同“星空丝带”，同纬度东西方向仅时间不同。

评论摘要
主要讨论点：围绕 ZenithTrack 通过“天空窄带”展示地球自转的体验、可理解性和功能改进展开。 不同观点： • 概念很酷、适合投影：多位评论者认为可投到天花板上，能在无需望远镜的情况下直观感受地球转动。 • 解释存在疑问：有人不理解“one rice-grain tall”的含义，追问是否指手臂长度下米粒对应的角直径，焦点在尺度说明是否清晰。 • 地球自转的“即时感”很有价值：有人分享用带太阳滤镜的跟踪望远镜给小学生演示，跟踪失效后孩子们反而被太阳快速移出视野震撼。 • 非跟踪观察更能体现运动：评论认为非跟踪望远镜或该工具都能让人惊讶地感到地球转得很快。 • 功能建议：因有人屏蔽定位请求，页面默认到 Stonehenge，建议允许手动输入经纬度；另有人建议增加搜索框，可跳转到特定恒星或坐标。 • 裸眼也可体验类似效果：有人提出在高山地区，让低空月亮被山脊部分遮挡，站着观察月亮移动，效果甚至比望远镜漂出视野更震撼。 补充讨论：争议不明显，主要是赞赏与改进建议；唯一的理解障碍集中在“米粒高度”这一比喻的角尺度定义。

Radicle: Sovereign {code forge} built on Git

作者: KolmogorovComp | 评分: 172 | 评论数: 11 | 发布时间: 2026-05-15 12:07
文章摘要

Radicle 是基于 Git 的开源点对点代码协作平台，去中心化复制仓库，用户自主掌控数据与流程。它通过加密身份、签名数据、 gossip 协议和本地优先设计，支持离线使用、抗审查协作，并提供 CLI、Web、桌面端等模块化工具。

评论摘要
主要讨论点：围绕 Radicle 作为去中心化/本地优先代码协作平台的价值、适用场景、成熟度与文档表达展开。 不同观点： • 支持去中心化 forge：认为 Radicle 相比 GitHub 等中心化平台更能避免控制、审查和平台依赖，且私有仓库、本地优先、加密身份、签名产物等方向有潜力。 • 实用体验积极：有人表示 Radicle “好用、能跑”，尤其适合 agentic workflow；也有人看好其作为未来智能体协作 forge 的基础。 • 需求与场景质疑：有人不清楚它到底解决什么问题，追问是否主要是反中心化和抗审查；也有人批评 FAQ 没讲清 Radicle 与 Git/GitHub 的区别、“forge”含义及额外价值。 • 部署与生态顾虑：希望更容易做局域网/本地私有部署，像无中心服务器版 on-prem GitLab；当前需要脚本且文档不足。 • 替代现有基础设施的期待：有人希望 Radicle 替代 crates.io，减少 Rust 对 GitHub/Microsoft 的依赖，并解决命名空间问题。 • 成熟度问题：关注高负载表现、CI、PR 流程，以及是否支持 Mercurial、SVN、Pijul 等非 Git VCS。 补充讨论：有人提到域名迁移；也有小吐槽如官网字体。争议焦点在于：Radicle 的核心价值是否足够清晰、是否能在 GitHub 强势生态下获得采用，以及去中心化带来的复杂性是否值得。
