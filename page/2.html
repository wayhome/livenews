301party.com是一个提供多种重定向服务的网站，允许用户通过特定URL路径实现不同类型的重定向，如301、302等。用户可以通过修改"url"参数自定义目标地址，例如重定向到指定网站或本地服务。此外，网站还提供了一些快捷路径，如"/metadata"重定向到AWS实例元数据服务，"localhost"重定向到本地主机等。该网站还包含一些特殊DNS记录，如将localhost.301party.com解析到127.0.0.1。需要注意的是，这类服务可能被用于绕过安全检测或进行其他潜在恶意活动。

Comptime.ts: compile-time expressions for TypeScript

作者: excalo | 评分: 89 | 评论数: 5 | 发布时间: 2025-08-03 19:11
文章摘要

**comptime.ts** 是一个简单的 TypeScript 编译器工具，允许在编译时评估标记为 `comptime` 的表达式，从而将运行时计算移至编译时，优化代码性能。其灵感来源于 Bun macros 和 Zig comptime。使用时需确保标记的表达式在编译时安全评估，因为该工具不提供隔离。`comptime` 导入仅限于项目文件，但可以从 `node_modules` 导入。 ### 示例 1. **简单求和函数**：编译时计算结果并替换。 2. **零运行时 CSS 库**：将 `emotion` CSS 转换为编译时计算的类名。 3. **常量计算**：如时间单位在编译时转换为具体数值。 ### 安装与使用 - 安装：通过 `bun`, `pnpm` 或 `npm` 安装。 - 使用：支持 Vite 和 Bun 打包工具，通过插件配置启用。 ### 特性 - 支持函数调用和模板字符串等复杂表达式。 - 结果必须可序列化为 JSON。 - 提供 CLI 和 API 使用方式。 - 支持强制编译时评估和 Promise 解析。 ### 注意事项 - `comptime` 标记的 import 语句在输出中会被移除。 - 编译时计算可大幅优化性能，但需谨慎处理副作用和依赖管理。

评论摘要
主要讨论点：JavaScript中的新型导入属性及其应用和影响 不同观点： • [spankalee] 认为使用 `type: 'comptime'` 是对 `type` 导入属性的不当使用。他指出，`type` 是规范定义的属性，应该对应于所导入模块的 MIME 类型，当前 Web 平台支持 "json" 和 "css" 两种类型。由于导入文件的 MIME 类型仍然是 `application/javascript`，因此如果这个模块有类型，它应该是 "js"。他建议选择一个不同的导入属性。 • [apatheticonion] 则关注于将 Rust 风格的宏和过程宏引入 JavaScript 的需求，例如使用类似 `jsx!` 的语法来替代 `.tsx` 文件，或者使 WebAssembly 更易用，以便能够在 Web 应用中使用 Rust 编写代码。 • [mdarens] 提到了 Zig 语言的编译时特性，并质疑该特性是否适用于像 Zig 那样的编译时泛型类型。他认为类型级别的映射与运行时代码使用相同语法是非常强大的功能，可以解决 TypeScript 中 "过大联合" 的问题。 • [Thom2000] 对 `import-with` 语法表示陌生，并指出很难找到相关文档，询问这是否是一种语法扩展。 • [stevage] 认为这种导入属性可能对预编译 markdown 有用。 补充讨论： • 关于 `type` 属性的正确使用及其是否应该用于非标准用途存在争议。 • 对 JavaScript 引入其他语言特性（如 Rust 的宏）的需求和可能性进行了讨论。 • 对编译时特性和类型系统在不同编程语言中的实现和应用进行了比较。 • 对新语法和特性的文档缺乏及其对开发者理解和使用的影响提出了疑问。 • 提出了这种新特性在实际应用场景中的潜在用途，如预编译 markdown。

文章摘要

本文讨论了作者正在开发的名为Plush的玩具编程语言及其解释器的性能优化。Plush具有基于actor的并行机制，并已能支持2D/3D图形和多核并行处理。作者特别关注Fibonacci微基准测试（fib），因为它强调函数调用的执行速度。在测试中，Plush运行fib(38)需要9.10秒，比CPython 3.13.5的5.70秒慢了60%。 为了优化性能，作者首先将bytecode指令中的`push`和`call`合并为`call_direct`，减少了指令分派开销，使时间缩短至8.44秒。接着，作者使用Linux的`perf`工具分析解释器的主要开销，发现延迟编译机制（即函数首次调用时才编译为bytecode）虽然节省了时间和内存，但也增加了函数查找的开销。 作者通过这些优化措施，旨在提升Plush解释器在fib基准测试上的性能，使其能够超越CPython。
