Clj-coll: Clojure collections and sequences in Common Lisp

作者: todsacerdoti | 评分: 18 | 评论数: 0 | 发布时间: 2025-07-26 14:58
文章摘要

CLJ-COLL 是一个在 Common Lisp 环境中实现 Clojure 集合和序列 API 的库。它提供了类似 Clojure 的不可变数据结构，如 Cons、Queue、PersistentList、Vector、Set 和 Map，并通过 Clojure 的 API 访问。该库旨在让 Clojure 程序员更容易使用 Common Lisp，但不包含完整的 Clojure 语言特性，如 `def`、`defn`、`fn` 和 Clojure 样式解构。它支持 DOSEQ 以及 Clojure 兼容的 map/reduce/transduce 操作。库中包含 257 个函数，其中大部分直接来自 Clojure 的 `clojure.core` 和 `clojure.set` 命名空间。虽然不支持 Clojure 的 LOOP/RECUR，但可以使用 Common Lisp 的迭代机制。该库还提供了与 Clojure 类似的打印和读取表语法支持，并包含单元测试和文档。对于希望在 Common Lisp 中使用 Clojure 风格集合和序列 API 的开发者来说，CLJ-COLL 是一个有用的工具。

文章摘要

`dlg` 是一个用于 Go 语言的轻量级日志工具，支持 printf-style 调试。它在生产构建中完全消失，从而实现零成本开销。通过不使用 `dlg` 标签进行构建，所有日志调用将从二进制文件中移除，不影响运行时性能。`dlg` 提供两个主要函数 `Printf` 和 `SetOutput`，支持运行时配置堆栈跟踪和并发安全。调试模式通过 `dlg` 标签启用，允许显示堆栈跟踪和自定义输出。该工具设计注重性能和简约，确保在生产环境中无任何内存或 CPU 开销。

评论摘要
主要讨论点：Go语言中死码消除（dead code elimination）与Printf调试语句的交互，以及日志记录和调试的最佳实践。 不同观点： • mdaniel认为，在使用Printf时，如果其参数涉及到函数调用（如`thing.Something()`），即使Printf本身被死码消除优化掉，这些参数的函数仍然会被执行。因此，他质疑所谓的"完全消失"的说法，并指出在Printf中执行操作是一种常见的[反面]模式，但用户可能希望了解这种情况如何与死码消除交互。 • smcameron提出了一种替代方法，即使用版本控制工具（如stacked git）来管理调试语句。通过工具可以方便地删除不再需要的调试语句，从而解决手动删除的问题。 • negrel分享了一个类似的Go库（negrel/assert），用于零成本调试断言，表明他支持和实现了类似的调试方法。 • kitd对库的功能表示赞赏，但建议在生成堆栈跟踪时，只显示调用Printf的行，而不显示Printf内部的行，以减少不必要的噪音。 • sethammons则从日志记录的整体策略角度出发，认为在极端处理需求下，死码消除可以带来性能优化。他个人偏好使用支持结构化日志和上下文感知的日志记录器，并通过中间件进行自定义过滤。 补充讨论： • mdaniel对Printf中执行操作的[反面]模式表示不满，但承认其普遍性。 • smcameron提供了一个实际操作的解决方案，通过版本控制工具管理调试语句。 • kitd关注调试信息的有效性和简洁性，建议优化堆栈跟踪的显示内容。 • sethammons从更广泛的日志记录策略角度讨论死码消除和调试的权衡。 争议焦点：死码消除是否能完全消除Printf及其参数中的副作用，尤其是当参数包含函数调用时。mdaniel对此表示质疑，认为即使Printf被消除，参数中的函数仍会被执行。
