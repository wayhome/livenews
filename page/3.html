How do you keep Web MIDI from crashing a 1983 synthesizer?

这篇文章讨论了使用现代浏览器的 Web MIDI API 控制1983年老式合成器（如 Yamaha DX7）时面临的技术挑战。主要问题包括： 1. **缓冲区溢出**：现代计算机传输速度过快，而老式合成器使用2MHz的8位处理器和256字节RAM，无法及时处理数据。解决方案是在JavaScript中实现软件流控制，分块发送数据并添加延迟。 2. **专有数据格式**：每个厂商的SysEx格式都不同且无文档，需要编写专门的解析器来处理各品牌合成器的独特字节结构。 3. **浏览器安全限制**：因涉及直接硬件访问，浏览器对Web MIDI API实施严格权限控制，部分浏览器完全禁用此功能。

评论摘要
主要讨论点：MIDI设备与现代系统的兼容性问题及相关技术挑战 不同观点： • **缓冲稳定性因平台而异**：USB MIDI缓冲表现在不同操作系统上差异巨大，Windows最稳定，macOS存在命令丢失问题（2017 MacBook），Linux偶尔崩溃 • **Web应用vs桌面应用的争议**：有用户反对用Web应用替代废弃的桌面软件，认为未来不确定；建议打包为离线优先的桌面应用以提高吸引力 • **硬件性能瓶颈并非只存在于老设备**：不仅1980年代设备跟不上，较新的廉价MIDI键盘也会导致Firefox崩溃；旧版Digital Loggers网络电源开关因广播流量过大导致以太网栈崩溃 • **AI生成内容的质疑**：网站的"vibe-coding"风格引发对AI使用的怀疑，认为MIDI这种精心设计的资源受限系统不应依赖AI，应该保持手工编写的传统 补充讨论：有人提出MIDI历史可作为协议/抽象层意义的经典案例，建议使用可编程逻辑阵列或微控制器板进行非标准协议转换。
