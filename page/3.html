Redis 8.8: New array data structure, rate limiter, performance improvements

作者: ksec | 评分: 179 | 评论数: 10 | 发布时间: 2026-06-03 10:05
文章摘要

Redis 8.8 正式发布，带来显著性能提升和多项新功能。性能方面，多种数据类型的操作吞吐量提升最高达83%，持久化和复制速度提升60%。新功能包括：全新的通用数据结构array（索引可寻址的动态数组）、内置的窗口计数器限流器、Streams消息NACK支持、哈希字段的子键通知、JSON数值数组存储的显式控制、时序查询支持多聚合器，以及有序集合的COUNT聚合器。这些改进为现有用例提供了更好的灵活性和效率，并开启了新的应用场景。

评论摘要
主要讨论点：Redis 8.8 新功能发布及 Redis 项目现状 不同观点： • **技术细节纠正派（simonw）**：指出官方描述有误，rate limiter 实际使用的是 GCRA（通用信元速率算法）而非窗口计数器，这是一种漏桶算法，只需为每个限流键存储单个整数（理论到达时间），算法设计精巧且受 Brandur Leach 的 redis-cell 项目影响 • **功能需求派（9dev）**：认可 Redis 作为外部数据结构工具的价值，但指出两大不足：1) 缺乏像 SQLite 那样的嵌入式能力；2) 高可用方案过于复杂，需要阅读大量文档理解两种多节点方案，且存在诸多限制使其在许多应用场景不实用 • **许可证担忧派（tapoxi, ShakataGaNai）**：质疑 Redis 许可证变更后是否还有继续使用的理由，提到 Redis/Valkey 分裂事件，以及 Kubernetes operator 停止维护等问题 • **AI 动机质疑派（fga_qwrh）**：认为 Redis 作者突然热衷 AI 是因为数组数据结构在 AI 中的应用，这一动机在数周前就已明显 补充讨论：有用户（caraphon）对新功能持积极态度，认为 rate limiter 和数组功能值得尝试。另有提及 Redis 与 DeepSeek 可能存在合作关系（focusgroup0）。

ESP32 Bit Pirate 是一个开源固件，可将ESP32设备转变为多协议黑客工具，灵感来自Bus Pirate。它支持通过串口或Web CLI与多种数字协议（I2C、UART、SPI、1-Wire等）和无线协议（蓝牙、Wi-Fi、Sub-GHz、RFID）交互，具备嗅探、发送、脚本化功能。支持多款ESP32-S3设备（M5 Cardputer、LILYGO等），提供协议分析、EEPROM读写、红外遥控、USB编程等超过15种工作模式。可通过Web Flasher一键刷写固件，支持Python脚本自动化操作。

评论摘要
主要讨论点：ESP32 Bit Pirate 固件项目的实用性、与 Bus Pirate 的对比，以及社区对项目真实性的质疑 不同观点： • **积极支持派**：认为这是优秀项目，远程调试 I2C/UART 的 Web 访问功能非常实用，只需投入约5美元的 ESP32 即可替代复杂的接线方案（dbl000, coldcity_again, rkachowski） • **实用对比派**：已有 Bus Pirate v3.6 用户质疑升级必要性，认为新版 BP v6 约100美元的价格过高，询问 ESP32 固件除无线功能外的实际差异（officialchicken） • **技术探索派**：提出具体使用场景需求，如串口转 WiFi 适配器、5V I/O 支持、特定开发板兼容性等实际问题（farfatched, kps, tamimio, throwa356262, ktzar） • **替代方案派**：推荐 Glasgow Interface Explorer，强调其 FPGA 芯片支持自定义协议和高速开发的优势（jwr） • **怀疑质疑派**：对项目真实性表示担忧，质疑是否使用 LLM "抄袭"他人作品、刷 GitHub star，以及夸张宣传"支持所有协议"的可信度（marcosscriven, voidUpdate） 补充讨论：作者 geotp 面对部分刻薄评论，得到社区成员鼓励。项目提供 Web 刷写工具和详细文档，coldcity_again 已成功移植到 Heltec 设备。争议焦点在于项目的原创性和实际能力边界。
