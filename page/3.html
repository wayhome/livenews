文章摘要

亚马逊S3服务在廉价HDD硬盘上实现了每秒1PB流量的惊人性能。尽管HDD存在物理限制（平均随机读取延迟约11ms），但S3通过大规模并行架构克服了这一瓶颈：将数据分散在数千万块磁盘上，采用分片存储（ShardStore）和日志结构合并树（LSM）技术，使写入保持顺序访问优势。同时通过请求路由、智能缓存和预取策略优化读取性能。这种设计使S3以极低成本实现了400万亿对象存储、1.5亿QPS和超高可用性，成为现代互联网的基础设施典范。

Python-Style Kwargs in TypeScript

作者: ingve | 评分: 10 | 评论数: 13 | 发布时间: 2025-09-22 08:25
文章摘要

本文介绍了在TypeScript中模拟Python关键字参数(kwargs)的方法，以解决函数可选参数过多时调用不清晰的问题。作者建议使用"选项对象"模式：将可选参数放入一个对象参数中，通过解构赋值设置默认值并指定类型。这种方法显著提高了代码可读性，保持了类型安全，且允许灵活地只覆盖特定参数。虽然这会使得选项键名成为API的一部分，但在非用户面向前端代码中，通过TypeScript LSP可以轻松重命名。文章推荐在函数有多个可选参数时采用这种模式。

评论摘要
主要讨论点：如何优化函数参数的结构化设计，以及是否应该使用默认参数值。 不同观点： • 支持使用对象作为参数： - [Waterluvian] 认为当参数较多时，使用对象作为参数更清晰，并在函数内部处理默认值。 - [quink] 建议使用定义良好的类（如 Go 的选项结构体）来简化参数传递。 - [lerp-io] 提到 JavaScript 的对象解构和默认参数特性可以很好地解决这个问题。 - [lloydatkinson] 认为在 JS/TS 中，使用对象参数是更常见的做法。 • 反对使用默认参数值： - [williamdclt] 强烈反对使用默认参数，认为这会导致设计问题和潜在错误，应强制开发者显式指定所有参数。 • 对特定语法或实现的批评： - [nrawe] 认为文章中提出的解决方案在语法上不够简洁，不如 Python 的关键字参数（kwargs）清晰。 - [thrance] 对文章的价值提出质疑，认为其建议（对象作为最后一个参数）过于简单。 - [lbreakjai] 指出文章中的代码示例存在错误。 补充讨论： • 争议焦点： - 是否应该使用默认参数值（[williamdclt] vs 其他未明确反对的评论）。 - 哪种参数传递方式更优（对象 vs 传统参数列表 vs 关键字参数）。 • 其他值得注意的点： - [Garlef] 总结了常见的参数传递模式：少量参数直接传递，多参数使用对象，有时结合主要参数和选项对象。 - [jarredkenny] 指出 TypeScript 的对象解构与 Python 的 kwargs 在功能上类似。
