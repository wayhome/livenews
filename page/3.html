Where Do the Bytes Go?

作者: ingve | 评分: 32 | 评论数: 2 | 发布时间: 2025-03-29 11:26
文章摘要

本文简要描述了在调用 `write` 系统调用时，数据在操作系统内核中的处理流程。主要步骤包括： 1. **系统调用入口**：`write` 调用通过 libc 进入内核，经过系统调用机制（如 `syscall` 函数）进入内核态处理。 2. **系统调用分派**：内核检查系统调用号，确认其有效性后，调用机器无关的系统调用处理函数 `mi_syscall`。 3. **参数处理**：在 `mi_syscall` 中，内核进行调试检查、跟踪点检查等操作，随后调用具体的系统调用函数 `sys_write`。 4. **参数重打包**：`sys_write` 将用户传入的参数重打包为 io 向量，然后调用 `dofilewritev` 进行进一步处理。 5. **文件操作**：`dofilewritev` 获取文件描述符对应的文件操作结构，并调用其 `fo_write` 方法，最终进入 `vn_write`。 6. **VOP 调用**：`vn_write` 根据文件状态设置标志位，并通过 `VOP_WRITE` 调用实际的写操作。 整个过程中，数据一直保存在用户态的 io 向量中，直到最终写入文件。

You Need Subtyping

作者: speckx | 评分: 49 | 评论数: 15 | 发布时间: 2025-03-26 18:38
文章摘要

本文讨论了编程语言设计中子类型（subtyping）的概念及其重要性。子类型允许某种类型的值在需要另一种类型的地方使用，与类或继承无关。例如，在JavaScript或Python等语言中，函数可以接受包含特定属性的对象，即使该对象还有其他未使用的属性。虽然一些开发者认为低层次、注重性能的语言不需要子类型，但作者指出，即使是优化过的语言，仍需子类型来处理如空检查（null checking）等特性。例如，Kotlin中非空字符串（String）是可空字符串（String?）的子类型，这有助于编译时捕捉错误。子类型不仅适用于高层次语言，对于具备复杂类型系统的现代语言也至关重要。

评论摘要
主要讨论点：关于子类型（subtyping）在编程语言中的应用和理解 不同观点： • [masklinn] 认为函数接受可以是 String 或 null 的值时，传递一个保证是非 null 的 String 是可行的，但指出这并不意味着 String 是一种 String 的子类型。同时，提到 nullability 属性可能会影响内存布局，特别是在未装箱的整数情况下。 • [pansa2] 提出大多数现有编程语言几乎没有子类型，但随后质疑这一观点，认为当今大多数代码仍然采用面向对象编程（OOP）风格，而OOP通常通过继承支持子类型。 • [jolux] 建议文章标题可以改为“为什么你需要代数子类型”，表明代数子类型可能更适合文章讨论的主题。 • [ijustlovemath] 认为如果目标是组合性，接口/特性（traits/interfaces）已经能实现相同的目标，并且更加通用。 • [gugagore] 指出子类型是类型多态性的一种形式，并列举了其他形式，如参数化多态性、adhoc多态性以及行多态性，认为行多态性与讨论更相关。 • [continuational] 认为如果有一个例子展示子类型不带来更多问题会更有说服力。 • [jyounker] 反驳文章观点，认为子类型在编程语言中很常见，列举了Java、Kotlin、Scala、C++、Python、Go和C#作为例子。 • [a3w] 提出高层次编程语言中，子类型被视为理所当然，因为很多特性似乎都是基于子类型实现的。 • [stephantul] 对文章中“装箱”（boxed）一词的含义感到困惑，请求解释。 • [psychoslave] 将子类型与鸭子类型（duck typing）进行比较。 • [smitty1e] 对文章中子类型关系的例子提出质疑，认为 {x: int, y: int, z: int} 应该是 {x: int, y: int} 的超类型，而非子类型。 • [SomeoneOnTheWeb] 反对文章观点，认为TypeScript中的子类型由于协变性带来了很多问题。 补充讨论： • 子类型在不同编程语言中的实现和应用情况存在争议。 • 子类型与内存布局的关系，特别是未装箱数据类型的情况下。 • 对文章中特定术语（如“装箱”）的定义存在疑问。 • 子类型与多态性的不同形式之间的比较和联系。 • 实际编程中子类型可能带来的问题，如协变性引发的复杂性。

Xee是由Martijn Faassen开发的基于Rust的现代XPath和XSLT引擎。Xee代表"XML Execution Engine"，支持最新版本的XPath和XSLT。XPath是一种用于查询XML的编程语言，而XSLT则利用XPath进行XML文档的转换。Xee提供了一个命令行工具`xee`用于XPath查询，以及一个Rust库`xee-xpath`用于在Rust中执行XPath查询。 该项目始于2023年，由Faassen的客户Paligo发起，旨在用Rust实现现代XPath和XSLT。尽管XML技术已不如从前流行，但它仍在许多领域广泛使用，如SVG和MathML。Xee的Rust实现不仅为Rust生态带来现代XML技术，还可能通过WASM在浏览器中运行，并与其他语言（如PHP和Python）集成。 Xee实现了XPath的现代版本，具备功能性编程语言特性，如类型系统、变量、函数定义、条件和循环等。Faassen曾开发了Python的XML库lxml，重新进入XML领域后，他结合Rust和XML的专业知识开发了Xee。
