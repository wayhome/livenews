Mullvad exit IPs are surprisingly identifying

作者: RGBCube | 评分: 372 | 评论数: 24 | 发布时间: 2026-05-15 02:35
文章摘要

文章指出 Mullvad VPN 会按 WireGuard 公钥确定性分配服务器出口 IP，而非每次随机。作者测试 9 台服务器、3650 个公钥后发现，理论上组合巨大，实际仅出现 284 种。原因可能是 Mullvad 用公钥作种子调用 RNG，并以各服务器 IP 池大小为上限，导致不同服务器分配到相近百分位的 IP。这样多个出口 IP 组合可能成为识别用户的指纹风险。

评论摘要
主要讨论点：Mullvad 被曝不同服务器出口 IP 分配存在可关联性，可能形成用户级指纹；讨论集中在其严重性、VPN匿名预期、修复与披露流程。 不同观点： • Mullvad回应：部分行为是有意设计、部分不是；成因与原文描述不完全一致，已在部分基础设施测试补丁，并会重新评估“隐私 vs 用户体验”的取舍；同时呼吁研究者发布前先通知厂商。 • 风险严重派：认为这种跨服务器稳定映射像“情报机构会设计的VPN”，可帮助论坛管理员识别封禁用户小号；元数据仍会泄露身份。 • 质疑论证派：有人指出“>99%同一人”的说法统计上不严谨；重叠区间只能排除大多数用户，不能直接得出个体识别准确率。 • VPN定位派：认为VPN本就不等同Tor，不应期待对访问网站匿名；需要强匿名应使用Tor，且Tor也可能被出口节点攻击。 • 工程折中派：单服务器内稳定IP有用户体验价值，例如固定服务可用性；但跨服务器相关性应修复，如用 user key + server id 随机化。 • 信任Mullvad派：有评论称Mullvad过往在地理定位数据上较诚实，相信会修复。 • 站点治理派：有人认为网站运营者可利用此属性执行封禁；也有人提到持续维护VPN IP封锁列表，服务方与用户之间是“猫鼠游戏”。 补充讨论：有人追问作者是否提前联系Mullvad；还有人疑惑第三方客户端为何不能像官方客户端一样轮换WireGuard key。

主要讨论点：围绕 Start9 的 StartWRT/RISC-V 开放路由器的“开放性、价格、硬件规格、软件维护与实际可用性”展开。 不同观点： • 质疑定制 OpenWRT 分叉：有人认为小创业公司维护自家 OpenWRT fork 风险高，历史上很多众筹硬件因软件栈过度定制而失败；更希望使用官方 OpenWRT，Turris 也被指出长期承担“再维护”负担。 • 开放性宣传被质疑：评论认为其并非“最开放”，OpenWrt One、Turris 已提供开源启动栈、内核、原理图，甚至 Gerber/CERN OHL 等更完整硬件资料；RISC-V 芯片也不必然比部分 ARM 更“开放”。 • 价格与性能不匹配：多名用户认为 300 美元/25 万众筹目标过高；1GbE+WiFi 6 路由器可低价购买，类似 CPU 的 BananaPi 板约 100 美元。大家要求提供路由吞吐、VPN 吞吐等真实性能数据。 • 硬件配置争议：4GB RAM、16GB eMMC 远超 OpenWRT 基本需求，被问“用来做什么”；同时端口太少，仅 1 WAN+1 LAN，不适合备份 WAN、自托管隔离网络，甚至有人认为 2026 年至少应有双 SFP+。 • 支持 RISC-V：也有人看好 RISC-V 在嵌入式、低功耗设备中的应用，希望更多系统采用。 补充讨论：有人担心外国产处理器/WiFi 模块是否受美国监管影响；也有人提到希望 USB-C 供电。WiFi 固件闭源被认为是行业性难题。
