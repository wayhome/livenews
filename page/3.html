TorchCodec 0.14: HDR Video Decoding for CPU and CUDA, and Fast Wav Decoder

文章摘要

TorchCodec 0.14 发布，兼容 torch >= 2.11，主要更新包括： 1. **快速 WAV 解码器**：新增 WavDecoder，绕过 FFmpeg 直接读取 WAV 数据，解码速度显著提升，支持多种采样格式。 2. **HDR 视频解码**：VideoDecoder 支持高动态范围视频解码，通过 `output_dtype=torch.float32` 输出完整精度的 HDR 色彩范围，支持 CPU 和 CUDA（测试阶段）。 3. **其他改进**：音频定位速度大幅提升，移除了对 NVIDIA NPP 库的依赖，简化 CUDA 解码安装。 4. **Bug 修复**：解决了 CUDA 解码器关闭时的罕见崩溃问题及奇数尺寸视频解码问题。

The only scalable delete in Postgres is DROP TABLE

作者: hollylawly | 评分: 164 | 评论数: 23 | 发布时间: 2026-06-11 16:48
文章摘要

这篇文章讨论了Postgres数据库中大规模删除数据的最佳实践。主要观点是： 大量使用`DELETE`会降低性能，因为它不会立即释放磁盘空间，还会产生"死元组"增加vacuum负担，并给读取查询带来额外开销。Postgres的MVCC机制会保留多个行版本，删除操作实际上是"增加工作"而非"完成工作"。 相比之下，`DROP TABLE`和`TRUNCATE`直接删除物理文件，立即释放空间，不产生死元组，性能开销与数据量基本无关。 文章建议：对于需要大规模删除数据的场景，应设计schema使其可以通过`DROP TABLE`或`TRUNCATE`来实现，而不是使用`DELETE`。对于一次性清理场景，可以使用事务DDL创建临时表保留需要的数据，然后直接DROP原表。

评论摘要
主要讨论点：数据库大规模DELETE操作的性能问题及替代方案 不同观点： • **DELETE可扩展性争议**：crazygringo认为DELETE本身是可扩展的，问题在于批量操作需要不同策略；saisrirampur认为调优良好的autovacuum可让DELETE在TB级别正常工作，文章过于绝对 • **DROP TABLE替代方案的风险**：saisrirampur警告DROP TABLE需要ACCESS EXCLUSIVE LOCK，可能阻塞其他语句，不适合高并发CRUD应用；而多数评论者认可这是大规模删除的有效方案 • **分区策略的适用性**：elnerd和buremba展示了基于时间分区的成功案例（DNS日志、时序数据）；levkk指出CRUD应用难以结构化分区，可能误删重要业务数据；cowthulhu认为需要清空整表本身就说明设计有问题 • **通用性认知**：jandrewrogers和insumanth强调这是所有数据库的共性问题，UPDATE实际是INSERT+DELETE，Elasticsearch等系统表现更明显 补充讨论：评论提到pg_partman工具、pg_repack方案、Oracle相对PG的DELETE优势，以及小规模删除时DELETE可能比TRUNCATE更快的反直觉现象。整体共识是批量操作需要专门优化策略。

zeroserve 是一个高性能 HTTPS 服务器，现在支持 Caddy 兼容模式。它将 Caddyfile 配置 JIT 编译为 eBPF 和本地机器码，在 io_uring 事件循环中运行。性能测试显示：zeroserve 吞吐量达 38,948 req/s，是 Caddy 的 3 倍；延迟 p50 为 1.45ms，比 Caddy 低 70%；内存占用仅 30.9 MiB，远低于 Caddy 的 67.4 MiB。支持图灵完备的 eBPF 脚本，可从 Caddyfile 调用自定义代码，例如实现 AWS SigV4 认证的 S3 反向代理。

评论摘要
主要讨论点：关于 zeroserve（一个基于 io_uring 和 eBPF 的高性能 Web 服务器）的技术价值和安全性争议 不同观点： • **性能怀疑派**：认为这是"vibe coded"项目，6个月内会死掉；没有真实使用场景，Caddy/nginx 性能已足够，35k qps 远超实际需求，水平扩展更实用（Thaxll, bastawhiz, zsoltkacsandi） • **安全担忧派**：io_uring 几周前刚出安全公告，风险太高；JIT 编译攻击面巨大；缺少 ACME 支持是致命缺陷；3400 行锁文件和 AGENTS.md 令人质疑安全性（ok123456, pbohun, BoingBoomTschak, tln） • **技术质疑派**：不支持 ACME 和插件，"Caddy 兼容"名不副实；eBPF 在用户空间运行失去了内核空间的核心优势；nginx 表现依然出色，不是所有东西都需要重写（codingjoe, stymaar, augunrik） • **支持/中立派**：技术上令人印象深刻，想尝试；用户空间 eBPF 虽有复杂度限制但图灵完备；类似 TUX/IIS 的性能优势对大玩家有意义（nullstyle, smallerize, BoingBoomTschak 部分认可） 补充讨论：有用户报告 Chrome 出现 su3.io:443 证书选择弹窗的异常情况（可能与项目相关）

这是一份20世纪60-70年代反主流文化运动的视觉档案目录。内容涵盖：嬉皮公社（如Tree Frog、Rainbow等）、地下出版物（如Helix、Actuel、Chicago Seed）、音乐场馆海报（Boston Tea Party等）、独立书店和艺术空间、以及Rick Griffin、Wes Wilson等反文化艺术家的作品。这些条目记录了从旧金山到波士顿、从加拿大到欧洲的嬉皮运动视觉文化，包括迷幻海报、地下报纸、公社生活照片和独立出版物，是那个时代青年反叛、精神探索和另类生活方式的图像见证。

主要讨论点：关于1960-70年代反文化运动影像资料的价值和意义 不同观点： • **社区主义vs财富孤立观**：反文化运动展现了人们在简单生活中相互帮助、共同生活的社区模式，与现代财富带来的私人庄园、空旷豪宅形成鲜明对比。这种集体生活方式让人们感到快乐和舒适 • **历史档案的可及性**：有评论者指出土耳其等国家通过官方平台（如filmmirasim.ktb.gov.tr）提供类似历史影像资料的访问，强调历史资料保存和公开的重要性 • **商业使命的认可**：Far Out Company致力于挖掘被低估的60-70年代反文化艺术家作品，这种带有使命感的商业模式获得肯定 补充讨论：有评论提到内容的美学风格让人想起《全球概览》（Whole Earth Catalog），暗示这些影像延续了当年反文化运动的视觉和精神传统。另有亲历者表达了对那个时代的怀念。整体氛围积极正面，评论者们从不同角度肯定了保存和传播这段历史的价值。
