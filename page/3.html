When good pseudorandom numbers go bad

作者: chewxy | 评分: 32 | 评论数: 2 | 发布时间: 2025-05-19 07:17
文章摘要

文章讨论了在实际计算机环境中计算矩阵特征分解时可能出现的误差，引用了Wilkinson（1965）的分析，指出由于浮点运算的特性，计算结果可能与理论值有出入，甚至在处理非对称矩阵时，实际计算的特征值可能与理论上的实特征值不一致。文章还描述了作者的同事在使用R语言进行多变量正态分布模拟时遇到的再现性问题，尽管使用了`set.seed()`来控制随机数生成器状态，但在不同机器上仍得到不同的结果。经过调查，发现问题并非出在`set.seed()`或`MASS::mvrnorm()`函数本身，而是由于浮点运算的固有误差导致的。这提醒我们，计算机运算并不总是符合预期，浮点运算的特性可能引发不易察觉的错误。

评论摘要
主要讨论点：数值稳定性、可重复性与工具链支持之间的关系 不同观点： • AlotOfReading认为，大多数人实际上并不关心数值稳定性或计算的精确性，他们更在意结果的可重复性。为了实现可重复性，人们往往会深入研究数值稳定性等话题，但实际上，现代硬件如果遵循一些基本原则（如同样的输入、同样的操作顺序、避免使用特殊函数、非规格化数或NaN值），就可以实现可重复性，且不会造成性能损失。然而，由于工具链不优先考虑这些原则，且用户缺乏相关知识，导致可重复性难以保证。 • mjcohen则通过个人经验分享了对数值计算的兴趣，提到自己曾使用Fortran编写特征值和特征向量程序，并在VAX Fortran环境下发现下标检查会增加30%的运行时间。mjcohen的评论侧重于个人实践经验，特别是历史上的计算环境对性能的影响，而未直接讨论可重复性问题。 补充讨论： • AlotOfReading强调了现代硬件和工具链在实现可重复性方面的潜力和不足，指出即使有实现可重复性的技术基础，但由于工具链支持不足和用户知识的缺乏，实际操作中仍存在困难。 • mjcohen的经验提供了一个历史视角，展示了在过去计算环境下（如VAX Fortran）性能优化的重要性，特别是下标检查对运行时间的影响，这与现代硬件和工具链讨论形成了一定的对比。 争议焦点： • 争议的焦点在于是否可以通过遵循一些基本原则在现代硬件上实现低成本的可重复性。AlotOfReading认为这是可行的，但工具链和用户知识的不足是主要障碍。而mjcohen的经验则侧重于性能问题，未直接涉及可重复性，但暗示了在历史计算环境下性能优化的重要性。

文章摘要

SQLite-JS 是一个将 JavaScript 功能引入 SQLite 的扩展，允许用户通过 JavaScript 创建自定义的 SQLite 函数、聚合函数、窗口函数和排序规则。用户可以编写 JavaScript 代码来处理单个行（标量函数）、多行聚合计算（聚合函数）、窗口数据操作（窗口函数）以及自定义排序（排序规则）。该扩展提供了多个创建函数的接口，如 `js_create_scalar`、`js_create_aggregate` 和 `js_create_window`，并支持直接在 SQLite 中执行 JavaScript 代码。通过这些功能，用户可以在 SQLite 数据库中实现更灵活和强大的数据操作。示例包括通过 JavaScript 计算年龄或中位数等。

文章摘要

文章介绍了Anthropic推出的新协议MCP（Model Context Protocol），该协议旨在让语言模型调用外部工具以执行实际任务，而不仅仅是讨论它们。MCP类似于统一的接口标准，允许一次实现后在不同AI模型和工具间复用，类似USB-C在AI工具中的应用，但目前仍处于早期、不成熟的阶段。 作者尝试用MCP解决语言模型在处理张量计算等复杂符号运算时的不足。通过将Mathematica等计算机代数系统与LLM结合，模型负责自然语言理解和规划，而代数系统则执行精确计算。 尽管MCP生态系统目前文档不全、工具简陋，且存在安全风险，但其基本实现类似FastAPI，易于理解。通过简单示例，作者展示了如何利用MCP让模型正确完成大整数因式分解等任务，而不是凭空捏造答案。 尽管技术仍在初期阶段，但MCP展示了与形式验证系统集成的潜力，未来应用前景广阔。
