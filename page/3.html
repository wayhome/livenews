A USB Interface to the "Mother of All Demos" Keyset

作者: zdw | 评分: 247 | 评论数: 18 | 发布时间: 2025-03-23 15:31
文章摘要

Douglas Engelbart在1960年代初开始探索计算机如何增强人类智力，并开发了许多现代计算的特性，如鼠标、超文本、共享文档、窗口和图形用户界面。在1968年的联合计算机会议上，他通过一场开创性的演示（被称为“所有演示之母”）展示了这些创新。这场演示包括使用一种名为"keyset"的输入设备，但它并未普及。Engelbart的演示还展示了层次文档编辑、图形绘制以及通过远程连接与同事协作，预示了现代计算的许多功能。他的工作受到Vannevar Bush 1945年文章《As We May Think》的启发，旨在增强人类解决复杂问题的能力。Engelbart在斯坦福研究所创立了增强研究中心，并开发了名为NLS的系统，该系统支持交互式文档编辑、代码浏览和数据库检索。这场演示使用了当时先进的硬件和通信技术，连接了Menlo Park和旧金山的会场。

评论摘要
主要讨论点：关于弦键盘（Chorded Keyboard）的历史、应用及其优缺点的讨论 不同观点： • andrehacker认为，道格拉斯提出的弦键盘概念催生了一些相对成功的继承者，例如80年代荷兰的Velotype，它有更多的键， reportedly 使学习“弦”变得更加容易。他还提到了《Nerds 2.0.1》这本书及其相关的PBS系列，认为这是对该主题的有益补充。 • Animats指出，最早的弦键盘可以追溯到1897年Baudot的发明，最初的设计用于发送5位电传字符，并且已经实际部署，而不仅仅是一个原型。 • neilv讨论了Engelbart的演示中出现的键盘设备，指出弦键盘在“可穿戴计算”研究人员中很受欢迎，如Twiddler。其优点是只需要一只手操作，并且可以在没有稳定表面的情况下使用。 • jntun补充了历史细节，指出Engelbart演示中的桌子、办公室和椅子都是由Herman Miller专门设计的。 • peteforde提出了技术性建议，推荐使用RC网络和六角反相器来处理开关输入的反弹问题，而不是依赖100毫秒的延迟。 • GregDavidson分享了个人使用Twiddler与Android手机配合的经验，能够完全操作桌面应用程序，如Emacs。 • jarpineh对弦键盘的潜在优势提出了疑问，包括其在防止RSI（重复性劳损）和占用空间方面的效果，并询问了多语言用户如何适应这些弦键盘，是否需要为不同语言优化不同的弦。 • vagab0nd提到了一种有趣的实验，尝试在vim中设置类似于演示中的声音效果，但未能实现长时播放。 • spit2wind提到了Plover速记引擎，并询问了在欧洲或其他地方是否有制造这些键盘的厂家。 • DonHopkins详细介绍了Valerie Landau与Doug Engelbart的合作，以及他们共同开发的多项技术和专利，包括用于弦键文本输入的多点触控界面和iPhone上的“TipTapSpeech”应用程序。 • KennyBlanken对弦键盘的 ergonomic（人体工学）方面提出了批评，认为每次按键都需要多个手指的动作，可能会增加重复性劳损的风险。 补充讨论： • 评论中还涉及到了一些技术细节和历史背景的补充，例如对不同弦键盘设备的具体使用方法、技术实现和其在多语言环境下的适应性问题。 • XKCD被Animats引用作为一个幽默的补充，增加了讨论的趣味性。 争议焦点： • 主要争议点在于弦键盘的 ergonomic 可行性。KennyBlanken认为弦键盘可能导致重复性劳损，而其他如neilv和GregDavidson则强调了其在单手操作和便携性方面的优势。

Osgint – OSINT tool to find information about GitHub user

作者: CHEF-KOCH | 评分: 60 | 评论数: 8 | 发布时间: 2025-03-24 05:51
文章摘要

OSGINT是一个开源工具，用于查找GitHub用户的各类信息。其主要功能包括：通过电子邮件查找GitHub用户名，通过用户名查找关联电子邮件（但并非每次都有效），以及获取用户资料信息（如账户创建日期、公开Gists、ID、公开PGP和SSH等）。该工具通过分析公开提交记录和GPG密钥来获取电子邮件信息，并利用GitHub的用户API进行数据检索。用户可以通过命令行指定用户名或电子邮件进行查询，并可以选择以JSON格式输出结果。工具还提供了示例输出，展示了查询结果的详细信息。

评论摘要
主要讨论点：GitHub用户信息展示的实用性及潜在问题 不同观点： • zellyn: 认为展示的信息与GitHub个人资料页面的信息基本一致，除了邮箱信息外，没有提供新的内容。zellyn指出，带有其用户名的邮箱是正确的，而其他邮箱可能是其他人贡献其创建的仓库时所使用的。 • 1317: 认为该展示并没有提供任何新的信息，除了邮箱以外，其他信息都可以直接在GitHub个人资料页面上看到。 • theyknowitsxmas: 质疑该功能对除垃圾邮件发送者以外的其他人有何好处。 • ExxKA: 提到这可能会导致招聘人员重新开始通过GitHub发送垃圾邮件。 • Dotnaught: 认为这种展示方式比直接将补丁附加到提交中更麻烦。 • cpursley: 指出这种展示方式的概念类似于https://reporeach.com，旨在提供更多用户信息。 • belter: 质疑谁会使用真实姓名作为GitHub用户名，并提供了知名人物如Elon Musk和Donald Trump的GitHub用户名作为例子。 补充讨论： • 评论中涉及了对用户隐私和信息公开的关注，特别是邮箱信息的公开可能带来的垃圾邮件问题。 • 不同用户对该功能的态度各异，有的认为没有实际用途，有的则关注其可能带来的负面影响如垃圾邮件增加。 • 提到了类似功能的其他平台，如reporeach.com，说明这种信息展示方式在开发者社区中可能已有类似的应用。 • 对使用真实姓名作为GitHub用户名的合理性提出了质疑，反映了用户对隐私和身份公开的考虑。 争议焦点： • 该功能是否提供了有用的新信息，还是仅仅重复了已有的公开信息。 • 邮箱信息的公开可能导致的垃圾邮件问题及其对用户的潜在影响。

文章摘要

本文讨论了针对Linux发行版Fedora的Pagure基础设施的供应链攻击。作者Thomas Chauchefoin指出，攻击者利用了Pagure代码托管平台的漏洞，植入了恶意代码，可能影响众多依赖该平台的开发项目。攻击主要通过伪造的提交和未经授权的访问进行，威胁到软件构建过程的完整性。文章建议开发者加强安全措施，如启用双因素认证、定期审计代码变更，并使用签名验证来确保代码来源的可靠性。Fedora团队正在积极修复漏洞并提升系统安全性，以防止类似攻击再次发生。

评论摘要
主要讨论点：围绕技术配置、工具使用以及开源社区机制的讨论 不同观点： • [blueflow] 认为 Bash 在通过 sshd 启动时加载 bashrc 是不合理的，尤其是在非交互式 shell 中加载会导致像 git 和 rsync 这样的工具出错。具体问题在于，如果远程机器的 bashrc 向 stdout 写数据（如设置窗口标题），这些工具将无法正常工作。为解决此问题，需要在 bashrc 中加入特定判断以提前返回，避免触发这个“bug”。 • [superb_dev] 不同意将 Git 的 shell 设置为 `/sbin/nologin` 或 `/bin/false`，因为这样用户将无法通过 SSH 连接。他提出了一种解决方案，即将登录 shell 设置为 `git-shell`，不过他也提到这个方法在某些自定义的 Python 环境中可能不适用。 • [INTPenis] 提到了在 Fedora 贡献者系统中的实际体验，指出自我服务机制虽然允许任何人创建贡献者账户，但要求新账户必须由已有贡献者担保，这可能成为新贡献者加入的障碍。他个人曾因未能找到担保人而放弃。 • [ufo] 对 Git 要求使用 `--end-of-options` 表示不满，认为这种设计是荒谬的，增加了不必要的复杂性。 • [TZubiri] 认为选择使用红帽产品但不通过红帽官方渠道获取产品是一种冒险行为，隐含了潜在的风险。 补充讨论： • 关于 Bash 和 sshd 交互引发的问题，讨论焦点在于技术配置的合理性以及解决方法的通用性。 • 关于 Fedora 贡献者系统，争议点在于新贡献者需要担保的机制是否合理，有人认为这种机制可能阻碍新人参与。 • 关于 Git 的使用体验，讨论集中在 Git 命令行设计的复杂性以及可能的替代方案。 • 关于使用红帽产品的讨论，焦点在于通过非官方渠道获取产品的风险。

BeeFormer: CF and CBF hybrid approach for recommendation systems

作者: klaussilveira | 评分: 9 | 评论数: 0 | 发布时间: 2025-03-23 12:20
文章摘要

本文介绍了推荐系统中的**BeeFormer**方法，旨在解决冷启动问题，即新物品没有交互数据时推荐困难。传统协同过滤（CF）方法依赖交互数据，而内容过滤（CBF）方法依赖物品属性，如文本描述，但后者可能无法捕捉用户行为模式。BeeFormer通过训练语言模型，结合交互数据学习用户行为模式，并将这些知识迁移到未见过的新物品上，从而提升推荐效果。 文中提供了详细的训练步骤和代码示例，包括数据下载、预处理和模型评估。数据预处理时，仅保留评分4.0以上且至少有5次交互的用户数据。由于原始数据缺少文本描述，研究使用LLM（大规模语言模型）生成物品描述以增强模型训练。实验表明，BeeFormer在推荐性能上取得了显著提升。
