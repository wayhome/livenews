New high-quality hash measures 71GB/s on M4

作者: nicoshev11 | 评分: 100 | 评论数: 9 | 发布时间: 2025-05-14 07:45
文章摘要

Rapidhash 是一个非常快速、高质量且跨平台的哈希算法，是 wyhash 的官方 successor。它在多种系统（AMD64 和 AArch64）及编译器（gcc、clang、icx、MSVC）上表现优异，不依赖特定机器指令集。Rapidhash 在 SMHasher 和 SMHasher3 测试中表现卓越，速度超越 70GB/s，并在碰撞测试中表现出接近理想的碰撞概率。与 xxh3 相比，rapidhash 在多项性能测试中均表现出色，尤其是在小尺寸键值的哈希计算中。Rapidhash 的平均延迟和峰值吞吐量在多个硬件平台上均领先于 xxh3。所有测试和实验代码可在项目的 collisions 和 bench 文件夹中找到。

主要讨论点：不同开发者对各种哈希函数性能、使用场景及其实际效果的评价和争议 不同观点： • **jandrewrogers** 认为rapidhash在小键哈希功能上是目前最先进的选择，特别是在质量和速度上优于XXH3和GXHash等其他哈希函数。他指出，对于批量哈希，有其他更好的选择，但XXH3和GXHash在质量测试中表现不佳，因此不属于严肃的竞争者。 • **aidenn0** 提出异议，认为哈希函数在某些情况下已经足够快，没有必要为了微小的性能提升（如节省40皮秒）而更换现有方案（如从xxhash切换到其他哈希函数）。对于大键，现有的哈希函数已经比NVMe驱动器快几个数量级。 • **rurban** 反驳jandrewrogers的观点，指出rapidhash在smhasher上的表现已经不是最快的，umash和gxhash在速度和性能上都优于rapidhash。特别是gxhash的速度是rapidhash的两倍，虽然rapidhash由于体积小对哈希表更友好。 • **curiouscoding** 提供了实际使用中的经验，指出在处理10到30字符长度的随机字符串时，gxhash比xxhash更快，可能是因为gxhash能一次性处理最多32个字符，避免了分支预测失败。他认为在高速情况下，针对短字符串的分支预测设计可能比绝对吞吐量更重要。 • **realo** 以一种轻松的方式表达了对哈希函数速度的惊讶，强调了每哈希只需几纳秒的速度，比光子从屏幕到达眼睛的速度还快。 补充讨论： • **wpollock** 提出了关于rapidhash是否缓存友好的问题，暗示了对内存性能影响的关注。 • **bandrami** 表达了对讨论方向的不满，暗示他期望不同的讨论发展。 争议的焦点： • 争议的核心在于不同哈希函数在各种应用场景中的性能表现，特别是rapidhash是否真的如jandrewrogers所说的是小键哈希的最佳选择，其他开发者如rurban和curiouscoding提供了不同的实际测试结果和观点。

本文讨论了如何利用AI（特别是Google的Gemini模型）将自然语言转换为SQL查询（即文本到SQL技术），以提高开发人员和分析人员的工作效率，并让非技术用户也能直接与数据库交互。文中介绍了Google Cloud中的多种文本到SQL应用，如BigQuery Studio、SQL Editor、SQL Generation工具以及AlloyDB AI等。 尽管像Gemini 2.5这样的先进大型语言模型（LLM）能够处理复杂的SQL查询，但面对真实世界的数据库和用户问题时，仍面临挑战，包括： 1. **提供业务特定上下文**：模型需要了解数据库的模式和业务语义，但为每个数据库进行专门训练既昂贵又不实际。 2. **理解用户意图**：自然语言存在歧义，模型可能会生成不准确的查询，尤其是在处理模糊问题时。 为了应对这些挑战，需要进一步研究如何有效构建上下文、检索表格以及评估文本到SQL的质量。

Popcorn: Run Elixir in WASM

作者: clessg | 评分: 108 | 评论数: 8 | 发布时间: 2025-05-15 17:14
文章摘要

Popcorn 是一个允许在浏览器中运行 Elixir 代码的库，通过客户端 AtomVM 运行时执行编译后的 Elixir 代码。它提供了 Elixir 与 JavaScript 互操作的 API，处理序列化、通信以及保持浏览器响应。 ### 主要功能： 1. **执行环境**：通过 WebAssembly（WASM）在浏览器中运行 Elixir。 2. **API**：提供 JS 和 Elixir 之间的消息传递机制。 3. **示例**：包括 Elixir REPL、文档交互示例和生命游戏模拟。 ### 使用步骤： 1. **添加依赖**：在 `mix.exs` 中添加 `{:popcorn, "~> 0.1"}`。 2. **构建运行时**：运行 `mix popcorn.build_runtime` 生成 WASM 和 JS 库。 3. **HTML 配置**：在 HTML 文件中引入生成的 JS 文件。 4. **Elixir 入口**：定义一个永不退出的 `start/0` 函数，并通过 `Popcorn.Wasm.send_elixir_ready` 通知 JS。 ### API 详解： - **JS API**：`Popcorn.init()` 初始化，`call()` 和 `cast()` 用于发送消息到 Elixir。 - **Elixir API**：`Popcorn.Wasm.send_elixir_ready()` 通知 JS 初始化完成。 ### 注意事项： 该库仍在开发中，API 不稳定，部分功能未实现。详细限制见文档。 通过 Popcorn，开发者可以在浏览器中运行 Elixir 代码并与 JS 交互。

Chapter 2 of *Concurrency Control and Recovery in Database Systems* (1987) by Bernstein, Hadzilacos, and Goodman provides a foundational and formal treatment of serializability theory, essential for ensuring correct concurrent transaction execution in databases. The chapter systematically introduces key concepts: 1. **Histories**: A model representing the partial order of operations across transactions, focusing on dependencies. 2. **Serializable Histories**: Defined through conflict equivalence and serialization graphs; a history is serializable if its graph is acyclic. 3. **The Serializability Theorem**: Proves that a serializable history is equivalent to a serial execution if its serialization graph is acyclic. 4. **Recoverable Histories**: Introduces properties like Recoverable (RC), Avoids Cascading Aborts (ACA), and Strict (ST) to handle crashes and transaction aborts. 5. **Generalized Operations**: Extends the theory to operations beyond simple reads and writes. The chapter is precise and minimalist, focusing on scheduler-observable structures to ensure correctness, making it a cornerstone in concurrency control theory.
