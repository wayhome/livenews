文章摘要

cuTile Rust 是 NVIDIA 开发的 GPU 编程框架，让开发者用 Rust 语言编写内存安全、无数据竞争的 GPU 内核。它将 Rust 的所有权机制扩展到 GPU：可变张量在启动前被分区为互斥片段，不可变张量共享访问。通过 `#[cutile::module]` 宏将 Rust 代码 JIT 编译为 GPU 代码。性能方面，在 NVIDIA B200 上达到 7 TB/s 内存带宽（91% 峰值）和 2 PFlop/s（92% 峰值），GEMM 性能接近 cuBLAS。项目还包含 Grout 推理引擎，在 RTX 5090 上 Qwen3-4B 达到 171 tokens/s。目前处于早期开发阶段。

评论摘要
主要讨论点：cuTile Rust项目的技术特性、性能表现及其在GPU编程生态中的定位 不同观点： • **技术对比角度**（the__alchemist）：关注cuTile-rs与NVIDIA CUDA-oxide的区别，特别是在host端语法和device端kernel编写方式上的差异。提出实际工作流整合问题，涉及cudarc、burn、candle等现有Rust GPU工具链的兼容性。 • **应用前景角度**（binarybana）：看好cuTile-rs在本地LLM推理场景的潜力，强调HuggingFace Grout项目的优势——先进性能、代码库规模小（可放入上下文窗口）、单一二进制部署。认为cuTile让kernel开发更简单且性能更高。 • **技术实现细节**（melihelibol - 作者）：详细阐述核心创新——将Rust所有权模型跨越到GPU kernel编程，通过tile编程模型实现编译期数据竞争检测。强调性能表现：B200上GEMM达到峰值92%，安全抽象几乎零开销。提供了Qwen3推理的实测数据（RTX 5090上4B模型171 tokens/s）。 补充讨论：作者坦承项目处于早期阶段，存在API不成熟、部分场景性能落后cuBLAS、放弃SIMT级控制等限制。同时指出Tile IR跨NVIDIA架构可移植（sm_80+）但不跨GPU厂商。项目开放社区贡献，欢迎反馈塑造发展方向。
