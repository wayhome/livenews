文章介绍“steering”：在本地大模型推理中直接调控激活向量以改变输出风格或能力。作者以 DwarfStar 4/DeepSeek-V4-Flash 为例，说明其原理、潜力与局限：相比提示词更直接，但受限于模型访问、成本和实际收益。

评论摘要
主要讨论点：围绕“steering vectors/控制向量”在本地模型推理中改变模型行为的能力、应用场景、与提示词控制的区别，以及 DwarfStar/DeepSeek V4 Flash 的定位与实用性展开。 不同观点： • antirez 澄清：DwarfStar 的 steering 功能已能移除 DS4 的拒答；公开的只是玩具示例数据，不是能力本身。他犹豫是否公开 steering 文件，因为这会降低使用门槛。其强调运行时 steering 优于直接改 GGUF/模型权重，可按时机、场景、阈值动态施加，减少对模型能力的损伤。 • NitpickLawyer 认为文章遗漏了 steering vectors 最大用途：去拒答/“uncensoring”。早期研究显示拒答常集中在单一方向向量上，可识别并削弱；动态 steering 比发布修改版模型更灵活，能避免永久损害其他任务表现。 • kamranjon 强调更广泛意义：DwarfStar 展示了前沿实验室隐藏的“控制旋钮”，未来用户会期待模型提供这种细粒度控制，并将其纳入开发和交互流程。 • micahwhite 提供例子：用 steering 让 AI 更激进、偏向政治行动主义，说明该技术不只用于去拒答，也可改变模型立场或风格。 • bel8 区分概念：文章说 steering 只适用于本地模型，但 GitHub Copilot 也有“steer with message”。他认为那更像是在 agent 流程中插入消息，和激活向量 steering 不是一回事。 • dominotw 反驳“提示词已可精细控制”的说法：提示只能挖掘训练数据中的模式，难以克服训练和后训练带来的偏见，不能等同于真正细粒度控制。 • amelius/aswegs8 对实用性存疑：一个认为这更像深度学习研究工具而非实际产品；另一个质疑需约 192GB RAM 的模型是否还能称为“本地”。 • wolttam 纠正事实：DwarfStar 不是 llama.cpp 的精简版，而是独立项目，只是受其影响。 • anonym29 质疑 DeepSeek V4 Flash 热度：认为其更大、更低效，且幻觉率高，实际表现不如 Minimax M2.7；并举例称 M2.7 在超长上下文下仍保持连贯。 补充讨论：争议焦点主要在 steering 的开放风险、动态控制相对改模型的优势、提示词是否足够、以及“本地模型”和 DS4F 本身是否具备实际价值。
