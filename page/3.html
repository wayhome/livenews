XS: A programming language. Anywhere, anytime, by anyone

作者: yacin | 评分: 53 | 评论数: 14 | 发布时间: 2026-05-17 14:48
文章摘要

XS 是一种便携编程语言，单个 2.9MB 静态二进制集成编译器、语言服务器、调试器、格式化、lint、测试、性能分析和包管理，无运行时依赖。源码可在 Linux、macOS、Windows、WASI、iOS、Android、ESP32、树莓派等平台不变运行。支持解释器、字节码 VM、JIT、C/JS 转译和 WASM 等后端。安装脚本会校验 SHA-256。基准显示启动约 3ms，fib(30) JIT 为 31ms。

评论摘要
主要讨论点：围绕该新语言/项目是否有真实设计价值、是否为AI生成“包装”、以及其定位与技术可信度展开。 不同观点： • 强烈质疑派：多名评论认为 README、网站、文档和注释明显由 AI 生成，充满“tree walk interpreter、algebraic effects”等术语但缺少真实动机、设计取舍和目标用户说明；甚至有人称其为“AI slop”，认为没有可信作者与维护承诺。 • 技术怀疑派：指出 VM 设计几乎照搬《Crafting Interpreters》的 clox，并混入 Lua 指令编码；提交历史混乱；类型系统不一致，存在两套推断系统；effects 依赖脆弱的多次 continuation 实现；跨平台宣传应谨慎看待。 • 定位质疑派：质疑“Anywhere, anytime, by anyone”的口号，认为没有语言能同时适合所有人和所有项目；单一二进制集成编译器、调试器、linter 等虽有价值，但对很多项目并非关键。 • 文档/展示问题：有人认为网站难以看出语言真正亮点，标准库文档缺少目录；语言介绍从注释和空白讲起显得奇怪，缺少差异化说明。 • 部分认可派：也有人认为语法选择有品味，actor/nursery 等特性不错，整体覆盖了重要功能；但同时承认项目看起来很“生成式”。 • 具体批评：有人批评 `let/var/const` 设计中“const 与 let 运行时相同仅表达意图”很糟；也有人认为 2026 年仍有 GIL 是重大弱点。 补充讨论：还有人提到不要与 Moddable 的 XS JavaScript 引擎混淆；Perl XS 用户可能会对名称或扩展方式产生联想。争议焦点主要是：项目是否真实可信、AI生成内容是否掩盖了设计空洞，以及语言是否有明确受众和技术原创性。

文章摘要

Mado 是一个用 Rust 编写的高速 Markdown Linter，兼容 CommonMark 和 GitHub Flavored Markdown。它支持多数 markdownlint 规则，性能约比现有工具快 49–60 倍。可通过 Homebrew、Nix、Arch、Scoop、WinGet 或预编译二进制安装，也支持 GitHub Actions 集成。配置可使用本地或全局 `mado.toml`，项目提供测试、基准、性能分析和模糊测试等开发流程。

评论摘要
主要讨论点：围绕某个 Markdown 相关工具的性能必要性与同类工具对比展开。 不同观点： • 性能未必是关键：alfanick 认为该工具不一定需要特别快，因为现实中很少有人编写 1MB 的 Markdown 文件；即便是 1MB，也仍然是很小的数据量，因此性能优化的实际意义可能有限。 • 质疑与现有工具的差异：nikolay 提出该工具相比 rumdl 有何优势，暗示如果功能或性能没有明显改进，就需要说明其存在价值。 补充讨论：争议焦点在于：Markdown 工具是否需要强调速度，以及新工具相较已有项目（如 rumdl）是否有明确差异化或优势。
