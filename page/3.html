Show HN: JavaScript-free (X)HTML Includes

作者: Evidlo | 评分: 162 | 评论数: 21 | 发布时间: 2025-08-22 18:47
文章摘要

这篇文章介绍了一个名为xsl-website的开源项目，该项目展示了如何利用浏览器内置的XSL支持来构建网站，无需服务器端代码、静态网站生成器或JavaScript。项目包含XML文件和XSL模板，浏览器通过加载XML文件中指定的XSL模板将自定义标签渲染为HTML，实现跨页面的统一主题。项目还提供了高级示例，展示如何定义带字段的模板或嵌套使用模板。该项目主要使用XSLT（70%）和CSS（30%）语言编写。

评论摘要
主要讨论点：XSLT 和 XML 在网页开发中的使用现状、优缺点及替代方案 不同观点： • **支持 XSLT 和 XML 的观点** - tannhaeuser 认为 HTML 最初是作为 SGML 的词汇设计的，实体和宏功能本应简单且直接支持，无需依赖 JavaScript 的复杂解决方案。 - ulrischa 提出结合 PHP 和 XSLT 可以实现稳健的模板解决方案，并且 PHP 可以扩展 XSLT 的功能。 - postepowanieadm 和 msylvest 认为 XML/XHTML 在 LLM 时代仍有意义，尤其是 LLM 可以简化 XSLT 的编写。 • **反对或质疑 XSLT 的观点** - shakna 指出 Chrome 计划将 XSLT 设为可选功能，并可能从标准中移除，表明其逐渐被边缘化。 - b_e_n_t_o_n 质疑客户端 XSLT 的性能问题，如多次请求和页面渲染延迟（“Spinnergeddon”）。 - mjaniczek 认为 XSLT 虽然概念新颖，但在实际应用中并不完全实用。 • **替代方案讨论** - bawolff 提出 CSS 可以作为 XSLT 的替代方案，尤其是在显示层面，尽管功能上不如 XSLT 强大。 - xnx 提问为何 HTML Imports 未被广泛采用，暗示可能有其他技术替代 XSLT 的需求。 - em-bee 分享了使用 XSLT 构建网站的实际案例，但未明确评价其优劣。 补充讨论： - **争议焦点**：XSLT 的复杂性和实用性是否值得保留，尤其是在现代浏览器和开发环境中。 - **技术比较**：XSLT 与 CSS、PHP、服务器端渲染（SSR）等方案的对比，尤其是在性能和易用性方面。 - **未来趋势**：LLM 是否能为 XSLT 带来新的生命力，或者加速其淘汰。 - **历史回顾**：raggi 和 mgr86 提到 XSLT 在早期的浏览器支持较好，且身份转换等模式常见，但现代浏览器支持减弱。

Nitro是一个轻量级、灵活的进程监控和初始化系统，适用于Linux嵌入式、桌面、服务器、容器等场景。它通过目录中的脚本配置服务，支持可靠重启、日志链和参数化服务。主要特点包括全内存运行、高效事件驱动、无运行时内存分配、单一二进制文件等。服务通过`setup`、`run`、`finish`等脚本管理，支持日志重定向和特殊服务（如`LOG`和`SYS`）。可通过`nitroctl`工具控制系统启动、停止和重启。
