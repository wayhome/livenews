Small Town America vs. Big Box Stores

作者: spking | 评分: 24 | 评论数: 3 | 发布时间: 2025-04-09 14:20
文章摘要

文章主要讨论了美国小镇上的本地商店与大型连锁店（如Dollar General）之间的竞争。华盛顿综合商店（Washington General Store）是缅因州一家由Sean和Amy Donaghy夫妇经营的本地商店，不仅提供日常用品，还成为社区居民聚集和交流的地方。然而，一家大型Dollar General即将开业，引发了当地居民的担忧，他们害怕这会对小镇的独特性和经济生态造成破坏。 研究表明，连锁店往往会挤垮本地商家，限制新鲜食品的供应，并从本地经济中抽走财富。尽管一些本地企业如新奥尔良的Mike's Hardware通过差异化经营成功生存下来，但大多数小商家很难与连锁店竞争。大型零售商还通过政府补贴和税收优惠获得不公平的优势，进一步威胁本地经济。文章呼吁保护本地商业，让资金在社区内循环。

主要讨论点：Dollar General等大型连锁店与本地社区商店之间的竞争及其社会价值。 不同观点： • alibrarydweller认为Dollar General通过压缩价值主张到单一维度——低价，赢得了市场，但忽略了社区商店在多维度上的价值，比如赞助公园或根据社区需求精选商品。他们认为社会需要一种“无损算法”，既能高效享受连锁店的便利，又能保留本地商店的多样性价值。 • iambateman对Strong Towns理念表示支持，但反对将Dollar General视为“骗局”。他认为消费者选择Dollar General是因为其价格更低，这是市场的自然结果。他建议小型企业应通过独特价值与大企业竞争，同时可以通过政治手段争取补贴以支持本地企业，而不是简单抱怨大企业的不公平优势。 • briandear质疑“我们”是谁，认为社区应自行决定在哪里购物。如果Dollar General提供了更好的价格，消费者自然会选择它。他们指出，要求对Dollar General施加限制实际上是剥夺了低收入人群的选择权，因为这些人依赖于低价商品。 补充讨论： • 争议的焦点在于Dollar General的低价策略是否是一种“骗局”以及社区是否有权自行决定其购物选择。 • alibrarydweller强调了多维度价值和无损算法的重要性，而iambateman和briandear则更关注市场选择和消费者自主权。 • iambateman提出通过政治手段和合作组织争取对小型企业的支持，以对抗大企业的优势。 • briandear提醒注意不应将个人偏好强加于经济上处于不利地位的人群。

Man pages are great, man readers are the problem

作者: WhyNotHugo | 评分: 52 | 评论数: 28 | 发布时间: 2025-04-09 13:11
文章摘要

本文讨论了man页面的功能和当前阅读器的局限性。虽然man页面实际上支持链接和跨参考（如`.Xr`和`.Sx`宏），并且在转换为HTML时这些链接是可点击的，但常用的man页面阅读器（如`man(1)`命令结合`less(1)`）并不支持显示或跟随这些链接。此外，当前的阅读器也无法在调整终端窗口大小时重新排版文本。文章呼吁开发更好的man页面阅读器，既能支持链接功能，又能实现文本重排，从而提升用户体验。

评论摘要
主要讨论点：关于man pages格式、工具及其现代化改进的讨论 不同观点： • **blueflow**：认为man pages的编写语言（mdoc和mandb）难以掌握，文档不完整，提议在构建过程中将man pages转换为Markdown，利用Markdown工具链来简化编写过程。但也指出Markdown本身存在不统一的问题，不同工具的解析规则和功能集各异。 • **taeric**：反对将man pages转换为Markdown，认为现有的man pages具有丰富的功能，Markdown在处理链接和语义方面不如现有的解决方案，最终可能导致重复复杂化的过程，类似于从XML迁移到JSON后又试图为JSON添加命名空间。 • **tomxor**：支持使用Vim的ft-man-plugin来改善man pages的阅读体验，特别是其对链接和缩进的处理，相较于默认的less工具有显著优势。 • **jordemort**：推荐使用pinfo工具查看man pages和info页面，该工具具有类似lynx的交叉引用导航功能。 • **ksynwa**：希望man pages阅读器能够直接跳转到特定命令行参数的描述部分，目前需要通过正则表达式搜索实现。 • **jasonjmcghee**：建议使用bat工具为man pages提供语法高亮，以提高可读性。 • **amelius**：提议将man pages全部转换为HTML格式，以实现现代化。 • **tasn**：强烈支持用Markdown替代man pages，认为man pages在界面和编写体验上都不如Markdown，尤其对于习惯于现代文档格式的开发者而言。 补充讨论： • **sjmulder**：指出许多web版本的man pages排版不佳，但OpenBSD的mandoc驱动的在线man pages是个例外，具有良好的排版。 • **mplanchard和kazinator**：提到Emacs和Vim在man pages阅读和导航方面的优势，例如Vim的K命令可以直接打开光标下单词的man page，以及man page阅读器可以记住上次阅读的位置。 • **NoSalt**：认为man pages需要更多示例，以帮助用户更好地理解命令的使用方法。 • **pjmlp**：指出有许多X Windows的man pages阅读器，但未被提及，可能是个问题。 • **kccqzy**：介绍如何在macOS和Linux上将man pages转换为PDF，利用其支持链接和良好排版的特性。 争议焦点： • 是否应将man pages转换为Markdown或HTML等现代格式，以简化编写和阅读体验（blueflow、taeric、tasn等不同观点）。 • Markdown是否具备足够的统一性和功能性来替代man pages格式（blueflow和tasn的不同看法）。

Dockerfmt: A Dockerfile Formatter

作者: spicypete | 评分: 124 | 评论数: 16 | 发布时间: 2025-04-09 01:21
文章摘要

`dockerfmt` 是一个现代化的 Dockerfile 格式化工具和解析器，基于 BuildKit 内部解析器构建。它提供命令行工具，用于检查和格式化 Dockerfile，支持设置缩进、添加尾部新行等。目前不支持 RUN 命令中的分号和组命令，也不处理长 JSON 命令的换行。该工具使用 `mvdan/sh` 格式化 Shell 命令，并支持简单的 heredocs 和内联注释。JS 绑定可在 `js` 目录中找到。该项目遵循 MIT 许可，用户可以通过 GitHub 贡献代码。

评论摘要
主要讨论点：Dockerfile 的格式化、工具支持、多阶段构建及替代工具 不同观点： • [grandempire] 认为一个真正的软件工程项目应该有大量的配置文件（dot files）来支持格式化、包管理、代码检查和持续集成，并质疑谁来格式化这些配置文件，暗示项目复杂度高且维护困难。 • [jensenbox] 对源代码中没有 Dockerfile 表示失望，认为 Dockerfile 的缺失使得试用项目变得困难，尤其希望通过 Docker 容器运行项目。 • [urxvtcd] 和 [nikeee] 支持在多阶段 Dockerfile 中通过缩进使结构更清晰，认为不这样做就像其他语言中不缩进函数体一样不合理。 • [travisgriggs] 以幽默的方式提出 Dockerfile 格式化工具的递归问题，认为随着选项增多，最终可能需要一个“格式化格式化工具”的工具。 • [xyst] 认为 Dockerfile 格式化工具应由项目自身提供，而不是第三方工具，并举例 Go 和 Rust 内置格式化工具，减少了关于“最佳实践”的无谓讨论。 • [QuarterDuplex] 提出是否可以分层组合 Dockerfile，区别于 Docker Compose，希望找到一种优雅的方式来组合不同 Docker 镜像的层次。 补充讨论： • [yjftsjthsd-h] 对 RUN 命令支持 `&&` 但不支持 `;` 提出疑问，认为这两种写法在逻辑上相似，不应该有区别。 • [mdaniel] 提到一个被删除的评论，暗示该产品缺乏 QA，并表达了对特定格式化工具的不满，认为自己的写法更符合习惯。 • [righthand] 提到使用 YAML LSP（语言服务器协议）来处理 Dockerfile 格式，指出其通过 schema.org 查找 Containerfile 格式。 • [PantaloonFlames] 提出一个侧重点，询问为什么继续使用 Dockerfile 而不是 Podman，暗示 Podman 可能是更好的替代方案。 争议焦点： • Dockerfile 是否应该有内置的格式化工具，还是依赖第三方工具。 • 多阶段 Dockerfile 的缩进和结构清晰性是否重要，以及是否应成为规范。 • RUN 命令中 `&&` 和 `;` 使用的区别是否合理。 • 是否有比 Dockerfile 更优的工具如 Podman。
