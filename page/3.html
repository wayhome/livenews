Run your GitHub Actions locally

作者: flashblaze | 评分: 150 | 评论数: 28 | 发布时间: 2025-05-16 08:55
文章摘要

`nektos/act` 是一个允许开发者在本地运行 GitHub Actions 的工具。它通过模拟 GitHub 提供的环境变量和文件系统，让用户无需每次修改工作流文件后都进行 commit 和 push，从而加快反馈速度。此外，它还可以替代 `make` 作为本地任务运行器，直接使用 `.github/workflows/` 中的定义来执行任务。通过 Docker API，它拉取或构建所需镜像并运行相应的动作。该工具还提供了 VS Code 扩展，方便在编辑器中直接管理和运行工作流。项目使用 MIT 许可，拥有大量贡献者和广泛的使用者。详细使用指南和贡献说明可在项目文档中查看。

文章摘要

文章介绍了名为Ann的社交注释工具，它基于ActivityPub协议，支持去中心化的网页注释功能。用户可以通过Ann存储、发送和接收注释，类似于评论、推荐或点赞。与传统社交媒体不同，Ann本身只是一个服务器，需结合前端应用使用。应用场景包括：在Gemini浏览器或博客中添加评论区、科研部门内部共享论文、获取关注者的文章推荐、通过浏览器插件查看和添加注释、用于AI训练的注释网络、以及作为插件集成到LibreOffice、Logseq等工具中。Ann的目标是让各种应用轻松集成社交功能，避免对中心化服务和JavaScript、追踪器的依赖，同时尊重用户隐私和选择。

Kilo: A text editor in less than 1000 LOC with syntax highlight and search

作者: klaussilveira | 评分: 156 | 评论数: 9 | 发布时间: 2025-05-19 20:28
文章摘要

Kilo是一个小型文本编辑器，代码不到1000行，具有语法高亮和搜索功能。它不依赖任何库，甚至不使用curses库，而是利用标准的VT100终端转义序列。基本用法包括打开文件、保存（CTRL-S）、退出（CTRL-Q）和查找字符串（CTRL-F）。项目处于alpha阶段，代码借鉴了作者其他的项目（load81和linenoise）。Kilo鼓励开发者作为起点，创建更先进的编辑器或命令行界面。该项目由Salvatore Sanfilippo（antirez）编写，并根据BSD 2条款许可证发布。

评论摘要
主要讨论点：围绕文本编辑器的实现和终端使用体验的讨论 不同观点： • **akkartik** 认为使用 Kilo 文本编辑器是让他放弃终端编程的最后一根稻草。他现在更喜欢在一个简单的画布上进行编程，并分享了他自己开发的轻量级文本编辑器（1200行代码，支持比例字体、自动换行、剪贴板、无限撤销等功能）。他认为这样的工具足以编辑如《Moby Dick》这样的复杂文本。 • **lor_louis** 认为 Kilo 作为一个周末项目很有趣，但并不适合作为复杂文本编辑器的基础，因为其核心数据结构（行数组）在处理更复杂的操作时不够高效。他分享了自己构建的文本编辑器，并建议如果重新开始会使用"piece table"数据结构（引用了VS Code的相关博客文章）。 • **thomasdziedzic** 提到他刚完成一个类似 Kilo 的文本编辑器教程，并推荐了这个教程，认为它非常出色，是一个很好的学习资源。 • **lbj** 对其他人急于脱离终端编程表示不解，并质疑为什么评论者们如此渴望摆脱终端。 • **90s_dev** 认为阅读 Kilo 这样的代码是一种学习经历，可以帮助理解C语言、文本编辑器、VT代码、语法高亮等技术，以及在去除各种便利功能、边界情况和错误处理后，实现任何功能所需的基础代码量。 • **nulld3v** 提到 Kilo 项目启发了一个类似的 Rust 项目，并指出该 Rust 项目在处理 Unicode 时使用了一些额外的辅助工具（如unicode-width）来确定字符的显示宽度。 • **revskill** 提出一个简单的问题，文本编辑器是否就是网格操作。 • **jonstewart** 简短地提到 ed 是标准文本编辑器，暗示其在文本编辑器历史中的重要地位。 • **fuzztester** 以幽默的方式评论了 Kilo 的名称和其实际轻量特性之间的反差。 补充讨论： - Kilo 作为一个学习项目和轻量级文本编辑器的实现，引发了对文本编辑器核心数据结构和实现细节的深入讨论。 - 争议的焦点之一是 Kilo 的核心数据结构是否适合复杂操作，以及是否有更好的选择（如 piece table）。 - 不同用户对终端编程和现代图形界面编程的偏好不同，反映了技术社区中对不同编程环境和工具的多元看法。

Linguists Find Proof of Sweeping Language Pattern Once Deemed a 'Hoax'

作者: bryanrasmussen | 评分: 9 | 评论数: 4 | 发布时间: 2025-05-19 06:23
文章摘要

语言学家发现，因纽特语言确实如1884年人类学家弗朗茨·博厄斯所观察到的，有四个描述雪的词，这表明语言与自然环境存在联系。然而，这一观察被夸大成神话，1984年《纽约时报》甚至声称因纽特人有100个雪的同义词。1991年，语言学家杰弗里·普勒姆称这些说法为“骗局”。但近期一项大规模计算分析证实了因纽特语言对雪的重视，并发现了其他语言类似的现象，如萨摩亚语对熔岩、苏格兰语对燕麦片的详细描述。研究分析了超过600种语言的双语词典，寻找“词汇精细化”现象，即语言对某个核心概念有多个词描述。结果显示，语言词汇的丰富程度反映了该文化的重要概念和价值观。该研究支持了语言相对论的观点，即语言能微妙地影响而非决定我们的思维方式。

评论摘要
主要讨论点：语言中的词汇差异及其影响，包括翻译、文化表达以及实际生活经验中的语言运用。 不同观点： • [pjc50] 认为，语言中的词汇向量嵌入与此类似，文章提出的关于“用一个词描述某事物与用一组共同理解的词描述某事物之间的区别”是合理的。每个翻译都会丢失一些信息，但同时可能带来不同的内涵。译者和本地化人员常常争论：我们是寻找最接近原文的词，还是寻找最能匹配原意的感觉和意义。 • [FrankWilhoit] 提出，即使在密切相关的语言之间也存在许多差异。他认为应考虑这些差异对公共政策的影响，尤其是在边界和移民问题上。 • [more_corn] 通过具体例子说明，虽然某些语言可能没有单一的词汇来描述某些事物（如雪的类型），但可以通过语言详细描述这些差异。他举例说，不同类型的雪对人们活动（如铲雪、驾驶、滑雪）有不同影响，因此用语言描述这些差异是合理且必要的。 补充讨论： • [jnord] 提供了一个链接，但该链接未包含实质性观点或讨论，因此不影响主要讨论点。 争议的焦点： • 主要争议在于翻译中应以词义的精确匹配为主，还是以感觉和意图的匹配为主。这涉及到语言表达的灵活性与文化内涵的传递问题。 • 另一个讨论点是语言差异对公共政策（如移民政策）的潜在影响，这涉及语言与社会政策的关系。
