What is the average length of a queue of cars? (2023)

作者: alexmolas | 评分: 19 | 评论数: 3 | 发布时间: 2025-08-04 04:55
文章摘要

文章讨论了在山路上车辆排队长度的问题。作者最初通过概率推导，假设车辆速度独立同分布，得出每队列的平均车辆数为2。然而，经过模拟实验后，发现实际结果与此不符。模拟显示，平均队列长度约为10.69，且存在极大变异。作者最初的推导基于几何分布，但未考虑到实际情况中的复杂因素，因此得出了错误的结论。模拟结果更符合实际观察，表明队列长度分布广泛，半数队列长度不超过2，但也有长度极大的情况。

评论摘要
主要讨论点：对博客文章中关于车辆排队问题的结论和假设的分析 不同观点： • dmurray认为文章结论回答了一个错误的问题。他指出，文章讨论的是车辆排队的数量问题，而不是问题的本质。他解释，第一辆车必然形成一个队列，第二辆车只有比第一辆慢时才开始新队列（概率1/2），第三辆车则需要是目前最慢的才开始新队列（概率1/3），以此类推。总和为1 + 1/2 + 1/3...，这个和是文章末尾的公式，但存在一个差一错误。平均队列长度应为车辆数除以这个调和数列和，该和也趋向于无穷大。 • alexchamberlain对文章中的假设提出质疑，幽默地指出作者忘记了假设道路是无弹性且无质量的。这暗示了对模型过度简化的不满，认为忽略了一些实际物理因素。 补充讨论： • dmurray的评论重点在于数学模型的正确性及其在实际问题中的应用，指出公式推导中的潜在错误，并提出修正建议。 • alexchamberlain的评论则侧重于对模型假设的批评，强调在建立数学模型时考虑物理现实的重要性。 这两种观点共同揭示了对博客文章中数学模型和假设的关注，指出了理论推导与实际应用之间的差距。争议的焦点在于数学模型的适用性和假设的合理性。

Comptime.ts: compile-time expressions for TypeScript

作者: excalo | 评分: 128 | 评论数: 8 | 发布时间: 2025-08-03 19:11
文章摘要

**comptime.ts** 是一个简单的 TypeScript 编译器工具，允许在编译时评估标记为 `comptime` 的表达式，从而将运行时计算移至编译时，优化代码性能。其灵感来源于 Bun macros 和 Zig comptime。使用时需确保标记的表达式在编译时安全评估，因为该工具不提供隔离。`comptime` 导入仅限于项目文件，但可以从 `node_modules` 导入。 ### 示例 1. **简单求和函数**：编译时计算结果并替换。 2. **零运行时 CSS 库**：将 `emotion` CSS 转换为编译时计算的类名。 3. **常量计算**：如时间单位在编译时转换为具体数值。 ### 安装与使用 - 安装：通过 `bun`, `pnpm` 或 `npm` 安装。 - 使用：支持 Vite 和 Bun 打包工具，通过插件配置启用。 ### 特性 - 支持函数调用和模板字符串等复杂表达式。 - 结果必须可序列化为 JSON。 - 提供 CLI 和 API 使用方式。 - 支持强制编译时评估和 Promise 解析。 ### 注意事项 - `comptime` 标记的 import 语句在输出中会被移除。 - 编译时计算可大幅优化性能，但需谨慎处理副作用和依赖管理。

评论摘要
主要讨论点：Zig语言的`comptime`特性及其在JavaScript中的可能应用 不同观点： • [anonymoushn] 认为该特性无法替代JavaScript中C预处理器宏的当前用法，特别是在处理条件编译时（如通过"if (comptime foo)"）。虽然Zig的`comptime`特性能够满足这种需求，但当前的实现不行。 • [apatheticonion] 希望在JavaScript中拥有Rust风格的宏和过程宏（proc macros），例如通过宏简化JSX语法，或者通过WASM使Rust可以直接编写Web应用。 • [spankalee] 指出使用`import {sum} from './sum.js' with {type: 'comptime'}`是一种对`type`导入属性的不当使用，因为`type`属性应该对应模块的MIME类型，如"json"和"css"，建议选择其他导入属性。 • [stevage] 认为该特性可用于预编译markdown，显示出对预处理任务的潜在用途。 • [mdarens] 对Zig的`comptime`特性表示兴奋，但质疑其是否适用于类型本身，如Zig中的`comptime`泛型，并提到这在TypeScript中解决“过大联合类型”问题的潜力。 • [Thom2000] 对`import-with`语法表示陌生，并指出相关文档稀缺，怀疑这是一种语法扩展。 • [revskill] 表示无需框架即可实现相关功能，显示出对轻量级解决方案的偏好。 • [shortrounddev2] 希望该特性可以返回命名函数，提出了对功能进一步增强的期望。 补充讨论： • 关于`import {sum} from './sum.js' with {type: 'comptime'}`的语法是否合适的讨论，特别是对`type`属性的使用是否恰当。 • 对Zig的`comptime`特性在JavaScript中替代C预处理器宏的可行性存在争议。 • 对该特性如何应用在不同场景中（如预编译markdown、解决TypeScript类型问题）提出了具体例子和应用场景。 • 部分评论者对该语法的文档和实现细节表示关注，显示出对该特性实际应用中的不确定性。

Breaking the sorting barrier for directed single-source shortest paths

作者: baruchel | 评分: 132 | 评论数: 8 | 发布时间: 2025-08-06 14:43
文章摘要

文章介绍了一种突破经典算法速度限制的新方法，用于解决计算机科学中的最短路径问题。传统的最短路径算法，如1956年Edsger Dijkstra提出的算法，通过逐步扩展已探索区域来找到从起点到其他所有节点的最短路径。然而，由于最终结果需要排序，这种方法受限于“排序障碍”，无法进一步提升速度。 过去的研究在特定条件下打破了这一障碍，但对任意权重的图仍然无解。直到2021年，清华大学的段然提出了一种新算法，成功打破了排序障碍。该算法的关键在于每一步选择下一个探索节点的策略，避免了排序过程，从而提高了速度。这一成果被视为计算机科学领域的重大突破。

评论摘要
主要讨论点：新算法复杂度及其在图算法中的应用 不同观点： • [o11c] 认为该算法在高度密集图中的表现会更复杂，尤其是当边的数量 `m` 远大于节点数量 `n` 时。他还指出，对于某些图类型（如开放网格图），Dijkstra算法中的前线节点数量是有限的（如`sqrt(n)`），并且提到非基于比较的排序方法（如桶排序）可能在这种算法中更有效。 • [karussell] 关注该算法在社区中的传播，指出这个算法经过多次提交才引起更广泛的关注，带有一定的幽默感。 • [polytely] 对该算法的发现过程表示赞叹，认为这种算法虽然看起来可能在游戏开发中偶然发现，但实际上其发现过程非常了不起。 • [ljlolel] 提到其算法教授Tarjan，并指出Tarjan发明了许多算法，暗示对新算法的创造性持保留态度。 • [aDyslecticCrow] 觉得文章过于冗长且细节不足，期待论文中更详细的描述，并关心新算法如何保证Dijkstra所能提供的“全局最小值”，担心前线节点的聚集可能会导致遗漏某些解。 • [flafla2] 对新算法的复杂度O(m log^2/3 n)表示赞叹，认为这是一个巨大的成就。 • [ape4] 认为新算法比Dijkstra算法复杂得多，但这是算法发展的自然趋势。 • [crawfordcomeaux] 提出将该算法与随机性结合使用，以进一步加快算法的可能性。 补充讨论： • 不同用户对算法复杂度的关注点不同，有的关注数学和复杂度分析（如[o11c], [flafla2]），有的则关心算法的实际应用和潜在改进（如[crawfordcomeaux], [aDyslecticCrow]）。 • 对新算法的发现和传播也有一定的讨论，[karussell]和[polytely]对此表现出一定的兴趣和感慨。 • 争议焦点在于新算法是否能在所有情况下替代Dijkstra，尤其是关于“全局最小值”的保证和前线节点处理的潜在问题([aDyslecticCrow])。

Zig Error Patterns

作者: Bogdanp | 评分: 97 | 评论数: 9 | 发布时间: 2025-08-06 15:03
文章摘要

本文介绍了在使用Zig编写带单元测试的代码时，作者改进打印调试和结合调试器的几种模式。 1. **改进的打印调试**：通过使用Zig测试中的`errdefer`，可以在测试失败时才打印相关信息，避免了大量无用输出，并提供准确的错误上下文。 2. **在调试器中运行测试**：直接使用调试器如`gdb`调试测试代码时，由于测试运行器会优雅地处理错误，无法自动触发断点。手动添加`@breakpoint()`调用可以解决此问题，但会造成代码冗余和需要猜测错误位置。 3. **结合技巧**：在测试中使用`errdefer`和`@breakpoint()`，在错误发生时自动触发断点，并提供调试信息。但这种方法会导致测试摘要只显示整个步骤失败，而不是具体错误。 4. **条件编译**：利用Zig构建系统的编译时选项，通过添加布尔选项`debugger`，控制是否在测试中调用`@breakpoint()`。这样可以在需要时启用调试断点，而不影响正常测试行为。 通过这些方法，可以在Zig测试中更有效地使用打印调试和调试器，提高调试效率。

文章摘要

FDA批准了一种突破性的眼药水——VIZZ，用于改善老花眼（ presbyopia ）导致的近视力模糊，无需眼镜。这种由LENZ公司开发的药水含有阿西克利定（aceclidine），每天使用一次，可在不影响远视力的情况下，提供长达10小时的清晰近视力。与早期可能导致眉毛沉重或其他副作用的眼药水不同，VIZZ通过缩小瞳孔产生“针孔效应”来改善视力，且不显著刺激眼部聚焦肌肉。该批准基于多项临床试验数据，显示其安全有效，预计2025年第四季度广泛上市。这一创新为数百万受老花眼困扰的成年人提供了新的治疗选择。
