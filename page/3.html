Usbliter8: an A12/A13 SecureROM Exploit

作者: givinguflac | 评分: 124 | 评论数: 10 | 发布时间: 2026-06-18 14:23
文章摘要

这篇文章介绍了团队发现并利用的一种新型 iPhone BootROM 漏洞。核心问题在于 USB 控制器的 DMA 处理缺陷：Setup 包缓冲区重置与地址递增逻辑不一致，导致可控的越界写。结合固件配置失误，研究者可破坏 A12、A13 等设备的启动链并取得控制权。文章还指出，此类 BootROM 漏洞因存在于不可修改代码中，最有效的缓解方式是更换新硬件。

评论摘要
主要讨论点：苹果A11芯片的新型硬件级漏洞（usbliter8），这是一个无法修补的BootROM漏洞，影响iPhone XR/XS/11等设备。 不同观点： • **安全影响有限派**（ndiddy）：虽然是硬件漏洞，但由于BPR（Boot Process Register）机制的限制，攻击者无法在有密码的设备上直接获取完整数据访问权限，仍需配合其他漏洞才能完全破解 • **越狱爱好者兴奋派**（nfriedly, thenthenthen）：这是重大突破，为iOS 18及更新版本的越狱带来希望，能重现过去越狱的辉煌（自定义功能、加速动画、运行服务器等） • **技术分析派**（NooneAtAll3, edelbitter）：质疑漏洞的可利用性，认为软件层面可能通过实时检测USB DMA损坏来防御；疑惑为何DMA直接访问栈内存 补充讨论： 漏洞根源在DesignWare USB控制器硬件本身的环形缓冲区实现缺陷：接收第四个Setup包时指针重置机制存在问题，导致12字节步长的缓冲区下溢。djfergus和raffael_de强调这是无法通过软件更新修复的硬件级漏洞，影响范围广泛但关注度不足。

The worthlessness of Vitamin D is mildly exaggerated

文章摘要

这篇文章讨论维生素D的健康效应。作者指出，虽然早期研究显示维生素D与多种健康指标相关，但随机对照试验未能证实补充剂的神奇效果，导致许多专家认为维生素D补充无用。然而作者认为怀疑论者矫枉过正：经典理论认为维生素D主要用于调节钙吸收和骨骼健康，只有血液浓度低于25 nmol/L（仅2%人群）才需要补充。但历史上维生素D与癌症等疾病存在相关性。作者倾向于认为，对于维生素D水平偏低的人群，补充可能仍有益处，尽管证据有限但值得考虑。

评论摘要
主要讨论点：维生素D补充剂的实际效果及其研究方法的局限性 不同观点： • **补充剂效果有限派**：文章作者及支持者认为维生素D的实际效果被夸大，仅对严重缺乏者有明显改善。高剂量补充可能有害，现在甚至出现维生素D过量的情况。鱼油等也经历了类似的"炒作-证伪"循环 • **研究方法存在问题派**：多位评论者指出现有研究设计有缺陷，包括：采样偏差（冬季北方地区数据缺失）、剂量建议基于错误数学计算、未测量血液水平变化、缺乏D3+K2联合研究等 • **阳光vs口服补充派**：认为自然日晒产生的维生素D效果优于口服补充（降低30%全因死亡率），可能与皮肤产生的NO等其他因素有关，而非单纯维生素D作用 • **个体差异重要派**：强调需要根据血液检测结果动态调整剂量。有评论者服用2000IU多年仍不达标，需增至5000IU。TARGET-D试验通过动态调整剂量（维持40-80 ng/mL）显示心脏病风险降低52% 补充讨论：维生素D本质上可能更接近激素而非维生素（类固醇结构）；现代饮食已解决多数营养缺乏症，过度补充维生素更像"投机爱好"而非必需

F* file system – file search that reads SSD directly bypassing OS kernel

作者: neogoose | 评分: 87 | 评论数: 12 | 发布时间: 2026-06-21 20:44
文章摘要

FFS（F* File System）是一个用C语言编写的命令行文件搜索工具，约1500行代码。它的核心特点是绕过操作系统内核，直接读取磁盘原始数据进行搜索。 **主要特性：** - 直接读取磁盘块设备，跳过VFS缓冲层 - 支持Ext4、Btrfs和APFS文件系统 - 可搜索未挂载的卷（如.dmg、.iso文件） - 利用OpenMP实现多核并行处理 **性能表现：** 文件数量越多，相比ripgrep优势越明显。在325万文件的测试中，FFS用时36秒，而ripgrep需要75秒。 **局限性：** macOS主磁盘需禁用SIP保护、可能遗漏最近写入的文件、仅支持已实现的文件系统。本质上这是一个概念验证项目，展示直接磁盘访问可以超越内核VFS的性能开销。

评论摘要
主要讨论点：一个直接读取块设备的文件搜索工具项目，声称"绕过操作系统"实现快速搜索 不同观点： • **技术准确性质疑**：多位评论者（watusername、Retr0id）指出标题误导，该项目读取 /dev 设备节点仍需经过内核，并非真正"绕过OS"。watusername建议集成SPDK才算真正绕过内核 • **性能怀疑**：self_awareness质疑实际性能，认为绕过内核缓存反而可能更慢，正常文件系统利用缓存甚至不需要触碰磁盘 • **权限问题**：neogoose承认需要sudo权限是最大缺陷，使其"几乎最无用"；porridgeraisin提供了详细的setfacl解决方案，通过ACL授权避免每次都用sudo • **适用范围争议**：kasabali质疑"只支持SSD"的说法，认为读取块设备的方式对HDD、U盘等也应适用 • **其他技术观点**：amelius质疑能否确保SSD控制器的flush真实性；noufalibrahim将其定义为用户态文件系统实现；drewg123遗憾不支持BSD FFS 补充讨论：项目支持ext4/btrfs/apfs、多线程、压缩、嵌套卷和离线卷搜索等特性获得认可，但标题夸大、需要特权、实际性能存疑是主要批评点
