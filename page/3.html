Gossamer: a Rust-flavoured language with real goroutines and pause-free memory

作者: mwheeler | 评分: 68 | 评论数: 15 | 发布时间: 2026-06-26 18:32
文章摘要

Gossamer 是一门新编程语言，主要特点如下： **语法与数据流**：支持前向管道操作符（`|>`），默认不可变，代码从上到下线性流动，逻辑清晰直观。 **内存管理**：采用确定性引用计数和 `arena{}` 区域内存，无需 GC 停顿，也不需要 Rust 的借用检查器和生命周期标注。 **并发模型**：基于 M:N 调度器的真正协程（goroutine），无需 `async/await`，没有函数着色问题，阻塞调用只挂起协程而非线程。 **运行与发布**：提供字节码虚拟机和 REPL 供快速开发，也可通过 LLVM 编译为单一无依赖的原生二进制文件。VM 还可编译为 WebAssembly 在浏览器中运行。 **类型系统**：支持 `Result`/`Option`/`?`、穷举 `match`、trait、泛型，无 `null`，对熟悉 Rust、Go 或 F# 的开发者友好。 **标准库**：内置 HTTP、JSON、加密、SQL、压缩等模块，并支持调用 Rust 代码扩展。

评论摘要
主要讨论点：Gossamer 语言是否真正适合作为"系统编程语言"，以及其设计选择的合理性 不同观点： • **质疑系统编程定位**（reocha, Zak）：禁用 unsafe、无宏系统、无移动语义且使用引用计数，这些限制使其不适合低级编程。编译器用 Rust 而非自举也说明问题。 • **并发模型设计缺陷**（Jtsummers）：同时提供 `go` 和 `spawn` 令人困惑。`go` 继承了 Go 语言的问题（无法 join 或取消），而 `spawn` 已经能解决这些问题，为何还要保留 `go`？ • **内存管理问题**（quotemstr）：使用引用计数+循环收集器会导致性能问题（如释放大型图结构时的停顿），忽视了现代 GC 研究成果。现有的无停顿 GC（如 ZGC）才是更好选择。 • **谨慎乐观**（jeremyjh）：这正是理想的语言交集——Rust 的类型系统但无需手动内存管理、Go 的并发但有现代类型、Kotlin 无 JVM 包袱。但担心生态系统和可信度问题，AI 时代的新语言很难建立社区。 • **技术细节质疑**（pantsforbirds, lstodd）：代码示例不等价（Python 用 set 去重，Gossamer 没有）；M:N 调度并非新技术，2000年代就很常见。 补充讨论：多人怀疑这是"vibe coded"项目（IshKebab 提到仅2个月历史），精美网站反而成为负面信号（throwrioawfo）。有人推荐类似项目 Lis 和 Swift 作为替代方案。
