Value Numbering

作者: surprisetalk | 评分: 20 | 评论数: 0 | 发布时间: 2026-06-08 12:45
文章摘要

这篇文章介绍了编译器优化技术中的**值编号(Value Numbering)**。 文章首先解释了SSA(静态单赋值)形式如何为每个表达式分配唯一名称。在此基础上,值编号技术通过识别在编译时已知会产生相同运行时值的指令,来消除公共子表达式。 核心实现方法是**哈希一致性(Hash-consing)**:为每条指令计算哈希值,哈希相同且内容相等的指令被视为等价,可以复用结果。文章以Maxine VM为例展示了二元操作的值编号实现。 文章还讨论了**纯操作vs非纯操作**的区别:纯操作不依赖外部状态可以安全优化,而像数组加载、printf等非纯操作需要特殊处理。最后引入了局部值编号(LVN)的概念,用于优化基本块内的直线代码。

Grit: Rewriting Git in Rust with agents

作者: cbrewster | 评分: 71 | 评论数: 20 | 发布时间: 2026-06-09 19:58
文章摘要

作者使用 AI agents 将 Git 用 Rust 重写，创建了名为 Grit 的项目。Grit 是基于库的、内存安全的 Rust 实现，通过了 99% 以上的 Git 测试套件（超过 42,000 个测试）。 与 C Git 不同，Grit 设计为可重入、可链接的核心库，而非依赖 fork/exec 的命令链。这使得它能够嵌入到 GitButler、Jujutsu 等工具中，解决网络功能不完整的问题。未来还可能构建 WASM 版本，在边缘函数中运行完整的 Git 命令。 目前 Grit 仍处于早期阶段，存在性能问题且未经实际使用测试，但为构建现代化的 Git 工具链提供了有前景的起点。

评论摘要
主要讨论点：关于用AI将Git用Rust重写的项目引发的争议，核心焦点集中在许可证问题、实用性质疑和AI辅助开发的意义。 不同观点： • **许可证争议方**：强烈质疑项目将GPL许可改为MIT的决定。认为即使是LLM生成的代码，基于GPL项目的完整测试套件开发仍应视为衍生作品，更改许可证是对原作者的不尊重，破坏了开源信任。这来自GitHub联合创始人让问题更严重。 • **实用性质疑方**：认为Git已经足够稳定可靠，10多年来从未出现内存溢出等问题，即使20人以上团队也很少碰到Git限制。质疑Rust重写的必要性，认为这更像是炫技而非解决实际问题。 • **AI开发乐观派**：认为AI降低了重新实现的成本，原本需要数年的项目现在几个月甚至几周就能完成。重新实现易于测试，商业护城河因实现难度而消失。有开发者分享了用类似方法重写nginx、Redis等项目的经验。 • **哲学分歧方**：反对放弃Git的Unix哲学（简单命令链接），认为Unix哲学在当前时代仍然重要，是特性而非缺陷。 补充讨论：有人提到已存在的gitoxide项目进展良好；二进制文件体积问题（31MB vs 原版4.7MB）；以及对项目长期维护策略和社区贡献模式的疑问。

Exif Smuggling (2025)

作者: rolph | 评分: 78 | 评论数: 9 | 发布时间: 2026-06-09 21:06
文章摘要

这是一个名为"Exif Smuggling"的概念验证攻击项目。该技术将可执行payload隐藏在JPG图片的Exif数据中,利用浏览器的图片缓存机制被动下载恶意代码。攻击者无需发起网络请求即可从浏览器缓存中提取payload。项目包含将PowerShell加载器转换为ClickFix命令的工具,以及将DLL文件嵌入JPG图片的脚本。这是Cache Smuggling攻击的演进版本,可用于钓鱼攻击场景。

评论摘要
主要讨论点：通过图片EXIF数据隐藏和执行恶意代码的技术及其影响 不同观点： • **技术创新角度**（BoppreH）：这是一种高明的攻击方式，通过浏览器缓存读取嵌入图片中的载荷，避免直接包含恶意代码或网络调用，实现类似C&C服务器的可变载荷功能，比简单混淆更高级 • **技术多样性**（Grom_PE）：EXIF并非唯一方法，PNG额外块、JFIF标记或文件末尾追加数据都可行；更有趣的是研究能抵抗数据剥离和重编码的方法，将图片数据流本身变成多语言文件 • **历史案例**（_def, ale42）：类似技术早已存在——多年前有人利用只检查MIME类型的图片托管服务上传image.php文件执行EXIF中的PHP代码；恶意广告商也曾用类似隐写术技术隐藏恶意代码 • **实际应用**（mkoryak）：开发者分享了将网站代码隐藏在logo图片alpha通道中的实践案例 • **安全与便利性矛盾**（porphyra）：由于此类安全隐患，现在几乎所有平台都剥离EXIF数据，导致无法查看照片的相机、镜头和拍摄参数等有用信息 • **技术分类质疑**（motohagiography）：询问这是否属于常规隐写编码/打包工具范畴，还是具备自执行能力；认为这可能只是用于绕过基于签名检测的工具 补充讨论：存在对原始来源链接的疑问（Omni5cience指出链接指向无提交的随机fork）

The Evolution of 'More Like This'

作者: snikolaev | 评分: 8 | 评论数: 0 | 发布时间: 2026-06-10 03:16
文章摘要

这篇文章讨论了"More Like This"(MLT)搜索功能的演变。传统MLT基于词汇匹配，通过分析文档中的重要词汇来查找相似文档，适用于错误代码、SKU等精确匹配场景。现代方法则使用embedding向量表示文档，通过比较向量相似度来查找语义相近的内容，即使用词不同也能找到相关文档。词汇方法在精确匹配时表现优秀且成本低，而embedding方法更擅长捕捉语义相似性，能跨越不同表述方式。文章介绍了KNN、ANN等相关技术术语，以及混合搜索和重排序等现代搜索优化方法。
