文章摘要

Stalwart宣布全面支持JMAP协议家族，成为首个完整实现JMAP日历、联系人、文件存储和共享功能的服务器。这套基于JSON的新协议取代了传统的WebDAV、CalDAV等技术，解决了XML格式冗长复杂、iCalendar/vCard标准陈旧等问题。JMAP及其配套的JSCalendar、JSContact提供了更简洁高效的JSON数据模型，统一了邮件、日历等协作功能的实现方式。该项目获得了NLNet的资金支持，目前已完成核心功能开发，正朝着1.0稳定版迈进。多个客户端项目已开始适配这些新协议，预计将推动协作软件的创新发展。

这篇文章简明介绍了SSA（静态单赋值）形式在编译器优化中的重要性。SSA是一种中间表示（IR），通过确保每个变量只被赋值一次来简化程序分析和优化。文章解释了SSA如何将带有状态变化的命令式代码转换为易于分析的组合逻辑电路，从而帮助编译器高效地进行优化，例如常量折叠和消除无用代码。SSA广泛应用于各种编译器（如LLVM、GCC等），因其简化数据流分析和优化过程的优势而成为现代编译器设计的标准方法。

评论摘要
主要讨论点：[SSA（静态单赋值）的定义、用途、优缺点及其在编译器和编程中的意义] 不同观点： • **SSA的定义与介绍** - [rdtsc]认为文章应在开头明确定义SSA，以便吸引不熟悉的读者。 - [ivanjermakov]直接给出了SSA的全称（静态单赋值）。 • **SSA的实用性** - [pubby]质疑SSA的价值，认为其并非唯一能实现图表示的IR，且转换成本高，但最终承认SSA作为单一表示的统一性是其优势。 - [zachixer]指出SSA的“简洁性”依赖于忽略状态，但在面对别名、内存模型或并发时会崩溃。 - [mbauman]认为SSA对人类代码的可读性也有显著提升。 • **SSA与函数式编程的关系** - [noelwelsh]和[torginus]提出SSA本质上是函数式的，并探讨了其与函数式编程范式（如尾递归）的联系与矛盾。 - [anon291]进一步从范畴论角度分析SSA，并提到MLIR等现代框架对SSA的改进。 • **SSA的技术细节与争议** - [KeplerBoy]纠正了文章中关于乘法器位数的技术细节。 - [ModernMech]吐槽了网页中迷你地图的实现方式。 补充讨论： - **争议焦点**：SSA是否值得作为编译器的统一表示，以及其与函数式编程的关系是否被高估。 - **有趣观点**：[torginus]提出SSA的phi节点为循环提供了另一种范式，可能比尾递归更优。

这篇文章介绍了`Element`接口中的`setHTML()`方法，这是一个实验性技术，用于安全地将HTML字符串解析并插入DOM中。该方法通过内置的XSS防护机制自动移除不安全元素和属性，可替代不安全的`innerHTML`。文章详细说明了其语法、参数（包括可选的自定义消毒器配置）、返回值及异常情况，并通过基础用法示例和实时演示展示了如何使用默认和自定义消毒器来处理未经验证的HTML输入。由于该方法在某些主流浏览器中不可用，使用时需谨慎检查兼容性。

评论摘要
### 主要讨论点： 新引入的 `setHTML()` 方法及其在 DOM API 中的作用，特别是在防止 XSS（跨站脚本）攻击方面的意义。 ### 不同观点： • **支持 `setHTML()` 的引入**： - `CaptainOfCoit` 和 `padjo` 认为这是一个期待已久的功能，填补了 DOM API 的空白，尽管它来得太晚。 - `textlanes33` 认为这是 `innerHTML` 的一个更安全、更可预测的替代方案。 - `xnorswap` 指出 LLM 生成的代码容易存在 XSS 漏洞，`setHTML()` 可以作为一个安全的后备方案，减少错误的发生。 • **对 `setHTML()` 设计的质疑**： - `ishouldbework` 不理解为什么即使明确允许 `script` 标签，它仍然会被剥离，认为这种无法覆盖的过滤设计很奇怪。 - `ibowankenobi` 认为 API 设计可以更好，建议允许重用文档片段（DocumentFragment）并添加可选参数。 • **技术实现和浏览器支持**： - `evilpie` 提到 Firefox Nightly 已经默认启用了这一功能。 - `redbell` 指出该功能尚未被主流浏览器广泛支持，仍处于早期阶段。 - `cheeaun` 分享了一个 polyfill 链接，帮助在不支持的浏览器中使用这一功能。 • **相关扩展讨论**： - `_the_inflator` 建议在 JavaScript 文档的开头引入类似 `use strict` 的配置对象，以定义脚本选项（如消毒和其他配置）。 - `CGamesPlay` 询问“XSS-unsafe”是否有明确定义，认为在这个上下文中假设是不安全的。 - `Traubenfuchs` 询问这是否是 `innerHTML` 与 `DOMPurify.sanitize` 结合的更简单内置替代方案。 ### 补充讨论： - **争议焦点**： - `setHTML()` 的设计是否过于严格，尤其是无法覆盖的过滤规则（如 `script` 标签的处理）。 - 该功能的浏览器支持现状及其未来的普及前景。 - **其他讨论**： - 关于如何进一步改进 JavaScript 的安全性配置（如 `_the_inflator` 的建议）。 - 对 XSS 漏洞防护的更深层次技术讨论（如 `xnorswap` 提到的逃逸与消毒的区别）。
