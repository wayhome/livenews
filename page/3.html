O(n) vs. O(n^2) Startups

作者: ocean_moist | 评分: 64 | 评论数: 19 | 发布时间: 2025-05-15 04:54
文章摘要

这篇文章讨论了两种不同类型的科技创业公司：$O(n)$ startup和$O(n^2)$ startup。$O(n)$公司（如Mailchimp、37signals）的增长呈线性，关键指标（如收入、用户数）随时间线性增长，通常为自给自足的B2B SaaS企业，注重高利润和稳定增长。$O(n^2)$公司（如Slack、Uber）则具有超线性增长，通过网络效应和大量支出实现快速扩张，常依赖风险投资。 文章指出，风投通常只投资$O(n^2)$公司，而$O(n)$公司更常见且创始人最终可能获得更高的经济回报，尽管它们不易成为风投的回报来源。两者在人才招聘、经济压力和产品市场契合度（PMF）方面也有显著差异：$O(n)$公司注重销售人员，而$O(n^2)$公司则青睐高能动性的员工；前者面临薪资支付压力，后者则关注增长和用户留存。 结论是，$O(n)$公司由于低调且稳定，可能为创始人带来更高的预期经济价值（EV）。

评论摘要
主要讨论点：创业公司增长模式及其影响 不同观点： • [bee_rider] 认为创业公司的增长像 sigmoid 函数，初期通过口碑迅速扩展（指数增长），然后随着用户互相影响变为线性增长，最终达到市场饱和时增长趋缓。目标是在线性阶段被大公司收购。 • [danjl] 指出 O(n) 公司因资金有限，更加谨慎 hiring，且依赖于经验丰富的创始人和工程师，而 O(n^2) 公司往往根据风投的建议进行招聘，可能更注重短期扩展而非长期匹配职位需求。 • [vessenes] 引用私人股权投资者的观点，强调深入理解风投组合经济的重要性，指出即使是十亿美元公司的CEO也可能经济困难，而收入较少的企业主可能生活优越，暗示创业公司财务状况复杂。 • [ridiculous_leke] 从员工角度出发，比较 O(n) 和 O(n^2) 公司，认为 O(n^2) 公司提供的薪酬更高，但当前在 O(n) 公司的工作环境和长期增长潜力较好，存在职业选择的两难。 • [wavemode] 对 O(n) 和 O(n^2) 的表述提出算法上的质疑，认为传统算法分析中 n 通常代表时间或其他成本，而非公司关键指标。 • [chubot] 提到 "黑天鹅养殖" 概念，指出投资者往往倾向于选择高风险高回报的 O(n^2) 路径，即使这与创始人的利益不完全一致。 • [dvt] 认为创业者通常不会刻意选择某种增长模式，而是顺应发展，实际运营中更多是应对日常生存问题，而非进行预先的优化选择。 • [mperham] 提到 O(1) 独行创业者，指出并非所有创业都遵循典型的创业公司增长模式，有些人选择独自创业。 • [neilv] 补充 O(n^2) 公司往往依赖零利率政策和风投资金驱动的人工增长，并指出高 agency 的员工和股权激励在 O(n^2) 公司中起到重要作用。 • [ark296] 认为风投领域的规则与普通商业世界不同，长期处于风投环境中可能会忽略大多数企业并不遵循幂律分布的事实。 • [brudgers] 指出 O(n) 增长的公司在硅谷不被视为真正的“创业公司”，而只是普通的新企业，并强调创办普通新企业和创办风投支持的创业公司在资本和难度上的差异。 补充讨论： • 争议的焦点之一是 O(n) 和 O(n^2) 公司的招聘策略和员工选择。一些评论认为 O(n) 公司因资金有限更谨慎，而 O(n^2) 公司更注重快速扩展和高 agency 的人才。 • 另一个值得注意的点是，不同增长模式下的财务状况和个人职业选择之间的权衡，员工在选择公司时需要考虑薪酬、工作环境和长期增长潜力等因素。 • 算法表述的准确性也被提出，评论中有人质疑 n 在增长模式讨论中的代表意义，提出与传统算法分析的区别。 • 最后，创业公司和普通新企业在定义和资本运作上的差异也被提及，强调了风投支持的创业公司在增长模式和风险上的独特性。

Project Verona: Fearless Concurrency for Python

文章摘要

本文介绍了Project Verona团队为Python开发的新所有权模型Lungfish，旨在解决内存管理和并发问题。团队首先通过一个名为FrankenScript的简化语言进行快速原型设计，以探索基于区域的所有权概念，并生成可视化的程序结构图。该原型验证了所有权模型的可行性，并帮助团队向社区解释设计思路。 团队与Microsoft的Faster CPython团队合作，并计划在2025年的Python语言峰会上寻求更广泛的反馈。为了逐步实现新所有权模型，团队首先引入深度不可变性，分为三个部分：深度不可变性模型、循环不可变垃圾管理、以及子解释器间的消息传递集成。深度不可变性是所有权模型的关键，确保并发线程安全共享类型信息。 选择Python是因为其广泛使用和向并发模型转变的趋势，而不用线程和锁的方式是因为当前探索的是子解释器间消息传递。不同于Rust的所有权模型，团队设计的新模型适用于Python的动态类型和现有对象图。
