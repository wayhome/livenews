Are insecure code completions in PyCharm a vulnerability?

作者: 12_throw_away | 评分: 26 | 评论数: 8 | 发布时间: 2026-06-11 01:26
文章摘要

作者测试了PyCharm的"Full Line Completion"代码补全功能，发现其AI模型会建议不安全的代码：当输入urllib3相关代码时，它建议禁用SSL证书验证（cert_reqs='CERT_NONE'）和关闭安全警告，这会使程序容易遭受中间人攻击。作者向JetBrains报告此问题，但对方态度模糊——既说不是安全漏洞，又要求遵守漏洞披露政策。作者等待90天后发现问题未修复，并指出这类AI代码生成的安全问题普遍存在，但目前缺乏有效的优先级处理机制。

评论摘要
主要讨论点：AI代码自动补全是否构成安全漏洞 不同观点： • **直接威胁论**（sph）：认为终端AI自动补全存在即时风险，用户可能在tab补全后不小心执行恶意命令（如curl恶意脚本），只需按回车就会对系统造成破坏 • **漏洞促成者论**（stephantul, mgc8）：这不是漏洞本身，而是"漏洞制造者"——类似使用复杂技术会增加产生漏洞代码的可能性。建议JetBrains改进本地模型或允许用户使用自定义模型 • **人类责任论**（chmod775）：只有当我们免除人类责任、把开发者降级为"检入LLM代码的肉体载具"时，这才算漏洞。强调人应对自己的行为负责 • **技术局限论**（marcosdumay）：插件开发者对此无能为力，LLM开发者已经努力修复这个问题2年了，甚至牺牲了其他功能，但仍无法可靠解决 • **语义澄清论**（runningmike）：严格来说这不是"漏洞"（vulnerability），而是"潜在安全弱点"（potential security weakness），语义区分很重要 补充讨论：有人质疑"monster-in-the-middle"术语（可能是"man-in-the-middle"的替代说法）

World Capitals Voronoi

文章摘要

这是一个基于球面Voronoi图的世界地图可视化项目。它根据最近首都城市重新划分了世界版图——每个区域由距离最近的首都决定。 计算采用球面Voronoi图算法，考虑了地球曲率来精确计算距离。数据来源于Natural Earth的1:10m文化矢量数据集（首都城市）。 这种可视化方式打破了传统国界，展示了一种基于地理距离的另类世界划分方式。类似项目还有"美国Voronoi图"。

评论摘要
主要讨论点：对基于首都距离的Voronoi地图可视化的观察和讨论 不同观点： • **地理准确性质疑**：有人指出城市选择很随意（如Genova和Lyons被省略），且多首都国家处理不当（南非有3个首都但地图未体现） • **技术赞赏**：称赞可视化的帧率和延迟表现出色，交互体验流畅 • **政治敏感性**：台北占据中国大陆领土引发争议，类似渥太华和墨西哥城占据美国领土，被认为会引起政治问题 • **地理现实性**：认为结果虽有趣但接近现实，如法国-西班牙边界区域对应Occitan语区和比利牛斯山脉的人口分布特点 • **改进建议**：提议用"距离/√人口"替代纯距离最小化，以抵抗"女巫攻击"（人口操纵） 补充讨论： 有人开玩笑称这是"新版Risk棋盘游戏"或"引发第三次世界大战速通"。也有人希望看到统计数据：哪些国家得失最大、哪些区域离原属国最远。都柏林占据英国部分、哥本哈根拿下瑞典南部等跨国现象被认为"很公平"。
