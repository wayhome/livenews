The ways we contain Claude across products

文章摘要

这篇文章介绍了Anthropic公司在开发Claude AI产品时如何控制其潜在风险。文章指出，随着AI能力提升，其潜在破坏力也在增长。Anthropic采用两种主要方法限制风险：一是人工监督（但用户会对频繁的审批请求产生疲劳，93%的请求被自动批准）；二是环境隔离，通过沙箱、虚拟机和访问控制等技术手段限制AI的操作范围。 文章将安全风险分为三类：用户误用、模型异常行为、外部攻击。防御策略包括：限制运行环境、控制权限边界、监控模型行为。Anthropic在claude.ai、Claude Code和Claude Cowork三个产品中应用了不同的隔离架构，并分享了实践中的成功经验和失败教训。

I was recently diagnosed with anti-NMDA receptor encephalitis

作者: Tomte | 评分: 415 | 评论数: 41 | 发布时间: 2026-06-03 14:10
文章摘要

作者被诊断患有抗NMDA受体脑炎，这是一种自身免疫性疾病，会导致大脑炎症。起初出现流感样症状、焦虑和恐慌发作，随后发展为慢性下颌疼痛、平衡问题、自杀倾向和精神病症状（妄想和幻听）。最初被误诊为焦虑症或精神分裂症并送入精神病院，后经神经科确诊。通过静脉注射免疫球蛋白和类固醇治疗后迅速好转，目前正在参加临床试验。医生表示因发现较早，预后良好。作者认为这是人生中最糟糕的经历，但现在正在康复并重新投入工作。

评论摘要
主要讨论点：围绕罕见自身免疫/神经疾病的误诊、诊断困难，以及医学研究和临床经验在识别新病症中的作用。 不同观点： • 患者与家属视角：多位评论者分享亲历，强调这类病常被长期误诊、被当成心理问题或常见病，过程充满痛苦与风险。例子包括MCAS、心脏自身免疫病、NORSE、EGPA等，有人靠长期自行研究和试错才推动正确诊断。 • 医学专业视角：有医生评论认为，罕见病“容易先被当成精神疾病”是现实，但当症状与常见病不吻合时，医生必须记得考虑罕见病；这种基于经验的判断很难被AI取代。 • 科研与知识进展视角：有人指出相关疾病是近年才明确描述的新诊断，说明医学仍在快速发展；提升科研投入和公众/医生认知，可能帮助更多患者被识别和治疗。 • 病因推测视角：有人补充NMDA脑炎常与卵巢肿瘤等副肿瘤综合征相关，也有人猜测部分病例是否与Covid诱发自身抗体有关，但后者更多是推测。 补充讨论：讨论焦点主要在“为何长期误诊”与“谁更能发现罕见病”。一边强调患者自救、信息公开和新研究的重要性，另一边强调临床训练与医生经验仍是关键。另有评论对AI在罕见病医疗建议中的价值表示谨慎。

文章摘要

SQL是唯一一种基于数学而非潮流的编程语言，学一次可用30年。1995年的SQL查询在2026年仍能原样运行，因为它建立在不变的关系代数之上。相比之下，JavaScript等语言每隔几年就要重写。SQL的持久性源于其数学基础——你描述想要什么，数据库引擎决定如何获取。尽管SQL有向后兼容带来的缺陷（如NULL处理、GROUP BY重复等），但这种稳定性使其成为开发者最值得投资学习的技能，在任何技术栈中都能受用几十年。

评论摘要
主要讨论点：SQL作为编程语言的价值和地位，以及学习SQL的重要性 不同观点： • **SQL是优秀但非完美的工具**（wodenokoto）：SQL并非数学纯粹性的典范，而是一个未能实现自然语言目标的"时尚语言"，只是碰巧存活下来。语法不一致（如'='有时是身份测试、groups/partitions混用、AS位置不统一），难以学习且需要大量重构 • **SQL教授底层逻辑思维**（aledevv, TonyAlicea10）：学习SQL的真正价值不在于语法，而在于培养集合论思维和逻辑推理能力。许多开发者用过程式思维写SQL导致性能低下，理解关系代数和数学模型才是关键 • **SQL知识经久不衰**（vbezhenar, Hugsbox, ErroneousBosh）：SQL与C语言、Unix工具、IPv4网络一样，是20-30年不变的核心技能。专门构建的工具能经受时间考验，如同锤子这样的工具 • **SQL仍需持续学习**（sdevonoes）：不能"一次学会"SQL，需要在实际工作中针对不同问题持续学习和应用 • **存在更好的替代方案**（teleforce, veqq）：D4M基于关联数组代数比SQL更通用，Datalog等语言在某些方面优于SQL 补充讨论：多数人认可直接使用SQL而非ORM能获得更好的性能和控制力，但高级SQL查询仍然复杂难懂

文章摘要

这篇文章介绍了 Agent Radio（h5i msg），一个让 Claude Code 和 Codex 等 AI 编程助手通过 Git 进行实时协作对话的多智能体消息系统。它基于 i5h 协议（智能体间信息与交互握手协议），将消息以 JSON 格式存储在 Git refs 中，无需外部服务器。通过简单的命令即可安装使用，所有交互自动版本化并可审计。这解决了单个智能体上下文窗口限制和大规模代码库并行处理的协作难题，让多个 AI 智能体能像真人对话一样协调开发任务。

评论摘要
主要讨论点：AI代理之间如何通过不同通信渠道进行协作交互 不同观点： • **支持多样化通信方式**：cadamsdotcom提出AI可通过git仓库、文件、Unix socket、终端等多种方式对话；多位开发者分享了实践经验（append-only文件、tmux、Jira/Git、GitHub issues） • **质疑自发性和价值**：xg15认为通过提示词实现不够有趣，真正的突破应是AI自发创建通信渠道；iandanforth质疑中间层的必要性，认为Claude和Codex可直接互相驱动 • **沙箱隔离派**：rigonkulous强调应将AI完全沙箱化在独立VM中，通过Jira和Git接口交互，像对待初级程序员一样管理 • **工具和框架分享者**：rothific、Game_Ender、frb、ryanthedev等分享了各自的协作协议、外部内存系统、MCP技能代理等具体实现 补充讨论： 技术细节争议围绕git使用的优势（mchinen提问）和.jsonl文件冲突问题（mirekrusin担忧）。多数开发者倾向于放弃复杂编排框架，转而使用人类熟悉的协作工具（GitHub、Jira）来管理AI代理，体现出"AI作为团队成员"的实用主义趋势。
