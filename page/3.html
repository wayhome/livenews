The new skill in AI is not prompting, it's context engineering

作者: robotswantdata | 评分: 335 | 评论数: 60 | 发布时间: 2025-06-30 20:53
文章摘要

"Context Engineering" is emerging as a key focus in AI, surpassing the previous emphasis on "prompt engineering." It involves providing all necessary context to make a task solvable by large language models (LLMs). This includes not just the user prompt, but also instructions, conversation history, long-term memory, retrieved information, and available tools. The quality of this context determines an agent's success or failure. For example, a "magical" AI assistant uses rich context like calendar information, past emails, and contact details to generate helpful responses, unlike a "cheap demo" agent that provides robotic and unhelpful outputs. Context engineering is a dynamic, system-based approach that ensures the model receives the right information and tools in the appropriate format, highlighting that successful AI agents rely more on context quality than model complexity or code sophistication.

Genetic code enables zebrafish to mend damaged organs

作者: bookofjoe | 评分: 93 | 评论数: 5 | 发布时间: 2025-06-29 01:00
文章摘要

新研究由加州理工学院（Caltech）和加州大学伯克利分校（UC Berkeley）合作完成，发现斑马鱼能够修复和再生受损心脏的能力与其神经嵴细胞有关。这些细胞占斑马鱼心脏细胞的12%至15%，在心脏受损时启动再生过程。研究揭示了一组在再生过程中被激活的基因，这些基因在胚胎发育期间活跃，成年后休眠，再生时重新激活。研究团队希望通过CRISPR技术在人类心脏细胞中重新激活这些基因，以探索人类心脏再生的可能性。该研究发表在《美国国家科学院院刊》上。

评论摘要
主要讨论点：与蜥蜴再生尾巴相关的基因能力及其在进化中的意义 不同观点： • zombot指出蜥蜴拥有能够再生尾巴的基因编码。这表明蜥蜴具有某种人类不具备的再生能力。 • flobosg提供了相关研究的预印本链接，补充了关于该基因能力的科学文献，让讨论有了具体的参考资料（https://www.biorxiv.org/content/10.1101/2025.01.16.633462v1）。 • m3kw9提出疑问，认为应该探讨为什么人类在进化过程中没有获得类似的再生能力，暗示这种能力可能在进化中被认为不必要或不利。 • sydbarrett74用“ nocturnal bottleneck”（夜间瓶颈）来解释，可能暗指人类祖先在进化过程中由于环境或生存压力，没有发展出类似蜥蜴的再生能力。 • taneq用编程语言的幽默方式指出，如果器官受损，应当有“不执行”的机制，似乎是在暗示生物进化可能有某种“设计”上的限制或选择。 补充讨论： - m3kw9的疑问引发了关于进化必要性的讨论，即为什么人类没有进化出类似的再生功能。 - sydbarrett74用“夜间瓶颈”回应了m3kw9，指出环境或进化历史可能影响了再生能力的进化。 - taneq的评论带有技术幽默，但可能暗示着对生物机制复杂性的理解。 争议焦点： - 主要争议在于为什么人类没有进化出像蜥蜴一样的再生能力，以及这是否与进化历史或环境选择有关。

The hidden JTAG in a Qualcomm/Snapdragon device’s USB port

作者: denysvitali | 评分: 167 | 评论数: 5 | 发布时间: 2025-06-30 18:34
文章摘要

本文介绍了Qualcomm在其SoC中隐藏的EUD（嵌入式USB调试）接口，该接口自2018年起几乎存在于所有Qualcomm SoC中。通过EUD，开发者可以通过USB接口直接进行SWD调试，而无需额外工具或焊接。尽管Qualcomm在今年二月公开了相关源代码，但此前该功能依赖于专有库，仅供内部员工及合作伙伴使用。在Linux内核中的支持也引发了一些讨论，最终Qualcomm公开了代码并更新了openOCD分支。尽管构建过程中遇到一些问题，但经过修复后，成功实现了EUD的构建和使用，并添加了对Hexagon调试的支持。这一功能为内核和DSP调试提供了极大的便利。

评论摘要
主要讨论点：Qualcomm SoC的调试接口、安全性以及特殊功能（如USB音频 offload） 不同观点： • [jeffreygoesto] 认为在某些SoC上可以通过ETM端口获取完整的程序追踪，并且调试体验非常好，可以调试应用程序、操作系统及驱动程序，甚至可以细化到单个汇编指令级别。这表明某些SoC提供了强大且细粒度的调试功能。 • [mmastrac] 对比了之前的Qualcomm调试体验，指出过去的Qualcomm调试接口存在严重的安全问题，通过USB暴露的简单读/写/执行原语可以让用户轻松获取root权限。同时，提到大多数移动芯片集的调试端口仍然不足，像MediaTek设备仍需要一些特殊操作才能通过USB暴露串行接口。他还预测大多数OEM厂商会禁用这些调试功能，尤其是消费级设备中，因为像Google这样的大公司不希望设备具备调试能力。 • [tripdout] 对生产设备上的调试功能能否启用表示关注，尤其提到OnePlus 6设备中该功能被熔断但仍可访问的情况，质疑如何读取生产设备上的eFuse，并提到设备树中存在相关寄存器。这表明生产设备中的调试功能可能存在潜在的破解或绕过方法。 • [dazhbog] 对Qualcomm自定义硅片功能表示惊讶，描述了当启用特定寄存器时，SoC通过USB接口重定向并添加一个USB集线器，进而提供SWD编程器和串行端口连接到ARM核心的IO。他认为这种设计非常了不起，显示了Qualcomm在硬件调试支持上的创新。 • [jauntywundrkind] 提出了另一个话题，赞扬Qualcomm在USB音频offload方面的努力，尤其是将音频设备数据转发到USB主机控制器，然后发送到USB音频设备。他认为这是一种出乎意料但非常有趣的技术优化。 补充讨论： • 调试接口的安全性与可访问性之间的矛盾，尤其是OEM厂商和Google对消费级设备调试功能的限制。 • 不同芯片厂商（如Qualcomm和MediaTek）在调试接口实现上的差异。 • Qualcomm在硬件设计上的创新，如通过自定义硅片添加调试功能以及USB音频offload优化。 • 对生产设备上调试功能熔断但仍可访问的实际操作和安全性的担忧。
