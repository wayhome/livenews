文章摘要

文章介绍了 Epiq：一个面向 Git 仓库的本地优先、事件溯源式项目管理工具。它提供终端 ASCII 看板、键盘/类 Vim 操作、可按需同步、冲突友好协作，并支持 MCP，方便 AI 代理参与工作流。

评论摘要
主要讨论点：围绕 Git 分布式 issue tracker 的设计取舍、适用人群、数据同步与 UI 形态展开。 不同观点： • 支持者认为项目很酷：Git 可作为“数据库”，有免费托管和离线/分布式优势；适合 repo 内 issue、个人任务管理，减少切换到网页工具的成本。 • 谨慎/质疑者指出：过去分布式 Git issue tracker 常有设计缺陷，关心是否把数据与代码分离、如何避免冲突、同步是否可靠。 • 面向人群争议：若只给开发者用，TUI 合理；若要覆盖产品经理、设计师等团队成员，强制终端界面不现实。 • 数据组织争议：有人建议默认使用中心化 issue 仓库，或提供跨 repo issue 关联；否则修改 issue 可能被迫和本地未完成代码一起提交。 • 技术方案认可：用户级不可变事件日志被认为能优雅避免 Git 冲突。 • UI/架构建议：希望 UI 与数据层可分离，增加本地 Web UI；也建议参考 git-bug 的经验。 • AI 集成争议：有人认为与其做 MCP server，不如发布 agent 可调用的 CLI skill，甚至偏好单二进制加 skill。 补充讨论：核心分歧在“开发者专用工具”还是“团队协作工具”，以及 issue 是否应与代码同仓库强绑定。

主要讨论点：围绕 Jason Scott 长期数字化和保存资料的工作（手册、磁带、Textfiles、Archive Team/Internet Archive）展开，重点是对其贡献、项目进展和相关信息的补充。 不同观点： • 高度赞赏 Jason Scott 的保存工作：多位评论者称其“高产”“好人”“king among men”，强调他让大量原本可能消失的资料公开可见。例子包括 4-5 年数字化 1300 多盘磁带，以及十年整理约 13000 本手册，平均每天约 3.5 本。 • 个人经历与情感认同：有人提到 Textfiles 是自己早期访问的网站之一，能参与项目像是“见到偶像”；也有人回忆曾为早期募捐捐款，并收到一本重复手册作为回馈，十年后看到成果感到惊喜。 • 信息更新与链接补充：有评论指出当前 archive 链接已过时，提供了更新的 Web Archive 链接；另有人补充最新文章是 2026 年 5 月 10 日的 “Manuals Plus: The Wrap-Up”；还有人提醒 Jason 正在 Twitch 直播。 • 资料内容疑问：有人不清楚“manuals”具体指什么，询问是电器说明书、教材还是其他类型资料。 • 对个人事件的追问：有人注意到博客中提到“跟踪者”和“有人试图伤害其家人”，希望找到更多背景信息。 补充讨论：整体氛围以感谢和敬佩为主，争议不明显；焦点更多在项目规模、资料可访问性、链接时效和背景信息补全。
