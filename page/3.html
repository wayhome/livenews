How Compiler Explorer Works in 2025

作者: vitaut | 评分: 145 | 评论数: 9 | 发布时间: 2025-06-04 17:32
文章摘要

《Compiler Explorer在2025年的工作原理》介绍了这一工具如何处理每年9200万次的编译请求。文章详细描述了从用户在Monaco编辑器中输入代码，到代码通过CloudFront和负载均衡器发送至服务器，并进入编译队列的过程。服务器使用nsjail工具创建一个隔离环境运行编译器，生成输出结果并过滤无关信息，最终以JSON格式返回浏览器渲染。 为了应对高负载，系统会自动扩展各集群的实例数量。安全性方面，通过nsjail实现严格的进程隔离，防止用户执行任意代码。文章还提到管理近4TB的编译器版本通过大量Python和shell脚本实现，且坚持不淘汰旧版本以避免链接失效。这种做法不仅保证了稳定性，还为用户提供了长久的编译环境。

评论摘要
主要讨论点：围绕Compiler Explorer工具的多个方面展开的讨论，包括成本、域名、技术实现（客户端编译）、界面问题以及论坛帖子格式问题。 不同观点： • [tomcam] 认为用户在看到Compiler Explorer的实现时，应该称赞其创建者Matt Godbolt的出色工作，而不是编译器本身。这表明评论者更关注工具背后开发者的贡献。 • [galkk] 详细分析了Compiler Explorer的运行成本，每月约3000美元，包括AWS、监控、错误处理和编译数据存储等费用。评论者对该工具能在如此高负载下保持低成本运行表示惊讶，并与其他类似平台（如lichess）进行了对比，认为这种高效利用云资源的案例非常值得关注。 • [psnehanshu] 提出了关于域名管理的建议，认为应该将godbolt.org和compliler-explorer.com这两个域名进行整合，以避免链接失效问题，从而提高用户体验。 • [wild_pointer] 询问是否有可能通过WebAssembly技术在客户端进行部分或全部编译工作，这表明评论者对工具的技术实现有进一步优化的兴趣，尤其是在客户端性能提升方面。 • [arkj] 提到在主页上看到同一帖子的多个链接，暗示可能存在界面展示错误，这涉及到工具或平台的用户界面问题。 • [quaintdev] 质疑Hacker News（HN）平台本身可能存在问题，并附上了一张截图作为证据，表明讨论可能偏离了Compiler Explorer本身，转向了平台的技术问题。 • [unconed] 认为在帖子末尾添加AI免责声明的方式不妥，建议如果需要添加声明，应该放在开头，以确保读者第一时间知悉。这涉及到信息透明度和用户体验的问题。 补充讨论： • 评论中涉及了多个技术实现和用户体验的讨论点，如WebAssembly的可行性、域名管理、界面问题和平台帖子格式问题，表明用户不仅关注工具本身的功能和成本，还对其技术细节和用户体验有较高要求。 • 争议的焦点主要集中在工具的域名管理和用户界面的问题上，部分用户认为可以通过技术手段（如重定向、客户端编译）来改善用户体验。

文章摘要

Binfmtc – binfmt_misc C scripting interface

作者: todsacerdoti | 评分: 86 | 评论数: 11 | 发布时间: 2025-06-08 12:38
文章摘要

**binfmtc** 是一个让 C 语言用于脚本编写的工具，解决了因编译步骤繁琐而选择解释型语言的问题。通过在 C 脚本中添加特定注释标记 `/*BINFMTC: ...*/` 并赋予执行权限，每次调用脚本时，系统会自动编译并执行程序。该工具利用 Linux 的 **binfmt_misc** 机制，在调用 C 脚本时自动调用编译器（如 gcc）生成临时二进制文件并运行。此外，还提供了一个类似 C shell 的 "real csh" 示例，用于日常系统管理任务。安装可通过添加特定源并使用 `apt-get` 完成，未来计划包括支持更多语言如 gcj、g77、mono 等。
