F* file system – file search that reads SSD directly bypassing OS kernel

作者: neogoose | 评分: 37 | 评论数: 10 | 发布时间: 2026-06-21 20:44
文章摘要

FFS（F* File System）是一个用C语言编写的命令行文件搜索工具，约1500行代码。它的核心特点是绕过操作系统内核，直接读取磁盘原始数据进行搜索。 **主要特性：** - 直接读取磁盘块设备，跳过VFS缓冲层 - 支持Ext4、Btrfs和APFS文件系统 - 可搜索未挂载的卷（如.dmg、.iso文件） - 利用OpenMP实现多核并行处理 **性能表现：** 文件数量越多，相比ripgrep优势越明显。在325万文件的测试中，FFS用时36秒，而ripgrep需要75秒。 **局限性：** macOS主磁盘需禁用SIP保护、可能遗漏最近写入的文件、仅支持已实现的文件系统。本质上这是一个概念验证项目，展示直接磁盘访问可以超越内核VFS的性能开销。

评论摘要
主要讨论点：这个项目是否真的“绕过内核/文件系统”、其实用性与安全性，以及命名和宣传是否准确。 不同观点： • 技术纠错派：多人指出它并没有“绕过内核”，只是直接读取 `/dev` 块设备，最多算绕过文件系统；`watusername` 还拿 `SPDK` 举例，认为那才更接近真正绕过内核。`Retr0id` 也认可项目很酷，但强调表述不准确。 • 实用性质疑派：`neogoose` 认为项目很有趣但“几乎没用”，因为依赖 `sudo`；`wk_end` 也表示自己不会信任或使用。对此 `porridgeraisin` 反驳，提出用 `setfacl`、用户组和开机脚本授予只读权限，认为可在不直接给 `sudo` 的情况下使用。 • 标题/命名批评派：`kasabali` 直指标题很蠢，认为既然是读块设备，不只 SSD，HDD、U 盘、存储卡也应适用；争议焦点是项目宣传是否故意夸大“SSD”“绕过内核”。 • 周边吐槽与补充：有人调侃速度和可靠性能否媲美 Windows Search；有人提到 SSD 控制器的“魔法”仍无法绕过，如 flush 是否真的可靠；还有人吐槽仓库简介有拼写错误，以及项目名 `FFS` 却不支持 BSD 的 FFS。 补充讨论：评论整体态度是“技术上有意思，但宣传过头、可信度和落地价值存疑”。
