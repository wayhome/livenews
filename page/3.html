Suspicious Discontinuities (2020)

作者: tosh | 评分: 245 | 评论数: 18 | 发布时间: 2026-06-27 13:32
文章摘要

这篇文章探讨了政策中"硬性门槛"带来的问题。以美国医疗保险补贴为例：收入刚超过$48,560的人可能比收入$55,000的人实际可支配收入更少,因为失去补贴导致医保费用暴增$7,200/年。这种不连续的政策设计激励人们故意降低收入(如买入预期作废的期权来亏钱),以获得补贴资格。文章指出美国税收和福利体系中充斥着类似的discontinuities(断点),并建议用渐进式退出机制代替硬性门槛。文章还类比了计算机队列、网站投票系统、大学招生等领域的类似问题,说明平滑过渡通常优于硬性截断。

评论摘要
主要讨论点：政策和系统中的阈值效应（threshold effects）及其产生的不合理现象 不同观点： • **支持渐进式过渡**：多位评论者认为应用"缓慢淘汰"（slow phase-outs）或渐变机制替代硬性阈值，避免边际税率突增等cliff效应。提出税收和福利应采用梯度设计而非绝对临界点 • **主张取消资格审查**：collabs强烈建议完全取消政府福利的资格审查（means testing），让所有人都能使用服务，认为对"愚蠢者"的额外税收惩罚应属非法，并批评医保追偿规则过于残酷 • **接受现状并利用**：amluto提出更激进观点——干脆不设淘汰机制，让高收入者也享受同等补贴，这样他们能更好理解政策优劣并推动系统改进 补充讨论： 评论区提供了丰富实例验证阈值效应的普遍性：马拉松配速员导致完赛时间聚集、印度税法12L收入cliff产生70K逆向激励、英国育儿福利cliff、国际象棋评分整数关口心理效应、AWS工程师为达标而牺牲P90以上性能。有评论者提出操作性建议（如教师分题评分、利用股票亏损调节收入），也有人从公民教育角度强调识别这些discontinuities对理解复杂系统的重要性。

Enhancing x11 Application Security with LXC (2025)

文章摘要

这篇文章介绍了如何使用 LXC 容器来增强 x11 应用程序（如浏览器）的安全性。主要步骤包括： 1. **网络配置**：安装 lxc 和 lxcfs，配置网络桥接接口 lxcbr0 2. **创建容器**：建立配置文件，使用非特权容器并通过 UID/GID 映射（将容器内 ID 映射到主机上不存在的 ID 范围 100000-165535）实现隔离 3. **应用安装**：在容器中安装所需软件（如 Firefox），创建专用用户运行应用 4. **x11 配置**：挂载 x11 socket，处理 .Xauthority 授权文件以支持图形应用 核心思想是通过容器隔离，即使应用被攻破，攻击者也无法获得主机系统的有效权限，从而保护用户的家目录和敏感数据。

评论摘要
主要讨论点：在容器中运行应用程序的安全性问题，特别是X11的安全漏洞和沙箱逃逸风险 不同观点： • **X11存在严重安全缺陷**：直接访问X11服务器会造成巨大的沙箱逃逸漏洞，任何应用都能控制/监视其他应用（包括root终端）。建议使用嵌套X服务器如Xephyr或waypipe等替代方案 • **X11难以淘汰**：质疑X11是否会像IE6一样，在主流发行版计划弃用（2025/2026）后仍存在十年以上 • **容器化的实用性问题**：容器化应用听起来不错，但在需要访问文件时会遇到困难 • **替代方案建议**：推荐使用firejail（自带常用应用预制配置）、AppArmor/SELinux（无需容器）、或XNamespace扩展（X11Libre正在开发的新方案） 补充讨论： 有评论指出Firefox本身已有完善的沙箱机制，文章标题可能过度宣传容器化的安全价值，应更关注X11本身的安全问题。也有人感叹理想世界不需要这些安全措施的复杂性。

How do you keep Web MIDI from crashing a 1983 synthesizer?

文章摘要

这篇文章讨论了使用现代浏览器的 Web MIDI API 控制1983年老式合成器（如 Yamaha DX7）时面临的技术挑战。主要问题包括： 1. **缓冲区溢出**：现代计算机传输速度过快，而老式合成器使用2MHz的8位处理器和256字节RAM，无法及时处理数据。解决方案是在JavaScript中实现软件流控制，分块发送数据并添加延迟。 2. **专有数据格式**：每个厂商的SysEx格式都不同且无文档，需要编写专门的解析器来处理各品牌合成器的独特字节结构。 3. **浏览器安全限制**：因涉及直接硬件访问，浏览器对Web MIDI API实施严格权限控制，部分浏览器完全禁用此功能。

评论摘要
**主要讨论点：** 一款用于保存老式合成器补丁的 SysEx 备份产品的定价策略、技术实现和市场定位 **不同观点：** • **定价过高派**：月费 $20 或终身 $599 的价格不合理，比完整的 DAW 软件（Ableton、Logic）还贵，年费 $230 远超免费或低价竞品（如免费的 Dexed 插件、付费的 Plogue 插件都包含 librarian 功能） • **商业模式质疑派**：产品依赖公司持续存在才能保存备份数据，但高定价可能导致公司倒闭，用户希望支持纯 .syx 文件下载以防数据丢失；目标市场（老式合成器用户）规模小且设备越来越稀缺 • **技术实现批评派**：用未知前景的 Web 应用替代桌面应用不明智，应该开发离线优先的桌面应用；网站风格疑似使用 AI 生成（"vibe-coding"），但 MIDI 是精心设计的资源受限系统，不需要 AI 介入 • **营销策略反感派**：通过恐吓式营销（"电池会死，补丁会丢失"）来推销产品的方式令人反感 **补充讨论：** 评论中穿插了 USB MIDI 缓冲问题的技术讨论，包括不同操作系统的兼容性差异，以及 MIDI 协议标准速率（31.25 Kbaud）下老设备应能正常工作的理论分析。
