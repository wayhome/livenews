Sem: New primitive for code understanding – not LSPs, but entities on top of Git

作者: rohanucla | 评分: 104 | 评论数: 14 | 发布时间: 2026-06-06 20:03
文章摘要

Sem 是一个为 Git 提供语义理解的命令行工具。它将传统的逐行 diff 转换为函数级别的变更视图，显示哪些函数被添加、修改或删除。核心功能包括：实体级差异对比(sem diff)、按函数追溯提交历史(sem blame)、依赖关系影响分析(sem impact)、单个实体的演化历史(sem log)等。支持26种编程语言，无需配置，一键安装后可替代 git diff。AI 代理使用 sem 输出时准确率提升2.3倍。适用于任何 Git 仓库。

评论摘要
主要讨论点：关于 Sem 工具（一个为 AI 代理和人类提供语义化代码变更分析的工具）的实用性、性能和营销方式的讨论 不同观点： • **支持者**：认为工具概念很酷，对人类和 AI 都有帮助。有开发者表示曾尝试构建类似的依赖关系图工具，验证了这个需求的真实性。也有人看到了在数据工件追踪、代码审查 UI 改进、自动拆分提交等场景的应用潜力 • **质疑实用性者**：怀疑该工具是否真正解决了复杂项目中的实际问题，建议提供更多实际应用场景的示例来证明价值 • **批评营销方式者**：强烈反对"AI 代理准确率提升 2.3 倍"的宣传说法，认为基准测试不是真实世界任务，这种夸大宣传削弱了工具的可信度。建议诚实地推销工具的真实功能 • **关注性能者**：担心在包含数十万文件的大型 monorepo 中的表现，因为这类仓库连基本的 git 操作都很慢 • **用户体验批评者**：指出"10 秒试用"部分劫持了 git diff 并安装 pre-commit hook，但没有提供卸载说明，认为这种做法对用户不友好 补充讨论：有人询问该工具是否专门用于检查 Claude Code 对代码库的修改，反映出工具与特定 AI 工具集成的关注点
