Zig: Build System Reworked

作者: tosh | 评分: 321 | 评论数: 20 | 发布时间: 2026-05-30 08:38
文章摘要

Zig编程语言在2026年5月26日对构建系统进行了重大重构。主要变化是将`build.zig`的编译过程分为两个独立进程：配置器（configurer）和制造器（maker）。配置器以调试模式编译用户的构建逻辑并生成二进制配置文件，制造器以发布模式编译并执行构建图。 这次改进带来三大性能提升：1) 每次修改只需重新编译用户的`build.zig`代码，而非整个构建系统；2) 当配置未变化时可跳过重新运行构建逻辑；3) 执行构建图的进程现在启用了优化。基准测试显示`zig build --help`命令的执行时间从150ms降至14.3ms，性能提升超过90%。此外，第三方工具如ZLS也能从序列化配置文件中受益。

评论摘要
主要讨论点：Zig 0.16.0 版本发布后，开发者对该语言的评价和使用体验 不同观点： • **积极支持派**：认为 Zig 是优秀的"工具语言"和"车库修补"语言，简单易上手，设计周到，新的 IO 机制高效且代码优雅，编译速度出色，跨平台编译能力强大（特别是 glibc 版本控制） • **谨慎观望派**：关注稳定性问题，认为像异步 IO 这样的大特性表明语言仍不稳定，询问何时会有稳定版本发布 • **对比质疑派**：质疑 Zig 相比其他语言的优势，如"为什么要用 Zig 而不是 Node.js/TypeScript"，以及 Rust 用户是否应该尝试 Zig • **功能批评派**：认可 Zig 的诸多优点，但对字符串处理感到不满，认为过于繁琐，希望有可选的 RAII 支持来简化字符串和容器管理 补充讨论： 有开发者提出"双语言编程"理念，认为 Zig 可能是高级语言之外的理想低级语言搭档，比 C++ 和 Rust 更容易在长时间中断后重新上手。社区对 0.17.0 快速发布（几周内）感到惊喜，因为 0.16 用了超过一年。另有人询问 MIT License (Expat) 的含义。

Tsplat – Run Gaussian splatting in your terminal

作者: martianvoid | 评分: 28 | 评论数: 4 | 发布时间: 2026-05-28 12:15
文章摘要

tsplat 是一个用 Rust 编写的 3D 高斯溅射（Gaussian Splatting）渲染工具，可在终端中运行，纯 CPU 实现，无需 GPU 或显示服务器，支持 SSH 远程使用。它通过 Unicode 半块字符或图形协议将 3DGS 场景直接渲染到终端。 主要特性包括：支持 INRIA 3DGS .ply 格式场景文件、可调节溅射数量上限、提供相机控制（平移、旋转、缩放）和自动环绕模式。 技术实现上，每个高斯溅射由位置、缩放、旋转、颜色和不透明度表示。渲染管线包含五个步骤：投影溅射（构建 3D 协方差矩阵并投影到 2D）、计算边界框、深度排序、瓦片分箱和 alpha 合成。项目还包含高斯溅射原理的详细教程文档。

评论摘要
主要讨论点：关于一个在终端中实现高斯溅射（Gaussian Splatting）项目的质疑 不同观点： • **对项目动机的质疑**（a1o）：第二次提交是向LLM询问"选择会火的东西"，认为这种做法很奇怪，暗示项目可能缺乏真实的技术动机 • **对AI判断力的批评**（daveguy）：认为当前AI无法提供好的判断力，特别是在"应该构建什么"这类问题上。虽然高斯溅射技术本身很酷，但"在终端中实现"只是吸引技术宅的噱头。由于项目源自LLM，对其准确性表示怀疑 • **对内容推广的怀疑**（relaxing）：质疑为什么有这么多高斯溅射相关内容被推送到Hacker News上，暗示可能存在人为推广行为 补充讨论：daveguy提供了一个解释该技术的视频链接，说明尽管对项目本身持批评态度，但认可高斯溅射技术的价值。整体讨论氛围偏向质疑，焦点在于项目的真实性、技术价值与营销动机之间的矛盾。

It takes two neurons to ride a bicycle (2004)

作者: malshe | 评分: 96 | 评论数: 21 | 发布时间: 2026-05-26 16:51
文章摘要

这篇论文提出了一个仅用两个神经元的网络来控制自行车骑行。过去的方法要么需要大量学习时间(如强化学习需要1700次练习),要么需要复杂的数学分析。而人类学骑车并不需要这些。 作者开发了一个通用机器人模拟器来模拟自行车的物理运动,并设计了极简的神经网络控制器。该网络能够引导自行车朝目标方向行驶,表现出与人类相似的特点:长距离目标精确,但短期内受稳定性影响。这种行为不是刻意设计的,而是网络控制方式的自然结果。论文还指出骑车的反直觉性:向右转需要先向左推车把使车身右倾。

评论摘要
主要讨论点：关于"两个神经元控制自行车"研究的有效性和完整性 不同观点： • **简化过度派**（mk_stjames）：模拟过于简化，忽略了蹬踏控制，真正困难的是从零速度启动时的平衡问题，而非仅仅"抑制不稳定性"。任何学过骑车的人都知道起步最难。 • **重新发明轮子派**（actinium226, ebhn）：这只是重新包装了PID控制，或者只是手写了一个函数然后称之为"神经元"。方法并不新颖，只是换了个说法。 • **优化成果派**（dchristian）：从3456个输入神经元优化到17个输入+2个隐藏节点是巨大的进步。这是寻找复杂系统最小形式的有趣方法，尽管传统控制理论可能用更少神经元实现。 • **输入设计派**（wrsh07）：需要考虑输入的设计，如果给网络提供合适的输入特征（如x1²和x2²），可以用更少的神经元解决问题。 • **实际骑行派**（sandworm101）：研究者可能没真正骑过车，车把不是主要控制方式，视频显示可以不用手也能转弯到45度倾角。 补充讨论：有人提出该方法可能适用于平衡车等其他平衡车辆；也有人质疑能否实现自动驾驶自行车。
