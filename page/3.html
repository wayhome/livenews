Deno 2.8

作者: roflcopter69 | 评分: 304 | 评论数: 21 | 发布时间: 2026-05-22 11:23
文章摘要

Deno 2.8 发布，这是迄今最大的次要版本更新，新增多个子命令： **deno audit fix** - 自动升级有漏洞的 npm 包到最近的补丁版本 **deno bump-version** - 更新 deno.json 或 package.json 中的版本号，支持 patch/minor/major 增量，在工作区中可基于 Conventional Commits 自动推导版本变更 **deno ci** - 专为 CI 环境设计的安装命令，强制使用 lockfile 并在不匹配时报错 **deno pack** - 将 Deno/JSR 项目构建为可发布到 npm 的 tarball，自动转译 TypeScript、生成类型声明文件、重写模块说明符以兼容 npm 生态 升级命令：`deno upgrade`

评论摘要
主要讨论点：Deno 与 Node.js/Bun 的竞争态势，以及 Deno 的发展方向争议 不同观点： • **Deno 优势派**：认为 Deno 的权限模型、TypeScript 原生支持、安全性设计体现了 Unix 精神，是 JS 生态应该前进的方向。适合小型服务和业余项目，性能持续改进令人印象深刻。 • **Node 兼容性必要派**：认为 Deno 加强 Node 兼容性（从 40% 提升到 75%）是正确方向，npm 默认支持和 lib.node 包含使迁移更容易，这些改进让 Deno 更实用。 • **方向转变质疑派**：批评 Deno 为商业原因妥协初心，默认包含 Node 类型污染了 Deno/Web 代码，过度向 Node/NPM 靠拢会失去差异化优势。担心专业项目中途因方向变化被迫回归 Node。 • **生态竞争观察**：Bun 因速度快、标准库全面且被 Anthropic 收购而增长迅速；Node 依然是稳定方案；Deno 的沙箱和导入机制优势已被商品化，吸引力下降。 补充讨论：有开发者建议 Deno 应坚持初始价值观，AI 代理的出现可能缓解技能迁移压力；也有人希望看到 Deno 用于 Python/WASM；项目融资模式（拒绝捐赠）可能带来长期压力。

Comparing an LZ4 Decompressor on Four Legacy CPUs

文章摘要

这篇文章讨论了作者为8位和16位复古计算机平台实现LZ4压缩算法的经历。作者最初为SNES项目压缩数据，后来为6809、68000处理器实现了版本，最近又完成了Z80、8080、8086和6502的四个新实现。 文章详细解释了LZ4的工作原理：通过交替的字面量字符串和反向引用来压缩数据。每个"序列"包含一个长度字节（高4位表示字面量长度，低4位表示反向引用长度加4）、字面量数据、以及2字节的偏移量。当长度超过15时，使用额外字节扩展长度值。 作者特别强调Z80实现非常直接，并以此为基础对比了不同CPU架构的实现差异，展示了如何将Z80代码转换为8080、x86版本，以及6502需要采用的不同实现策略。

评论摘要
主要讨论点：围绕一篇讲解8位CPU上压缩/解压实现的技术文章，讨论其内容价值、实现思路、算法背景以及网站可用性问题。 不同观点： • 文章的技术价值很高：有评论认为它详细比较了不同8位CPU上的实现差异，如6502与Z-80、8080与Z-80/8086，能看出不同架构设计如何影响真实代码写法，这是文章最突出的优点。 • 文章适合复古计算机爱好者：有人推荐作者的博客，认为其内容面向喜欢1980年代家用电脑/游戏机、但不完全清楚底层原理的读者。作者常以“自己摸索”的方式，逐步展示如何让游戏在特定系统上运行，因此ASM深度解析很有教学性。 • 对实现策略的理解：有评论指出文中提到的“三个限制”本质上是通过“过度约束”来避免昂贵的条件判断，不必频繁做if测试，从而让解压过程能全速执行；这体现了性能优先的设计思路。 • 对LZ类算法的补充背景：有人从更一般的角度说明，LZ家族算法长期受自解压可执行文件欢迎，因为它结构简单、效率高，像RLE的自然扩展，既能获得高压缩率，又只需几十字节的解压器。 补充讨论： • 存在网站体验争议：一方面有人抱怨WordPress/合作方的隐私弹窗和合规做法繁琐，甚至提供了archive链接绕过；另一方面也有人批评该博客内容虽多但导航困难。 • 争议焦点不在文章结论本身，而在“网站可访问性/易用性”与“技术内容质量”之间的反差。

作者时隔三年重新开始写作。这段时间他一直忙于人工智能领域的工作，与两位合伙人创立了一家名为2Brains的公司。虽然他们共同开展的工作尚未完成，但并未停止——专利已提交，架构已记录，小团队（包括作者本人）仍在继续推进。作者表示写作是他思考方式的一部分，三年不写作让他感到不适。

评论摘要
主要讨论点：科技作家 Bob Cringely 宣布重新开始写作，引发读者对其过去作品的回忆和对其可信度的争议。 不同观点： • **怀旧派**：多位评论者表达对 Cringely 早期作品的喜爱，包括 InfoWorld 专栏（1987-1995）、《Accidental Empires》、纪录片《Triumph of the Nerds》等，认为这些内容有趣且具启发性 • **怀疑派**：部分人质疑其写作持续性，指出他 2023 年也宣称"回归"但只写了 2 篇就消失；还有人讽刺他推广 Web3 项目 • **批评派**：强烈批评 Cringely 的 Minecraft 服务器众筹项目失败，认为他是骗子，对其诚信表示质疑 • **中立观察者**：有人认为批评者过度执着于众筹项目失败，呼吁放下"righteous indignation"，不要骑着"白马"无休止地攻击 补充讨论：评论中提到他目前似乎在开发 AI 芯片项目。争议焦点集中在：Cringely 是否值得信任，以及对其过去项目失败的批评是否合理。怀旧情感与现实失望形成鲜明对比。
