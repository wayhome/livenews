Citing 'severe' math deficits, UC faculty demand a return to SAT tests for STEM

作者: brandonb | 评分: 631 | 评论数: 62 | 发布时间: 2026-05-28 14:13
文章摘要

超过600名加州大学教师呼吁恢复STEM专业申请者的SAT/ACT标准化考试要求。他们指出，自2020年取消考试要求六年来，新生数学准备不足问题严重，教授们常需从中学数学开始补课。加州大学伯克利分校数据显示，20%以上的微积分新生存在基础缺陷。教师认为标准化考试能更可靠地评估学生能力。批评者则认为SAT考试不公平，高中成绩已足够预测大学表现。加州大学系统正在重新审议招生政策，哈佛、斯坦福等名校已恢复考试要求。

评论摘要
主要讨论点：美国加州取消SAT等标准化测试后，大学生数学基础严重不足，教授需要在STEM课程中重教中学数学的问题。 不同观点： • **支持标准化测试派**：认为取消SAT等考试反而加剧不平等。富裕家庭通过私立学校和课外辅导（如俄罗斯数学学校）获得更大优势，而贫困学生失去了通过标准化考试实现阶层跨越的机会。MIT重新恢复SAT要求印证了这一观点。 • **质疑教学责任派**：认为大学教授不应在课堂上重教基础数学，应通过先修课程要求和分级考试筛选学生。有UCLA学生表示从未遇到教授讲中学数学的情况，学生应自行补足知识缺口。 • **批评"公平"政策派**：指出加州教育从追求"平等机会"转向强制"结果平等"，甚至试图禁止高中微积分课程，否认学生天赋差异。社区大学取消分级考试和补习课程后，失败率高达三分之一。 • **技术与教学方法争议**：有教师指出过度强调数字化教学反而造成课堂分心，传统黑板和纸笔练习更有效，但行政部门却要求必须使用iPad等设备。 补充讨论：多位评论者用体育天赋类比数学能力，质疑为何社会接受运动能力差异却不承认智力差异。也有人提到评分虚高问题——学生实际未掌握知识却获得好成绩，导致升学后暴露真实水平。

评论摘要
主要讨论点：Mistral AI作为欧洲AI公司的发展现状及其战略定位 不同观点： • **技术落后派**：Mistral自2025年Q3以来技术严重落后，推理模型表现不佳，120B参数的"小模型"竞争力不及四分之一大小的中国模型（Gemma4、Qwen3.6）。中国实验室（DeepSeek、MiMo、Minimax）表现远超Mistral，欧洲政府部门虽想使用但明知其性能差距。 • **战略优势派**：Mistral专注本地部署和欧洲市场定位明智。BNP Paribas、Abanca等受监管行业客户因数据主权需求必须使用欧洲方案，这是相对美国云服务商的差异化优势。工具调用和结构化输出能力适合Alexa+等场景。 • **商业生存派**：Mistral可能通过"虽然性能差但是唯一可用的欧洲选择"实现盈利，这是悲哀但现实的商业路径。欧洲大型企业高管出席活动，合作伙伴从微软、埃森哲到初创公司，显示商业拓展积极。 • **系统性问题派**：欧洲高税收、过度监管阻碍创新，顶尖人才流向美国公司。欧洲缺乏灵活性和谦逊态度调整方向，AI领域将像半导体一样被少数国家垄断。 补充讨论：有用户反映Mistral正淘汰专用模型（如Devstral），推荐迁移至通用模型但成本暴增近4倍，引发不满。部分人质疑其护城河，认为类似"带数据中心的软件咨询"。

We should be more tired than the model

作者: tosh | 评分: 180 | 评论数: 36 | 发布时间: 2026-05-29 12:12
文章摘要

这篇文章讨论了AI代码生成工具对开发者技能的影响。作者发现使用AI生成代码后，虽然完成了编码任务，但缺少了手写代码时大脑的思考过程，导致技能退化和"脑雾"感。为此，作者提出了几种应对方法：先自己实现再让AI审查、用AI提问而非直接生成、比较多种实现方案、与他人讨论方案、遇到问题先自己思考20分钟再用AI、重读基础书籍和论文、重新实现基础数据结构等。这些方法虽然短期内降低了效率，但长期能巩固自身基础，更好地使用工具。核心观点是：我们应该比模型更累——主动思考而非被动接受。

评论摘要
主要讨论点：AI编程工具对开发者技能保持和工作方式的影响 不同观点： • **积极重构派（simonw）**：通过指导AI进行大量重构（而非直接编写代码）来加深理解，认为主动重构比被动审查代码更能帮助记忆和建立心智模型 • **产品管理转型派（paulmooreparks）**：将编码委托给AI后，开发者应提升到产品管理层面，关注安全性、可访问性等更高层次问题，跳出代码看全局 • **抽象工具派（CraigJPerry）**：认同理解是瓶颈，但不赞同通过重构缓解，主张问题根源在于缺乏更好的抽象工具 • **苏格拉底教学派（d4rkp4ttern）**：让AI以苏格拉底式提问方式测试开发者对问题和解决方案的理解，通过主动思考促进学习和记忆 • **技能焦虑派（sam-cop-vimes, stantonius）**：担心AI工具带来产出压力和就业威胁，反思工具本应让生活更轻松；发现克制使用AI比执行代码更耗费精力 • **品味优先派（adamtaylor_13）**：质疑技能退化的严重性，认为"品味"（判断力）比技能更重要且不易退化，开发者价值在于优雅解决问题而非编写代码 • **委托合理派（peteforde）**：将使用AI类比为团队协作中的委托，认为有效委托让人更聪明而非更笨 补充讨论：多位评论者提到需要在开发中"增加摩擦"以保持深度思考，以及当前AI工具的交互方式（聊天框或自动补全）打断心流状态，需要更好的UI设计。

Real-time LLM Inference on Standard GPUs: 3k tokens/s per request

作者: NicoConstant | 评分: 205 | 评论数: 33 | 发布时间: 2026-05-29 09:47
文章摘要

这篇文章主要讨论了AI推理速度优化问题。核心观点是： 1. **单请求解码速度**对AI代理至关重要，因为代理工作流是串行的（检查→规划→编辑→测试→修改） 2. **内存带宽**而非算力是瓶颈。在批量大小为1时，GPU的内存带宽利用率（MBU）比算力利用率更关键 3. **现有推理软件栈**未充分利用GPU硬件能力。标准数据中心GPU（如H200、MI300X）拥有极高的内存带宽（30+ TB/s），但软件层面存在瓶颈 4. **架构/引擎/内核协同设计**可以突破限制，让GPU达到专用推理硬件的速度水平 文章强调，随着AI代理变得更自主，**智能×迭代速度**成为生产力前沿，快速生成token能显著改善用户体验（从8分钟降至20秒）。

评论摘要
主要讨论点：Kog.ai推出的新推理引擎在H200 GPU上实现了超高token生成速度，但其实用性和公平性引发争议。 不同观点： • **质疑比较公平性**：使用2B小模型对比大型前沿模型不公平，缺少与Taalas（15000 tok/s）等竞品的对比，需要在30B等实用规模模型上验证性能（mungoman2, ilaksh, robmccoll） • **质疑"标准GPU"说法**：H200和MI300X是高端数据中心GPU，不应称为"标准GPU"，有标题党嫌疑（0-bad-sectors, 867-5309, bcjdjsndon） • **技术价值肯定**：恢复了内存带宽与token生成速度的线性关系，在数据中心硬件上实现了消费级显卡的效率表现，demo体验出色（stymaar, rashkov, cataflam） • **实用性担忧**：模型输出质量差、逻辑错误明显，批处理（dynamic batching）和新模型适配能力未知，对speculative decoding等新方法的适用性存疑（blindr, CastFX, joefourier） • **扩展性质疑**：类比小规模线性扩展不代表大规模同样有效，担心扩展到更大模型时遇到瓶颈（robmccoll, arjie） 补充讨论：有用户关注开源计划、多卡通信瓶颈（PCIe限制）等工程实现细节。

评论摘要
主要讨论点：关于Visual C++ 6和90年代游戏开发工具的怀旧讨论 不同观点： • **VC++6的评价**：多数人认为VC++6是微软经典之作，界面清爽、速度快、功能强大（支持断点、堆栈跟踪等），有人使用到2009年。相比之下，Borland C++6被认为不稳定、容易崩溃 • **开发平台选择**：John Carmack在1996年的观点显示Win32成为主流，放弃DOS开发。Linux被视为第二重要平台（黑客比例高），NeXTStep是个人最爱但现实中不得不用NT • **代码质量哲学**：Quake代码库仅2个警告，体现Carmack的高标准。游戏开发界普遍不重视严格工程实践，但个别开发者坚持零警告、大量断言的原则 • **FTP传输问题**：有人指出作者可能不了解FTP的ASCII模式（默认模式），认为二进制模式应该是默认，因为文本文件损坏容易修复，而二进制文件损坏难以恢复 补充讨论：Sean Barrett（stb库作者）至今仍使用VC++6；网站设计简洁实用受到赞赏；Quake引发了对局域网、网络延迟等技术的兴趣；期待Fabien的新书；整个安装过程像"猴岛小英雄"解谜般荒诞

What Is a Dickover?

作者: tambourine_man | 评分: 244 | 评论数: 33 | 发布时间: 2026-05-29 23:54
文章摘要

这篇文章定义并批评了"dickover"这一网页设计模式：指网站或应用故意用弹窗、遮罩层阻挡内容，强迫用户进行不必要的交互（如接受cookie、订阅newsletter、安装app等）。作者认为这种设计无处不在且极其恶劣，用户访问网页就应该直接看到内容，而不是被各种弹窗打断阅读体验。文章还提到了相关但程度较轻的"dickbar"（非模态的部分遮挡条），并用大量实例说明这些设计模式如何破坏用户体验。作者对这种将付费订阅者也当作骚扰对象的做法尤为不满。

评论摘要
