"Chonky" 是一个 Python 库，利用微调过的 Transformer 模型将文本智能地分割成有意义的语义块，可用于问答系统（RAG）。通过 `pip install chonky` 安装后，用户可以导入 `TextSplitter` 类，对文本进行自动分块处理。该库在首次运行时会下载所需的模型，并支持在 CPU 上运行。示例代码展示了如何将长文本分割为多个语义相关的段落。该项目基于神经网络方法进行文本分块，适用于人工智能和机器学习领域中的语义分割任务。

BPS is a GPS alternative that nobody's heard of

作者: sksxihve | 评分: 410 | 评论数: 24 | 发布时间: 2025-04-13 01:31
文章摘要

文章主要介绍了一种鲜为人知的GPS替代方案——BPS（广播定位系统）。作者在NAB展会上意外发现了一个展示BPS的展台，该系统通过ATSC 3.0电视信号提供精确定时，精度可达±10纳秒。BPS旨在为媒体、电力网、5G通信等领域提供可靠的地基时间同步备份，尤其在防干扰方面具有优势。目前，美国约有1,700个电视台可能升级支持BPS，但参与测试的电视台还不多。作者还提到在ASUS展台发现的具备PPS（脉冲每秒）功能的主板。文章最后提供了更多关于BPS和相关技术的资源链接，并表示将在后续视频中深入探讨这一主题。

评论摘要
主要讨论点：ATSC 3.0及其在广播定位系统（BPS）中的应用，以及与GPS等其他系统的比较 不同观点： • Lammy认为，ATSC 3.0的Dedicated Return Channel（专用回传通道）主要用于市场营销和用户数据收集，担心隐私问题，并质疑其技术需求背后的动机。 • geerlingguy指出，ATSC 3.0仍处于实验阶段，部署有限，但其长远计划是通过建立地面传输网络实现不依赖GPS的 timing 信号传输。他还提到，ATSC 3.0的推出面临诸多障碍，包括需要新硬件以及消费者购买意愿低等问题。 • lxgr强调，高功率且经过认证的GNSS替代方案非常必要，尤其在面对越来越多的GPS干扰和欺骗事件时。他批评了美国及NATO国家取消地面导航系统的决定，并指出其他国家（如俄罗斯和中国）保留并发展了类似系统。 • keithwinstein认为，ATSC 3.0并非实现BPS的必要条件，现有DTV传输的短期稳定性已经足够，并提到Rosum在2005年就已经实现了利用电视信号进行定位的功能。 • LeoPanthera指出，ATSC 3.0频道经过加密，不再有免费的开放标准和开源 viewer，这限制了使用Kodi、VLC等软件观看电视的可能性，并对这一决定表示不满。 • hwpythonner质疑是否必须使用FM或TV信号，提出为何不利用现有的蜂窝基站进行timing传输，并比较了蜂窝网络与BPS在精度和多径处理上的差异。 • master_crab认为，BPS可能只在信号重叠较多的城市地区有用，在乡村和水上仍需依赖GPS。 • neuroelectron提到RTK/PPS等其他高精度定位技术，并提供相关模块的参考链接。 • WhyNotHugo对利用广播电视作为BPS基础表示惊讶，认为电视在许多地区已经不再流行。 • skissane询问是否存在DVB-T的等效方案。 补充讨论： • ATSC 3.0的推出和消费者接受度问题，包括新硬件需求和对“个性化广告注入”等功能的不满。 • 利用eLoran等技术实现不依赖GPS的timing传输，并讨论了其在不同应用场景中的优势和局限。 • 对蜂窝网络与广播网络在timing精度、覆盖范围和多径处理上的比较与讨论。 争议焦点： • ATSC 3.0是否主要为了商业利益（如广告和数据收集）而设计，还是真正为了技术进步和服务改进。 • 是否应利用现有蜂窝网络而非新建广播网络来实现BPS。 • 加密和封闭标准对消费者选择权和隐私的影响。

文章摘要

JSLinux是由Fabrice Bellard开发的一个在线平台，允许用户在浏览器中运行Linux或其他操作系统。平台提供多种模拟系统，包括基于x86和riscv64架构的多种操作系统和用户界面选项。例如，x86架构下有Alpine Linux和Windows 2000，riscv64下有Buildroot和Fedora 33。部分系统提供图形界面（X Window）或文本界面（Console/VGA Text），并可通过点击链接启动。某些系统启动时间较长，使用图形界面时需右键点击调出菜单。平台还提供技术文档和常见问题解答。

评论摘要
主要讨论点：Linux VMs 与 Windows 2000 VMs 的运行情况对比 不同观点： • skerit 指出 Linux VMs 无法运行，具体表现为在尝试访问 `https://vfsync.org/u/os/buildroot-riscv64/head` 时遇到 CORS 错误。这表明该用户在使用 Linux 虚拟机时遇到了技术问题，特别是与跨域资源共享（CORS）相关的错误。 • skerit 同时提到 Windows 2000 的虚拟机运行非常顺利，没有遇到类似的问题。这暗示了 Windows 2000 虚拟机的稳定性和正常运行，与 Linux VMs 的问题形成对比。 补充讨论： • 争议的焦点可能在于不同操作系统虚拟机的兼容性和配置问题。Linux VMs 出现了网络或配置问题（CORS 错误），而 Windows 2000 则没有类似的问题，这可能表明问题出在 Linux 环境配置或特定于 Linux 的兼容性问题上。 • CORS 错误的具体原因未被深入讨论，但可能涉及服务器配置、虚拟机网络设置或浏览器安全策略等问题。这可能需要进一步排查虚拟机的网络连接和服务器端的跨域资源配置。 • Windows 2000 虚拟机的顺利运行提供了一个正面的例子，表明至少在某些操作系统上，虚拟机配置是成功的，可以作为一个对比参照来排查 Linux VMs 的问题。
