文章摘要

HeidiSQL发布了首个Linux版本，支持SSH隧道、35种语言翻译、状态栏图标、SQL编辑器中的括号高亮和自动标签恢复等功能。该版本基于Lazarus 3.8和FreePascal 3.2.2开发，但尚不支持MS SQL和Interbase/Firebird，且存在一些已知问题如网格编辑器崩溃和SQL编辑器中无自动换行。对于RedHat系Linux，开发团队计划发布.tgz文件和Flatpak以支持更多发行版。用户反馈AUR安装顺利，并提供了MariaDB配置建议。

主要讨论点：HeidiSQL 的优缺点及与其他数据库工具的比较 不同观点： • **支持与赞赏**： - 长期用户 [igitur] 对作者多年独自开发表示尊重，并期待通过 Lazarus / FreePascal 进行贡献。 - [atmanactive] 认为 HeidiSQL 是最好的桌面 SQL 工具，并鼓励继续努力。 - [sakesun] 和 [mappu] 对 HeidiSQL 的用户体验表示高度赞赏，认为其无可替代。 • **与其它工具的比较**： - [redditor98654] 认为拥有许可证的 Datagrip 更难被击败，尤其在支持数据库种类和 AI 集成方面。 - [sandreas] 提到 DbGate 并询问其与 HeidiSQL 的比较。 - [rd07] 目前使用 DbGate 和 DBeaver，期待尝试 HeidiSQL。 - [rorylaitila] 和 [moron4hire] 都从用户体验角度对 HeidiSQL 和 DBeaver 进行了比较，认为 HeidiSQL 更简洁但有 bug。 • **批评与问题**： - [deergomoo] 提到 HeidiSQL 的历史 bug，如 UI 锁定和异常对话框问题，质疑其稳定性。 - [spapas82] 指出 HeidiSQL 在 PostgreSQL 和 MS SQL Server 上的表现不如 MySQL/MariaDB，存在较多的 bug 和速度问题。 • **技术问题与跨平台体验**： - [mappu] 提到在 Debian 12 和 distrobox Ubuntu 上的安装问题，指出依赖项需要注意。 - [Shorel] 强调 HeidiSQL 的功能丰富，以至于在 Linux 上通过 Wine 使用也在所不惜。 补充讨论： • **功能改进建议**： - [igitur] 提到需要对 SQL 方言进行更好的抽象，以支持更多数据库方言。 • **个人偏好与迁移**： - [mohas] 表示 HeidiSQL 的优秀体验使其一直锁定在 Windows 平台。 争议焦点：HeidiSQL 的稳定性与其他数据库工具（如 Datagrip 和 DBeaver）的功能丰富度之间的比较。用户对 HeidiSQL 的长期 bug 问题表示不满，但对其功能和用户体验仍有较高评价。

本文记录了一次对支付卡终端进行逆向工程的过程，目标设备是Worldline Yomani XR终端。作者最初对该设备的安全性有较高预期，但在拆解和分析后发现了一些安全漏洞。 设备外壳和PCB设计精良，采用多层PCB结构，主处理器为定制ASIC "Samoa II"。虽然没有发现明显的防拆开关，但设备通过板间连接和压力敏感的Zebra条进行防拆检测。此外，关键PCB上还有曲折的 traces 作为物理入侵检测机制。 在尝试探索设备固件时，作者通过拆焊闪存芯片成功提取了未加密的固件内容。固件采用修改过的YAFFS2文件系统，作者编写了一个兼容的文件系统读取器，成功读取了文件系统内容，发现设备运行Linux系统，内核版本为3.6，使用过时的软件组件如busybox和uClibc。 最终，作者意外获得了一个root shell，暴露了设备的安全隐患。
