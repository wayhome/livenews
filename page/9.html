评论摘要
主要讨论点：malloc(0) 的行为及其合理性 不同观点： • [bobmcnamara] 支持 malloc(0) 返回 -1 并增加计数器，认为这有助于检测内存泄漏。这种实现方式通过 free(-1) 来减少计数器，从而追踪内存分配问题。 • [Lvl999Noob] 质疑为何需要多次分配大小为 0 的内存，并建议如果需要唯一地址，可以使用 malloc(1) 代替。同时认为 malloc(0) 应返回常量值如 NULL 或 -1。 • [randomNumber7] 认为分配 0 字节内存没有实际用例，且不关心返回的指针值，因为无法解引用。因此觉得 malloc(0) 应返回 NULL。 • [tptacek] 认为可以通过封装 malloc 来实现所需语义，例如返回 NULL 或某个哨兵指针，以解决标准复杂性问题。 • [AaronDinesh] 主张 malloc(0) 应始终返回 NULL，质疑返回有效指针的合理性。 • [a-dub] 对 0 页在不同系统中的处理方式感兴趣，暗示可能存在不同的行为。 • [eesmith] 提到曾在 AIX 系统上遇到 malloc(0) 返回 NULL 导致程序失败的问题，并通过总是分配 size+1 来解决。 补充讨论： • [carra] 对标题中使用 "some bits" 感到困惑，认为容易引起误解。 • 争议焦点在于 malloc(0) 的合理行为，包括是否应返回 NULL、有效指针或常量值，以及是否有必要支持多次分配大小为 0 的内存。

The probability of a hash collision (2022)

文章摘要

这篇文章主要讨论了哈希碰撞的概率问题。哈希函数将复杂输入映射为一个数字，用于数据存储和加密等领域。当两个不同输入被哈希函数映射到同一值时，就会发生哈希碰撞，这可能导致问题。文章通过“生日问题”来解释碰撞概率：即使有大量盒子（或可能性），随着物品数量增加，碰撞概率也会上升。例如，在有365个可能生日的情况下，30个人中有两人同生日的概率约为70.6%。计算无共享生日的概率后取其补集，即可得到至少一个碰撞的概率。文章提供了具体计算方法，并指出即使物品数不超过盒子数，碰撞概率也会随数量增加而上升。
