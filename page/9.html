Wildlife is watching us, too – and changing their behavior in response

作者: hhs | 评分: 8 | 评论数: 2 | 发布时间: 2026-05-23 22:45
文章摘要

耶鲁大学领导的一项大规模研究发现，野生动物不仅对栖息地改变做出反应，也会因人类的直接存在而改变行为。研究团队使用GPS追踪了美国37个物种（22种鸟类、15种哺乳动物）超过4500只动物，收集了1180万个位置数据点。结合手机数据和卫星测量，研究发现超过65%的物种会根据人类存在改变行为模式。不同物种反应各异：灰狼扩大活动范围以避开人类，渡鸦则扩大觅食区域利用人类食物源，而郊狼倾向于限制活动。研究强调，保护野生动物不仅要关注栖息地丧失，还需考虑人类活动的时间和地点。

评论摘要
主要讨论点：人类对全球生态系统和野生动物的影响 不同观点： • 人类是入侵物种观点：认为人类对生态系统产生负面影响，野生动物最好的应对方式是远离人类。强调人类活动对自然环境的破坏性，将人类本身定位为生态系统的外来入侵者。 • 常识性认知：提出不需要科学研究就能理解人类正在影响全球生态系统这一事实，暗示这是显而易见的问题。 补充讨论：该评论表达了对人类中心主义的批判立场，认为人类活动对野生动物和生态系统造成了系统性的负面影响。评论者采用了较为激进的表述方式，将人类整体视为生态问题的根源。

文章摘要

美国数据中心电力消耗已达全国总量的6%，两年内增长36%，主要由AI热潮驱动。报告警告当数据中心用电超过5%时会引发强烈反对，美国、英国(5.8%)和德国(9.5%)均已越过这一阈值。各州已提出数百项监管法案，部分地区因电力短缺暂停新项目审批至2032年。水资源消耗、"僵尸"工作负载(占3吉瓦)和低效小型数据中心也加剧了问题。2026年全球数据中心支出预计达1万亿美元，其中美国占7000亿。电网承载能力和社区抵制可能成为AI发展的关键制约因素。

评论摘要
主要讨论点：数据中心能源消耗对社会资源分配的影响 不同观点： • **技术优化派（k1w1）**：问题在于资源浪费而非数据中心本身。指出13%的云计算来自"僵尸"工作负载，容器化AI沙盒环境效率低下。主张通过技术改进（如共享架构替代容器）来解决，认为市场会自然淘汰低效方案。 • **市场调节派（bob1029）**：对无限扩张持怀疑态度。强调最终总有人类付费者，机器需求不会真正无限增长，市场机制会自然限制。 • **民生优先派（trueno）**：强烈反对数据中心与民用争夺能源。认为在能源基础设施尚未满足人类需求时，数据中心不应享受公共资源优先权。主张数据中心应自行承担能源基础设施成本，批评将AI与公用事业等同的做法。类比比特币挖矿未能兑现绿色能源承诺。 • **产业对比派（Nasrudith）**：认为反对数据中心的立场自相矛盾。指出制造业回流美国造成的负面影响远超数据中心，批评这种选择性反对。 补充讨论：核心争议在于数据中心是否应与民生争夺有限的能源资源，以及技术效率提升能否解决根本矛盾。freakynit分享的报告暗示这场"电力战争"正在升级。

Slumber a TUI HTTP Client

作者: jicea | 评分: 183 | 评论数: 21 | 发布时间: 2026-05-22 04:29
文章摘要

Slumber是一个基于终端的HTTP客户端，用于与REST和其他HTTP服务交互。它提供两种使用模式：终端用户界面(TUI)和命令行界面(CLI)。TUI模式支持交互式发送请求和查看响应，CLI模式适合快速请求和脚本编写。Slumber的设计目标是易用、可配置和可共享，配置通过YAML格式的"请求集合"文件定义，两种模式共享相同的配置结构。

评论摘要
主要讨论点：关于 Slumber（一个终端 HTTP 客户端工具）的评价和替代方案 不同观点： • **积极评价派**：认为工具看起来精致、易用，适合快速上手，赞赏其 Neovim 集成支持，愿意在日常工作中尝试 • **替代方案推荐派**：提出多个类似工具作为替代，包括 Emacs 的 verb、Resterm（使用 .rest/.http 文件）、posting（另一个 TUI 客户端） • **技术细节质疑派**：对 YAML 配置格式表示困惑，认为 YAML 比 JSON 更复杂、可读性差且有安全隐患；质疑文档中"与其他 HTTP 客户端交互"的表述可能是笔误 • **功能需求派**：希望支持导入/导出 Postman 集合和环境变量、支持 OpenAPI 规范自动生成查询、显示生成的 curl 命令 • **实用性问题派**：指出 Mac 上删除键不可用的问题、JSON 响应显示区域太小（10-20 行不够用） • **开发者反思派**：认为此类小工具现在创建太容易（不到一小时），导致分享价值降低，人们可以轻松定制自己的版本 补充讨论：关于 TUI 术语的学术讨论——应该是"Text User Interface"而非"Terminal User Interface"，还有人提出 CHUI（Character User Interface）作为对比概念。

Deno 2.8

作者: roflcopter69 | 评分: 410 | 评论数: 23 | 发布时间: 2026-05-22 11:23
文章摘要

Deno 2.8 发布，这是迄今最大的次要版本更新，新增多个子命令： **deno audit fix** - 自动升级有漏洞的npm包到最近的补丁版本 **deno bump-version** - 更新deno.json或package.json中的版本号，支持patch/minor/major增量，在工作区中可同步更新所有成员包 **deno ci** - 专为CI环境设计的安装命令，强制使用lockfile并在不匹配时报错 **deno pack** - 将Deno/JSR项目构建为可发布到npm的tarball，自动转译TypeScript、生成类型声明文件、重写模块标识符，使代码能在Node.js生态系统中运行 升级命令：`deno upgrade`

评论摘要
主要讨论点：Deno、Bun、Node.js 三种 JavaScript 运行时的对比与选择 不同观点： • **Deno 优势派**：认为 Deno 的权限模型、原生 TypeScript 支持、Unix 哲学理念是核心优势，困惑为何开发者选择 Bun 而非 Deno。强调其安全性（默认禁用安装脚本）和简洁性，适合小型服务。 • **Node.js 稳定派**：认为 Node.js 是稳定解决方案且会长期存在，现已支持 TypeScript 和单文件可执行打包，无需迁移。 • **Bun 实用派**：Bun 虽混乱但速度快，标准库包含所有功能，且被 Anthropic 收购，发展势头强劲。 • **Deno 方向担忧派**：批评 Deno 为商业原因不断向 Node 兼容性妥协（Node 兼容性从 40% 升至 75%，默认包含 lib.node 类型），偏离初衷。认为若继续此趋势，使用 Deno 的理由将越来越少。 • **AI 时代技术选择派**：认为在 AI Agent 时代，应优先使用 Rust 和 TypeScript，因其类型安全、内存安全和大量代码语料库便于 AI 理解。 补充讨论：有人提到 Deno 团队谦逊但可能面临资金压力（拒绝捐赠），建议提供订阅服务。也有人质疑为何浏览器仍不原生支持 TypeScript。整体而言，社区对 Deno 的技术认可度高，但对其商业化方向和实际采用率存在疑虑。
