文章摘要

文章认为，连续八小时睡眠是现代9-5制度和人工照明的产物。传统地中海农耕社会顺应日照与季节：夏有午睡、冬有“二段睡”。作者赞赏希腊仍保留午休与分段工作，认为这更符合自然节律。

评论摘要
主要讨论点：午睡/分段睡眠（siesta、polyphasic sleep）与现代9-5工作制、商店营业时间是否冲突，以及这种作息到底是“自然”还是被浪漫化。 不同观点： • 质疑派：西班牙用户认为午睡被过度美化，虽有健康益处，但会压缩白天可用时间；8小时工作制下很难安排，学校和工作制度也因此混乱。 • 支持派：有人认为地中海作息更灵活，下午下班后商店、牙医、餐馆仍开着，方便办事；也有人觉得炎热季节“晚睡+午休”更合理。 • 历史/科学争论：有人说分段睡眠是现代工业社会前就存在的普遍模式；反对者指出缺乏确证，工业化并非处处同步。也有人补充现代平均睡眠比百年前少，睡眠时长本身就受现代生活影响。 • 现实批评：有人认为9-5和过早开工、过少服务时间在“惩罚”上班族，连办事、取包裹都困难。 • 折中观点：睡眠应因人因地而异，受纬度、光照、孩子、疲劳程度影响；与其坚持某种“标准”，不如多实验找适合自己的节奏。

Git Is Not Fine

作者: steveklabnik | 评分: 55 | 评论数: 9 | 发布时间: 2026-05-15 17:51
文章摘要

文章批评 Git 主要擅长分布式存储，却把协作工作流当成附带功能，导致堆叠 PR、异步开发、追踪后继提交/重写历史等场景很别扭；作者借此推荐 jj，认为它更适合现代分布式协作。

评论摘要
主要讨论点：Git 是否足以应对多分支/堆叠 PR、单仓库（monorepo）并行开发，以及 jj 等新工具是否真的有必要。 不同观点： • 认为 Git 已够用：多人表示自己靠普通 commit+rebase 就能处理，堆叠 PR 只是额外复杂度；有人甚至觉得 20 张图“过度证明”，文章把问题讲得太玄。 • 认为复杂场景下 Git 很痛苦：在 monorepo、5–50 个并行分支、嵌套分支时，手动 rebase/切分改动很麻烦，工作常要拆成多个依赖分支，worktree/stash 也不够用。 • 工具派/自动化派：Git 本身没问题，关键是脚本化流程；有人用自写 rb.sh/lb.sh 管理堆叠分支，也有人直接用 AI 辅助 rebase、改提交信息。 • 新工具支持者：部分人表示已安装 jj，期待它解决“树状”工作流带来的痛点；也有人提到类似 Mercurial 的内部系统体验更好。 • 反对过度工程：另一派认为这是“为了工具而工具”，应坚持基础用法；若频繁需要额外工具，说明团队流程或工程设计本身有问题。 补充讨论：争议焦点主要在“Git 的分布式设计是否天然限制了某些高级工作流”，以及“堆叠 PR/新 VCS 是刚需还是少数人的过度复杂化”。

文章摘要

评论摘要
