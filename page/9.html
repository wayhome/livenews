Digitising CDs (a.k.a. using your phone as an image scanner)

作者: JNRowe | 评分: 20 | 评论数: 3 | 发布时间: 2025-07-28 04:47
文章摘要

作者在雨中发现了一堆90年代的“软件杂志”，并花时间清理、晾干和整理。这些杂志通过法国的一种名为“Commission paritaire”的机制获得国家补贴，包含足够的原创内容以满足补贴要求，并附带有趣的软件CD。这种模式在法国很特别，如今仍能看到附带音乐CD、DVD或玩具的杂志。90年代，Diamond Editions出版社利用这一机制推出了包含正版软件的杂志，如ClarisWorks和CorelDraw。作者试图数字化这些CD封面，但由于反光问题，改用数码相机拍摄，并通过Darktable软件进行调整，最终获得清晰图像。这些杂志和CD已被上传至Archive.org供下载。

评论摘要
主要讨论点：通过软件或技术手段优化对CD的图像处理过程，包括去 skew（倾斜校正）、批量处理以及探讨从照片中恢复数据的可能性。 不同观点： • **Igrom的观点**：Igrom建议使用手机上的相机软件进行CD图像的自动处理。他提到一些手机相机具有文档模式，能够自动检测边缘、裁剪和去 skew，例如他的Xiaomi Redmi Turbo 3。他建议打印一个比CD稍大的黑色矩形框，以便相机软件能够捕捉CD的轮廓，随后通过批量处理修剪图像的白边，从而减少手动操作。 • **dvh的观点**：dvh提供了一种技术性的解决方案，使用ffmpeg命令行工具手动校正图像的透视变形。他给出了具体的命令示例，通过提供图像四个角的坐标来实现图像的去 skew操作。这种方法更加技术性，适合有技术背景的用户。 • **sandbach的观点**：sandbach提出了一个不同的问题，即是否可以通过照片恢复CD上的数据。他质疑是否有可能从CD闪亮一面的照片中恢复数据，这是一个关于数据恢复技术的假设性问题，引发了对技术可能性的讨论。 补充讨论： • **技术实现的差异**：Igrom的方法侧重于利用现有的手机软件功能来简化图像处理过程，而dvh的方法则依赖于命令行工具和手动输入坐标，更加适合需要高精度和自定义控制的用户。 • **争议焦点**：sandbach提出的从照片恢复CD数据的可能性引发了对技术极限的思考，但其他评论并未直接回应这一问题，显示出讨论方向的分歧。 • **实际操作的可行性**：Igrom和dvh的方法都提供了减少手动劳动的思路，但其实际效果可能依赖于软件的识别精度和用户的技术水平。

Implementing dynamic scope for Fennel and Lua

作者: Bogdanp | 评分: 31 | 评论数: 1 | 发布时间: 2025-07-23 20:49
文章摘要

本文讨论了在Fennel和Lua中实现动态作用域（dynamic scoping）的方法。Lua虚拟机不支持动态作用域，Fennel也没有类似Clojure的`Var`概念。然而，通过使用Lua的`debug`库，可以模拟Clojure等Lisp语言中的动态作用域。作者希望实现一个更符合Lisp习惯的动态作用域机制，而不是通过显式引用变量名的方式。 文章首先解释了词法作用域（lexical scoping）和动态作用域的区别。词法作用域下，变量仅在其定义的代码块内有效；而动态作用域允许变量在特定动态范围内像全局变量一样被访问。作者通过一个代码重构的例子展示了词法作用域的局限性，并对比了Clojure中使用`binding`实现动态作用域的方法。 最后，作者提到可以参考Leafo的指南来实现这一特性，并计划在fennel-cljlib项目中继续推进这一工作。

评论摘要
主要讨论点：动态绑定与隐式上下文对象在脚本语言设计中的使用和优劣比较 不同观点： • **支持使用隐式上下文对象**：tikotus认为使用一个**不可变的隐式上下文对象**可能比动态绑定更适合他的需求。他的主要论据是，隐式上下文对象能够覆盖大多数常见用例，并且在处理**协程**（coroutines）时更加直观和可预测，减少意外行为。 • **对动态绑定的兴趣与疑虑**：tikotus提到他对**动态绑定**的概念很感兴趣，尤其是在为游戏开发设计的脚本语言中。但他对动态绑定在协程中的表现存在疑问，似乎不确定动态绑定如何在协程环境中有效工作。 补充讨论： • **可预测性与意外行为**：tikotus强调了使用隐式上下文对象的一个优点，即它能够减少使用中的“意外”。这表明他可能认为动态绑定在某些场景下，尤其是涉及协程时，可能会引入不易察觉的复杂性或不可预测性。 • **协程的支持**：tikotus特别提到自己是**协程的频繁使用者**，因此他关注的是哪种方法能更好地支持协程操作。他似乎认为隐式上下文对象在这方面更具优势。 • **适用场景的考虑**：tikotus在动态绑定和隐式上下文对象之间摇摆不定，表明他仍在评估哪种方法能更好地满足其脚本语言的具体需求，尤其是针对游戏开发的特殊场景。 争议焦点：动态绑定在协程环境下的适用性和可预测性是争议的核心，tikotus显然对这一点存在疑虑。

Tinyio: A tiny (~200 line) event loop for Python

作者: tehnub | 评分: 111 | 评论数: 7 | 发布时间: 2025-07-22 22:02
文章摘要

**tinyio** 是一个简化版的 Python 事件循环库，仅约200行代码，旨在解决 **asyncio** 的一些复杂性和错误处理问题。它适用于简单场景，当任何协程出错时，整个事件循环会崩溃，所有协程都会取消。与 **asyncio** 不同，它使用 **yield** 而不是 **await** 来暂停和恢复协程。 ### 主要特点： 1. **简单性**：没有 **futures** 或 **tasks**，API 非常少，包括 **Loop**、**run_in_thread**、**sleep** 和 **CancelledError**。 2. **错误处理**：一个协程出错会取消所有协程，错误会传播到整个事件循环和线程中运行的同步操作。 3. **嵌套支持**：允许嵌套事件循环。 4. **线程支持**：通过 **run_in_thread** 可以在线程中运行同步函数，并返回可被 **yield** 的协程。 5. **语法**：使用 **yield** 来暂停协程，支持等待单个或多个协程。 ### 示例： ```python import tinyio def slow_add_one(x: int): yield tinyio.sleep(1) return x + 1 def foo(): four, five = yield [slow_add_one(3), slow_add_one(4)] return four, five loop = tinyio.Loop() out = loop.run(foo()) assert out == (4, 5) ``` ### 安装： ```bash pip install tinyio ``` ### 为什么用 **yield** 而不是 **await**： 因为 **await** 语法需要额外定义如 **tinyio.Task** 这样的类，而 **yield** 更简单直接。

评论摘要
主要讨论点：关于一个名为tinyio的Python库的用法、设计选择以及与其他类似库的比较 不同观点： • [patrickkidger] 认为tinyio库相对简单，功能直接，预期不会有太多疑问。他对回答问题持开放态度，但觉得库本身较为直白。 • [codethief] 对库中使用`yield`而不是`await`表示好奇，并询问这样选择的原因。他还提到了在不同库中实现类似功能的术语差异（如'gather'和'nursery'）。 • [kstrauser] 提到了tinyio的灵感可能来源于Python早期的一个名为Tulip的异步实验，并提供了一个相关链接以供参考。 • [unsnap_biceps] 作为一个不太熟悉Python的开发者，对如何将一个函数标记为协程但又不使用`yield`语句表示困惑。他还提到了一些丑陋但有效的技巧（如使用`if False: yield`），并质疑这种做法是否影响执行或仅是为了IDE识别。 • [moreati] 对使用` as `的导入方式是否会影响运行时行为表示疑问，或者这仅仅是一种风格选择。 补充讨论： • [jojohohanon] 提出了tinyio与Twisted库是否有相似之处的疑问，暗示可能存在某些设计上的借鉴或对比。 • [gjvc] 提供了另一个相关库curio的链接，引导人们参考另一个实现异步功能的库，可能暗示tinyio并不是唯一的选择。 争议焦点： • 使用`yield`而非`await`的合理性是讨论中的一个焦点，[codethief] 和 [unsnap_biceps] 都对这种设计选择表示了不同的疑惑和看法。 • [unsnap_biceps] 对Python中标记协程的技巧表示不满，认为有些丑陋，并质疑其必要性。 总结来看，讨论主要围绕tinyio库的设计和使用细节展开，包括与其他库的比较、语法选择的原因以及对不熟悉Python的开发者的一些困惑解答。

Yes, the Book of PF, fourth edition is coming soon

作者: turtleyacht | 评分: 123 | 评论数: 6 | 发布时间: 2025-07-23 11:04
文章摘要
