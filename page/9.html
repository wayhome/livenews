文章摘要

Weave 是一个 Git 的实体级语义合并驱动工具。它通过 tree-sitter 解析代码，按函数和类进行合并，而非传统的逐行合并。当两个代理编辑同一文件的不同函数时，Weave 能实现无冲突的干净合并。 **核心特性：** - 支持 28 种编程语言和 5 种数据格式 - 在 31 个合并场景测试中达到 100% 成功率（Git 仅 48%） - 提供三层架构：合并驱动、CRDT 状态协调、MCP 服务器 - 已处理 4,917 次真实文件合并，零回归问题 **安装：** `brew install weave && weave setup`

评论摘要
主要讨论点：关于语义化合并工具（Weave）的评价，以及Git合并冲突解决方案的讨论 不同观点： • **支持者观点**：认为基于AST/语义的合并优于传统行级合并，LLM可以理解代码意图从而更好地解决冲突，工具理念很好值得探索 • **质疑者观点**：认为过度强调"agent"而忽视人类用户需求，合并冲突本质是协作和架构问题的症状，不应只靠工具解决 • **实践者反馈**：有用户报告Weave存在静默数据损坏问题且无法修复，实际测试中除TypeScript外表现不如Mergiraf • **替代方案支持者**：提出词级diff、Mergiraf等其他解决方案可能更实用，不需要复杂的语义分析 补充讨论： - 多位评论者提到Mergiraf作为成熟的替代方案 - 有人指出网站内容质量差（"slop"），缺乏清晰的使用说明和效果对比 - 讨论延伸到agent协作协议、极限编程的频繁集成、以及更好的diff可视化工具需求 - 锁文件冲突被认为是常见但通常不需要智能合并的场景
