Show HN: A web browser agent in your Chrome side panel

作者: parsabg | 评分: 116 | 评论数: 20 | 发布时间: 2025-05-18 11:48
文章摘要

BrowserBee 是一个开源的 Chrome 扩展程序，通过自然语言控制浏览器操作。它利用大型语言模型（LLM）解析指令并制定计划，同时使用 Playwright 实现强大的浏览器自动化功能。BrowserBee 注重隐私保护，所有操作均在浏览器内完成（LLM 除外），可安全地与登录网站交互，无需后端基础设施。它支持多种 LLM 提供商，如 Anthropic、OpenAI、Gemini 和 Ollama，并能跟踪 token 使用情况和费用。此外，它还提供多种浏览器工具，如导航、标签页管理、交互、观察、鼠标和键盘操作等，并具有记忆功能，可保存有用的操作序列以便将来使用。

评论摘要
主要讨论点：围绕浏览器扩展和LLM（大型语言模型）应用的技术方案、隐私安全、跨浏览器支持及用户体验的讨论。 不同观点： • **关于信息优化与安全性的讨论：** - dataviz1000认为可以通过使用堆叠上下文（stacking context）和缓存DOM结构，将发送给LLM的信息量减少100倍。同时指出Playwright和Chrome DevTools Protocol (CDP) 结合会带来安全问题，特别是涉及银行和敏感账户的操作。 - 他建议自己实现功能，而不是依赖Playwright，并提出通过提示用户点击按钮来处理需要可信事件的场景。 • **关于会话模板化和隐私保护的建议：** - nico对项目表示赞赏，并建议增加会话模板化功能，使会话可以像电子邮件模板一样使用占位符标签。同时也提到通过使用本地LLM（如ollama）实现更注重隐私的方案。 • **关于跨浏览器支持的需求：** - dbdoskey和donclark提到希望该扩展可以支持Firefox等其他浏览器，指出Mozilla的Orbit未能满足需求。 • **关于类似项目和功能简化的分享：** - stoicfungi分享了自己构建类似Chrome扩展的经历，并提到为了简化功能而移除了交互模式。 • **关于内容发送和隐私安全的疑问：** - barbazoo和hoppp对内容是否发送到LLM以及是否涉及密码发送提出疑问，质疑项目的隐私安全性。 - krembo和rizs12提到Chrome Canary已经内置Gemini Nano，无需调用第三方LLM API，并质疑扩展是否符合隐私优先的原则。 • **关于模型选择的讨论：** - matula对Ollama模型硬编码为Qwen3和Llama 3.1表示不满，建议增加自定义配置功能以支持用户选择的模型。 • **关于开发历程和未来计划的询问：** - m0rde对项目的开发历程和是否依赖AI代理编写代码表示兴趣，并询问了 monetization（商业化）和捐赠的打算。 • **用户遇到的错误问题：** - saadshamim报告使用Gemini和OpenAI API时遇到错误，即使使用有效的新API密钥也无法解决。 • **关于LLM执行DOM操作的能力：** - 0xd1r询问该扩展是否可以进行DOM操作，例如填写表单，或者是否需要为每个特定网站结构化LLM的响应。 补充讨论： - 多个评论提到了隐私和安全问题，特别是涉及到与敏感网站（如银行）的交互以及是否将数据发送到LLM。 - 对跨浏览器支持有明确需求，尤其是Firefox用户。 - 用户对模型选择和自定义配置功能有较高期望，希望可以根据个人偏好选择LLM模型。 - 一些用户对项目的技术实现细节（如DOM操作和错误处理）表示关注，并提供了反馈。

Spaced repetition memory system (2024)

作者: gasull | 评分: 259 | 评论数: 10 | 发布时间: 2025-05-18 15:48
文章摘要

spaced repetition记忆系统结合了测试效应和间隔效应，有效帮助记忆大量信息，不仅限于死记硬背，还能促进概念理解。最早的消费级系统是Piotr Wozniak创建的Supermemo。此类系统包括传统工具如Supermemo、Mnemosyne、Anki，以及一些变体应用。尽管它们能引导注意力、促进应用和创造，但编写有效的提示较为困难，且系统收益不会立刻显现。许多人因不良记忆经历或认为记忆对深度创造不重要而忽视SRS。然而，SRS能通过自动化记忆过程加速学习初期的痛苦阶段，并提升参与度。关键在于优化复习过程的情感连接和提示质量。

评论摘要
主要讨论点： spaced repetition systems（间隔重复系统）的使用体验、工具推荐、内容创建与准确性、系统适用性及长期效果 不同观点： • [vjk800] 认为间隔重复系统中的记忆内容难以选择，重要的东西自然而然就记住了，不重要的做卡片复习感觉像无意义的家务。 • [lovestory] 推荐了一个漫画来帮助理解间隔重复的概念，认为对新手有帮助。 • [golly_ned] 强烈推荐 RemNote 作为间隔重复和笔记工具，强调其易用性、AI集成和功能强大，特别适合学习和实时做笔记，但提到在网络不稳定时的bug问题。 • [pillefitz] 受启发开发了 ReadBoost.io，将Q&A和SRS嵌入ePub中，认为个人使用效果不错，但承认可能仍有bug。 • [navbaker] 寻求预制卡片或特定学习内容的互动资源，例如钢琴和弦记忆。 • [dpkirchner] 认为编写有效的记忆卡片需要专业知识，担心自己编写的卡片可能导致错误记忆。 • [dmazin] 推荐了一篇关于如何编写好提示的博客文章，认为这篇文章帮助他理解了间隔重复的正确使用方法。 • [max_] 询问是否有仅用于间隔重复的Android应用推荐。 • [synergy20] 认为间隔重复系统适合短期冲刺学习，但不适合长期深度思考和学习。 补充讨论： • 工具和资源推荐是讨论中的一个重要部分，用户分享了多个实用工具和网站链接，如RemNote和ReadBoost.io。 • 争议的焦点包括用户对创建有效记忆卡片的信心不足以及间隔重复系统的长期学习效果。 • 不同用户对间隔重复系统的适用场景有不同看法，有的认为适合日常记忆任务，有的则认为更适合短期学习。 • 系统易用性和功能性也是讨论重点，一些用户如[golly_ned]对RemNote的AI集成和界面设计表示赞赏，但提到在特定情况下会出现技术问题。

Coding without a laptop: Two weeks with AR glasses and Linux on Android

作者: mikenew | 评分: 942 | 评论数: 94 | 发布时间: 2025-05-14 15:11
文章摘要

本文介绍了作者如何在手机上运行完整的Linux桌面环境，而无需使用虚拟机或替换操作系统。通过chroot容器，作者成功运行了如i3窗口管理器、Firefox浏览器等原生arm64程序。作者为了实现无需携带笔记本电脑的旅行工作模式，搭配了折叠键盘和AR眼镜，利用手机的DisplayPort功能驱动显示。整套设备包括二手的Pixel 8 Pro手机、Xreal Air 2 Pro AR眼镜和折叠键盘，总成本为636美元。 这套设置让作者可以在户外、咖啡店、飞机上等各种场所工作，具有便携性和自由度。尽管搭建Linux环境有一定难度，但最终实现了如Neovim编程、Flutter调试等开发功能。作者认为，这种设置带来了笔记本电脑无法提供的便携和自由感，特别适合户外工作。不过，过程中也遇到了一些困难和细节问题。

GitHub Copilot: Meet the new coding agent

文章摘要

GitHub推出了一款新的编码代理，集成于GitHub Copilot中。该代理通过GitHub Actions提供安全、可定制的开发环境，当用户将GitHub issue分配给Copilot或在VS Code中提示时开始工作。代理会在草案拉取请求中提交代码更改，并记录每一步操作，用户可实时跟踪。代理处理低至中等复杂度的任务，如添加功能、修复错误、重构代码等，且需要人工批准才能运行CI/CD工作流，确保安全。代理还支持通过Model Context Protocol访问外部数据，并能处理图片。完成任务后，代理会通知用户审查，并根据反馈自动提出代码更改。该工具旨在帮助开发者专注于更高价值的工作。

$30 Homebrew Automated Blinds Opener

作者: busymom0 | 评分: 237 | 评论数: 21 | 发布时间: 2025-05-18 17:05
文章摘要
