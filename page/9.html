TIL: You can make HTTP requests without curl using Bash /dev/TCP

作者: mrshu | 评分: 519 | 评论数: 56 | 发布时间: 2026-06-16 16:40
文章摘要

这篇文章介绍了如何在没有 curl 或 wget 的精简容器中使用 bash 发送 HTTP 请求。核心方法是利用 bash 的 `/dev/tcp` 特性直接打开 TCP 套接字，手动构造 HTTP 请求并发送。通过 `exec 3<>/dev/tcp/host/port` 打开连接，用 `printf` 写入 HTTP 请求头，用 `cat` 读取响应。需要注意：这不是真正的 HTTP 客户端，不支持 TLS、重定向等高级特性；需添加 `Connection: close` 头避免连接挂起；这是 bash 特有功能，非 POSIX 标准。适合在受限环境下快速测试连接，日常工作仍应使用 curl。

评论摘要
主要讨论点：使用Bash的/dev/tcp功能手动发送HTTP请求的技术实现和实用性争议 不同观点： • **支持派**：认为这是很酷的技巧，在没有curl/wget的容器环境中非常实用（mrshu, yread）；是理解计算机底层原理的好方法，"没有魔法"的启蒙（xenadu02） • **技术纠正派**：强调Bash只是打开TCP socket而非真正的HTTP客户端，手写HTTP解析会有问题，生产环境不应使用（basilikum, 1vuio0pswjnm7）；建议用nc、socat等专业工具 • **替代方案派**：提供其他解决方法如nsenter、Perl IO::Socket（timwis, sam_lowry_）；Plan 9的/net更优雅（gatestone） • **兼容性讨论**：这是Bash特性非POSIX标准，dash不支持；Debian曾默认禁用此功能直到2009年（dredmorbius, Coelacanthus） 补充讨论：多数人认为这对调试、学习、临时需求有价值，但不适合生产环境；example.com成为测试首选因为少数仍支持HTTP的域名；有人分享CTF比赛中利用此技巧绕过限制的案例。

10Gb/s Ethernet: switching to a Broadcom SFP+ module

作者: gpjt | 评分: 184 | 评论数: 21 | 发布时间: 2026-06-16 17:48

主要讨论点：Letterboxd面临所有权变更，用户对其未来和替代方案的看法 不同观点： • **反对Letterboxd评论质量**：认为平台充斥大量低质量的单行笑话式评论，希望有字数过滤功能，不希望"Twitter化"的电影评论体验 • **支持联邦化替代方案**：认为Letterboxd的功能可以被去中心化方案替代，其元数据主要来自TMDB，不反对Letterboxd消失以推动更可靠的替代品 • **质疑IMDB亏损说法**：指出IMDB有订阅服务、数据授权、广告收入和2.5亿月访问量,不太可能是亚马逊的"引流产品" • **只需基础功能用户**：仅需要观影清单和流媒体平台查询功能，寻求简单替代方案 • **crowdfunding计划不可行**：批评众筹10万美元试图收购Letterboxd的计划缺乏实际可行性和资金来源说明 • **认为Letterboxd无害**：相比Goodreads的糟糕UI和有毒用户,Letterboxd问题较小，且容易被替代 • **强调UI优势**：认为Letterboxd相比IMDB的核心优势在于优秀的用户界面 补充讨论：争议焦点集中在平台价值评估上——是否值得拯救，以及什么才是理想的电影社区平台。
