JEP 506: Scoped Values final for Java 25

作者: ludovicianul | 评分: 28 | 评论数: 3 | 发布时间: 2025-04-15 11:17
文章摘要

JEP 506 提出引入 "scoped values" 机制，允许方法在线程内及其子线程中共享不可变数据。相比线程局部变量（ThreadLocal），scoped values 更易于理解和推理，具有更低的空间和时间成本，尤其在与虚拟线程（JEP 444）和结构化并发（JEP 505）结合使用时。该机制经历了多个预览和改进阶段（JEP 429, JEP 446, JEP 464, JEP 481, JEP 487），并计划在 JDK 25 中正式引入。其目标包括易用性、可理解性、健壮性和高效性，但不旨在改变 Java 语言或废弃 ThreadLocal API。Scoped values 解决了在方法间传递共享数据时的繁琐问题，尤其在大型程序中不同组件间传递上下文时非常实用。

评论摘要
主要讨论点：Java中引入ScopedValue作为ThreadLocal的替代方案的适用性和潜在优势 不同观点： • Pet_Ant认为ScopedValue提供了一种了解变量生命周期的方法，适合处理大量数据，但对于大多数企业级CRUD应用而言可能并不适用。他提到ScopedValue的语法并不吸引人，并猜测这可能是一种"monad"（虽然他自称不是函数式编程专家）。 • skerit对该提案表示感兴趣，认为自己在某些场景下可能会使用ScopedValue。 • djenndhxhd指出，如果不小心处理， tramp参数（方法中为了传递数据而增加的额外参数）会很常见，并表示认同该提案的价值。 补充讨论： • Pet_Ant提到虚拟线程的引入预期会大幅增加运行线程的数量，传统的ThreadLocal在这种情况下可能不适用，因此引入了ScopedValue。 • 争议的焦点可能在于ScopedValue的适用范围及其在不同类型应用中的实际价值，特别是对于企业级CRUD应用的适用性存在分歧。 • 对ScopedValue是否属于monad的讨论表明，部分开发者对新特性在函数式编程中的定位存在疑问。 总体而言，讨论围绕ScopedValue的实际应用价值及其在不同开发场景中的潜在优势和局限性展开。

Behind the 6-digit code: Building HOTP and TOTP from scratch

作者: dogacel | 评分: 230 | 评论数: 24 | 发布时间: 2025-04-11 13:06
文章摘要

这篇文章主要介绍了基于一次性密码（OTP）的认证机制，特别是HOTP和TOTP的工作原理。OTP是一种用于动态生成密码的技术，有效防止重放攻击。与传统密码不同，OTP每次使用后即失效，或在限定时间内有效。 文章首先解释了OTP的基本概念，然后详细介绍了HOTP（基于计数器的一次性密码）和TOTP（基于时间的一次性密码）。HOTP通过一个递增的计数器生成密码，而TOTP则使用当前时间作为计数器，通常以30秒为间隔更新密码。 文章进一步说明了TOTP的生成公式，强调了密码生成依赖于共享的密钥，且该算法必须是可预测且同步的，以确保客户端和服务器生成相同的密码。TOTP的优势在于利用时间同步，避免了计数器同步问题，并减少了恶意用户收集密码的可能性。 文章最后提到，HOTP和TOTP已被标准化，并广泛用于双因素认证（2FA）系统中。

评论摘要
主要讨论点：TOTP及HOTP等一次性密码技术的工作原理、应用场景及其实施细节 不同观点： • ucarion认为，"忘记密码"流程中的六位验证码虽然是一次性密码（OTP），但不属于HOTP或TOTP，因为没有像TOTP那样通过QR码注册密钥的步骤。他还提出可以用公钥加密代替HMAC，并指出WebAuthn已经实现类似概念。此外，他还提醒要防范暴力破解。 • 3eb7988a1663提供了简短的Python实现以帮助理解TOTP原理，并分享了一个20行代码的GitHub链接。 • sksxihve质疑为什么银行仍然使用短信2FA而不是TOTP，并询问是否存在监管问题。 • Steve6分享了自己创建API生成TOTP码的经验，并提供了一个用于测试的API链接（https://totpapi.com），希望能帮助其他人。 • notpushkin怀疑Facebook在密码恢复时使用的是随机生成的数字，而不是基于HOTP/TOTP的方案。 • gbraad分享了自己使用zsh、openssl和xxd创建的命令行TOTP工具，并提到11年前曾为诺基亚手机开发过类似应用。 • yuliyp确认Facebook的登录/账户恢复码不是TOTP/HOTP，而是随机数，并建议通过解码QR码来验证实现。 • DarkCrusader2提供了另一篇关于TOTP的简洁文章链接。 • ryandv推荐了RFC 4226和RFC 6238作为学习TOTP和HOTP的入门资料，并提到自己曾用Rust实现过这些标准。 • thatkid02提供了自己关于JavaScript双因素认证的文章链接。 • rothfuss对文章中的时钟问题感到困惑，并质疑文章中的图片是否为AI生成。 • coppsilgold建议在账户上设置TOTP以获得更好的待遇，并提到一些密码管理器（如KeepassXC）集成了TOTP功能，但也指出这可能在某些情况下违背2FA的初衷。 补充讨论： • 对TOTP和HOTP的实现细节存在不同理解，尤其在密钥注册和随机数生成方面。 • 有人提到银行继续使用短信2FA可能涉及监管问题，但未有明确答案。 • 对Facebook在密码恢复过程中使用随机数而非TOTP的怀疑引发了对具体实现的讨论。 • 提供了一些实用工具和代码实现以帮助理解和应用TOTP技术。 • 对文章内容（如时钟问题和图片质量）的批评和疑问。

2025年4月14日，英特尔宣布将Altera业务的51%出售给技术投资公司Silver Lake，交易价值87.5亿美元。这使Altera成为最大的纯FPGA半导体解决方案公司，并实现运营独立。英特尔将保留Altera的49%股份，继续参与其未来成功。Raghib Hussain将接替Sandra Rivera，成为Altera的新任首席执行官，他曾在Marvell和Cavium等公司担任要职。此次交易预计在2025年下半年完成，届时Altera的财务结果将不再并入英特尔的综合财务报表。2024财年，Altera收入为15.4亿美元，GAAP营业亏损6.15亿美元。英特尔期望通过此次交易聚焦核心业务，并借助Silver Lake的行业专长加速Altera的发展。

Monte Carlo Crash Course: Sampling

作者: ibobev | 评分: 98 | 评论数: 2 | 发布时间: 2025-04-14 14:54
文章摘要
