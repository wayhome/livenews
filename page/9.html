79% of OpenBSD kernel source is AMD DRM

作者: cnst | 评分: 61 | 评论数: 7 | 发布时间: 2025-08-07 21:03
文章摘要

作者H. Hartzer在邮件中指出，在OpenBSD系统中，解压后的源码文件大小约为1.7GB，而其中sys/dev/pci/drm/amd目录占据了499MB，其下的include子目录占据了458MB。他质疑这些文件的大小是否必要，是否可以进行精简。Hartzer认为该目录的大小显得过于庞大。

评论摘要
主要讨论点：OpenBSD 7.9内核源代码中AMD DRM占据大部分体积，讨论现代操作系统中GPU驱动相关问题。 不同观点： • [cnst] 指出OpenBSD 7.9内核源代码的634MB中，79%的体积来自AMD的Direct Rendering Manager (DRM) 实现，尤其是asic_reg目录。并对比Linux内核中类似情况，强调这是源代码体积，而非编译后的代码。还指出OpenBSD 6.5到7.7版本之间，内核源码体积的急剧增长。 • [bombcar] 认为现代计算机实际上是以GPU为中心，CPU和操作系统只是辅助启动和支持GPU运行。这一观点呼应了内核源码中DRM占据大量体积的现象。 • [somat] 部分理解这种现象，指出没有稳定的指令集架构（ISA）使得硬件厂商可以创新，但也导致每个硬件设备几乎都需要独特的驱动。尽管对AMD的开源态度表示赞赏，但也希望AMD能清理驱动代码或确定一个稳定的ISA。 • [methou] 提醒Mac和Windows用户不要将Direct Rendering Manager (DRM) 与数字版权管理（Digital Rights Management）混淆，提供了相关维基百科链接以澄清概念。 • [__turbobrew__] 简单地表示AMD的代码是“臃肿的”（bloat）。 • [snvzz] 认为GPU驱动应该放在用户空间，而不是内核中，但指出由于UNIX架构的历史原因，目前仍然难以摆脱这种设计。 补充讨论： • [rasz] 提供了一个相关链接，提到Linux内核维护者曾拒绝了一个AMDGPU补丁，暗示在Linux社区中也存在对AMD驱动代码的争议。 争议焦点： • 内核中包含大量GPU驱动代码是否合理，尤其是AMD DRM实现占据了OpenBSD内核源码的绝大部分。 • 是否应该将GPU驱动移到用户空间，以减少内核的复杂性和体积。 • AMD驱动代码的“臃肿”问题以及是否需要一个更稳定的ISA以减少设备特异性驱动的问题。

A candidate giant planet imaged in the habitable zone of α Cen A

文章摘要

这篇文章报告了使用詹姆斯·韦伯空间望远镜上的MIRI仪器对距离太阳最近的恒星之一——半人马座α星A的日冕观测结果。在2024年8月、2025年2月和2025年4月的三次观测中，研究团队发现了可能的巨行星候选者S1，其距离恒星1.5角秒，有效温度约为225-250 K，半径约为1-1.1木星半径，质量在90-150地球质量之间。S1在2024年8月的观测中被检测到，但在2025年的两次观测中未被发现。结合之前的VLT/NEAR观测数据，S1可能与2019年观测到的C1是同一物体，轨道周期为2-3年，偏心率约为0.4，且与半人马座α星AB轨道平面有较大倾角。这些发现为进一步研究该行星候选者的性质和轨道提供了基础。

主要讨论点：Python 安装工具和 ZIP 文件解压行为的兼容性及安全性问题 不同观点： • [zahlman 的观点] - 认为 Python 安装工具应该确保其 ZIP 实现遵循 ZIP 标准，并在解压前检查中央目录（Central Directory）。 - 指出 `zipfile` 模块已经实现了这一逻辑，使用 `zipfile` 可以避免相关问题。 - 质疑 `uv` 安装工具的解压行为不同于标准实现，可能来源于某个 Rust 库，并担忧其他 Rust 项目也可能存在类似问题。 - 提到 PyPI 已经实现了 ZIP 和 tarball 的压缩炸弹检测，但质疑 `zipfile` 是否能处理所有压缩炸弹问题，并询问是否存在有效的使用场景或规则。 • [captn3m0 的观点] - 对其他使用 ZIP 文件的包管理注册表是否能缓解 ZIP 混淆攻击表示好奇，并询问是否存在这样的例子。 补充讨论： • [jspiner 的观点] - 对文章表示感谢，但没有提出技术性问题或观点，主要是表达对讨论内容的兴趣。 争议焦点： • `uv` 安装工具的 ZIP 解压行为与标准 Python 库 `zipfile` 实现的不同，是否会导致潜在问题。 • `zipfile` 模块是否能够处理所有类型的压缩炸弹，以及是否需要明确压缩炸弹的规则或阈值。 其他值得注意的讨论点： • 对 Rust 项目中 ZIP 文件处理的潜在问题表示担忧，并提出了是否还有其他项目存在类似问题的疑问。 • 对其他包管理注册表如何应对 ZIP 相关安全问题表示好奇。

Sweatshop Data Is Over

作者: whoami_nr | 评分: 44 | 评论数: 8 | 发布时间: 2025-08-07 14:00
文章摘要
