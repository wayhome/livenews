Modernish – A library for writing programs for POSIX-based shells and utilities

作者: sundarurfriend | 评分: 67 | 评论数: 8 | 发布时间: 2025-07-21 15:42
文章摘要

Modernish 是一个用于编写健壮、可移植、可读和强大的 POSIX shell 脚本和实用工具的库。它提供了更安全的变量与命令扩展、新的语言结构（如循环迭代）等功能，增强了传统 shell 脚本的编写体验。Modernish 完全用 shell 语言编写，无需安装二进制代码，适用于多种 shell 实现，并可在嵌入式或多用户系统中部署。它还允许将库与脚本打包，确保在任何 Unix-like 系统上运行。该项目寻求测试者与开发者加入，以进一步完善库的功能和兼容性。文档提供了详细的使用说明和示例代码。

评论摘要
主要讨论点：关于Unix shell脚本工具的现代化及其实际应用的讨论 不同观点： • jonathaneunice认为，尽管像sh、bash、zsh等shell的演进值得赞赏，但本质上它们仍然只是shell体验，而非完整的编程语言体验。他指出，对于处理复杂任务（如时间戳、JSON解析、并发管理等），使用完整的编程语言（如Python）具有更好的语义、类型系统、异常处理、模块化、数据结构和工具支持。因此，对于任何具有一定复杂性的任务，他更倾向于选择完整的编程语言。 • lioeters提供了一个具体的代码示例，展示了如何使用Modernish工具简化和增强传统shell脚本的功能。通过对比Plain POSIX sh和Modernish的实现，lioeters试图展示Modernish在处理复杂任务时的优势。 • pimlottc指出，文档在展示实际命令方面不够直观，建议在文档开头添加简短的代码示例，以便用户快速了解工具的使用方法，特别是在移动设备上浏览时。 • cmcconomy表示，虽然欣赏Modernish这样的工具，但他更倾向于使用系统默认安装的工具，以确保在不同主机间无缝工作。 • amterp对现代命令行脚本领域表现出兴趣，但更希望远离Bash中的控制流和循环编写。他提到正在开发一种更接近Python风格的CLI脚本语言（RAD），尽管其适用场景与Modernish略有不同。 • leonheld赞赏Modernish完全用shell编写，没有其他依赖，认为这是许多尝试“振兴”sh的工具所忽视的重要特性，并表示会采用Modernish。 • cb321对Modernish的`use`函数提出了改进建议，认为应该让`use`处理整个参数列表，以便在单行中实现“方言调整”，从而提高代码的简洁性和灵活性。 补充讨论： • lorenzohess仅对工具的名称表示赞赏，没有进一步展开讨论。 争议的焦点： • 主要争议点在于是否应继续使用shell脚本工具，还是转向更强大的完整编程语言来处理复杂任务。jonathaneunice主张使用Python等语言，而lioeters和leonheld则支持通过工具如Modernish来增强shell脚本的功能。

Mwm – The smallest usable X11 window manager

作者: daureg | 评分: 168 | 评论数: 18 | 发布时间: 2025-07-21 12:04
文章摘要

mwm 是一个极简窗口管理器，专为追求最小化的用户设计。它仅有 20 行代码，不具备模式、美化界面、鼠标控制、虚拟桌面、配置文件等功能，窗口无标题栏、状态栏、按钮、边框和菜单，所有窗口全屏显示，一次只显示一个。它只包含最基本的功能：启动应用、切换窗口和关闭窗口。用户可以通过修改源码自定义键绑定，使用简单的 `grab` 和 `map` 宏。构建过程也很简单，运行 `./build.sh` 即可。mwm 强调软件应具备可 hack、有趣、小巧和可塑性强的特点，让用户能够轻松理解和修改。

评论摘要
主要讨论点：X11与Wayland生态的对比，以及对极简窗口管理器（WM）的讨论 不同观点： • **X11的简便性与Wayland的复杂性**：一些用户（如trollied和ahlCVA）怀念X11的简单操作，如通过SSH和"export DISPLAY"轻松实现远程应用显示，而Wayland将窗口管理器和显示服务器绑定，使得新颖或实验性的窗口管理器更难发展和存活。即使有像wlroots这样的工具，开发者仍需投入更多精力才能实现X11中默认提供的功能。 • **对mwm（Motif Window Manager）的看法**：scoreandmore对mwm有深厚感情，认为它是完美的WM，并自1991年以来一直使用。然而，chasil指出mwm与Motif的命名冲突，并提到dtvwm在CDE中取代了mwm。pjmlp则在比较mwm与twn和uwm的大小。 • **对极简WM的讨论**：一些用户（如90s_dev和newlisp）欣赏极简WM的设计，认为现代软件常常过于臃肿，而极简WM展示了如何在保持功能和便利的同时实现最小化。90s_dev特别提到虽然现代软件有其存在的理由，但他个人倾向于使用和编写极简软件。 • **技术细节与代码实现**：90s_dev和ajross讨论了WM的源代码，赞赏其使用C宏实现的简洁和优雅。adxl认为代码易于阅读和理解，而yjftsjthsd-h则提到该WM类似于X11的cage。 补充讨论： • **用户对资源的需求**：throwaway328询问是否有列出最小WM的资源页面，显示出对极简WM资源的兴趣。 • **兼容性问题**：teddyh指出该WM不符合ICCCM标准，这可能影响其在某些环境中的使用。 • **Wayland的可能性**：neoden提问是否能在Wayland中实现类似X11的极简WM功能，显示出对Wayland生态中极简WM潜力的关注。 争议焦点： • **mwm命名冲突**：chasil指出mwm与Motif Window Manager的命名冲突，可能引起使用上的混淆。 • **X11与Wayland的优劣**：X11的简便性与Wayland的复杂性之间的对比是讨论的焦点，尤其是对于开发者和长期用户的影响。

Rust Running on Every GPU

文章摘要

这篇文章介绍了一个通过Rust编写的单一代码库，能够在多个GPU平台上运行，包括CUDA（NVIDIA）、SPIR-V（Vulkan兼容GPU）、Metal（Apple设备）、DirectX 12（Windows）和WebGPU（浏览器），并为非GPU系统提供CPU后备方案。传统上，GPU编程需要使用专用语言，而该项目通过Rust GPU、Rust CUDA和Naga等项目，将Rust代码直接编译为适用于不同GPU的格式，避免了重复逻辑和复杂性。 该演示实现了一个简单的比特onic排序算法，所有计算逻辑在不同平台上共享。通过Rust特性标志和编译目标选择不同的后端和驱动API，如wgpu、Vulkan、CUDA等。尽管仍有许多待改进之处，但该项目展示了Rust在跨平台GPU计算中的潜力，是一个重要的里程碑。
