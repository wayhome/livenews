Signal Carnival

作者: adunk | 评分: 107 | 评论数: 9 | 发布时间: 2025-04-20 17:13
文章摘要

《Signal Carnival》是Revision 2025上发布的一款C64演示，要求用户切换音频和视频线以体验独特效果。该创意源于90年代将音频连接到视频的操作，但《Signal Carnival》首次实现了音视频线同时互换，且保持音画正常输出。技术上，利用C64的VIC芯片以高频生成音频，通过调整亮度控制音量和波形。视频则通过SID芯片的音量寄存器生成，但由于内部带通滤波器，像素模糊，水平分辨率受限。演示加载过程中持续进行音频输出，并采用自定义加载器处理数据解码和效果生成。

Gemma 3 QAT Models: Bringing AI to Consumer GPUs

作者: emrah | 评分: 569 | 评论数: 39 | 发布时间: 2025-04-20 12:22
文章摘要

Gemma 3 QAT模型通过量化感知训练（QAT）技术，显著降低了内存需求，使得像Gemma 3 27B这样的大型模型可以在消费级GPU（如NVIDIA RTX 3090）上运行。QAT在训练过程中模拟低精度操作，以减少量化带来的性能下降，确保模型在较小、较快的情况下仍保持高精度。例如，Gemma 3 27B模型的内存占用从BF16的54 GB降至int4的14.1 GB，使得强大的人工智能模型能够在普通消费硬件上运行。这种技术使得高性能AI模型更易于访问和使用。

作者: walterbell | 评分: 6 | 评论数: 1 | 发布时间: 2025-04-22 00:40
文章摘要

文章讨论了一种由生成式AI引发的新型网络威胁——"Slopsquatting"。研究表明，大型语言模型（LLM）如GPT-4、CodeLlama等在生成代码时，常推荐不存在的依赖包，其中约19.7%为虚假包。攻击者可注册这些AI虚构的包名并分发恶意代码，利用开发者对AI输出缺乏严格验证的信任，进行供应链攻击。这种现象被称为"Slopsquatting"，类似于" typosquatting"但基于AI错误。研究还发现，这些虚假包名具有一定的持久性和相似性，增加了攻击的成功率。为防范此威胁，建议开发者在生产和运行时安装依赖扫描工具，加强安全测试。

主要讨论点：关于某个话题的小型讨论，涉及技术实现、隐私问题以及用户体验。 不同观点： • 观点一：支持技术创新，强调新技术带来的效率提升和潜在应用场景。有评论指出，新技术可以自动化重复性任务，减少人为错误，尤其是在数据处理和分析领域。支持者还认为，技术进步不可避免，应积极适应。 • 观点二：关注隐私问题，担心新技术可能导致用户数据被滥用。有评论提到，自动化和数据收集可能侵犯用户隐私，建议加强数据保护法规和透明度。这些评论者对新技术持谨慎态度，强调需要在创新和隐私之间取得平衡。 • 观点三：质疑新技术的实际效果和用户体验，认为其可能过于复杂或不实用。一些用户分享了他们的使用体验，指出某些功能可能不如宣传的那么有效，或者在实际操作中遇到困难。他们建议在推广新技术之前进行更多的用户测试和优化。 补充讨论： • 争议焦点在于如何在技术创新和隐私保护之间找到平衡。一些评论建议通过技术手段（如加密）和政策手段（如法规）来缓解隐私问题。 • 另一个值得注意的讨论点是关于新技术的普及和教育。有评论认为，用户需要更多的教育和培训来理解和有效使用新技术，从而最大化其潜在利益。 • 最后，有评论探讨了技术供应商的责任，认为他们有义务提供透明的信息和可靠的安全措施，以赢得用户的信任。

Coding Neon Kernels for the Cortex-A53

作者: yeko | 评分: 8 | 评论数: 1 | 发布时间: 2025-04-21 15:34
文章摘要

本文介绍了作者在FOSDEM会议上展示的用于高性能软件定义无线电（SDR）运行时环境qsdr的工作进展，特别是针对Kria KV260板上ARM Cortex-A53处理器的NEON汇编内核实现。作者解释了如何手写汇编实现一个计算核\(y[n] = ax[n] + b\)，并详细讨论了优化该内核的技巧。由于Cortex-A53的指令时序文档不公开，作者通过微基准测试 reverse-engineer 其指令时序。Cortex-A53是一个按序执行且部分双发射的CPU，这意味着优化代码的手动调整可能带来显著性能提升。作者还讨论了NEON寄存器和指令的并行执行特性，如128位NEON操作会占用两个NEON单元，而64位操作可以并行执行。此外，作者指出CPU与L1缓存之间的加载和存储路径宽度不同，加载为64位，存储为128位。这些细节对优化汇编代码至关重要。

评论摘要
主要讨论点：A53核心的性能表现及其编译器优化问题 不同观点： • 观点一：A53核心并不理想，尤其是编译器对其优化不足。dmitrygr指出，A53核心在编译器优化方面存在问题，特别是在乘法运算时，Android的AOT编译器生成的代码性能较差。 - 支持论据：dmitrygr提到，ChromeOS团队的实习生使用精确周期模型发现，A53在乘法运算时的代码生成存在问题。一个小补丁就能显著提升A53上大多数Android工作负载的性能，且不会影响A57/A72核心的性能。 - 争议点：尽管有性能改进的补丁，但最终并未发布，暗示存在内部政治原因。 补充讨论： • 技术细节：评论中提到了具体的核心型号（A53、A57、A72）和编译器类型（AOT编译器），以及特定操作（乘法运算）对性能的影响。这表明在技术层面上，不同硬件架构和编译器优化的匹配度对性能有重要影响。 • 内部决策问题：尽管技术上可以实现性能改进，但由于非技术因素（如内部政治），补丁未能发布，这反映了在技术项目中非技术因素可能对最终结果产生重大影响。

In depth with Windows 11 Recall–and what Microsoft has (and hasn't) fixed

作者: prng2021 | 评分: 4 | 评论数: 0 | 发布时间: 2025-04-22 03:23
文章摘要

Microsoft is reintroducing the Recall feature to Windows 11, initially limited to Copilot+ PCs, which constitute a small fraction of Windows 11 systems. Recall had previously faced controversy due to privacy and security concerns, as it created an extensive database of text and screenshots recording user activity. The original version was criticized for being enabled by default, having significant security flaws, and lacking protection for sensitive data. In response, Microsoft has revamped Recall's security architecture. It is now turned off by default, requires Windows Hello reauthentication, and encrypts data at rest. Sensitive information is automatically filtered, and users must explicitly opt in twice to enable the feature. Additionally, Recall will not function if Windows Hello or drive encryption is not enabled. The feature captures screenshots and uses OCR to create a searchable text database, but only from the active window and display. Despite these changes, Recall remains limited to newer PCs with specific NPUs, meaning most current Windows users won't be affected.
