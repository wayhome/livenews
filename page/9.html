Node.js is able to execute TypeScript files without additional configuration

作者: steren | 评分: 420 | 评论数: 33 | 发布时间: 2025-08-17 06:03
文章摘要

Node.js v22.18.0 (LTS)版本的主要更新包括：默认启用TypeScript类型剥离功能，使得Node.js无需额外配置即可直接执行TypeScript文件；新增多项实验性功能，如`import.meta.main`支持、权限模型传播、文件系统事件处理优化等；同时更新了多个依赖库，包括SQLite、OpenSSL、npm等。该版本还修复了若干漏洞，并对文档进行了多处改进。

主要讨论点：Node.js 对 TypeScript 的支持（特别是类型剥离功能）及其与其他运行时（如 Bun）的比较 不同观点： • **支持 Node.js 的类型剥离功能** - 认为这是 Node.js 的重大改进，提高了开发体验（如 `tsx` 和 `zod` 的整合） - 赞赏其零成本的生产环境优势（无需 sourcemaps） - 举例说明如何通过 `stripTypeScriptTypes` 简化纯 TypeScript 应用的开发 • **对 Node.js 的限制提出批评** - 指出 Node.js 不支持 `node_modules` 中的 TypeScript，限制了实用性 - 提到不支持某些 TypeScript 功能（如 `enum`），可能误导用户 - 认为标题声称“执行 TypeScript”是误导，实际只是类型剥离 • **推崇 Bun 作为替代方案** - 认为 Bun 更优秀，支持 TypeScript 执行、依赖解析更快、开发体验更好 - 举例说明成功迁移 Node 项目到 Bun 的经验 - 认为 Node.js 的改进是受 Deno 和 Bun 的竞争驱动 • **对生态分裂的担忧** - 类比 ESM 的混乱，担心 TypeScript 支持会引发新的生态分裂（如不同版本和工具的兼容性问题） 补充讨论： - **争议焦点**：Node.js 的类型剥离是否真正解决了 TypeScript 的执行问题，还是仅仅简化了流程？ - **技术细节**：类型剥离的实现方式（替换为空白符）受到赞赏，但有人希望 TypeScript 原生支持这一功能。 - **生态影响**：尽管有批评，Node.js 的类型剥离功能已帮助一些团队成功迁移到 TypeScript。
