“Don’t mock what you don't own” in 5 minutes (2022)

作者: JNRowe | 评分: 31 | 评论数: 11 | 发布时间: 2025-06-16 01:04
文章摘要

这篇文章讨论了在测试中处理第三方依赖的常见问题，特别强调了“不要 mock 你不拥有的东西”这一原则。文章解释说，这一原则建议在使用 mock 对象时，应该替代自己编写的对象，而不是第三方对象。作者通过一个 Python 程序示例说明了 mock 第三方对象的缺点，并展示了如何避免这种情况。文章指出，直接 mock 第三方 API 会导致测试代码复杂且脆弱，建议使用假的客户端对象返回预定义的静态值来进行测试。作者还提到自己更倾向于使用简单的 stubs 和验证过的假对象，而不是传统的 mock。文章最后推荐阅读 Martin Fowler 的文章以了解 mock、stub 等测试概念的区别。

评论摘要
主要讨论点：是否应该在测试中使用 mock 以及如何有效测试复杂系统 不同观点： • [hamstergene] 支持广泛使用 mock 和抽象接口，认为这样可以减少重复工作、确保 mock 保持更新，并促进依赖注入和全面测试的采用。这种方法可以让库的作者提供最佳的 mock 实现，从而使测试更加可靠。 • [eximius] 支持使用高保真假对象（fakes），只在必要时使用 mocks，主张在实际可行的场合使用真实对象进行测试，特别是在跨团队集成测试中，这样可以提高测试的准确性。 • [molf] 对过度依赖 mock 持怀疑态度，认为测试应尽量覆盖更多的代码栈，避免在依赖更新时出现未检测到的错误。建议使用 HTTP 录制/回放库来应对复杂 API 的变化，而不是完全依赖 mock。 • [AugustoCAS] 批评了一些开发者在测试中过度使用 mock，特别是在功能编程中不恰当地使用 mock，指出这种做法可能源于对测试双的概念缺乏理解。 • [lmm] 认为如果测试只覆盖业务接口部分而不涉及可能出错的部分，那么使用 mock 可能没有必要，强调测试应关注实际可能出错的地方。 • [fellatio] 赞同使用倒置控制，但认为需要在某个层面使用真实对象进行测试，以确保系统整体运行正确。 • [ramchip] 指出讨论的观点与 2015 年 Jose Valim 提出的 "mocks 和明确合同" 类似，认为这是一个已有的实践。 • [strken] 对 "不 mock 不属于自己的代码" 这一原则提出质疑，认为其核心在于如何处理 awkward API 而不是所有权问题。 • [hmmokidk] 赞赏 Stripe 提供的 CLI 测试工具，认为其在 webhook 测试中的应用很有价值。 • [mpweiher] 分享了一篇 2014 年的文章，标题为 "为什么我不使用 mock"，暗示对 mock 的不认同。 补充讨论： • 争议的焦点在于是否应广泛使用 mock 以及如何在测试中平衡 mock 与真实对象的使用。 • 一些开发者认为 mock 会导致测试覆盖不足，特别是当依赖库发生未预期的变化时，而另一些开发者则认为 mock 能有效隔离测试环境，提高测试效率。 • 高保真假对象和 HTTP 录制/回放库被认为是 mock 的替代方案，可以提高测试的实际覆盖率和可靠性。 • 对测试双（test doubles）和 mock 的理解差异导致了不同的测试实践，特别是在不同编程范式中的应用。 • 一些评论提到了对 mock 的实际应用经验和历史讨论，显示出这一话题在开发社区中已有较长时间的争议和探索。

The Humble Programmer (1972)

作者: squircle | 评分: 129 | 评论数: 19 | 发布时间: 2025-06-17 01:25
文章摘要

Edsger W. Dijkstra在1972年的ACM图灵讲座文章《谦逊的程序员》中回顾了自己作为荷兰首位程序员的职业经历。他描述了编程职业在其国家发展缓慢的过程，以及自己在理论物理学和编程之间的挣扎。在1950年代，编程尚未被视为一个正式的职业，甚至在结婚登记时不被认可。自动计算机早期是独特的实验设备，程序员的工作不被重视，更多焦点在硬件上。Dijkstra提到，他的导师van Wijngaarden鼓励他将编程发展为受人尊敬的学科，这改变了他的职业选择。文章反思了过去的编程环境，并指出许多对编程的误解源于那个时代。Dijkstra强调了对年轻人的建议需谨慎，因为这些建议可能会影响他们的职业选择。

评论摘要
主要讨论点：计算机系统架构、编程语言设计、程序员职业发展和社会对编程的期望 不同观点： • **[bob1029]** 认为现代计算机系统中多级存储的管理策略依然复杂，尤其是在异构系统（CPU/GPU）中选择合适的内存/计算资源时。他强调了提前优化的重要性，特别是在保持L1缓存温度以提高性能方面。他还提到像SQLite这样的工具在降低信息延迟方面的优势。 • **[varjag]** 提出编程职业的薪酬变化问题，认为过去几十年编程职业可能并没有达到社会预期，导致社会对程序员工作表现不满，并推测未来程序员的薪酬可能会下降。 • **[saghm]** 讨论了程序结构和可管理性的重要性，指出不同程序在智力可管理性上的巨大差异。他提到了一些编程规则，特别是那些无法机械强加的规则，并以Coq为例讨论了Turing不完备性可能并非对所有应用都是问题。 • **[ddtaylor]** 批评了某些计算机设计中的严重缺陷，认为这些设计缺陷阻碍了计算科学的发展，并指出即使多年后，人们仍未意识到这些问题，反而以销售量作为设计良好的依据。 • **[stereolambda]** 对比了过去与现代社会对计算机和程序员的需求差异，认为20世纪90年代后视角从社会整体转向公司和行业。他还提到现代编程语言如Golang试图引导用户思维，并讨论了软件成本与程序员薪酬的关系。 • **[Michelangelo11]** 指出教授方法学可能会扩大能力差距，使得已经具备能力的人变得更加出色，从而加剧不平等。 • **[selcuka]** 批评FORTRAN语言已经过时，认为其不再适合作为思维工具，并讽刺其标准化委员会未意识到这一点。 • **[enord]** 认为Dijkstra的严格规范虽有道理，但其精英主义倾向可能让很多人反感，并指出在程序和组织中执行速度的权衡问题。 • **[b0a04gl]** 认为Dijkstra的观点比同时代的其他观点更有持久性，指出团队在追求快速输出而非干净设计时往往会遇到问题。 补充讨论： • 争议焦点之一是计算机系统设计中的缺陷及其对行业的影响，[ddtaylor]强烈批评某些设计，而[b0a04gl]则支持Dijkstra对设计严格性的强调。 • 另一个讨论点是编程语言的演变和选择，[saghm]和[selcuka]对现代编程语言如Coq和FORTRAN的适用性提出了不同看法。 • 程序员职业的发展和社会期望的变化也是重要讨论点，[varjag]和[stereolambda]分别从薪酬和社会需求角度进行了分析。

Accumulation of cognitive debt when using an AI assistant for essay writing task

作者: stephen_g | 评分: 326 | 评论数: 65 | 发布时间: 2025-06-16 02:49
文章摘要

这篇文章探讨了使用大型语言模型（LLM）如ChatGPT辅助写作对神经和行为的影响。研究将参与者分为LLM组、搜索引擎组和纯大脑组（无工具），通过脑电图（EEG）评估写作时的认知负荷，并使用自然语言处理（NLP）分析作文。结果显示，纯大脑组显示出最强且分布最广的脑网络连接，而LLM组连接最弱。当LLM用户转至无工具写作时，显示出大脑连接不足；而无工具用户转至LLM组时，记忆 recall 和相关脑区活跃度增加。LLM组对作文的自我认同感最低，且引用自己作品时困难更大。研究表明，虽然LLM提供了便利，但可能导致长期的认知负担和学习能力下降。

评论摘要
主要讨论点：LLM（大型语言模型）对人类思维和认知能力的影响，包括可能的认知退化、技术依赖以及人与技术之间的健康关系。 不同观点： • **LLM导致认知退化和思维浅化**：[mjburgess]和[NetRunnerSu]认为，过度依赖LLM会造成“认知债务”，导致思维能力下降，甚至可能造成不可逆的认知功能萎缩。他们强调，思维过程本身是人类能力发展的关键，外包思维过程会削弱人类的适应能力和深度思考能力。 • **技术依赖的历史重演**：[santiagobasulto]指出，类似的担忧在谷歌和手机刚出现时也曾有过，但社会最终适应了这些技术。这暗示当前对LLM的担忧可能只是历史重演，最终人类会找到与这些技术共存的方法。 • **生成与辨别的技能差异**：[pcwelder]认为，LLM在生成内容方面的能力有限，但在辨别内容好坏上却有优势。生成技能难以获得且非常宝贵，如果人们过度依赖LLM生成内容，这些技能可能会萎缩。 • **技术作为工具，需合理使用**：[keithwhor]认为，LLM是一种工具，可以加速某些任务的完成，但如何使用它决定了其效果。如果人们学会健康地使用这些技术，它们可以带来积极的效果，比如帮助处理复杂生活问题，但也可能导致依赖和认知退化。 • **LLM对不同任务的参与感差异**：[tkgally]发现，使用LLM进行写作和翻译任务时，精神参与感不如自己完成这些任务时强，但在其他任务如头脑风暴和研究中，LLM却能带来新的精神参与感。 补充讨论： • **认知退化的不可逆性**：[NetRunnerSu]特别强调，过度依赖LLM可能导致一种“认知临界点”，即大脑由于长期不使用某些复杂的认知功能，导致这些功能永久性丧失，无法再恢复。 • **LLM对学习和记忆的影响**：[fercircularbuf]和[greekanalyst]都提到，LLM可能削弱学习和记忆能力，因为人们不再需要主动参与复杂的认知任务，这与使用GPS导致空间记忆减退的例子类似。 • **LLM对深度理解的阻碍**：[niemandhier]认为，LLM的使用让人停留在浅层的快速迭代上，而不是深入理解和研究某一主题，这可能会阻碍深度学习和理解。 争议的焦点：LLM的使用是否会导致不可逆的认知退化，以及如何在利用LLM加速任务完成的同时，保持和发展人类的深度思考和生成能力。
