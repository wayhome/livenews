评论摘要
主要讨论点：当代金融市场的真实性和有效性问题 不同观点： • **市场泡沫论**：第一位评论者直接指出存在"泡沫"现象，暗示市场估值脱离实际价值 • **算法主导论**：第二位评论者认为金融系统已被AI和算法交易主导，IPO文件等传统披露机制形同虚设，无人真正阅读分析，市场本质上是"合成白痴"的集合 • **人类决策边缘化**：过去20年交易公司为追求速度优势不断靠近交易机器，人类在金融决策中的作用持续减弱 • **散户无力论**：普通投资者在市场中基本没有影响力，只有像GameStop (GME)轧空事件那样的集体行动才能短暂产生效果 补充讨论：评论特别提到政治人物言论（如特朗普）能轻易撼动市场，进一步印证了市场的非理性和算法驱动特征。整体讨论呈现出对现代金融市场结构性问题的批判态度。

LibreCAD in the Browser

作者: devttyeu | 评分: 92 | 评论数: 11 | 发布时间: 2026-07-02 01:00
文章摘要

作者将开源2D CAD工具LibreCAD移植到浏览器中运行，使用GLM-5.2 AI模型辅助完成。通过Emscripten将C++/Qt源码编译为WebAssembly，实现了完整应用（非阅读器或简化版）的浏览器端运行。 核心技术挑战是处理模态对话框的嵌套问题。传统Asyncify方案只支持单层挂起，遇到嵌套对话框会卡死。最终采用JSPI（WebAssembly JavaScript Promise Integration）技术解决，支持任意深度的嵌套挂起。需要从源码编译Qt 6.9并启用JSPI和WebAssembly异常支持。 首次加载约18MB（Brotli压缩），之后浏览器缓存。目前仅支持Chrome/Edge 137+，因为Firefox和Safari尚未支持JSPI。整个移植过程展示了WebAssembly生态的成熟度和Qt对Wasm的良好支持。

评论摘要
主要讨论点：LibreCAD Web版的可用性、浏览器兼容性，以及Web应用与桌面应用的优劣对比 不同观点： • **技术问题方**：pockybum522遇到功能故障（Chrome 150无法绘图），gedw99解释需要Chrome/Edge 137+且启用WebAssembly JSPI支持 • **质疑Web化趋势方**：mrsssnake认为桌面版更优（仅82.7MB、无需账户、离线可用、系统统一更新），质疑为何要把桌面程序强行塞进浏览器 • **批评浏览器单一支持方**：drivingmenuts不满只支持Chrome，认为开发者不关心其他浏览器用户 • **推荐替代方案方**：felooboolooomba建议使用FreeCAD的Sketcher（支持约束），IshKebab推荐SolveSpace（已有Web版且更适合简单任务） • **支持者**：localdeclan表示感谢，认为对基础需求很实用；hersko简单点赞 补充讨论：争议焦点在于"便捷性"（无需安装、跨平台）与"实用性"（性能、兼容性、功能完整度）的权衡。技术门槛（需特定浏览器版本）降低了Web版的可访问性优势。

Podman v6.0.0 于2026年7月2日正式发布。这个主要版本带来了多项重大改进： **核心更新：** - **网络现代化**：从 slirp4netns/iptables 迁移到 Netavark/Pasta/nftables，简化维护并支持未来功能 - **podman machine 增强**：改进多提供商体验，新增 `podman machine os update` 命令 - **Quadlet 升级**：支持 REST API，改进文件跟踪，扩展 .volume 单元功能 - **配置管理优化**：改善多用户环境的配置文件处理 - **Docker 兼容性**：更新 Docker API 支持，简化从 Docker 的迁移 该版本经过数月开发，旨在现代化核心基础设施、增强安全性并改善用户体验。

评论摘要
主要讨论点：Podman 作为 Docker 替代方案的可行性及其优缺点 不同观点： • **支持切换派**：多位用户（cdmckay、mati365、EddieB）分享了成功从 Docker 切换到 Podman 的经验，强调切换简单（可直接使用 docker-compose.yml）、Quadlets 功能强大、rootless 容器更安全、内存占用更低。有用户在生产环境稳定运行两年无问题。 • **批评兼容性问题派**：PufPufPuf 指出 Podman 声称兼容 Docker 但存在细微差异，会导致用户投诉。rsyring 强烈批评 Podman 不支持 Ubuntu 等流行发行版的便捷安装，认为这是严重阻碍其采用的问题。 • **macOS 平台挑战派**：victor_vhv 和 satvikpendem 提到在 macOS 上使用 Podman 的困难，包括随机无响应、构建失败等问题。OrbStack 在 macOS 上表现更好但是闭源收费软件。 • **技术优势认可派**：SwellJoe 认为 Podman 技术上明显优于 Docker，不理解为什么 Docker 仍然更流行。多位用户称赞新的网络功能、Quadlets 和 systemd 集成。 补充讨论：两位用户（Tepix、mjburgess）抱怨 Podman 官网灰色字体可读性差，这是个无关技术但影响用户体验的细节问题。
