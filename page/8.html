Everything to know about UniFi OS Server

作者: codydeluisio | 评分: 71 | 评论数: 6 | 发布时间: 2025-08-03 21:09
文章摘要

UniFi OS Server是Ubiquiti推出的自托管平台，允许用户在自己的硬件上运行UniFi Network及部分应用程序（如InnerSpace和Identity），无需Dream Machine或Cloud Key。它支持x86、x64和ARM64架构，兼容UXG网关，但不支持Cloud Gateways。该平台引入了环境分析、SD-WAN式组网、Zero Trust访问等新功能，但仍需Ubiquiti登录以使用云功能。当前版本不支持Protect、Talk、Access等应用，且缺乏多租户管理和全局MSP角色分配功能。对于已经自托管UniFi Network的用户，该平台提供了一些实用功能，但并未彻底改变MSP的管理方式，主要是一次后端改进而非前端革新。

The /o in Ruby regex stands for "oh the humanity "

作者: todsacerdoti | 评分: 179 | 评论数: 14 | 发布时间: 2025-08-02 14:37
文章摘要

这篇文章讨论了Ruby中正则表达式使用`/o`修饰符引发的一个隐蔽问题。作者在代码审查中发现，一个用于匹配字符串的`Matcher`类在某些情况下始终返回`true`，即使输入不匹配。经过排查，作者发现问题源于正则表达式中的`/o`修饰符。该修饰符会导致插值正则表达式在首次使用时被缓存，后续不再重新插值。这意味着正则表达式只会使用第一次插值的结果，导致匹配行为异常。通过移除`/o`修饰符，问题得以解决。文章还探讨了Ruby内部机制，包括通过VM字节码进一步理解该行为。

评论摘要
主要讨论点：Ruby 和 Perl 中正则表达式的 `/o` 修饰符的含义、用途及其潜在问题 不同观点： • fanf2 认为 Ruby 文档对 "interpolation mode" 的描述具有误导性，并引用 Perl 文档作为对比，指出 Perl 对该修饰符的效果说明更清晰。Perl 历史上曾需要 `/o` 来避免不必要的重新编译，但现代 Perl 已自动优化，因此 `/o` 几乎不再有用。 • jononor 以幽默的方式评论该符号看起来像表情符号，未深入技术讨论。 • riffraff 提到 `END {}` 也是从 Perl 继承而来，并推测其最初可能来自 awk，将讨论引向其他语言特性。 • tialaramex 强烈反对 `/o` 修饰符，称之为“footgun”（易于误用的功能），认为它容易导致神秘 bug，并认为语言设计应尽量避免这种功能。相比之下，性能问题可以通过优化解决，而 footgun 则可能引发更严重的错误。 • cbsmith 作为有经验的 Perl 程序员，表示对 `/o` 的作用非常清楚，并暗示对老手来说这不是问题。 • kazinator 通过对比 C++ 的静态变量初始化和 POSIX 的 `pthread_once`，解释 `/o` 的行为，认为其作用明确且合理。 • rco8786 对深入讨论表示赞赏，但未发表具体立场。 • alfiedotwtf 提到如果不喜欢 `/o`，那么可能更不喜欢 Perl 的 `/e` 修饰符，暗示 Perl 的其他功能可能更具争议性。 • lupire 将 `/o` 的问题与闭包的按名或按值捕获问题类比，认为两者都容易让用户困惑。 • phoronixrly 对 `/o` 持正面态度，认为这是一个有趣的功能。 • jwlake 将 `/o` 与 JavaScript 中的 `g` 修饰符类比，可能暗示对该功能的理解有误差。 • zer00eyz 引用经典的“用正则表达式解决问题的两难困境”来调侃对正则表达式的使用。 • IshKebab 认为这是 Ruby 的常态，暗示 Ruby 文档问题并非孤立现象。 • Joker_vD 强烈反对 `/o`，认为其行为不可理喻，并质疑在正则表达式中使用插值时重新插值的必要性，指出若期望值不变，直接一次编译即可，无需插值。 补充讨论： • 争议焦点在于 `/o` 修饰符是否容易导致误用和 bug。支持者认为其作用明确，尤其对有经验的程序员而言；反对者则认为它是一个 footgun，容易导致神秘问题，且在现代语言中不再必要。 • 讨论还涉及与其他语言特性的对比，如闭包捕获问题和 Perl 其他修饰符（如 `/e`）。 • 部分评论者对文档的清晰度提出批评，认为 Ruby 文档在此方面的表现不如 Perl。

作者: 0x54MUR41 | 评分: 87 | 评论数: 9 | 发布时间: 2025-08-03 04:11
文章摘要

Seed7是一种由Thomas Mertes设计的高级编程语言，具备开源解释器和编译器，编译器将Seed7程序转换为C程序并编译为机器码。Seed7支持用户自定义语句和操作符，具有无特殊语法即可定义模板和泛型的能力。它采用静态类型检查，无自动类型转换，提升编译时错误检测能力。Seed7具备自动内存管理，无需垃圾回收，支持异常处理和源码调试。它提供大整数和大有理数类型，支持函数、操作符和语句的重载。预定义多种数据类型和数据库独立API，可连接多种数据库。Seed7代码具有良好的可移植性，适用于Linux、Unix和Windows系统。解释器和示例程序使用GPL许可，运行库使用LGPL许可。
