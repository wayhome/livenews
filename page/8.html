How the cochlea computes (2024)

文章摘要

这篇文章解释了耳朵如何处理声音信号，指出耳蜗并非进行傅里叶变换，而是通过基底膜对不同频率的振动产生共振来实现频率分离。基底膜上的毛细胞根据位置对应不同频率，通过机械电转换将振动转化为电信号。研究发现，耳蜗的滤波器在时间和频率分辨率之间存在权衡，更接近于小波或Gabor变换，而非傅里叶变换。这种处理方式被认为是为了减少自然声音中的冗余信息，且人类语音占据了独特的时间-频率空间，可能是为了适应环境声音而进化形成的。

评论摘要

Immutable releases are now generally available on GitHub

作者: fastest963 | 评分: 137 | 评论数: 14 | 发布时间: 2025-10-31 13:59
文章摘要

GitHub推出不可变发布功能，增强软件供应链安全。不可变发布一旦发布，其资源和标签将无法被修改或删除，防止篡改。新功能包括不可变资源、标签保护和发布认证，可通过GitHub CLI或Sigstore兼容工具验证发布真实性。用户可在仓库或组织级别启用该功能，现有发布不受影响，但新发布将自动变为不可变。GitHub还提供相关文档指导发布完整性验证。

评论摘要
主要讨论点：[GitHub 引入不可变发布的利弊及相关功能需求] 不同观点： • **支持不可变发布** - [hoistbypetard] 表示惊讶此前发布可变，认为不可变发布是必要的改进。 - [raphinou] 认为不可变发布解决了发布篡改问题，简化了校验流程，无需额外镜像和校验工具。 • **反对不可变发布的绝对性** - [dare944] 指出不可变发布可能妨碍紧急撤回（如存在安全隐患的版本），建议支持不可撤回的“撤销”功能。 - [josephcsible] 认为禁止删除过于严格，建议通过修改记录或内容哈希实现透明性。 • **功能改进建议** - [rhodey] 呼吁在 Actions 页面标注是否为 GitHub 官方运行，以增强信任。 - [codethief] 询问如何在 UI 中直观识别不可变发布。 - [skrrtww] 质疑自动生成的源代码是否稳定，认为需提供哈希稳定的下载。 • **信任与实现质疑** - [lrvick] 强调真正的不可变性需依赖外部签名或本地哈希，对 GitHub 的内部安全政策表示不信任。 - [shpx] 认为“不可变”是营销术语，实际仍可能被 GitHub 修改，建议标注“已编辑”。 - [OptionOfT] 举例发现标签被移动，质疑不可变发布的实际执行。 补充讨论： - **争议焦点**：不可变发布的严格性是否合理（如禁止删除）及其实际执行效果。 - **其他讨论**： - [bob1029] 批评 GitHub 忽视核心功能（如 PR 审查）优化，认为应优先修复基础体验。 - [IshKebab] 对 GitHub 创新持观望态度，期待更多功能更新。
