The Linux Kernel Seeing Rare Code Activity Around SPARC64

作者: mikece | 评分: 5 | 评论数: 3 | 发布时间: 2025-07-24 13:18
文章摘要

文章报道了Linux内核中针对SPARC64架构的罕见代码更新。SPARC64是由Sun Microsystems开发的处理器架构，尽管仍被Linux内核支持，但很少有代码活动。近日，开发者Thomas Weißschuh提交了一系列补丁，旨在将SPARC64转向使用通用的vDSO库。vDSO允许将某些系统调用直接暴露给用户空间，以避免标准系统调用机制的开销。SPARC64是最后一个未使用该通用vDSO库的架构，转换后将减少数百行代码，降低维护负担。由于Oracle在八年前停止了SPARC CPU的开发，且大多数SPARC用户使用Solaris，因此SPARC在Linux内核中的支持还能持续多久仍是未知数。

评论摘要
主要讨论点：为什么开放的SPARC架构没有像RISC-V一样被广泛采用，以及SPARC架构的当前维护情况。 不同观点： • [mikece] 认为SPARC是一个开放的、非专有且免版权费的架构，依据是SPARC由SPARC International管理并开放。他质疑为什么芯片制造商不去制造开源的SPARC处理器，而是选择了RISC-V。这暗示他认为SPARC应该比RISC-V更有竞争力，但实际情况并非如此。 • [MobiusHorizons] 提供了一个技术角度，指出SPARC64架构在代码维护上存在问题，特别是与vDSO库相关。他提到通过将SPARC代码转换为通用的vDSO基础设施，能够减少几百行代码，并降低维护负担。这表明他认为SPARC在技术维护上仍有工作要做，且存在改进空间。 • [warrenm] 对SPARC64仍有足够的使用量表示惊讶，质疑它是否值得继续更新。他似乎认为SPARC64已经过时，或者其用户群体较小，不值得继续投入资源进行维护和更新。 补充讨论： • SPARC的开放性和非专有性并没有自动转化为市场上的广泛采用，这与RISC-V的流行形成对比。 • SPARC64架构在技术维护上存在特定的挑战，比如代码清理和维护负担。 • 有人对SPARC64当前的使用情况和是否值得继续维护表示怀疑。 争议焦点： • SPARC在开放性和技术优势上是否足以与RISC-V竞争，以及是否值得继续投资于SPARC架构的维护和开发。

作者: ingve | 评分: 79 | 评论数: 9 | 发布时间: 2025-07-23 09:57
文章摘要

Python 3.14引入了一个新功能，允许通过`python -m pdb -p pid`将pdb调试会话连接到一个正在运行的Python进程。这使得开发者可以在无需提前修改代码或重启程序的情况下，动态调试运行中的进程。文章介绍了如何使用`sys.remote_exec`方法向指定进程ID的Python进程注入并执行代码。具体来说，开发者可以在一个Python REPL中调用`sys.remote_exec(pid, script_path)`，让目标进程执行指定的脚本。文章通过一个简单的累加整数的程序演示了该功能的实际应用，展示了如何在不中断程序运行的情况下，远程注入代码以查看调用栈信息。这一新功能降低了调试Python程序的门槛，简化了调试流程，并减少了对CPython内部细节的依赖。

主要讨论点：Python 3.14 中调试功能的改进及其相关工具的讨论 不同观点： • [jasonjmcghee] 认为 PEP 768 是一个很好的官方资源，提供了关于新功能的有用信息。他引用了该文档，但没有深入讨论具体功能。 • [BossingAround] 提到两个新功能：无需修改或停止程序即可打印堆栈跟踪，以及在运行时无需修改程序即可执行。他对 remote_pdb 的提及表示困惑，因为该工具在 Python 2.7 中已经存在。他还希望 Python 调试工具能标准化，特别是希望有像 VSCode 那样的远程调试能力。 • [maeln] 认为这对调试运行在 GUnicorn、Celery 等应用上的多线程、多进程程序非常有用。他指出目前 pdb 使用不便，而 VSCode 的 Debug Adapter Protocol 实现是目前最完善的。 • [snthpy] 开玩笑地建议将此版本命名为 CPithon，但没有详细讨论具体功能。 • [skeledrew] 提到 pyrasite 项目，并分享了他使用 ptpython 创建的 REPL 包装器的经验，计划将其发展成类似 Pharo/Smalltalk 的实时编码体验。 • [poulpy123] 希望有一个调试器可以回溯断点或异常，暗示对时间回溯调试功能的需求。 • [whinvik] 关心调试脚本和被调试脚本的 Python 版本兼容性问题，询问是否需要两者都运行 3.14 版本。 • [orbisvicis] 指出在特定位置运行注入代码的问题，可能是对调试功能的技术实现提出疑问。 • [frou_dh] 对新功能表示赞赏，特别是无需第三方库即可在同一机器上附加 pdb 到任何运行进程的能力，缓解了他对依赖 remote_pdb 的担忧。 补充讨论： • 评论中多次提到 VSCode 的远程调试能力，显示出用户对现有工具的高度认可和对未来标准化的期待。 • 对 remote_pdb 及其在 Python 3.14 中变化的讨论显示出用户对现有工具的熟悉程度和对其改进的需求。 • 对调试工具的易用性和功能增强（如实时编码和时间回溯）的期望反映了用户对生产力提升的渴望。

文章摘要

本文介绍了Vintage Apple网站上的古董级Macintosh编程书籍库，该库包含超过150本与 vintage Mac编程相关的书籍。这些书籍由Nick R.提供，并经过扫描后分享给社区。库中包括多种编程语言的指南，如Apple Basic、Macintosh Pascal、C语言和汇编语言，以及关于Macintosh工具箱、图形、声音编程和游戏动画的资料。时间跨度主要集中在1983年至1988年，涵盖Macintosh早期开发的各种技术细节和编程方法。感谢Nick的贡献，让这些历史资源得以保存和共享。
