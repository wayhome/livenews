How much do electric car batteries degrade?

作者: xnx | 评分: 99 | 评论数: 24 | 发布时间: 2025-08-18 17:53
文章摘要

电动汽车电池的退化程度比人们普遍担心的要低。研究发现，尽管手机和电动车都使用锂离子电池，但电动车电池设计寿命更长。数据显示，大多数电动车在行驶20万英里后仍能保持80%以上的初始容量。电池退化主要来自日历老化（每年约1-2%）和循环老化，其中初期退化较快（前2.5万英里下降3-5%），之后趋于平缓。这种误解导致二手电动车价格被低估，实际上电池寿命表现良好。

评论摘要
主要讨论点：[电动汽车电池寿命、衰减及其对二手车市场的影响] 不同观点： • [电池衰减是主要问题] - starwatch引用研究指出，电池容量降至80%以下时，性能会急剧下降，认为此时电池已不适合电动汽车使用。 - tonymet强调最后20%的电量至关重要，直接关系到车辆能否到达充电站，认为电池衰减会严重影响用户体验。 • [电池衰减并非主要问题] - gwbas1c和brikym以实际使用经验为例，指出电池衰减并不像传闻中那么严重，且新型号电池在低温下的表现更好。 - bangaladore认为电池工程问题（如冷却系统故障）比自然衰减更值得关注，尤其是2017/18年前的电池设计。 • [市场心理和保修政策的影响] - themafia认为二手车价格下跌更多是由于对电池寿命的悲观预期，而非实际衰减。 - aidenn0指出长保修期可能只是营销策略，尤其是当保修不可转让时。 - tzs质疑保修条款的实际覆盖范围，认为多数保修在年限或里程达到其一即失效。 补充讨论： - 争议焦点：电池衰减的实际影响（如tonymet与gwbas1c的争论）以及保修政策的透明度（如tzs与原文作者的矛盾）。 - 其他讨论点：充电基础设施（kulahan提到共享停车问题）、技术进步（kingstnap提到电池化学改进）以及手机电池与汽车电池的对比（fencepost和shawnz的讨论）。

XZ Utils Backdoor Still Lurking in Docker Images

作者: torgoguys | 评分: 71 | 评论数: 9 | 发布时间: 2025-08-19 00:07
文章摘要

2025年8月12日，Binarly研究团队发现尽管XZ Utils后门事件已过去一年多，但仍有35个以上包含该后门的Docker镜像在Docker Hub上公开可用。该后门通过修改liblzma.so库中的函数钩子，影响OpenSSH服务器的安全性。团队使用15TB的Docker镜像数据集进行分析，发现12个Debian基础镜像仍受感染，甚至有些新镜像基于这些受感染镜像构建，形成了间接感染。虽然数量看似不多，但由于仅扫描了部分镜像且专注于Debian系统，实际受影响范围可能更大。

评论摘要
主要讨论点：Docker 镜像的安全性问题，特别是涉及 XZ 后门的案例。 不同观点： • **Docker 是安全隐患**（DiabloD3）：认为 Docker 及其依赖包普遍存在安全漏洞，除非自行构建镜像，否则不可信。建议使用传统虚拟机或官方编排工具。 • **Debian 已修复问题**（dima55）：指出问题已由 Debian 修复，但 Docker 镜像用户未能受益于这些修复，因为他们不使用标准的 Debian 安装方式。 • **问题被夸大**（creatonez）：认为标题过于耸人听闻，XZ 后门从未进入 Debian 稳定版，问题在于用户使用了未更新的测试版镜像。移除漏洞镜像可能破坏可重现构建。 • **社区镜像问题**（burnt-resistor）：批评使用未经审核的社区镜像而非维护良好的系统，导致漏洞长期存在。 • **Docker 普遍不安全**（sugarpimpdorsey）：认为大多数 Docker 镜像本身缺乏基本安全措施，运行在 root 权限下，后门问题只是冰山一角。 补充讨论： • **漏洞触发条件**（jchw）：质疑有多少容器会实际触发后门，因为 OpenSSH 在容器中并不常见。 • **替代方案建议**（LeoPanthera）：建议开发者从 XZ 迁移到 lzip，认为后者是更优的 LZMA 容器格式。 争议焦点： • 问题的严重性：部分评论认为问题被夸大（如 creatonez），而其他人坚持 Docker 和社区镜像存在系统性风险（如 DiabloD3、burnt-resistor）。 • 解决方案：是移除漏洞镜像（可能破坏构建）还是依赖用户自行更新和维护系统。

这篇文章主要讲述了作者在研究1997年英特尔AN430TX主板时发现的特殊8×19字体VGA显示模式。作者通过物理主板截图确认了这种罕见的显示方式，并追溯其最早出现在1997年的英特尔主板上。为了探究该字体的出现时间，作者尝试使用Phoenix BIOS解码工具分析不同版本的BIOS更新文件，但遇到文件格式解析的困难。最终通过内存转储技术成功解码BIOS，揭示了BIOS更新文件在闪存中的实际布局。这一发现不仅确认了8×19字体的存在，还展示了逆向工程老式计算机系统的技术挑战。
