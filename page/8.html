Experimenting with Random() in CSS

作者: kilian | 评分: 22 | 评论数: 4 | 发布时间: 2026-06-24 12:51
文章摘要

这篇文章介绍了CSS新增的`random()`函数，可以为属性设置随机值来创建创意设计。作者通过多个实例展示其应用： 1. **散景效果**：使用`random()`随机设置圆形的位置、大小、颜色和模糊度 2. **落花效果**：随机控制花瓣的起始位置、大小、下落和旋转动画 3. **可拖拽的宝丽来照片堆**：随机排列照片堆叠效果 4. **随机诗歌设计**：使用离散随机值和权重随机值进行排版 目前该功能在Polypane 29+、Chromium 148+（需开启实验特性）和Safari 26.2+中可用，Firefox暂不支持。文章提供了可交互的代码示例供读者测试。

评论摘要
主要讨论点：关于CSS随机数功能的技术讨论 不同观点： • **视觉效果担忧**（smallnix）：真正随机分布的值可能产生不理想的同色聚集现象（"聚类错觉"），影响视觉效果 • **技术细节纠正**（MartijnBraam）：散景效果（Bokeh）并非对不同圆形有不同模糊度，而是始终投影光圈的精确形状 • **文档完整性批评**（vintagedave）：文章缺少效果截图展示，只有大量代码。作者提到浏览器兼容性问题和示例可能失效，却不提供可视化结果，体验不佳 • **历史技术回顾**（g-）：CSS在此功能之前已存在获取随机数的复杂方法，甚至通过操作DOM并重新读取变化值来实现（因为某些操作具有随机性） 补充讨论：评论涵盖了从视觉设计、技术实现细节、文档质量到技术演进历史等多个层面，反映了开发者对新CSS随机数特性从不同角度的关注。

What Ozempic does to the gut-brain axis

作者: randycupertino | 评分: 162 | 评论数: 21 | 发布时间: 2026-06-27 21:34
文章摘要

研究发现GLP-1药物（如Ozempic）除了减肥，还有抗抑郁效果。中国东南大学研究团队通过小鼠实验发现，这些药物能促进肠道中的德氏乳杆菌生长，该菌产生类大麻素物质来改善情绪。关键是这种效果依赖肠道菌群——无菌小鼠中抗抑郁作用消失。有趣的是，减肥和抗抑郁似乎通过不同机制实现。研究还通过粪便移植验证了因果关系。日常可通过酸奶、开菲尔等发酵食品获取这种益生菌。这揭示了肠道微生物在调节情绪中的重要作用。

评论摘要
主要讨论点：GLP-1类药物（如Ozempic、Zepbound）对减肥和情绪的影响及其利弊 不同观点： • **积极支持派**：多位用户报告显著效果，包括减重15-20公斤、改善情绪、减少暴食冲动、提升运动动力，甚至减轻肌肉酸痛。有用户认为其社会影响可比他汀类药物，改变了对该药的看法。 • **谨慎怀疑派**：担心长期依赖性问题，研究显示2年内体重反弹，认为未解决根本问题（如食物成瘾）。质疑需终身用药的方案。关注骨密度流失等副作用和20年使用史后的未知风险。 • **副作用体验者**：报告恶心、上腹部压痛、疑似胰腺炎症状。特别值得注意的是，有用户出现自杀倾向（Ozempic）和快感缺失（anhedonia），但换用Zepbound后症状消失。另有用户表示对抑郁症完全无效。 • **经济负担关切**：保险停保后月费用达450美元，体重反弹导致情绪恶化，形成恶性循环。 补充讨论：医生建议对暴食型抑郁症优先考虑氟西汀；有人期待未来能用于戒断咖啡因、尼古丁等成瘾物质；代谢理论在精神疾病研究中被低估；标题未标注"小鼠实验"引发争议。

文章摘要

这篇文章讨论了如何在AI时代举办有意义的软件竞赛。作者指出当前软件黑客松面临两大问题：AI生成的低质量项目泛滥，以及如何激励参与者认真投入。 作者所在的非营利组织Hack Club采用按编码时长付费的模式（每小时8.5美元），通过Hackatime追踪实际编码时间。但这容易导致参与者为赚钱而敷衍了事。 解决方案是借鉴游戏开发竞赛（Game Jam）模式：低质量作品在投票中会被淘汰，没有奖励。同时设定明确期望（避免使用LLM）、邀请优秀评委、给予充足时间让参与者写出高质量代码。这样既解决了AI滥用问题，又通过竞争机制确保参与者真正投入学习，而非仅为奖金敷衍。

评论摘要
主要讨论点：Hack Club的Radish项目投票机制和展示方式 不同观点： • **支持新投票机制但有顾虑**（Heliodex）：认可"自由投票喜欢的项目"这一创新方式，但担心技术含量高却难以演示的项目（如编程语言、分布式系统、操作系统、CLI工具）在投票中会处于劣势，可能打击新手积极性，建议设置双轨奖励：基于工作时长的大奖+基于投票数的小奖 • **技术问题反馈**（LoganDark）：网站在Safari浏览器中反复崩溃，完全无法访问 • **质疑标题策略**（bediger4000）：对"I'm 15"这类年龄强调的标题表示怀疑，认为可能是SEO策略或spam/AI内容的标志，作为65岁用户对此类标题持负面偏见 补充讨论： Heliodex提到Siege项目的成功案例，说明大奖（如Framework笔记本）确实能吸引参与者，即使投入大量时间也可能一无所获。同时指出该项目与Hack Club常规做法有明显区别。一条评论被标记为[flagged]已被移除。

Enhancing x11 Application Security with LXC (2025)

作者: shirozuki | 评分: 69 | 评论数: 10 | 发布时间: 2026-06-27 21:27
文章摘要

这篇文章介绍了如何使用 LXC 容器来增强 x11 应用程序（如浏览器）的安全性。主要步骤包括： 1. **网络配置**：安装 lxc 和 lxcfs，配置网络桥接接口 lxcbr0 2. **创建容器**：建立配置文件，使用非特权容器并通过 UID/GID 映射（将容器内 ID 映射到主机上不存在的 ID 范围 100000-165535）实现隔离 3. **应用安装**：在容器中安装所需软件（如 Firefox），创建专用用户运行应用 4. **x11 配置**：挂载 x11 socket，处理 .Xauthority 授权文件以支持图形应用 核心思想是通过容器隔离，即使应用被攻破，攻击者也无法获得主机系统的有效权限，从而保护用户的家目录和敏感数据。

评论摘要
主要讨论点：在容器中运行应用程序的安全性问题，特别是X11的安全漏洞和沙箱逃逸风险 不同观点： • **X11存在严重安全缺陷**：直接访问X11服务器会造成巨大的沙箱逃逸漏洞，任何应用都能控制/监视其他应用（包括root终端）。建议使用嵌套X服务器如Xephyr或waypipe等替代方案 • **X11难以淘汰**：质疑X11是否会像IE6一样，在主流发行版计划弃用（2025/2026）后仍存在十年以上 • **容器化的实用性问题**：容器化应用听起来不错，但在需要访问文件时会遇到困难 • **替代方案建议**：推荐使用firejail（自带常用应用预制配置）、AppArmor/SELinux（无需容器）、或XNamespace扩展（X11Libre正在开发的新方案） 补充讨论： 有评论指出Firefox本身已有完善的沙箱机制，文章标题可能过度宣传容器化的安全价值，应更关注X11本身的安全问题。也有人感叹理想世界不需要这些安全措施的复杂性。

The case for physical media ownership

文章摘要

数字商品通常是可撤销的许可而非真正所有权。实体媒介（光盘、书籍）可转售、出借和离线使用，但数字内容受平台控制。若商店关闭、失去版权或改变政策，已购内容可能被移除。微软Xbox One曾因联网验证和禁止二手游戏遭抵制而撤回政策；美国法院裁定数字文件不适用首次销售原则。2022年起消费者起诉亚马逊用"购买"按钮误导用户。迪士尼+、HBO Max、索尼PlayStation等平台已多次移除用户已购内容，引发争议。数字许可无法转售且依赖账户和服务持续运营。

评论摘要
主要讨论点：数字内容的所有权问题——用户购买的数字产品能否真正"拥有" 不同观点： • **支持DRM-free数字所有权**：真正的所有权在于能否自由分享，而非物理形式。应购买Bandcamp音乐、GOG游戏等无DRM内容，可以备份和永久使用（knaik94, rldjbpin, CodesInChaos） • **主张直接盗版**：由于版权协议复杂，盗版反而提供了最稳定的长期访问方式，4K无DRM资源可永久保存和分享（blfr） • **物理媒体已不可靠**：现代游戏光盘常只含下载器或需联网激活，物理形式无法保证真正所有权。DRM比物理/数字形式更关键（jolmg, CodesInChaos, thayne） • **呼吁版权改革**：建议禁止永久DRM、允许个人转码、对停售内容解除版权限制，以适应现代数字环境（stego-tech） 补充讨论： Sony删除已购内容事件引发强烈不满；UltraViolet尝试分离流媒体技术和法律所有权但最终失败；多数普通用户更重视便利性而非所有权，难以意识到问题严重性；即使物理媒体也可能因固件升级而失效。核心共识是当前"购买"实质是可随时撤销的许可协议。
