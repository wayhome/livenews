文章摘要

文章摘要

In April 2025, the online community Soyjak.Party claimed to have hacked 4chan, restoring the deleted /QA/ board and leaking emails of 4chan "janitors" (moderators). The hackers exploited vulnerabilities in 4chan's outdated PHP code and deprecated MySQL functions, particularly in the yotsuba.php script that handles posts and moderation. Leaked information included a list of emails, some of which were .edu addresses. Although there were claims that some janitors used .gov emails, this remained unverified. The hack led to widespread discussion on platforms like Twitter (X), KiwiFarms, and Reddit. The incident was confirmed and widely reported across various internet forums and social media.

Damn Vulnerable MCP Server

文章摘要

"Damn Vulnerable MCP Server" 是一个教育性项目，旨在展示模型上下文协议（MCP）实现中的安全漏洞。该项目包含10个难度递增的挑战，演示了各种漏洞和攻击向量，如提示注入、工具中毒、权限过大、恶意代码执行等。它面向安全研究人员、开发人员和AI安全专业人士，帮助他们了解并缓解MCP实现中的潜在安全问题。项目使用Docker搭建，包含挑战代码、文档和解决方案。MCP是一种标准化协议，允许应用为大型语言模型（LLMs）提供结构化的上下文信息。项目还提供了VSCode扩展CLINE的连接指南，以帮助用户开始使用。

评论摘要
主要讨论点：MCP（Model Context Protocol）的安全性、配置及其在不同环境中的使用 不同观点： • **[eddythompson80]** 认为MCP并不是“脆弱”的，他将MCP比作另一种客户端应用程序，强调其边界应该被理解为客户端与服务之间的界限。他认为将MCP视为脆弱就像说所有Web应用都是脆弱的一样，虽然不完全错，但主要问题在于开发者的经验不足，尤其是那些认为移动端应用不需要考虑认证和授权的开发者。 • **[kiitos]** 指出MCP服务器应运行在“隐式信任”的环境中，且MCP协议假设其传输是可信的，不需要再进行额外的认证。这意味着MCP服务器不应作为公共API来访问，而这一点似乎并未被广泛理解。 • **[puliczek]** 关注实用性，将相关资源添加到了一个GitHub项目中，以帮助更多人了解MCP安全问题。 • **[lbeurerkellner]** 作为Invariant Labs的初始安全笔记作者，提供了更多学习资源和安全扫描工具，并详细描述了MCP可能遭受的攻击方式，如工具中毒和账户接管。 • **[latchkey]** 认为讨论过于复杂，建议从基本例子开始，指向了一个具体的GitHub问题以供参考。 • **[balalayuki]** 提出了技术实现问题，询问如何正确配置和部署一个易受攻击的MCP服务器用于本地渗透测试，并遇到了端口占用问题，寻求配置建议和依赖隔离的实践（如Docker）。 • **[ldoughty]** 从教育工作者的角度出发，指出“Damn Vulnerable”命名在教育环境中可能不合适，建议使用更合适的命名以避免不必要的争议和麻烦。 补充讨论： • **[sgt101]** 强调信任的重要性，并提供了一篇文章链接，进一步讨论信任在MCP中的角色。 • **[pizzafeelsright]** 将MCP的使用类比为人际关系，认为在高度信任的环境之外使用MCP是不合适的。 • **[macinjosh]** 用比喻的方式指出MCP使用中的潜在风险，将其比作一把可能打到用户拇指的锤子。 争议焦点： • MCP是否脆弱及其适用环境：一些人认为MCP本身并不脆弱，而是其使用环境和配置问题；而另一些人则关注MCP在不同环境中的潜在安全风险。 • 命名问题：在教育环境中使用“Damn Vulnerable”命名是否合适，引发了关于命名和专业性的讨论。 技术实现问题： • 如何正确配置和部署MCP服务器，尤其是在本地渗透测试环境中，以及如何解决端口占用等技术问题。

Building an AI That Watches Rugby

作者: reddavis | 评分: 70 | 评论数: 20 | 发布时间: 2025-04-17 10:18
文章摘要

Memory Size Matters to PostgreSQL

文章摘要

本文讨论了PostgreSQL中用于管理共享缓冲区内存的机制，特别是时钟扫描（clock sweep）算法。共享缓冲区用于在数据库和后台之间传输数据页。早期版本使用简单的LRU算法，但因其局限性，PostgreSQL 8.0.0引入了自适应缓存替换（ARC），然而由于专利问题，后续版本替换为效率较低的2q算法，最终在8.1版本中采用了当前的时钟扫描算法。 时钟扫描通过"nextVictimBuffer"指针循环查找可替换的缓冲区。若缓冲区被固定或使用计数非零，则跳过。若缓冲区脏污，需先写入磁盘。当自由列表为空时，算法会遍历整个共享缓冲区以寻找替换候选。 这种机制在所有缓冲区都有效时会进行全缓冲区扫描，确保缓冲区管理的并发性和效率。在批量操作时，该策略可能会被覆盖，导致共享缓冲区的完全重写。
