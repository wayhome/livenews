这篇文章介绍了二次方融资（Quadratic Funding）机制的运作方式： **核心原理**：根据捐赠者数量而非金额分配匹配资金，奖励获得广泛社区支持的项目。计算时对每笔捐款取平方根加权，使拥有100个小额捐赠者的项目比单个大额捐赠者获得更多匹配。 **验证机制**：公链（BTC/ETH）可公开验证，私链（Monero/Zcash）通过view key验证且保护隐私。自动检测可疑地址，由委员会审核可疑捐赠（仍会到达项目但不计入匹配）。 **活动细节**：仅接受加密货币捐赠，匹配池11.5万美元全额分配，15%用于运营成本，支持Tor浏览器匿名捐赠。

评论摘要
主要讨论点：关于某个筹款活动的潜在问题和推广情况 不同观点： • **安全漏洞担忧**（hliyan）：指出筹款机制存在潜在漏洞——单个大额捐赠者可能通过大量代理支持者进行捐款，从而规避某种限制或获得不当优势 • **推广信息分享**（Cider9986）：发现并分享了该筹款活动在Tor浏览器上的广告推广链接，属于中立的信息通报 补充讨论：两条评论之间没有直接的争议或辩论关系，而是从不同角度关注同一筹款活动——一个关注潜在的系统漏洞和安全性问题，另一个关注该活动的营销推广渠道。hliyan提出的proxy supporters（代理支持者）问题暗示该筹款可能采用了某种匹配或倍增机制，使得这种exploit具有实际意义。

Doing nothing at work

文章摘要

这篇文章主张工程师应该减少工作时间，保持80%的利用率。原因是：科技公司的绩效取决于异常事件，而高影响力的机会（如帮助签大单、缓解故障、加速关键功能）都具有时效性。如果总是100%忙于低优先级工作，就会错过这些机会。作者建议适当"无所事事"：这样能注意到机会、让管理者愿意分配任务、保持精力应对高压工作、给大脑休息空间产生新想法。在处理故障时，放慢节奏、避免恐慌反而更有效。关键是为真正重要的工作保留时间和精力。

评论摘要
主要讨论点：软件工程师应该保持80%的工作负荷，还是应该全力以赴？以及如何看待"胶水工作"（glue work）的价值。 不同观点： • **支持80%负荷策略**：多位评论者认同保留余力很重要，类比游戏中的法力值管理和运动员需要休赛期。系统若长期100%运转会失去应对突发情况的能力，且软件开发需要思考时间，匆忙编码难以产出好设计。远程工作能帮助保持这种节奏。 • **激励机制扭曲问题**：几位评论者指出，预防问题往往得不到认可（"这是你应该做的"），反而是制造问题再解决问题的人获得双重荣誉。在大型或官僚组织中，有人甚至会故意让小事故发生以获得可见度，只要不演变成灾难。 • **胶水工作的争议**：有人认为应该避免无偿的胶水工作，因为组织未正式优先考虑这些任务；但也有人（如Google员工）表示，公司将其纳入绩效考核（称为"citizenship"），要求每个人分担，避免少数人（尤其是女性）承担所有杂务。关键是"不要成为唯一做无回报胶水工作的傻瓜"。 补充讨论：有人警告要警惕"掠夺者"通过非正式渠道索取无偿劳动；也有人担心完全自私的态度会让团队合作困难。估算工作时间时建议乘以1.5-2倍缓冲。

Tectonic: A modernized, complete, self-contained TeX/LaTeX engine

文章摘要

Tectonic是一个现代化的、完整的TeX/LaTeX排版引擎，基于XeTeX和TeXLive构建。其主要特点包括：自动下载所需支持文件，无需安装完整LaTeX系统；智能循环处理TeX和BibTeX；默认不生成中间文件，直接输出完整PDF；支持Unicode和现代OpenType字体；可嵌入其他应用；使用Rust语言开发并在GitHub开源。Tectonic简化了传统TeX的使用流程，特别适合需要精确排版和数学公式的科学文档，并可集成到GitHub Actions实现自动化编译。

评论摘要
主要讨论点：关于 Tectonic（LaTeX 现代化项目）的价值、局限性，以及 TeX/LaTeX 生态系统的未来 不同观点： • **LaTeX 不可替代派**（eigenblake）：LaTeX 的数学排版和输出质量无可比拟，即使编译慢也值得等待。其他实时预览方案在质量上都是妥协。愿意将其他工具作为前端，但最终输出必须通过 LaTeX。 • **Typst 替代派**（kxhbr, xvilka）：TeX 底层架构充满黑魔法和历史包袱，现代化改造成本极高。Typst 已经是"现代版 TeX"，解决了 Unicode、错误信息、编译流程等痛点。继续改造 TeX 意义不大，除非有既有模板依赖或功能缺失。 • **Tectonic 实用派**（certik）：Tectonic 完美解决了 LaTeX 的实际使用问题，跨平台、易于集成、"开箱即用"，已作为唯一 LaTeX 发行版使用多年。 • **技术挑战派**（maxloh, kxhbr）：详细说明 Tectonic 从 XeTeX 的复杂构建流程（WEB→Pascal→C→Rust）中脱身的动机。但项目已多年未有重大更新，维护者缺乏时间和动力继续投入。 补充讨论： - 生态兼容性问题：XeTeX 与 pdflatex 差异导致 Overleaf 项目不兼容 - 可复现性困境：minted 等依赖外部进程的包无法在 Tectonic 中实现 - 历史遗留方案：提及 2000 年代 Java 模块化尝试（NTS、ExTeX）
