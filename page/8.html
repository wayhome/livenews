LISPy things you can do in 64K bytes of core

作者: smartmic | 评分: 7 | 评论数: 1 | 发布时间: 2025-07-07 13:19
文章摘要

这篇文章介绍了在极小内存限制下运行LISP系统的历史和技术细节，特别是仅用64K内存的LISP实现，称为Kilo LISP。文章比较了早期计算机如IBM 704和PDP-1上的LISP实现，IBM 704有1,183,608位核心内存，而PDP-1仅有4096字内存。Kilo LISP占用约13K内存，剩余空间可容纳8192个cons单元。文章还展示了在这些系统上运行的LISP示例代码，并提到尽管早期计算机速度很慢，但如今可以在智能手机上模拟这些古老系统。文章重点关注内存使用而非运行速度。

评论摘要
主要讨论点：20世纪8位计算机时代，不同编程语言在编程教育中的适用性及优缺点 不同观点： • PaulHoule认为，在8位计算机时代，BASIC是初学者编程的主流语言，但其使用GOTO和GOSUB存在缺陷，尤其是GOSUB不支持参数和局部变量，限制了编程的灵活性。 • 一些人不满BASIC作为入门语言，原因是GOTO语句导致程序结构不清晰，但PaulHoule指出GOSUB的局限性其实更严重。 • Pascal语言受到静态类型语言爱好者的欢迎，但由于6502等处理器的寄存器和寻址模式有限，编译Pascal代码非常困难。 • Logo语言因其Lisp风格和图形功能吸引了一部分人，特别是在MIT等学术机构中，被认为具有较强的教育价值。 • FORTH语言未被广泛视为教育语言，但其利用堆栈的方式和自定义控制结构的能力，吸引了部分有抱负的程序员，被视为介于BASIC和汇编之间的一种语言。 补充讨论： • 到1983年左右，即使是廉价的计算机也能支持64KB内存，这为使用更多种类的编程语言（如C语言）提供了可能，但BASIC因其根深蒂固的地位依然占据主导。 • PaulHoule提到，理论上可以在6502处理器上运行Lisp，但未详细说明其实际可行性和流行程度。 • 争议焦点在于BASIC的简易性和普及性与其结构上的局限性之间的平衡，以及其他语言（如Pascal、Logo、FORTH）在教育中的潜在优势与实际应用中的困难。

Deno 2.4

作者: hackandthink | 评分: 117 | 评论数: 11 | 发布时间: 2025-07-07 08:44
文章摘要

Deno 2.4 恢复了 `deno bundle` 命令，用于创建单文件 JavaScript 捆绑包，支持服务器和浏览器平台，兼容 npm 和 JSR 依赖，并通过 esbuild 实现自动树摇和压缩。此外，新增 `--unstable-raw-imports` 标志，允许直接导入文本和二进制文件，简化非 JavaScript 文件的处理。同时，捆绑功能也支持与 `deno compile` 结合使用，可将资源嵌入最终编译的二进制文件中。其他更新包括内置 OpenTelemetry 稳定化、使用 `--preload` 修改环境、更简单的依赖管理等。`deno bundle` 目前为实验性功能，未来计划增加运行时 API 和插件支持。

评论摘要

Overthinking GIS (2024)

文章摘要

文章讨论了地理信息系统（GIS）在现代地图制作中的重要性，并介绍了如何通过计算地形可用性来优化数据使用。作者希望通过GIS数据定义一个更人性化的指标——“可使用性”，具体指地形是否适合建设。为此，作者试图计算地形的坡度（grade），并使用USGS提供的高分辨率数字高程模型（DEM）数据进行分析。 文章详细描述了如何利用数学工具，特别是向量微积分中的梯度（gradient）和拉普拉斯算子（Laplacian），来计算地形的坡度和变化率。通过这些计算，作者可以识别地形线密集（陡峭）和稀疏（平坦）的区域，最终实现对地形可用性的量化。作者还提供了使用Python和OpenCV库进行这些计算的简要代码示例。 总之，文章展示了如何通过GIS数据和技术手段实现对地形可使用性的评估，并为相关研究提供了实用的计算方法。

评论摘要

Local-first software (2019)

文章摘要

Toys/Lag: Jerk Monitor

作者: ptramo | 评分: 49 | 评论数: 9 | 发布时间: 2025-07-06 14:33
文章摘要

作者升级到240 Hz显示器后，对延迟更加敏感，发现无线鼠标更换USB端口后每几秒会有约10毫秒的延迟。为研究这些细微延迟，作者开发了一个工具（found.as/l），用于显示浏览器渲染帧之间以及指针移动报告之间的延迟，还分析了指针事件的批处理及其偏移。为了获得高精度计时器，作者修改了配置文件（xmit.toml），添加了跨源隔离头。最终，作者的观察得到了验证，他将避免使用该USB端口。

评论摘要
主要讨论点：鼠标事件处理、采样率、显示刷新率对用户体验的影响，以及相关技术问题 不同观点： • TheTon：几年前在Windows 10系统上发现鼠标事件丢失导致位置漂移的问题，但在macOS或Linux上没有此问题，怀疑是Windows的bug。尽管如此，仍相信高性能鼠标用户可能会丢失偶尔的移动事件，尽管这不一定被注意到。 • sillysaurusx：虽然可以理解高刷新率（如120Hz）可能有不易察觉但仍可感知的影响，但对8kHz鼠标设置是否真正影响用户体验持怀疑态度。建议通过双盲实验验证高采样率的实际影响，并提到类似的采样率辩论已经在音乐领域有过结论，通常是期望偏差导致人们认为有区别。 • jerlam：提到Logitech无线鼠标由于传感器休眠导致延迟问题，影响用户体验，最后退货。相比之下，之前的游戏鼠标由于高采样率和长休眠时间没有此问题。 • naoru：指出Safari在macOS上可能没有正确处理"pointerrawupdate"事件，导致没有指针事件的帧，同时提到ProMotion在不同浏览器中的帧率差异。 • ptramo：认为在240Hz显示器上需要将鼠标采样率设置为4000Hz或8000Hz，并提到有一个工具可以帮助确认硬件上的设置。 • daft_pink：发现将键盘直接插入Mac的USB端口速度更快，询问是否有更高品质的USB hub。 • xnx：询问某个工具是否测量与另一个网站不同的内容。 • rufus_foreman：无关技术讨论，提到对Devo乐队歌曲的个人喜好。 补充讨论： • 争议焦点：高采样率（如8kHz）是否对用户体验有实际影响。sillysaurusx主张通过实验验证，而TheTon和ptramo则相信高采样率可能有影响。 • 不同操作系统（Windows, macOS, Linux）处理鼠标事件的差异以及对用户体验的影响。 • 无线鼠标因节能功能引入的延迟问题与游戏鼠标高采样率的对比。 • 浏览器和操作系统对鼠标事件处理的兼容性问题。
