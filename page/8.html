Safari and Firefox change how big sites render based on the domain

作者: cdrnsf | 评分: 60 | 评论数: 7 | 发布时间: 2026-05-14 15:33
文章摘要

文章指出 Safari 和 Firefox 会针对特定大站点内置“兼容性补丁”，按域名修改渲染、API、UA 等，以修复网站只适配 Chrome 或自身代码问题；Chrome 不需要这样做，反映其市场主导造成的 Web 兼容性循环。

评论摘要
主要讨论点：浏览器是否应针对特定网站加入“兼容性 quirks/特殊规则”，以及这反映的是浏览器责任、网站责任还是 Chrome 主导地位问题。 不同观点： • Chrome“没有本地列表”是因为其兼容处理更多在服务端完成；Safari、Firefox则会基于域名调整渲染行为。 • 有人认为给新网站（如 claude.ai）加入 WebKit quirks 不妥：这类网站仍在积极维护，应该由网站方修复兼容问题；quirks 更适合老旧或维护缓慢的网站。 • 有人原以为 Chrome 也有类似列表，并举 WebKit 仓库中本站点也存在 quirk 的例子，说明这种做法并非只针对大型网站。 • 反对浏览器各自维护不同修复列表的观点：如果 Safari 和 Firefox 的站点及修复完全一致还可理解，但现实并不一致，可能导致行为碎片化。 • 网站开发责任观点：Web 服务至少应安排开发者使用 Firefox、Safari 测试；有人表示自己负责 Firefox，确保客户应用至少支持 Chrome 和 Firefox，Safari 则取决于是否有 Mac。 • 用户代理/平台歧视问题：有人提到 Linux 桌面用户也会遇到网站因 UA 中含 “Linux” 而无法正常使用，说明兼容问题不只限于浏览器。 • 市场压力观点：建议用户放弃 Chrome，让网站所有者看到 Chrome 流量下降，从而减少只为 Chrome 优化的现象。 补充讨论：争议焦点在于，浏览器是否应主动为具体网站“兜底”，还是应迫使网站遵循标准、承担跨浏览器兼容责任。

文章摘要

文章以街道建筑为例，说明物品既有可见的物理属性，也有不可见的金钱属性：所有权、价格、租金、贷款与税收等。作者指出，这些抽象的货币关系深刻决定人们如何使用空间、组织劳动，并依靠制度与强制力维持，体现了现代社会将金钱与事物相混同的“双重现实”。

主要讨论点：围绕书摘/文章对“货币”的批判展开，讨论货币是否只是有缺陷的抽象、经济学如何解释货币、以及现代货币制度是否损害储蓄与信任。 不同观点： • 文章形式批评：有人认为原文铺垫过多、隐喻冗余，应直接表达观点；也有人只是抱怨网页弹窗影响阅读。 • 货币是必要抽象：Bratmon认为作者把“货币”作为对生产劳动和资产的抽象，发现其会“泄漏”后就认为应废除，这是误解。类比软件工程，抽象虽不完美但对复杂经济至关重要，不能因失效场景否定其价值。 • 货币崇拜批评：justonceokay用“coin sickness”形容重视金钱多于实际物质财富的人，例如只认服装品牌却不懂面料和做工，呼应对货币符号化的批判。 • 经济学批判：imtringued认为主流经济学对“货币中性”与“货币降低交易成本”存在概念偷换。若货币提高劳动生产率，就类似资本品，可产生收益；高利贷因此可能榨取分工带来的巨大剩余。中央银行通过设定利率、提供货币，压低既有持币者的收益。 • 硬通货/反通胀立场：mikewarot主张“真正的钱”应是金属等稳定、可储蓄的实物媒介，批评现代货币制度鼓励投资股市、侵蚀储蓄，2%通胀目标和缩水式涨价削弱社会信任。 • 讽刺性回应：underlipton以调侃方式总结为“以物易物回来了、格林斯潘是魔鬼、政府在通胀上撒谎”，并指出原文讨论的时代背景与沃尔克冲击、日本失落十年等宏观历史相关。 补充讨论：有人推荐两本关于货币史和现代公司的书，作为理解货币与商业制度的延伸阅读。
