Why is this site built with C

作者: todsacerdoti | 评分: 142 | 评论数: 32 | 发布时间: 2025-03-30 17:51
文章摘要

本文讲述了作者在搭建个人网站过程中遇到的挑战和最终选择使用C语言构建网站的原因。起初，作者使用Django和Nginx搭建了一个动态网站，但发现维护和发布内容过于繁琐。随后，他转向使用Nuxt生成静态网站，但依赖JavaScript工具链又导致维护困难。最终，作者总结出新网站需满足易于写作、静态生成、少依赖、长期稳定等要求。经过多次尝试，他选择使用C语言编写一个简单的Markdown解析器，以实现零依赖、快速生成静态网站的目标，解决了之前遇到的速度和维护问题。

本文介绍了GitHub CodeQL潜在供应链攻击的发现过程。攻击始于一个公开暴露的秘密，有效期仅1.022秒，但足以让攻击者在大多数使用CodeQL的仓库中执行代码。攻击可能导致： 1. 泄露私有仓库的源代码，损害知识产权。 2. 窃取GitHub Actions中的凭据，进一步发动供应链攻击。 3. 在运行CodeQL的内部基础设施上执行代码。 4. 危害使用CodeQL和GitHub Actions缓存的仓库中的工作流凭据。 研究人员通过自建的秘密扫描工具发现了这一问题，并确认了潜在的供应链攻击风险。尽管攻击手段类似于近期发生的tj-actions/changed-files攻击，但GitHub尚未发现其平台或系统受到危害的证据。CodeQL是GitHub的代码分析引擎，被数十万仓库信任使用。

评论摘要
主要讨论点：GitHub Actions的安全性、权限管理和性能问题 不同观点： • Sytten认为，GitHub如果推出不可变 actions，可以解决目前 GitHub Actions (GHA) 上大部分的安全问题，尤其是攻击风险。他提到这一方案本可以防止很多当前出现的灾难性问题，并对 GitHub 尚未推出该功能表示失望。 • nyrikki 关注临时 token 的权限问题，质疑为什么这些 token 可以创建新部署和生成工件证明。虽然 GitHub 修复时禁用了调试日志，但 nyrikki 认为更重要的是修改临时 token 的权限以适应代码分析引擎的需求。 • ashishb 提出，CI（持续集成）和 CD（持续交付）应完全分离，以防止 CI 环境被攻破后导致 CD 相关的 token 泄露。这表明了对现有架构安全性的担忧。 • junto 对 GitHub 的响应速度表示赞赏，认为其快速反应值得肯定。 • helsinki 的评论更多是个人感慨，与技术讨论无直接关系，提到对域名所有权的个人兴趣。 • udev4096 认为使用公共 GitHub Actions 容易引发安全问题，建议自行托管 CI 系统，例如使用 woodpecker、Circle、Travis、GitLab 等工具，以获得更高的安全性。 • ryao 指出，在 OpenZFS 的 PR 中使用 CodeQL 并未造成问题，因为其代码并非秘密，表明在某些场景下，GitHub Actions 的安全问题可能并不严重。 • atxtechbro 简单询问问题是否已经修复，未提供进一步的论据或观点。 • bloqs 抱怨网站的性能问题，指出页面滚动时表现很差，涉及用户体验。 补充讨论： • 安全问题集中在临时 token 的权限管理和 GitHub Actions 的不可变性，部分用户认为 GitHub 应该采取更多措施来防止潜在攻击。 • 有人建议将 CI 和 CD 环境分离，以增强安全性，减少因 CI 被攻破而带来的风险。 • 对 GitHub 的响应速度表示肯定，但也有对其性能的批评。 • 针对使用公共 GitHub Actions 的风险，部分用户建议自行托管 CI 系统以提高安全性。

Oka.wiki

作者: jjmarr | 评分: 93 | 评论数: 9 | 发布时间: 2025-03-30 23:59
文章摘要

Open Knowledge Association (OKA)是一个非营利组织，致力于通过资助全职贡献者和翻译者来改善Wikipedia及其他开放平台的内容。他们优先处理能产生最大影响的工作，特别关注来自Wikipedia编辑中代表性不足国家的贡献者，以减少系统性偏见。OKA通过月度津贴支持这些贡献者，并利用机器学习工具进行初步草稿以提高效率。他们的工作重点是翻译现有高质量文章，优先处理科学、技术、工程和金融等缺乏关注的领域，覆盖英语、西班牙语和葡萄牙语Wikipedia。OKA的资金主要来自个人捐款，但也接受慈善机构、政府和公司的捐助，且不影响编辑的独立性。目前，他们已创建2,200多篇新文章，年浏览量达800万次。

评论摘要
主要讨论点：付费维基百科编辑组织的必要性、潜在利益冲突及系统性偏见问题 不同观点： • **caseyy**：对oka.wiki这样的组织存在的必要性表示怀疑，认为已有大量优秀的维基百科文章和机器翻译工具，不需要付费编辑。同时，对付费编辑可能带来的利益冲突表示担忧。 • **jjmarr**：解释Wikimedia基金会并不直接支付编辑者报酬，而oka.wiki是一个非营利组织，主要资助翻译工作，并列举其资助编辑的三大英语文章，试图说明其贡献。 • **ahmedfromtunis**：指出即使付费编辑保持客观，他们的工作仍可能造成偏见。例如，在标准竞争中，一个公司可以通过资助编辑创建详细文章来影响公众选择，即使文章本身是客观的。 • **stevefan1999**：质疑oka.wiki是否能真正避免系统性偏见，即使其透明公开。引用“谁来监督监督者”的问题，表达对任何组织（包括oka.wiki）的潜在政治倾向的担忧。 • **seydor**：担心这种付费编辑模式可能演变为一种官方化的“草根伪装”业务，提出维基百科是否会允许这种模式的疑问。 • **peanutz454**：怀念像微软Encarta那样的多媒体百科全书，认为维基百科尽管预算庞大，但在软件更新和内容质量上不如Encarta，并建议创建类似Encarta的多媒体资源供教育使用。 • **chasing**：要求如果要开放付费编辑模式，必须明确列出捐赠者和捐赠金额，以确保透明性。 • **jon8888**：简短评论，暗示付费编辑可能是偏见的来源，但没有详细论述。 补充讨论： - 评论中反复提到付费编辑可能带来的利益冲突和系统性偏见问题。 - 有人质疑维基百科现有的运作模式和资源分配，特别是与历史上的多媒体百科全书（如Encarta）对比。 - 透明性和监督问题也被多次提及，尤其是对付费编辑模式的潜在不信任。
