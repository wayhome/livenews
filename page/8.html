Nnd – a TUI debugger alternative to GDB, LLDB

作者: zX41ZdbW | 评分: 267 | 评论数: 24 | 发布时间: 2025-05-06 13:58
文章摘要

"nnd" 是一个为 Linux 开发的调试器，具有快速、基于 TUI（文本用户界面）、从零实现且不依赖 gdb 或 lldb 的特点。它适用于大型的可执行文件，强调操作流畅无卡顿，支持多线程和异步任务。然而，它仅限于 Linux 系统、x86 架构和64位程序，且目前不支持远程调试、多进程、记录/回放等功能。 该调试器具备常见的调试功能，如断点、条件断点、步进、代码和反汇编显示等，并为 C++ 和 Rust 提供了内置的美化打印功能。目前，它作为一个约 6 MB 的独立可执行文件分发，用户可通过 curl 下载或从源码编译使用。项目仍在开发中，作者每日使用并认为其有帮助，但尚未广泛测试。

评论摘要
主要讨论点：围绕调试器工具的功能、使用体验以及TUI（文本用户界面）与GUI（图形用户界面）的优劣比较。 不同观点： • **调试器功能的重要性**：al13n详细列举了一个完善的调试器应具备的核心功能，如显示代码、线程、堆栈跟踪、局部变量、条件断点、步进调试、自定义键绑定、TUI支持等。这些功能增强了调试器的实用性和用户体验。 • **与GDB的比较**：philsnow指出GDB已经有TUI，但比较“复古”，而al13n的项目提供了更多的现代功能和舒适性（creature comforts）。tieze则提到了pwndbg，它为gdb/lldb增加了生活质量（QoL）改进，如tmux窗格、堆检查、着色等，提供了更友好的调试体验。 • **对TUI的态度**：一部分用户如udev和larusso对TUI有积极的评价，认为TUI快速且高效，尤其对于习惯使用命令行的开发者来说非常方便。但tw600040则对TUI持否定态度，认为TUI是“无人区”，既没有GUI的优势，也没有纯命令行的简洁。 • **其他语言和平台的需求**：jebarker表达了对Python调试器的需求，尤其是在远程服务器和集群计算节点上使用，而Zambyte则关心Zig语言的调试器支持情况。 • **对大文件和大型二进制文件的处理**：alfanick好奇如何处理ClickHouse这样的大型二进制文件（2.5GB），而coldblues提到RAD调试器正在进行Linux端口的开发，希望改善Linux上的调试体验。 补充讨论： • **性能与用户体验**：dec0dedab0de赞赏了al13n项目中对操作效率的重视，尤其是多线程、异步操作、可取消任务和进度条等功能。 • **怀旧与现代工具的比较**：trollbridge将该项目与曾经的CodeView相比较，认为其提供了现代调试工具中缺乏的一些功能。 • **终端应用的吸引力**：gitroom表示自己长期使用TUI应用，认为终端操作速度快且直观，比一些大型GUI工具更符合需求。 争议焦点： • **TUI与GUI/CLI的优劣**：一部分用户认为TUI结合了GUI和CLI的优点，而另一部分用户（如tw600040）则认为TUI是“最差的两者结合”，不如纯粹的GUI或CLI。

Accents in latent spaces: How AI hears accent strength in English

作者: ilyausorov | 评分: 233 | 评论数: 30 | 发布时间: 2025-05-06 14:07
文章摘要

BoldVoice是一款AI驱动的口音教练应用，专注于帮助非英语母语者改善口音。文章介绍了如何通过机器学习模型理解和量化口音强度。首先，他们引入了“口音指纹”概念，通过大规模带口音的英语语音模型生成嵌入表示（torch.Size([1, 768, 12])）。接着，通过构建包含1000条语音数据的潜在空间，展示了不同口音强度的分布，并使用PLS回归和UMAP降维技术，将口音强度可视化。文章对比了产品管理实习生Victor（带强烈中文口音）和美国英语母语者Eliza的录音，发现Victor的录音位于潜在空间的右上角，而Eliza的则在左下角，表明Victor的口音更强。文章还展示了如何通过去除背景噪音和调整音域来帮助Victor更接近Eliza的口音，但去除噪音对口音强度影响不大，表明模型主要关注口音特征而非录音质量。

作者: voxadam | 评分: 141 | 评论数: 15 | 发布时间: 2025-05-06 18:47
文章摘要

**Brush** 是一个用 Rust 实现的兼容 POSIX 和 bash 的 shell，支持 Linux 和 macOS，并通过 WSL 在 Windows 上实验性运行。它功能齐全，可作为日常使用的交互式 shell，能执行大多数 sh 和 bash 脚本，但存在一些已知的兼容性限制，如部分 `set` 和 `shopt` 选项未完全实现。目前不建议在生产环境中使用，但欢迎贡献和反馈。安装方式包括通过 `cargo install` 或 Nix、Arch Linux 的 AUR 进行安装。项目采用 MIT 许可，主要通过与现有 shell 对比进行测试，拥有 550+ 个测试案例。

Old Timey Code and Old Timey Mono Fonts

文章摘要

本文讨论了软件膨胀（bloat）仍然是软件最大的漏洞问题。作者Daniel Zender回顾了1995年Niklaus Wirth提出的“精简软件”的呼吁，并指出近30年后情况仍未改善。现代软件往往包含数百万行代码和大量未知来源的外部库，导致安全问题频发，甚至大型科技公司也犯下基本的安全错误。 文章强调软件安全形势严峻，建议通过立法（如欧盟的NIS2、网络弹性法案和产品责任指令）来提升软件质量。作者分析了当前问题 partly 源于经济激励，因为快速推出不安全软件能节省时间和成本。最后，作者分享了自己编写简约但现代软件的实践，呼吁业内人士共同改善现状。 总之，软件确实变得异常复杂和危险，需要更多关注和改进。
