Iroh: A library to establish direct connection between peers

文章摘要

Iroh 是一个基于公钥拨号的 API，能够自动寻找并维持最快网络连接，支持打洞技术以实现直接连接，失败时可回退到公共中继服务器。它使用 QUIC 协议，提供认证加密、并发流、数据报传输等功能，避免线头阻塞。Iroh 提供了多个预定义协议，如 iroh-blobs 用于内容寻址的大规模数据传输，iroh-gossip 用于建立发布-订阅网络。此外，Iroh 还支持 Rust 以外的其他语言通过 FFI 绑定使用。项目包含多个子模块，如核心库 iroh、中继服务器实现 iroh-relay 等，并采用 Apache-2.0 和 MIT 双重许可。

Howdy – Windows Hello style facial authentication for Linux

作者: LorenDB | 评分: 60 | 评论数: 8 | 发布时间: 2025-06-23 18:34
文章摘要

Howdy 是一个为 Linux 提供类似 Windows Hello™ 面部认证功能的软件。它利用内置的红外发射器和摄像头进行面部识别，通过 PAM 系统实现登录、锁屏、sudo 等场景下的密码替代。Howdy 支持 Debian/Ubuntu、Arch Linux、Fedora 和 openSUSE 等发行版，安装方式各有不同，部分需要额外配置。它依赖于 Python 3.6+、meson、ninja 等工具构建，并可通过命令行管理面部模型。安装后需运行 `sudo howdy add` 进行面部录入。如遇问题，可通过查看 Wiki 或 GitHub 上的类似问题进行排查。用户还可以通过贡献代码或提交功能请求参与项目。

评论摘要
主要讨论点：开源面部识别认证项目的质量和功能与商业版本的比较，以及技术实现和应用场景的讨论 不同观点： • **[bsimpson]** 认为开源项目的面部识别认证可能会有更多的误报/漏报，因为商业版本需要支持所有人使用，经过了大量测试，而开源项目可能在广泛适用性上有所欠缺。 • **[aitchnyu]** 关注用户体验问题，希望在系统处理面部识别时有提示，特别是当识别失败时，可以有一个重试按钮。同时，也对红外照片是否会欺骗模型提出了疑问，并对红外摄像头的实验表示兴趣。 • **[joelthelion]** 表示希望能有更好的指纹识别支持，暗示面部识别并不是其首选的认证方式。 • **[charcircuit]** 指出该开源项目与Windows Hello的不同之处，包括它仅通过2D图像提取特征，缺乏深度重建，容易被纸张等简单手段欺骗。此外，还提到该项目在功能上不如Windows的面部识别广泛，仅用于用户认证，且保存面部特征点文件时使用明文，存在安全问题。 • **[mouse_]** 表达了对预桌面认证功能的期待，认为这是一个非常吸引人的特性，希望能看到其实现。 • **[seany]** 关注开源面部识别模型在NIST/iBeta排名中达到较好性能所需的条件，暗示开源项目在性能上与商业模型存在差距。 • **[deafpolygon]** 对项目依赖Python2表示不解，可能在考虑技术更新和维护的必要性。 • **[fsateler]** 注意到项目虽然活跃，但最后一个版本发布于2020年，质疑为何没有新的版本发布。 补充讨论： • 项目在技术实现上的局限性（如2D图像 vs 深度重建）以及安全性问题（明文保存特征点）是主要的技术争议点。 • 用户体验和多因素认证方式（如指纹识别与面部识别的对比）也是讨论的重要内容。 • 开源项目与商业版本在性能、可靠性及功能广泛性上的对比是潜在的争议焦点。
