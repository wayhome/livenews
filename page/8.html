Multiple Security Issues in GNU Screen

作者: st_goliath | 评分: 268 | 评论数: 21 | 发布时间: 2025-05-13 11:28
文章摘要

这篇文章主要讨论了在GNU/Linux系统中**Screen**软件的多个安全问题，特别是5.0.0版本中的本地root提权漏洞，该漏洞尤其影响设置为setuid-root的安装（如Arch Linux和NetBSD）。文章详细描述了这些漏洞的发现过程、影响范围以及提供的补丁。同时，文章还概述了不同Linux和UNIX发行版中的Screen配置和版本情况，并提供了安全改进建议及漏洞影响矩阵。此外，文章强调了Screen的多用户模式及其潜在的安全风险，因为该模式下Screen代码运行具有root权限，增加了攻击面。最后，文章附上了相关的补丁集和问题披露过程的困难。

评论摘要
主要讨论点：GNU Screen及相关终端工具的安全性、功能性及未来发展 不同观点： • [RMPR] 指出Screen的多用户模式在以setuid-root权限运行时，会增加安全风险，并提到类似工具tmate，同时质疑tmux是否存在相同漏洞。 • [teddyh] 补充说明在Debian系统中，GNU Screen默认并未以setuid-root权限安装，从而降低了相关风险。 • [zoobab] 提到Screen在日志功能上缺乏文档，并建议改进问题跟踪系统。 • [mmsc] 认为GNU Screen的开发已经停滞，并对该软件的当前开发状态表示怀疑，同时询问特定功能是否存在。 • [indigodaddy] 询问是否存在针对Screen漏洞的RedHat官方CVE页面。 • [seethishat] 推荐使用tmux，尤其是在OpenBSD上，因其经过审核，更为安全。 • [sundarurfriend] 推荐Zellij作为现代化的终端多路复用工具，认为其默认设置和用户界面更加友好。 • [nmz] 强调安全性应优先考虑代码行数较少的工具，如mtm、abduco和dvtm，并认为Screen由于代码复杂性难以实现真正的安全。 • [Pxtl] 建议将Screen转换为围绕tmux的兼容层，以解决其功能和安全问题。 • [charcircuit] 强烈反对在2025年继续使用setuid二进制文件，认为这会导致严重的安全漏洞，应全面移除。 补充讨论： • [jedimastert] 和 [worldsavior] 提供了Screen安全问题的博文链接，为讨论提供了参考资料。 • [lemonwaterlime] 和 [Scene_Cast2] 讨论了byobu和Zellij等工具的使用体验，特别是键绑定和现代化的特性。 • [warpeggio] 以幽默方式表达了对tmux的偏好。 争议焦点： • GNU Screen在多用户模式下的安全性及其未来发展方向。 • 是否应全面淘汰setuid二进制文件以提升安全性。 • 不同终端多路复用工具（如tmux、Zellij）之间的比较与选择。 总体来看，讨论围绕GNU Screen及其替代工具的功能性、安全性和未来发展展开，参与者提供了多种视角和建议。

Why I Use WebAssembly

作者: todsacerdoti | 评分: 7 | 评论数: 1 | 发布时间: 2025-05-14 17:19
文章摘要

WebAssembly (WASM) 是我最喜欢的技术之一，它拓展了 web 应用的可能性。例如，通过 `npm install @ffmpeg/ffmpeg`，你可以在浏览器中运行 FFmpeg，实现文件转换，这原本需要依赖在线转换工具。然而，WASM 的应用远不止于此，它还可以用于提升性能，比如 Figma 使用 WASM 将加载时间缩短了三倍。此外，WASM 还具有出色的隔离特性，使其在浏览器之外也很有用，甚至可能改变跨平台应用的分发和云服务的部署方式。 我使用 WASM 的原因主要在于它可以直接在客户端处理复杂任务，例如文件转换，从而避免服务器往返通信，并能实时显示任务进度。这不仅降低了托管成本，还可以提升用户体验。 当然，并不是所有 web 应用都适合放弃服务器而转向 WASM，特别是那些需要集中式服务器作为信任中介的应用。但对于“桌面级”的 web 应用，WASM 提供了强大的支持，能够实现高性能和跨平台。尽管 WASM 目前在性能和功能上仍有局限，但对于偶尔使用的用户而言，它已经足够。
