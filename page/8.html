文章摘要

Defuddle是一个用于从网页中提取主要内容的工具，能够去除不必要的元素如评论、侧边栏、页眉、页脚等，生成干净、可读的HTML文档。它专为Obsidian Web Clipper设计，适合作为Mozilla Readability的替代品，具有更宽容的元素处理方式，并能一致地处理脚注、代码块等。Defuddle提供三个版本：核心版（无依赖，适合浏览器使用）、完整版（支持数学公式解析）、Node.js版（使用JSDOM，支持Markdown转换）。它提取的内容包括标题、作者、发布日期、主图、网站图标等元数据，并提供调试模式和选择性移除元素的功能。安装通过npm进行，使用时可根据需求配置选项。

Loading Pydantic models from JSON without running out of memory

作者: itamarst | 评分: 107 | 评论数: 12 | 发布时间: 2025-05-22 18:06
文章摘要

文章主要讨论了如何在使用Pydantic模型加载大型JSON文件时减少内存消耗。默认情况下，Pydantic加载JSON文件会导致高内存使用，可能达到文件大小的20倍。为解决此问题，文章提出了两种主要方法： 1. **使用ijson库进行增量解析**：通过流式处理JSON文件，逐项加载数据，从而减少解析时的内存占用，但速度会变慢。 2. **使用带slots的数据类**：通过Pydantic的数据类支持和slots特性，固定对象属性以减少内存使用。 最终，结合这两种方法，可以将100MB JSON文件的峰值内存使用从2000MB减少到450MB。这些方法特别适用于需要处理大型JSON文件且内存资源有限的情况。

评论摘要
主要讨论点：Pydantic库的JSON解析性能和内存使用优化，以及相关技术选择和替代方案。 不同观点： • [scolvin] Pydantic的作者介绍了即将进行的改进计划，通过迭代解析JSON来提高性能并减少内存使用。他们提到新的JSON解析器jiter已经支持迭代解析，接下来的任务是在pydantic-core中解决生命周期问题。这将使Pydantic的JSON解析速度提高约3倍，并显著降低内存开销。 • [fidotron] 质疑当前Pydantic处理大文件时的内存消耗问题，指出处理100MB文件需要2GB内存是不合理的，并将其与XML解析中的SAX和DOM方法进行类比，暗示需要一种更节省内存的解析方式。 • [jmugan] 提到在处理复杂模型（包含多层嵌套的BaseModels和联合类型）时，Pydantic无法完全加载模型，部分深层结构仍为字典。他寻求一种能够搜索不同加载方式的解析器。 • [deepsquirrelnet] 建议使用jsonl替代JSON，或者重新评估是否适合使用JSON格式，尤其对于大文件，建议考虑二进制格式。 • [dgan] 表示已放弃使用Python的dataclasses和JSON，转而使用protobufs，并为每个wire模型添加Mixin类以提供额外方法。他认为自动且静态类型化的反序列化值得投入。 • [fjasdfas] 询问在所有Python数据类型上设置`slots=True`的潜在缺点。 • [kayson] 关心dataclass版本的速度比较情况。 • [zxilly] 建议使用mmap可能节省内存，但不确定是否能在Python中实现。 • [thisguy47] 希望看到`ijson`与`json.load(f)`的比较，并提到`ujson`也值得关注。 • [m_ke] 建议放弃Pydantic，转而使用msgspec，并提供了一个参考链接。 补充讨论： - 对Pydantic性能和内存使用的关注是主要焦点，尤其是处理大文件和复杂模型时。 - 提出了多种替代技术，包括protobufs、jsonl、mmap和msgspec，每种技术都有不同的优缺点。 - 对Pydantic未来改进的期待，特别是迭代解析JSON的性能提升。 - 不同用户对性能、易用性和内存消耗的不同需求和偏好，导致了多样化的技术选择和建议。
