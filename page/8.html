Mac Themes Garden

作者: speckx | 评分: 179 | 评论数: 20 | 发布时间: 2025-05-07 19:44
文章摘要

2025年5月5日，作者推出了"Mac Themes Garden"网站，展示超过3000个经典Mac时代的Kaleidoscope主题，供用户浏览、下载和探索。网站还提供RSS订阅源，方便用户跟踪主题的更新。该项目源自作者运营的Mac Themes Bot，最初在Bluesky、Mastodon和Cohost上展示Mac OS X和经典Mac主题。由于原始数据获取困难，作者通过手动截图记录约4000个Kaleidoscope主题的信息，包括主题的作者和发布年份。由于过程复杂且耗时，目前网站建设尚未完成，但已上线供用户使用。

I can’t understand Apple’s Critical Alert policy (2023)

文章摘要

本文作者开发了一款名为SuperDose的iOS药物提醒应用，需要使用苹果的紧急警报API，以便在手机静音或勿扰模式下仍能发出提醒通知。尽管苹果的健康应用也使用该API，作者的请求却被拒绝，理由是其应用无法保证使用场景。作者对此感到困惑，因为紧急警报功能需要用户明确同意才能启用，且其他看似不紧急的提醒应用却获得了批准。作者担心没有该权限，用户可能因手机静音而错过关键药物提醒，存在潜在危险，并对苹果的政策感到沮丧。

2009年，奥巴马就任美国总统时，因安全风险被迫放弃使用黑莓手机，引发广泛关注。虽然初期有报道称他完全放弃黑莓，但实际上在经过特殊加密和安全措施后，他得以继续使用。其前任小布什在2000年上任时也放弃了使用电子邮件。奥巴马的黑莓经过美国特勤局、白宫通信局和国家安全局的多方协作，安装了加密软件SecurVoice，以确保通信安全。初期曾考虑使用军用设备Sectéra Edge，但因其笨重不便而未被奥巴马采纳。最终，奥巴马保留了一部经过安全强化的黑莓手机，并更改了电子邮件地址以确保保密。

Bootstrapping Lisp in a Boot Sector

作者: gone35 | 评分: 84 | 评论数: 3 | 发布时间: 2025-05-05 07:52
文章摘要

**sectorlisp** 是一个仅 512 字节的 LISP 实现，能够在裸机上引导启动 John McCarthy 的元循环求值器。该项目旨在通过三方面简化 LISP：提供一个纯 LISP 表达式实现，仅使用核心功能；提供可读的 C 语言参考实现，可在 POSIX 平台上引导元循环求值器；以及一个可在个人电脑 BIOS 上启动的 i8086 汇编实现。用户可以通过 `make` 命令生成一个可启动的 `sectorlisp.bin` 文件，或使用模拟器如 **Blinkenlights** 或 **QEMU** 进行测试。该项目展示了如何在极小环境中实现 LISP 引导。

评论摘要
主要讨论点：在引导扇区中实现Lisp语言的可行性和价值 不同观点： • [积极观点] **cassepipe** 提供了相关博客文章链接，对在引导扇区实现Lisp表示关注，并可能认为这是一个有趣且具有技术挑战性的项目。 • [质疑观点] **gitroom** 对在如此有限的空间中实现Lisp表示惊讶，质疑在这种严格限制下能实现的功能范围。同时，提出了这种限制是否会促进更好的解决方案，还是只会增加不必要的难度。 补充讨论： • **技术挑战**：gitroom 强调了在引导扇区这样小的空间中实现复杂语言的技术难度，反映了对技术实现细节的关注。 • **约束的价值**：gitroom 还提出了一个值得讨论的问题，即技术约束是否能推动创新，或只是造成不必要的障碍。这是一个关于技术限制对创造力和解决方案影响的普遍性讨论。 争议焦点：主要在于技术限制是否能够激发更好的解决方案，还是在实际操作中只会导致额外的困难。这涉及到对创新过程中的约束作用的不同看法。

Web search on the Anthropic API

作者: cmogni1 | 评分: 262 | 评论数: 14 | 发布时间: 2025-05-07 20:18
文章摘要

Waiting for Postgres 18: Accelerating Disk Reads with Asynchronous I/O

作者: lfittl | 评分: 538 | 评论数: 18 | 发布时间: 2025-05-07 14:57
文章摘要

Postgres 18引入异步I/O（AIO），显著改变了I/O处理方式，尤其在云环境中能大幅提升性能。异步I/O允许并发处理多个读请求，无需等待每个请求完成，从而减少I/O等待时间。Postgres 17通过引入读流API为异步I/O打下基础，但仍依赖操作系统内核的预读取机制。Postgres 18则直接由数据库获取数据，绕过内核机制，提高I/O效率。 Postgres 18新增了`io_method`配置参数，控制I/O操作方式，包括： 1. `io_method = sync`：保持同步I/O模式。 2. `io_method = worker`：使用后台I/O工作进程处理读请求，不阻塞主进程。 3. `io_method = io_uring`：利用Linux的io_uring实现高效异步I/O。 在AWS上的测试显示，异步I/O使读取性能翻倍，io_uring表现尤为突出。当前版本AIO仅支持读操作，写操作仍为同步。用户需根据实际环境调整`io_method`和`effective_io_concurrency`以优化性能。
