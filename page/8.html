Floor and Ceil versus Denormals on CPU and GPU

作者: ibobev | 评分: 41 | 评论数: 8 | 发布时间: 2026-05-26 13:22
文章摘要

这篇文章探讨了浮点数运算中floor和ceil函数在处理非规格化数(denormals)时的行为差异。 核心问题是：`floor(-1.175493930432748e-38)`的结果是什么？ 文章首先解释了floor、ceil、trunc、round四个函数的舍入规则。关键在于，该输入值是一个非规格化数（接近零的极小值）。不同平台对非规格化数的处理方式不同： - **保留非规格化数**：`floor(-1.175...e-38) = -1.0` - **将非规格化数归零**：`floor(-1.175...e-38) = -0.0` 这种差异可能导致CPU和GPU之间、不同GPU厂商之间的不确定性行为。作者测试发现，x86-64架构的CPU（使用Visual Studio 2022编译）在各种编译选项下都保留非规格化数。

评论摘要
主要讨论点：浮点数非规格化数（denormals）在硬件实现中的必要性和性能权衡 不同观点： • **取消denormals派**：认为denormals是极小的数值（约2^-149），在大多数场景不需要，RISC-V等追求简洁的架构应该去掉它们，需要时可改用double或自定义浮点实现 • **性能优先派**：指出CPU处理denormals极慢（可能慢10倍），对很多应用来说denormals和零的差异可忽略，建议启用flush-to-zero编译选项来提升性能 • **规范化处理派**：提出WebGPU/WGSL的解决方案——为每个操作指定精度要求，并通过完整的测试套件验证 • **正确性质疑派**：质疑为何正确实现denormals会影响性能，以及Nvidia为追求性能而走捷径的做法 • **设计缺陷派**：认为这是IEEE浮点设计的问题之一，建议考虑新设计如Posits来长期替代IEEE标准 补充讨论：有人指出denormals实际上是零能被表示的方式，暗示其基础性作用；另有人提到即使denormals的发明者在使用时也遇到正确性问题，引用了相关论文附录作为证据。

文章摘要

Rockstar游戏工作者工会（Rockstar Game Workers Union）正式成立，隶属于英国独立工人工会（IWGB）。该工会因Rockstar去年以"严重不当行为"为由解雇30多名员工而与公司对簿公堂，工会认为这是打压工会的行为。此事促使爱丁堡、伦敦、利兹等多地的Rockstar员工加入工会。工会的三大诉求是：薪酬透明化、灵活工作制和终止加班文化。法庭审理日期已定但尚未公布，工会已开通社交媒体账号并接受捐款支持诉讼。

评论摘要
主要讨论点：Rockstar游戏开发者成立工会的意义和影响 不同观点： • **支持工会派**：认为工会能改善工作条件（结束crunch加班文化、提高薪酬透明度、灵活工作），并最终提升产品质量。强调游戏行业存在严重的剥削问题（65-80小时无偿加班），工人需要团结对抗资方。 • **质疑工会派**：担心工会按资历晋升的机制会阻碍优秀开发者获得应有回报，可能导致产品质量下降。有人直接预测"游戏会很糟糕"。 • **行业问题分析派**：指出游戏开发薪酬远低于大科技公司（尽管工作性质相似），以及软件工程师工会在美国难以建立的原因（外包、H1B签证导致的廉价劳动力竞争，如有人才$65K做$250K的工作）。 • **对Rockstar管理层的批评**：列举具体案例，如GTA5加载bug多年未修复直到玩家逆向工程解决，且公司未给予奖励，认为工会成立是管理层无能的结果。 补充讨论：评论区充满调侃，多次提到"在GTA6发布前我们先有了工会/AGI/火星生命"，反映出对GTA6漫长开发周期的戏谑。

Real-time LLM Inference on Standard GPUs: 3k tokens/s per request

作者: NicoConstant | 评分: 205 | 评论数: 33 | 发布时间: 2026-05-29 09:47
文章摘要

这篇文章主要讨论了AI推理速度优化问题。核心观点是： 1. **单请求解码速度**对AI代理至关重要，因为代理工作流是串行的（检查→规划→编辑→测试→修改） 2. **内存带宽**而非算力是瓶颈。在批量大小为1时，GPU的内存带宽利用率（MBU）比算力利用率更关键 3. **现有推理软件栈**未充分利用GPU硬件能力。标准数据中心GPU（如H200、MI300X）拥有极高的内存带宽（30+ TB/s），但软件层面存在瓶颈 4. **架构/引擎/内核协同设计**可以突破限制，让GPU达到专用推理硬件的速度水平 文章强调，随着AI代理变得更自主，**智能×迭代速度**成为生产力前沿，快速生成token能显著改善用户体验（从8分钟降至20秒）。

评论摘要
主要讨论点：Kog.ai推出的新推理引擎在H200 GPU上实现了超高token生成速度，但其实用性和公平性引发争议。 不同观点： • **质疑比较公平性**：使用2B小模型对比大型前沿模型不公平，缺少与Taalas（15000 tok/s）等竞品的对比，需要在30B等实用规模模型上验证性能（mungoman2, ilaksh, robmccoll） • **质疑"标准GPU"说法**：H200和MI300X是高端数据中心GPU，不应称为"标准GPU"，有标题党嫌疑（0-bad-sectors, 867-5309, bcjdjsndon） • **技术价值肯定**：恢复了内存带宽与token生成速度的线性关系，在数据中心硬件上实现了消费级显卡的效率表现，demo体验出色（stymaar, rashkov, cataflam） • **实用性担忧**：模型输出质量差、逻辑错误明显，批处理（dynamic batching）和新模型适配能力未知，对speculative decoding等新方法的适用性存疑（blindr, CastFX, joefourier） • **扩展性质疑**：类比小规模线性扩展不代表大规模同样有效，担心扩展到更大模型时遇到瓶颈（robmccoll, arjie） 补充讨论：有用户关注开源计划、多卡通信瓶颈（PCIe限制）等工程实现细节。
