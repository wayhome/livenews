F* file system – file search that reads SSD directly bypassing OS kernel

作者: neogoose | 评分: 104 | 评论数: 14 | 发布时间: 2026-06-21 20:44
文章摘要

FFS（F* File System）是一个用C语言编写的命令行文件搜索工具，约1500行代码。它的核心特点是绕过操作系统内核，直接读取磁盘原始数据进行搜索。 **主要特性：** - 直接读取磁盘块设备，跳过VFS缓冲层 - 支持Ext4、Btrfs和APFS文件系统 - 可搜索未挂载的卷（如.dmg、.iso文件） - 利用OpenMP实现多核并行处理 **性能表现：** 文件数量越多，相比ripgrep优势越明显。在325万文件的测试中，FFS用时36秒，而ripgrep需要75秒。 **局限性：** macOS主磁盘需禁用SIP保护、可能遗漏最近写入的文件、仅支持已实现的文件系统。本质上这是一个概念验证项目，展示直接磁盘访问可以超越内核VFS的性能开销。

评论摘要
主要讨论点：一个名为fff的项目，声称通过直接读取块设备来"绕过文件系统"实现快速搜索 不同观点： • **技术准确性质疑**：多位用户（watusername, Retr0id）指出标题有误导性——该项目并未真正"绕过内核"，只是绕过了文件系统层，仍需通过内核读取/dev设备节点。watusername建议集成SPDK才算真正绕过内核 • **实用性争议**：neogoose认为需要sudo权限使其"几乎无用"，但也承认开发过程很有趣；kasabali质疑"仅限SSD"的说法，认为标题误导 • **性能怀疑**：self_awareness质疑其速度优势，认为使用内核缓存的常规方式应该更快，因为可能完全不触碰磁盘 • **权限解决方案**：porridgeraisin提供了详细的setfacl和组权限配置方案，可在不需要sudo的情况下运行 • **功能认可**：部分用户认可其技术实现，支持ext4/btrfs/apfs、多线程、压缩和独立卷搜索等特性 补充讨论：有用户开玩笑对比Windows Search（4petesake），提及BSD FFS文件系统支持缺失（drewg123），以及对F*编程语言的联想（wk_end）。amelius提出SSD控制器层面的刷新可靠性问题。

评论摘要
主要讨论点：在AI时代，软件工程师是否还需要学习编程，以及需要学习到什么程度。 不同观点： • **必须深度学习编程基础**：AI是技能放大器而非替代品，就像计算器需要数学知识才能有效使用。缺乏基础的人用AI会产生垃圾代码且无法判断质量。需要理解数据结构、算法、架构等核心概念，才能有效指导和评估AI生成的代码（vitally3643, alfanick, sn9）。 • **重点转向理论与架构理解**：未来人类的角色是指导AI而非直接编码。应优先学习计算机科学理论、系统架构、抽象层理解，而非具体算法实现。需要知道"正确的问题"和识别未知盲区（YuechenLi, lubujackson, w10-1）。 • **编程将成为基础素养而非核心技能**：类比数学发展历程，编程会像解方程一样不再是可售卖技能，但理解编程对构建更高层次能力必不可少。学习编程主要是为了培养问题分解思维和与AI沟通的语言（jonfw, al_borland）。 • **英语将成为新编程语言**：有观点认为5-10年后主流"编程语言"将是英语，编程能力即用英语清晰表达需求和测试（jamesli233）。 • **AI已完全替代编程工作**：极端案例显示部分公司已禁止员工手写代码，完全依赖AI生成和审查，传统开发岗位正被取消（sqeak）。 补充讨论：多数人强调"分层理解能力"的重要性——团队中总需要能深入底层的专家。AI成本上升和服务可靠性也是实际考量因素。
