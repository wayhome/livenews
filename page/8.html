Show HN: MCP Server SDK in Bash

作者: muthuishere | 评分: 124 | 评论数: 15 | 发布时间: 2025-05-30 04:25
文章摘要

这篇文章介绍了由`muthuishere`开发的轻量级Bash实现的MCP（Model Context Protocol）服务器——`mcp-server-bash-sdk`。该项目旨在提供一个零开销的替代方案，避免使用Node.js、Python等较重的运行时环境。它实现了完整的JSON-RPC 2.0和MCP协议，支持通过stdio进行动态工具发现和外部JSON配置。 主要特性包括： - 完整的JSON-RPC 2.0协议支持 - 动态工具发现 - 外部JSON配置 - 易于扩展的自定义工具 项目包含两个主要脚本：`mcpserver_core.sh`处理协议，`moviemcpserver.sh`包含业务逻辑。文章还提供了创建自定义MCP服务器的示例，如`weatherserver.sh`，并介绍了如何在VS Code和GitHub Copilot中使用该工具。 该项目适用于AI助手和本地工具执行，但具有不支持并发、有限内存管理等局限性。项目遵循MIT许可证。 完整代码见：[GitHub链接](https://github.com/muthuishhere/mcp-server-bash-sdk)

On eval in dynamic languages generally and in Racket specifically (2011)

作者: swatson741 | 评分: 64 | 评论数: 9 | 发布时间: 2025-05-28 20:44
文章摘要

文章讨论了动态语言中的`eval`函数，它看似强大，但有经验的程序员通常避免使用，因其不当使用会引发问题。作者通过一个比喻解释了`eval`的本质：一种是直接给出明确指令（如将画布涂成红色），另一种是让其他人执行包含指令的句子。前者可被编译和优化，而后者类似于`eval`，无法很好地编译且执行结果依赖于环境。`eval`在某些情况下是必要且有用的，例如当指令来自外部（如施工经理），但多数情况下应避免，因其使程序更难理解和优化。关键在于区分何时真正需要动态执行代码。

评论摘要
主要讨论点：不同编程语言中 `eval` 函数的差异及其使用场景，特别是 Lisp 语言中的 `eval` 特性及其相关讨论。 不同观点： • **taeric 的观点**：Lisp 中的 `eval` 与大多数其他语言的 `eval` 不同，它接受的不是字符串，而是代码即数据（code is data）的理念。这使得 Lisp 的 `eval` 可以带来一些显著的差异，尤其是在元编程（metaprogramming）方面。他通过个人探索展示了这一特性。 • **neilv 的观点**：反对新手在未充分理解的情况下滥用 `eval`。他指出，许多新手在阅读学术教材后会立即尝试使用 `eval`，而往往这是不合适的。他还提到，在 Racket 社区中，他曾尝试 discourage 误用 `eval`。他认为 `eval` 应作为最后的、危险的工具来使用，且在教学中应尽量延后介绍。 • **kazinator 的观点**：认为 `eval` 不应被阉割，主张保留完整的语言功能。他提出可以通过多种方式对 `eval` 进行沙盒化，包括验证代码和在限制环境中执行代码。他还强调，不应让 `eval` 的功能因为安全问题而被削弱。 • **programLyrique 的观点**：通过引用学术文章，展示了 `eval` 在其他语言（如 JavaScript 和 R）中的使用情况，提供了一些背景信息和实例，但没有深入展开讨论。 • **behnamoh 的观点**：提出了 Lisp 的强大宏系统是否源于能够用 Lisp 自身实现 `eval` 函数的问题。他认为 Lisp 通过少量原语和特殊形式构建了 `eval` 函数，并通过此机制扩展出新的语法规则，这与 Lisp 宏系统有相似的核心思想。 • **TOGoS 的观点**：总结了 `eval` 函数在不同层次上的语义定义。他认为，`eval` 的语义定义越复杂，其行为就越不明确。他将 JavaScript 的 `eval` 视为不明确的一端，Lisp 宏则处于中间，而经过解析和编译的 lambda 表达式则处于定义明确的另一端。 补充讨论： • 争议的焦点之一是 `eval` 的使用场景及其潜在的危险性。neilv 强调新手容易误用 `eval`，而 kazinator 则认为应通过沙盒化等手段来安全地使用 `eval`，而不是简单地避免使用。 • 另一个讨论点是 Lisp 的 `eval` 与宏系统的关系，behnamoh 和 TOGoS 提供了对 Lisp 元编程能力的深入理解，并探讨了 `eval` 在其中扮演的关键角色。 • 不同语言中 `eval` 的实现和使用差异也被提及，如 JavaScript 和 R 中的 `eval`，提供了跨语言的比较视角。 通过这些观点，可以看出 `eval` 函数在不同语言和场景中的复杂性和潜在问题，以及 Lisp 在元编程方面的独特优势。
