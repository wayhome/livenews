Quantum dot qubit using High NA EUV lithography

作者: luu | 评分: 20 | 评论数: 2 | 发布时间: 2026-05-27 09:15
文章摘要

imec在ITF World大会上展示了全球首个使用高数值孔径极紫外光刻(High NA EUV)技术制造的量子点量子比特器件。这是首个采用该技术的集成硬件设备。 硅量子点自旋量子比特被视为工业化量子计算的有力候选，因其生产工艺与传统CMOS芯片兼容。imec成功制造出栅极间隙仅6纳米的量子比特网络，理论上可在单芯片上集成数百万量子比特。 High NA EUV光刻技术实现了纳米级精密图案化，使量子比特从实验室演示转向300mm晶圆厂规模化生产。该技术不仅对2纳米以下逻辑芯片和高密度存储至关重要，也将在未来量子计算硬件中发挥关键作用。

评论摘要
主要讨论点：量子计算的实际进展与公众预期之间的差距 不同观点： • **技术现实派（somewhatgoated）**：认为当前研究仅证明了潜在量子比特架构的制造方法，并未实际制造出量子比特。对量子计算能否规模化持怀疑态度，指出我们仍处于探索可扩展架构是否可物理制造的早期阶段。 • **公众认知观察**：普通大众误以为量子计算即将到来，需要立即准备应对，但这与技术实际进展存在明显脱节。 • **算法怀疑派（dvh）**：简短质疑是否实现了Shor算法（用于破解RSA加密的关键量子算法），暗示这类研究可能缺乏实质性突破。 补充讨论：评论反映出量子计算领域存在"炒作与现实"的矛盾——媒体和公众对量子计算的期待远超当前技术能力，而实际研究仍在解决基础制造问题。Shor算法的提及点出了量子计算商业化的关键里程碑尚未达成。

Is AI causing a repeat of frontend’s lost decade?

作者: xyzal | 评分: 392 | 评论数: 73 | 发布时间: 2026-05-29 11:09
文章摘要

这篇文章探讨了AI对编程工作的影响，作者将其类比为前端开发在过去十年经历的"去技能化"过程。 文章指出，JavaScript框架曾将前端开发从需要深入理解HTML、CSS、浏览器差异、可访问性等专业技能的工作，简化为任何通用程序员都能操作的任务。这降低了入门门槛，但也削弱了专业开发者的议价能力，导致工作质量下降。 作者认为AI正在对整个编程行业做同样的事情——通过更高层次的抽象自动化编程工作，虽然提高了效率，但也在"去技能化"这个职业。程序员们感到失落，因为他们花费多年磨练的技能正在被市场贬值。 文章还提到，这种抽象层往往会带来性能损失和复杂性，最终细节问题总会暴露出来。

评论摘要
主要讨论点：AI和现代框架是否导致前端开发"去技能化"，以及这种变化的利弊 不同观点： • **支持简化派**：认为所谓"深度专业知识"实际上是处理浏览器兼容性、CSS特异性等"意外复杂度"，现代抽象层和AI让更多人能构建产品是好事，即使牺牲部分性能或可访问性也是合理权衡 • **历史循环派**：指出"去技能化"并非新现象——Web开发曾被C/C++开发者视为降低门槛，早期框架(Rails/Django)也曾引发类似争议。每一代技术进步都伴随这种焦虑，这是行业自动化的必然结果 • **质量怀疑派**：质疑AI生成代码的独特性和价值，指出"AI味"明显的产品容易被识破，缺乏竞争壁垒。同时认为过去的工作质量也参差不齐，AI至少保证了基于成熟惯例的"可用性" • **复杂度转移派**：认为现代前端(SSR、懒加载等)比早期HTML/CSS/JS更复杂，只是复杂度从底层quirks转向了架构层面。真正的专业工作仍需理解底层技术，框架只是"漏洞百出的抽象" 补充讨论：多位评论者指出真正的问题在于设计决策和用户体验的平庸化，而非技术本身。有人建议前端开发者转向设计能力提升，因为"品味"是AI难以替代的领域。

The California state assembly has passed the 'Protect Our Games Act'

作者: TechTechTech | 评分: 223 | 评论数: 24 | 发布时间: 2026-05-29 19:55
文章摘要

加州议会通过了《保护我们的游戏法案》(AB 1921)，这是"停止杀死游戏"运动的重大进展。该法案要求数字游戏发行商在终止服务后仍需保持游戏可访问性。法案规定：2027年1月1日后发售的数字游戏，停服前需提前60天通知，并须提供替代版本、补丁或退款。该运动源于2024年育碧关闭《飙酷车神》服务器事件。法案尚需加州参议院和州长批准才能生效，但在游戏公司云集的加州通过具有重要象征意义，预计将影响整个美国游戏行业的服务政策。

评论摘要
主要讨论点：加州AB 1921法案要求游戏公司在终止服务前提供60天通知，并确保玩家能继续访问游戏或提供退款。 不同观点： • **支持立场**：认为这是消费者保护的重大胜利。指出服务器架构转换技术上可行（去掉负载均衡和匹配系统即可），开发者应提前规划。强调游戏是文化遗产，应像实体游戏一样可传承，社区自建服务器已有成功先例（如Battlefield 2通过BF2Hub复活） • **技术担忧**：质疑发布服务器代码的可行性，因为许多公司使用第三方专有中间件，不拥有全部代码。担心合规成本和法律复杂性 • **规避策略预测**：认为公司会转向订阅制、免费游戏等豁免模式来规避法规。有人担忧会像电影业一样为每款游戏成立空壳公司，关闭时无人可追责。也有人建议公司可能只保留1台服务器"技术上"维持服务 • **反对立场**：批评加州过度监管会扼杀游戏产业（类比好莱坞外迁）。质疑谁来承担持续运营服务器的成本 补充讨论：法案仅适用于2027年后数字销售的游戏，排除订阅服务和免费游戏。有人呼吁将保护扩展到订阅游戏和数字商品继承权。也有开发者关心跨州管辖问题。

文章摘要

评论摘要
主要讨论点：AI代码审查工具在实际应用中的价值、成本和实施方式 不同观点： • **支持派**：认为AI代码审查ROI很高，值得投入。有团队使用Copilot和GitHub Actions效果良好，建议直接用最强模型（Opus/GPT-5.5）以降低复杂度。也有开发者采用Gerrit工作流让AI agent互相审查，虽然慢但质量更好 • **质疑成本效益派**：指出Cloudflare在小于10行的PR上花费5000美元，而初级工程师审查成本接近0.2美元且能积累人力资本。质疑"共享上下文"节省token的说法存在逻辑漏洞 • **信噪比问题派**：多数人反映AI审查信噪比太低，过度纠结框架特定模式（如PySpark）和琐碎细节，反而成为负担。开发者需要在提交前先"训练"AI以减少噪音 • **流程优化派**：建议将AI审查前置到pre-commit hook或pre-push阶段，而非在MR阶段，以加快反馈循环、减少噪音。认为非确定性的AI系统不适合CI环节 补充讨论：有人提出更智能的方案——让AI遍历整个代码库理解架构影响而非仅看diff，或开发教育性审查工具按语义重要性组织代码块。也有人质疑PR审查本身是否真是瓶颈，以及AI迭代审查可能陷入无限循环的问题。

文章摘要

这篇文章介绍了如何设置本地 git 远程仓库。主要步骤包括： 1. 使用 `git clone --bare` 创建裸仓库作为远程仓库 2. 通过本地路径或 SSH 协议添加远程仓库：`git remote add local [路径]` 3. 设置默认分支并进行推送和拉取操作 作者分享了使用本地远程仓库的好处：当异地远程仓库不稳定或访问延迟高时，本地远程仓库提供了快速可靠的备份方案。这样既能享受本地推送的零延迟，又能保持异地备份，且无需依赖大型科技公司的服务。

评论摘要
主要讨论点：Git 本地远程仓库的实际应用场景和价值 不同观点： • **实用派**：认为本地远程很有价值。用于同一机器多个克隆间共享对象、离线备份（`git push /mnt/backup/repo.git --all`）、通过 USB 或 Rclone 挂载的文件系统同步加密仓库、使用 Syncthing 同步个人项目、在容器中隔离 agent 操作 • **历史延续派**：指出这是 Git 分布式特性的体现，早于 GitHub 时代就在共享计算机上使用，认为现代开发者因依赖 GitHub 而"重新发现"了 Git 的分布式本质 • **质疑派**（mystifyingpoi）：不理解必要性，认为本地分支就够了，等网络恢复再推送即可 • **技术扩展派**：提到相关技巧如 `git clone --reference` 节省空间、`git remote set-url --add --push` 实现一次推送到多个目标、使用 bare repo 搜索邮件列表 补充讨论： 有人提到 AI 检测到 PII 时可以阻止推送到云端但允许本地推送的安全场景。还有评论指出文章页脚包含 Anthropic 的模型拒绝触发字符串。并发问题在单人使用场景下可接受。
