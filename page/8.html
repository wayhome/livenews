CharlotteOS – An Experimental Modern Operating System

作者: ementally | 评分: 124 | 评论数: 10 | 发布时间: 2025-11-01 13:12
文章摘要

Catten是CharlotteOS项目的实验性现代操作系统内核，采用Rust和x86_64汇编语言开发，设计为可扩展的单体内核，借鉴了exokernel、Plan 9和Fuchsia等系统的理念。它支持类型安全的系统命名空间、基于URI的路径访问和细粒度权限控制，可通过网络跨主机访问资源。项目仍处早期开发阶段，主要面向x86_64架构，要求UEFI固件、ACPI支持和至少128MB内存。遵循GPLv3+许可证，鼓励社区贡献，提供Discord和Matrix交流渠道。

Hard Rust requirements from May onward

作者: rkta | 评分: 375 | 评论数: 52 | 发布时间: 2025-11-01 07:31
文章摘要

Debian开发者Julian Andres Klode宣布，计划从2026年5月起在APT中引入Rust硬性依赖和相关代码，主要涉及Rust编译器、标准库和Sequoia生态系统。此举旨在利用内存安全语言提升.deb、.ar、.tar等文件的解析能力及HTTP签名验证代码的安全性。他要求尚未支持Rust工具链的端口维护者在6个月内完成适配，否则应考虑淘汰相关端口，以推动项目采用现代技术，不再受限于老旧设备的兼容性问题。

评论摘要
主要讨论点：[Debian 是否应该强制要求使用 Rust 替代 C 语言编写的关键基础设施] 不同观点： • **支持 Rust 替代 C** - C 语言存在技术债务，特别是处理不可信数据时容易引发安全问题。 - Rust 在设计上更现代，具备内存安全特性，且并不比 C 更难写。 - 如果某些架构不支持 Rust，可以放弃它们（如 32 位 x86 被放弃一样）。 • **反对强制推行 Rust** - Rust 工具链对部分架构（如 alpha、hppa、m68k、sh4）支持不足，可能导致这些架构被边缘化。 - 强制推行 Rust 的方式（如邮件中的强硬语气）令人反感，可能引发社区分裂。 - 已有项目（如 Redox）尝试用 Rust 构建全新系统，应优先支持这些创新而非强制改造旧项目。 • **质疑 Rust 的长期影响** - Rust 生态可能导致 Debian 偏离 GNU/Linux 传统，因为 Rust 工具链和库多采用非 GPL 许可证（如 MIT）。 - 多语言工具链（Python、Node、Go、Rust）会增加发行版维护复杂度，可能引入供应链攻击等新问题。 • **中立或技术权衡观点** - 应等待 GCC 对 Rust 的支持成熟（如 gccrs），以降低语言迭代带来的兼容性风险。 - 重写旧工具（如 apt）未必能显著提升安全性，尤其是未改进设计的情况下。 补充讨论： - **争议焦点**： 1. **推行方式的合理性**：支持者认为强硬态度是应对保守主义的必要手段，反对者则认为这是“寄生式”强制改造。 2. **架构支持问题**：Rust 对部分老旧架构支持不足，可能迫使社区放弃这些平台。 3. **社区文化冲突**：Rust 开发者被批评带有攻击性（如邮件作者过往行为），引发对技术讨论氛围的担忧。 - **其他讨论点**： - Canonical 员工推动这一变更的动机引发猜测（是否存在商业意图）。 - 部分用户认为 Linux 生态需“修剪”遗留代码，但如何平衡创新与稳定性仍是难题。
