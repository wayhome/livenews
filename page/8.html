Gemini Diffusion

作者: mdp2021 | 评分: 842 | 评论数: 40 | 发布时间: 2025-05-22 01:13
文章摘要

Google在I/O大会上发布了Gemini Diffusion，这是其首个使用扩散模型（而非传统的自回归方式）的大语言模型。与逐字生成文本的传统模型不同，扩散模型通过逐步优化噪声来生成输出，具有更快的速度和更好的纠错能力，尤其在编辑、数学和代码任务中表现突出。作者测试显示，Gemini Diffusion能在数秒内创建交互式网页，速度达857 tokens/秒。尽管名为扩散模型，它仍基于Transformer架构，类似于BERT的掩码语言建模，但能处理更高比例的掩码 tokens。目前尚未有独立基准测试，但Google称其性能媲美Gemini 2.0 Flash-Lite，且速度快5倍。

Model-Based Machine Learning (2023)

作者: Tomte | 评分: 3 | 评论数: 0 | 发布时间: 2025-05-23 19:05
文章摘要

《Model-Based Machine Learning》一书由John Winn编写，旨在介绍基于模型的机器学习方法，所有版税捐赠给Cystic Fibrosis Trust。书中通过多个实际案例讲解关键概念和技术，包括： 1. **谋杀谜案**：介绍概率、随机变量、贝叶斯定理等基础概念。 2. **评估技能**：通过测试评估个人技能，涉及消息传递算法和ROC曲线。 3. **匹配玩家**：应用于在线游戏玩家匹配，涉及高斯分布和在线学习。 4. **整理收件箱**：通过学习用户行为清理收件箱，讨论过拟合和精确度-召回曲线。 5. **推荐系统**：通过协同过滤推荐电影，涉及对称性和对称破缺。 6. **理解哮喘**：通过模型预测儿童哮喘，涉及时间序列和模型选择。 7. **利用众包**：通过众包数据提供准确信息，涉及Dirichlet分布和混淆矩阵。 8. **解读模型**：分析他人创建的模型，涉及LDA和主成分分析等。 书中还介绍了机器学习生命周期，并展望了该领域的未来发展。读者可获取书中源代码，并通过反馈提交错误和意见。

Remote Prompt Injection in Gitlab Duo Leads to Source Code Theft

作者: chillax | 评分: 25 | 评论数: 4 | 发布时间: 2025-05-23 07:12
文章摘要

本文介绍了Legit研究团队在GitLab Duo中发现的远程提示注入漏洞，该漏洞可导致源代码泄露和HTML注入攻击。GitLab Duo是集成在GitLab中的人工智能助手，旨在帮助开发者进行代码建议、安全审查等任务。然而，研究发现，通过在合并请求、提交信息、问题描述和源代码中嵌入隐藏提示，攻击者可以操纵GitLab Duo，泄露私有项目的源代码，篡改代码建议，甚至泄露未公开的零日漏洞。 攻击者利用KaTeX、Base16等编码技巧隐藏提示，成功骗过系统。此外，由于GitLab Duo的响应采用Markdown格式并逐步渲染，攻击者可以注入恶意HTML，控制页面部分内容，发起网络攻击。GitLab已修复此问题，但文章详细解析了整个攻击链，展示了从提示注入到HTML注入的完整过程。

评论摘要
主要讨论点：AI应用安全问题，特别是与不受信任的第三方服务器相关的数据泄露风险，以及对大型供应商在安全问题上的处理方式的讨论。 不同观点： • wunderwuzzi23：赞赏揭露数据泄露问题，指出通过不可信第三方服务器（尤其是图像渲染）进行数据泄露是常见的AI安全问题。提到自己曾构建ASCII Smuggler并记录了图像数据泄露向量，且在多家供应商中发现了10多个类似问题。同时提到GitHub Copilot Chat去年有类似漏洞。 • cedws：对提示注入问题未解决表示担忧，认为在问题解决之前不会将LLM（大型语言模型）集成到任何工具中，例如MCPs、IDEs或agents。倾向于仅使用简单的提示框，并手动处理输出。 • mdaniel：批评GitLab让LLM拥有读取平台上所有仓库的权限是错误的做法，认为应该使用个人访问令牌或为Duo单独创建一个访问令牌，这是一种更安全的改进。 • nusl：对GitLab的修复措施表示怀疑，认为其补救措施不太可信。 补充讨论： • 讨论中提到了多个具体案例和漏洞（如ASCII Smuggler和GitHub Copilot Chat的漏洞），这些实例为观点提供了支持。 • 不同用户对供应商在处理安全漏洞方面的能力和措施持不同态度，有人认为问题普遍且严重，有人对具体案例的修复效果表示不信任。 • 安全问题集中在数据泄露和提示注入两个方面，用户对当前修复措施的效果和供应商的应对能力存在争议。

文章摘要

Kotlin LSP 是一个为 Kotlin 语言提供的 Visual Studio Code 插件，基于 IntelliJ IDEA 和 Language Server Protocol (LSP) 实现，目前处于预览前的探索阶段。该项目支持 JVM Kotlin Gradle 项目的基本功能，如项目导入、代码导航、代码操作、重构和代码完成等，但仅限 JVM 项目。当前版本适合实验和玩具项目，不建议日常使用，因其稳定性未得到保证。该插件主要在 macOS 和 Linux 平台的 VS Code 上测试通过，其他 LSP 编辑器需手动配置。部分源码暂时闭源，未来将完全开源。反馈和问题可通过 GitHub 提交。
