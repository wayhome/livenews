.NET on Heroku Now Generally Available

文章摘要

.NET 支持在 Heroku 平台上已正式发布（Generally Available，GA），标志着 .NET 开发者可以在 Heroku 上获得全面支持的生产环境。.NET 生态系统现已成为 Heroku 的第七个运行时环境，开发者可以获得最新的 .NET 运行时和 SDK，自动构建和部署 .NET 应用（包括 C#、F# 和 Visual Basic）。Heroku 提供全面的文档和支持，适应 .NET 开发者的习惯和工作流程，支持多种部署模式和自动化任务，如数据库迁移和回滚。无论你是新用户还是从测试版过渡，Heroku 都提供了平滑的部署体验和工具，帮助 .NET 开发者更高效地构建和发布应用。

评论摘要
主要讨论点：围绕不同工具和方法部署 .NET 应用程序的讨论 不同观点： • mythz：表示将继续使用 **Kamal**（https://kamal-deploy.org）工具来将 .NET Docker 应用程序部署到 **Hetzner Cloud**（https://cloud.hetzner.com）。这表明 mythz 对 Kamal 工具和 Hetzner Cloud 有一定的依赖和信任。 • bob1029：对不同的 .NET 部署模型（如 **self-contained**、**ReadyToRun** 和 **Native AOT**）进行了评论。他特别指出 **self-contained** 部署选项可能存在风险，因为这种方法允许将应用程序直接复制到任何云虚拟机上运行，并结合 **SQLite** 使用时，只需复制文件夹和重启进程，几乎不需要其他编排工作。这暗示 bob1029 认为这种简便性可能隐藏着潜在的复杂性和风险。 补充讨论： • peterpost2：提到 **Heroku** 已被 **Salesforce** 收购的事实，但该评论并未直接参与部署工具或方法的讨论，只是提供了一个背景信息。 • stuaxo：提到自己误以为讨论的是 **.NET** 在 **Haiku** 操作系统上的部署，表明讨论中可能存在一些技术背景或工具的混淆。不过该评论未深入探讨具体部署方式。 争议焦点： • bob1029 对 **self-contained** 部署方式的简便性表示了一定的担忧，认为其虽然操作简单，但可能存在潜在风险。而 mythz 则似乎更关注实际应用中的便捷性，继续使用 Kamal 和 Hetzner Cloud 进行部署。 总结：讨论主要围绕 .NET 应用程序的不同部署方式，尤其是 self-contained 方式的便捷性与潜在风险，以及具体工具（如 Kamal 和 Hetzner Cloud）的使用。

文章摘要

本文讲述了作者尝试在古董笔记本电脑（Toshiba 300 CDT）上安装各种操作系统，最终只有OpenBSD成功运行。这台1998年发布的笔记本内存仅32MB，运行现代系统非常困难。作者最初尝试了多种Linux发行版和其它操作系统，均失败。最终，OpenBSD成功启动并运行，尽管由于硬件限制和安全性设置，使用过程缓慢且具有挑战性。 作者提到，OpenBSD因其简约和安全性备受推崇，但学习曲线陡峭。在尝试配置和使用过程中遇到了许多困难，例如权限问题和配置文件错误。作者还对比了现代公司繁琐的客户验证流程，赞赏OpenBSD.Amsterdam提供的虚拟机服务，支持OpenBSD开发且操作直接、无繁琐手续。 最终，作者再次尝试OpenBSD，感受到其文档和专注于创建可靠系统的优点，尽管使用过程中仍遇到配置问题。

Aptera's First Solar Road Trip. 300 Miles, One Charge

文章摘要
