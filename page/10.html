Json2dir: a JSON-to-directory converter, a fast alternative to home-manager

作者: alurm | 评分: 42 | 评论数: 7 | 发布时间: 2025-08-08 18:46
文章摘要

`json2dir` 是一个将 JSON 转换为目录结构的工具，能够快速管理 dotfiles，是 home-manager 的替代方案。它通过解析 JSON 文件来创建目录、文件、符号链接和可执行脚本。对象表示目录，字符串表示文件内容，数组可以表示符号链接或可执行文件。使用时需注意 JSON 的 UTF-8 编码限制，以及在创建文件时防范 TOCTOU 攻击。该项目使用 Nix 和 Rust 构建，提供了 flake.nix 用于打包，并可在 json2dir.cachix.org 使用 Nix 缓存。项目文件包括构建脚本和示例配置等。

评论摘要
主要讨论点：围绕 json2dir 项目及其相关技术实现的优缺点讨论 不同观点： • [tadfisher] 认为 NixOS 及其相关工具（如 home-manager）通过激活脚本在文件系统中散布配置文件，破坏了配置的原子性，增加了出错机会。他主张使用包装脚本和程序命名空间技术（如 bwrap）来避免这些问题，但承认共享库是该方法的弱点。 • [bapak] 提出了一种跨平台的命令序列方案，直接使用 shell 命令（如 echo, mkdir, ln 等）来实现配置文件的管理，而不是使用 JSON 格式。 • [thayne] 反对使用 JSON 作为配置语言，指出 JSON 不支持注释和多行字符串，这使得脚本编写和维护变得困难。 • [Rucadi] 支持通过覆盖或修补软件包本身来处理配置文件（dotfiles），认为这样可以更好地控制配置，并便于在不同机器上迁移应用。 • [netsharc] 倾向于使用传统的 shell 命令（如 echo, cat, ln, mkdir 等）来实现配置管理，而不是引入新的工具或格式。 • [mdtrooper] 提出了 dir2json 的可能性，即反向将目录结构转换为 JSON 格式，但没有进一步展开讨论。 • [jauntywundrkind] 分享了一个通过 JavaScript 代理项目来自动持久化更改的方案，强调了可视化和可脚本化状态的优势。他还认为使用层次文件系统来存储数据比使用复杂的 JSON 格式更好，支持更直观的终端用户编程。 补充讨论： • 争议的焦点主要集中在 JSON 作为配置语言的适用性，特别是在可读性（注释和多行字符串支持）和操作便利性方面。 • 另一个讨论点是关于如何有效管理配置文件和目录结构，包括使用包装脚本、命名空间技术、shell 命令，以及直接修补软件包等不同方法的优缺点。 • 有些参与者（如 [jauntywundrkind]）还提出了对更直观的文件系统使用和终端用户编程的期望，认为当前依赖复杂数据格式的做法可能并不理想。

Flipper Zero dark web firmware bypasses rolling code security

作者: lq9AJ8yrfs | 评分: 460 | 评论数: 32 | 发布时间: 2025-08-07 21:10
文章摘要

YouTube频道Talking Sasquach最近测试了一种Flipper Zero的自定义固件，可以破解现代车辆使用的滚码安全系统。与传统的RollJam攻击需要干扰信号并重放不同，这种新攻击只需捕获一次遥控钥匙信号，无需干扰，即可完全模拟钥匙的所有功能，如开锁、关锁和开启后备箱。这种攻击通过逆向工程滚码序列或利用所谓的"RollBack"攻击实现，使原钥匙失效。受影响车辆包括克莱斯勒、道奇、菲亚特、福特、现代、Jeep、起亚、三菱和斯巴鲁等。目前尚无简单修复方法，可能需要大规模召回车辆。

评论摘要
主要讨论点：无钥匙进入系统和汽车钥匙扣的安全性及潜在漏洞 不同观点： • [kj4ips] 认为许多滚码系统基于KeyLoq技术，该技术设计良好，但存在一个致命弱点：如果掌握了"制造商密钥"，通过两次捕捉信号即可破解序列密钥。虽然直接暴力破解成本高，但获取制造商密钥并不困难。 • [RachelF] 指出无钥匙启动系统存在安全隐患，认为多重安全机制更为可靠。同时提到汽车制造商可能从车辆被盗中获益，因为保险赔付常促使顾客购买新车。 • [rootsudo] 质疑为何将相关技术与"暗网"过度关联，认为使用这些技术本身不一定违法，尽管在美国可能涉及法律问题（如USC 18 1029/30）。 • [Terr_] 提出如果信号不是广播传输，而是通过物理接触或人耳可感知的声波传输，可能提高安全性。认为锁车操作相对解锁操作更安全。 • [finaard] 认为某些视频内容缺乏实质性信息，只是重新包装了已有的滚码漏洞。 • [palata] 关心钥匙扣失效后的后果，询问用户是否能自行重置，还是必须由零售商处理。 • [tzs] 询问如果不按钥匙扣按钮是否能避免被攻击，并提到自己的车在靠近车门时可通过按车门把手上的按钮解锁。 • [theoreticalmal] 认为攻击的主要威胁不是车辆被盗，而是攻击者通过捕获按键信号使原钥匙失效，迫使用户重新编程，从而造成不便。 • [beagle3] 提到自己的保险公司要求安装代码输入设备以防止汽车被盗，认为尽管初期麻烦，但能有效防止常见盗车手段。 • [piyuv] 担心政客可能因无钥匙系统的不安全性而禁止相关工具（如Flipper Zero），而不是正视问题本身。 • [antirez] 猜测攻击针对的是KEELOQ协议，并质疑芯片中的加密技术是否真的被完全破解，表示需要进一步了解攻击细节。 • [move-on-by] 询问为何某些汽车制造商（如Chevrolet、Toyota）未受影响，而其他制造商（如Ford、Hyundai）则存在漏洞，是否有未被测试或使用不同技术的原因。 • [geekamongus] 提到在亚马逊上可以轻松购买福特车队的钥匙，从而解锁大多数福特卡车和面包车，质疑当前系统的安全性。 • [joelthelion] 质疑为何汽车不使用公钥加密技术，是成本问题还是其他原因。 • [IshKebab] 对漏洞的有效性表示震惊，认为实现该系统的工程师应该知道其不安全性，并表示自己不会想到去检查这种漏洞。 补充讨论： • 争议焦点在于无钥匙系统的安全性以及如何有效防止攻击。 • 不同评论者对制造商密钥的泄露途径、攻击的可行性及后果、以及潜在解决方案（如公钥加密、物理接触信号传输）进行了讨论。 • 对汽车制造商是否从车辆被盗中获益的质疑，以及对政客可能禁止相关工具的担忧也被提出。

Writing a storage engine for Postgres: An in-memory table access method (2023)

作者: ibobev | 评分: 95 | 评论数: 2 | 发布时间: 2025-08-04 08:53
文章摘要

Postgres 12引入了可更换存储引擎的功能，类似于MySQL长期支持的特性。尽管目前Postgres的第三方存储引擎开发尚处早期阶段，但像OrioleDB和Citus Columnar等项目正在积极开发中。更换存储引擎有助于根据不同工作负载（如分析型工作负载、写密集型工作负载或内存存储）选择合适的存储方案，同时保留Postgres的其他基础设施优势。 文章还讨论了表访问方法（table access methods）和外部数据包装器（FDWs）的区别，指出表访问方法提供更紧密的集成和更好的性能。作者尝试编写了一个基本的表访问方法原型，并提供了构建和安装自定义Postgres存储引擎的指南和代码示例，代码可在GitHub上找到。

评论摘要
主要讨论点：OLTP数据库是否可以采用分层存储系统，特别是内存、NVME缓存和对象存储的组合。 不同观点： • [支持采用分层存储的观点] rubenvanwyk 提出，OLTP数据库可以采用分层存储系统，将数据保存到内存，缓存到NVME，并最终永久保存到对象存储，每层提供不同的保障级别。这种方法可以提升数据库性能，并且通过分层管理数据，能够根据数据的重要性或访问频率提供不同的存储策略。 • [对现有实践的质疑] o11c 指出，截至2023年，关于这一主题的公开文档非常稀少，唯一的参考资料是PostgreSQL官方文档中非常简略的说明。这暗示了当前可能并没有广泛应用或成熟的解决方案来实现这种分层存储系统，尤其是在OLTP数据库中。 补充讨论： • [技术实现的挑战] o11c 提供的链接指向PostgreSQL的文档，表明这种分层存储系统的实现可能涉及复杂的底层技术，并且在实际应用中可能缺乏足够的支持和文档。这揭示了在现有数据库系统中实现这种架构可能面临的技术和文档不足的挑战。 • [潜在的性能和可靠性问题] 从不同观点中可以推断出，分层存储系统虽然可能带来性能上的提升，但也可能引入新的复杂性和可靠性问题，尤其是在不同存储介质之间的数据一致性和持久性保障方面。 • [对现有技术的扩展需求] rubenvanwyk 的评论还暗示了对现有OLTP数据库存储技术的一种期望或建议，即通过引入现代存储技术（如NVME和对象存储）来扩展和优化数据库性能和可靠性。 整体来看，讨论的焦点在于OLTP数据库是否以及如何有效采用分层存储系统，涉及到技术实现、现有实践、文档支持和潜在的性能与可靠性问题。

Leonardo Chiariglione – Co-founder of MPEG

作者: eggspurt | 评分: 212 | 评论数: 14 | 发布时间: 2025-08-07 10:09
文章摘要

本文是Leonardo Chiariglione的自述，回顾了他作为视频编码研究者、标准化专家和企业家的职业生涯。他创立了MPEG（运动图像专家组），推动了MPEG-1、MPEG-2、MPEG-4等数字媒体标准的制定，引领了数字媒体时代的发展。2020年因MPEG被利益集团操控而离开后，他创立了MPAI（人工智能音视频数据编码组织），致力于基于人工智能的新标准开发。文章还提及他撰写的两本书籍，分别讲述MPEG的兴衰和MPAI的发展历程。

评论摘要
主要讨论点：MPEG标准的演变、专利问题及其对行业和消费者的影响 不同观点： • ZeroGravitas和wheybags认为，MPEG标准被大公司滥用，专利制度阻碍了技术发展，导致了市场采纳的延迟，伤害了消费者和行业的利益。他们指出，MPEG标准从推动技术发展转变成了阻碍创新的路障。ZeroGravitas特别提到，MPEG在技术和商业上都已“耗尽动力”，并引用了史蒂夫·乔布斯对专利许可问题的批评。 • Merrill则为MPEG辩护，指出MPEG的专利政策实际上是ISO-IEC的政策，且MPEG-LA的设立是为了简化许可流程。Merrill还提到，开发新视频编码算法的经济和技术难度很大，很多时候等待硬件和网络技术的进步比改进编解码器更划算。 • marcodiego批评MPEG的创立者抱怨失去影响力是虚伪的，认为他只是 lamenting 失去权力，并称其为“专利黑手党”的一部分。 • dostick质疑“ obscure forces”是什么，并提出非营利组织的开放标准可能因为商业标准的竞争而受阻。他还建议压缩标准可以像USB联盟那样发展。 • mananaysiempre补充了一个细节，提到MPEG关闭时其所有页面和资料被删除并重定向到AI相关内容。 • karel-3d表示不理解AI与视频编解码器的关联，显示出对这两个领域关系的困惑。 • selvan预测未来可能出现基于深度学习的专利免费视频编解码，并提到DCVC-RT等技术，认为AI在音视频编解码中的应用是一个有潜力的领域。 • _bent对MPAI的标准提出质疑，认为某些标准没有必要，因为不同游戏的服务器之间不需要互操作性。 • kouru225询问对MPEG创立者新组织MPAI的看法，表示对编写编解码器不太了解，希望听取他人意见。 • zazazx简单表示，行业确实利用了MPEG的专利制度。 • scotty79建议对IP权利人强制征税，以改善系统健康，并认为AI行业将摧毁当前的版权制度。 • gcr对MPEG小组的解散表示欢迎，认为开放编解码器正在取代旧的合作模式，且这种变化对编码技术的前沿是有利的。 补充讨论： • 一些评论提到了AI与视频编解码器的潜在关系，如karel-3d和selvan，显示出对新技术趋势的关注。 • 有人质疑MPEG关闭时其资料被删除并重定向到AI内容的行为，如mananaysiempre，这涉及到历史资料的保存和重用问题。 • 对MPAI新组织的看法不一，有人表示好奇并希望了解更多，如kouru225。 • 对专利制度的批评主要集中在它对技术发展和市场采纳的阻碍，如ZeroGravitas和wheybags，但也有人如Merrill试图解释其复杂性和历史背景。 争议焦点： • MPEG的专利制度是否阻碍了技术进步和市场采纳。 • MPEG的关闭及其创立者转向AI领域的行为是否合理。 • 对MPAI新组织的看法及其未来潜力。 总结：讨论围绕MPEG标准的历史、专利问题及其对行业的影响展开，参与者对MPEG的评价褒贬不一，有人认为其阻碍了创新，有人则认为其在特定历史背景下有其合理性，并对未来技术发展如AI在编解码器中的应用充满期待。
