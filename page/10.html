谷歌将于2025年8月25日起停止支持其URL缩短服务“goo.gl”，届时所有生成的短链接将返回404错误。谷歌在2019年关闭了该工具的创建功能，但现有链接继续有效。由于这些短链接的流量大幅下降（超过99%的链接无活动），谷歌决定彻底停用该服务，并从去年开始对点击这些链接的用户显示警告页面。用户需尽快将他们的短链接迁移到其他服务。

评论摘要
主要讨论点：Google 关闭 goo.gl URL 短链接服务引发的争议和讨论 不同观点： • [edent] 认为关闭该服务是文化上的破坏行为，指出约有 60,000 次学术引用将失效，无数书籍的参考文献将永久损坏。他质疑关闭服务的理由，认为仅仅是存储几个 TB 数据和一点 CPU 资源的成本，不足以成为关闭服务的正当理由。 • [mrcslws] 批评谷歌基于使用率做决策，认为不应只看短链接的使用百分比，而应考虑所有链接提供的总价值。他指出，99% 的链接没有活动并不能证明它们没有价值。 • [JimDabell] 提到 Cloudflare 曾提出帮助维持该服务运行但被拒绝，并提醒用户不要依赖谷歌服务，因为谷歌有意停止服务而不是技术上无法维持。 • [jaydenmilne] 提到 ArchiveTeam 正在尝试暴力破解整个 URL 空间以保存数据，并邀请用户参与帮助保存这些链接。 • [cpeterso] 推测谷歌关闭该服务可能是为了防止 goo.gl URL 被用于钓鱼攻击，同时指出谷歌自己的服务仍在生成 goo.gl 短链接，只影响用户生成的链接。 • [jedberg] 提出一个简单解决方案，建议谷歌发布 URL 映射的文本文件或 SQLLite 数据库，以便公众知道这些链接的去向，并认为这不涉及隐私问题。 • [ElijahLynn] 强烈批评谷歌的决定，认为这是对信任的重大打击，谷歌已经因多次关闭服务而受到批评，这次更是雪上加霜。 • [hinkley] 调侃谷歌已经关闭了许多服务，质疑他们的“关闭清单”现在有多长。 • [davidczech] 认为保留这样一个静态地图服务的成本极低，不理解为何要关闭。 • [krunck] 反对使用 URL 短链接，建议不要中间人（MITM）内容，并提倡使用合理的 URL 模式。 • [musicale] 对谷歌关闭服务的行为表示不惊讶，引用了 "killedbygoogle.com" 网站。 • [cyp0633] 提到 Compiler Explorer 的运营者试图收集公共短链接并自行进行重定向，以保存这些链接。 • [pentestercrab] 指出最近利用 goo.gl URL 进行钓鱼攻击的案例增多，认为这是关闭服务的原因之一。 • [david422] 提到自己正在开发一个项目，考虑过使用短链接但最终决定自己创建，以避免依赖第三方服务。 • [xutopia] 认为谷歌越来越难以依赖，关闭服务的决定让用户更加难以信任他们的软件。 补充讨论： • 争议焦点在于谷歌关闭 goo.gl 服务的正当性及其对用户和文化的影响。 • 不同用户提出了技术解决方案、批评、调侃以及替代方案。 • 钓鱼攻击和安全问题也被提及，作为可能的关闭理由。
