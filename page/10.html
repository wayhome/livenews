Stealing Is a Skill

作者: bewal416 | 评分: 244 | 评论数: 63 | 发布时间: 2026-06-24 13:08
文章摘要

这篇文章阐述了"偷窃是一种技能"的观点。作者受到已故创意人 Virgil Abloh 提出的"3% 方法"启发——通过复刻他人作品来学习其精髓，然后只修改 3% 使其成为自己的创作。作者和同事在重建营销网站时，逐像素复刻了 Mintlify 的网站设计，在这个过程中深入理解了每个设计决策背后的逻辑。通过"偷窃"学习，他们最终找到了属于自己品牌的那 3% 差异化元素。作者认为，职业成功不在于创意的原创性，而在于高效识别和解决问题——而聪明人往往已经做过类似的事。因此，应该将"偷窃"变成一种技能：识别该偷什么、为何偷、偷多少。

评论摘要
主要讨论点：在设计和创作中"借鉴/抄袭"的边界问题 不同观点： • **反对直接抄袭派**：认为像素级复制他人商业网站是剽窃和盗窃行为，与真正的"伟大艺术家偷窃"概念不同。真正的"偷窃"应该是提取不可见的核心理念，而非表面复制（rglover, sandcat_, agilek, emaro） • **支持临摹学习派**：将这种做法类比为写作中的copywork练习、音乐家抄写爵士乐独奏、儿童学习语言的模仿过程。认为逐字复制是理解大师作品的有效方法，能提升自身技能（dghlsakjg, pseudosavant, darepublic, bingoMen） • **条件支持派**：认可临摹作为练习手段的价值，但强调应从多个来源综合借鉴、加入自己的创新，而非单纯复制一个作品。区分练习性质和商业用途（dinkleberg, meander_water） • **情境区分派**：指出在市场环境中这是盗窃，在社区传统中则是学习。艺术和传统在被拖入市场竞争前不是竞争关系（erikschoster） 补充讨论：多位评论者引用"好的艺术家复制，伟大的艺术家偷窃"这句话，但对其解读截然不同。争议焦点在于：商业环境下的像素级复制是否能被视为正当的学习手段。

MarkdyScript 是一个零依赖的纯 TypeScript 动画系统，专为 AI 生成设计。核心特性包括：使用结构化 DSL 语言编写动画脚本，采用 Web Animations API 和 CSS 实现渲染（无 Canvas/GSAP），框架无关可在任何环境使用。提供三个轻量包：核心解析器(~12KB)、DOM 渲染器(~22KB)、Astro 组件(~2KB)。支持场景设置、角色定位、动作序列、时间轴编排等功能，通过简洁的语法创建复杂动画效果，特别适合 LLM 生成和验证动画代码。

文章摘要

这篇文章介绍了Macbook Neo上光标延迟问题的临时解决方案"Unlag Neo"。 **问题**:Macbook Neo在光标接近屏幕边缘或进入终端窗口时会出现延迟,原因可能是系统从硬件光标切换到软件光标时出现卡顿。 **解决方案**:通过屏幕录制功能强制系统使用软件光标来消除延迟。作者提供了一个脚本(`create_unlag_neo_app.sh`)自动创建应用程序,该应用以极低资源消耗(每10秒录制1像素到/dev/null)进行屏幕录制,只会在屏幕右上角显示录制指示器(⏺)。应用还支持全屏时自动暂停功能以隐藏指示器。 这是一个权宜之计,等待Apple正式修复该问题。

评论摘要
主要讨论点：MacBook Neo 鼠标光标延迟问题及其修复方案 不同观点： • **技术解释派**：userbinator 从 GPU 架构角度分析，认为延迟源于硬件光标切换到软件光标时需要等待 GPU 命令队列刷新。这是底层渲染机制导致的。 • **修复方案质疑派**：TheTon 强烈反对此修复方法，认为强制 WindowServer 合成光标而非使用硬件叠加层是"糟糕的修复"，虽然能解决问题但代价太大。 • **实用主义派**：exogen 分享类似经验，通过调整光标大小解决了 TV.app 的颜色处理问题，认为这个副作用可以接受甚至更好。 • **长期维护担忧派**：anotherpaul 指出 hacky fix 的隐患——bug 修复后仍在运行无用脚本，不知何时该移除这些临时方案。 • **性能退化批评派**：PaulHoule 和 whywhywhywhy 批评现代软件架构，对比老设备（1984 Mac、800MHz G4）反而没有光标延迟，质疑当前系统的倒退。 补充讨论：elicash 认为这个有趣修复能引起 Apple 注意促成真正修复；gcr 称赞代码示例展示了 Swift 最小化 App Bundle 的方法；m132 简短表达对乔布斯时代品质的怀念；amelius 和 xnx 以幽默方式评论修复方案的得失。
