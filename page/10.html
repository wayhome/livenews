TwoFold (2✂︎f) 是一个命令行工具，使纯文本文件具有动态文件的功能，介于文本扩展器和模板引擎之间。它受 Emacs Org-mode、Python Jupyter Notebooks 和 React JS 启发，通过处理文本文件中的 LISP/XML 样式的标签，生成动态内容。它支持 XML、HTML 文档，并可自定义标签样式如 lisp、jinja2 等。TwoFold 可实时监控文件变化，支持实时协作，适用于验证信息、计算统计、检查拼写错误等。它兼容多种文本文件格式，但不适配二进制文件。标签分为单次使用和可刷新两类，用户可自定义标签并通过命令行加载。首次运行需使用 Bun 下载和启动，提供预构建的可执行文件。使用时通过 XML 样式的标签调用 JavaScript 函数，可以扫描文件查看可用标签并进行渲染。

Binary Formats Are Better Than JSON in Browsers

作者: adamkf | 评分: 61 | 评论数: 9 | 发布时间: 2025-05-13 22:30
文章摘要

文章主要讨论了在浏览器中使用二进制格式替代JSON的性能优势。过去JSON在浏览器中的表现优于其他二进制格式，但随着互联网速度的提升和网页应用复杂性的增加，这种情况发生了变化。作者指出，对于性能要求较高的网页应用，使用Avro、Protobuf或Bebop等二进制格式可能更为合适。 作者在2023年为解决服务器到Web应用的大响应问题，选择了MessagePack，但发现所有测试的二进制编码都比JSON慢。然而，最近几个月的实验显示，一些JavaScript二进制编码库在性能上已经超越了JSON。 文章还提到在浏览器中进行基准测试的挑战，包括使用Node.js而非浏览器进行测试的常见错误，选择具有代表性的数据集的重要性，以及不同输入数据类型和大小对结果的影响。最终，作者通过实验表明，二进制格式在浏览器中的表现已经优于JSON，特别是在处理大型数据集时。

评论摘要
主要讨论点：不同序列化格式（如JSON、二进制格式）在性能、工具支持和使用场景上的优劣比较 不同观点： • **[pjmlp]**：认为不需要重复CORBA和DCOM的老路，解析文本效率不高。虽然JSON-RPC比SOAP稍好，但整体上工具支持和可读性是关键。 • **[codelikeawolf]**：在VS Code代码库中发现使用自定义二进制缓冲区来编码/解码IPC消息，质疑小消息是否也有必要使用二进制编码。提出何时使用二进制编码更高效的问题。 • **[avmich]**：建议将编码问题交给压缩层处理，暗示可能通过压缩来解决性能问题而不是直接采用复杂的二进制格式。 • **[victorNicollet]**：分享了生产环境中使用自定义二进制格式的经验，指出二进制格式在数据可视化和分析中的优势，特别是在处理大型数组时能显著减少解析时间。但也提到调试二进制格式较为困难。 • **[jiehong]**：提出Apache Parquet格式是否适合比较的疑问，尤其是浏览器中的实现质量。 • **[zigzag312]**：讨论MessagePack的性能，猜测如果使用整数字段键是否能提升性能。 • **[broken_broken_]**：虽然起初不理解为何要向浏览器发送大量数据，但认可数据可视化和一些特定场景（如视频游戏和 observability 平台）的需求。 • **[naikrovek]**：强烈支持二进制格式，认为二进制格式在提取信息速度和大小上都优于JSON。认为开发者对二进制格式的恐惧是不必要的，二进制格式更高效且灵活。 • **[mannyv]**：质疑比较的完整性，指出可能缺少反序列化和验证延迟的比较。 补充讨论： • 争议焦点之一是二进制格式和JSON在性能上的实际差异，尤其是**[naikrovek]**和**[codelikeawolf]**之间的对立观点。 • 另一个值得注意的讨论点是调试二进制格式的困难，**[victorNicollet]**提到浏览器开发工具对非JSON格式的支持不足，增加了调试的复杂性。 • **[jiehong]**提出的Apache Parquet实现质量问题也是一个重要的考虑因素，特别是在浏览器环境中的适用性。 总结：讨论主要围绕不同序列化格式在性能、工具支持和特定使用场景下的优劣展开，参与者提供了各自的经验和见解。

文章摘要
