Claude Code IDE for Emacs 通过 Model Context Protocol (MCP) 实现与 Claude Code CLI 的原生集成，打造双向通信桥，使 Claude 能利用 Emacs 的强大功能，如 LSP、项目管理、自定义 Elisp 函数等。其主要功能包括自动项目检测、终端集成、MCP 协议支持、工具集成（如文件操作、编辑状态等）、诊断集成（如 Flycheck、Flymake）、高级差异查看（通过 ediff）、标签栏支持和选择缓冲区跟踪等。Claude 能执行项目范围的搜索、重构，访问特定模式及其功能，并执行自定义 Elisp 函数，从而提供更智能的上下文感知协助。安装需 Emacs 28.1 及以上版本、Claude Code CLI、vterm 或 eat 包，并通过 use-package 配置。

评论摘要
主要讨论点：Emacs和Vim等文本编辑器如何整合AI编程工具（如Claude Code和Aider）以提升竞争力，以及在实际应用中遇到的挑战和解决方案。 不同观点： • blahgeek认为，AI编码工具的出现对Emacs和Vim等小众编辑器是利好消息。这些编辑器不需要费力实现复杂的IDE功能，而是可以通过整合AI工具，专注于其独特的编辑功能，从而更具竞争力。 • yoyohello13进一步指出，Emacs因其高度可定制性（如通过elisp改变编辑器行为）对AI代理非常友好，具有巨大潜力。 • vemv分享了自己使用Claude Code的实际体验，认为在Emacs中运行这些工具能提高效率，但对新工具的采用仍需谨慎。 • Karrot_Kream则表达了对Emacs配置复杂性的担忧，特别是与新工具集成的困难，同时也考虑是否Neovim会是更好的选择。 补充讨论： • pjm331提到自己开始编写自己的elisp工具，并认为Claude在编写elisp方面表现不错，尽管有时会丢失括号。 • wyuenho指出目前有多个Emacs/Claude Code集成包，但其中一些未被广泛讨论的包可能功能更全面。 • cml123反对一些Emacs社区对AI工具集成的排斥，认为Emacs与AI的结合是有历史渊源的，排斥这种结合是有害的。 • ericdallo推广自己的项目ECA，旨在为Emacs提供最好的AI编程配对工具。 • wwarner更关注与Org模式（或笔记功能）的集成，以解决AI助手对话保存问题。 • efitz质疑在使用Emacs作为IDE的开发者与采用AI编码工具的开发者之间是否有很大重叠。 • megaloblasto希望能够在本地运行AI工具，并询问使用本地模型进行编码的可行性。 • eulers_secret询问Claude Code是否可以与OpenCode（允许其他模型提供者的Claude Code分支）一起使用，以避免被特定提供者或模型绑定。 • qalmakka担心在Emacs和Neovim中处理敏感数据时会不小心上传到LLM，并分享了一种使用bubblewrap的解决方案。 • cristea对老牌编辑器能够跟上新技术的发展表示赞赏，并希望Vim也能实现类似的功能。 • brotherjerky询问是否有类似的Neovim解决方案。 争议焦点： • Emacs的配置复杂性和新工具集成的困难。 • 对AI工具与Emacs等编辑器整合的接受度和潜力存在不同看法。 • 使用AI工具处理敏感数据时的安全性问题。
