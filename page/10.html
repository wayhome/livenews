Chimpanzees act as 'engineers', choosing materials to make tools

作者: docmechanic | 评分: 85 | 评论数: 21 | 发布时间: 2025-03-25 14:39
文章摘要

研究发现，坦桑尼亚贡贝溪国家公园的黑猩猩在制作工具时展现出一定的工程学能力，它们故意选择具有特定机械和结构特性的植物来制作更具弹性的工具，用于钓取白蚁。研究团队使用便携式机械测试器比较了黑猩猩使用的植物材料和未使用的材料，发现未使用的植物材料要坚硬得多。黑猩猩选择的植物种类，如*Grewia spp.*，在远至5000公里外的黑猩猩群体中也用于制作工具，显示出这种基础的工程选择可能在黑猩猩的工具文化中根深蒂固。该研究揭示了黑猩猩对材料特性的直觉理解，并为研究人类工具使用能力的演化提供了重要启示。

文章摘要

文章指出，随着无现金社会的兴起，英国儿童因吞咽异物而需要接受手术的病例显著减少。根据英格兰皇家外科医学院的数据，2012年至2022年间，此类手术数量下降了29%。历史上，硬币占六岁以下儿童吞咽异物的75%以上，而无现金支付的普及减少了家中的硬币数量，从而降低了相关手术的需求。尽管病例减少，医生仍提醒家长警惕纽扣电池和磁铁等危险物品。NHS数据显示，这种趋势不仅有益于儿童安全，也缓解了医疗系统的压力。

Plain – a web framework for building products with Python

作者: brylie | 评分: 286 | 评论数: 48 | 发布时间: 2025-03-29 03:55
文章摘要

Plain 是一个基于 Python 的 web 框架，是 Django 的分支，旨在引入新想法并保持 Python 生态系统的成熟模式。它支持通过单条命令进行本地开发并快速上线，包含多个独立可选的包，如处理 URL、视图、模板、表单、缓存、电子邮件、会话、后台任务和 JSON API 等功能。Plain 还提供认证包，支持传统和现代登录方式，如密码和 OAuth。其管理包允许自定义管理后台和功能标志控制，开发包优化本地开发体验，前端包则集成现代工具如 Tailwind 和 HTMX。Plain 被设计用于构建新业务、内部工具或个人项目。

主要讨论点：Django框架及其分支Plain框架的优缺点与未来发展方向 不同观点： • **支持Plain框架的观点**： - [miiiiiike] 认为Django需要像Angular一样复兴，当前社区太小且封闭，需要更多贡献者。对Django现有问题感到担忧，认为需要采取行动，哪怕是通过分叉。 - [petr25102018] 理解Plain作为分叉的存在，认为Django领导层未能突破旧范式，Plain或其他第三方应用的尝试是有价值的。 • **反对Plain框架的观点**： - [theptip] 不理解为什么要分叉Django，认为Django的ORM和生态系统是其强项，分叉会破坏兼容性，建议通过Django项目模板实现改进。 - [sroerick] 对Plain的“为什么”感到困惑，认为Django的不足可以通过现有生态系统（如Celery和Django REST）解决，分叉可能增加复杂性。 - [999900000999] 对Plain持混合态度，认为Django的插件生态和文档支持无可替代，不希望看到一个由单人维护的分叉。 - [spapas82] 认为Plain的所谓创新已经在Django核心或可靠的第三方包中实现，分叉可能分裂社区，不如将努力用于改进Django。 - [mcdirty] 认为Plain的文档和维护者较少，投资风险大。 - [jgb1984] 表示会继续使用Django，对Plain不感兴趣。 • **对Django的批评与改进建议**： - [mariocesar] 对Plain分叉感到不安，认为这是在绕过Django的集体努力，担心Plain可能走向商业化或狭隘的方向，但同时也感到被推动更积极参与Django贡献。 - [nop_slide] 认为Django在DX和功能上落后于Laravel和Rails，生态系统碎片化，配置复杂，文档不够完善，希望Django能更完整。 - [askonomm] 对Django设置中使用字符串引用类的方式不满，认为这导致无法轻松导航和使用自动完成功能。 • **技术细节与安装问题**： - [JodieBenitez] 在尝试运行Plain的入门套件时遇到SSL证书下载失败和需要输入密码的问题，建议将SSL设为可选。 补充讨论： • **关于Django社区和贡献**： - [miiiiiike] 提到Django社区小且紧密，外人很难参与，感觉需要等待而不是主动贡献。 - [mariocesar] 表示对Django的热爱，希望社区能更开放和尊重贡献。 • **关于分叉与创新的讨论**： - [scottpersinger] 建议从FastAPI等现代框架开始，而不是分叉Django。 - [mychael] 认为Plain的独特价值不明显，只是对Django的简单替换。 争议焦点： • Plain框架是否有必要分叉Django，以及分叉是否会导致Django社区的分裂和生态系统的破坏。 • Django当前的不足是否可以通过现有生态系统和第三方包解决，还是需要通过分叉或重大改进来实现。 总结： 评论中对于Plain框架的分叉存在明显分歧，一方认为Django需要重大改进甚至分叉，另一方则认为Django的强项在于其生态系统和兼容性，分叉可能弊大于利。同时，对Django社区的封闭性和贡献难度也有所批评。
