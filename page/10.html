文章摘要

NNCP（Node to Node Copy）是一组简化安全存储转发文件、邮件和命令交换的工具，旨在帮助构建小型（几十个节点）的朋友对朋友（F2F）、静态路由、延迟容忍的暗网网络。它支持完整性检查、端到端加密、公钥认证和洋葱加密，每个节点同时作为客户端和服务器运行，支持推送和轮询模式，并支持多播区域。NNCP还支持离线传输、不同存储介质及空气隔离计算机，但也提供在线TCP守护进程。其优势在于简化、加密安全、兼容Sneakernet并易于与现有SMTP服务器集成，是基于GNU GPLv3的自由软件，适用于所有POSIX系统。

文章摘要

GizmoSQL 是由 GizmoData™ 开发的 Apache Arrow Flight SQL 服务器实现，支持 DuckDB 或 SQLite 作为后端数据库。它支持通过中间件进行身份验证，并允许通过 TLS 进行加密连接。该项目最初是从 Voltron Data 的开源项目 sqlflite 分支而来，并在 Apache 2.0 许可证下独立扩展为 GizmoSQL。 用户可以通过发布的 Docker 镜像运行 GizmoSQL，并可选择启用或禁用 TLS。运行时可以挂载自定义的 DuckDB 数据库文件，该文件需使用 DuckDB 1.3.0 版本创建。此外，用户可在容器启动时执行初始化 SQL 命令，但选择查询结果不会显示，且失败的命令将导致服务器退出。最后，GizmoSQL 支持通过 JDBC 连接到服务器。

Fun with Futex

作者: ingve | 评分: 89 | 评论数: 5 | 发布时间: 2025-06-03 06:37
文章摘要

本文介绍了在Linux中使用Futex系统调用实现优化锁的过程。首先，文章展示了一个简单的自旋锁实现，该实现通过持续检查锁的状态来实现互斥。然而，自旋锁会导致高CPU消耗，特别是在锁竞争激烈的情况下。为了解决这一问题，文章引入了Futex系统调用，它能够在锁不可用时让线程休眠，并在锁释放时唤醒线程。Futex提供了两种主要操作：`FUTEX_WAIT`用于让线程休眠，`FUTEX_WAKE`用于唤醒线程。文章通过几个案例详细说明了Futex的行为和使用方法，强调了其在处理锁等待时的优势和注意事项。最终，通过Futex可以有效减少不必要的CPU消耗，提高多线程程序的效率。

评论摘要
主要讨论点：关于使用futex及替代方案（如parking_lot）实现锁机制的讨论，包括不同平台上的实现差异和优化方案。 不同观点： • **parking_lot方案的优势**：[skitter] 提出使用parking_lot（如Rust的parking_lot crate）来管理线程队列，而不是依赖内核空间的futex。这种方法通过一个字节的状态信息和基于地址的哈希表来管理线程队列，具有跨平台一致性（1字节大小），并允许更灵活的公平性控制和回调机制。缺点是该方案仅适用于单进程内使用，而futex可在Linux上跨进程使用。 • **futex的正确理解**：[gpderetta] 纠正了对futex的误解，指出FUTEX_WAIT的正确行为应该是“除非值不是X，否则让线程休眠”，而不是“当值是X时休眠”。他还强调futex是无状态的、基于边沿触发的原语，其值本身不重要，主要是用来避免错过唤醒。 • **Darwin平台的特殊性**：[lilyball] 提到Darwin有自己最近公开的futex原语，但由于其QoS（服务质量）线程优先级实现的不同，容易出现优先级反转问题。因此，在Darwin上实现文中所述的锁时，通常应使用`os_unfair_lock`来避免优先级反转问题。 • **rseq在自适应用户空间锁中的应用**：[scottlamb] 提到了rseq (`RSEQ_SCHED_STATE_FLAG_ON_CPU`) 作为一种决定何时从自旋切换到阻塞的潜在方案，并指出像`absl::Mutex`和`parking_lot::Mutex`这样的实现可能受益于这种机制。 • **无系统调用唤醒操作的需求**：[geertj] 提到当前锁机制的问题不仅在于等待时需要进入内核，还在于当前持有锁的线程也需要进入内核进行唤醒操作。他探讨了通过Intel的调试寄存器实现一种无需系统调用的唤醒操作，但承认这需要内核任务的参与，并非完美方案。 补充讨论： • **跨平台兼容性**：parking_lot方案的一个明显优势是跨平台一致性，而futex在不同操作系统（如Linux和Darwin）上的实现和API存在差异，给跨平台开发带来挑战。 • **优先级反转问题**：Darwin的QoS实现导致在使用自旋锁或类似原语时更容易出现优先级反转问题，因此需要特别注意锁的选择和实现。 • **自适应锁的未来发展**：rseq作为一种可能的未来优化方案，提供了一种自适应用户空间锁的新思路，但目前仍处于探索阶段。

The wake effect: As wind farms expand, some can ‘steal’ each others’ wind

作者: JumpCrisscross | 评分: 49 | 评论数: 20 | 发布时间: 2025-05-31 12:21
文章摘要

文章主要讨论了风电场之间存在的“风能盗窃”现象，即当一个风电场在另一个风电场的上风处时，会减慢风速，影响下风处风电场的能量输出。这种现象被称为尾流效应，可导致下风向风电场能量输出减少10%或更多。随着全球海上风电场的快速扩展，特别是规模和密度的增加，尾流效应愈发显著，可能延伸超过100公里。这种效应引发了风电场开发商之间的纠纷，尤其是在风电场密集的北海地区。为了解决这一问题，英国已启动新研究项目，旨在通过建模分析2030年风电场的尾流效应，帮助政府和开发商优化规划，避免纠纷。

评论摘要
主要讨论点：风力发电场的“尾流效应”及其潜在影响 不同观点： • **风权与资源争夺**：glkindlmann和JohnKemeny指出，风力发电涉及风权的概念，类似于水权，存在资源争夺问题。JohnKemeny还提到，当一个风电场上风处的风力被前一个风电场削弱时，可能引发冲突，类似于共享资源的争夺。 • **尾流效应的影响程度**：glumreaper引用研究数据表明，尾流损失对风电场的影响较小（约3.28%），并将其比作新风电场在两年后的自然损耗，认为其影响微不足道。morkalork则指出尾流效应可延伸100公里，影响另一风电场10%的输出，认为需从国家规模优化风电场布局。 • **环境影响与效益权衡**：g42gregory关注风电场对环境（如鸟类、气候、昆虫种群）的潜在负面影响，并质疑其正负效果的权衡。collinmcnulty则建议将风电场的影响与其他障碍物（如建筑物）比较，以更好地理解其环境影响。 • **气候变化对风力发电的影响**：acyou提出全球变暖可能影响风力发电输出，因为气温升高会降低空气密度，尽管整体系统中可能有更多能量。 补充讨论： • **技术与科幻设想**：roxolotl提到一个十年前的研究模型，探讨风力涡轮机对飓风的影响，指出其在理论上可减弱风暴强度。polishdude20则提出一个科幻设想，关于利用风力阵列从风暴中获取能量以保护居住区。 • **教育与认知**：p0w3n3d认为风力发电的基本原理（能量守恒）是显而易见的，不需要复杂解释。 • **社会态度与发展需求**：bamboozled强调了对风电场的批评，并指出需要持续实验和发展更好的解决方案，以避免风力发电成为像核能那样的“禁忌”话题。 • **幽默与类比**：Kon-Peki用帆船比赛中的战术比喻风电场“偷风”行为。hulitu则以幽默方式提到未来可能出现太阳能农场“偷光”的问题。
