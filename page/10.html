RFC 10008: The new HTTP Query Method

作者: schappim | 评分: 396 | 评论数: 37 | 发布时间: 2026-06-17 10:51
文章摘要

这是RFC 10008规范，定义了HTTP的QUERY方法。QUERY方法用于发送安全且幂等的查询请求，允许在请求体中传递查询参数，而非URI中。它填补了GET（参数在URI中，有长度限制）和POST（不明确表示安全性和幂等性）之间的空白。QUERY请求可以安全地被缓存和自动重试，适用于需要传递大量查询数据的场景，同时保持请求的安全性和幂等性特征。规范还定义了Accept-Query头字段，用于发现服务器支持的查询格式。

评论摘要
主要讨论点：关于新HTTP方法QUERY（RFC 10008）的利弊和实现方式 不同观点： • **支持QUERY方法**：认为这解决了长期痛点，避免了为查询创建POST端点的尴尬，也不需要为每个查询定义无限的资源。规范写得清晰易懂，实现合理简洁 • **质疑缓存语义**：认为将请求体作为缓存键非常奇怪，用户可控的无界缓存键易被恶意破坏。对于复杂过滤或图像输入等场景，缓存应在HTTP层之外处理。建议用POST加新header（如"Vary: request-body"）更向后兼容 • **倾向GET with body**：有人多年来一直在GET中发送请求体，质疑为何不直接扩展GET而要创建新方法。但规范指出GET body被完全忽略且存在缓存问题 • **安全担忧**：指出应从方法层面内置跨域保护，服务器默认不响应跨域QUERY，浏览器不自动发送cookies，避免重复GET/POST的跨域安全错误 补充讨论： 有人期待HTML表单支持method="query"避免POST刷新重复提交警告；希望浏览器书签能保存请求参数；建议标准化分页的items range header；可扩展到AI流式查询场景替代不合适的POST+EventSource；也有人觉得"query"命名与现有"查询"术语冲突易混淆

主要讨论点：围绕“已消失/衰败的小型机场与飞行场”网站，大家在分享个人记忆、场地变迁价值，以及对网站范围和标题表述的讨论。 不同观点： • 怀旧与社区记忆：多人把这些机场视为地方历史与人情网络的载体，如有人讲祖父经营偏远机场，曾驱赶夜间毒贩、维系飞友社区，去世后机场因维护成本高被卖掉，现成太阳能农场；也有人回忆在废弃二战机场学开车。 • 认可网站的史料与兴趣价值：不少人称赞网站长期保存这些资料，帮助他们研究旧机场、结合 Google Earth 做航空摄影考证，或为个人飞行模拟补充更多真实小机场，提升体验。 • 关注机场消失的制度与社会原因：有人感叹旧机场大量消失，一方面居民投诉噪音要求关闭老机场，另一方面新机场又受繁琐审批限制；并举例称“98%噪音投诉往往来自1-2人”。争议焦点在于机场关闭究竟主要是公共利益还是少数人推动。 • 认为讨论范围过于美国中心：多位评论者希望标题或标签明确注明“美国”，避免误导其他地区读者；也有人补充英国相关的废弃机场维基页面，回应“美国之外是否也有类似资料”。 补充讨论： • 有人询问网站收录标准，并举出仍活跃或疑似未关闭的草地跑道，说明网站“失落机场”与“仍在使用机场”边界可能不清。 • 还有人分享具体趣闻，如罗斯威尔飞机坟场、机场曾作《虎胆龙威2》取景地、旧广告提供买车送飞行体验等。

Clojure Hosted on Go

作者: dnlo | 评分: 193 | 评论数: 13 | 发布时间: 2026-06-17 23:14
文章摘要

Glojure 是一个运行在 Go 上的 Clojure 解释器，让开发者能够像 Clojure 访问 Java 框架一样轻松使用 Go 库。它是一种"宿主语言"，Go 值和 Glojure 值可以互相转换使用。 主要特性包括： - 通过 `glj` 命令行工具提供 REPL 交互环境和脚本执行 - 支持将 Glojure 嵌入到 Go 应用中作为脚本语言 - Go 和 Clojure 代码可以相互调用 - REPL 具备多行编辑、自动补全、历史记录等功能 目前处于早期开发阶段，需要 Go 1.19+ 版本，可运行大部分 Clojure 核心库功能，适合业余项目使用。

评论摘要
主要讨论点：Glojure（Go语言实现的Clojure方言）及相关技术选型 不同观点： • **看好Glojure前景**：认为这是最有前景的Go上Clojure实现，因为它提供了完整的互操作能力；Clojure方言整体发展迅速，正在快速达到功能对等 • **性能担忧**：质疑tree-walking解释器的性能表现，认为可能会很慢；指出大多数Go REPL因为需要编译/执行而很慢，缺少真正的"evaluation"环节 • **替代方案倡导者**：有人推荐其他方案如Tengo（因为觉得Clojure困难）、Carp Lisp、Wile Scheme（带安全特性）、typed FP语言Lisette、joker的改进版本 • **安全性关切**：询问Glojure是否缺少安全性和沙箱特性，这对嵌入式语言使用很重要 补充讨论： 项目维护权已转移到gloathub组织但保持同步更新；社区分享了多个相关项目链接和2024年的历史讨论；REPL实现机制（编译vs虚拟机）成为技术细节争论点；Go的运行时、工具链和生态系统获得普遍认可。
