Visual Studio Code: Text Buffer Reimplementation (2018)

作者: stefankuehnel | 评分: 52 | 评论数: 4 | 发布时间: 2025-05-20 09:34
文章摘要

Visual Studio Code 1.21引入了新的文本缓冲区实现，显著提升了性能，包括速度和内存使用。最初考虑用C++实现以节省内存，但因在原生表示和V8字符串间转换的成本高昂，性能未达预期。最终，团队通过优化JavaScript/TypeScript代码提升了性能。 旧的文本缓冲区使用线性数组，对小文件表现良好，但处理大文件时内存消耗过大，例如35MB文件会导致内存溢出。新方案采用"piece table"数据结构，初始内存占用接近文件大小，修改所需内存与编辑次数成正比。为加快行查找速度，采用了缓存机制。 新实现通过减少元数据和优化数据结构，实现了性能提升。

评论摘要
主要讨论点：不同文本编辑器使用的数据结构及其优缺点 不同观点： • [smartmic] 提问是否有关于不同文本编辑器（尤其是GNU Emacs、vi(m)、Sublime等黑客常用编辑器）使用的数据结构的概述。 • [lenkite] 认为"piece table"是一种出色的编辑器数据结构，具有概念简单、对大文件内存效率高、缓存局部性好、易于实现撤销/重做操作、原文件可以只读等优点。同时指出，新一代编辑器似乎更倾向于使用Rope数据结构。 • [joeblubaugh] 对"ordered Array"作为数据结构表示质疑，认为其性能几乎显而易见地较差。 • [timewizard] 对Rope数据结构表示兴趣，并提供了一个维基百科链接以供参考。 补充讨论： • lenkite详细列举了piece table的优点，特别是在处理大文件和实现某些编辑功能方面的效率。 • joeblubaugh对ordered Array的性能提出批评，暗示其在大规模或高性能应用中的不足。 • timewizard通过提供Rope数据结构的维基百科链接，引导进一步了解Rope的特性及其在编辑器中的应用。 争议焦点： • 对ordered Array作为文本编辑器数据结构的性能存在争议，joeblubaugh认为其性能较差，而lenkite则未直接回应这一观点，但指出了Rope作为新一代数据结构的流行趋势。 总结：讨论主要围绕文本编辑器使用的不同数据结构展开，包括piece table和Rope的优缺点，以及对ordered Array性能的争议。

When good pseudorandom numbers go bad

作者: chewxy | 评分: 70 | 评论数: 5 | 发布时间: 2025-05-19 07:17
文章摘要

本文讨论了在实际计算机中进行矩阵特征值分解时可能出现的误差问题，引用了Wilkinson（1965）的研究。即使对于具有重复实特征值的实不对称矩阵，计算结果也可能出现复共轭特征值对。文章还描述了作者同事在使用R语言进行多变量正态分布模拟时遇到的不可重现性问题，尽管使用了`set.seed()`来控制随机数生成器状态，但在不同机器上仍得到不同的随机数结果。作者最终发现问题根源在于浮点运算的特性，这导致计算机行为与预期不符。这一问题并非来自`set.seed()`或`MASS::mvrnorm()`函数本身，而是浮点运算的固有缺陷。

评论摘要
主要讨论点：在计算机科学中，关于随机函数和哈希函数的使用及其可再现性的问题 不同观点： • somat认为，人们常常误将随机函数当作哈希函数使用，导致出现问题。他指出，随机函数在不同版本和系统之间没有硬性规范，结果不可预测，而哈希函数则是确定性的。随机函数本质上是非确定性的，不应该期待其具有可再现性。 • AlotOfReading持不同观点，认为大多数人实际上关心的是可再现性，而不是数值稳定性和正确性。他指出，在现代硬件上，通过遵循一些基本原则（如同样的输入、同样的操作顺序、避免特殊函数等），可以实现实际的可再现性，且性能成本很低。然而，由于工具链和用户知识的问题，这种可再现性并未得到优先考虑。 补充讨论： • mjcohen提到自己过去的经验，表明在不同硬件和设置下，算法的性能可能会有显著差异（如VAX Fortran中下标检查增加30%的运行时间），但未直接涉及主要讨论点。 • coolcase对讨论内容不太理解，询问是否涉及 race condition、硬件差异或浮点运算的随机性，这反映了部分读者对讨论技术细节的困惑。 • jam0wal以简明的语言指出，如果需要恒定输出，直接使用常量数组即可，而不应将偏见强加于随机函数的解释上。 争议焦点： 主要争议在于随机函数和哈希函数的使用及其可再现性。somat强调随机函数的不可预测性，而AlotOfReading则认为在一定条件下，现代硬件可以实现可再现性。

Attention Wasn't All We Needed

作者: mooreds | 评分: 94 | 评论数: 7 | 发布时间: 2025-05-23 18:14
文章摘要

文章主要介绍了一种名为Group Query Attention（GQA）的技术，该技术通过共享键和值的投影来减少多头注意力机制中的内存使用。与传统的Multi-Head Attention（MHA）不同，GQA使用较少的键和值头（$N_{kv}$），并将它们共享给多个查询头（$N_h$），从而降低计算成本和内存占用。具体实现中，先将输入序列通过线性变换得到查询、键和值，然后对键和值进行分组共享，以减少缓存大小。GQA在保持模型性能的同时，显著提高了推理速度并降低了内存需求，特别适用于大型模型的部署。Multi-Query Attention（MQA）是GQA的一种极端形式，其中$N_{kv}$为1。
