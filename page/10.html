Understanding Tool Calling in LLMs – Step-by-Step with REST and Spring AI

作者: muthuishere | 评分: 97 | 评论数: 4 | 发布时间: 2025-07-13 09:44
文章摘要

本文介绍了如何在LLM（大型语言模型）中实现工具调用功能，从原始的REST API到使用Spring AI简化开发流程。工具调用允许LLM在无法直接回答问题时调用外部函数或API来获取数据。文章通过一个具体示例，展示了从发送用户请求、模型返回工具调用、执行函数、返回结果到最终生成回答的完整流程。 具体步骤包括： 1. 发送用户请求和工具定义到LLM。 2. 模型返回需要调用的工具和参数。 3. 执行指定函数并获取结果。 4. 将函数结果返回给模型。 5. 模型根据结果生成最终回答。 文章还介绍了如何利用Spring AI简化这一过程，开发者只需使用注解定义工具函数，Spring AI会自动处理参数绑定、消息状态管理、并行工具调用等复杂操作，大大减少手动编写REST代码的工作量。 Spring AI还支持通过MCP服务器轻松扩展工具调用功能，使其不仅限于聊天应用。

评论摘要
主要讨论点：大型语言模型（LLM）和相关工具在构建聊天栈中的标准化问题，以及不同工具和方法的比较 不同观点： • **_moog 的观点**：_moog 认为目前在构建聊天栈时，缺乏标准化，尤其是不同工具和层级之间存在不同的模式和模板，导致初学者在理解流程时感到困惑。为了解决这个问题，_moog 绘制了一个流程图，展示了从初始请求到 Ollama 和 MCP 服务器的各个步骤中使用的（大致）模式，并分享了该图以帮助其他人。 • **upghost 的观点**：upghost 对工具调用采用 JSON blob 的形式感到奇怪，更倾向于 NexusRaven 风格，即提供带有文档字符串的 Python 函数存根，并返回带有填充参数的 Python 函数调用。upghost 还对 MCP 比 REST 或 CLI 更受欢迎表示不解。 • **rapidaneurism 的观点**：rapidaneurism 提出了一个具体的技术问题，询问如何将用户令牌传递给 MCP 调用，是否需要将令牌交给 LLM 并期望其填充参数。 • **nullorempty 的观点**：nullorempty 简短地提到 Spring 在 Hacker News 上并不被看好，虽然没有直接讨论主要话题，但暗示了对某些技术选择的看法。 补充讨论： • **工具调用方式的比较**：讨论中提到了不同工具调用方式的优缺点，如 JSON blob 和 Python 函数存根的比较。 • **具体技术实现问题**：如 rapidaneurism 提出的用户令牌传递问题，显示了对具体技术细节的关注。 • **分享资源**：_moog 分享了自己绘制的流程图，提供了一个实际的资源来帮助理解和解决标准化问题。 争议焦点： • 不同工具和方法在实际应用中的优劣，例如 JSON blob 与 Python 函数存根的比较，以及 MCP 比 REST 或 CLI 更受欢迎的原因。
