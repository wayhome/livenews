Scaffold Level Editor

文章摘要

在最新的Nightshift Galaxy开发直播中，开发者展示了一款名为Scaffold的专用关卡编辑工具，该工具旨在提升工作效率、确保游戏独特性以及优化性能。作为独立开发者，作者希望通过自动化重复工作来专注于核心玩法设计。Scaffold工具提供交互式内饰设计、独特游戏系统以及高效数据结构，以避免游戏变得平庸。工具利用凸分解（Convex Decomposition）原理优化射线追踪和路径寻找算法，通过将场景分割为凸体积实现高效计算。固定容量的“对象桶”和空间细分技术进一步优化性能，确保在复杂场景中保持高帧率。工具还结合A*算法进行路径规划，确保角色在无碰撞路径上移动。总体而言，Scaffold旨在解决独立开发中的常见挑战，提升游戏开发效率和性能。

Decoding the 90s: Cryptography in Early Software Development (2023)

作者: mu0n | 评分: 127 | 评论数: 10 | 发布时间: 2025-04-07 14:43
文章摘要

这篇文章介绍了对90年代中期的QText文档进行密码破解和逆向工程的过程。QText是一个DOS时代用Turbo Pascal编写的希伯来-英语文字处理器。客户丢失了文档密码，因此作者团队被委托进行密码恢复。 文章描述了以下关键点： 1. 使用DOSBOX模拟器加载QText，初步分析发现密码短且未加盐，密钥似乎包含在文件中。 2. 加密方式简单，基于每行每列进行加密，空格不加密。 3. 由于密钥空间小，暴力破解密码是可行的。 4. 通过逆向工程分析MS-DOS二进制文件，发现QText可执行文件是PKZip打包的自解压文件。 5. 使用DOSBOX调试功能和外部工具成功解包可执行文件。 文章还讨论了早期软件开发和加密实现的特点，旨在提供历史洞见并保存相关知识和技术。

评论摘要
主要讨论点：90年代加密技术、现代加密实践、技术实现细节、用户体验问题、网站技术问题 不同观点： • [susam] 认为90年代的自定义RC4实现普遍存在安全漏洞，例如IV初始化不当、可预测的密钥流和明文泄漏。同时指出，微软Outlook 2003使用CRC32来"哈希"个人文件夹密码也是不安全的做法。不过，行业已经进步，如今自定义加密被视为危险信号。 • [blintz] 提出可以通过运行实际解密功能来破解90年代的简单加密，例如使用多核并行计算，尽管效率较低，但仍可接受。同时认为文章中提到的方法更具趣味性。 • [RKFADU_UOFCCLEL] 回顾90年代的加密实践，提到当时常用裸RSA和分组密码，且通常由一个“懂加密”的人负责，其工作通过功能测试后即被接受。当时破解和防御破解都是一种乐趣。 • [kragen] 对"早期软件开发"的定义提出质疑，认为尽管1992年距今不远，但软件开发的历史已经很长。同时思考当前是否仍处于"早期软件开发"阶段。 补充讨论： • [gizajob] 对文章无关的网站启动画面表示不满，认为浪费时间。 • [ipython] 表达了对文章的喜爱，回忆了使用IDA Pro和Bochs进行低层动态分析的时光，认为这些工具在当时非常强大。 • [fullstop] 提到文章图片无法加载的问题，并提供了截图和分析，指出可能是URL参数问题导致。 • [mfro] 对ScummVM免费提供IDA Pro 5.0表示赞赏，并计划尝试使用。 争议焦点： • 90年代加密技术的安全性以及现代加密实践的进步。 • 技术实现的效率问题，例如是否应通过多核并行计算来破解简单加密。 • 对"早期软件开发"定义的不同理解。 总结：评论主要围绕90年代加密技术的安全问题、现代加密实践的进步以及技术实现和用户体验等方面展开讨论。不同评论者根据自身经验提出了对加密技术发展的看法，并对一些具体技术实现和网站问题进行了讨论。

Any program can be a GitHub Actions shell

作者: woodruffw | 评分: 277 | 评论数: 21 | 发布时间: 2025-04-08 01:20
文章摘要

本文讨论了GitHub Actions中使用`shell`关键字来指定运行命令的shell类型。虽然默认值通常是合理的（如Linux和macOS上为bash，Windows上为pwsh），但用户可以明确指定任何在$PATH中的可执行文件作为shell。GitHub会对指定的shell添加一些默认标志，例如对bash添加`--noprofile --norc -eo pipefail`。文章还提到，利用这一特性可以实现一些不寻常的操作，例如使用C语言作为步骤运行器，或通过修改$PATH变量来使用自定义脚本。文章最后探讨了这一机制在安全方面的潜在影响，指出GitHub对$PATH的查找方式以及对预注册工具的接受可能带来意外行为。

评论摘要
主要讨论点：GitHub Actions的使用技巧、调试方法、安全性以及与其他工具的比较 不同观点： • **支持使用复杂技巧进行调试**：[jstrieb]和[throw10920]认为，使用如`-x`标志或自定义脚本可以有效帮助调试GitHub Actions工作流，尤其是在处理复杂脚本时，这些技巧非常有用。[throw10920]还提到，在处理大规模shell脚本时，有时会希望有更强的编程语言支持，如Python的标准库。 • **简化GitHub Actions逻辑**：[greener_grass]倾向于将复杂逻辑移到外部构建系统或CLI程序中，通过GitHub Actions调用，以便于本地调试。这种方法强调保持GitHub Actions的简洁性，避免在CI环境中进行复杂的调试。 • **使用GitHub Actions进行集中化管理**：[digianarchist]分享了一种利用`repository_dispatch`事件和通配符进行集中化发布管道的技巧，以便产品团队不必维护各自的工作流。这种方法强调了在多产品、多版本管理中的实用性。 • **对GitHub Actions代码可读性和安全性的评价**：[aljarry]指出GitHub Actions Runner的代码易于阅读和调试，并提供了具体代码位置以供参考。[nonethewiser]则讨论了潜在的安全风险，指出如果未注意到提交中的恶意代码，可能会带来安全隐患，但总体风险仍在可控范围内。 补充讨论： • **与其他工具的结合**：[dolmen]提到使用Go代码和goeval工具在GitHub Actions中运行CI作业，尽管需要一些shell技巧。此外，[cdata]建议将GitHub Actions与Nix结合使用，以增强其功能。 • **GitHub Actions与传统脚本的比较**：[z3t4]和[_def]讨论了GitHub Actions的YAML配置与传统bash脚本的优劣，提出了使用YAML配置是否优于直接运行bash脚本的问题，并提到了shell指令与shebang的等效性。 • **幽默与调侃**：[cturner]和[markus_zhang]以幽默的方式表达了对GitHub Actions复杂性和潜在技术债务的担忧，前者将其与过去的电子表格转换代码的经历相比较，后者则戏谑地提到用C语言和汇编语言编写CI/CD任务。 争议焦点： • 主要集中在**调试复杂性**和**安全性**上。部分用户认为GitHub Actions的调试难度较高，倾向于简化其使用，而其他用户则认为通过一些技巧可以有效调试并进行集中化管理。同时，也有对潜在安全风险的讨论，但总体认为风险可控。

Globstar: Open-source static analysis toolkit

作者: vortex_ape | 评分: 3 | 评论数: 0 | 发布时间: 2025-04-08 22:32
文章摘要

Globstar 是一个开源静态分析工具包，帮助开发者和安全工程师编写和运行代码检查器。它使用 tree-sitter 进行强大的 AST 分析，支持从简单的 YAML 接口到复杂的 Go 接口编写检查器。Globstar 具有以下特点： 1. **高速高效**：用 Go 编写，适合大型代码库，独立二进制文件无需担心依赖。 2. **原生支持 tree-sitter**：利用 S-expressions 编写检查器，或用 Go 实现更复杂的逻辑。 3. **CI 友好**：可在任何 CI/CD 管道中运行，无需额外安装依赖。 4. **完全开源**：MIT 许可，可自由用于商业项目。 安装方法： ```sh curl -sSL https://get.globstar.dev | sh ``` 编写检查器示例： ```yaml # .globstar/dangerous_eval.yml language: python name: dangerous_eval message: "Dangerous use of eval() detected." category: security severity: critical pattern: > (call function: (identifier) @func (#eq? @func "eval") arguments: (argument_list [(identifier) (binary_operator)])) ``` 在 CI 中运行： ```yaml jobs: analyze: runs-on: ubuntu-latest steps: - uses: actions/checkout@v3 - name: Install Globstar run: curl -sSL https://get.globstar.dev | sh - name: Run Globstar run: globstar check ```

Drag racers are ditching superchargers for scuba-style tanks and compressed air

作者: PaulHoule | 评分: 53 | 评论数: 19 | 发布时间: 2025-04-03 21:44
文章摘要

文章介绍了压缩空气增压技术（Compressed Air Supercharging，CAS）在直线加速赛车中的应用。这种技术通过将压缩空气以3,300 psi的压力储存在碳纤维罐中，然后将其输送至发动机，提供极冷、高密度的空气，以提升动力。相比涡轮增压和传统机械增压，CAS无需消耗引擎马力或排气驱动，且温度更低，对引擎内部和硬件更温和。尽管初期受到质疑，但如Dale Vaznaian等先锋和一些赛车手如Tina Pierce、Ryan Mitchell已开始采用并取得显著成绩。CAS能在较低压力下提供高效能，甚至适用于自动变速箱车辆，且对燃油辛烷值要求较低。尽管尚未普及，但其潜力巨大，未来可能对高性能赛车产生深远影响。
