Let Equals Equal Equals

作者: bennypowers | 评分: 8 | 评论数: 2 | 发布时间: 2026-05-28 09:14
文章摘要

这篇文章揭露了浏览器中 `ariaDescribedByElements` 等 ARIA 元素引用 API 的一个严重问题：当目标元素位于兄弟 shadow root 中时，赋值操作会被静默丢弃，不报错也不警告，导致辅助技术用户无法获得必要信息。 规范制定者为防止 shadow DOM 封装泄露而添加了"作用域"限制，只允许引用同一 DOM 或父级 DOM 中的元素。但这个解决方案牺牲了可访问性。文章指出封装问题有已知的替代方案（如 getter 返回 null 但保留内部引用），而当前的静默失败机制却让开发者无法修复可访问性问题。 作者认为，当开发者显式持有两个节点引用并主动赋值时，这是有意为之的操作，不应被静默拒绝。这个设计缺陷使得跨组件的 ARIA 关系几乎无法实现。

评论摘要
主要讨论点：关于 `input.ariaDescribedByElements = [helpText];` 这行代码的性质判断 不同观点： • **观点一（mrkeen的疑问）**：认为这应该是一个布尔表达式（boolean expression） • **观点二（mrkeen的自我纠正）**：否定了布尔表达式的说法，指出这实际上是一个赋值操作（Assignment），而不是等值比较（Equals） • **技术细节补充**：强调左侧（LHS）涉及隐式的 getter 操作，说明 `ariaDescribedByElements` 可能是一个属性访问器 补充讨论：这是一个自问自答式的技术澄清，核心在于区分赋值运算符（=）和比较运算符（==或===）的语义差异。评论者特别提到了"implicit getters"，暗示这可能涉及到对象属性的访问机制，而非简单的变量赋值。
