SQLite JSON at full index speed using generated columns

作者: upmostly | 评分: 355 | 评论数: 33 | 发布时间: 2025-12-12 13:25
文章摘要

本文介绍了SQLite数据库的JSON处理功能及其强大应用。作者分享了一种高效处理JSON数据的方法：将原始JSON存储在表中，创建虚拟生成列提取特定字段并建立索引，从而在不迁移数据的情况下实现快速查询。这种方法结合了NoSQL的灵活性和关系型数据库的性能优势，允许后期灵活添加查询字段和索引。作者通过实例演示了该模式的操作步骤，并强调这是SQLite的一个隐藏优势。文章表达了作者对SQLite的喜爱，并预告将继续分享更多SQLite的高级功能。

评论摘要
主要讨论点：[SQLite中JSON数据的索引优化方法及其与其他数据库的比较] 不同观点： • **Lite³格式的支持者** - 提出直接使用序列化B-tree编码JSON文档（Lite³格式），无需解析即可快速查询 - 示例：https://github.com/fastserial/lite3 - 争议点：与传统JSON解析和索引方法的性能对比未明确 • **DuckDB的推崇者** - 推荐DuckDB处理分析型工作负载，认为其速度更快且易于使用 - 示例：直接查询JSON文件路径（`SELECT avg(sale_price) FROM '/my-data-lake/sales/*.json'`） - 争议点：与SQLite的适用场景差异（分析型 vs. 嵌入式） • **生成列（Generated Columns）的实践者** - 认为通过生成列索引JSON字段是常见做法 - 示例：在Postgres中用生成列维护JSON中的外键约束 - 补充：SQLite的表达式索引（`CREATE INDEX idx ON table(json_extract(data, '$.key'))`）存在路径语法变动风险 • **数据规范化的倡导者** - 批评过度使用JSON列，认为规范化数据更利于索引和约束 - 论据：JSON列难以保证一致的索引和约束，增加查询开销 • **历史技术对比观点** - 指出类似方法在90年代XML文档数据库中已有应用 - 强调SQLite的现代集成优势 补充讨论： - **性能争议**：有评论质疑文章未提供基准测试验证“全速”性能（Seattle3503） - **扩展用例**：索引JSON数组需依赖FTS或单独表（AlexErrant） - **工具更新意识**：建议定期查看SQLite新特性（kevinsync） - **移动端体验问题**：iPhone上SQL编辑器存在交互缺陷（simonw）

Guarding My Git Forge Against AI Scrapers

作者为了保护自己的Git代码托管平台（Forgejo）免受AI爬虫的侵扰，采取了一系列防御措施。他发现大量爬虫不断抓取代码库中的历史提交和文件，导致服务器响应缓慢。通过统计发现，一个Linux代码库可能产生超过3000亿个可抓取页面。作者先后实施了反向代理缓存、请求速率限制、手动重定向到垃圾页面、自动识别并毒化爬虫请求（使用Iocaine和Nam-Shub-of-Enki技术）以及查询监控等措施，有效减轻了爬虫带来的负担。文章强调了保护个人数据免受AI训练数据收集的重要性。

评论摘要
主要讨论点：[如何应对AI爬虫对自托管服务的滥用及其影响] 不同观点： • **技术防御措施**： - Gitea的`REQUIRE_SIGNIN_VIEW=expensive`能有效减少AI流量（mappu） - 使用Geoblocking限制特定国家访问（FabCH） - 通过Anubis等工具大幅降低访问量（kstrauser） - 要求HTTP/2.0或SSH访问以过滤爬虫（Bender） - 使用OAuth2-proxy保护特定仓库（craftkiller） • **爬虫行为的低效性**： - 爬虫未优化，频繁访问无关页面（hashar） - 爬虫应通过git克隆本地分析而非频繁请求（Artoooooor） • **隐私与访问控制**： - 建议将服务隐藏于内网或VPN后（wrxd） - 完全屏蔽HTTP/S端口，仅允许Wireguard访问（overfeed） • **对AI的潜在影响**： - 通过提供误导性数据（如翻译为冷门语言）可能污染AI训练集（dirkc） - 生成垃圾内容以干扰爬虫（GoblinSlayer） • **爬虫背后的动机争议**： - 部分爬虫可能是被劫持的家庭IP（dspillett） - 认为某些服务商故意制造骚扰以推广付费反爬服务（PeterStuer） 补充讨论： - **争议焦点**：爬虫是否真的需要如此低效（hashar vs. PeterStuer对动机的分析） - **极端方案**：静态化git仓库（qudat）与完全封闭网络（overfeed）的对比 - **幽默回应**：iocaine项目用生成迷宫反制AI（GoblinSlayer） - **副作用观察**：服务器负载可被风扇噪音感知（sodimel）
