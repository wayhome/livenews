DuckLake is an integrated data lake and catalog format

作者: kermatt | 评分: 259 | 评论数: 30 | 发布时间: 2025-05-27 13:43
文章摘要

DuckLake是一种由DuckDB团队推出的数据湖和目录格式，通过使用Parquet文件和SQL数据库提供高级数据湖功能，简化了传统湖仓的复杂性。它支持快照、时间旅行查询、模式演变和分区等功能，并通过ACID事务保证多表操作的并发访问。DuckLake可以使用支持ACID事务和主键约束的任何SQL系统作为目录数据库，如PostgreSQL、SQLite、MySQL和DuckDB。用户可以在对象存储（如AWS S3）上存储数据，并通过DuckDB扩展实现对DuckLake的一流支持。DuckLake提供了轻量级快照和性能优化，适合需要数据湖和目录的一站式解决方案。

评论摘要
主要讨论点：围绕DuckLake及相关数据湖技术（如Iceberg、Delta Lake）的讨论，包括它们的优缺点、元数据管理、集成问题以及与现有工具的比较。 不同观点： • **amluto** 认为Parquet在处理时间戳数据时缺乏对范围分区的原生支持，导致需要使用一些不优雅的解决方案（如按日期列分区），并希望有一个统一的文件命名方案来支持范围分区。同时提到不同数据格式的微小差异也带来不便。 • **dkdcio** 对DuckLake表示兴奋，认为其相对于Iceberg和Delta Lake更易于在本地尝试，尤其是避免了大量设置工作，且性能表现优秀。然而，他也提到Delta Lake的Python实现较为碎片且多bug。 • **georgewfraser** 认为Iceberg将元数据存储在文件中的做法不如直接存储在数据库中高效，并预测DuckLake的元数据管理方式可能会被广泛吸收，而Iceberg格式可能逐渐被淘汰。 • **Dowwie** 强调DuckLake通过将元数据存储在SQL数据库中，解决了Lakehouse系统在查询规划和表更新时效率低下的问题，从而提高了操作速度和可靠性。 • **wodenokoto** 分享了自己在工作中构建简易数据湖的经验，使用deltalake-rs和DuckDB，但遇到并发写入的问题，尤其是在处理回填和定时触发的函数时。 • **jakozaur** 提到Iceberg在元数据处理上的不足，并指出Snowflake使用FoundationDB处理元数据的做法更为合理。 • **spenczar5** 对DuckLake的元数据格式表示担忧，认为这种新格式可能在处理大型数据集时难以实现良好的查询并行性，而Iceberg在这方面已有广泛支持。 补充讨论： • **nehalem** 和 **buremba** 提到MotherDuck与DuckLake的关系，认为MotherDuck可能更专注于提供DuckDB的“多人模式”及用户界面层。 • **snthpy** 关注DuckLake中未版本控制的`table_stats`和`column_stats`表，担心这会影响时间旅行查询（time-travel queries）的功能。 • **a26z** 关注DuckLake与Apache Spark等其他大数据工具的集成问题，询问其是格式还是目录。 • **BewareTheYiga** 认为DuckLake的技术优势在企业环境中面临市场和决策者的非技术性因素挑战，如现有供应商关系和决策习惯。 争议焦点： • DuckLake与Iceberg等现有数据湖技术在元数据管理和查询性能上的优劣比较。 • DuckLake的新元数据格式是否适用于大规模数据查询。 • 在企业环境中推广DuckLake等新技术的实际可行性，尤其在面对已有市场巨头时。

Clojure MCP

作者: todsacerdoti | 评分: 196 | 评论数: 9 | 发布时间: 2025-05-25 06:48
文章摘要

Clojure MCP 是一个正在开发中的阿尔法软件，旨在通过人工智能辅助实现 Clojure 项目的 REPL 驱动开发。该项目提供了一套完整的工具，包括 Clojure REPL 连接、Clojure 编辑增强（使用 clj-kondo、parinfer 等工具）、以及针对 Clojure 开发优化的功能集，是 Claude Code 的超集。其主要优势包括即时反馈、增量开发、人工监督以及函数式编程方法。该工具设计为一个内聚的系统，支持智能文件编辑、结构化操作和 REPL 集成开发，并能有效管理文件读写状态。推荐与 Claude 4 等高性能 LLM 模型配合使用，以获得最佳体验。虽然可以与其他代码助手一起使用，但建议先独立体验 Clojure MCP 工具的全部功能。

DNA methylation age from peripheral blood predicts Alzheimer's progression

作者: bookofjoe | 评分: 4 | 评论数: 0 | 发布时间: 2025-05-28 21:56
文章摘要

本文研究了DNA甲基化年龄（即表观遗传时钟）与阿尔茨海默病（AD）进展之间的关系。通过使用纵向模型和结构性神经影像分析，发现第二代表观遗传时钟DNAmPhenoAge和DNAmGrimAge能够预测从认知正常到轻度认知障碍或AD的进展，并与更差的认知结果相关。此外，表观遗传年龄与AD相关大脑区域的皮层变薄及白质病变负担有显著关联。这表明，基于血液的表观遗传时钟在预测AD风险和病理生理方面具有广泛应用潜力，与先前研究的结论不同。研究强调了使用纵向数据和多模态神经影像的重要性。

GitHub MCP exploited: Accessing private repositories via MCP

作者: andy99 | 评分: 473 | 评论数: 53 | 发布时间: 2025-05-26 13:46
文章摘要

GitHub MCP服务器存在一个严重漏洞，攻击者可通过恶意GitHub Issue劫持用户代理，窃取私有代码库数据。该漏洞由Invariant的安全分析器首次发现，属于“有毒代理流”攻击，即代理被操纵执行非预期操作，如泄露数据或执行恶意代码。在攻击示例中，用户使用MCP客户端（如Claude Desktop）连接GitHub MCP服务器，攻击者通过在公共代码库创建恶意Issue，诱导代理拉取私有数据并泄露在公开的Pull Request中。Invariant开发了自动化方法检测此类有毒代理流，以帮助组织识别和防范此类风险。当前软件开发工具广泛使用，需高度关注此类漏洞。

评论摘要
主要讨论点：关于MCP（Multi-Component Protocol）和LLM（如Claude）使用访问令牌的安全性及潜在漏洞的讨论。 不同观点： • **losvedir**：认为问题不在于MCP本身，而在于用户是否明智地授予LLM适当的权限。如果使用细粒度的访问令牌，限制LLM只能访问必要的资源，那么这种攻击就不会成功。重点在于用户应谨慎管理凭证权限。 • **mirzap**：质疑这种操作是否真的算作“漏洞”。如果授予代理访问令牌，它就能访问相应权限内的资源。责任在于用户是否正确配置了权限，而不是MCP或LLM本身的问题。 • **adeon**：认为安全问题源于LLM处理不可信输入时的行为。任何不可信的输入都可能导致LLM执行非预期的操作。同时指出，安全防护的复杂性表明AI公司在设计初期的安全意识不足。 • **joshmlewis**：认为这种攻击实际上是利用了提示注入（prompt injection）技术，而非MCP本身的漏洞。强调在构建或使用代理系统时，应谨慎管理代理的访问权限，并以请求代理操作的用户作为安全责任的主要承担者。 • **JoshMandel**：指出GitHub OAuth流程在权限管理上的不足，特别是默认授予全权访问的问题。为了安全使用代理，用户可能需要创建额外的GitHub账户，但这种做法并不方便。 • **kiitos**：认为该漏洞的描述被夸大了。要实现攻击，用户需要进行多个配置步骤，且攻击成功的前提是用户明确请求LLM处理不受信任的数据。同时指出，GitHub MCP在公私库交互上的设计存在缺陷。 • **dino222**：认为MCP只是其中一个协议，未来可能会有更多类似的协议出现。LLM未来可能会具备直接使用API的能力，因此需要更强的安全措施。 • **linkage**：认为MCP并不是问题的核心，提示注入攻击本身才是关键，即使没有MCP，类似的攻击也能通过其他客户端实现。 补充讨论： • **lbeurerkellner**：作为相关作者之一，提供了多个关于MCP和代理安全的资源链接，并提到具体的攻击场景执行痕迹，进一步讨论了安全防护措施如Guardrails和AgentDojo。 • **phtrivier**：指出问题根源可能在于用户选择了“总是允许”工具调用确认，而非每次都人工审核。这种操作与安全需求之间存在张力。 • **ttoinou**：建议对LLM的每个查询设置细粒度的权限开关，如开启/关闭记忆、访问特定应用或连接器等，而不是依赖LLM模糊的描述进行安全管理。 • **drkrab**：指出当用户授予第三方访问其GitHub仓库时，必须信任该第三方实施了所有GitHub的安全策略，而这在实际中可能很难保证。 争议焦点： • 该问题是否应被视为MCP或LLM本身的漏洞，还是用户配置权限不当所致。 • GitHub OAuth流程的权限管理是否足够便捷和安全。 • 安全责任应由用户承担还是应内置于AI系统设计中。

The Myth of Developer Obsolescence

作者: cat-whisperer | 评分: 345 | 评论数: 55 | 发布时间: 2025-05-27 10:33
文章摘要

文章主要讨论了技术发展对软件开发的影响，尤其是从无代码运动到人工智能辅助开发的演变。每次新技术出现时，都会有人宣称这些技术将使开发者过时，例如无代码工具、云计算和 offshore 开发等。然而，现实是这些技术并没有取代开发者，而是创造了新的专业角色和更高的薪酬需求，例如无代码专家和DevOps工程师。 人工智能辅助开发同样遵循这一模式。尽管AI能生成代码，但它往往需要高级工程师的校正和系统架构设计。软件开发中最有价值的技能不是写代码，而是设计系统架构，这是AI无法替代的。技术进步并未消除专业技能的需求，而是将其提升到更高的抽象层次。

Singularities in Space-Time Prove Hard to Kill

作者: nsoonhui | 评分: 26 | 评论数: 2 | 发布时间: 2025-05-28 04:04
文章摘要

文章讨论了时空中的奇点问题，特别是在黑洞和宇宙大爆炸中的奇点，这些奇点打破了当前的引力理论。爱因斯坦的广义相对论预测，当物质或能量高度集中时，时空会无限弯曲，形成奇点，但大多数物理学家认为这是理论的数学 artifact，而非实际存在。罗杰·彭罗斯在1960年代证明了奇点在纯时空宇宙中不可避免，而近期研究进一步表明，即使在更接近现实的量子粒子宇宙中，奇点依然存在。这些发现表明，奇点可能不仅仅是数学幻象，而是时空结构中的真实缺陷，挑战物理学家寻找更基本的量子引力理论来解释这些现象。

评论摘要
主要讨论点：黑洞奇点问题及其相关理论解释 不同观点： • [randomtoast] 支持使用弦理论中的"模糊球"（Fuzzballs）概念来解决黑洞奇点问题。根据这一观点，传统认为的奇点实际上是由弦和膜交织而成的量子"模糊"结构，取代了平滑的事件视界，从而在量子引力框架下保留了信息，解决了信息悖论问题。虽然这一理论仍有争议，但它在量子引力理论中有具体的实现方式。 • [scotty79] 提出了一种非传统的观点，认为黑洞奇点在自己的参考系中可以在有限时间内形成，但在其他参考系中则需要无限时间。因此，从我们的角度来看，奇点从未真正形成。由于广义相对论中无法明确界定同时性，物理学家通常不考虑在强引力场中远程事件的先后顺序。这种观点进一步推测，在无限时间内，某些事件（如与大量反物质碰撞）可能会中断黑洞的坍缩过程，导致类似大爆炸的巨大能量释放，且没有白洞奇点。 补充讨论： • [randomtoast] 的观点强调了弦理论在解决黑洞信息悖论中的潜力，认为模糊球理论提供了一种不依赖火墙模型且不破坏半经典引力的解决方案。 • [scotty79] 的观点挑战了传统广义相对论对奇点形成的理解，强调了参考系和同时性问题在黑洞物理学中的复杂性，同时提出了一种基于大爆炸类比的可能性。 • 争议的焦点在于如何在量子引力框架下有效解决黑洞信息悖论，以及不同参考系对奇点形成时间的影响。这些讨论反映了当前物理学界对黑洞本质及其奇点问题的多角度探索。

Outcome-Based Reinforcement Learning to Predict the Future

作者: bturtel | 评分: 96 | 评论数: 5 | 发布时间: 2025-05-27 13:33
文章摘要

本文介绍了一种基于结果的强化学习方法（RLVR），用于提升大规模语言模型在实际预测任务中的表现。作者通过适应两种主要算法——群相对策略优化（GRPO）和ReMax——解决了在二元、延迟和噪声奖励环境下学习不稳定的问题。改进后的方法应用于一个140亿参数的模型，在预测校准和假设预测市场投注中表现优于前沿基线模型。实验显示，该方法不仅提高了预测准确性，还能通过简单的交易规则转化为经济价值。这表明，经过优化的RLVR方法可以将小规模语言模型转化为具有经济价值的预测工具，并具有扩展至更大模型的潜力。

评论摘要

主要讨论点：大学生在学年结束时丢弃大量物品的现象及其背后原因，奢侈品市场的人为稀缺性，以及垃圾回收和二手物品处理的实际操作。 不同观点： • **奢侈品市场的虚假性**：[newccount] 认为奢侈品品牌通过销毁未售出的库存来人为制造稀缺性，并使用各种手段隐藏商品的真实产地，质疑奢侈品的实际价值。他们引用Cartier母公司销毁4亿英镑手表的例子来支持这一观点。 • **文化差异和物品处理方式**：[dkga] 提到在瑞士，人们通常会把不需要的物品放在路边供他人免费拿取，并对作者感到内疚表示不解。他们认为重复使用物品是一种积极的行为。 • **国际学生和搬家困难**：[matthewowen] 和 [AdmiralAsshat] 分享了作为学生在搬家时面临的实际困难，例如物品运输成本高、时间紧迫，导致不得不丢弃一些物品。[AdmiralAsshat] 特别提到自己曾被迫丢弃一个便宜的搅拌机，因为运输成本高于其本身价值。 • **垃圾回收和物品再利用**：[bityard] 和 [nappy-doo] 分享了在大学城通过垃圾箱寻找可用物品的经验，指出很多被丢弃的物品实际上仍然完好无损。他们认为这是一种资源再利用的方式。[alnwlsn] 进一步指出，不仅是学生，富裕地区的人们也常常丢弃稍有损坏但仍可修复的物品。 • **捐赠数据和未被统计的捐赠**：[Kon-Peki] 质疑文章中对学生捐赠量的统计数据，认为未被大学统计的捐赠，例如通过教堂和犹太教会进行的捐赠，可能未被计算在内。 • **市场流动性和二手物品买卖**：[the__alchemist] 提到买卖二手物品的不便之处，指出买卖之间的价差和流动性问题使得人们更倾向于丢弃物品而不是转售或捐赠。 补充讨论： • **道德和法律问题**：[nancyminusone] 认为从垃圾中捡东西没有道德问题，只要明确物品是被丢弃而不是被误放。 • **实际案例和经验**：[xivzgrev] 和 [pknomad] 分享了自己或他人通过Craigslist转售被丢弃物品的实际经验，指出这种行为在学生中并不少见。 争议焦点： • **奢侈品市场的真实价值和人为稀缺性**：有人质疑奢侈品市场通过销毁商品制造稀缺性和高价值形象，而其他人则可能认为奢侈品有其独特的市场需求和价值。 • **物品丢弃和再利用的文化差异**：不同地区和文化在处理不再需要的物品时的方式和态度存在差异，一些人认为重复使用是积极的行为，而另一些人则可能因为各种实际困难而选择丢弃。 • **二手物品市场的流动性和便利性**：买卖二手物品的实际操作中存在的困难和不便，使得人们更倾向于丢弃物品而不是转售或捐赠，这是另一个值得注意的讨论点。

Nanoparticle-cell link enables EM wireless programming of transgene expression

文章摘要

研究人员开发了一种通过电磁无线编程控制哺乳动物转基因表达的新方法，称为EMPOWER。该方法利用多铁芯纳米颗粒（如钴铁氧体和铋铁氧体）与细胞界面，这些纳米颗粒外层涂有壳聚糖，能安全进入细胞质并屏蔽生物环境。在低频磁场刺激下，纳米颗粒产生生物安全的活性氧（ROS），激活细胞内的KEAP1/NRF2通路，从而控制特定治疗蛋白（如胰岛素）的表达。该技术非侵入性且精确，已在糖尿病小鼠模型中成功验证，能有效调控胰岛素分泌并维持正常血糖水平。这一突破为慢性疾病治疗和合成生物学研究开辟了新途径。
