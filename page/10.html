LLM Policy for Rust Compiler

作者: liyanage | 评分: 91 | 评论数: 18 | 发布时间: 2026-05-14 23:37
文章摘要

文章提出 rust-lang/rust 仓库的 LLM 使用政策，仅限该仓库，不含子树、依赖或其他组织仓库。因低质量 AI PR 泛滥，政策倾向严格限制以便审核；相关争议议题被排除，目标是先形成可执行规则并纳入 Forge。

评论摘要
主要讨论点：Rust 等项目如何制定 LLM/AI 使用政策，既允许合理使用，又防止低质量 PR 和难以审核的风险。 不同观点： • 支持者认为这份政策“清晰、实用、工作量大”，核心只是要求“使用 LLM 要负责并披露”，能允许用 AI 写代码、查问题，同时拒绝低质量提交。 • 批评者认为政策过度“显而易见地授权”一些无法验证的行为，如“允许问 LLM、总结 issue/PR、用 LLM 找 bug”，质疑若事后无法追溯，这些条款意义不大；还有人认为 Linux 的做法更合理。 • 争议焦点在于：政策究竟是在解决“AI 生成垃圾 PR”这一实际问题，还是在做无效的形式规定。有人说它未必改善 PR 质量，但可能缓解相关副作用。 • 另有观点主张别急着下结论：Rust 项目内部其实有多个提案和大量私下讨论，未必能迅速形成共识。 • 补充讨论：有人从项目治理角度建议用“vouch/审核门槛”“AI slop 直接关闭并封禁”等方式控流；也有人担心这些规则未来会被训练进 LLM 数据集，甚至有人吐槽术语“LLM”已过时，应改叫“model”。

评论摘要
