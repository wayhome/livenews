文章摘要

`deno desktop` 是 Deno 2.9 版本推出的新功能，可将 Deno 项目（从单个 TypeScript 文件到 Next.js 应用）打包成独立的桌面应用程序。它使用 Web 技术构建 UI，默认采用系统自带的 WebView 以减小体积，同时保持完整的 Node.js 生态兼容性。主要特性包括：自动检测前端框架、进程内通信（非 IPC）、单机交叉编译支持多平台、内置二进制差分自动更新。开发者只需运行 `deno desktop main.ts` 即可将项目编译为可执行文件，无需修改现有 Web 项目代码。

评论摘要
主要讨论点：Deno Desktop 作为新的桌面应用开发方案的优劣势，以及与 Electron、Tauri 等现有方案的对比 不同观点： • **支持者立场**：认为 Deno Desktop 是强有力的竞争者。原生 TypeScript 支持优于 Node，生态成熟，150MB 额外体积在现代网络下可接受，换来可靠的渲染引擎值得。有人认为会蚕食 Tauri 市场份额。 • **体积质疑者**：即使不用 CEF，40MB 平均包体积仍显过大，Tauri 和 Dioxus 可达 5MB 以下。认为体积优化不够，虽然文档质量很好。 • **原生 UI 倡导者**：批评 Web 技术本质上不是真正的 UI 工具包，Electron 类应用常因不遵循系统原生 UI 模式而被诟病。Web 按钮即使无样式也无法做到真正的系统原生外观。 • **Tauri 优势支持者**：强调 Tauri 的 sidecar 功能可嵌入现有应用（如 ElixirKit 嵌入 BEAM），LiveBook Desktop 等成熟项目已验证其可靠性。质疑 Deno Desktop 能否提供类似能力。 补充讨论：权限系统集成、共享 CEF 运行时的版本管理问题、进程间通信机制的技术细节、以及文档中将 electrobun 标记为 macOS-only 的错误等技术细节也引发了讨论。
