Message your other Claude Code sessions

作者: mfiguiere | 评分: 157 | 评论数: 24 | 发布时间: 2026-08-08 15:34
文章摘要

这篇文章介绍了 Claude Code 的跨会话消息功能（需 v2.1.224+ 版本，支持 macOS/Linux）。该功能允许不同 Claude Code 会话之间传递消息，而非共享完整对话历史或文件。 **主要用途：** - 传递重要发现或决策给相关会话 - 协调并行工作树中的多个会话 - 获取长时间运行任务的状态反馈 - 跨机器会话间的消息回复 **工作机制：** Claude 使用 ListAgents 发现可达的其他会话，用 SendMessage 发送消息。消息在接收会话的工具调用间隙读取，闲置时则启动新轮次。 **权限控制：** 每个会话有独立的入站控制，消息可能被传递、暂存或拒绝。权限边界保持独立，不会跨会话请求被拒绝的操作。

评论摘要
主要讨论点：AI代理之间的消息传递和上下文共享功能 不同观点： • **安全担忧派**：指出这本质上是远程代码执行漏洞，开放了新的攻击面，安全研究人员对此只能无奈接受 • **自建工具派**：大量用户表示已自行构建类似功能，使用tmux、IRC服务器、Telegram、MCP等不同技术栈实现，体现出个人化软件开发的趋势 • **实用主义派**：强调功能价值——减少重复上下文的token成本，专业子代理可共享知识，甚至能在用户不在时自主协调诊断问题并创建工单 • **体验反馈派**：指出当前实现较笨拙，需要手动在终端间复制消息，不如其他工具（如Codex）流畅；有用户通过本地HTTP端点播放提示音来改善体验 补充讨论： 评论中出现有趣细节——AI代理之间会互相评价（Codex称Claude"冗长"），以及它们会自建消息系统。有用户希望增加对话压缩功能。还有技术对比，如浏览器BroadcastChannel API未被充分利用，以及与multiplexer集成的可能性。整体反映出AI工具个性化定制的普遍需求。

文章摘要

这是一个将1991年Microsoft Word 1.1a（代号Opus）移植到64位Windows的开源项目。项目保留了原始C源代码和资源文件，通过以下方式实现现代化： - 将16位x86汇编代码翻译为C/C++ - 适配分段内存模型到x64架构 - 将Win16 API调用转换为Win32 API - 使用现代工具重新构建原始资源 构建环境需要Visual Studio 2022和CMake 3.25+。项目包含完整的测试套件，覆盖运行时、数据结构和UI自动化测试。 这不是模拟器或重新实现，而是让原始Word应用以64位可执行文件的形式运行，保持了原汁原味的用户体验。项目提供了详细的构建说明和测试流程，适合研究早期文字处理软件的架构和实现。

评论摘要
主要讨论点：针对Microsoft Word 1.1a的Windows x64移植项目的讨论 不同观点： • **怀旧派**：多位用户（acmdas、bananaboy）怀念老版本Word/Excel，认为'98年后UI质量下降，早期版本功能已足够使用，磁盘占用更小 • **技术实现关注**：spider-mario发现构建问题（缺少cmake文件），BaudouinVH询问Linux移植难度，haunter分享了在现代Windows运行16位应用的解决方案 • **实用需求**：ulfw希望看到项目截图，ranger_danger询问是否提供编译好的二进制文件，反映用户对便捷性的需求 补充讨论：zatkin提到有趣的历史巧合——"Opus"既是Word 1.1a的代号，也是Anthropic的LLM模型名称。整体氛围积极，用户对复古软件移植项目表现出兴趣，但也暴露出项目在文档完整性（缺少截图）和技术配套（构建文件缺失、无预编译版本）方面的不足。

评论摘要
