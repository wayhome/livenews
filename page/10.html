RDNA 4's “Out-of-Order” Memory Accesses

作者: ingve | 评分: 152 | 评论数: 6 | 发布时间: 2025-03-23 22:18
文章摘要

AMD's RDNA 4 architecture introduces improvements in memory subsystem handling, particularly with "out-of-order" memory accesses. Previously, in RDNA 3, memory requests from different shader waves were processed in a strict order, causing delays if one wave had to wait for another's memory loads. This led to inefficiencies, as later requests couldn't bypass earlier ones, even if their data was ready. In RDNA 4, requests from different waves can be processed out-of-order, eliminating false dependencies and improving performance. Testing involved creating scenarios where "wave X" and "wave Y" had differing memory access patterns. In RDNA 3, wave X's accesses were unnecessarily delayed by wave Y's cache misses, as the memory subsystem waited for all wave Y's accesses to complete. However, in RDNA 4, both waves operate independently, preventing such delays and improving overall efficiency. This change aligns with multithreaded programming principles, enhancing performance scaling in GPU operations.

I want a good parallel computer

作者: raphlinus | 评分: 219 | 评论数: 33 | 发布时间: 2025-03-21 19:55
文章摘要

本文讨论了为何GPU尽管在实时图形渲染和机器学习等任务中表现出色，但在其他工作负载中未被广泛应用的原因。主要障碍有两个：一是GPU的执行模型较简单，难以高效处理动态任务；二是编程语言和工具不足，使得并行计算编程更加困难。现代GPU日益复杂，新功能虽有进步但仍不完善。作者通过开发Vello渲染器的经验，指出GPU在处理中间数据结构时存在内存管理问题，无法在有限内存中高效运行。尽管有许多潜在解决方案，但当前硬件存在致命缺陷。作者呼吁设计更简单、更强大的并行计算机，并提到历史上曾有一些有潜力的设计未被广泛应用。文章最后表达了对未来改进的期待和可能性。

Show HN: A terminal emulator in pure PHP

作者: aarondf | 评分: 192 | 评论数: 12 | 发布时间: 2025-03-21 17:43
文章摘要

**SoloTerm/Screen** 是一个用纯 PHP 编写的终端渲染器，用于在 PHP 应用中创建富文本用户界面，尤其为 **Laravel** 的 **Solo** 提供支持。它专注于解释和渲染带有格式的文本内容，而非处理输入或进程管理。通过虚拟终端缓冲区，它安全地解释 ANSI 转义序列（如光标移动、颜色变化），并在隔离环境中管理屏幕输出，确保复杂操作不会干扰界面其他部分。 **功能特点**： - 纯 PHP 实现，仅依赖 **Grapheme** 库。 - 支持 ANSI 转义序列，包括光标定位、文本样式和屏幕操作。 - 支持 Unicode/多字节字符和双宽度字符（如 CJK 字符）。 - 管理缓冲区和滚动功能。 **安装**： 通过 Composer 安装，要求 PHP 8.1 及以上版本。 **使用示例**： 创建屏幕对象，写入文本和 ANSI 转义序列，并输出渲染内容。Screen 使用多个缓冲区管理内容和样式，支持复杂的光标操作和文本样式。 该库最初为 **Solo** 开发，现已独立，可用于任何需要终端渲染的 PHP 应用。

文章摘要

The New Three-Tier Application

作者: qianli_cs | 评分: 73 | 评论数: 23 | 发布时间: 2025-03-18 13:04
文章摘要

文章主要介绍了应用程序架构的演变以及应对分布式后端复杂性的解决方案。最初，90年代的应用采用三层架构：数据源层、域层和表示层。随着时间推移，表示层演变为前端，域层演变为后端。由于计算和组织复杂性的增加，后端从单体架构转向微服务和无服务器架构，导致需要协调分布式操作。为解决这些问题，开发人员引入了编排层，负责在服务间协调操作，确保代码在面对故障时正确执行。编排层有两种主要实现方式：一种是利用事件处理系统或消息代理（如Kafka）的DIY方式，另一种是使用专用编排系统（如AWS Step Functions、Apache Airflow）。虽然编排层解决了分布式系统的复杂性问题，但两种方式各有优缺点，DIY复杂难维护，专用系统则需将控制流外包给外部工具。

评论摘要
