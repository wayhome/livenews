AirBorne: Wormable zero-click remote code execution (RCE) in AirPlay protocol

文章摘要

Oligo Security Research发现苹果AirPlay协议及其软件开发工具包（SDK）存在一系列漏洞，可能导致多种攻击，包括无点击远程代码执行（RCE）、单点击RCE、访问控制列表（ACL）绕过、本地任意文件读取、敏感信息泄露、中间人攻击（MITM）和拒绝服务（DoS）等。这些漏洞被统称为“AirBorne”，可能被攻击者利用来完全控制支持AirPlay的设备，包括苹果设备和使用AirPlay SDK的第三方设备。 其中，CVE-2025-24252和CVE-2025-24132两个漏洞可被用于制造可传播的零点击RCE攻击，导致恶意软件在本地网络中传播。苹果与Oligo合作修复了这些漏洞，并发布了更新软件。Oligo共报告了23个漏洞，导致17个CVE编号发布。 攻击可能影响MacOS、AirPlay SDK和CarPlay设备，特别是在设备设置为“同一网络上的任何人”或“所有人”时更易受攻击。攻击者可能通过公共WiFi入侵设备，进而通过企业网络传播攻击。

Performance optimization is hard because it's fundamentally a brute-force task

作者: todsacerdoti | 评分: 280 | 评论数: 31 | 发布时间: 2025-04-29 12:29
文章摘要

这篇文章讨论了性能优化的困难之处，主要包括以下几点： 1. **组合性**：某些优化只能一起工作，而有些组合则会导致性能下降。选择正确的优化组合需要深厚的知识和经验。 2. **剪枝和试错**：去除明显的次优方案往往依赖于启发式方法。优化通常需要大量的试错，无法单靠直觉，必须进行性能分析（profiling）。 3. **连续性**：一些算法需要选择参数和优化边界，例如混合排序算法和FFT，小改动可能导致性能剧变。持续的重新 benchmarking 是必要的。 4. **不兼容性**：某些优化由于外部限制而失败，例如两个查找表（LUT）无法同时放入缓存。这种情况下，需要通过分块等技巧尝试解决。 文章最后建议将优化工作分配给多人进行，开源项目尤其受益。同时，作者提倡建立自动寻找最佳参数的测试平台，以减轻手动优化的负担。

Show HN: I built a hardware processor that runs Python

作者: hwpythonner | 评分: 967 | 评论数: 73 | 发布时间: 2025-04-28 11:44
文章摘要

PyXL是一个直接在硬件上执行Python的处理器，无需虚拟机、即时编译（JIT）或操作系统。它通过自定义工具链将Python代码编译为CPython字节码，再转换为自定义汇编代码，最终生成在FPGA上运行的二进制文件。PyXL在Zynq-7000 FPGA（Arty-Z7-20开发板）上运行，其核心运行频率为100MHz。与MicroPython相比，PyXL的GPIO往返延迟仅为480纳秒，而MicroPython需要约15,000纳秒，速度快30倍，按时钟速度归一化后快50倍。PyXL通过直接在硬件上执行Python字节码，实现了确定性时序和亚微秒级的精度，避免了软件堆栈和解释器的开销。
