Use your Nvidia GPU's VRAM as swap space on Linux

作者: tanelpoder | 评分: 459 | 评论数: 42 | 发布时间: 2026-06-02 22:55
文章摘要

**nbd-vram 项目概要：** 这是一个让 NVIDIA GPU 显存作为 Linux 交换空间的工具，专为混合显卡笔记本设计。在集成显卡负责显示、独显闲置时，将其显存用作高优先级 swap。 **工作原理：** 守护进程通过 CUDA API 分配显存，用 NBD 协议将其作为块设备暴露给内核，再挂载为 swap 分区。数据通过 PCIe 在内存和显存间传输。 **优势：** 无需编写内核模块，不依赖 NVIDIA 内核符号，兼容所有 CUDA GPU（包括消费级显卡）。绕过了 P2P API 的 Quadro 限制。 **实测效果：** 8GB 显存分配 7GB 作 swap，配合 zram 和 SSD，总可用内存从 16GB 扩展至 46GB。

评论摘要
主要讨论点：将GPU显存(VRAM)用作系统交换空间的可行性和实际效果 不同观点： • **支持者观点**：适合笔记本等无法升级内存的场景，能让闲置的显存发挥作用。特别是对于拥有大显存但日常开发不跑AI模型的用户(如32GB VRAM大部分时间闲置)，这是个不错的想法 • **性能质疑者**：实测性能令人失望。RTX 3070的1.3 GB/s顺序读写速度远低于理论值(PCIe 4.0 x16应有64GB/s，GDDR6本身448GB/s)，甚至不如直接用NVMe SSD做交换空间快两倍。实际使用体验"完全就像传统的交换分区"，并非"90%性能损失换更多内存"的理想方案 • **技术实现讨论**：已有多个类似实现(MTD/phram驱动、OpenCL方案、Windows的GpuRamDrive等)。有人质疑当前实现层次过多导致性能低下，建议使用自定义块设备驱动 • **稳定性担忧**：Wayland环境下显存分配更动态，显存不足可能导致整个桌面崩溃。需要考虑显存分配的反压机制 补充讨论：有人提出应将此功能内置到内核中作为资源管理的一部分；另有观点认为现代系统很少使用交换空间(除了休眠功能)；GPU数据库应用场景的探讨

When does fragmentation occur in the CUDA caching allocator?

作者: matt_d | 评分: 10 | 评论数: 1 | 发布时间: 2026-06-01 18:43
文章摘要

这篇文章主要讨论 PyTorch CUDA 缓存分配器中的内存碎片问题。 **核心问题**：尽管有足够的空闲内存，分配器仍可能无法满足请求。 **原因**：分配器将 GPU 内存组织为段(segments)和块(blocks)两层结构。分配时会分割块，释放时会合并相邻的空闲块。关键限制是**不同段中的块无法合并**。 **典型场景**：在 LLM 服务等需要最大化内存利用的应用中，分配顺序会导致碎片。例如先分配小块再分配大块时，可能创建多个无法合并的段，导致浪费。 **解决方案**：文章介绍了"可扩展段"(expandable segments)特性如何通过允许段动态增长来缓解碎片问题，特别是在 CUDA 图录制等场景中。

评论摘要
这条评论只有一个作者的观点，没有多方讨论。以下是分析： **主要讨论点：** LLM服务中的内存分配策略，特别是如何处理长期存在的权重/图缓冲区与短期KV缓存的碎片化问题 **核心观点：** • 作者认为长期块与短期块交错导致的碎片化是LLM服务的常态而非边缘情况——模型权重和图缓冲区永久驻留，而每个请求的KV缓存频繁创建和销毁 • 可扩展段(expandable segments)无法跨越合并这种混合场景，因此标准缓存分配器不适用 • 解决方案是放弃依赖缓存分配器管理KV缓存，改为在上层自行管理：vLLM在启动时预留大内存区域，用固定大小的块进行分页管理，让底层分配器完全看不到KV的频繁分配释放 • 这种方法将碎片化问题提升一层解决——虽然碎片化依然存在，但通过应用层的显式内存管理避免了分配器层面的问题 **技术背景：** 这是针对GPU内存管理的专业讨论，涉及PyTorch缓存分配器的局限性和vLLM等推理框架的优化策略。

Algorithmic Theming Engines

这篇文章介绍了CSS的`contrast-color()`函数，用于自动选择可读的文本颜色。尽管多年来有各种工具和库，但2025年仍有70%的网站未通过基本的WCAG对比度检查。`contrast-color()`函数能在浏览器样式计算时自动返回黑色或白色文本颜色，无需JavaScript库。目前版本（Level 5）只支持黑白两色输出，未来Level 6计划支持更多候选颜色。该函数曾名为`color-contrast()`但已更名。规范刻意保持算法灵活性，虽然当前使用WCAG 2.x标准，但预留了升级到APCA等新算法的空间。
