主要讨论点：围绕Intel移除AVX-512的支持以及高效CSV解析技术的多方面讨论。 不同观点： • 一些用户对Intel移除AVX-512支持表示不满，认为Intel在消费者SKU中放弃了他们自己的投资，而AMD则在消费者CPU上保留了这一支持（[chao-], [Aardwolf], [gitroom]）。 • 部分用户关注具体的技术细节和优化方法，比如通过SIMD指令进行优化（[stabbles], [vessenes], [anthk]）。 • 有些评论对CSV解析的实际性能提升表示怀疑，认为其宣传可能具有误导性，特别是在处理CSV格式的复杂性方面（[imtringued]）。 补充讨论： • 一些用户对CSV解析性能的提升表示赞赏，并分享了实际应用中的需求和经验（[theropost], [criddell]）。 • 讨论中提到了其他可能更优的数据存储和交换格式，例如HDF5格式，强调了其结构化和压缩的优势（[constantcrying]）。 • 部分评论对Intel在消费者CPU中引入大小核架构的决定表示批评，认为这影响了AVX-512等技术的持续发展（[Aardwolf], [gitroom]）。 • 也有用户对CSV解析的具体应用场景和实现细节提出了疑问，希望了解更多关于解析结果处理的信息（[haberman]）。 • 技术实现的难度和现代编译器自动向量化能力的对比也被提及，有用户认为手动优化SIMD代码未必能带来显著性能提升（[chpatrick]）。 争议焦点： • Intel移除AVX-512支持的决定引发不满，用户认为这是在放弃已取得的一些技术进展。 • CSV解析性能的宣传被质疑为具有误导性，特别是在处理复杂CSV格式时。 整体来看，讨论围绕Intel的技术决策和高效CSV解析技术的实际效果展开，涉及技术细节、应用需求以及对技术宣传的质疑。

New Tool: lsds – List All Linux Block Devices and Settings in One Place

作者: mfiguiere | 评分: 90 | 评论数: 5 | 发布时间: 2025-05-09 18:13
文章摘要

本文介绍了一个名为 `lsds` 的Python工具，用于在Linux系统中集中展示磁盘的各类信息。通常，用户需要运行多个命令（如 `lsblk`、`lsscsi`、`nvme list` 等）来获取不同方面的磁盘信息，并手动关联输出。而 `lsds` 工具通过直接读取 `/sys/class/block` 目录下的信息，汇总了设备名、主/次设备号、大小、类型、I/O调度器、是否旋转盘、队列深度、请求数、写缓存等详细信息。该工具特别适用于查看NVMe SSD的配置信息，并提供选项以更简洁或详细的方式输出结果。例如，在一个有21个SSD的机器上运行 `lsds`，可以清晰展示各磁盘的关键参数。

评论摘要
主要讨论点：围绕工具和设备文件的讨论，包括 `lsblk` 命令的输出、功能重写、以及对设备文件的设想和应用。 不同观点： • [jayofdoom] 认为 `lsblk` 命令可以返回比默认更多的数据，特别是通过 `lsblk -H` 和指定列来调整输出。他还对该工具与其他类似工具的区别表示好奇。 • [bitbang] 表示对 `lsblk` 功能的支持，但建议增加 JSON/JSONL 格式的输出选项，以增强与其他工具的兼容性。 • [trillic] 分享了一个用 C 语言重写该功能的练习，并提供了 GitHub 上的代码片段链接，展示了如何通过重写实现相似功能。 • [DonHopkins] 提出了一个富有创意的设想，建议将 `/dev/zero` 设备文件的理念进一步扩展，比如通过设备文件的次设备号控制返回值，甚至设想用此方法生成无限的表情符号，并探讨了在 HTTP 服务器中应用的可能性。 补充讨论： • [babuloseo] 提出了将此功能打包用于 Arch Linux 系统的可行性，并呼吁 Arch Defense Taskforce 团队关注此事，暗示了对该功能在特定发行版中集成的兴趣。 争议焦点：目前讨论中没有明显的争议，主要是功能实现方式和改进建议的不同看法，特别是对输出格式和设备文件的创新使用设想。
