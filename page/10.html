Nōdo – Call Node.js from Ruby

作者: namiwang | 评分: 4 | 评论数: 0 | 发布时间: 2025-03-26 02:16
文章摘要

**Nodo** 是一个允许从 Ruby 调用 Node.js 的工具，通过在一个长期运行的 Node 进程中执行 JavaScript 代码，避免每次调用时重新初始化 JS 对象。它使用 Unix 套接字进行进程间通信，性能优于传统的 process/eval 方法。 **主要功能**： 1. **定义 JS 函数**：像定义 Ruby 方法一样定义 JS 函数。 2. **支持异步函数**：从 Ruby 同步调用 JS 异步函数，Ruby 调用会阻塞直到 JS 函数resolve。 3. **使用 npm 模块**：通过 `require` 或 `import` 加载 npm 模块。 4. **动态导入 ES 模块**：支持动态导入 ES 模块。 5. **定义 JS 常量**：可以在 Ruby 类中定义 JS 常量。 6. **初始化时执行自定义 JS**：可以在类初始化时执行自定义 JS 脚本。 7. **继承**：子类可以继承父类的函数、常量、依赖和脚本，但函数可以被重写。 8. **延迟函数定义**：函数代码可以在对象实例化时生成，而非类定义时。 **安装**：在 Gemfile 中添加 `gem 'nodo'` 并确保 Node.js 已安装。

文章摘要

这篇文章讨论了C++标准库（STL）的优缺点，特别是编译时间长和因严格向后兼容导致的代码可读性和性能问题。作者认为许多对C++的批评实际上源于STL，并提出可以自行构建标准库（命名为pystd），借鉴Python标准库的设计。作者展示了如何从零开始实现一个简单版本的标准库，并通过一个文本处理应用演示其功能。与STL版本相比，pystd的编译时间更短，可执行文件更小，运行速度相近。作者还提出了通过每年更新命名空间来实现ABI稳定性及其灵活性的设计思路。所有代码在Github上开源，并提供了禁用STL和实现基础功能的详细步骤。

The Hartlib Papers

作者: sebg | 评分: 20 | 评论数: 2 | 发布时间: 2025-03-25 10:39
文章摘要

《哈特利布文件》项目源于17世纪学者萨缪尔·哈特利布的愿景，他致力于记录人类所有知识并普及于世。他的大量信件手稿（超过25,000页）于20世纪60年代入藏大学图书馆。该项目在300年后通过电子版实现其理想，包含全部手稿的全文本转录和图像。1996年和2002年分别出版了CD-ROM版，最新在线版提供免费访问。该项目由谢菲尔德大学人文研究所开发，并由迈克尔·格林格拉斯等人负责。

评论摘要
主要讨论点：数字档案的价值及其在不同领域的应用 不同观点： • [peterldowns] 认为数字人文（Digital Humanities）和自然语言处理（NLP）以及更广泛的计算机科学领域（如AI、LLM、GenAI等）之间的交集很少。他指出，数字人文领域主要由图书馆员和档案管理员组成，他们拥有大量有趣的材料，并希望使其更易于访问。他建议，如果有人对这类项目感兴趣，可以直接联系这些专业人士。 • [axus] 的评论更关注具体内容，指出档案中的第一个条目以对政府变更的辞职开始，暗示数字档案中具体历史内容的潜在价值和意义。 补充讨论： • [peterldowns] 强调了跨学科合作的可能性和必要性，特别是数字人文与NLP、AI等领域的合作潜力。 • [axus] 的评论则将焦点转向了数字档案中的具体历史事件和内容，提示了档案在记录历史变迁中的作用。 • 争议的焦点可能在于不同领域对数字档案的关注点不同：一方面是技术与人文的结合，另一方面是档案内容的实际历史和文化价值。
