The Lone Lisp Heap

作者: stevekemp | 评分: 87 | 评论数: 8 | 发布时间: 2026-05-28 18:16
文章摘要

这篇文章介绍了lone这个Lisp解释器的内存管理实现。作者从零开始构建了一个自定义内存分配器，因为lone使用独立C编写，没有标准库的malloc。 核心思路是： 1. 用结构体描述内存块（位置、大小、是否空闲） 2. 通过链表连接所有内存块 3. 分配时遍历链表找到合适的空闲块 4. 将大块切分成所需大小和剩余部分 5. 释放时标记为空闲，并尝试合并相邻空闲块 文章展示了从最简单的单块管理到支持动态分配的完整演进过程，体现了作者边学习边实现的开发方式。整个语言和虚拟机都是在实践中逐步成长起来的。

评论摘要
主要讨论点：关于用C语言从零实现Lisp解释器的技术文章 不同观点： • **民族自豪感**：巴西开发者为同胞的技术成就感到骄傲，将其与José Valim开发Elixir相提并论，表达了对这类底层项目的向往 • **经验主义观点**：开发语言和运行时能学到很多，但最终会意识到可以做得更好——暗示这是一个迭代改进的过程 • **实现细节回顾**：有开发者分享了类似经历，在Lisp/Prolog系统中用链表页面替代数组索引以提升性能 • **术语争议**："freestanding"一词的使用不标准。标准定义指在裸机上运行无OS环境，但作者实际使用了Linux的mmap/mremap系统调用，并非真正的freestanding环境 • **技术疑问**：有人质疑基于名称判断应该使用heap的假设是否正确 补充讨论：多数评论对技术文章本身持正面态度，认为这类非热门技术的深度内容很有价值。争议焦点在于"freestanding C"的定义——作者声称不用malloc/libc，但实际依赖Linux系统调用。

Using Tailscale with an OrbStack VM on macOS

作者: highpost | 评分: 66 | 评论数: 7 | 发布时间: 2026-05-25 22:10
文章摘要

这篇文章介绍了如何在 macOS 上使用 OrbStack 虚拟机配合 Tailscale 构建开发环境。主要步骤包括：通过 cloud-init 配置 Ubuntu VM，使用 Tailscale 认证密钥将 VM 加入 tailnet 网络，并启用 Tailscale SSH 实现远程访问。文章特别说明了 macOS 沙箱限制下如何通过 Keychain 安全存储认证密钥，以及如何配置访问控制列表（ACL）和标签来管理权限。配置完成后，用户可以通过 MagicDNS 或本地代理从任何地方 SSH 连接到 VM，无需暴露主机端口，还能直接使用 git 等工具进行远程操作。

评论摘要
主要讨论点：OrbStack 与 Tailscale 结合使用的实践经验和安全考量 不同观点： • **OrbStack 优势派**：认为 OrbStack 是 macOS 上最好的容器/VM 集成方案，网络、文件共享、SSH 都很便捷，远胜 Docker Desktop 和 Podman Desktop • **便利性应用派**：利用 Tailscale + OrbStack 实现多环境隔离（工作/家庭双 tailnet、多仓库实例互不干扰）、远程访问开发环境、跨设备查看仪表板等实用场景 • **安全顾虑派**：指出 OrbStack 的便利性建立在宽松的安全模型上，其默认配置缺乏真正的文件系统隔离；Tailscale 在 OrbStack 中更多是便利工具而非硬安全隔离 补充讨论： • **权限继承问题**：VM 中的 Tailscale 会继承宿主机用户权限而非 VM 标签设备权限，需断开宿主机连接才能实现预期的访问控制 • **最佳实践**：开发者们普遍采用 Docker/OrbStack 环境 + Tailscale sidecar 模式进行开发，便于环境复制和端口管理 • **近期改进**：OrbStack 最近才添加真正的文件系统隔离选项，之前的沙箱效果不理想
