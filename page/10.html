C and C++ prioritize performance over correctness (2023)

作者: endorphine | 评分: 85 | 评论数: 15 | 发布时间: 2025-03-28 20:26
文章摘要

Russ Cox的文章讨论了C和C++中“未定义行为”的问题，指出这些语言为了性能而牺牲了正确性。C89标准引入了未定义行为的概念，涵盖了从明显的错误（如访问已释放的内存）到不同实现间处理差异（如未初始化变量、有符号整数溢出等）。这种未定义行为导致现代编译器可能会生成意外的代码，例如删除包含未初始化变量的循环。整数溢出也被视为未定义行为，编译器可以随意优化，甚至删除检查溢出的代码，因为标准允许任何处理方式。Cox指出，C和C++过于注重性能，导致程序的正确性难以保证，建议开发者在编译时启用所有警告并修复它们。

评论摘要
主要讨论点：C/C++中的未定义行为（UB）及其在性能和正确性之间的权衡 不同观点： • jurschreuder认为C++是中级语言，不应追求对初学者的友好性。他批评现代年轻人过于娇气，并指出C++从未导致他的电脑崩溃或损坏。 • nine_k通过一个笑话暗示，即使某些操作非常快，但如果结果不正确，速度快并没有实际意义。 • meling引用一句话来表达对快速执行的关注，同时也暗示需要谨慎处理关键部分，例如确保O2优化和/或LTCG在Windows上的启用。 • dang提到C和C++在性能和正确性之间优先考虑性能，并提供了一个讨论链接，该链接有大量评论。 • uecker支持C语言中未定义行为的存在，认为捕捉有符号溢出很容易，而无符号回绕会导致难以发现的错误。 • gavinhoward完全同意uecker的观点，并提供了一篇文章链接以支持其立场。 • gblargg对文章中的无限循环例子提出质疑，认为如果变量不是volatile，编译器可以合并循环，因为程序无法区分。 • indigoabstract提出一种比喻，认为某些高性能工具（如Ferraris）应该更像Volvos，即更注重安全性。同时，强调在关键部分需要快速执行。 • agentultra指出如果没有编写规范，任何程序都可以被认为是足够的，并质疑C23标准中未重新审视未定义行为的原因，质疑是出于实用主义还是教条。 • pcwalton提到未定义行为在算术溢出中的最强论据，解释了C文本书中常见的迭代数组方式存在的问题，并指出该问题在C++迭代器或使用指针宽度索引的其他语言中不存在。 • ajross认为C/C++起源于计算资源有限的年代，正确性并不是首要考虑。他解释了ANSI委员会在定义未定义行为时的历史背景和现实考虑。 • dataflow认为C/C++给予未定义行为过多自由，而不是约束有效行为以最大化性能。他认为只需将未定义行为定义为产生未定义结果即可。 • netbioserror对比了C/C++和Rust以及其他新语言，指出C/C++中写出正确代码困难，而新语言通过各种特性使写出正确代码更容易且性能损失较小。 • on_the_train以幽默方式评论，暗示对C++的批评是日常现象。 • Brian_K_White认为C/C++让程序员成为正确性的最终定义者，优先考虑程序员控制而非编译器/运行时控制。 补充讨论： • 关于未定义行为的历史背景和现实需求。 • 不同编程语言在性能和正确性之间的权衡及其对开发的影响。 • C/C++中未定义行为的具体例子及其在编译器优化中的影响。 • 新语言在正确性和性能方面的优势及其对开发者友好的特性。 争议焦点： • C/C++中未定义行为的存在是否合理，尤其是在性能和正确性之间的权衡上。 • 是否应该重新审视和修改C/C++标准中关于未定义行为的规定。 • 不同语言在开发实践中的优劣比较，特别是C/C++与其他新兴语言的对比。

Public secrets exposure leads to supply chain attack on GitHub CodeQL

作者: cyberbender | 评分: 292 | 评论数: 9 | 发布时间: 2025-03-30 19:54
文章摘要

本文介绍了GitHub CodeQL潜在供应链攻击的发现过程。攻击始于一个公开暴露的秘密，有效期仅1.022秒，但足以让攻击者在大多数使用CodeQL的仓库中执行代码。攻击可能导致： 1. 泄露私有仓库的源代码，损害知识产权。 2. 窃取GitHub Actions中的凭据，进一步发动供应链攻击。 3. 在运行CodeQL的内部基础设施上执行代码。 4. 危害使用CodeQL和GitHub Actions缓存的仓库中的工作流凭据。 研究人员通过自建的秘密扫描工具发现了这一问题，并确认了潜在的供应链攻击风险。尽管攻击手段类似于近期发生的tj-actions/changed-files攻击，但GitHub尚未发现其平台或系统受到危害的证据。CodeQL是GitHub的代码分析引擎，被数十万仓库信任使用。

评论摘要
主要讨论点：GitHub Actions的安全性、权限管理和性能问题 不同观点： • Sytten认为，GitHub如果推出不可变 actions，可以解决目前 GitHub Actions (GHA) 上大部分的安全问题，尤其是攻击风险。他提到这一方案本可以防止很多当前出现的灾难性问题，并对 GitHub 尚未推出该功能表示失望。 • nyrikki 关注临时 token 的权限问题，质疑为什么这些 token 可以创建新部署和生成工件证明。虽然 GitHub 修复时禁用了调试日志，但 nyrikki 认为更重要的是修改临时 token 的权限以适应代码分析引擎的需求。 • ashishb 提出，CI（持续集成）和 CD（持续交付）应完全分离，以防止 CI 环境被攻破后导致 CD 相关的 token 泄露。这表明了对现有架构安全性的担忧。 • junto 对 GitHub 的响应速度表示赞赏，认为其快速反应值得肯定。 • helsinki 的评论更多是个人感慨，与技术讨论无直接关系，提到对域名所有权的个人兴趣。 • udev4096 认为使用公共 GitHub Actions 容易引发安全问题，建议自行托管 CI 系统，例如使用 woodpecker、Circle、Travis、GitLab 等工具，以获得更高的安全性。 • ryao 指出，在 OpenZFS 的 PR 中使用 CodeQL 并未造成问题，因为其代码并非秘密，表明在某些场景下，GitHub Actions 的安全问题可能并不严重。 • atxtechbro 简单询问问题是否已经修复，未提供进一步的论据或观点。 • bloqs 抱怨网站的性能问题，指出页面滚动时表现很差，涉及用户体验。 补充讨论： • 安全问题集中在临时 token 的权限管理和 GitHub Actions 的不可变性，部分用户认为 GitHub 应该采取更多措施来防止潜在攻击。 • 有人建议将 CI 和 CD 环境分离，以增强安全性，减少因 CI 被攻破而带来的风险。 • 对 GitHub 的响应速度表示肯定，但也有对其性能的批评。 • 针对使用公共 GitHub Actions 的风险，部分用户建议自行托管 CI 系统以提高安全性。

Oka.wiki

作者: jjmarr | 评分: 105 | 评论数: 9 | 发布时间: 2025-03-30 23:59
文章摘要

Open Knowledge Association (OKA) 是一家非营利组织，旨在通过提供月度津贴资助全职贡献者和翻译者，改善Wikipedia及其他开放平台的免费内容。OKA优先支持能产生最大影响的工作，特别关注代表性不足的国家以减少系统性偏见。其流程公开透明，自由撰稿人拥有高度自主权。OKA已创建2,200多篇Wikipedia新文章，年浏览量达800万次。组织主要通过翻译现有内容而非创建新内容来实现高影响力，使用机器学习工具减少手动工作，专注于英语、西班牙语和葡萄牙语 Wikipedia。资金主要来自个人捐款，也接受其他慈善机构、政府和公司的捐赠，但不允许影响编辑内容。

评论摘要
主要讨论点：Wikipedia和Oka等平台上的编辑付费、内容偏见以及资金透明度问题 不同观点： • [jjmarr] Wikimedia基金会不直接支付编辑者报酬，但Oka.wiki作为非营利组织，通过资助编辑者进行文章翻译。jjmarr列举了Oka资助的三篇英文文章，以展示其成果。 • [ahmedfromtunis] 认为即使编辑者保持客观，他们的工作仍可能产生偏见。例如，如果两家公司竞争某一标准的广泛采用，其中一家公司可以支付编辑者撰写详尽的文章，即使内容客观，也可能影响更多人选择被更好记录的选项。这种偏见难以完全避免。 • [stevefan1999] 质疑Oka是否真的能避免系统性偏见，即使它声称透明公开。stevefan1999将Oka视为一种政治团体，认为即使其目标与公众价值观一致，也需要警惕“谁来监督监督者”的问题。 • [peanutz454] 对Wikipedia的资金使用提出批评，认为其预算庞大，但内容质量不如过去的MS Encarta，且主要依靠志愿者贡献。peanutz454建议Wikipedia应该开发类似Encarta的多媒体内容，以提高教育价值。 • [seydor] 担心Wikipedia允许这种资助模式可能会导致“官方化的草根营销”（astroturfing）现象，影响平台的中立性。 • [chasing] 强调如果平台要保持开放性，必须明确列出捐赠者和捐赠金额，以确保透明度。 • [jon8888] 简单指出，这种资助模式揭示了偏见的来源，暗示付费编辑可能带来内容偏见。 补充讨论： - 评论中多次提到内容偏见的问题，无论是否涉及付费编辑，偏见都可能存在，且难以完全消除。 - 对Wikipedia的高预算和员工数量是否合理提出质疑，有人认为其资金使用不够高效，尤其是在提升内容质量方面。 - 透明度和监督是另一个讨论重点，特别是如何确保平台的中立性和资金使用的合理性。 争议焦点： - Oka等资助平台是否能真正避免偏见，确保内容中立。 - Wikipedia的高预算和员工数量是否合理，以及其资金使用的透明度。
