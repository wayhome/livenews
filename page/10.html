Lines of code got a better publicist

作者: RyeCombinator | 评分: 424 | 评论数: 72 | 发布时间: 2026-06-11 12:26
文章摘要

这篇文章批评AI行业用代码生成量来衡量AI工具的价值。作者指出，Google、Anthropic等公司宣称75-80%的代码由AI生成，但这只是"代码行数"的新包装——我们早已知道代码量是糟糕的开发者衡量指标。 早期研究声称AI让开发者快55%，但后续研究结果矛盾：有的显示效率提升26%，有的显示反而慢19%（且开发者自己感觉变快了）。企业层面，69%公司使用AI但90%未见生产力提升。 作者担心这些"虚荣指标"会影响预算和人员决策，呼吁关注真正的业务成果而非代码生成量。

评论摘要
主要讨论点：AI代码生成工具是否真正提高了开发效率,以及用代码行数(LoC)作为生产力指标的问题 不同观点: • **AI炒作批判派**:认为公司夸大AI生产力,实际是用AI作借口裁员或过度营销。OpenAI博客强调百万行代码却不说产品价值,微软提出"每月百万行代码"的目标像讽刺。这些都是bullshit,为了讨好投资者 • **度量标准质疑派**:指出行业花了几十年说明LoC不能衡量生产力,因为重要的是代码质量而非数量。AI时代却又回到用LoC、ticket数等简单指标,这是倒退和尴尬。应将LoC视为"成本"而非资产 • **实际影响怀疑派**:认为AI可能加快开发速度,但无法解决根本问题——很多项目最终不上线,官僚层级依然存在。公司需要从上到下重建才能发挥AI价值,这不太可能发生 • **商业逻辑批判派**:质疑"AI让人更高效所以裁员"的逻辑——这说明公司不想更高效,只想用更少的人维持同样产出。还有人指出这是短视的逐利行为 补充讨论:部分评论注意到现实中AI被用来生成大量低质量单元测试(300行测试对应20行代码修改),以及有CEO开始意识到按行付费的代码并不能转化为利润,态度正在转变。

Software is made between commits

作者: jeremy_k | 评分: 308 | 评论数: 70 | 发布时间: 2026-06-11 16:28
文章摘要

Zed团队推出DeltaDB——一种新型版本控制系统，用于取代传统的Git pull request工作流。DeltaDB将每个操作（而非仅提交）记录为细粒度的delta，使代码与生成它的AI对话实时关联。引用锚定在delta而非行号上，代码变更时不会失效。支持多人和多个AI agent同时编辑同一文件，无需等待commit即可协作。团队认为软件现在形成于对话而非提交中，DeltaDB正是为此设计的版本控制工具，几周后将推出测试版。

评论摘要
主要讨论点：Zed 编辑器推出的 DeltaDB 功能（捕获提交之间的所有开发过程）引发的争议 不同观点： • **支持精心整理的提交历史**（Lindby, Xotic007）：提交之间的过程是"混乱的汤"，应该通过 git rebase 创建小而原子化的提交来讲述清晰的故事。中间的试错和删除的代码本应被丢弃，保留所有垃圾反而没有价值。 • **Git 已足够强大**（WorldMaker, chrishill89）：Git 本身可以处理频繁的自动提交，通过 `--first-parent` 等工具就能区分"顶层提交"和"对话式提交"。代理工具不需要超越 Git 的新方案，现有工具配合项目管理系统已经足够。 • **隐私和思考过程的保护**（tomjakubowski, jchw, flerchin）：编码过程是私人的思考过程，不应被序列化和公开访问。这种监控式的记录令人不适，代码的价值已经体现在最终提交中，过程中的失误不需要展示。还提到研究表明这可能影响创造力。 • **工具整合的实用性问题**（jchw, OtherShrezzing）：开发者使用多种工具，不可能全部整合到一个数据库中。多家公司提出类似方案，但都没有给出令人信服的价值主张。 补充讨论：有人指出 Google 的 citc 系统已实践类似方案十年；有人担忧开发者监控问题；有人讽刺开发者愿意为 LLM 写文档却不愿为团队写；还有人认为好的代码库应该自解释，不需要额外的过程记录。

阿根廷开发者Dante Leoncini成功让1998年的《半条命》游戏在2007年的诺基亚N95手机上以30帧运行，并添加了鼠标键盘支持。N95搭载332 MHz双核ARM处理器和64MB内存，运行Symbian系统。此前他已在该手机上运行过《雷神之锤3》、《古惑狼》等游戏和多个模拟器。虽然仍有卡顿问题，但开发者已找到原因并在修复中。这项移植需要为Symbian系统原生构建游戏，而非模拟PC版本。

评论摘要
主要讨论点：在诺基亚N95上移植《半条命》游戏引发的怀旧讨论 不同观点： • **对技术成就的赞叹**：jonhohle感叹现在的超级计算机手机反而感觉很慢，对比当年羸弱硬件却能实现强大功能；porphyra指出当年手机芯片落后PC十年，现在单核性能已基本持平 • **对诺基亚N95/Symbian系统的怀念**：ljf认为N95接近完美手机，遗憾Symbian没有建立好的应用商店；p4bl0回忆N95在iPhone发布前就具备浏览器等功能，Symbian系统很优秀；totetsu分享2008年在Symbian手机上玩Quake的经历 • **对中国灰色市场翻新的惊讶**：kotaKat发现中国市场用旧主板和新配件重组"全新"N95等诺基亚手机，甚至N900也能翻新，收到的手机里还有2025年中国移动的测试短信 • **对Tom's Hardware网站体验的不满**：Reefersleep和stego-tech都抱怨该网站广告泛滥，甚至强制下载文件，表示不会再访问 补充讨论：jamesfinlayson提到Valve尚未开源GoldSource引擎；M95D分享了基于mbedtls的Symbian TLS补丁；socalgal2询问类似半条命的游戏推荐
