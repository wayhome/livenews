“ZLinq”, a Zero-Allocation LINQ Library for .NET

作者: cempaka | 评分: 254 | 评论数: 15 | 发布时间: 2025-05-20 22:29
文章摘要

"ZLinq" 是一个为 .NET 设计的零分配 LINQ 库，由 Yoshifumi Kawai 开发，旨在通过使用结构体和泛型实现无内存分配。该库包括 LINQ to Span、LINQ to SIMD、LINQ to Tree（支持 FileSystem、JSON、GameObject 等），并提供源代码生成器以替代任意类型。它支持多平台，如 .NET Standard 2.0、Unity 和 Godot，且在 GitHub 上已获得超过 2000 星。 ZLinq 实现了 .NET 10 中所有方法的 100% 覆盖，具有 99% 的行为兼容性，并通过 SIMD 支持等优化在性能上超越传统 LINQ。在基准测试中，ZLinq 在链式调用中保持零分配，而普通 LINQ 分配会随方法增加而上升。 使用 ZLinq 只需调用 `AsValueEnumerable()`，并兼容所有 .NET 版本。此外，ZLinq 提供源代码生成器，可选择性消除对 `AsValueEnumerable()` 的需求，便于集成。 总体而言，ZLinq 在大多数实际场景中表现出色，尤其在减少内存分配和提高性能方面具有显著优势。

主要讨论点：围绕.NET中LINQ和ZLinq的性能优化及其应用的讨论 不同观点： • **支持LINQ优化的观点**： - zamalek认为，理论上.NET 10应该能解决LINQ的性能问题，其新特性基本上都是关于这方面的。同时，C#将LINQ视为一种契约，只要方法名和签名正确，LINQ语法就能自动生效。 - jasonthorsness表示，在生产环境中，由于分配问题，他们通常避免在性能敏感的路径中使用LINQ，但重新实现类似功能既费时又容易出错。他赞赏这种优化方法，并认为如果更多语言有类似的功能会更好。 • **实用性和可操作性的怀疑**： - bigmattystyles认为，这种优化超出了普通开发者的能力范围，虽然能理解代码，但很难独立实现。 - martijn_himself询问这种优化对普通.NET开发者的实际意义，以及是否需要在Web应用中用ZLinq替换LINQ。 • **技术细节的争议**： - KallDrexx质疑ZLinq如何做到零分配，因为使用`Func`会产生引用类型分配。 - torginus指出，ZLinq未能解决如`First(x=>x.Name==myPersonName)`中捕获变量导致的分配问题，质疑其广告效应。 • **对.NET生态的建议**： - incoming1211建议将这些改进贡献回.NET本身。 - garganzol认为，.NET运行时或JIT应优化小内存分配，优先使用栈而不是堆，并指出.NET 10正在朝这个方向努力。 补充讨论： • **对LINQ技术基础的探讨**： - HexDecOctBin询问C#有哪些特性使得LINQ成为可能，而其他语言则不行。 • **与其他语言特性的比较**： - srean提到C++中的表达式模板，并比较了其与LINQ的异同，强调了C++模板调试困难的问题。 • **对LINQ分配问题的基本疑问**： - ImHereToVote直接询问LINQ为何会产生内存分配。 争议的焦点： • 争议的焦点主要在于ZLinq是否真正实现了零分配，特别是在处理变量捕获和lambda表达式时。此外，关于这些优化是否应整合进.NET本身也是讨论的一个热点。
