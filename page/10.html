Show HN: AG-UI Protocol – Bring Agents into Frontend Applications

作者: swiftlyTyped | 评分: 15 | 评论数: 5 | 发布时间: 2025-05-13 16:09
文章摘要

AG-UI 是一个开源、轻量级、基于事件的协议，旨在标准化 AI 代理与前端应用程序的交互。它定义了16种标准事件类型，支持多种事件传输方式（如SSE、WebSockets等），并提供了灵活的中间件层以确保跨环境兼容性。AG-UI 允许双向状态同步、实时上下文增强、生成式 UI 及更多功能，兼容多种流行代理框架如 LangGraph、Mastra、CrewAI 等。该协议提供了参考实现和客户端库，帮助开发者快速构建支持代理功能的应用。AG-UI 通过与社区和多个框架合作，确保其实用性和广泛适用性。更多信息和示例可在 ag-ui.com 查看。

评论摘要
主要讨论点：AG-UI协议的发布及其在AI代理与前端应用交互中的作用 不同观点： • [swiftlyTyped] 介绍了AG-UI协议，强调其作为一个开放、轻量级、基于事件的协议，旨在标准化AI代理如何与前端应用连接。该协议支持多种事件传输方式（如SSE, WebSockets, webhooks）并定义了16种标准事件类型，用于常见的代理-用户交互场景。AG-UI的发布伴随着与LangChain, Mastra, CrewAI等项目的集成，并且未来还会有更多合作。 • [dhorthy] 表示曾考虑过类似概念，称之为"MWP - model workload protocol"。该概念旨在通过客户端无关的方式（如SMS, WhatsApp, 内嵌应用, React组件）展示代理的工作状态，包括工作、思考、调用工具、出错、需要人工输入或批准等状态。 • [aatd86] 对AG-UI的具体用途存在疑问，不确定该协议是否用于提高可访问性或是一种新的UI构建范式。 • [Arindam1729] 对AG-UI表示兴奋，并计划尝试使用该协议，尤其是在MCP之后寻找新的解决方案。 • [nathan_tarbert] 对AG-UI表示高度赞赏，认为该协议将解决许多代理开发者面临的问题，并对其未来充满期待。 补充讨论： • AG-UI协议的定位：在代理协议生态中，AG-UI专注于代理与人类用户在应用中的交互，而MCP负责代理与工具之间的通信，A2A/ACP则负责代理与代理之间的通信。 • 社区反应：AG-UI在发布后受到了积极的反馈，并且已经计划了工作组会议以进一步扩展和指导该协议的发展方向。 • 协议的实际应用场景：包括但不限于代理状态展示、错误处理、人工输入和批准等，涵盖了多种代理与用户交互的需求。 • 未来发展：AG-UI不仅有初步的集成伙伴，还计划与其他项目展开更多合作，显示出其在代理-用户交互领域的广泛应用潜力。

Can you trust that permission pop-up on macOS?

作者: nmgycombinator | 评分: 280 | 评论数: 21 | 发布时间: 2025-05-12 18:26
文章摘要

本文讨论了Mac电脑上新发现并修复的一个安全漏洞（CVE-2025-31250），该漏洞允许应用程序A伪造权限提示，使其看似来自应用程序B，而用户的同意响应却应用于应用程序C。此漏洞存在于macOS的TCC（隐私权限控制）系统中，未修复前，任何能够发送XPC消息到tccd进程的应用都可能利用此漏洞。文章还提到Apple Events这一古老的进程间通信技术，虽然源自1993年的Classic Mac OS时代，但至今仍用于macOS的自动化操作。自macOS Mojave 10.14起，发送Apple Events需要用户通过TCC授权，这与该漏洞的机制相关。修复前，攻击者可借此绕过权限系统，进行潜在的恶意操作。

评论摘要
主要讨论点：macOS的安全性和权限系统的有效性及用户体验问题 不同观点： • [xp84] 认为macOS频繁弹出要求输入管理员密码的对话框是一个糟糕的设计，容易被恶意软件模仿，建议采用其他方式（如菜单栏图标或像Windows一样的安全屏幕）来替代。 • [cypherpunks01] 建议通过将应用安装在用户目录下并使用非管理员账户来减少权限请求的干扰，并提到Pareto Security应用推荐这种做法。 • [nmgycombinator] 讨论了macOS某些版本中未修补的漏洞问题，并对Apple未在所有发布版本中包含补丁表示困惑。 • [kristel100] 提到“权限疲劳”现象，用户习惯性点击“允许”以完成工作，建议采用分层的信任模型而不是二元提示。 • [muppetman] 通过对比苹果曾经的广告嘲讽Windows Vista的权限问题，指出自己的Mac现在也有类似甚至更严重的问题。 • [Alex_001] 认为macOS的TCC系统（隐私保护机制）虽然看似坚固，但实际上可能通过数据库操作绕过，提出需要重新思考权限信任的执行方式。 • [nottorp] 表示自己成功拒绝了Mac OS弹出的Chrome访问蓝牙的请求，认为权限系统有时是有效的。 • [lapcat] 认为TCC系统从一开始就是一个“纸牌屋”，只对合法开发者造成障碍，却无法阻止恶意软件，并质疑Apple工程师对技术的理解。 • [sefrost] 提到Slack在Mac上反复弹出要求安装helper tool的提示，IT部门也无法解释，担心存在被利用的风险。 • [silvestrov] 指出Apple花费了一年时间才发布某个漏洞的补丁，认为时间过长。 • [pier25] 提到Adobe Creative Cloud即使在系统设置中禁止后台进程仍会运行，质疑其行为。 • [commandersaki] 赞赏某研究人员的成果和演示。 • [Jerry2] 关心研究人员是否因其工作获得了奖励。 • [zoomTo125] 认为Apple花费近一年时间发布补丁，令人失望，并对其他厂商的表现更加不抱希望。 补充讨论： • 争议焦点在于macOS权限系统的安全性和用户体验之间的平衡问题。一些用户认为频繁的权限提示不仅打扰工作，还可能导致用户忽视真正的安全威胁（如“权限疲劳”现象）。 • 另一个值得注意的点是Apple在修补漏洞方面的速度和效率问题，有用户认为其反应较慢，导致系统安全风险增加。 • 讨论中也涉及了具体操作建议，如通过将应用安装在用户目录下和使用非管理员账户来减少权限请求干扰，并提供了Pareto Security应用的参考。

Wtfis: Passive hostname, domain and IP lookup tool for non-robots

作者: todsacerdoti | 评分: 100 | 评论数: 11 | 发布时间: 2025-05-12 22:15
文章摘要

"wtfis" 是一个被动的主机名、域名和IP查询工具，专为人类易读而设计。它通过多个OSINT服务收集信息，并尽量减少API调用以避免达到免费 tier 的限额。主要功能包括： 1. 使用 Virustotal 作为主要信息源，获取主机名、IP的最新分析数据、信誉评分、流行度排名和分类等。 2. 可选使用 IP2Whois 获取更高质量的 whois 数据。 3. 使用 IPWhois 获取IP的地理位置和ASN信息。 4. 通过 Shodan 获取开放端口、操作系统和标签等信息。 5. 使用 Greynoise 判断IP是否为常规扫描或商业应用。 6. 通过 URLhaus 和 AbuseIPDB 查询是否为恶意URL或IP。 安装通过 `pip install wtfis` 或 `brew install wtfis`，配置需要设置多个API密钥。使用命令 `wtfis [选项] 实体` 查询信息。
