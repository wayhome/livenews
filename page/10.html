Remote Prompt Injection in Gitlab Duo Leads to Source Code Theft

作者: chillax | 评分: 208 | 评论数: 10 | 发布时间: 2025-05-23 07:12
文章摘要

本文介绍了Legit研究团队在GitLab Duo中发现的远程提示注入漏洞。该漏洞允许攻击者通过在项目不同位置（如合并请求、提交信息、问题描述和源代码）隐藏恶意指令，窃取私有项目的源代码，操纵代码建议，甚至泄露未公开的零日漏洞。攻击者还可以利用该漏洞进行HTML注入，将恶意URL或内容注入页面，控制页面部分元素，发起网络攻击。GitLab已修复此问题，但该案例展示了AI助手在处理用户输入时面临的安全挑战。

评论摘要
主要讨论点：围绕LLM（大型语言模型）和相关安全问题的讨论，包括 prompt injection、数据泄露、GitLab Duo 的安全隐患等。 不同观点： • [cedws] 认为在 prompt injection 问题解决之前，不会将 LLM 集成到任何工具中，例如 MCPs、IDEs、agents 等，而是坚持使用简单的 prompt 框，手动处理输出。 • [wunderwuzzi23] 赞扬了对数据泄露问题的关注，指出通过不受信任的第三方服务器泄露数据是常见的 AI 安全问题，并提到曾发现 GitHub Copilot Chat 有类似漏洞，暗示大厂在安全问题上存在疏漏。 • [mdaniel] 对 GitLab 使用 Duo 系统用户的方式表示不满，认为个人访问令牌或为 Duo 单独创建令牌是比赋予 LLM 读取所有仓库权限更好的做法。 • [nusl] 对 GitLab 的修复措施表示怀疑，认为其解决方案不太可靠。 • [Kholin] 提出如果 Duo 是 web 应用，设置合适的内容安全策略（CSP）是否可以防止此类安全问题，并提供了一个参考链接。 • [benl_c] 建议通过嵌入式提示（"prompt medicine"）来提高 LLM 的安全性，并提供了一个具体项目（csiro/stdm）作为示例，强调安全和用户知情同意。 • [aestetix] 以调侃的方式提问 GitLab Duo 是否能运行 Doom，暗示对 LLM 或相关系统的权限和安全性存在担忧。 • [d0100] 担心即使修复了某些漏洞，如果 gitlab.com 上的其他 URL 存在漏洞（如开放重定向），问题仍可能再次出现。 • [tonyhart7] 认为 LLM 生成代码的过程中可能会引入许多安全漏洞，指出由于许多程序员本身在安全问题上表现不佳，输入到 LLM 中的数据也可能不安全，导致问题加剧。 补充讨论： • 评论中多次提到 LLM 和相关系统在代码安全和数据泄露方面的潜在问题，特别是当 LLM 被集成到开发工具和生产环境时，安全风险更加突出。 • 争议的焦点在于 LLM 的安全性、厂商的修复措施是否足够有效，以及如何通过技术手段（如 CSP）或流程改进（如个人访问令牌）来缓解这些风险。

Jjui – A Nice TUI for Jujutsu

作者: Curiositry | 评分: 219 | 评论数: 9 | 发布时间: 2025-05-26 02:16
文章摘要

Jujutsu UI (jjui) 是一个为 Jujutsu 版本控制系统设计的终端用户界面（TUI）。主要功能包括通过自动补全更改 revset、进行 rebase 操作、压缩修订、查看修订详情、书签管理、操作日志查看和预览修订内容等。用户可以通过快捷键执行各种操作，如分割、恢复、编辑修订，以及查看 diff 等。支持通过 Homebrew、Archlinux、Nix 和源码安装。最低支持的 Jujutsu 版本为 v0.21。项目采用 MIT 许可证，欢迎贡献代码。

文章介绍了一个用于APT的SomewhatMaxSAT求解器及其最新改进。求解器保护手动安装的软件包不被移除（视为事实），而自动安装的软件包则成为可选的单元子句，在常规单元传播后解决。文章讨论了在允许移除手动安装包时出现的问题：求解器错误地移除了不必要移除的包。为解决此问题，作者提出在假设所有可选子句前，先假设它们全部成立，再根据需要撤销不合适的假设。 文章详细描述了求解器的操作步骤，包括事实入队、假设可选文字、传播、回溯等过程，并通过伪代码展示了解决冲突的流程。虽然该方法不是严格的MaxSAT，但实验表明它在依赖求解器中表现良好，且避免了全局最大化的计算开销。进一步的改进仍在探索中。
