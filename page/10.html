PostgreSQL and the OOM killer: Why we use strict memory overcommit

作者: furkansahin | 评分: 189 | 评论数: 18 | 发布时间: 2026-07-03 13:00
文章摘要

这篇文章解释了为什么Ubicloud在管理PostgreSQL服务时始终使用严格内存过度分配(strict memory overcommit)配置。 **核心问题**：Linux系统允许进程分配超过物理内存的虚拟内存，当内存耗尽时，OOM Killer会杀死进程释放内存。对普通进程来说这不是问题，但PostgreSQL无法容忍这种情况。 **原因**：PostgreSQL的主进程(postmaster)为每个连接fork出后端进程，这些进程共享内存段（包括缓冲区、WAL缓冲、锁表等）。如果OOM Killer杀死某个后端进程，共享内存可能处于不一致状态，导致数据损坏风险。因此，当检测到任何子进程被杀时，postmaster会终止所有后端进程。 **解决方案**：使用严格内存过度分配可以在内存分配时就失败，避免后续的灾难性OOM kills。文章还讨论了如何设置合理的内存限制阈值。

评论摘要
主要讨论点：Linux内存过量分配（overcommit）机制的配置选择与问题 不同观点： • **支持严格模式（禁用overcommit）**：Ubicloud在生产环境使用严格模式运行Postgres；部分用户禁用overcommit以避免程序被OOM killer随机杀死；认为Windows不做overcommit的设计更合理 • **反对严格模式**：man8alexd认为严格模式是过时、不精确且易出错的方案，会因文件缓存动态分配导致OOM或浪费内存；mono442指出禁用会浪费RAM和磁盘空间；10000truths认为很多程序隐式依赖overcommit，不检查malloc失败 • **折中方案**：Bender建议保持mode 0但调整overcommit ratio和oom_score_adj；man8alexd推荐使用OOM Score Adjust这一现代方案；senderista认为成熟数据库应自行实现内存管理 • **架构建议**：otterley和leononame都认为应将数据库与应用分离部署，避免资源竞争 补充讨论：ralferoo深入分析了OOM killer对共享内存计算的逻辑缺陷，并提出了改进事务处理的技术方案；多位用户分享了Go应用、Postgres、云环境不使用Swap等实际踩坑经验。核心争议在于稳定性与资源利用率的权衡。

1990年代初，8人在亚利桑那州的"生物圈2号"密封结构中生活两年，试图在模拟地球生态系统中自给自足。实验遭遇氧气下降、二氧化碳上升、动物死亡等问题，当时被视为失败。然而如今专家认为它提供了宝贵的生态学和大气科学经验，证明了地球不可替代性。该设施现用于气候变化研究，成为理解地球系统的重要工具。

FlashAttention-4: Algorithm and Kernel Pipelining Co-Design

作者: skidrow | 评分: 3 | 评论数: 0 | 发布时间: 2026-07-04 22:35
文章摘要

FlashAttention-4 针对 Blackwell GPU 的硬件不对称扩展问题进行了算法和内核协同设计。现代加速器张量核心吞吐量增长远超共享内存带宽和特殊函数单元，导致注意力机制的性能瓶颈从矩阵乘法转向前向计算中的 softmax 指数运算和反向计算中的共享内存流量。 FlashAttention-4 通过以下创新解决这些瓶颈：新的流水线设计实现张量核心与其他操作的最大重叠；前向采用 FMA 单元的多项式近似模拟指数函数；反向利用张量内存存储中间结果并采用 2-CTA MMA 模式减少共享内存流量；新调度器优化负载均衡。 在 B200 上实现 1605 TFLOPs/s（71% 利用率），比 cuDNN 9.13 快 1.3 倍，比 Triton 快 2.7 倍。

评论摘要
**主要讨论点：** Reddit反垃圾机制的有效性与AI生成内容泛滥问题 **不同观点：** • **垃圾信息泛滥派**（leviathant, PUSH_AX）：认为Reddit上AI驱动的营销内容极其普遍且隐蔽，包括大公司如SCAYLE利用LLM制造虚假故事污染信息源。版主工具虽在改进但仍需人工处理，大量内容已是LLM生成。 • **系统怀疑派**（randysalami）：认为Reddit可能故意允许一定程度的操纵行为，既能虚增用户数，也能引导公共讨论方向，平衡各方利益。怀疑存在复杂的非公开机制。 • **技术细节派**（justcool393）：提供详细技术解释，说明Reddit删除机制的不同类型（spam、confirm spam、reinforce spam等）和历史演变，认为90%问题可用基础规则解决。 • **受害者派**（pedalpete, Terr_, felooboolooomba）：分享被shadowban的负面经历，申诉无果，感到系统不透明且容易误伤正常用户。 **补充讨论：** 多位用户注意到该帖子疑似重复出现在首页，引发对Reddit推荐算法的质疑。部分用户将此问题类比为早期邮件垃圾过滤，认为现在面临人类和AI双重挑战。
