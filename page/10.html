New Vulnerability in GitHub Copilot, Cursor: Hackers Can Weaponize Code Agents

作者: pseudolus | 评分: 224 | 评论数: 22 | 发布时间: 2025-04-14 00:51
文章摘要

Pillar Security研究人员发现了一种新的供应链攻击方式，称为“规则文件后门”。该方法通过在Cursor和GitHub Copilot等AI代码编辑器使用的配置文件中注入隐藏的恶意指令，悄无声息地危害AI生成的代码。利用隐藏的Unicode字符和复杂的规避技术，攻击者可以操纵AI插入绕过代码审查的恶意代码，使其对开发人员和安全团队不可见，从而在项目中传播。 与传统代码注入不同，这种攻击将AI本身武器化，使其成为攻击载体，把开发者的得力助手变成同谋，可能影响数百万终端用户。规则文件广泛共享、采用、信任且很少验证，成为理想的攻击目标。攻击者通过操纵规则文件中的上下文和隐藏字符，影响AI生成包含漏洞或后门的代码，且这种攻击具有持久性，能通过项目分叉传播，威胁供应链安全。

评论摘要
主要讨论点：GitHub调查中关于生成式AI编码工具的使用情况，及其潜在的安全问题和实际影响 不同观点： • DougBTX：质疑文章对调查数据的解读，认为文章夸大了企业对AI工具的实际支持程度。文章强调几乎所有开发者都在使用AI工具，但调查显示企业对AI工具的支持比例较低，尤其在不同国家之间存在差异。 • mrmattyboy：对将生成式AI称为“最信任的助手”表示讽刺，指出这些工具存在错误和遗忘细节的问题，暗示其并不可靠。 • tsimionescu：关注Unicode隐藏文本可能引发的安全攻击，但认为这不是AI本身的问题，而是文本文件隐藏数据的问题，解决该问题可以消除攻击风险。 • tobyhinloopen、markussss：批评页面滚动体验差，质疑开发者的设计决策。 • MadsRC：提出通过签名规则文件来缓解攻击的设想，但认为这并不能真正解决问题，因为LLM处理输入的方式使得隐藏指令仍然可能存在于源文件中。 • DrNosferatu：提供了一种查找可疑Unicode字符的脚本，并询问是否有改进空间。 • fjni：批评GitHub和Cursor对该问题的回应过于懒惰，认为提供安全编码环境是产品的一部分，不应由用户独自承担责任。 • lukaslalinsky：认为对AI生成代码的过度依赖会导致更多劣质代码进入生产环境，强调需要更多能读写代码的程序员。 • yair99dd：引用了一篇关于AI对齐问题的论文，暗示相关风险。 • AutoAPI：提到过往关于通过表情符号走私数据的讨论，暗示类似问题早已存在。 • Oras：认为Unicode隐藏文本攻击与前端提交密钥类似，企业已有工具可以检测漏洞和恶意代码。 • GenshoTikamura：提出“进步的每一单位都伴随着等量的麻烦”的观点，暗示技术进步伴随固有风险。 • gregwebs：询问是否有主动防御不可见Unicode攻击的方法。 • jdthedisciple：建议通过限制输入字符集来简单解决隐藏指令问题。 补充讨论： • 关于Unicode隐藏文本的安全漏洞是讨论的核心，参与者提出了多种技术解决方案和批评意见。 • 对生成式AI工具的可靠性和企业支持程度的质疑反映了开发者对该技术实际应用中的担忧。 • 对页面设计和用户体验的批评虽然与主讨论点无关，但也反映了用户对实际使用中细节的关注。
