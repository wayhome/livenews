Create space-saving clones on macOS with Python

作者: ingve | 评分: 18 | 评论数: 3 | 发布时间: 2025-08-03 17:27
文章摘要

这篇文章介绍了如何在macOS上使用Python创建节省空间的文件克隆。APFS文件系统支持一种称为“空间节省克隆”的功能，可以在不占用额外磁盘空间的情况下创建文件副本。与符号链接或硬链接不同，克隆文件是独立的，编辑一个副本不会影响其他副本。 文章讨论了克隆文件的优点，包括节省磁盘空间和速度更快。它还提供了在macOS上克隆文件的几种方法： 1. 使用Finder中的“复制”命令。 2. 在命令行使用`cp -c`命令。 3. 使用macOS的`clonefile()`系统调用。 对于Python开发者，文章展示了如何通过`subprocess`模块调用`cp -c`命令，以及如何使用`ctypes`模块调用`clonefile()`函数来实现文件克隆。实验表明，克隆文件在速度和空间效率上都优于直接复制文件。

评论摘要
主要讨论点：macOS 文件系统中使用文件克隆（clones）功能的相关问题及技术细节 不同观点： • [mikeyla85] 认为在使用 fclones 替换重复文件后，系统的可用空间显示出现问题，导致某些程序显示的可用空间不一致。这表明在实际操作中，文件克隆可能引发一些意外的系统问题，尤其是在磁盘空间管理方面。他通过自身经历提出警告，建议不要轻易修改相关系统功能。 • [crazygringo] 则对文件克隆持积极态度，并质疑为何在 Mac 上的 `cp` 命令和 Python 中不默认使用克隆。他认为文件克隆可以减少磁盘空间使用，且从用户角度看不出不使用克隆的缺点。他还提到克隆只是文件系统的一种实现细节，因此应默认使用以提高效率。 • [zahlman] 解释了克隆文件的技术原理，指出尽管克隆文件在数据上是共享的，但它们是独立的，编辑一个副本不会影响另一个。他提到 APFS 文件系统使用写时复制（copy-on-write）技术来高效存储数据，并引用了 `clonefile` 和 reflinks（参考链接）等技术概念，试图从技术角度阐明文件克隆的实现方式及其优势。 补充讨论： • 争议焦点在于文件克隆功能的实际效果和潜在问题。mikeyla85 提出的磁盘空间显示问题表明克隆功能在某些情况下可能导致不一致和混乱，而 crazygringo 则强调了克隆在节省空间上的优势，忽视了潜在的复杂性和问题。 • 另一个值得注意的讨论点是不同场景下是否应默认使用克隆功能。crazygringo 认为克隆应在更多场景下默认使用，而 zahlman 的技术解释则暗示了克隆功能的实现细节和其可能需要的特定条件或工具支持（如 `clonefile` 和 reflinks）。 • 技术实现细节也是讨论的一部分。zahlman 提到了 APFS 文件系统的具体技术如写时复制和 `clonefile`，为那些希望深入理解文件克隆工作原理的用户提供了参考。

Weather satellites detect 515-mile-long lightning flash

文章摘要

2017年，一场雷暴产生了一道惊人的闪电，长度达515英里（829公里），创下世界纪录。这一巨型闪电（megaflash）从德克萨斯州延伸至密苏里州，打破了2020年创下的477英里（768公里）的纪录。巨型闪电定义为长度至少达到62英里（100公里）的闪电，而普通闪电通常不到10英里（16公里）。研究团队利用GOES-16卫星的数据确认了这一长度。这类巨型闪电非常罕见，通常需要持续约14小时的雷暴才可能产生。随着闪电测绘技术的进步，未来可能会发现更多此类极端现象。研究结果发表在《美国气象学会公报》上。
