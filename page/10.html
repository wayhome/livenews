Typst: A Possible LaTeX Replacement

作者: pykello | 评分: 741 | 评论数: 96 | 发布时间: 2025-09-27 07:31
文章摘要

这篇文章介绍了Typst，一个可能替代LaTeX的文档排版工具。Typst专注于技术文档，支持数学公式、表格和浮动图表等功能，输出质量与LaTeX相当，但语法更简单、定制更容易，且编译速度更快。Typst是开源的（Apache-2.0许可证），用Rust编写。尽管LaTeX在学术界广泛应用，但其安装体积大、编译速度慢、错误信息晦涩难懂，以及定制困难等问题引发了许多不满。Typst由两名德国开发者于2019年启动，2023年发布首个测试版，目前已更新至v0.13.1，拥有365名贡献者。Typst支持快速增量编译和实时预览，适合学术写作，并开始被部分期刊接受。文章还提到Typst的安装和使用方法，包括通过命令行工具进行编译和实时编辑。

评论摘要
主要讨论点：[Typst 与 LaTeX 的对比及其在文档生成中的优劣势] 不同观点： • **Typst 支持者**： - Typst 编译速度快（比 LaTeX 快 3-4 倍），尤其是在处理大型文档时（如 2000 页以上的文档）。 - 开发者体验更好，错误信息更清晰，类似于 Rust 编译器的风格。 - 语法简洁，易于学习和使用，适合快速编写和调试。 - 更适合现代编程需求，如版本控制和自动化生成 PDF（如 Lambda 函数生成发票）。 - 避免了 LaTeX 的包冲突问题，模块化设计更合理。 • **LaTeX 支持者**： - LaTeX 在排版质量和精细控制上仍占优势（如 Typst 的排版质量约为 TeX 的 95%）。 - LaTeX 有成熟的社区和大量现成模板，尤其是在学术界（如论文、期刊投稿）。 - 用户已对 LaTeX 的复杂性问题找到了解决方案，切换成本高。 - LaTeX 的宏系统（如 plain TeX）提供了极高的灵活性，尽管学习曲线陡峭。 • **中立或观望态度**： - Typst 仍需时间发展，尤其是在学术界和出版界的模板支持上。 - LaTeX 的某些功能（如 PDF 嵌入图片）在 Typst 中尚未完全实现。 - 其他替代方案（如 SILE、HTML+MathML）也值得关注，但各有优缺点。 补充讨论： - **争议焦点**： - Typst 是否能完全替代 LaTeX，尤其是在学术出版领域。 - Typst 的简洁性和易用性是否足以弥补其功能上的不足（如排版细节控制）。 - **其他讨论点**： - Typst 在 Unicode 和非拉丁语言（如梵文）支持上的优势。 - LaTeX 的安装和依赖管理问题（如大型安装包、企业环境限制）。 - Typst 在自动化工作流（如批量生成 PDF）中的高效表现。

SSH3: Faster and rich secure shell using HTTP/3

文章摘要

这篇文章介绍了SSH3项目，这是一个基于HTTP/3重新设计的SSH协议，旨在提供更快的会话建立速度和更丰富的安全功能。SSH3利用QUIC和TLS 1.3进行安全通道建立，支持HTTP认证机制，包括OAuth 2.0和OpenID Connect等新认证方式。相比传统SSHv2需要5-7次往返时间建立会话，SSH3仅需3次，显著提升了速度。此外，SSH3还支持UDP端口转发、连接迁移等QUIC协议特性。不过文章强调SSH3目前仍处于实验阶段，尚未经过充分的安全审查，不建议在生产环境中部署。项目是开源的，鼓励社区参与反馈和分析。

评论摘要
主要讨论点：[SSH3的技术优势、命名争议、项目状态、与传统SSH的对比] 不同观点： • **支持SSH3的技术优势** - Zambyte指出SSH3在建立连接时更快（3次往返 vs SSHv2的5-7次），但活动连接速度相同，认为这一改进合理。 - Arch-TK补充SSH的慢主要源于会话设置（如PAM），SSH3的优化对Ansible等工具可能有实际帮助。 • **对SSH3的质疑与担忧** - kelnos认为连接建立时间对用户体验影响不大，且SSH已通过长期验证，SSH3的可靠性存疑。 - alsosprachben指出SSH的多路复用设计注重隔离性，而HTTP协议可能引入不必要的复杂性。 • **命名争议** - psanford提到SSH3可能改名，因其实现与主流SSH哲学差异较大（如基于HTTP/3）。 - dev_l1x_be批评讨论过度关注名称而非技术价值。 • **项目状态与未来** - miduil和vladdoster质疑项目活跃度（最后一次提交为1年前）。 - staplung希望SSH3能加入更多新功能（如Mosh的间歇连接支持）。 补充讨论： - **争议焦点**：SSH3是否真能解决传统SSH的痛点（如kelnos与Arch-TK对“连接速度”重要性的分歧）。 - **技术延伸**：ryangibb提到用Cap'N Proto实现密钥交换的替代方案，she46BiOmUerPVj探讨HTTP头部能否实现SSH的域名转发。 - **语言优势**：computersuck认为Go语言的内存安全性是SSH3的额外优势。

BBC网络安全记者乔·蒂迪揭露了一起网络犯罪团伙试图收买内部人员的案件。犯罪团伙通过加密聊天应用Signal联系他，承诺如果提供BBC系统访问权限可获得15%-25%的赎金分成（预计数千万美元）。该团伙自称来自名为"美杜莎"的勒索软件组织，已成功入侵300多家机构，包括英美企业。记者在BBC编辑指导下与黑客周旋，发现该组织总部可能在俄罗斯，专门避开俄语地区目标。案件反映出网络犯罪日益猖獗，利用内鬼获取权限的模式正威胁全球企业安全。（199字）

评论摘要
主要讨论点：[如何应对MFA轰炸攻击及提升认证安全性] 不同观点： • **分享攻击脚本以提高防御** 有评论者认为受害者应公开黑客使用的脚本，以便其他公司能提前部署防护措施。这是基于信息共享能增强整体安全性的理念。 • **改革认证通知机制** 另一观点主张彻底取消验证码推送通知（如丹麦MitID的做法），要求用户主动打开认证APP操作。这能从根本上防止"疲劳接受"攻击，尽管初期可能引发用户体验争议。该观点以Uber 2022年被黑事件为例证。 • **识别攻击模式的重要性** 讨论中明确指出这是一种已知的"MFA轰炸"技术，通过高频触发二次验证请求迫使受害者误操作。此观点为前两个解决方案提供了技术背景支撑。 补充讨论： - 争议焦点在于安全性与便利性的平衡：强制手动打开认证应用虽安全，但可能遭遇用户抵制（如丹麦案例所示）。 - 值得注意的是，该讨论将技术分析（攻击原理）、产品设计（通知机制）和社会工程（用户行为预测）三个维度有机结合。
