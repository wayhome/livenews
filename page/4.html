LLMs tell bad jokes because they avoid surprises

作者: dfabulich | 评分: 64 | 评论数: 22 | 发布时间: 2025-08-13 17:53
文章摘要

这篇文章指出，大型语言模型（LLM）在喜剧、艺术、新闻、研究和科学等领域表现不佳的根本原因是它们被设计为最小化意外性。作者以笑话为例，指出好的笑话需要既出人意料又在事后看来理所当然，而LLM由于训练目标是预测最可能的下一词，因此无法生成真正有趣或创新的内容。同样的原理也适用于故事创作和新闻报道，LLM生成的内容往往平淡无奇，缺乏惊喜和深度。作者认为这是LLM固有的设计限制，无法通过增加算力或数据来解决。

评论摘要
主要讨论点：[LLM是否能够有效生成幽默内容及其限制因素] 不同观点： • **LLM能够生成幽默**：部分用户认为LLM可以生成幽默内容，例如通过特定提示（如模仿喜剧演员风格）或实验性设置（如“Surprise Mode”）来优化幽默生成。例如，用户jpalomaki通过ChatGPT生成了一些有趣的对话笑话，而user fluoridation提到LLM在某些随机情境下也能产生令人发笑的内容。 • **LLM幽默能力有限**：多位用户指出LLM在幽默生成上的局限性，认为其受限于预训练目标（如最小化交叉熵损失函数）和后续微调（如RLHF、安全限制），导致其难以产生真正出人意料的笑点。用户kazinator认为主流LLM的“事实性”和“安全性”微调与幽默生成的要求相冲突。 • **幽默的认知理论**：用户kens引用《Inside Jokes》一书，提出幽默的进化意义在于帮助人们发现认知错误，而LLM的预测性目标可能与之矛盾。但user libraryofbabel反驳这种观点，认为作者将“惊喜”与“可能性”混为一谈。 补充讨论： • **争议焦点**：LLM的预训练目标是否天然排斥幽默生成？用户golol认为预训练本身不排斥“惊喜”，但低温和微调可能限制了幽默能力。 • **比较案例**：用户Applejinx对比了LLM与马尔可夫链的幽默生成差异，指出LLM倾向于保持上下文一致性，而马尔可夫链可能通过意外词汇制造更强的“惊喜”效果。 • **用户实验**：多位用户通过实际测试（如生成特定风格笑话或分析儿童幽默）探讨LLM的幽默表现，表明其能力高度依赖提示设计和模型配置。

I Prefer RST to Markdown (2024)

文章摘要

作者通过比较reStructuredText(rST)和Markdown，阐述了为什么更喜欢使用rST来编写技术书籍。主要原因是rST作为中间重量级的文档树表示，提供了更强大的扩展性和灵活性。文章以插入图片为例，说明虽然rST语法更复杂，但允许自定义指令和节点处理，支持文档树转换等高级功能。作者以自己编写的编程逻辑书籍为例，展示了如何使用rST的扩展功能实现习题和解答的自动排版、链接和格式转换。这些复杂需求是轻量级的Markdown难以实现的，因此尽管rST学习曲线更陡峭，作者仍坚持使用它来满足专业出版需求。

评论摘要
主要讨论点：Markdown 与 reStructuredText（RST）在文档编写中的适用性比较 不同观点： • **支持 Markdown** - 优势：轻量、易读易写、语法简单、普及度高（如 Slack、Obsidian 支持） - 适用场景：快速笔记、简单文档、评论等非正式内容 - 论据：RST 的图片嵌入语法更复杂（`![alt](img.jpg)` vs `.. image:: img.jpg :alt: alttext`），且过度使用 RST 可能导致文档减少（开发者因繁琐语法放弃编写） - 争议点：对粘着语（如韩语）支持更好（CommonMark 虽有边缘情况，但优于 RST） • **支持 RST** - 优势：功能完备（如目录、索引）、扩展性强（支持需求管理工具如 Sphinx-Needs） - 适用场景：书籍、大型文档集、正式出版内容 - 论据：作者以写书为例，RST 更适合复杂结构；部分用户反馈 Markdown 超过 10 页后难以维护 - 争议点：扩展生态碎片化（部分插件更新滞后），且缺乏 WYSIWYG 编辑器和自动纠错工具 • **中间/替代方案** - **AsciiDoc**：平衡功能与简洁性 - **Djot**：类似 Markdown 但更易解析，支持表格等扩展 - **Org Mode**：读写体验优于 RST，大文档支持优于 Markdown，但普及度低 补充讨论： - **工具链限制**：RST 解析器仅限 Python，而 Markdown 多语言支持更灵活。 - **用户群体差异**：专业文档作者倾向 RST，普通用户偏爱 Markdown 的易用性。 - **语言兼容性**：RST 对非拉丁语系（如韩语）支持较差，影响其普适性。 - **新兴工具**：Typst 的简单性与复杂性平衡尚未形成共识。
