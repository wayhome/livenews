1990 Networking: LAN Manager 2.0

作者: userbinator | 评分: 13 | 评论数: 0 | 发布时间: 2025-07-19 20:03
文章摘要

微软于1990年发布了LAN Manager (LM) 2.0，这是其网络产品线的一部分，始于1984年的MS-NET，最终演变为Windows NT文件共享。LAN Manager 1.0于1988年作为OEM产品发布，微软与3Com合作开发了网络驱动程序NDIS规范。1990年，微软决定直接销售LAN Manager 2.0，绕过OEM，导致与3Com关系恶化。 关于LAN Manager 2.0的发布时间存在争议。尽管有证据显示1990年6月底微软完成了“最终”版本，但缺乏明确的发布公告。一份1990年8月的 press release 提到 LAN Manager 2.0 服务器需要 OS/2 1.21，而该版本当时仅通过OEM提供，使得直接销售受限。InfoWorld 报道3Com于1990年9月底发布了基于LAN Manager 2.0的3+Open，而微软可能在1990年8月直接销售了LAN Manager 2.0。 微软知识库文章提供了更新信息，指出LAN Manager 2.00a为CSD1，2.00b为CSD2。1990年6月的版本为CSD0，而11月的版本为2.00b。因此，1990年6月到11月之间有多次更新。

“Dynamic Programming” is not referring to “computer programming”

作者: r4um | 评分: 166 | 评论数: 20 | 发布时间: 2025-07-18 11:09
文章摘要

"动态规划"（Dynamic Programming）中的“编程”一词并非指计算机编程，而是指类似于电视节目编排的“规划”或“计划安排”。该术语由理查德·贝尔曼在1950年代创造，原意是为了掩饰其数学研究的本质，以避免政治上的敏感。动态规划的核心是通过规划子问题的解决顺序来有效解决复杂问题，例如计算斐波那契数列。子问题的解决有依赖顺序，必须先解决前面的问题，如必须先计算出fib(6)和fib(5)才能计算fib(7)。动态规划可以自顶向下递归解决，也可以自底向上逐步解决，两种方法都旨在避免重复计算，提升效率。因此，理解“规划”是理解动态规划的关键，而非“动态”。

主要讨论点：动态规划（Dynamic Programming，DP）的定义、命名由来、实际应用以及在不同上下文中的使用和混淆。 不同观点： • **动态规划的个人学习经历**：[npsomaratna] 分享了自己在90年代参加IOI竞赛时首次接触动态规划的经历。由于当时资源有限，他花了很长时间才理解动态规划的概念，最终在国际竞赛中获奖。 • **动态规划命名的争议**：[tgma] 引用了Wikipedia中关于动态规划命名由来的争议，指出该术语可能并非严格源自动态或规划，而是为了在术语上压过“线性规划”。 • **对命名的批评与替代建议**：[IshKebab] 和 [gsf_emergency_2] 认为“动态编程”这个名称具有误导性，建议使用“缓存递归”（cached recursion）或其他更具描述性的术语。 • **动态规划在实际问题中的应用**：[cousin_it] 分享了一个具体的动态规划问题，即通过递归关系计算两个人之间的亲缘关系百分比，并阐述了问题的解决方案。 • **动态规划在经典算法中的应用**：[DonHopkins] 详细描述了James Gosling的Emacs屏幕重绘算法如何利用动态规划技术解决字符串编辑的最小成本路径问题，并提到该算法的复杂性及其实现的挑战。 • **动态规划在不同领域中的混淆**：[smokel] 指出，动态规划在LeetCode问题和强化学习中的使用具有不同含义，前者用于优化确定性系统，后者用于优化随机过程，容易引起混淆。 • **对术语动态的调侃与联想**：[ygritte] 和 [mrbluecoat] 分别调侃了“动态编程”与“动态类型”以及“极限编程”（Extreme Programming）等术语，指出这些术语在不同背景下的不同含义。 • **教育中对动态规划的简化处理**：[sureglymop] 提到在大学课程中，讲师很快将动态规划简化为“DP”，以避免学生混淆，表明教育者意识到该术语可能引发的困惑。 • **动态最优性与数据结构**：[bob1029] 提到“动态最优性”概念，认为像伸展树（splay tree）这样的数据结构通过动态调整数据存储方式实现最优访问，这种思想与动态规划有相似之处。 补充讨论： • **动态规划术语的起源文献**：[pss314] 提供了Richard Bellman关于动态规划命名的文献链接，进一步探讨了该术语的历史背景。 • **不同政治背景下的编程术语**：[nottorp] 分享了在共产主义罗马尼亚时期，由于资源限制和审查制度，编程书籍被伪装成其他主题出版的经历，显示了术语使用的历史和文化差异。 争议的焦点： • 动态规划这个术语本身的准确性和适用性是争议的核心。许多人认为该术语具有误导性，因为“动态”和“编程”都不能准确反映该技术的本质。这种命名问题导致了学习者和从业者的混淆。 • 动态规划在不同领域中的不同应用和含义也引发了讨论，尤其是在教育和实际应用中的定义混淆问题。

Writing your Clojure tests in EDN files

文章摘要

本文介绍了Jacob O'Bryant对使用EDN文件进行快照测试的方法的简化和改进。之前的方法过于复杂，依赖控制反转，测试编写成本高。新方法简化了测试编写过程，测试代码类似于在REPL中运行，测试输入数据和预期结果保存在EDN文件中。测试运行程序自动执行代码并更新结果，开发者通过Git差异检查结果变化，决定是否接受更改或修复问题。此外，如果代码抛出异常或使用`tap>`捕获中间值，这些信息也会记录在测试文件中，方便调试。这种方法减少了认知负担，使测试编写更加便捷。

评论摘要
主要讨论点：使用不同文件格式和方法进行快照测试和验证测试 不同观点： • [lyxell] 支持使用 **txtar 文件** 进行快照测试，其中一个字段包含预期输出，一个或多个字段包含输入。这种方法的优势在于大多数主流编程语言都有 txtar 解析器，因此可以轻松将整个测试套件跨语言移植。他以 Rust 的 txtar 库为例，说明这种方法的实际应用。 • [andersmurphy] 对 [lyxell] 的观点表示赞同，并补充提到这种预期测试的方式让他想起 **Jane Street 的 "expect" 测试**（提供了一个相关博客链接）。这表明 Jane Street 也有类似的测试实践，强调了预期输出和输入的紧密结合。 • [erichocean] 提出了另一种不同的测试方法，即 **SQL 数据库的测试**。他描述了一种测试 SQL 查询的方式：在一个 .sql 文件中包含查询语句，随后紧跟预期响应（作为 SQL 注释）。测试运行器会执行查询并验证其结果是否与注释中的预期响应匹配。这种方式可以包含数据库创建、插入数据等操作，并可以集成到 CI 基础设施中。 补充讨论： • [lyxell] 的方法侧重于跨语言的快照测试，利用 txtar 文件的结构化特性，使其易于移植和维护。 • [andersmurphy] 通过引用 Jane Street 的博客，补充了关于 "expect" 测试的背景信息，表明这种测试方法在某些社区中已经比较成熟。 • [erichocean] 的方法则专注于 **SQL 查询的测试**，展示了如何使用注释来存储预期结果，这种方法特别适合数据库相关的测试，并且强调了其在 CI 环境中的应用。 争议焦点： • 没有直接的争议，但讨论中涉及了不同领域（通用编程语言测试与 SQL 数据库测试）的测试方法。可以看出，不同方法适用于不同的场景，但都围绕如何高效进行快照测试和验证测试这一核心主题。

Comparison of MGR, SunView, OpenWindows and X11R6 (2022)

作者: hualapais | 评分: 16 | 评论数: 6 | 发布时间: 2025-07-21 16:09
文章摘要
