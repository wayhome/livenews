Exposing a web service with Cloudflare Tunnel (2022)

作者: sturza | 评分: 93 | 评论数: 15 | 发布时间: 2025-07-09 09:08
文章摘要

本文介绍了如何使用Cloudflare Tunnel在不暴露服务器端口的情况下安全地托管web服务。首先，通过安装`cloudflared`客户端并登录Cloudflare账户进行授权。接着，创建一个隧道（tunnel），获取其凭证和ID。然后，建议配置`systemd`服务以更好地管理隧道。具体步骤包括创建配置文件和设置服务，以确保隧道能稳定运行。Cloudflare Tunnel通过在服务器和Cloudflare数据中心之间建立持久的外向连接，保护服务器不被直接暴露在公共互联网中，同时实现正常的应用托管。这种方法适用于各种环境，包括家庭服务器或Kubernetes集群等。

主要讨论点：Cloudflare Tunnel 的使用及其安全性、实用性 不同观点： • **teiferer** 认为使用 Cloudflare Tunnel 与直接开放端口在安全风险上没有本质区别，因为最终处理流量的还是家中的服务器进程。他对 Cloudflare 是否过滤流量以及如何判断好坏流量表示质疑。 • **44za12** 非常喜欢使用 Cloudflare Tunnel，并成功在旧的 Raspberry Pi 上托管了博客和多个项目，展示了实际使用案例。 • **mgerdts** 指出，如果互联网暴露的应用被攻破，攻击者可能会轻松访问家庭网络，因此需要额外的防护措施。 • **yegle** 提到根据 Cloudflare 的服务条款，通过 Cloudflare Tunnel 传输媒体流可能违反规定，他自己选择使用 oauth2-proxy 来保护 Plex 服务。 • **ajd555** 表示自己多年使用 Cloudflare Tunnel，并且免费 tier 非常慷慨，没有遇到任何问题，甚至有 kubernetes 部署方案。 • **agnishom** 询问是否可以用 tailscale funnel 实现同样的功能，暗示对替代方案的兴趣。 • **jz10** 提到在工作中使用 Cloudflare Tunnel，但觉得 web 界面不易用，因此开发了一个 TUI 工具来管理隧道，并增加了基本认证保护。 补充讨论： • **speerer** 对 Cloudflare 的服务条款表示担忧，特别是其中关于用户内容永久授权给 Cloudflare 的条款。 • **cedws** 询问是否有人用 Cloudflare Tunnel 运行私人邮件服务器，暗示对这种特定用途的兴趣。 • **kramer2718** 对该方案表示赞赏，并计划在即将到来的项目中使用。 • **Hikikomori** 分享了自己使用 Zero Trust 认证保护服务的经验，并提到创建了一个 Python 脚本自动处理相关配置。 • **theyknowitsxmas** 指出现在的设置过程已经简化为从仪表板复制粘贴，并且可以通过 Access 保护子域，提供了简化操作的信息。 • **jekwoooooe** 表示喜欢使用 Cloudflare Tunnel 来暴露内部服务，并通过 Google 认证和其他零信任保护措施来确保安全。 争议焦点： • Cloudflare Tunnel 是否真正提升了安全性，尤其是与直接开放端口相比。 • Cloudflare 服务条款的限制，特别是内容授权条款，是否会对用户造成困扰。
