文章摘要

亚利桑那州的荒原中散落着许多隐秘的墓地与孤独的坟墓，从著名的O'Neill墓到被沙漠吞噬的原住民村落墓地。这些墓地有的位于"魔鬼之路"等偏远地带，有的属于已消失的村庄。托霍诺奥德汉族保留地的原住民保持着在亡灵节清理墓地的传统，即使村庄早已荒废。一些现代墓碑与古老石冢并存，展现了不同时代的葬俗。这些沙漠中的寂静墓园，有的墓主身份成谜，有的记录着部落历史，构成了这片土地独特的文化记忆。

Using JWT to establish a trusted context for Row Level Security

文章摘要

本文探讨了PostgreSQL中行级安全(RLS)功能的实现挑战，并提出使用JWT(JSON Web Tokens)建立可信上下文的解决方案。作者指出传统RLS依赖数据库角色存在诸多不足，如管理复杂、与连接池不兼容等问题。文章提出通过数字签名技术(JWT)构建加密可信上下文，使数据库能验证上下文来源的真实性和完整性，从而安全地用于RLS策略。作者介绍了对称(HMAC)和非对称(RSA/ECDSA)加密方案的优缺点，并发布了一个实验性扩展jwt_context来实现这一构想。最后，作者邀请社区就这种使用JWT的方式提供反馈意见。

评论摘要
主要讨论点：[JWT在数据库连接池和REST API中的应用及其安全性] 不同观点： • [支持JWT的方案] - conradludgate分享了Neon的实现，通过连接池管理JWT上下文，确保每个请求使用新签名的JWT，并通过`DISCARD ALL`清除上下文，防止重用。 - Apaec提到PostgREST长期使用JWT进行认证，提供了成熟的参考案例。 - themafia建议在现有OAuth流程中添加自定义属性，与JWT兼容，便于策略应用和输出过滤。 • [反对JWT的方案] - some_furry指出JWT存在典型的安全漏洞，并引用多个漏洞案例（如Auth0和firebase/php-jwt的漏洞），建议在新设计中避免使用JWT，推荐使用PASETO（更安全的选择）。 补充讨论： - 争议焦点：JWT的安全性是否足够，尤其是在新设计中是否应优先选择其他替代方案（如PASETO）。 - 讨论关系：some_furry的反对观点直接回应了其他评论中JWT的应用案例，提出了具体的安全隐患和替代方案。 - 其他注意点：themafia的建议侧重于兼容性和扩展性，为JWT的命名属性提供了实践指导。

I Was Wrong About Data Center Water Consumption

作者: dskrvk | 评分: 28 | 评论数: 3 | 发布时间: 2025-09-01 19:29
文章摘要

这篇文章主要讨论了作者之前对数据中心耗水量的错误估算。作者原本引用伯克利实验室报告的数据中心间接耗水量（来自发电厂）为每日5.79亿加仑，但后来发现该数据实际上是消耗性用水而非总用水量。经核查，作者认为该报告高估了数据中心耗水量，因为其计算包含了水力发电大坝水库的蒸发量（远高于火力发电的耗水量）。虽然技术上这些蒸发量确实算作消耗，但作者质疑是否应将其完全归咎于数据中心用电。最终，作者建议应更谨慎地解读水资源使用数据。
