JEP 519: Compact Object Headers

作者: Skinney | 评分: 56 | 评论数: 4 | 发布时间: 2025-05-22 08:24
文章摘要

JEP 519 提议将紧凑对象头（Compact Object Headers）从实验性功能转变为正式产品功能。该功能最初作为实验性功能在 JDK 24 中引入，经过测试证明其稳定性和性能优越，包括在 Oracle 和亚马逊的生产环境中得到了验证。测试显示，启用紧凑对象头后，SPECjbb2015 基准测试的堆空间使用减少了 22%，CPU 时间减少了 8%，垃圾收集次数减少了 15%，且 JSON 解析 benchmark 运行时间缩短了 10%。因此，现在是将其从实验性功能升级为正式功能的时候。升级后，将不再需要通过命令行选项 `-XX:+UnlockExperimentalVMOptions` 来启用该功能。

评论摘要
主要讨论点：JEP 519 关于启用紧凑对象头（Compact Object Headers）的默认设置及其性能影响 不同观点： • **nicktelford** 认为 JEP 519 没有默认启用紧凑对象头是不合理的。他认为大多数用户不会特意去启用该功能，如果该功能已经被确认为稳定且能提升性能，就应该默认开启。他还提到，JVM 过去因为需要复杂的标志来优化性能（尤其是GC配置）而声名狼藉，尽管现在有所改善，但 JEP 519 似乎在这一方面又开了一个倒车。 • **SerCe** 则指出，先前的 JEP 450 提供了更多关于该功能的实现细节。该功能已经在 Oracle 和亚马逊进行了广泛测试，包括整个 JDK 测试套件和亚马逊生产环境中的数百个服务。SerCe 认为，在大公司中，平台团队有更多的机会和资源来测试和量化性能改进，而这是其他人难以获得的。 • **hmottestad** 对 JEP 519 的性能结果表示赞赏，特别是提到 JSON 解析基准测试显示了 10% 的性能提升。不过，他并没有对默认启用问题提出质疑，而是更关注性能改进的具体表现。 • **kosolam** 提出了一个问题，即该 JEP 是否也能提高 GraalVM 原生镜像的可执行文件的效率。这表明他对该功能在不同环境或工具链下的适用性表示关注。 补充讨论： • 争议的焦点在于 JEP 519 没有默认启用紧凑对象头，这引发了 nicktelford 对用户体验和易用性的担忧，而 SerCe 则通过实际测试数据来支持该功能的可行性和稳定性。 • 该功能的具体性能提升效果得到了 hmottestad 的肯定，尤其是在 JSON 解析基准测试中的表现。 • kosolam 提出了该功能在 GraalVM 环境下的适用性问题，这是一个值得进一步探讨的方向。
