We Designed TigerBeetle's Docs from Scratch

作者: mooreds | 评分: 46 | 评论数: 8 | 发布时间: 2025-04-07 12:35
文章摘要

TigerBeetle团队从零开始重建了其文档网站，以符合TigerStyle和第一性原理的思维方式，而不仅限于数据库本身。他们最初使用Docusaurus来快速搭建文档原型，但发现它违背了团队的“零依赖”原则，引入了过多依赖和复杂性，且生成的额外文件影响了GitHub上的纯净展示，搜索功能也不理想。团队希望文档与数据库本身一样精益求精，因此决定创建一个简洁、清晰、快速的阅读体验。新的文档网站依赖Zig编译器，使用Pandoc进行Markdown解析，以确保内容在各种形式下的一致性，并通过Zig的构建系统实现增量更新。最终，文档网站不仅提升了外部用户体验，也优化了内部代码实现。

smartfunc: Turn Docstrings into LLM-Functions

作者: alexmolas | 评分: 49 | 评论数: 10 | 发布时间: 2025-04-08 09:43
文章摘要

`smartfunc` 是一个将 docstrings 转换为 LLM（大语言模型）功能的 Python 库，基于 Simon Willison 的 `llm` 库构建。通过使用装饰器，开发者可以轻松地将函数的文档字符串转换为 LLM 提示，并使用指定的后端（如 GPT-4）生成结果。该库支持使用 Jinja2 模板和 Pydantic 模型定义响应结构，允许通过 `.env` 文件存储 API 密钥，并具有异步支持和多供应商生态系统。其目标是在快速原型设计中提供简洁的解决方案，专注于简单易用，而非复杂的功能集。以下是一个示例： ```python from smartfunc import backend from pydantic import BaseModel class Summary(BaseModel): summary: str pros: list[str] cons: list[str] @backend("gpt-4o-mini", system="You are a helpful assistant.", temperature=0.5) def generate_poke_desc(text: str) -> Summary: """Describe the following pokemon: {{ text }}""" pass print(generate_poke_desc("pikachu")) ``` 这个库的主要优势在于其简洁性和对特定功能集的专注，适用于快速原型设计和简单任务。

评论摘要
主要讨论点：LLM（大型语言模型）在编程中的应用和集成方式，特别是在不同函数和模块间如何灵活使用LLM，以及Docstring的使用和价值。 不同观点： • senko：认为在运行时不容易将同一函数用于不同LLM是现有库的缺陷。他自己的方法是显式传递LLM对象，以提高灵活性和易用性，并提供了具体例子来展示该方法的实际应用。 • lukev：支持senko的方法，认为将LLM视为像编译器一样的工具，比将其视为初级开发者更具可扩展性、可扩展性和组合性的心智模型。 • shaism：表示曾实现过类似方法，并认为当前LLM的编码能力已大大增强。他还提出装饰器方法可以进一步扩展，不仅限于LLM调用，还可以基于Docstring生成Python代码，从而促进编写明确的Docstring，并保证代码和文档的一致性。 • simonw：提到自己几周前在一个LLM Python库中添加了schema功能，并认为senko的集成方式与该功能很好地结合在一起。 • asadm：讨论了在JS中的类似工作，并设想函数可以简化为针对特定功能的小型模型，而不是对基础模型的API调用。 • nonethewiser：认为编写docstring很繁琐，LLM可以自动生成docstring，但他质疑docstring是否真的比普通文本描述更好，因为LLM也能很好地处理后者。 • noddybear：指出senko的项目看起来很像Tanuki，并提供了一个链接。 • miki123211：提到promptic这个工具，认为它比LLM更强大，因为支持更多的模型提供者，且不需要插件。 • dheera：分享了反向使用LLM的经验，即在难以理解的代码中插入docstring，通过LLM自动生成大量注释。 补充讨论： • 争议焦点之一是docstring的价值和编写繁琐性。虽然有些人认为docstring有助于代码和文档的一致性，但也有人认为编写docstring很麻烦，LLM自动生成可能是一个解决方案。 • 另一个讨论点是LLM作为开发工具的最佳使用方式，包括将其视为编译器（lukev的观点）还是代码生成器（shaism的观点）。 • 还有对不同工具和库的比较，例如Tanuki和promptic，以及它们在LLM集成中的优劣。 整体来看，讨论围绕着如何更好地在编程中集成和使用LLM，包括具体的实现方法、工具选择以及对docstring等文档编写的看法。

文章摘要

EPFL研究人员开发了一种名为ByzFL的工具，旨在解决人工智能（AI）中的数据可信性问题。随着AI广泛应用于各个领域，依赖集中化大数据训练的模型面临安全、隐私和数据所有权等问题。为此，研究团队提出了联邦学习（federated learning）方法，允许模型在去中心化设备上进行训练，避免直接使用原始数据。然而，由于数据可能包含错误、恶意篡改或设备被黑客攻击，研究团队开发了ByzFL库，用于测试和增强AI模型对抗不良数据的能力。ByzFL通过使用鲁棒的聚合方法（如中位数）来排除极端数据，确保系统的安全性。该工具的目标是确保未来在关键领域（如医疗、自动驾驶）中应用的AI系统更加可信和安全。

评论摘要
