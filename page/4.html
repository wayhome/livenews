The many JavaScript runtimes of the last decade

作者: LinguaBrowse | 评分: 194 | 评论数: 20 | 发布时间: 2025-07-27 14:28
文章摘要

过去十年中，JavaScript运行时和引擎大量涌现，使JavaScript得以在云端、边缘计算、智能电视、移动设备甚至微控制器等多种环境中运行。这种多样性源于不同场景对任务精确度的需求。2002年，Akamai推出首个“边缘计算”解决方案，但直到2009年Node.js出现，JavaScript才开始被用于服务器端。2014年，AWS Lambda使Node.js进入无服务器领域。2016年，AWS推出Lambda@Edge，使JavaScript真正进入边缘计算。然而，Cloudflare Workers在2017年迅速崛起，成为直接产品化的JavaScript运行时，获得巨大成功。随后，Deno于2018年出现，成立Deno Land Inc并推出Deno Deploy，挑战Cloudflare。2022年，WinterCG成立以统一新运行时标准，Bun和Wasmer也相继推出新边缘计算解决方案。 不同运行时使用不同引擎，如Deno用V8，Bun用JavaScriptCore，WinterJS用SpiderMonkey，LLRT用QuickJS，Cloudflare Workers用workerd。在微控制器领域，轻量级引擎如Duktape、Espruino、JerryScript、Moddable和elk应运而生，支持低资源设备。最后，一些JavaScript引擎基于已有虚拟机，实现与其他语言的零成本互操作。

评论摘要
主要讨论点：JavaScript 各种运行时和引擎的分析与比较 不同观点： • LinguaBrowse 认为文章覆盖全面，读者能学到新知识，强调文章的广度和深度。 • Laurencerowe 指出 Cloudflare 的 workerd 运行时使用的是 V8 引擎，而非自定义引擎，纠正原文中的不准确之处。 • Weiliddat 补充提到 Bellard 的 QuickJS 仍然活跃，并提供了相关链接，认为需要在讨论中提到这一点。 • Willquack 分享了自己参与的其他未被提及的 JavaScript 运行时项目，如 PythonMonkey 和 DCP，并描述了这些项目的特点和用途。 • Ksherlock 提到微软的 JScript 也应该被提及，尽管其历史久远，但其服务器端应用（如ASP）仍有历史价值。 • Asn0 补充了90年代的 Nombas ScriptEase 运行时，并给出了相关链接。 • Sytten 纠正了 LLRT 运行时的贡献者情况，强调其社区贡献的特性，并指出其在 Rust 环境中的优势。 补充讨论： • Ottod 和 Podgorniy 对文章质量表示赞赏，认为其具有很高的参考价值。 • Dfee 提出了对不同 JavaScript 运行时未来生存能力的担忧，特别是面对竞争和生态系统整合时，如何确保代码的互操作性。 • NeutralForest 关心如何保持文章中链接的有效性，担心未来可能无法访问原始页面。 • Dehrmann 回忆了 Rhino 作为 Java 内置 JS 解释器的历史，并提到当时没有内置 JSON 解析器的问题。 • Cat-whisperer 对新运行时如何处理异步上下文跟踪提出了疑问，关心它们是使用 Async Hooks 还是自定义解决方案。 • Tom1380 对在微控制器上使用 JavaScript 表示不解，提出了其实际应用场景的问题。 争议焦点： • 关于 Cloudflare workerd 运行时使用的引擎存在争议，laurencerowe 认为其使用的是 V8 引擎，而非原文所述的自定义引擎。 • 不同历史时期的 JavaScript 引擎和运行时（如 JScript、Nombas ScriptEase）是否应被纳入讨论，ksherlock 和 asn0 提出了补充意见。

文章摘要

2025年7月24日，作者分享从Arc浏览器转向Orion浏览器的体验。此前曾短暂使用过Zen，但其耗电问题严重。作者因计划过游牧生活，对电池续航要求提高，偶然发现基于Safari的Orion浏览器，其在电源优化方面表现出色，支持Chrome和Firefox扩展，并具备类似Arc的"空间"功能。虽然缺少多账户容器功能，但整体满足需求，且开发团队积极响应反馈。另外，作者还提到发现了两款工具：Radian（现代R语言控制台）和likvi.de（适合德国自由职业者的发票与会计管理工具）。

评论摘要
主要讨论点：Orion浏览器的功能、稳定性、兼容性及隐私特性 不同观点： • **Orion浏览器的用户体验**：[gregwebs] 喜欢Orion浏览器，因为它能阻止广告，并支持DarkReader扩展。然而，他提到该浏览器在手机上不稳定，经常冻结，因此他不得不切换回Safari。 • **Orion浏览器的支持平台**：[johnisgood] 指出Orion浏览器仅支持macOS和iOS，并提供相关链接以节省其他用户的时间。 • **多账户容器功能**：[yzydserd] 回应了关于Orion缺乏多账户容器（MAC）功能的批评，指出Orion通过“配置文件”实现了一定程度的账户隔离，尽管不如Firefox等浏览器功能全面，但可以实现完全分离。 • **JavaScript的默认设置**：[ne_ptun_us] 赞赏Orion允许设置整个互联网为JavaScript选择性加入模式，认为这是一个很好的默认设置，并强烈推荐尝试。 • **隐私和性能**：[mediumsmart] 认为Orion是唯一默认没有遥测功能的浏览器，赞扬其用户界面、低电池消耗及与Kagi的整合，并批评Chrome和Firefox需要大量调整才能达到类似的隐私保护效果。 • **兼容性**：[Apocryphon] 强调Orion是唯一努力提高向后兼容性的浏览器，提到其在macOS Mojave上的使用体验，并指出开发者计划未来支持High Sierra。 • **代理支持问题**：[therein] 关心Orion是否支持SOCKS代理，经过测试后发现尽管可以配置HTTP代理，但FoxyProxy扩展在Orion上无效，仍然无法使用SOCKS代理。 补充讨论： • Orion浏览器的隐私保护和性能是用户选择它的主要原因，但其稳定性和某些功能（如多账户容器和代理支持）的缺失或不足也引起了一些争议。 • 用户对Orion浏览器的扩展功能和兼容性有不同的需求和期望，部分用户对其在特定平台的支持表示关注。
