Binfmtc – binfmt_misc C scripting interface

作者: todsacerdoti | 评分: 86 | 评论数: 11 | 发布时间: 2025-06-08 12:38
文章摘要

**binfmtc** 是一个让 C 语言用于脚本编写的工具，解决了因编译步骤繁琐而选择解释型语言的问题。通过在 C 脚本中添加特定注释标记 `/*BINFMTC: ...*/` 并赋予执行权限，每次调用脚本时，系统会自动编译并执行程序。该工具利用 Linux 的 **binfmt_misc** 机制，在调用 C 脚本时自动调用编译器（如 gcc）生成临时二进制文件并运行。此外，还提供了一个类似 C shell 的 "real csh" 示例，用于日常系统管理任务。安装可通过添加特定源并使用 `apt-get` 完成，未来计划包括支持更多语言如 gcj、g77、mono 等。

评论摘要
主要讨论点：通过不同方法实现C脚本或类似功能 不同观点： • [rwmj] 提出了一种不使用 binfmt 的方式，通过条件编译和 shell 脚本结合，直接编译和运行 C 文件。他提到虽然可以用临时文件实现，但给出了一个无需 binfmt 的简单示例。 • [zx2c4] 提到了自己过去的一个类似项目，提供了一个链接，展示如何通过外部工具实现脚本化的 C 编译和执行。 • [monocasa] 提出了另一种方法，使用 tcc（tiny C compiler），其具有 shebang 兼容性，可以直接用于脚本。 • [radiospiel] 也分享了一个类似的方法，通过指向 C 编译器和运行器的 shebang 行实现。他质疑了通过 binfmt_misc 注册扩展的必要性。 • [kazinator] 强调这种方法完全可以在没有 Linux 特定的 binfmt-misc 黑科技的情况下实现，并提供了一个 Rosetta Code 上的多行 shebang 示例。 • [codr7] 分享了自己为书籍编写的一个简单黑科技，通过 C 程序内部实现类似的功能，并提供了 GitHub 链接。 • [rurban] 仅提到了一个年份 (2006)，可能暗示这种方法或类似想法早已存在。 • [elitepleb] 提到了一个类似的旧网页，展示了一种早期的实现方式。 • [enriquto] 惊讶地发现通过简单的包安装（binfmtc）就能在 Linux Mint 上实现类似的功能。 • [JSR_FDED] 表达了对 C 语言的喜爱，强调了 C 语言的简洁和直接，以及编程中的责任感。 • [Surac] 简短地表达了对这种方法的喜爱。 补充讨论： • 争议焦点之一是是否需要使用 binfmt_misc 注册扩展。部分评论者质疑其必要性，认为有其他更简单和跨平台的方法。 • 各种方法的优劣被间接讨论，包括条件编译、外部工具、shebang 兼容性等不同实现方式。 • 一些评论者分享了个人项目或发现，提供了具体的示例和资源链接，丰富了讨论。 总体来看，讨论围绕着多种实现 C 脚本化编译和执行的方法展开，涉及到具体技术细节和个人偏好。

Cheap yet ultrapure titanium might enable widespread use in industry (2024)

作者: westurner | 评分: 76 | 评论数: 10 | 发布时间: 2025-06-04 22:00
文章摘要

研究人员在东京大学工业科学研究所开发了一种有效去除钛中氧气的方法，从而降低了生产高纯度钛的成本。传统上，由于从钛矿石中去除氧气的成本高昂，钛产品的应用受到限制。该团队使用基于稀土金属的创新技术，将钛的氧含量降低到0.02%。关键步骤是将熔融钛与钇金属或其化合物反应，生成低成本、无氧的钛合金，且钇可回收利用。尽管该方法产生的钛合金中含有最多1%的钇，可能影响其机械和化学性质，但该技术简化了生产流程，有助于钛在工业和消费品中的广泛应用。这项研究发表在《Nature Communications》上。

评论摘要
主要讨论点：新型钛金属提纯方法的科学价值、应用前景及其局限性 不同观点： • Aurornis认为该研究尽管有趣，但并未完全解决问题，因为去除氧的同时引入了钇，影响了钛合金的机械和化学性能，本质上是用一个问题替换了另一个问题。 • digdugdirk指出，即使解决了技术问题，钛金属在工业应用中仍面临加工难题，因为钛的加工非常困难且成本高，导致其难以广泛应用，即便材料成本降低，加工成本依然高昂。 • duffpkg支持digdugdirk的观点，引用了历史文献说明钛加工的难度，并强调即使原材料便宜，规模化生产仍然面临巨大挑战。 • zafka转向了另一个钛合金材料Nitinol的讨论，分享了个人经历，指出尽管新材料有趣且有潜力，但个人应用开发仍然困难。 补充讨论： • westurner引用了研究文章，强调生产超纯钛的高成本问题，指出研究旨在解决这一难题，并提供了相关文献链接。 • LasEspuelas强调了开发低成本钛生产方法的紧迫性，指出当前存在对高效精炼方法的迫切需求。 • foota指出该技术已经申请了专利，提供了相关链接，关注研究的知识产权问题。 • jjcm则乐观认为，随着能源成本下降（如太阳能和核聚变技术的发展），钛的生产成本也将下降，并对当前的中间步骤必要性提出质疑。 • eth0up以个人使用体验为切入点，表达了对钛制品（如SnowPeak杯子）的喜爱，强调了钛制品的实际优点，如耐用和非反应性，但未直接讨论研究本身。 争议焦点： - 主要争议在于该新方法是否真正解决了钛提纯的实际问题。Aurornis认为钇污染问题仍未解决，而digdugdirk和duffpkg则强调钛金属加工本身的困难，即便提纯技术进步也难以改变其高成本和低可加工性。 - jjcm和westurner等人对未来能源成本下降是否能降低钛生产成本持不同看法，jjcm乐观认为能源成本下降将解决问题，而westurner则关注当前的高成本现实。 总结：讨论围绕新型钛提纯方法的科学进展和实际应用展开，涉及技术局限、加工难题、成本问题及未来发展前景等多方面。

OpenBSD IO Benchmarking: How Many Jobs Are Worth It?

文章摘要

本文通过fio基准测试探讨OpenBSD 7.7-current在随机读取、随机写入和延迟方面的I/O性能。测试使用1TB Crucial P3 Plus SSD，64GB测试文件，4KiB块大小，I/O深度32，作业数从1到32。结果显示，OpenBSD的I/O扩展在达到6到8个作业数时表现最佳，之后由于争用和CPU开销增加，性能下降。随机读取在8个作业时接近峰值性能，随机写入对并发更敏感。与Linux相比，OpenBSD在某些配置下表现不如Linux，但仍有提升潜力。结论建议在调优OpenBSD的I/O性能时，应避免过度增加作业数，以6到8个作业为佳。

评论摘要
主要讨论点：不同操作系统（OpenBSD与Linux）在存储IO性能测试中的表现，以及测试方法和硬件选择的合理性。 不同观点： • **wtallis** 认为，测试中使用的硬盘是低端消费级产品（QLC NAND和无DRAM控制器），其性能有限，不能很好地反映操作系统IO栈的可扩展性。他指出测试方法可能未考虑SLC缓存对写入测试的影响，建议限制测试数据量并确保驱动器在测试前有一致的起始状态。他还提到Linux的fio默认设置具有显著的性能优势，并建议进一步分析fio在不同操作系统上使用的IO引擎及默认缓存机制。 • **dfc** 对测试图表的准确性提出质疑，指出图表中X轴并非从原点开始，并且在Linux与OpenBSD对比图中，Linux在job=1时的数据缺失，认为这影响了测试结果的可信度。 • **synack** 对测试使用的CPU型号和核心数量的影响表示关注，并提出FreeBSD在相同测试中的表现值得探讨，暗示不同操作系统在相同硬件条件下的性能对比应更加全面。 补充讨论： • 测试硬件的选择对结果的影响，尤其是低端硬盘是否适合用来评估操作系统IO性能。 • 测试方法的改进建议，包括测试数据量和缓存状态的管理。 • fio工具在不同操作系统上的默认配置及其对性能的影响。 • 图表数据的完整性和准确性问题。 • 其他操作系统（如FreeBSD）在相同测试条件下的表现。 争议焦点：测试方法的科学性与结果的准确性，尤其是硬件选择和图表数据的完整性。
