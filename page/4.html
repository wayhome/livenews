LibreCAD in the Browser

作者: devttyeu | 评分: 3 | 评论数: 0 | 发布时间: 2026-07-02 01:00
文章摘要

作者将开源2D CAD工具LibreCAD移植到浏览器中运行，使用GLM-5.2 AI模型辅助完成。通过Emscripten将C++/Qt源码编译为WebAssembly，实现了完整应用（非阅读器或简化版）的浏览器端运行。 核心技术挑战是处理模态对话框的嵌套问题。传统Asyncify方案只支持单层挂起，遇到嵌套对话框会卡死。最终采用JSPI（WebAssembly JavaScript Promise Integration）技术解决，支持任意深度的嵌套挂起。需要从源码编译Qt 6.9并启用JSPI和WebAssembly异常支持。 首次加载约18MB（Brotli压缩），之后浏览器缓存。目前仅支持Chrome/Edge 137+，因为Firefox和Safari尚未支持JSPI。整个移植过程展示了WebAssembly生态的成熟度和Qt对Wasm的良好支持。

OpenWiki: CLI that writes and maintains agent documentation for your codebase

作者: handfuloflight | 评分: 26 | 评论数: 3 | 发布时间: 2026-07-01 20:51
文章摘要

OpenWiki是一个专为AI代理设计的CLI工具，用于自动编写和维护代码库文档。 **核心功能：** - 通过`npm install -g openwiki`安装 - 使用`openwiki --init`初始化配置模型和API密钥 - 在`openwiki/`目录下生成和更新文档 - 支持交互式会话或单次命令执行 - 可添加GitHub Action实现每日自动更新文档并提交PR **特点：** - 自动在AGENTS.md/CLAUDE.md文件中添加提示，指导代理引用文档 - 支持多个AI提供商（OpenRouter、Fireworks、OpenAI、Anthropic等） - 配置保存在本地`~/.openwiki/.env` - 支持LangSmith追踪（可选） 适合需要保持代码文档同步更新的团队使用。

评论摘要
主要讨论点：如何为LLM/AI agent有效地管理和组织知识库 不同观点： • **结构化wiki维护派**（rrvsh）：认为应该维护高质量的结构化wiki，注重良好的结构和写作理解性，以便agent和人类都能有效查找信息。但坦承维护成本超出预期，质疑其他人是否采用更随意的方式（"shotgunning"） • **动态生成派**（dcreater）：质疑预先维护wiki的必要性，认为直接让agent"写文档"或使用定义明确的prompt/skill可能更高效，隐含观点是即时生成可能优于预先维护 补充讨论：这场讨论反映了AI知识管理中"预先组织 vs 即时生成"的权衡问题。核心矛盾在于：结构化wiki虽然查找效率高但维护成本大；动态生成虽然灵活但可能缺乏一致性。dcreater的问题实际上挑战了wiki方法的核心价值主张。
