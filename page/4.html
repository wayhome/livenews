文章摘要

文章讲作者用一颗8位AVR单片机搭建“网站服务器”：因以太网太快，改用SLIP串口联网，实现IP/TCP和硬编码HTTP响应；再借助Linux、WireGuard和反向代理，把MCU网页通过公网对外访问。

评论摘要
主要讨论点：围绕“用微控制器实现极简 Web 服务器”的技术可行性、历史背景、芯片选择与网络协议细节展开。 不同观点： • 历史对照派：有人提到 25 年前就有“最小 Web 服务器”竞赛，ACE1101 微控制器曾获胜，并引用“Webserver on a fly”等早期案例，说明此类项目有悠久传统。 • 芯片平台讨论派：有评论者赞赏 AVR DD/EA/EB 系列，但担心新出的 PIC32 CM 具备类似外设、5V、MVIO、事件系统且采用 ARM Cortex-M0+，可能让 AVR DD 显得过时。反方思路是：AVR 的低功耗、1.8V、以及 EA/EB 出色的 12-bit ADC 和可编程增益仍有优势。争议焦点是“核心架构重要，还是外设与功耗更重要”。 • 协议/实现细节派：针对 10BASE-T 的曼彻斯特编码，有人探讨 AVR EB 是否可借助 LUT、UART、PLL 定时器输出高速编码，但也怀疑能否达到 20Mbit 线速。 • 怀旧体验派：有人喜欢看到 HTML 实时逐步加载，联想到拨号上网时代图片从上到下渲染的体验。 • 协议严谨派：指出 RFC 1055 有 2025 年勘误，可能影响 SLIP 解码算法，并调侃下一步也许会涉及 RFC 1144。 • 现实应用派：有人认为“嵌入式/IoT 设备跑 Web 服务器”并不新鲜，并举例 8051 集成 10/100 Ethernet 的芯片。 补充讨论：还有“加载虽慢但可上线生产”的玩笑评论，整体氛围兼具技术考据、硬件选型争论和复古趣味。

Halt and Catch Fire

作者: ScottWRobinson | 评分: 140 | 评论数: 21 | 发布时间: 2026-05-16 18:16
文章摘要

文章介绍“Halt and Catch Fire”(HCF)的来源与含义：最初是工程师玩笑，指会让CPU锁死、需重启的非法指令。文中重点讲摩托罗拉6800未公开 opcode 会使地址总线连续读内存，类似“自毁”但不真起火，并追溯其在BYTE、IBM等案例中的历史。

评论摘要
主要讨论点：围绕“Halt and Catch Fire”非法指令/硬件起火传说、早期计算机的危险性与怀旧，以及同名美剧展开。 不同观点： • 早期设备确有“软件/操作导致硬件受损”的经历：有人因打印日志缺少 LF，行式打印机在同一位置高速打印而起火并触发 halon；PET 4032 若 POKE 误写视频控制器会让电子束停在屏幕中心烧坏荧光粉；老式放映机卡片也会被强光点燃。 • “IBM 360 非法 opcode 起火”被质疑：有评论直接认为这是都市传说；另有人提到教授讲过美军芯片有自毁指令，但也怀疑可能是由偶然 opcode/HCF 传闻演化而来。 • 技术讨论认为 HCF 更像“停机”而非真起火：6502 某些 opcode 会 JAM 让 CPU 停止，后期 CMOS 版本部分变成 NOP；这些未用 opcode 可用于 FPGA 扩展而不冲突。 • 对80/90年代计算的怀旧：评论认为当时硬件和软件更可理解、电脑更像工具，性能跃迁更令人惊叹，也不像今天的设备那样争夺注意力。 • 对同名美剧评价积极：多人称其很好看，捕捉了80/90年代计算机行业及德州奥斯汀、达拉斯的氛围；也有人提醒剧集打折。 补充讨论：有人提到“lp0 on fire”作为相关梗；另有评论抱怨疑似 AI 账号刷评论，属于偏离主题的社区讨论。
