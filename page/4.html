文章摘要

PyPI正在采取新措施，防止因ZIP解析器实现差异引发的混淆攻击。这些攻击可能利用ZIP文件格式的复杂性，绕过人工审核和自动化检测工具。具体措施包括拒绝含有无效记录、重复文件名、文件不匹配、尾部数据或错误目录定位值的ZIP档案。此外，PyPI将警告开发者上传的wheel包中ZIP内容与RECORD元数据不匹配的情况，并计划在2026年2月1日后拒绝此类上传。建议Python安装工具实现对wheel内容和RECORD文件的交叉检查，以增强安全性。目前，尚未有证据显示PyPI曾遭遇此类攻击。

评论摘要
主要讨论点：Python 安装工具和 ZIP 文件解压行为的兼容性及安全性问题 不同观点： • [zahlman 的观点] - 认为 Python 安装工具应该确保其 ZIP 实现遵循 ZIP 标准，并在解压前检查中央目录（Central Directory）。 - 指出 `zipfile` 模块已经实现了这一逻辑，使用 `zipfile` 可以避免相关问题。 - 质疑 `uv` 安装工具的解压行为不同于标准实现，可能来源于某个 Rust 库，并担忧其他 Rust 项目也可能存在类似问题。 - 提到 PyPI 已经实现了 ZIP 和 tarball 的压缩炸弹检测，但质疑 `zipfile` 是否能处理所有压缩炸弹问题，并询问是否存在有效的使用场景或规则。 • [captn3m0 的观点] - 对其他使用 ZIP 文件的包管理注册表是否能缓解 ZIP 混淆攻击表示好奇，并询问是否存在这样的例子。 补充讨论： • [jspiner 的观点] - 对文章表示感谢，但没有提出技术性问题或观点，主要是表达对讨论内容的兴趣。 争议焦点： • `uv` 安装工具的 ZIP 解压行为与标准 Python 库 `zipfile` 实现的不同，是否会导致潜在问题。 • `zipfile` 模块是否能够处理所有类型的压缩炸弹，以及是否需要明确压缩炸弹的规则或阈值。 其他值得注意的讨论点： • 对 Rust 项目中 ZIP 文件处理的潜在问题表示担忧，并提出了是否还有其他项目存在类似问题的疑问。 • 对其他包管理注册表如何应对 ZIP 相关安全问题表示好奇。
