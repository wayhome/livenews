文章摘要

Lune 是一个独立的 Luau 运行时，允许编写和运行 Luau 程序，类似于 Node、Deno 等语言的运行时。它采用 Rust 编写，以确保速度、安全性和正确性，提供完全异步的 API。Lune 具有简约但强大的接口，包含文件系统、网络和 stdio 的全功能 API，所有功能被打包在一个约 5MB 的可执行文件中。它还提供世界级的文档，并为 Roblox 开发者提供熟悉的运行环境和一个可选的内置库用于处理 Roblox 场所和模型文件。Lune 的目标不是让程序变得简短或运行完整的 Roblox 游戏，而是为不同用途提供支持。要开始使用，请访问其安装页面。

Ratatoi is a C libary that wraps stdlib's strtol (as atoi does), but it's evil.

作者: rept0id-2 | 评分: 26 | 评论数: 7 | 发布时间: 2025-05-21 19:00
文章摘要

Ratatoi是一个C语言库，用于替代标准库中的`atoi`函数。它的特点是，如果在转换过程中检测到溢出，它会调用`abort()`使程序崩溃并显示"Aborted (core dumped)"。这样设计是为了优先确保内存安全，而不是让程序在错误状态下继续运行，从而避免在每个使用`strtol`的地方手动检查错误。该项目采用MIT许可证，包含`ratatoi.c`、`ratatoi.h`等文件。目前有2个星标，无发布版本或包。

评论摘要
主要讨论点：对 `strtol` 函数的设计及其错误处理的讨论 不同观点： • **threeducks 的观点**：认为 `strtol` 设计不佳，返回值应为错误代码，而实际的转换结果应通过指针返回。目前的错误处理过程过于复杂，需要检查 `endptr` 和 `errno`，并且在调用前还需手动设置 `errno`。他指出，`strtol` 的手册示例代码长达50行，其中大部分是错误处理，这说明了其设计问题。此外，他认为应用程序中崩溃通常不是好的解决方案。 • **cmovq 的观点**：提出 `strtol` 的完整实现其实比其封装更短，如果不满意 `strtol` 的API或错误处理，可以直接自己实现一个。他提供了一个GCC库中的实现链接，并指出在Windows平台上由于 `long` 和 `int` 都是32位，因此需要用 `strtoll` 来处理溢出问题。 • **rept0id-2 的观点**：提到 Ratatoi 库封装了 `stdlib` 的 `strtol`，但如果检测到溢出，会调用 `abort()` 导致程序崩溃并出现 "Aborted (core dumped)" 错误。他认为这种方法优先考虑内存安全性，避免在程序中手动检查错误。 • **ksherlock 的观点**：指出在使用 `errno` 进行错误检查时需要注意，`errno` 只在发生错误时设置，并不会在成功时清除。如果在调用前 `errno` 已经被设置，则可能会导致不正确的错误处理。他建议在调用前保存 `errno`，并在调用后恢复，以避免这种问题。 • **kazinator 的观点**：质疑 `atoi` 是否封装了 `strtol`，并询问是否有文档说明这一点。 • **snarfy 的观点**：简短评论，提到“pun driven development”，可能是在调侃命名或开发中的双关语，未提出具体技术意见。 • **timewizard 的观点**：认为依赖 `abort()` 处理错误可能会导致DDoS攻击的风险，而不是正确处理自己的错误。他担心这种方法在面对外部输入时不够健壮。 补充讨论： • `strtol` 的错误处理复杂性和设计合理性是讨论的焦点，特别是关于是否应该使用 `abort()` 来处理错误。 • 不同平台（如Windows和Linux）对溢出处理的差异被提及，强调了跨平台开发中的潜在问题。 • 对 `errno` 的正确使用和保存是另一个值得注意的技术细节，错误的处理不当可能导致误判。 • 对 `atoi` 和 `strtol` 之间关系的疑问显示出对文档和实现细节的关注。 • DDoS 攻击风险的提出，将讨论从单纯的技术实现引向安全性和稳定性考虑。

“ZLinq”, a Zero-Allocation LINQ Library for .NET

作者: cempaka | 评分: 254 | 评论数: 15 | 发布时间: 2025-05-20 22:29
文章摘要

"ZLinq" 是一个为 .NET 设计的零分配 LINQ 库，由 Yoshifumi Kawai 开发，旨在通过使用结构体和泛型实现无内存分配。该库包括 LINQ to Span、LINQ to SIMD、LINQ to Tree（支持 FileSystem、JSON、GameObject 等），并提供源代码生成器以替代任意类型。它支持多平台，如 .NET Standard 2.0、Unity 和 Godot，且在 GitHub 上已获得超过 2000 星。 ZLinq 实现了 .NET 10 中所有方法的 100% 覆盖，具有 99% 的行为兼容性，并通过 SIMD 支持等优化在性能上超越传统 LINQ。在基准测试中，ZLinq 在链式调用中保持零分配，而普通 LINQ 分配会随方法增加而上升。 使用 ZLinq 只需调用 `AsValueEnumerable()`，并兼容所有 .NET 版本。此外，ZLinq 提供源代码生成器，可选择性消除对 `AsValueEnumerable()` 的需求，便于集成。 总体而言，ZLinq 在大多数实际场景中表现出色，尤其在减少内存分配和提高性能方面具有显著优势。

文章摘要

Ben Johnson 介绍了 Litestream 及其最新改进。Litestream 是一个开源工具，允许在 SQLite 上运行全栈应用，通过将数据库更新持续流式传输到对象存储（如 S3），确保应用在服务器故障时可恢复。最初设计中，Litestream 通过“影子 WAL”记录更改，但恢复时需重放所有更改，速度较慢。为了改进，作者借鉴了 LiteFS 的设计，采用交易感知的方式，使用 LTX 文件记录排序后的页面更改，通过压缩减少重复页面，实现快速的时间点恢复。此外，Litestream 还解决了同步问题，通过现代对象存储的“条件写入”功能实现主实例的唯一性，从而简化读副本和故障切换操作，无需像 LiteFS 那样依赖外部工具如 Consul。Litestream 因其简便性而更受欢迎。
