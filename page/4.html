XZ Utils Backdoor Still Lurking in Docker Images

作者: torgoguys | 评分: 71 | 评论数: 9 | 发布时间: 2025-08-19 00:07
文章摘要

2025年8月12日，Binarly研究团队发现尽管XZ Utils后门事件已过去一年多，但仍有35个以上包含该后门的Docker镜像在Docker Hub上公开可用。该后门通过修改liblzma.so库中的函数钩子，影响OpenSSH服务器的安全性。团队使用15TB的Docker镜像数据集进行分析，发现12个Debian基础镜像仍受感染，甚至有些新镜像基于这些受感染镜像构建，形成了间接感染。虽然数量看似不多，但由于仅扫描了部分镜像且专注于Debian系统，实际受影响范围可能更大。

评论摘要
主要讨论点：Docker 镜像的安全性问题，特别是涉及 XZ 后门的案例。 不同观点： • **Docker 是安全隐患**（DiabloD3）：认为 Docker 及其依赖包普遍存在安全漏洞，除非自行构建镜像，否则不可信。建议使用传统虚拟机或官方编排工具。 • **Debian 已修复问题**（dima55）：指出问题已由 Debian 修复，但 Docker 镜像用户未能受益于这些修复，因为他们不使用标准的 Debian 安装方式。 • **问题被夸大**（creatonez）：认为标题过于耸人听闻，XZ 后门从未进入 Debian 稳定版，问题在于用户使用了未更新的测试版镜像。移除漏洞镜像可能破坏可重现构建。 • **社区镜像问题**（burnt-resistor）：批评使用未经审核的社区镜像而非维护良好的系统，导致漏洞长期存在。 • **Docker 普遍不安全**（sugarpimpdorsey）：认为大多数 Docker 镜像本身缺乏基本安全措施，运行在 root 权限下，后门问题只是冰山一角。 补充讨论： • **漏洞触发条件**（jchw）：质疑有多少容器会实际触发后门，因为 OpenSSH 在容器中并不常见。 • **替代方案建议**（LeoPanthera）：建议开发者从 XZ 迁移到 lzip，认为后者是更优的 LZMA 容器格式。 争议焦点： • 问题的严重性：部分评论认为问题被夸大（如 creatonez），而其他人坚持 Docker 和社区镜像存在系统性风险（如 DiabloD3、burnt-resistor）。 • 解决方案：是移除漏洞镜像（可能破坏构建）还是依赖用户自行更新和维护系统。

文章摘要

MCP doesn't need tools, it needs code

作者: the_mitsuhiko | 评分: 121 | 评论数: 21 | 发布时间: 2025-08-18 09:53
文章摘要

这篇文章讨论了使用命令行工具(CLI)与模型上下文协议(MCP)的优缺点对比。作者指出CLI工具存在平台依赖、版本兼容性和文档不全等问题，特别是处理非ASCII字符输入时容易失败。虽然CLI工具可通过bash组合使用，但需要维护会话状态，这对智能代理来说是挑战。相比之下，MCP能保持状态但缺乏组合能力。作者建议将MCP服务器设计为只暴露一个"超级工具"——实质上是运行eval()的Python解释器，既能保持状态又能利用已有工具功能。文章最后介绍了pexpect-mcp实验项目，展示了这种思路的实现。

评论摘要
