oavif: Faster target quality image compression

文章摘要

Loko Scheme: bare metal optimizing Scheme compiler

作者: dTal | 评分: 118 | 评论数: 5 | 发布时间: 2025-10-07 07:41
文章摘要

Loko Scheme 是一个优化的 Scheme 编译器，支持 R6RS 和 R7RS Scheme 标准，采用 Concurrent ML 实现并发。它能交叉编译到 Linux/amd64、NetBSD/amd64 和裸机 amd64 平台，性能良好。该项目提供多种安装方式（Git、Docker、包管理器等）和一个可启动的硬盘镜像。Loko Scheme 适用于构建静态链接并发应用、系统研究、unikernel 实验等场景，自带有限硬件支持（网络、磁盘、视频等）。目前支持传统 PIC 硬件，最新机器可能无法运行。采用 EUPL-1.2-or-later 许可，开发者可通过邮件报告问题或在 IRC 讨论。

评论摘要
主要讨论点：[Loko Scheme的实现特点及其潜在应用] 不同观点： • [对Loko Scheme的赞赏与期待] - pjmlp认为这是一个很好的成就，延续了Lisp工作站的梦想，并希望看到更多类似努力而非UNIX克隆。 - wkjagt对将其用于老旧笔记本电脑表现出兴趣，尽管目前仅支持串行连接。 - mark_l_watson喜欢其在裸机上运行的特点，并询问是否支持macOS，同时称赞了网站设计。 - pkphilip对其裸机运行能力表示兴趣，并寻求更多文档。 • [对并发模型的疑问] - JonChesterfield指出Loko的并发模型基于Concurrent ML（CML），但文档未提及通道（channels）且纤程（fibres）基于有限续延（call/cc），可能缺少CML中的一些高级特性（如死锁线程的垃圾回收）。 补充讨论： - 争议焦点：JonChesterfield的观点引发了关于Loko并发模型是否完整的讨论，尤其是与CML相比的功能缺失。 - 其他讨论点：用户对文档和教程的需求（pkphilip），以及对跨平台支持的关注（mark_l_watson）。

How I'm using Helix editor

文章摘要

本文作者分享了从Neovim切换到Helix编辑器的经验，主要包含三部分内容：1) 通过tmux配置解决Helix缺少文件管理器和Git界面的问题，使用yazi和lazygit作为替代工具；2) 调整Helix的键位绑定，使其更接近Vim的操作习惯；3) 自定义状态栏和实用快捷键，如文件重载、软换行切换、Git撤销等，以提高编辑效率。作者认为这些调整能帮助其他开发者更顺利地过渡到Helix编辑器。

评论摘要
主要讨论点：[编辑器选择与配置：Emacs、Vim/Neovim、Helix的比较与优缺点] 不同观点： • **Emacs优势派** - 强调现代Emacs（30+版本）内置功能强大，减少了对第三方插件的依赖（如Eglot替代lsp-mode）。 - 核心插件需求少（如Magit、Expreg），但仍保留高效生产力工具（如Consult + orderless）。 - 长期用户（10年以上）认为其高度可定制性无可替代。 • **Helix新兴支持者** - 赞赏Helix的简单性和开箱即用体验（如LSP集成、全局搜索）。 - 认为其设计连贯、默认配置合理，适合快速上手（对比Neovim需复杂配置）。 - 但承认局限性：缺乏插件生态（如无终端集成）、无法复用Vim肌肉记忆。 • **Neovim/Vim传统派** - 认为Neovim插件生态丰富（如LazyVim），可通过配置逼近Helix的交互逻辑。 - 部分用户偏好轻量Vim8配置（如仅用vim-fugitive、ale），强调供应链安全（减少插件更新）。 - 争议焦点：Helix是否只是“重新发明轮子”，且依赖隐性依赖项。 补充讨论： - **供应链安全争议**：部分用户因担心Neovim插件攻击面转向Helix，但反对者指出Helix依赖项不透明。 - **工具场景分化**： - 简单编辑场景：Helix或轻量Vim更优。 - 复杂开发：Emacs/Neovim凭借插件生态（如调试、Git集成）胜出。 - **社区态度差异**：Helix用户较少对比其他编辑器，而Neovim用户常主动对比，被指“防御性”反应。
