Spoofing OpenPGP.js signature verification

作者: ThomasRinsma | 评分: 53 | 评论数: 3 | 发布时间: 2025-06-10 13:58
文章摘要

这篇文章讨论了OpenPGP.js库中的一个安全漏洞（CVE-2025-47934），该漏洞允许攻击者在获得目标签名者（如"Alice"）的有效签名后，伪造任意签名，使OpenPGP.js用户误以为这些伪造的签名来自该签名者。漏洞的核心问题在于处理PGP消息格式时，OpenPGP.js错误地验证了包含额外数据包的畸形消息。具体而言，攻击者可以在合法签名后添加无效的压缩数据包，导致OpenPGP.js错误地将恶意消息验证为合法签名数据。文章提供了概念验证代码示例，展示了如何利用该漏洞。该漏洞已在OpenPGP.js的v5.11.3和v6.1.1版本中修复。

评论摘要
主要讨论点：PGP加密系统的设计缺陷和其带来的安全问题 不同观点： • [tptacek]: - 认为PGP的设计不正常，现代加密系统已经不再使用类似PGP的“包”（packet）格式。 - 指出PGP的设计缺乏合理的设计原则，存在问题是由于路径依赖（历史原因）。 - 主张抛弃现有PGP系统，重新设计，即使新的设计仍称为“PGP2”也没关系。 • [woodruffw]: - 强调PGP生态系统每年都会出现关键的解析漏洞。 - 引用Latacora的文章，指出PGP编码过于复杂，且这可能还不是PGP最严重的问题。 - 提到2022年有人向oss-sec发送了武器化的压缩包作为例子，进一步说明PGP的问题。 补充讨论： • PGP的设计复杂性和历史遗留问题被认为是其主要缺陷的原因。 • 有人认为PGP的编码复杂性不仅仅是技术问题，还涉及到其在实际应用中的安全隐患。 • 具体实例（如2022年武器化压缩包事件）显示了PGP在实际应用中的漏洞如何被利用。 • 争议的焦点在于是否应彻底抛弃PGP，重新设计新的加密系统以解决现有问题。

文章摘要

Pydoll 是一个用于自动化控制基于 Chromium 浏览器的库，无需 WebDriver，提供更真实的交互体验。它通过直接连接 Chrome DevTools Protocol (CDP) 来避免传统的外部驱动程序和兼容性问题，并能智能绕过 Cloudflare Turnstile 和 reCAPTCHA v3 等现代网站保护系统。Pydoll 模拟人类行为，如自然的鼠标移动和打字节奏，使自动化脚本难以被检测为机器人。其特点包括原生异步性能、强大的事件系统、直观的元素查找和健全的类型安全。安装简单，通过 `pip install pydoll-python` 即可使用，无需额外配置。

评论摘要
主要讨论点：围绕使用CDP（可能是Chrome DevTools Protocol）进行网页爬虫和自动化处理的技术讨论，包括其可行性、应用场景以及可能带来的滥用问题。 不同观点： • [mfrye0] 提出CDP是否仍能不被检测到的问题，质疑当前是否已有方法绕过检测，或者用户通过自动化处理验证码的方式来应对。 • [renegat0x0] 支持使用CDP，并提到自己正在开发一个集成工具包（AIO package），该工具可以通过爬虫服务器抓取页面内容并返回JSON格式的结果，认为这种方法可以避免多次设置Selenium的麻烦。他还分享了一个GitHub链接供他人使用。 • [jdnier] 对工具可能被滥用表示担忧，虽然没有详细阐述，但提出了道德和使用边界的问题。 • [nickspacek] 提到自己在使用某些ISP和浏览器配置时经常遇到CloudFlare和reCaptcha的验证，建议开发一种能够自动解决验证码的代理服务器，以提高用户体验。 • [hk1337] 认为CDP能解决Chrome浏览器兼容性问题，但指出自己使用Firefox和Selenium时并没有遇到类似的更新问题，并对该工具与MechanicalSoup进行了对比，指出两者在异步处理上的区别。 • [whall6] 简短评论，指出网页爬虫与反爬虫技术之间的持续对抗，暗示这种技术会不断演变。 • [bobbyraduloff] 对如何处理验证码的技术细节感兴趣，询问是否有相关文档或说明。 补充讨论： • 争议的焦点之一是工具的潜在滥用问题，[jdnier] 提出了对工具被不当使用的担忧，但未展开。 • [nickspacek] 则从用户体验的角度出发，认为自动化处理验证码有其合理性，尤其是在验证码频繁出现的情况下。 • 技术实现细节也是讨论的重要部分，[mfrye0] 和 [bobbyraduloff] 都对如何处理验证码表示关注，而 [renegat0x0] 分享了具体的实现和工具链接，提供了实际的技术方案。 • [hk1337] 的观点则集中在不同浏览器和工具之间的对比上，提出了Firefox作为替代方案的经验。
