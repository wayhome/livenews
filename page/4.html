A Python dict that can report which keys you did not use

作者: gilad | 评分: 64 | 评论数: 11 | 发布时间: 2025-07-27 02:22
文章摘要

文章介绍了一种名为 `TrackingDict` 的 Python 字典子类，能够追踪哪些键被访问过。这在处理大型数据对象或确保从数据库获取的所有数据都在报告中使用时非常有用。`TrackingDict` 通过重写 `__getitem__` 方法记录被访问的键，并提供了两个属性：`accessed_keys` 返回已访问的键，`never_accessed_keys` 返回未访问的键。文章还提供了一个示例，展示如何使用 `TrackingDict` 来检查哪些键在使用中未被访问。最后，文章更新了一个带类型提示的版本，并讨论了该实现的一些潜在问题和改进建议，例如对 `.get()` 方法的支持。

文章摘要

Maintaining weight loss

Making Libcurl Work in WebAssembly

文章摘要

本文介绍了如何在不修改代码的情况下，使基于libcurl的应用程序在WebAssembly中通过WebSocket代理实现网络通信。由于WebAssembly无法直接进行TCP连接，因此通过在服务器端运行websockify代理，将TCP连接封装成WebSocket连接，从而使libcurl可以正常工作。 关键步骤包括： 1. 使用WebSocket代理服务器（websockify）处理TCP连接。 2. 解决浏览器混合内容安全策略问题，建议使用wss://（安全WebSocket）而非ws://。 3. 通过设置SOCKS5代理服务器，使libcurl能够连接到任意HTTP服务。 具体实现可参考GitHub上的示例项目（https://github.com/r-wasm/ws-proxy）。这样，无需对现有代码进行大幅修改，即可使libcurl在WebAssembly环境中正常运行。

评论摘要
主要讨论点：通过WebAssembly和Websocket实现网络请求的优化及其实现细节 不同观点： • [vk6] 认为通过Websocket使用SOCK5的方式会导致多次往返延迟，尤其在远程代理服务器的情况下，延迟会非常明显。为解决该问题，他提出了一种新的协议（wisp-protocol），通过让多个TCP socket共享同一个Websocket连接，并通过客户端提前假设新socket创建成功来减少延迟。他也提到，尽管使用了不同的编程语言（如Rust或Python）实现代理服务器，性能瓶颈通常在于Linux的TCP栈，而非语言本身。 • [kamranjon] 对文件下载后的存储位置感到困惑，不确定文件是存储在浏览器内存中、通过Websocket传输到后端服务，还是使用新的文件系统API写入本地磁盘。 • [immibis] 质疑为什么在浏览器环境中还需要libcurl，指出这通常是为了让未针对浏览器环境设计的第三方代码能够运行。 补充讨论： • [vk6] 提到其最初的方案是通过SOCK5和Websocket结合，但发现延迟问题严重，因此开发了新的协议来优化。他还指出，在Emscripten中实现这种优化需要通过正则表达式修改生成的JavaScript代码。 • [vk6] 强调了不同主机请求或不支持HTTP/2的情况下，原方案的性能问题尤为突出，进一步论证了其新协议的必要性。 • [immibis] 的评论指出了一种潜在的误解，即在浏览器中使用libcurl的原因，明确了这是为了兼容未针对浏览器设计的代码。 争议焦点： • 主要争议在于是否需要在浏览器中使用libcurl，以及通过Websocket实现网络请求的实际效果和优化必要性。
