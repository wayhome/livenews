Open Memory Protocol – One Memory Store for Claude, ChatGPT, Curso

作者: soji_mathew | 评分: 26 | 评论数: 4 | 发布时间: 2026-06-30 00:05
文章摘要

这是 **Open Memory Protocol (OMP)** 的介绍文档。OMP 是一个开放标准，用于解决 AI 工具之间的"记忆孤岛"问题——不同 AI 工具（如 Claude、ChatGPT、Cursor）无法共享用户上下文和偏好设置。 **核心方案**：通过统一的协议规范、自托管服务器、SDK 和适配器，让所有兼容 OMP 的 AI 工具能够存储、检索和共享用户记忆。用户可以在 Claude 中进行对话，然后无缝切换到 ChatGPT 继续，所有上下文都保留在用户自己控制的服务器上。 **快速使用**：一行命令启动服务器，配置 Claude Desktop 连接，AI 就能自动记忆并跨工具共享信息。

评论摘要
主要讨论点：AI助手的记忆与上下文管理方式 不同观点： • **支持统一记忆库的观点**（andrewinardeer）：通过RAG（检索增强生成）将Obsidian笔记与AI会话同步，当上下文中没有信息时自动搜索RAG。认为这种方式运作良好。 • **质疑统一记忆的观点**（jcutrell）：认为记忆架构的核心价值在于上下文塑造（context shaping），而不仅仅是共享存储空间。如果只需要通用内存空间，用符号链接、云同步或Obsidian就足够了。批评"一站式记忆"方案的实用性不比普通markdown强多少，因为缺少了让记忆真正有用的上下文筛选和组织能力。 • **负面评价**（brcmthrowaway）：简单评论"Slop alert"（垃圾警告），表达对讨论内容或某种做法的否定态度，但未展开具体论据。 补充讨论：争议焦点在于AI记忆系统应该追求"全量存储+检索"还是"精心设计的上下文架构"。前者强调技术可行性和便利性，后者强调记忆组织的质量和针对性。

主要讨论点：正式验证（Formal Verification）在实际软件开发中的可行性和局限性，特别是AI辅助验证的潜力 不同观点： • **怀疑派（dfabulich）**：正式验证对大多数应用开发者仍然过于受限。电商等CRUD应用99%是I/O操作（数据库、UI、第三方API），而验证只能覆盖无副作用的核心逻辑，无法证明端到端的正确性。即使是基于属性的测试对这类应用也帮助有限。 • **实践派（GregDavidson）**：在开发过程中使用正式验证，让证明需求引导代码开发。结果是更简洁、高效的程序，调试工作量极少。但强调不会对常规流程编写的代码进行事后验证，且证明维护是痛点。 • **谨慎乐观派（thewillowcat）**：承认验证大型代码难度巨大，但认为AI自动化可能改变局面。在特定领域（如文件格式解析器）已经适用，主要障碍是开发者缺乏时间和知识。 • **成本质疑派（pron）**：质疑AI降低验证成本的论点。无论人工编写证明还是AI生成，成本依然存在。如果验证比测试贵100倍，用AI后可能仍然如此。 • **根本问题派（jongjong）**：指出"规范本身才是问题"。规范必须和代码一样详细和准确，否则验证毫无意义。安全属性如果不在规范中，验证就无法发现缺陷。 补充讨论：有人分享实际项目（Qed）和教学经验（Dafny），也有人质疑现实世界中状态冲突（如地震、客户去世）难以完全建模。
