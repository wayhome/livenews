Show HN: I built a Rust crate for running unsafe code safely

作者: braxxox | 评分: 98 | 评论数: 18 | 发布时间: 2025-04-06 13:28
文章摘要

`mem-isolate` 是一个 Rust crate，旨在通过使用 `fork()` 系统调用安全地运行不安全代码。它会在子进程中执行用户提供的函数，确保该函数不会影响父进程的内存状态，实现内存隔离。主要特点包括： 1. **内存纯净性**：即使函数存在内存泄漏或堆碎片化问题，也不会影响主进程。 2. **跨进程通信**：通过管道在父子进程间传递结果，使用序列化（如 `serde`）处理数据。 3. **性能开销**：每次调用引入约 1ms 延迟，适合对内存安全要求高的场景。 4. **系统支持**：仅支持 POSIX 系统（如 Linux, macOS），不支持 Windows 和 WebAssembly。 该工具适用于运行可能导致内存问题的代码，如 FFI 调用或不安全代码，通过隔离确保主程序的稳定性。

评论摘要
主要讨论点：Rust中的安全内存处理与隔离技术，特别是在处理不安全代码时的方法和问题。 不同观点： • woodruffw认为，Rust中的"safe"不仅仅意味着不会因为空间内存错误而崩溃，还意味着代码在空间和时间上都是内存安全的。他指出，有些内存不安全问题并不会导致可检测的故障，因此Rust的安全性比仅避免崩溃要强得多。 • nextaccountic提出了一种不通过创建新进程来隔离本地代码的方法，即通过将不安全的代码编译为WebAssembly，然后再转换为C代码，从而将未定义行为限制在逻辑错误范围内，而不是内存损坏。 • destroycom不建议在多线程应用中使用fork API，因为可能导致死锁和内存分配问题，尤其是在fork和exec调用之间存在其他操作时。 • pjmlp主张从一开始就设计多进程应用，并使用操作系统IPC和沙盒API，认为即时伪沙盒化是过时的且有问题的方法。 • TheDong指出，某些Rust代码在隔离环境中执行时可能不会按照预期工作，特别是涉及内部可变性时，这可能导致不正确的结果。 • wavemode认为，如果为了运行潜在的不安全代码而牺牲性能，那还不如使用具有垃圾回收机制的语言。 • Svetlitski和kelnos都强调了在多线程程序中使用fork()的危险性，特别是可能导致死锁和其他问题，建议在使用时要非常小心。 • null_investor认为，fork()和某些包在处理非常不安全代码时可能有用，但不建议频繁使用，因为可能会失去Rust相对于Python或Ruby的性能优势。 • dijit提到在Windows上调用Win32 API时缺乏有效的内存调试工具，并询问是否有适合Windows的工具来帮助调试内存问题。 • corank质疑如果不可安全代码需要进行内存mutation（例如实现双向链表）时，这种隔离方法是否适用。 • jesprenj对使用管道而非共享内存进行通信提出了疑问。 补充讨论： • syrusakbary对结合WebAssembly和隔离技术以获得更高安全性表示兴趣，并赞赏了该项目的创新性。 • 讨论中还涉及到具体工具和技术的使用，如wasm2c工具和fork()的实际应用问题，以及多线程程序中可能面临的挑战。 争议焦点： • 使用fork()在多线程应用中的安全性及其可能导致的复杂问题（如死锁）是主要争议点。 • 如何有效隔离和运行不安全代码，以及在性能和安全性之间的权衡，也是讨论的核心。

文章摘要

文章主要讨论了科技公司中工程师常犯的一个误区：他们过于专注于不直接创造利润的工作（如技术债务、无资金项目、重构等），却忽略了公司存在的核心目的是赚钱。文章将这种现象比作投票支持解雇自己的人，指出工程师如果不能将自己的工作与公司利润挂钩，职位就不稳定。科技公司由一小群人运营，目标是盈利，工作价值与其对公司利润的贡献成正比。作者建议工程师要了解公司的商业模式，并确保自己的工作支持该模式，否则可能面临失业风险。简单来说，工程师需要清楚公司如何赚钱，并让自己的工作与之相关联，以保持职位稳定。

评论摘要
主要讨论点：如何在工作中体现技术工作的长期价值，特别是在大型企业环境中，以及技术工作与商业利益之间的矛盾。 不同观点： • **bruce511** 认为，技术工作的价值不仅仅在于解决当前问题（如技术债务），还要能够展示其对未来十年的影响，并以直接的商业利益（如速度、可靠性、减少支持成本）来证明其价值。他强调技术人员需要主动向管理层“推销”自己的工作成果，而不仅仅是期待管理层自行发现。 • **mirawelner** 表达了对大型科技公司内部环境的不满，认为其中存在腐败和自私行为，因此选择进入大学和初创企业工作。然而，他的经历（部门被取消资金）表明，即使在学术或小型企业环境中，也存在不稳定性与风险。 • **lesuorac** 指出，资本主义体系与许多技术人员的个人价值观存在冲突。尽管提升无障碍功能（如屏幕阅读器支持）等技术改进能够显著改善人们的生活，但这些工作未必能为公司带来直接的利润。因此，追求利润最大化往往意味着技术人员需要专注于高需求领域，而不是最有社会价值的工作。 • **beacon294** 认为，问题的关键不在于工作是否直接盈利，而在于工作是否受到管理层的青睐。他警告说，技术人员需要小心选择项目，以免在环境变化时成为“替罪羊”，同时指出预测管理层的偏好变化是困难的。 补充讨论： • 技术工作与商业利益之间的矛盾是讨论中的核心问题，特别是在大公司环境中，技术人员不仅需要解决技术问题，还需要证明其工作的商业价值。 • 不同背景下的工作环境（如大型企业、学术界、初创公司）都有各自的挑战和不稳定性，选择合适的工作环境取决于个人的价值观和职业目标。 • 技术人员在工作中面临的不仅是技术挑战，还有如何在资本主义体系中平衡个人理想与现实需求的问题。

Neurotoxic worms growing up to 3ft long are in Ontario, Canada

作者: amichail | 评分: 24 | 评论数: 5 | 发布时间: 2025-04-06 22:23
文章摘要
