文章摘要

Positron 是 Posit PBC 推出的一款免费、下一代数据科学集成开发环境（IDE）。它是一个可扩展的多语言工具，支持编写代码和探索数据，并提供可重现的创作和发布环境。Positron 基于 Code OSS，用户可以参考 VS Code 文档了解基本功能。要开始使用 Positron，用户可以下载安装程序，查阅用户指南（如选择解释器和数据探索器），并通过 GitHub Discussions 提供反馈。Positron 采用 Elastic License 2.0 许可协议，其商标归 Posit Software, PBC 所有。

Modernish – A library for writing programs for POSIX-based shells and utilities

作者: sundarurfriend | 评分: 67 | 评论数: 8 | 发布时间: 2025-07-21 15:42
文章摘要

Modernish 是一个用于编写健壮、可移植、可读和强大的 POSIX shell 脚本和实用工具的库。它提供了更安全的变量与命令扩展、新的语言结构（如循环迭代）等功能，增强了传统 shell 脚本的编写体验。Modernish 完全用 shell 语言编写，无需安装二进制代码，适用于多种 shell 实现，并可在嵌入式或多用户系统中部署。它还允许将库与脚本打包，确保在任何 Unix-like 系统上运行。该项目寻求测试者与开发者加入，以进一步完善库的功能和兼容性。文档提供了详细的使用说明和示例代码。

评论摘要
主要讨论点：关于Unix shell脚本工具的现代化及其实际应用的讨论 不同观点： • jonathaneunice认为，尽管像sh、bash、zsh等shell的演进值得赞赏，但本质上它们仍然只是shell体验，而非完整的编程语言体验。他指出，对于处理复杂任务（如时间戳、JSON解析、并发管理等），使用完整的编程语言（如Python）具有更好的语义、类型系统、异常处理、模块化、数据结构和工具支持。因此，对于任何具有一定复杂性的任务，他更倾向于选择完整的编程语言。 • lioeters提供了一个具体的代码示例，展示了如何使用Modernish工具简化和增强传统shell脚本的功能。通过对比Plain POSIX sh和Modernish的实现，lioeters试图展示Modernish在处理复杂任务时的优势。 • pimlottc指出，文档在展示实际命令方面不够直观，建议在文档开头添加简短的代码示例，以便用户快速了解工具的使用方法，特别是在移动设备上浏览时。 • cmcconomy表示，虽然欣赏Modernish这样的工具，但他更倾向于使用系统默认安装的工具，以确保在不同主机间无缝工作。 • amterp对现代命令行脚本领域表现出兴趣，但更希望远离Bash中的控制流和循环编写。他提到正在开发一种更接近Python风格的CLI脚本语言（RAD），尽管其适用场景与Modernish略有不同。 • leonheld赞赏Modernish完全用shell编写，没有其他依赖，认为这是许多尝试“振兴”sh的工具所忽视的重要特性，并表示会采用Modernish。 • cb321对Modernish的`use`函数提出了改进建议，认为应该让`use`处理整个参数列表，以便在单行中实现“方言调整”，从而提高代码的简洁性和灵活性。 补充讨论： • lorenzohess仅对工具的名称表示赞赏，没有进一步展开讨论。 争议的焦点： • 主要争议点在于是否应继续使用shell脚本工具，还是转向更强大的完整编程语言来处理复杂任务。jonathaneunice主张使用Python等语言，而lioeters和leonheld则支持通过工具如Modernish来增强shell脚本的功能。

作者: AndrewDucker | 评分: 129 | 评论数: 21 | 发布时间: 2025-07-24 12:29
文章摘要

WiX Toolset项目计划引入开放源代码维护费，以支持项目的长期可持续性。从2025年4月5日发布的WiX v6.0起，所有利用WiX Toolset创收的用户需通过GitHub Sponsors支付维护费。费用标准为：少于20人的小组织每月10美元，20至100人的中等组织每月40美元，超过100人的大组织每月60美元。此费用不适用于WiX Developer Direct的支持协议客户。相关步骤包括获取最终用户协议（EULA）、将其添加到.nupkgs、设置GitHub赞助层级以及更新README文件。

评论摘要
主要讨论点：WiX Toolset 开源项目的维护者引入了开放源代码维护费（Open Source Maintenance Fee），引发了社区的不同反应和讨论。 不同观点： • **支持创新和维护者权益**：一些用户如 trjordan 认为这是一个聪明的解决方案，能够解决开源项目维护中的常见问题。维护者的时间和精力有限，尤其在面对企业用户时，他们希望获得相应的收入回报。通过引入维护费，维护者可以自由选择是否为付费用户提供支持，非付费用户则保持原有的体验。这种做法可以有效应对企业依赖开源软件却不回馈社区的问题。 • **质疑创新性和执行复杂性**：freeopinion 和 opticfluorine 等用户认为该方案并没有真正的创新。开源作者一直以来都可以选择是否接受贡献或者对某些问题提供支持。他们质疑这种收费方式是否必要，并认为这可能只是为了迫使商业用户支付费用。同时，Arch-TK 提出，直接对二进制文件和问题追踪器收取订阅费可能更简单有效，而不是依赖最终用户许可协议（EULA）来执行收费。 • **道德和开源精神的冲突**：一些用户如 kissgyorgy 认为，要求支付费用违背了开源精神的初衷，即自由使用和修改软件而不必对任何人负责。当项目开始收费时，用户可能会产生期望和要求，这使得项目维护变成了类似工作的负担。opticfluorine 也提到，这种做法让他感到不舒服，认为这是一种误导或恐吓策略。 • **法律和许可问题**：calibas 和 guluarte 等用户对项目的许可和法律细节提出了疑问。例如，WiX Toolset 的源代码是根据微软回收许可证（MS-RL）发布的，这意味着用户可以自行编译并用于商业用途。因此，用户可能通过自行编译代码来规避维护费用，这使得收费策略的执行变得困难。 补充讨论： • **界面和使用体验问题**：lars_francke 提到开放源码维护费的官网在浅色模式下不可读，并且其代码仓库不允许提交问题，这也影响了用户体验。 • **社区和贡献的讨论**：freeopinion 指出，如果用户对项目现状不满意，可以选择创建分支（fork），但这是一项重大承诺，通常需要资金支持。其他用户如 mellosouls 提供了相关消费者常见问题链接，帮助解答其他用户的疑问。 • **对开源软件付费的普遍看法**：一些用户如 cyberes 和 optymizer 理解并支持开源项目收费的做法，认为这能激励维护者继续投入项目，尤其是在长期缺乏资金支持的情况下。optymizer 更进一步指出，开源社区普遍存在的“饥饿艺术家”模式对项目的长期发展不利。 争议焦点： • **收费的合理性和执行问题**：用户对收费的合理性及如何有效执行收费策略存在分歧。一方认为收费是维护者应得的回报，另一方则认为这违背了开源精神，并且在法律上可能存在规避空间。

The future is not self-hosted

作者: drew_lytle | 评分: 77 | 评论数: 30 | 发布时间: 2025-07-25 12:00
文章摘要

本文讨论了亚马逊Kindle用户无法再将电子书下载到电脑上的问题，质疑用户是否真正拥有这些书籍，还是仅仅是从亚马逊“租用”它们。文章指出，数字商品一直以来都是以授权形式购买，而非真正拥有。这种情况不仅限于媒体，还包括存储在各大公司服务器上的个人数据。作者讲述了自己通过自建云服务器，摆脱大公司控制，完全拥有和掌控自己数字生活的经历。自托管（self-hosting）是指在自己的硬件上运行服务器和应用程序，虽然工作量大，但对追求控制权和自由的人来说具有吸引力。作者详细介绍了自己搭建家庭服务器的过程，并认为自托管虽不易普及，但对重视数据自主的人是一个选择。

评论摘要
主要讨论点：自托管（self-hosting）的可行性、复杂性、隐私性以及社区协作的可能性 不同观点： • MoreQARespect认为，自托管目前类似于iPhone出现前的手机世界。技术爱好者已经在使用这些工具，但普通用户尚未接受，因为设置过程繁琐且缺乏美观、符合人体工学的体验。一旦自托管变得无缝且易用，需求可能会迅速增长。 • stego-tech同意自托管优于企业云服务，但指出其复杂性和成本使其不适合普通用户。同时强调，隐私、安全和主权问题需要更广泛的讨论，并提出公共数据中心和基础设施的设想，呼吁开源项目简化部署流程。 • hermitcrab强调了网络应用（SAAS）的流行，但指出了订阅模式的长期成本问题，认为下载软件仍有其优势，如一次性付费和数据本地存储。 • bix6指出，许多人没有意识到他们放弃了多少隐私，并以自己为例说明通过自托管获得隐私的难度和工作量。 • jqpabc123认为，社区托管需要超越个体主义，但目前仍缺乏对系统管理员的激励机制，最终可能仍需依赖企业服务。 • singpolyma3质疑将自托管等同于在家中拥有物理服务器的观点，提出通过SSO技术实现自托管和社区协作的可能性。 • torium引用Stallman的观点，推荐不需要互联网连接的Pocketbook电子书阅读器，以避免数字内容限制。 • palata讨论了“托管托管”服务，如Hetzner或Infomaniak提供的Nextcloud实例，认为这是一种简化和安全的选择，但仍存在数据访问问题。 • hengheng不信任社区托管，担心E2E加密无法证明，以及社区共享服务器可能被没收的风险。 • dathinab建议立法强制规定数字内容购买的透明度和可用性，反对企业滥用商业行为。 • kbody提到Umbrel等项目提供了良好的用户体验，并认为更好的家庭互联网连接将使自托管更加普及。 • V__不同意一些作者的观点，认为自托管更多是关于数据和软件的控制，而非硬件的位置，并质疑社区云服务的可行性。 • mmstgshj提到disroot.org已经在提供部分E2EE服务，并明确标示哪些服务是E2EE。 • will5421询问是否可以通过VPN让朋友访问自托管服务器，提出创建共享相册的可能性。 补充讨论： • 自托管的复杂性和用户体验是讨论的核心，许多人认为需要简化和美化以吸引更多用户。 • 社区托管和协作的可能性被多次提及，但存在信任、技术可行性和法律风险等争议。 • 数字内容的拥有权和可用性问题引发了对现行商业模式和立法的批评。 • 不同用户对隐私、安全和便利的优先级不同，导致对自托管和社区托管的看法多样化。

文章摘要

文章揭露了伦敦皮卡迪利广场一系列礼品店通过频繁更换法律所有者（"phoenixing"）来逃避巨额税收的问题。这些店铺由英国亿万富翁Asif Aziz创办的Criterion Capital管理。调查发现，许多礼品店的注册地址是虚假或废弃的，如一个堆满垃圾的停车场。尽管这些店铺持续营业，但其法律所有者常常是来自印度、巴基斯坦或孟加拉的海外学生，他们在欠下大量税款后消失。合法企业因无法与之竞争而面临关闭风险，地方议会呼吁政府干预，但税务机关尚未采取有效行动。文章批评了这种明目张胆的逃税行为及其对公共利益的损害。

评论摘要
主要讨论点：英国一些看似不合理的小企业（如洗车店、糖果店）是否涉及洗钱，以及政府在处理这些问题上的表现。 不同观点： • [PaulHoule的观点] 认为这些企业存在某种合理的解释，并将这些抱怨视作英国人过去十年来的一个常见笑话。他没有直接指控这些企业涉及非法活动，而是暗示这些企业的存在可能有其背后的经济逻辑，只是表面上看起来不合理。 • [FridayoLeary的观点] 明确指出这些店铺显然是用于洗钱的，并以牛津街的糖果店为例，认为政府在处理这些问题时表现得非常无能。FridayoLeary还提到理发店数量的增加，并将其与非法移民和灰市公司等问题联系起来，认为政府在多个方面都未采取有效行动。不过，FridayoLeary也承认，虽然这些问题存在，但至少没有听到大规模的福利欺诈事件，可能与Universal Credit（ universal credit是英国的一种社会保障制度）的实施有关。 补充讨论： • [FridayoLeary] 进一步扩展了讨论，认为这些洗钱店铺可能在某种程度上帮助维持了商业街的活力，但明确表示这并不是一个好的借口。 • [FridayoLeary] 还提到政府在应对非法移民和灰市公司垄断驾驶考试名额等问题上的无能表现，认为这些问题与洗钱店铺问题有相似之处。 • [FridayoLeary] 对Universal Credit在防止福利欺诈方面的作用表示不确定，提出可能是这一制度有效，或者只是因为没有相关报道。 争议焦点： • 这些小企业是否真的是洗钱活动的幌子。PaulHoule没有直接指控，而FridayoLeary则明确指控并批评政府的不作为。 • 政府在应对这些问题上的能力和意愿，尤其是是否存在不作为或纵容的现象。 总结： 评论围绕英国一些看似不合理的小企业是否涉及洗钱展开，讨论了这些企业的存在原因和政府在监管上的表现。一方认为这些问题有合理的解释，另一方则明确指控这些企业涉及非法活动，并批评政府的无能。此外，还涉及了更广泛的社会问题，如非法移民和灰市公司的活动。
