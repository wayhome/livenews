Most AI value will come from broad automation, not from R & D

作者: ydnyshhh | 评分: 151 | 评论数: 15 | 发布时间: 2025-03-22 18:35
文章摘要

文章主要讨论了人工智能（AI）对未来经济的影响，特别是通过自动化研发（R&D）推动经济增长的观点。尽管一些业内有影响力的人士如Dario Amodei、Demis Hassabis和Sam Altman认为AI将主要通过加速R&D来产生经济效益，文章对此提出质疑。文章指出，R&D对经济增长的实际贡献小于普遍认知，且多数R&D成果无法被企业直接获利。此外，自动化R&D工作的难度高于预期，因为研究工作不仅涉及推理，还需要多种能力。因此，AI的经济价值更可能来自广泛的经济部署，而非仅限于R&D自动化。最终，文章认为AI的广泛应用将推动生产力提升和经济增长，但主要不是通过R&D渠道。

评论摘要
主要讨论点：技术乐观主义及其对社会、经济和劳动力的影响 不同观点： • [techpineapple] 认为技术乐观主义令人沮丧，因为技术正在取代人性，且许多被炒作的技术不太可能实现，感觉与社会的实际利益脱节。 • [getnormality] 对文章中关于研发（R&D）和资本深化的论述持怀疑态度，认为作者在概念上过于抽象，脱离实际。 • [mooreds] 引用了一篇关于技术部署的文章，认为当前我们仍处于生成型AI的探索阶段，而机器学习（ML）则处于部署阶段。 • [mitjam] 讨论了AI对各类生产要素相对价值的影响，认为AI可能会降低知识工作者的劳动相对价值，而社会、文化和象征资本的价值可能会上升。 • [mirekrusin] 认为争论研发与自动化哪个先带来好处没有意义，指出通过历史数据推断未来影响的做法不妥，强调AI本身即是研发的成果。 • [bashfulpup] 批评了将研发视为“复杂”而其他任务视为“简单”的观点，并指出自动化在许多日常任务中的应用被低估。 • [coldtea] 认为AI自动化主要针对的是无意义的官僚工作，而非真正提高生产力的工作，并警告资本的过度集中和缺乏长期思考的问题。 • [stego-tech] 将当前的自动化浪潮比作工业和农业革命，指出如果没有工人行动来确保利益的公平分配，自动化只会让资本升值，而不会提升社会整体。 • [colesantiago] 质疑技术乐观主义者如何应对中产阶级和贫困人群的就业问题，认为AI替代工作岗位将导致广泛的失业和社会问题，且UBI（全民基本收入）不切实际。 补充讨论： • [callamdelaney] 通过数据指出美国每年支付的工资总额中有巨大部分可以被自动化替代，强调自动化的经济潜力。 • [klooney] 提到在美国大多数R&D和服务业可能不会直接感受到自动化生产的影响。 • [Brysonbw] 认为当前讨论的观点有可能在未来得到验证，但需要时间来证明。 • [godelski] 强调R&D和生产的相互依存关系，批评忽视R&D基础作用的观点，并指出R&D的失败率高且价值往往被低估。 • [akomtu] 用假设的外星文明比喻，探讨了AI技术的引入对其他文明的影响和动机问题。 • [AndrewKemendo] 从技术角度支持自动化将替代人类劳动的观点，并指出关键问题在于“谁将从中受益”，且几乎没人关注自动化实现后的应对措施。 争议焦点： • 技术乐观主义是否现实及其对社会的影响，特别是对就业和经济不平等的影响。 • 研发（R&D）与资本深化在推动生产力增长中的相对重要性。 • AI自动化在实际应用中的可行性和广泛影响。

Copyright infringement is a 'strict liability' offence

作者: dp-hackernews | 评分: 12 | 评论数: 0 | 发布时间: 2025-03-23 11:46
文章摘要

本文主要讨论了如何证明侵权行为以及解决侵权问题的途径。首先，侵权需个案处理，权利人需提供证据证明其作品被未经许可使用，如截图或照片。关键在于证明侵权作品与原作品的联系，包括原作品是否可被获取以及是否有沟通记录。版权侵权是严格责任 offense，无论侵权方是否知晓作品受版权保护，只要使用即构成侵权。若侵权方能证明独立创作且未接触原作品，则可能不构成侵权。解决侵权可通过庭外和解，例如达成支付协议或授予追溯许可。建议寻求专业法律建议以了解更多选项。文中还提供了获取版权法律指导和免费法律支持的资源。

Next.js version 15.2.3 has been released to address a security vulnerability

作者: makepanic | 评分: 123 | 评论数: 22 | 发布时间: 2025-03-22 21:19
文章摘要

Next.js发布了15.2.3版本，以修复一个安全漏洞（CVE-2025-29927）。该漏洞涉及内部头字段`x-middleware-subrequest`，可能导致中间件被跳过，从而绕过关键安全检查，如授权验证。自托管的Next.js应用，特别是使用`next start`和输出为"standalone"的应用，需立即更新。受影响的版本包括15.x、14.x和13.x，补丁已发布。若无法立即更新，建议阻止包含`x-middleware-subrequest`头的外部请求。Cloudflare用户可启用WAF规则防护，而Vercel和Netlify托管的应用不受影响。Next.js团队还将发布针对v12的补丁，并计划改进与合作伙伴的沟通，开设了伙伴邮件列表。

评论摘要
主要讨论点：Next.js 中间件漏洞及其安全性和设计问题 不同观点： • **ratorx** 认为，Next.js 的中间件设计存在根本性缺陷，尤其是中间件与用户输入使用相同机制进行通信，这使得用户请求验证和中间件代码分离。此外，允许除白名单外的任何头部信息通过，这像是潜在的安全隐患。同时，ratorx 质疑框架为不好的服务器设计提供支持，并提出是否存在不适用有向无环图 (DAG) 请求流程的具体用例。 • **smlx** 提到 Next.js 有类似的漏洞历史，指出之前通过添加特定头部可以导致服务器端请求伪造 (SSRF) 的问题。他还批评 Next.js 的补丁发布策略不透明，尤其是对旧版本的支持问题，并认为使用 Next.js 对于重视安全和维护的项目来说风险很大。 • **ronbenton** 关注漏洞报告后的处理时间，质疑为何该安全问题在报告后两周才开始处理，并表达了对认证可被轻易绕过的担忧。 • **mikeocool** 认为 Next.js 增加了前端开发的复杂性，但对大多数应用来说价值有限。他特别指出文件路由和服务器端渲染在一些场景下可能有用，但对于多数应用来说，复杂性远超其带来的价值。 • **makepanic** 引用了官方对漏洞的描述，指出 Next.js 内部使用 `x-middleware-subrequest` 头来防止递归请求，但该机制被绕过可能导致请求跳过关键检查，例如授权验证。 • **dvektor** 和 **urbandw311er** 都表示对 Next.js 的安全性感到不安，dvektor 明确表示不会使用 Next.js，而 urbandw311er 则对自己团队选择自托管 Next.js 感到不安。 • **butterlettuce** 和 **ramoz** 都对 Vercel 和 Next.js 的声誉提出批评，ramoz 还提到希望其他框架（如 Remix 和 TanStack）能发出质量信号并改变方向。 • **ashishb** 认为 Next.js 的基础前提有缺陷，即在浏览器和后端运行相同的代码，这导致安全态势不同。他主张前端和后端应分离，以保持后端的信任和安全性。 补充讨论： • 争议焦点在于 Next.js 的中间件设计是否存在根本性安全缺陷，以及其漏洞响应速度是否足够快。 • 另一个讨论点是 Next.js 是否适合用于对安全性和维护要求高的项目，例如政府或大公司。 • 对 Vercel 和 Next.js 声誉的批评也是一个值得注意的讨论点。

Stop using the elbow criterion for k-means
