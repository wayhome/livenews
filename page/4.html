Running a software jam in a world of slop

作者: foxmoss | 评分: 46 | 评论数: 5 | 发布时间: 2026-06-27 13:36
文章摘要

这篇文章讨论了如何在AI时代举办有意义的软件竞赛。作者指出当前软件黑客松面临两大问题：AI生成的低质量项目泛滥，以及如何激励参与者认真投入。 作者所在的非营利组织Hack Club采用按编码时长付费的模式（每小时8.5美元），通过Hackatime追踪实际编码时间。但这容易导致参与者为赚钱而敷衍了事。 解决方案是借鉴游戏开发竞赛（Game Jam）模式：低质量作品在投票中会被淘汰，没有奖励。同时设定明确期望（避免使用LLM）、邀请优秀评委、给予充足时间让参与者写出高质量代码。这样既解决了AI滥用问题，又通过竞争机制确保参与者真正投入学习，而非仅为奖金敷衍。

评论摘要
主要讨论点：Hack Club的Radish项目投票机制和展示方式 不同观点： • **支持新投票机制但有顾虑**（Heliodex）：认可"自由投票喜欢的项目"这一创新方式，但担心技术含量高却难以演示的项目（如编程语言、分布式系统、操作系统、CLI工具）在投票中会处于劣势，可能打击新手积极性，建议设置双轨奖励：基于工作时长的大奖+基于投票数的小奖 • **技术问题反馈**（LoganDark）：网站在Safari浏览器中反复崩溃，完全无法访问 • **质疑标题策略**（bediger4000）：对"I'm 15"这类年龄强调的标题表示怀疑，认为可能是SEO策略或spam/AI内容的标志，作为65岁用户对此类标题持负面偏见 补充讨论： Heliodex提到Siege项目的成功案例，说明大奖（如Framework笔记本）确实能吸引参与者，即使投入大量时间也可能一无所获。同时指出该项目与Hack Club常规做法有明显区别。一条评论被标记为[flagged]已被移除。

The US Army Issued Ocarinas to Soldiers in World War II

作者: tomcam | 评分: 105 | 评论数: 9 | 发布时间: 2026-06-25 07:26
文章摘要

这篇文章讲述了二战期间美国政府向士兵分发塑料陶笛(ocarina)的故事。政府需要一种小巧、耐用、防水、便宜且易学的乐器来娱乐部队。陶笛符合所有要求:指法简单(类似爬梯子),调音为C大调,可塑料模压生产。当时陶笛在流行文化中有一定知名度,出现在《绿野仙踪》等电影中。政府选择了Gretsch等公司生产的两款陶笛,而非木制竖笛(塑料竖笛1946年才发明)或口琴。这些陶笛成为士兵们战时娱乐的重要工具。

评论摘要
主要讨论点：二战时期军用陶笛引发的关于互联网商业变迁、乐器教育和军队娱乐的讨论 不同观点： • **互联网商业怀旧派**：认为早期互联网更容易发现独特的个人手工艺品（如90年代售卖《时之笛》陶笛的个人卖家），现在要么被大公司打压，要么被Alibaba代购商以高价倒卖取代，互联网失去了原有的发现乐趣 • **四孔陶笛推崇者**：赞赏四孔陶笛设计精巧（60年代发明），用四个孔的组合实现半音阶，易学且音质优美，建议学校用其替代竖笛教学 • **竖笛批评者**：指出竖笛音量过大（超过100分贝），缺乏音量控制，可能需要听力保护，不适合学校教学 • **军事娱乐历史视角**：提到美军重视士兵娱乐（因多为义务兵且有大量空闲时间），除陶笛外还发行袖珍平装书，但这些物品文化影响有限，很少出现在战争电影或歌曲中 补充讨论：有人通过电影《第十七战俘营》中的陶笛情节印证了军用陶笛的存在；还有人回忆起学校时代使用tonette（另一种简易乐器）的经历。

WAL-RUS: a Rust Rewrite of WAL-G for PostgreSQL Backups

作者: saisrirampur | 评分: 3 | 评论数: 0 | 发布时间: 2026-06-27 23:32
文章摘要

ClickHouse Cloud 为解决 Postgres 备份工具 WAL-G 的内存可预测性问题，用 Rust 重写了备份工具，推出了开源项目 WAL-RUS。 WAL-G 使用 Go 语言编写，其垃圾回收机制导致内存使用难以预测，虚拟内存占用波动大，在资源受限环境下难以准确规划容量。 WAL-RUS 通过 Rust 的内存直接控制实现了：1）可预测的资源使用；2）持久连接的持续 WAL 归档；3）针对流式工作负载的优化；4）与 WAL-G 完全兼容。基准测试显示，WAL-RUS 在四个并发归档工作线程配置下，内存占用更小且更稳定。

How Many Elementary Particles Are There, Really?

作者: rwmj | 评分: 110 | 评论数: 20 | 发布时间: 2026-06-27 12:40
文章摘要

这篇文章探讨了基本粒子数量统计的复杂性。标准模型通常列出17种粒子：12种物质粒子（费米子）、4种力载体粒子（玻色子）和希格斯玻色子。但计数存在争议：若包含反粒子，物质粒子应为24种；考虑到W玻色子的正负电荷类型，数字还会增加。文章指出，由于量子场论的数学特性和粒子间的对称关系，基本粒子的准确数量并非简单的整数，不同物理学家有不同的统计方式，答案可能从17到995.5不等。这反映了我们对物质最基本层面认知的边界和复杂性。

评论摘要
主要讨论点：基本粒子的数量究竟应该如何计数，以及这个问题本身的定义是否合理 不同观点： • **质疑手性区分**（ziofill）：手性不是固有属性而是观测方式依赖的，就像光子偏振可用不同基底描述，不应作为区分不同粒子的标准。自旋才是明确定义的属性 • **支持30费米子+16玻色子**（Alulim）：基于自发对称性破缺前的物理，将反物质场视为独立场，可得出3代费米子共30个场，加上4个标量玻色子、8个胶子、3个W玻色子和1个B玻色子 • **应减少到9个**（Sniffnoy）：不应将3代费米子视为完全不同粒子，因为它们可以相互混合，只需计算上型夸克、下型夸克、电子型粒子和中微子即可 • **可能更少（前子理论）**（mac3n）：向相反方向思考，可能少至2个更基本的前子 • **本质上可能只有1个**（NoMoreNicksLeft）：问题在于是指类型还是数量 • **定义问题**（EwanG）："基本"的定义方式不同导致答案从17到995.5不等 补充讨论：有人质疑人类认知极限（brap），有人认为尺度无限延伸无底限（lacoolj），也有调侃性回答（42）

Show HN: KV-psi, using Linux PSI to to trim an LLM KV cache

作者: infiniteregrets | 评分: 3 | 评论数: 0 | 发布时间: 2026-06-27 22:50
文章摘要

PSI KV Governor 是一个利用 Linux 压力失速信息（PSI）在系统内存压力下修剪 LLM KV 缓存的参考实现。项目需要启用 PSI 的 Linux 系统、Python 3.10+ 和 llama.cpp。主要功能包括运行参考模拟器和基准测试，通过监控 `/proc/pressure/memory` 在内存压力时动态调整 KV 缓存大小。基准测试显示在 Jetson 设备上，PSI 变体通过 2-4 次修剪将最终 KV 从 1547 降至 1004-1291，吞吐量保持在 88-96 tok/s。项目提供了完整的构建脚本和测试工具。
