Show HN: Rv, a Package Manager for R

文章摘要

`rv` 是一个用于管理和安装 R 包的工具，以可重现、快速和声明式的方式进行。它仍在开发中，提供两个主要命令：`rv plan` 用于预览同步操作的结果，`rv sync` 用于同步库、配置文件和锁文件。通过配置文件指定项目所需的 R 版本、代码库和依赖项，`rv` 可以自动安装指定包及其依赖。配置文件示例如下： ```toml [project] name = "my first rv project" r_version = "4.4" repositories = [ { alias = "PPM", url = "https://packagemanager.posit.co/cran/latest" } ] dependencies = [ "dplyr", { name = "ggplot2", install_suggestions = true } ] ``` 安装和使用说明可参考文档，贡献者需安装 Rust 和可选的 Just 工具。项目文件和示例可在代码库中找到。

本文讨论了网页缓存技术，以帮助在小预算下应对大量网络流量。作者以自己网站为例，介绍了不同难度级别的缓存策略： 1. **简单级别**： mostly-static sites（ mostly-静态网站），如个人博客。使用内容哈希资源（content-hashed resources）和CDN（内容分发网络）缓存静态内容，确保长时间缓存且无需频繁更新。 2. **中等级别**： data-driven dynamic sites（数据驱动的动态网站）。通过将动态部分放在客户端，并利用CDN和Etag头来减少服务器负载和数据传输。 3. **困难级别**： authenticated per-user sites（每用户认证的网站），涉及更复杂的个性化内容处理。 作者详细介绍了如何通过内容哈希和CDN来提高网站性能，减少请求和响应时间，最终实现高效的缓存策略。

Show HN: SQL-tString a t-string SQL builder in Python

作者: pgjones | 评分: 62 | 评论数: 12 | 发布时间: 2025-05-16 12:48
文章摘要

SQL-tString 是一个用于构建 SQL 查询的 Python 库，类似于 f-string，但能防止 SQL 注入。它通过 `t-strings` 来插入变量，并将这些变量转换为 SQL 占位符，同时支持预定义的表和列名。使用 `sql_context` 可以限制允许的列和表名，防止注入攻击。如果变量设为 `Absent`，库会自动移除相关参数，适用于可选更新或条件语句。此外，还支持 `IsNull` 和 `IsNotNull` 来处理 SQL 中的 `NULL` 条件。默认使用 `qmark` 参数样式，但也支持其他如 `asyncpg` 样式。对于 Python 3.12 和 3.13，可通过 `locals()` 使用该库。该项目基于 MIT 许可证，目前有 43 个星标。

评论摘要
主要讨论点：动态SQL查询片段的组合、安全性及其实现方式 不同观点： • [badmonster] 提出如何在保持占位符安全性和避免手动字符串拼接的情况下，从较小的查询片段构建较大的查询，尤其是条件性构建WHERE子句或JOIN。 • [hombre_fatal] 认为这种方法比传统的通过一堆if语句构建WHERE子句要好，因为后者很难直观地看到最终的子句形态。他更喜欢这种能预先写好SQL语句的方法，因为可以使每个方面都是可选的，且表达式会被自动移除。 • [schultzer] 指出解析器是手写的，但建议构建基于BNF语法的词法分析器和解析器，并提供了相关代码示例和一致性测试工具的链接。 • [ilyagr] 建议允许在t-string中使用类似于Rust的`format!`的语法，例如`sql(t"SELECT {}", a - 1)`，以便更灵活地处理SQL查询中的表达式。 • [caturopath] 解释了`sql_context(columns="x")`的用法，并指出`columns`是一个字符串集合，可以通过设置多个有效选项来使用。 • [bencyoung] 担心`Absent`功能可能导致整个WHERE子句被移除，从而影响数据表，认为如果过滤条件存在于SQL查询中，就应该被使用。 • [jitl] 对SQL解析的重写功能（如移除表达式）表示担忧，特别是对于使用非标准SQL功能和复杂查询的项目。他还询问了是否支持将一个SQL t-string模板化到另一个SQL t-string中以实现组合。 • [schultzer] 再次回应，表示不清楚t-string是什么，但认为其功能类似于Elixir项目中的一些实现，只是不够优雅。 • [sirfz] 解释这种方法通过返回参数化查询和参数列表来强制执行参数化查询，可以用于构建统一的数据库客户端接口，并指出某些数据库客户端可以直接使用t-strings安全执行查询。 • [90s_dev] 赞赏库的设计，但批评使用词法作用域进行占位符查找的设计，认为应该通过字典显式传递参数。 • [owlstuffing] 强调语言应努力在 inline SQL 中实现类型安全，并提到Java中的Manifold项目通过编译器插件实现了这一目标。 补充讨论： • 争议的焦点在于使用t-strings和词法作用域进行占位符查找的设计是否合适，以及SQL解析的重写功能在复杂查询中的安全性和可靠性。 • 不同的开发者对如何构建和组合SQL查询有不同的偏好，有些开发者喜欢预先写好整个SQL语句，而另一些开发者则担心某些功能（如Absent）可能带来的潜在风险。 • 提供了一些关于如何实现SQL查询解析和模板化的具体技术建议和工具链接，如BNF语法和Manifold项目。

The Awful German Language (1880)

文章摘要
