It's five grand a day to miss our S3 exit

作者: ksec | 评分: 138 | 评论数: 17 | 发布时间: 2025-03-27 02:02
文章摘要

文章主要介绍了37signals公司计划在今年6月30日之前将数据从AWS S3迁移到自建数据中心的Pure Storage系统，以节省每年近150万美元的成本。目前，他们存储了18PB数据，并获得了AWS提供的免费60天数据迁出窗口，避免了高额的迁出费用。尽管数据传输需要约三周时间，但若未按时完成，他们将面临每天5000美元的额外支出。整体来看，使用Pure Storage在五年内可节省约500万美元，硬件成本为150万美元，支持和保修费用不到100万美元。

评论摘要
主要讨论点：云计算与自建硬件基础设施的成本对比及优缺点分析 不同观点： • **云计算的成本与便利性**：ifightcrime指出，云计算一直以来都比较贵，但用户为便利性和速度付费。当企业发展到一定规模时，云计算的成本效益不再划算。可以通过前期架构和供应商决策来缓解部分成本。 • **自建硬件的成本核算**：comrade1234分享了其过去的经验，通过电子表格计算自建硬件与托管成本，发现大约三年能回本。同时提到亚马逊会根据硬件成本调整价格。 • **S3系统的深度与灵活性**：siscia认为S3系统非常深且灵活，文章对S3的描述过于浅显。不同的用户可能需要其不同的功能，成本也会因此变化。 • **数据迁移与成本节约**：albert_e建议即使在截止日期前部分迁移数据也能节省大量成本，并提到可以使用S3的 cheaper tiers 来进一步节省开支。 • **云计算的高昂费用与扩展问题**：rvz强调云计算的费用过高，许多团队低估了成本。特别是对于使用Java微服务的团队，扩展成本可能非常高，最终导致不可持续。 • **自建硬件的可靠性问题**：Axsuul认为云计算虽然贵，但硬件故障处理得当，而自建硬件可能导致严重的停机时间，需要达到一定的冗余度才能考虑自建。 • **功能与需求的匹配**：andrewaylett指出，AWS的S3提供了很多额外功能，虽然成本高，但如果需要这些功能则是值得的。 • **存储介质的选择**：DeathArrow质疑使用SSD的必要性，认为HDD配合RAID结构足够，并提到Backblaze的使用案例。 • **文档与客户支持问题**：hbogert抱怨某些供应商的文档放在付费墙后，影响其向客户推荐。 • **具体成本节省的讨论**：calderwoodra和tgtweak提到当前的成本节省情况，以及通过通知供应商离开云服务可能获得的回扣。 • **硬件规模与成本关系**：ksec和Hnrobert42讨论了自建硬件后的机架数量与成本节省，并提到维护物理服务器的劳动成本。 补充讨论： • 评论中多次提到自建硬件与云计算在不同情况下的成本效益分析，特别是长期与短期的成本对比。 • 对于功能需求的讨论，用户对S3的功能深度与灵活性有不同看法，取决于具体使用场景。 • 一些评论关注具体迁移策略与成本节省的实际操作方法。

文章摘要

文章讲述了作者在圣塔安娜风肆虐时运行了一种模拟蠕虫的程序，该程序旨在模拟显微镜下的线虫（*Caenorhabditis elegans*），作为OpenWorm开源项目的一部分。该项目自2011年以来一直尝试构建这种微小生物的数字 twin，以深入了解其神经系统与行为的关联。尽管项目尚未完全成功，模拟运行十小时仅能生成五秒的蠕虫蠕动视频，但其目标是创造出首个虚拟动物，揭示大脑与行为的关系。文章探讨了为何科学家要花费十多年时间研究这种蠕虫，引用物理学家费曼的名言：“我不能创造的，我便不理解。”文章强调，理解生命不仅需要分解其组成部分，还需要重建整个系统。尽管*C. elegans*体型微小，其对生物学的贡献却十分巨大，与多个诺贝尔奖研究相关。

Postgres Language Server: Initial Release

作者: steinroe | 评分: 290 | 评论数: 15 | 发布时间: 2025-03-29 09:13
文章摘要

**Postgres Language Server** 是一个为 Postgres 提供语言工具和实现语言服务器协议（LSP）的项目，旨在提升开发者体验和提供可靠的 SQL 工具。该项目基于 Postgres 自身的解析器 **libpg_query**，确保 100% 的语法兼容性。它采用客户端-服务器架构，具有传输无关的设计，可以通过 LSP、CLI、HTTP API 或 WebAssembly 模块访问功能。主要特性包括自动补全、语法错误高亮、类型检查（通过 **EXPLAIN**）和受 **Squawk** 启发的 linter。项目当前专注于优化核心功能，并欢迎社区贡献。更多详情和贡献机会可查看项目的问题和讨论。

**vramfs** 是一个基于 Linux 的文件系统工具，利用 FUSE 库将文件系统创建于显卡的显存（VRAM）中，类似于内存盘（ramdisk），但使用的是显卡的显存。该工具并非为严肃场景设计，但在消费级 GPU（显存 4GB 以上）上表现良好。读写性能分别约为 2.4 GB/s 和 2.0 GB/s，约为内存盘的三分之一。 **要求**： - Linux 内核 2.6+ - FUSE 开发文件 - 支持 OpenCL 1.2 的显卡 **构建**： 安装 OpenCL 驱动并确认显卡被识别，安装 `libfuse3-dev` 及其他必要文件，运行 `make` 构建。 **挂载**： 使用 `bin/vramfs ` 挂载，建议大小不超过 VRAM 的 50% 以避免不稳定。 **实现**： vramfs 通过 FUSE 库实现用户空间文件系统，使用 OpenCL 分配显存，支持异步写入和同步读取，文件系统结构为树状目录。
