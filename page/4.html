OSS-SEC: Three bypasses of Ubuntu's unprivileged user namespace restrictions

作者: birdculture | 评分: 44 | 评论数: 5 | 发布时间: 2025-03-29 19:07
文章摘要

Qualys 安全咨询报告披露了 Ubuntu 未授权用户命名空间限制的三个绕过方法。Ubuntu 23.10 引入了这些限制，并在 24.04 版本中默认启用，旨在减少内核攻击面。然而，研究人员发现了三种绕过方法，使本地攻击者可以在命名空间内获得管理员权限，从而利用内核漏洞： 1. 通过 `aa-exec` 工具切换到允许创建命名空间的 AppArmor 配置文件。 2. 通过执行默认安装的 `busybox` shell，利用其配置文件的权限。 3. 通过 `LD_PRELOAD` 预加载到一个允许创建命名空间的程序中。 这些绕过方法仅在命名空间内有效，不会影响主机系统。Ubuntu 已发布相关信息，进一步说明可参考其官方讨论帖。

评论摘要
主要讨论点：Linux系统中与安全相关的功能（如AppArmor和用户命名空间）是否导致安全漏洞，以及如何应对这些潜在问题。 不同观点： • **o11c的观点**：当前讨论的情况本身不算一个直接的漏洞，仍然需要内核中的`CAP_SYS_ADMIN`权限才能进行恶意操作。他还提到，很多安全工具在处理多进程解释器时考虑不周，但若已经处于受限的AppArmor配置文件中，不太容易切换到限制较少的配置。 • **mjevans的观点**：质疑AppArmor配置文件是否允许从特权环境逃逸。他认为如果没有AppArmor的额外"许可"，标准的Linux权限或容器组应该可以防止这种情况发生。 • **quotemstr的观点**：反对将无特权的用户命名空间视为安全漏洞。他认为Ubuntu禁用这些命名空间的决策是短视的，反而会降低系统整体的安全性。禁用这些功能会让无特权程序更难设置用户空间沙箱。他主张修复内核漏洞，而不是随意禁用有用的功能。 • **j45的观点**：关注该问题是否仅存在于Ubuntu系统，还是也可能影响Debian等其他Linux发行版。 补充讨论： • 争议的焦点在于无特权的用户命名空间是否构成安全漏洞，以及禁用这些功能是否能真正提高系统安全性。 • 讨论还涉及到安全工具在处理多进程解释器时的不足，以及如何更好地通过权限配置防止潜在的恶意操作。 • 不同发行版（如Ubuntu和Debian）如何处理这些安全功能也是一个值得注意的讨论点。

文章摘要

**Postgres Language Server** 是一个为 Postgres 提供语言工具和实现语言服务器协议（LSP）的项目，旨在提升开发者体验和提供可靠的 SQL 工具。该项目基于 Postgres 自身的解析器 **libpg_query**，确保 100% 的语法兼容性。它采用客户端-服务器架构，具有传输无关的设计，可以通过 LSP、CLI、HTTP API 或 WebAssembly 模块访问功能。主要特性包括自动补全、语法错误高亮、类型检查（通过 **EXPLAIN**）和受 **Squawk** 启发的 linter。项目当前专注于优化核心功能，并欢迎社区贡献。更多详情和贡献机会可查看项目的问题和讨论。
