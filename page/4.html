A new experimental Go API for JSON

文章摘要

摘要： Go团队发布了实验性的新JSON API（encoding/json/v2和encoding/json/jsontext），旨在解决现有encoding/json包的多个问题。新版本改进了JSON语法处理（如严格UTF-8验证、禁止重复字段名），修复了行为缺陷（如nil切片/映射的序列化方式），并提供了更灵活的API设计（支持更多I/O选项）。同时解决了现有API的性能限制和一致性问题。该实验性版本暂不默认启用，可能继续调整API设计。

评论摘要
主要讨论点：[Go语言标准库中的JSON处理改进（v2版本）及其优缺点] 不同观点： • **支持改进的观点** - [physicles]：赞赏JSON v2的改进，尤其是将语法部分分离到jsontext包中，认为omitempty应被omitzero取代。 - [drej]：建议用户自行测试，发现性能提升显著，但存在内存分配回归问题，需要更多测试以完善v2。 - [rjrodger]：支持部分解决null与nil问题的改进，认为大多数语言的JSON解析器应使用特殊值处理"JSON null"。 • **批评现有设计的观点** - [coldtea]：认为encoding/json从一开始就设计糟糕，而非用户需求变化导致问题。 - [tibbe]：质疑v1设计中为何将nil slice或map编码为JSON null。 - [gethly]：强烈批评v2延续了v1中处理nil的错误行为，尤其是omitempty和omitnil的问题。 • **对Go JSON处理的一般不满** - [phoenixhaber]：认为Go中处理JSON过于繁琐，应像Rust的serde或其他语言一样无需关心编组细节。 - [h1fra]：不理解Go为何在如此常见的JSON处理上表现不佳，与其他语言相比显得复杂。 • **反对v2改进的观点** - [donatj]：认为v1基本足够，大多数问题可通过向后兼容的struct标签解决，v2的API过于复杂且不符合Go的简洁哲学。 补充讨论： - **争议焦点**：v2是否真正解决了v1的核心问题（如nil处理、性能、API复杂度），以及改进是否必要。 - **其他讨论**： - [breakingcups]：担心LLM仅支持v1 API可能影响v2的采用。 - [afdbcreid]：提到Go标准库多次发布v2的问题，对比Rust的保守标准库设计。 - [sroerick]：请求非Go开发者视角的高层概述，反映改进的对外部用户的影响。
