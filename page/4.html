文章摘要

Rocksky 是一个基于 AT Protocol 的去中心化音乐记录与发现平台。它支持 Last.fm、ListenBrainz 兼容的 scrobbling API，可记录播放历史、展示实时动态、统计每日收听数据，并提供热门艺人、曲目、专辑等个人榜单。平台集成 Spotify、Jellyfin、Pano Scrobbler、WebScrobbler，支持 MeiliSearch 搜索。项目主要使用 TypeScript 和 Rust 开发，未来计划加入 Webhooks、个性化推荐、Last.fm 同步、远程播放、自建音乐库播放等功能。

评论摘要
主要讨论点：围绕 Rocksky/AT Protocol 音乐发现与 scrobbling 服务的可用性、迁移、隐私、推荐能力展开。 不同观点： • 隐私担忧：有人希望可偏移 scrobble 时间，避免公开暴露自己何时在电脑前；认为自托管可能更安全。 • 看好推荐与社交潜力：多位评论者称赞 Last.fm 的推荐模型和社交音乐体验，认为若 Rocksky 推荐质量接近 Last.fm，就有机会做大。 • 迁移与兼容是关键：有人指出需支持导入 Last.fm 历史、兼容现有 scrobbling 客户端；也期待 Plex/PlexAmp 等应用接入。 • 开发者关心接入方式：讨论是否需要 Rocksky API key、是否支持 OAuth/“Sign in with Bluesky”；也有人询问能否像 ListenBrainz 一样用 token 和 endpoint 复用实现。 • 可靠性争议：Rocksky 若无法匹配规范化曲目就跳过 scrobble，被批评为“设计上不可靠”，用户不愿接受记录被丢弃。 • 概念与命名吐槽：有人不理解“scrobble”含义，认为术语晦涩；也有人调侃服务名像斯拉夫姓氏或误读 AT Protocol 为 GSM AT commands。 补充讨论：有人追问“推荐到新音乐后如何收听”，也有人好奇 Last.fm scrobbling 是否还能吸引新用户，还是主要维系老用户。

文章摘要

文章介绍 BuildBuddy 远程缓存通过内容定义分块（CDC）让大型构建产物只传输变化字节而非整文件。对 Bazel 启用后，可减少上传与存储约40%。该技术尤其改善链接、打包、归档等传递性大输出的缓存效率，避免小改动导致大量近似重复文件被完整上传下载。

评论摘要
主要讨论点：围绕内容定义分块（CDC）在构建、备份和镜像缓存中的实际效果、适用场景与潜在风险展开。 不同观点： • CDC在普通备份/同步场景中常常效果不佳：dotwaffle认为很多压缩工具生成的归档并不“rsyncable”，导致CDC难以发挥作用；他通过将文件以未压缩、稳定排序的归档方式存储，配合restic节省了大量空间，并提到Syncthing最终也放弃CDC，改用固定大小块。 • CDC在Bazel这类可控构建系统中很适合：同一评论指出，Bazel能控制输入和产物格式，因此更容易让CDC有效工作；其实现看起来也较高效，值得肯定。 • CDC可能适用于Docker构建：a_t48表示有兴趣将CDC用于Docker builds。测试显示，对最终镜像输出使用CDC可减少体积，但需要在节省空间和拉取时请求数量之间调优；用于build cache可能收益更大。 • 安全与极端输入风险：londons_explore提出疑问，恶意输入是否能故意制造极小或极大的分块，从而影响性能、存储或请求行为。 补充讨论：争议焦点主要在CDC的适用边界：在不可控、压缩归档场景中收益有限；但在Bazel/Docker构建缓存等可控系统中可能更有价值，同时需关注分块大小调优和恶意输入攻击面。

主要讨论点：Pixel 9/Android 驱动漏洞、AI功能扩大攻击面、漏洞修复与生态安全现状。 不同观点： • 对AI读取消息的担忧：有评论认为手机为实现AI搜索/理解消息而提前解码媒体，扩大了0-click攻击面，质疑“未经请求读取并处理短信/消息”的设计是否重蹈覆辙。 • 对Android安全响应的评价：有人因该漏洞90天内修复而对Google印象改善，但同时担心其他Android厂商响应更慢；也有人疑问苹果的修复速度及为何近年iPhone越狱少见。 • AI与漏洞发现：有人用GPT分析代码并识别问题，认为AI具备发现安全漏洞的潜力；但也有人强调专家经验仍关键，尤其在内核、驱动等细分领域。 • 攻击产业影响：有人讨论AI会让NSO等漏洞/间谍软件公司过时，还是使其能力增强。 • 技术根因与工程实践：讨论涉及整数溢出、缺少类似copy_to/from_user的安全惯用接口、内核物理地址固定、V4L2/硬件解码支持滞后等。 • 开源与上游化争议：有人指出Pixel BSP尚且开源仍有严重漏洞，其他Android或嵌入式设备可能更糟；主张Google认证应要求驱动上游进Linux内核，即使会拖慢硬件开发。 补充讨论：争议焦点集中在AI功能是否值得牺牲攻击面、Android生态碎片化带来的修复风险、以及AI在攻防中究竟是辅助专家还是改变行业格局。
