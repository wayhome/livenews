A Lean companion to Analysis I

作者: jeremyscanvic | 评分: 266 | 评论数: 14 | 发布时间: 2025-05-31 16:55
文章摘要

作者大约20年前编写了《Analysis I》这本实分析教材，专注于基础问题，如自然数、整数、有理数和实数的构造，以及提供足够的集合论和逻辑知识以帮助学生进行严谨的证明。虽然编写时未考虑形式化验证，但随着对证明助手的了解，作者意识到该书内容与Lead等证明助手兼容。因此，作者推出了《Analysis I》的Lead配套项目，将书中的定义、定理和练习“翻译”成Lead代码，允许通过填补代码中的“sorries”来完成练习。该项目目前已翻译了部分章节，并有意在后续章节中更多依赖Lean的Mathlib库。作者欢迎志愿者测试该项目并提供反馈，以确保练习能在Lead中顺利完成。

评论摘要
主要讨论点：使用Lean进行数学教学的优点、挑战以及相关资源和工具的比较 不同观点： • **立即反馈的优势**：ubj认为Lean的编译器可以提供即时反馈，这比等待人工反馈更有效率，并建议未来可以提供更具指导性的反馈，类似于Rust编译器的建议功能。 • **学习曲线的挑战**：danabramov和brosco认为Lean和Mathlib的学习曲线较陡，尤其是Mathlib的复杂性可能对初学者造成困难，但同时他们也认为这是将数学书籍与工具连接起来的有益尝试。 • **工具选择的理由不明确**：thdhhghgbhy指出作者未详细解释为何选择Lean而非Coq或Agda。 • **数学教育的激进观点**：UltraSane主张数学教育应侧重于计算机代数系统和定理证明器的构建，强调实用性和可视化，而非传统的纸笔计算。 • **教材与形式化证明的对比**：jhanschoo担心Mathlib中使用的过滤器概念与传统教材中的epsilon-delta方法存在差异，可能会对教学造成困扰。 • **资源和项目的分享**：IssaRice列举了多个尝试将Tao的Analysis I形式化到Lean的项目和资源，指出了这些项目大多停留在前几章，并分享了相关的GitHub链接。 补充讨论： • **Lean在不同数学领域的应用**：nextos提到定理证明在编程语言理论中已有应用，并认为分析中的定理相对更难，建议从 simpler starting point 开始。 • **Lean在主流教材与形式化数学库中的比较**：zozbot234讨论了主流教材与Mathlib在教授实分析时的不同方法，并提出了是否应在学术课程中教授Mathlib版本的问题。 • **具体领域的学习资源**：331c8c71询问使用Lean学习线性代数的起点，westurner则提到HoTT（同伦类型论）作为数学基础的替代方案，并分享了相关资源。 • ** isomorphism 的相关性**：practal质疑证明 isomorphism 到Mathlib等价的重要性，并询问是否可以省略这一部分。 争议焦点： • **Mathlib的复杂性与教学适用性**：一部分讨论者认为Mathlib的复杂性和快速变化可能不适合作为教学工具，而另一部分讨论者则认为这是一种有益的挑战和学习机会。 • **工具选择的理由**：部分讨论者对选择Lean而非其他定理证明器表示疑惑，认为需要更明确的解释。 总结：讨论围绕使用Lean进行数学教学的优缺点展开，涉及学习资源的分享、工具选择的合理性以及具体教学方法的适用性等问题。

Learning from the Amiga API/ABI

作者: danny00 | 评分: 38 | 评论数: 6 | 发布时间: 2025-06-01 14:21
文章摘要

这篇文章讨论了从Amiga操作系统API/ABI中可以学到的设计理念，特别是其直接调用共享库的方式，无需运行时链接。Amiga ABI通过一个已知位置的分支指令表实现函数调用，核心库`Exec.library`提供获取其他库函数地址的接口。该ABI不依赖特定CPU，兼容现代内存保护机制，适用于多种编程语言。文章还介绍了Amiga OS的其他优点，如内核的列表管理、消息传递和多任务处理，以及`Intuition`窗口系统的异步事件处理能力。相比现代操作系统，Amiga OS的设计更加简洁和易用。此外，文章提到AmigaDOS及其替代库ARP的演变，展示了Amiga OS库系统的灵活性。总体而言，Amiga OS的ABI设计在今天仍然具有借鉴意义。

评论摘要
主要讨论点：AmigaOS的设计优雅性及其与其他操作系统的对比 不同观点： • flohofwoe认为AmigaOS（除了DOS部分）是其见过的最优雅的软件设计之一。他强调了系统的单一固定启动地址（ExecBase）以及通过链表连接的数据结构，虽然安全性差，但非常适合学习和扩展。 • mpweiher极度赞赏Amiga Exec的优雅，认为其后的操作系统，包括Mach，都相形见绌。他特别指出AmigaOS通过简单的链表结构和面向对象的设计，使得操作系统不再神秘，且所有元素（任务、中断、消息等）都基于相同的节点结构，I/O操作通过消息队列实现。 • mitchbob称赞Carl Sassenrath对AmigaOS的贡献，间接支持AmigaOS设计上的创新性和影响力。 • orionblastar强调Amiga 1000相较于同时代Macintosh的性能优势，指出其依赖于定制的协处理器。同时提到可以通过AROS在旧PC上体验Amiga的感觉。 • o11c则对AmigaOS的某些赞誉持怀疑态度，认为一些所谓的“特性”如“无动态链接”和“无僵尸进程”实际上是通过实现动态链接和要求程序无bug来实现的，并不构成与现代系统的实质性区别。 补充讨论： • 讨论中还提到了具体的技术细节，如AmigaOS中的节点结构（next, previous, type, priority, name）以及消息和端口的实现方式。 • 争议的焦点在于AmigaOS是否真的如其他评论者所言，比现代操作系统更优雅和独特，还是这些特性只是历史发展的阶段性产物，且其独特性被夸大。 • 另外，orionblastar提到了通过AROS项目继续体验AmigaOS的可能性，表明AmigaOS的影响力在现代仍有延续。

Ovld – Efficient and featureful multiple dispatch for Python

作者: breuleux | 评分: 95 | 评论数: 9 | 发布时间: 2025-05-29 19:45
文章摘要

`ovld` 是一个用于 Python 的高级多重调度库，允许根据函数参数的类型和值进行调度，而无需使用 `isinstance` 语句。它支持多参数调度，速度快，并提供多种高级功能，如变体、混合和依赖类型。通过装饰器定义不同版本的函数来处理不同类型和值，还支持递归定义和代码生成。此外，`ovld` 允许设置优先级和使用 `call_next` 来控制调度顺序，适用于调试和扩展。示例展示了如何处理基本类型、列表和依赖类型的函数定义与调用，如阶乘计算。

Oniux: Kernel-level Tor isolation for any Linux app

文章摘要

**摘要：** 文章介绍了一款名为 **oniux** 的小型命令行工具，它通过 Linux 命名空间为任何 Linux 应用程序提供 Tor 网络隔离。oniux 使用内核提供的隔离功能，将应用程序置于独立的网络命名空间中，并通过自定义网络接口路由流量，确保数据不会泄露。与传统的 torsocks 相比，oniux 更安全，因为它不依赖于动态链接的 libc，且能防止恶意应用程序泄露数据。oniux 需要在 Linux 系统上安装 Rust 工具链，并通过克隆系统调用创建隔离的子进程。用户可以通过简单的命令行操作实现应用的 Tor 隔离，例如 `oniux curl https://example.com`。 **关键特性：** - 使用 Linux 命名空间实现隔离。 - 比 torsocks 更安全，防止数据泄露。 - 支持隔离整个 shell 和图形应用程序。 - 基于 Arti 和 onionmasq，用 Rust 编写。
