Deep Down the Rabbit Hole: Bash, OverlayFS, and a 30-Year-Old Surprise

作者: Deeg9rie9usi | 评分: 52 | 评论数: 6 | 发布时间: 2025-06-25 13:43
文章摘要

本文讲述了一次涉及Bash、OverlayFS及30年前遗留问题的调试过程。最初，客户报告在切换到OverlayFS后，OpenSSH的scp命令失败，错误信息显示为"shell-init: error retrieving current directory: getcwd: cannot access parent directories: Inappropriate ioctl for device"。调查发现，该问题源于Bash使用了自定义的getcwd()函数，而非glibc提供的版本。这是因为在交叉编译环境中，系统错误地认为getcwd()存在问题，导致Bash回退到古老的实现。该实现与OverlayFS不兼容，导致错误。最终，通过模拟Yocto项目中的处理方法，明确声明getcwd()行为，问题得以解决。根本原因在于OverlayFS的某些特性与Bash过时的getcwd()实现不匹配。

评论摘要
主要讨论点：POSIX API中errno的使用问题及其相关的历史性bug，尤其是与Bash、getcwd()、$PWD等相关的技术细节，以及跨编译中的注意事项。 不同观点： • chubot认为POSIX API中errno的使用规则令人困惑，特别是在某些情况下（如readdir()返回NULL表示错误和EOF），需要手动设置errno=0。他提到了Oils项目修复了一个与$PWD相关的历史性bug，该bug在AT&T ksh中也存在了30多年。他还解释了为何shell不能直接使用getcwd()，因为需要同时考虑继承的$PWD值和符号链接问题。 • jwilk提供了有关该bug的公开报告链接，方便进一步查阅相关讨论。 • pogopop77认为这是一个有趣的调查，并指出新范式（如覆盖文件系统）可能会以复杂的方式影响行为，增加调试难度。 • saurik则关注跨编译中的问题，认为不应忽视警告，而应更仔细地处理autoconf配置，确保在目标系统上正确运行，而不是盲目进行跨编译。 • akoboldfrying以幽默的方式提醒大家注意各种潜在问题，暗示了系统和软件环境中的复杂性。 • x0x0强调了软件开发的难度，指出历史性语义变化对现有软件的影响，以及一些软件未能及时升级所带来的问题。 补充讨论： • 争议焦点之一是POSIX API的设计是否过于复杂和容易出错，尤其是在errno的使用上。 • 另一个讨论点是关于历史性bug的修复，尤其是那些存在了几十年的bug，反映出软件维护中的挑战。 • 跨编译中的注意事项也被提及，强调了在不同环境下进行软件开发和测试的重要性。 • 覆盖文件系统等新范式带来的复杂性也被认为是调试和维护中的一个重要因素。

文章摘要

加州立法者正推动一项名为S.B. 690的提案，被称为“企业掩盖法案”。该法案将大幅削弱加州的隐私保护法（CIPA），允许大科技公司和数据经纪人未经同意秘密记录和监控用户的点击、通话和在线行为，并以“商业用途”为由分享或出售这些数据。这将合法化企业窃听，授权使用追踪工具，且无需告知或承担法律后果。该法案特别威胁到移民、LGBTQ+群体、寻求堕胎者以及抗议者和工人的隐私和安全。这是一次对数字隐私的公然攻击，必须立即采取行动阻止其通过。

评论摘要

Libxml2's "no security embargoes" policy

作者: jwilk | 评分: 6 | 评论数: 0 | 发布时间: 2025-06-25 19:36
文章摘要

Libxml2是一个广泛使用的开源XML解析工具包，自2000年发布以来，被众多开源项目、商业软件和政府采用。然而，尽管许多组织乐于使用开源软件，却很少有人愿意为其持续维护做出贡献。这导致libxml2的当前维护者拒绝接受安全禁运（security embargoes）政策，引发了对自由和开源软件项目维护条款的讨论。 Libxml2由Daniel Veillard为GNOME项目开发，后在2000年代初被广泛采用，支持多种编程语言和操作系统。随着时间推移，Veillard的维护工作逐渐减少，Nick Wellnhofer在2013年开始贡献代码并承担大部分发布工作。2021年，由于Veillard忙于工作，加之安全漏洞修复延迟，Wellnhofer一度暂停维护，但随后在谷歌捐赠下于2022年恢复，并计划通过Open Source Collective获得资助。 文章反映了开源项目在长期维护和资金支持方面的挑战。

Introducing Qodo Gen CLI: Build and Run Coding Agents Anywhere in the SDLC

作者: benocodes | 评分: 26 | 评论数: 3 | 发布时间: 2025-06-25 12:09
文章摘要

Qodo Gen CLI 是一个强大的命令行工具，用于构建、管理和运行 AI 代理，帮助开发者自动化整个软件开发生命周期（SDLC）中的工作流。它允许开发者创建自定义代理，定义其触发条件、输入、操作和输出，支持在终端和浏览器中交互使用，并将 AI 功能带入任何 IDE。该工具提供灵活的部署选项，适用于 SaaS 和企业环境。 主要功能包括： - 自定义代理：控制代理的行为、运行时间及使用工具。 - 工作流自动化：从 CI/CD、webhooks 触发代理。 - 浏览器和终端交互：通过终端或浏览器 UI 使用代理。 - 智能代码审查：自动审查 PR，生成摘要、识别问题并建议修复。 开发者可以用 Qodo Gen CLI 自动化诸如可访问性检查、测试运行和性能优化等任务。该工具现已开放 alpha 测试，可通过 `npm install -g @qodo/gen` 免费试用。
