Declarative Schemas for simpler database management

作者: kiwicopple | 评分: 73 | 评论数: 14 | 发布时间: 2025-04-03 17:02
文章摘要

本文介绍了声明式 schema 如何简化复杂数据库的管理。声明式 schema 将数据库的最终期望状态存储在 `.sql` 文件中，便于集中管理和版本控制。相比直接修改数据库 schema，声明式 schema 具有以下优势：单一管理界面，减少冗余和错误；版本化迁移，确保不同环境中的一致性；简明的代码审查，无需重复复杂迁移脚本。 随着数据库 schema 复杂性增加，传统迁移方法难以维护，因为缺乏单一的整体视图。例如，在 Supabase 中，复杂的 `projects` 表涉及私有表、RLS（行级安全）、视图和触发器，修改时需多步操作，容易导致冲突。 声明式 schema 通过集中管理 schema，简化了开发流程，提高了开发效率。

评论摘要
主要讨论点：关于数据库 schema 管理中声明式与命令式方法的优缺点，以及自动生成迁移脚本的可行性。 不同观点： • [xyzzy_plugh] 认为应该使用声明式 schema，但自动生成迁移脚本不可取。他建议手写迁移脚本并验证 schema 变化，通过测试确保数据库 schema 与预期一致。 • [jackb4040] 指出 SQL 本质上是命令式的语言，无法保证 create_table 等命令的安全执行。他强调声明式 schema 文件（schema file）的重要性，而不是依赖 SQL 命令。 • [webster451] 表示声明式 API 在某些场景下是有价值的，但大多数情况下，程序员需要对变更的控制以获得更好的行为。他认为世界本质上是命令式的，提供更高的控制和可预测性。 • [bartvk] 总结新的方法是直接修改 CREATE TABLE 脚本，工具自动计算差异并应用更改，这消除了新数据库创建和现有数据库更新之间的区别。 • [joshAg] 基于实践指出自动生成迁移脚本可能导致复杂变更（如修改 enum、非空列添加、数据迁移）难以实现，而这些在迁移脚本中更容易处理。 • [neutralino1] 提到 Rails 多年来一直在使用类似的方法，通过维护 schema.sql 文件和历史迁移脚本来管理数据库变更。 • [Guillaume86] 希望有一个类似微软 SSDT 的工具，支持声明式 schema 管理并集成到 IDE 中，提供更多功能如查找引用和错误检查。 • [geocar] 警告自动生成迁移脚本可能会在团队中导致严重问题，特别是在 CI 中自动应用这些迁移，可能会在未来引发难以修复的错误。 • [ucarion] 关心是否可以手动编辑生成的迁移脚本，以实现如 "create index concurrently" 等特定操作。 • [kiwicopple] 提到结合 Postgres Language Server，可以在 IDE 中直接执行语句，提高开发效率。 • [xaas] 提到使用 ZenStack 并计划放弃 supabase，暗示可能有其他工具更适合其需求。 • [oulipo] 将此方法与 Drizzle 进行比较，询问其相似性和差异。 • [mylons] 质疑这种方法相对于直接使用 raw sql 的优势，认为两者非常相似。 • [wmanley] 提供了一个关于 SQLite 声明式 schema 迁移的文章链接，供进一步讨论和参考。 补充讨论： - 自动生成迁移脚本的潜在风险与手动控制之间的权衡。 - 声明式与命令式方法在不同工具和框架中的实现和应用，如 Rails 和 SSDT。 - 具体技术如 Postgres Language Server 和 ZenStack 的实际应用案例和未来发展方向。 - 关于迁移脚本的编辑自由度和特定数据库操作的实现方法。 - 各种工具和方法在实际开发中的优缺点和取舍。

本文探讨了VMS操作系统的大小，特别是其源代码的行数。作者通过自定义程序统计了VMS多个版本（V6.2、V7.2、V8.2、V9.2-3）中15个核心组件的源代码行数，排除了空白行和注释行。结果显示，这15个组件在V8.2版本中总计约16.6万行代码，且这些组件的代码量在不同版本中几乎翻了三倍。VMS最初使用BLISS和MACRO-32编写，后来逐步转向C语言。每个新版本大约增加40万行代码，显示出VMS在不断发展和扩展。文章还提到，VMS源代码库包含409个组件，大小不一，共同构成了多平台的VMS操作系统。

主要讨论点：VMS操作系统的当前价值和历史演变 不同观点： • jamesy0ung认为VMS今天的主要用途仅限于那些无法迁移的现有应用。他对VMS的可靠性有所耳闻，但对其一年期的VM许可感到不满，认为VMS已经过时且小众，不如Linux等主流系统实用，因为Linux有众多厂商支持。 • markus_zhang对VMS的设计者David Cutler表示钦佩，并提到Cutler在微软的工作经历，表达了对与Cutler共事的向往。 • snovymgodym对VMS持负面看法，认为其历史是一连串的错误决策，错失市场机会，并最终成为遗留软件，仅用于从某些机构中榨取最后的价值。不过，他仍希望VMS能有一天被开源。 • uptownfunk对VMS怀有情感，提到VMS相关技术（如VAX）曾为他们家庭带来生计，因此对VMS有深厚感情，不论其多么过时。 • whartung对VMS代码库中ACPI部分的代码行数（超过165K行）感到惊讶，虽然他并不熟悉ACPI的细节，但觉得这个数字很大。 • zabzonk请求澄清讨论的VMS版本是否为VAX VMS。 • ConanRus对VMS的知识产权持有者表示不满，认为他们没有有效管理这一遗产，尤其在开源社区贡献方面缺乏支持，并提到因过时的VM映像下载机制导致用户不便。 补充讨论： • VMS的历史演变和市场表现是多个评论者关注的焦点，尤其是其错失技术发展机会（如Alpha和Itanium架构）导致当前的尴尬局面。 • VMS的可靠性和其在特定领域中的应用仍然被一些用户所认可，尽管其市场影响已经大不如前。 • 开源和用户友好性是部分评论者对VMS现状的批评点，尤其是对旧有系统如何在现代技术环境中生存和发展的关注。

I maintain a 17 year old ThinkPad

作者: Fred34 | 评分: 568 | 评论数: 146 | 发布时间: 2025-04-03 02:40
文章摘要

文章主要讨论了为何作者仍使用一台17年前的ThinkPad笔记本电脑，并通过Nassim Nicholas Taleb的“反脆弱”理论和Lindy效应来解释其原因。旧款ThinkPad因其模块化设计、可更换部件（如电池、硬盘、CPU等）以及坚固的做工，具备很高的耐用性和可修复性，展现出“ robust”（坚韧）的特性。相比之下，现代MacBook尽管性能强大，但其高度集成和不可更换部件的设计使其显得“fragile”（脆弱），一旦某个部件损坏，可能导致整个设备无法使用。此外，MacBook的操作系统支持期限和封闭的生态系统也限制了其使用寿命。因此，作者认为旧ThinkPad因其长寿和易修复性，符合Lindy效应，能够长时间保持功能性。

评论摘要
主要讨论点：ThinkPad与Framework笔记本在耐用性、可维护性、二手市场成功以及现代使用场景中的比较 不同观点： • CursedSilicon认为Framework笔记本虽然具备现代化优势和可更换组件（特别是主板）的特点，但由于是小型制造商，进入门槛较高，无法像ThinkPad那样在二手市场取得成功。ThinkPad因其耐用性和可维护性受到欢迎，但随着时间推移，老旧硬件难以满足现代操作系统和网络需求。 • zokier指出，虽然老旧的ThinkPad（如T440之前型号）在硬件上有很多限制，但T450及其之后的型号仍然具备现代功能，如USB3、M.2插槽和更长的电池寿命，使其在相当长时间内仍可作为日常使用设备。 • quailfarmer认为，硬件的高度集成并非缺陷，而是提升性能、可靠性和成本效益的必要设计选择，类似于Apple的硬件设计。虽然模块化设计（如Framework的易更换部件）具有吸引力，但并非必须功能。同时强调，Framework的维修文档和可维护性是值得保留的优点。 • dpedu分享了MacBook电池更换的个人经验，指出近年来的MacBook Air在电池更换上已经变得更加容易，反驳了完全否定Apple设备可维护性的观点。 • mtlmtlmtlmtl强调ThinkPad在防尘设计和屏幕保护方面的优势，特别是与其过去维修经验中常见的其他品牌笔记本故障相比，ThinkPad的设计使其具备更长的使用寿命。 • interroboink提到，老旧硬件最终会面临新操作系统停止支持的问题，限制其可使用的软件范围。虽然可以继续运行自定义编译的程序，但依赖现代操作系统功能的软件将逐渐不可用。 • anon6362展示了一台经过大量升级的T480，强调了其在性能和电池续航方面的优势，但也提到了一些硬件问题（如主板散热和ThrottleStop软件使用）。 • ajxs和ruleryak都对老旧ThinkPad（如x220和T420）的耐用性和性能表示赞赏，尽管这些设备年代久远，但仍然在某些场景下表现优于现代设备。 • randerson表达了对老旧ThinkPad被强制报废的遗憾，强调了其对旧设备的深厚情感。 • ivraatiems分享了其在翻新和销售老旧ThinkPad方面的经验，指出这些设备的持久市场价值。 • johnisgood遇到了旧ThinkPad T42的密码遗忘问题，寻求解决方案。 • markus_zhang使用T470S作为Ubuntu开发机，虽然对图形驱动有些抱怨，但总体满意其性能和稳定性。 补充讨论： • ThinkPad的耐用性和模块化设计使其在二手市场和老旧设备使用中表现出色，但随着硬件老化，支持现代软件和操作系统的能力减弱。 • Framework笔记本作为新兴品牌，具备现代化设计和可更换组件的优势，但在市场占有率和二手市场表现上尚无法与ThinkPad竞争。 • 关于硬件集成和模块化设计的争议，焦点在于如何在性能、可靠性和可维护性之间取得平衡。 • 老旧ThinkPad设备的实际使用经验和升级潜力被多次提及，显示出用户对这类设备的深厚感情和实际价值认可。
