F* file system – file search that reads SSD directly bypassing OS kernel

作者: neogoose | 评分: 95 | 评论数: 13 | 发布时间: 2026-06-21 20:44
文章摘要

FFS（F* File System）是一个用C语言编写的命令行文件搜索工具，约1500行代码。它的核心特点是绕过操作系统内核，直接读取磁盘原始数据进行搜索。 **主要特性：** - 直接读取磁盘块设备，跳过VFS缓冲层 - 支持Ext4、Btrfs和APFS文件系统 - 可搜索未挂载的卷（如.dmg、.iso文件） - 利用OpenMP实现多核并行处理 **性能表现：** 文件数量越多，相比ripgrep优势越明显。在325万文件的测试中，FFS用时36秒，而ripgrep需要75秒。 **局限性：** macOS主磁盘需禁用SIP保护、可能遗漏最近写入的文件、仅支持已实现的文件系统。本质上这是一个概念验证项目，展示直接磁盘访问可以超越内核VFS的性能开销。

评论摘要
主要讨论点：关于一个绕过文件系统直接读取块设备的搜索工具项目的技术评价 不同观点： • **质疑"绕过内核"说法**：多位评论者（watusername, Retr0id）指出该项目只是绕过了文件系统层，但仍通过内核读取 /dev 设备节点，并非真正绕过内核。建议集成 SPDK 才能实现真正的内核绕过。 • **实用性争议**：neogoose 认为需要 sudo 权限使得项目"几乎无用"，但承认开发过程很有趣；kasabali 质疑标题误导，认为它应该也能用于硬盘、U盘等设备；porridgeraisin 则提供了使用 setfacl 解决权限问题的详细方案。 • **性能质疑**：self_awareness 怀疑其性能优势，认为使用内核缓存的常规方式应该更快，因为可以避免磁盘访问。amelius 质疑能否绕过 SSD 控制器的"魔法"操作。 • **技术认知**：noufalibrahim 将其理解为用户空间文件系统实现；wk_end 从项目名联想到 F* 编程语言，表示不会信任使用但认可作者努力。 补充讨论：有评论讽刺 Windows Search、指出文档有拼写错误、以及遗憾项目不支持 BSD FFS 文件系统。

Cointegration and Long-Horizon Forecasting (2025)

作者: bryanrasmussen | 评分: 12 | 评论数: 2 | 发布时间: 2026-06-21 14:48
文章摘要

这篇1997年的工作论文挑战了传统观点。作者Christoffersen和Diebold发现，在长期预测中，即使变量间存在协整关系，忽略协整并不会降低预测准确性。使用标准多变量预测评估指标时，简单的单变量Box-Jenkins预测同样有效。研究指出标准预测准确性指标的潜在缺陷：它们无法衡量变量间协整关系的维持。作者建议采用能明确评估协整关系保持的替代性评估方法。

评论摘要
主要讨论点：协整（Cointegration）概念的解释及其在时间序列分析中的应用 不同观点： • [seanhunter] 详细解释协整概念：协整是用于解决时间序列回归分析中虚假相关问题的统计方法。如果多个时间序列单独需要d阶差分才能平稳，但它们的某个线性组合只需要更低阶差分即可平稳，则称这些序列协整。这意味着这些序列放在一起分析比单独分析更有意义。用类比说明：相关性像两人并排走路（方向一致但无因果关系），协整则像两人手牵手走路（存在更紧密的联系）。 • [joshdick] 对论文时效性提出质疑：指出论文发表于1997年，暗示内容可能过时。 补充讨论：两条评论之间存在隐含的争议焦点——统计概念和方法论的时效性问题。第一位评论者关注理论解释的准确性和可理解性，第二位则质疑研究材料的时代相关性。
