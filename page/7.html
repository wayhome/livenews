文章摘要

Pizlix是基于Linux From Scratch 12.2改进的内存安全操作系统，其用户空间程序使用Fil-C编译器构建以提高内存安全性，但内核仍使用Yolo-C编译。该系统支持X86_64架构，提供SSH服务、图形界面Weston等组件，并默认创建root和pizlo用户。安装需要准备特定分区和lfs用户，通过自动化脚本分阶段构建：先用Yolo-C建立工具链（Pre-LC），然后替换为Fil-C工具链（LC阶段），最后完成LFS构建（Post-LC阶段）。该系统展示了Fil-C编译器与C/C++的高度兼容性，多数LFS软件包无需修改即可编译。

Linux Kernel Rust Code Sees Its First CVE Vulnerability

作者: weinzierl | 评分: 90 | 评论数: 14 | 发布时间: 2025-12-17 17:30
文章摘要

Linux内核中的Rust代码首次出现CVE漏洞（CVE-2025-68260）。该漏洞涉及Android Binder的Rust重写部分，存在竞争条件可能导致内存损坏和系统崩溃，但不会造成远程代码执行等更严重问题。该漏洞影响Linux 6.18及更新版本。Greg Kroah-Hartman已公布这一情况。

评论摘要
主要讨论点：[Rust在Linux内核中的应用及其对内存安全的影响] 不同观点： • **Rust的支持者**：认为Rust虽然不能完全消除所有错误，但能显著减少内存安全问题。例如，n2d4引用Greg Koah-Hartman的话，指出Rust能大幅减少漏洞，尽管仍有CVE出现，但相比C代码的漏洞数量少得多。 • **Rust的批评者**：认为Rust的`unsafe`块可能导致问题，并且内核开发中不可避免需要共享可变状态，这使得Rust的优势被削弱。phendrenad2指出，内核开发需要大量共享可变状态，`unsafe`块的使用会导致安全边界模糊。 • **中立观点**：认为Rust的价值在于将问题隔离到`unsafe`块中，便于调试，但并不保证完全消除错误。drob518和bangaladore提到，Rust能帮助缩小问题范围，但并不能完全避免错误。 补充讨论： • **争议焦点**：Rust的`unsafe`块是否真的能有效隔离问题，还是会导致安全边界模糊。phendrenad2和uecker指出，`unsafe`块可能成为推卸责任的工具，而实际错误可能由安全代码触发。 • **其他语言对比**：pa7ch提到Zig可能更适合内核开发，而samdoesnothing则质疑为何Rust会受到比其他语言更多的批评。 • **未来展望**：troglo-byte质疑多语言内核是否能减少漏洞，并提到未来技术（如AI）可能改变开发格局。

这篇文章回顾了软塑料模型套装行业的发展历程。20世纪60年代由Airfix主导，70年代Atlantic和Matchbox加入使产量达到高峰。80年代Esci成为主要生产商，90年代Revell、HaT等公司推动产量回升。2000年后东欧厂商崛起，2006年产量达到顶峰（超过100套），但随后因经济放缓和市场饱和出现下滑。2009年产量创纪录（140套），但单个产品销量下降。2010-2013年产量保持较高水平（每年75套以上），主要由HaT、Strelets等公司主导。2014年新发行量锐减至2009年的一半以下，HaT和Mars成为主要生产商。文章展现了该行业从起步、发展到调整的完整周期。
