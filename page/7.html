Extending a Language – Writing Powerful Macros in Scheme

文章摘要

本文介绍了如何在Scheme中编写强大的宏，重点讲解了Scheme宏机制的独特优势，特别是其内置的卫生特性。文章从基础的宏示例开始，逐步讲解了语法对象、宏转换器、破坏卫生机制、分阶段执行以及扩展功能等内容。通过复杂示例（如LR(1)解析器生成器）和练习，帮助读者掌握Scheme宏的编写技巧。文章还提供了使用Chez Scheme、Emacs、Org、Geiser、Paredit等工具的设置指南，帮助读者在交互环境中实践。本文旨在展示Scheme宏的表达能力，并鼓励语言设计者引入类似机制以增强语言的灵活性。

评论摘要
主要讨论点：Scheme语法中的trace-let宏定义及代码格式改进建议，以及对编程语言中全大写命名的争议。 不同观点： • **支持对trace-let宏的格式改进**：[neilv]认为通过一些格式上的调整，可以使trace-let的代码更易于理解。他建议将语法规则模板中的模式变量改为全大写，并进行了其他一些调整，比如增加缩进和命名let循环变量为"loop"。这些改进旨在提高代码的可读性。 • **对全大写命名惯例的批评**：[neilv]强烈反对在某些语言中使用全大写命名常量，认为这是不必要的，甚至是“荒谬的”。他特别提到Java中的全大写常量命名方式，认为这种做法源于Java试图在外观上模仿C/C++，但实际上Java的应用场景与C/C++不同。他呼吁其他语言和API开发者停止这种做法，认为代码中的关键信息不应通过全大写来突出。 补充讨论： • **全大写在不同语言中的使用**：[neilv]认为全大写在Scheme中的使用（如模式变量）是有意义的，并称之为“有史以来最好的用法之一”。他还提到全大写在C预处理器中的使用，认为这是另一种合理的用法，因为预处理器宏可以引入几乎任意的文本。 • **对Java开发历史的推测**：[neilv]推测Java采用全大写常量命名是为了迎合当时从C/C++转来的嵌入式系统开发者，但最终Java的主要用户群体变成了企业内部信息系统开发者，他们并不使用类似C的开发方式。 争议焦点：全大写命名常量在编程语言中的合理性。一方认为这是一种不必要的惯例，尤其在Java中是历史遗留问题；另一方可能认为这是一种有用的惯例，有助于区分常量和其他变量。

文章摘要

本文作者开发了一款名为SuperDose的iOS药物提醒应用，需要使用苹果的紧急警报API，以便在手机静音或勿扰模式下仍能发出提醒通知。尽管苹果的健康应用也使用该API，作者的请求却被拒绝，理由是其应用无法保证使用场景。作者对此感到困惑，因为紧急警报功能需要用户明确同意才能启用，且其他看似不紧急的提醒应用却获得了批准。作者担心没有该权限，用户可能因手机静音而错过关键药物提醒，存在潜在危险，并对苹果的政策感到沮丧。

文章摘要

US Routing 是一个用于美国本地快速路由的 Python 库，基于北美道路数据集，支持通过城市名、邮政编码或坐标进行路由计算。主要功能包括快速路由、多种路由选项（最短距离、最快时间）、详细的路由信息（距离、时长、经过的州）。用户可以通过 pip 或 poetry 安装，并能自定义路由器。该库还提供了用于处理和下载北美道路数据的工具，并支持通过 geometries 构建自定义路由图。项目采用 MIT 许可，贡献者可通过提交 Pull Request 参与开发。
