British Columbia, Time Zones, and Postgres

作者: sprawl_ | 评分: 130 | 评论数: 18 | 发布时间: 2026-06-22 19:21
文章摘要

本文讨论了2026年3月英属哥伦比亚永久采用夏令时(UTC-7)后，Postgres时区存储面临的问题。文章指出，使用timestamptz存储未来预约时间会因时区规则变更导致时间偏差——原本存储的10点预约，在tzdata更新后查询会显示为11点。 **解决方案**：采用"双列模式"存储： 1. local_time（本地时间戳） 2. timezone_name（IANA时区名） 3. starts_at_utc（计算得出的UTC时间） 这种模式适用于需要保留"本地意图"的未来事件（如预约、日历事件），而历史事件或以UTC为准的数据（日志、交易记录）仍应使用普通timestamptz。

评论摘要
主要讨论点：英属哥伦比亚省取消夏令时后，如何在数据库和软件系统中正确存储和处理时间数据 不同观点： • **未来事件存储本地时间+时区，历史事件用UTC**：未来预约（如医生预约）应存储事件发生地的本地时间和时区，因为即使时区规则改变，预约时间的本地意义不变（周一早上8:30仍是8:30）；历史事件则用UTC时间戳 • **只存储UTC时间戳**：数据库中只应存储UTC的Unix时间戳（本质是计数器，全球同一瞬间数值相同），所有时区转换交给经过充分测试的软件库处理，避免手动处理时区带来的风险 • **使用SQL标准类型DATE和TIME**：对于与地点绑定的预约，应使用ANSI SQL的DATE和TIME类型，时区转换应在表示层完成，不属于数据库层 • **双字段存储法**：文章建议的两列存储方法可行，但仍应依赖成熟的软件库处理 补充讨论： 多位评论者强调**必须使用tzdata等成熟库**，不要自己实现时区转换逻辑；有人指出本地时间存储在时钟回拨时会产生**歧义问题**（同一小时出现两次）；也有人认为这类时区变更极少发生，倾向于**事后快速修补数据**而非提前过度设计；BC省内部不同地区时区选择仍在争议中，增加了复杂性。

The new HTTP QUERY method explained

作者: CommonGuy | 评分: 163 | 评论数: 22 | 发布时间: 2026-06-23 06:05
文章摘要

HTTP新增了QUERY方法（RFC 10008）来解决复杂查询的问题。传统上，GET请求通过URL参数过滤数据，但复杂查询会导致URL过长、编码问题和结构表达困难。虽然GET理论上可以带请求体，但各种客户端和服务器实现不一致，可能导致兼容性问题。POST虽支持请求体，但语义上是非幂等的创建操作，不适合查询场景，也无法被缓存。QUERY方法填补了这一空白，它类似GET但支持请求体，被定义为安全和幂等的，可缓存。但目前支持有限，需要谨慎使用，简单查询仍应使用GET，需要分享链接的场景也不适合QUERY。

评论摘要
主要讨论点：HTTP QUERY 新方法的必要性及其与 GET 方法带 body 的争议 不同观点： • **支持 QUERY 方法**：GET 带 body 是 hack 行为，不符合规范，显式的 QUERY 方法更合理；解决了大规模 GET 请求的痛点，body 解析支持不统一的问题 • **反对 QUERY 方法**：应该直接标准化 GET 的 body 支持更简单；新增方法语义与现有方法不匹配，设计不够优雅；CoAP 已支持 GET body，新方法反而造成代理转换摩擦 • **实用性担忧**：企业防火墙和旧版浏览器可能长期不支持 QUERY；昂贵的 SSL 代理设备仅支持 HTTP/1.1，可能导致 DoS；HTTPS 加密导致 CDN 无法缓存 QUERY body，需重构互联网拓扑才能真正受益 补充讨论：有人质疑过度关注 HTTP 方法设计 RESTful 接口的做法，认为 RPC 场景下优先考虑可缓存性元信息不合理；也有人担心网站会用 QUERY 阻止链接分享；DELETE 方法也存在类似 body 支持问题但影响较小。

主要讨论点：关于四元数（quaternion）和计算机图形学参考资料的质量和实用性问题 不同观点： • **fsloth的谨慎态度**：不推荐在生产环境中直接使用速查表（cheat sheets），认为应该参考专业的计算机图形学教材。速查表只适合已经理解概念的人使用，且需要确认其表示方法与实际问题域一致。同时指出目前缺乏既精确又实用的好书。 • **xeonmc的技术批评**：指出速查表中四元数转矩阵和四元数转轴角的公式存在严重缺陷——仅在四元数模长恰好为1时有效。具体问题包括错误地使用`sqrt(1 - a*a)`假设和`acos`函数，应该使用实际分量和`atan2`函数。批评这种有缺陷的公式在网络学习资料（包括维基百科）中普遍存在。 补充讨论：xeonmc强调如果从第一性原理推导四元数三明治公式，就会发现"假设单位四元数的便利简化"实际上是不必要的步骤，在浮点数实现中完全有害无益。这反映出理论简化与工程实践之间的矛盾。
