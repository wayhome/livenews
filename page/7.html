Configuration files are user interfaces

作者: todsacerdoti | 评分: 97 | 评论数: 21 | 发布时间: 2025-09-18 16:43
文章摘要

本文探讨了配置文件作为用户界面的重要性，批评了YAML等常见配置语言的缺陷。作者指出，配置文件本质上是用户界面，但当前行业对其期望过低，导致用户体验不佳。文章建议将配置文件视为真正的用户界面，追求更优的使用体验，并推荐了KSON项目作为优秀范例，展示了配置工具应具备的易用性和防错机制。最后，作者鼓励读者体验KSON的在线演示，以直观感受理想的配置工具形态。

评论摘要
主要讨论点：[KSON作为配置语言的优缺点及与其他配置格式的比较] 不同观点： • **KSON的语法问题** - 批评者指出KSON的无空格敏感性可能导致误导性缩进（如`ports`解析为`[80,8000,10000,12000,[14000]]`的例子）。 - 支持者认为其“JSON超集”特性优于YAML，尽管对`%%`块结束符等设计存在保留意见。 • **实现与供应链风险** - KSON的唯一实现基于Kotlin，依赖预编译库下载（无哈希验证），且构建过程复杂（涉及OpenJDK、GraalVM等），存在供应链攻击风险。 - 跨平台支持有限（仅x86_64/arm64的Windows/Linux/macOS）。 • **与其他配置语言的比较** - **HJSON**：更宽容的JSON变体，但KSON功能更丰富（如代码嵌入）。 - **HOCON**：被部分用户认为优于YAML和KSON。 - **Cue/Dhall/Starlark**：强调配置语言需具备表达力但限制I/O，推荐用于复杂配置。 - **JSON5**：简单易用，适合多团队协作，但缺乏高级功能。 • **代码嵌入的争议** - 反对者认为配置文件中嵌入代码违背架构原则（如`gricardo99`）。 - 支持者认为语言嵌入是实用特性（如`i_s`提及Pkl的类似功能）。 • **配置语言的本质与UX** - 一方认为配置文件是数据而非UI，文本编辑器才是UI（`bee_rider`）。 - 另一方主张配置是用户体验的一部分，需自解释字段名（如`ruuda`的`timeout_ms`例子）。 补充讨论： - **工具链问题**：Pkl等语言的工具链成熟度受质疑（如LSP支持不足）。 - **应用层灵活性**：建议应用支持多格式（如JSON/TOML），用户按需选择（`ruuda`）。 - **历史教训**：Terraform的HCL因冗长和难修改被批评，提示配置工具并非核心问题（`JohnMakin`）。 争议焦点： - 代码是否应嵌入配置文件。 - 配置文件是“数据”还是“用户界面”。 - 无空格敏感性的利弊。

Automatic differentiation can be incorrect

作者: abetusk | 评分: 64 | 评论数: 7 | 发布时间: 2025-09-18 14:01
文章摘要

这篇文章讨论了科学机器学习（SciML）中自动微分（AD）的数值分析问题。作者指出，尽管自动微分在理论上是正确的，但在实际应用中（如ODE和PDE求解），Python的Jax和PyTorch等库提供的标准AD方法可能因数值误差传播导致梯度计算不准确（误差可达60%以上）。相比之下，Julia的SciML库通过非标准改进克服了这些数值不稳定性，但需要在工程上做出权衡。文章强调AD在SciML领域仍面临重大数值挑战。

评论摘要
主要讨论点：[自动微分（AD）在数值计算中的稳定性和正确性] 不同观点： • [ComplexSystems] 认为文章指出的是数值不稳定性，而非理论错误，暗示问题在于实际应用而非理论本身。 • [deckar01] 通过实际使用Sympy的经验指出，符号计算在替换为浮点数时可能 silently fail，强调了实际应用中的问题。 • [Lerc] 认为重点应放在管理误差而非避免误差，特别是在机器学习（ML）中，浮点数精度越来越小的背景下。 • [drnick1] 提到作者倾向于Julia实现，但质疑Julia的普及度，暗示工具选择可能影响问题的解决。 • [ChrisRackauckas] 详细解释了AD在ODE求解中的问题，指出AD在某些情况下无法保证导数计算的准确性，并提到Julia通过修改AD行为来提升精度，但这是以牺牲AD的正确性为代价的。 • [ismailmaj] 从深度学习的角度出发，认为数值误差可以作为一种正则化手段，减少过拟合。 补充讨论： • 争议焦点在于AD的数值稳定性和理论正确性之间的权衡，以及不同工具（如Sympy、Julia）在解决这些问题时的策略。 • ChrisRackauckas的评论提供了具体的例子和技术细节，成为讨论的核心。 • ismailmaj的观点为讨论引入了新的视角，即将数值误差视为有益的正则化手段。

Genesis DB是一款专为事件驱动应用设计的事件存储数据库系统，主打高性能、简单易用和可靠性。其核心特点包括：高速读写、基于HTTP的简洁接口、一键备份恢复、支持CloudEvents标准、完善的监控功能。提供免费版（限制1万事件）和付费标准版（无事件限制），支持离线使用。适用于各类开发和生产环境，兼容Linux/Mac系统和常见CPU架构，可部署于Kubernetes等平台。最新版本为1.0.2，同时提供托管集群服务Genesis DB Velora和事件流处理工具Genesis DB Syncra。
