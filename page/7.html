Try Switching to Kagi

文章摘要

本文讨论了作者对使用谷歌搜索多年后遇到的问题，特别是搜索结果中充斥着广告和不相关的第三方网站，导致被误导并多付费用。作者引用了Aaron Pressman在《波士顿环球报》上的经历，讲述了在谷歌搜索“前往英国”时被误导多付了70美元的经历，以及在预订酒店时再次因误导性搜索结果多花了数百美元。作者随后推荐了一个名为Kagi的新搜索引擎，称其搜索结果更准确、无广告干扰。作者强调，推荐Kagi不是出于隐私考虑或抗议谷歌，而是因为Kagi的搜索结果更可靠，尤其是查找旧文章时表现优异。相比之下，DuckDuckGo虽然也有类似功能，但其搜索结果有时不够理想。

AirBorne: Wormable zero-click remote code execution (RCE) in AirPlay protocol

作者: throw0101a | 评分: 93 | 评论数: 8 | 发布时间: 2025-04-29 13:09
文章摘要

Oligo Security Research发现苹果AirPlay协议及其软件开发工具包（SDK）存在一系列漏洞，可能导致多种攻击，包括无点击远程代码执行（RCE）、单点击RCE、访问控制列表（ACL）绕过、本地任意文件读取、敏感信息泄露、中间人攻击（MITM）和拒绝服务（DoS）等。这些漏洞被统称为“AirBorne”，可能被攻击者利用来完全控制支持AirPlay的设备，包括苹果设备和使用AirPlay SDK的第三方设备。 其中，CVE-2025-24252和CVE-2025-24132两个漏洞可被用于制造可传播的零点击RCE攻击，导致恶意软件在本地网络中传播。苹果与Oligo合作修复了这些漏洞，并发布了更新软件。Oligo共报告了23个漏洞，导致17个CVE编号发布。 攻击可能影响MacOS、AirPlay SDK和CarPlay设备，特别是在设备设置为“同一网络上的任何人”或“所有人”时更易受攻击。攻击者可能通过公共WiFi入侵设备，进而通过企业网络传播攻击。

评论摘要
主要讨论点：Apple的AirPlay协议及其相关安全漏洞问题 不同观点： • Roguelazer认为，将网络协议的解析器以root权限运行是非常不安全的做法，尤其在Apple已经建立了复杂的沙盒和权限分离系统的情况下。他质疑这种设计选择，并猜测是否与DRM有关，但指出DRM守护进程`fairplayd`实际上是以低权限用户运行的。 • throw0101a提到具体的CVE编号（CVE-2025-24252和CVE-2025-24132）作为例子，指出Apple已经修复了相关漏洞，但使用其SDK的第三方可能也需要更新代码。 • m463关注到macOS的网络环境较为开放，提到邻居的AirPlay显示器会出现在镜像下拉菜单中，猜测这可能是攻击面的一部分。 • abhisek对CVE-2025-24252的利用方式表示关注，特别是其在ASLR等防护措施启用的情况下仍实现了零点击远程代码执行（RCE）。 • RainyDayTmrw简单指出，问题再次出现在解析和内存损坏上。 • pjmlp总结了多种内存安全问题（如使用后释放、栈缓冲区溢出、类型混淆等），并讽刺地评论这些错误通常是由初级开发者或实习生编写的代码中出现的，而资深开发者不会犯这样的错误。 • rubatuga则表示自己仍在使用macOS 12，暗示可能对新版本的安全性问题有所担忧。 补充讨论： • 讨论中多次提到内存安全问题，特别是使用后释放（UAF）漏洞，以及这些漏洞在macOS系统中的潜在影响。 • 有争议的焦点在于，Apple在创建了复杂的权限分离和沙盒机制后，仍然在某些关键组件上以root权限运行服务，这与其安全设计理念不符。 • 第三方开发者使用Apple的SDK时，可能未能及时修复相关的安全漏洞，增加了潜在的安全风险。 • 不同用户对新版本macOS的安全性表示了不同程度的担忧。

Art of the Hedgerow

文章摘要

本文探讨了英国树篱在历史、艺术和农业中的角色及其变迁。自1945年以来，约50%的英格兰树篱因农业生产需要被移除，导致生物多样性下降。二战后，为了解决粮食短缺问题，政府推动农业合理化，树篱被视为妨碍生产的存在。1947年农业法案加速了这一进程，虽然有效结束了战后物资匮乏，但也加速了树篱的消失。 然而，树篱并非永久固定，它们随农业需求和经济变化而波动。自公元前2500年以来，农民利用树篱作为农业工具，提供庇护、防风和土地划分。树篱还为多种动植物提供栖息地。 在艺术中，树篱反映了社会经济历史。例如，19世纪画家John Ferneley的作品不仅描绘了贵族狩猎场景，还无意中展现了当时经济衰退的乡村景象——树木被砍作柴火，树篱稀疏破败。树篱在艺术和现实中都是一个变化的实体，体现了英格兰乡村的历史变迁。

Node.js implementation of the BitTorrent DHT protocol

作者: wslh | 评分: 4 | 评论数: 0 | 发布时间: 2025-04-30 16:14
文章摘要

**bittorrent-dht 11.0.9 简介** `bittorrent-dht` 是一个用 Node.js 实现的简单且稳健的 BitTorrent DHT 协议库。DHT（分布式哈希表）是 BitTorrent 网络中用于无追踪器的种子文件的节点发现机制。该模块被 WebTorrent 等项目使用。 ### 主要特性： - 完整实现 DHT 协议（支持 BEP44，可存储任意数据）。 - 经过充分测试，支持多个并发查找，UDP 流量最小化。 - 可自定义选项，如节点 ID、启动服务器、并发数等。 - 支持 `dht_store`，需提供 ed25519 验证函数。 - 提供查找和宣布节点功能，内部处理 token 以防恶意使用。 ### 使用示例： ```javascript import DHT from 'bittorrent-dht'; import magnet from 'magnet-uri'; const uri = 'magnet:?xt=urn:btih:e3811b9539cacff680e418124272177c47477157'; const parsed = magnet(uri); const dht = new DHT(); dht.listen(20000, () => { console.log('listening'); }); dht.on('peer', (peer, infoHash, from) => { console.log(`found peer ${peer.host}:${peer.port} via ${from.address}:${from.port}`); }); dht.lookup(parsed.infoHash); ``` 该库还支持获取 DHT 当前状态、自定义哈希函数、监听端口等功能。

Optimizing eBPF I/O latency accounting when running 37M IOPS, on 384 CPUs

作者: tanelpoder | 评分: 7 | 评论数: 0 | 发布时间: 2025-04-30 07:04
文章摘要

本文介绍了一种更高效的使用eBPF统计Linux块I/O延迟的方法。作者在一个拥有21个NVMe SSD（8个PCIe5和13个PCIe4）的服务器上进行测试，服务器为双路AMD EPYC Genoa，拥有384个vCPU。在未进行底层调优的情况下，fio工具达到了38.5M随机读IOPS和173 GiB/s带宽。 作者在Ubuntu 25.04 Server和Linux 6.14内核上运行测试，使用18个fio工作线程每盘，总共378个线程。测试中发现传统工具biolatency会导致吞吐量下降超过2倍，因为其使用tracepoints产生了较高的CPU开销。 通过分析，作者发现问题在于biolatency使用hashmap记录I/O起始时间，导致每个I/O产生两次eBPF探针开销，每次约16微秒。这在高并发环境下尤其显著，占用了大量CPU资源。 作者提出了一种优化方法，显著降低了eBPF探针的CPU开销，使得在监控I/O延迟时对吞吐量的影响几乎可以忽略不计。优化后的方法将在后续文章中详细介绍。
