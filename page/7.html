Polars Cloud and Distributed Polars now available

作者: jonbaer | 评分: 146 | 评论数: 20 | 发布时间: 2025-09-04 03:01
文章摘要

Polars官方宣布正式推出Polars Cloud云服务，并在AWS上全面开放。该平台提供远程大规模执行Polars查询的能力，同时推出了分布式引擎的公测版，支持水平、垂直和对角线扩展策略，显著降低了大数据处理的成本和复杂度。Polars Cloud旨在弥合本地pandas易用性与远程PySpark可扩展性之间的差距，提供统一的API实现从本地到云端的无缝扩展。即将推出的新功能包括本地部署支持和实时集群仪表板。用户可通过官网立即体验该服务。

评论摘要
主要讨论点：Polars 作为 DataFrame 库的优缺点、与其他工具（如 SQL、DuckDB、Spark）的比较，以及 Polars Cloud 的相关问题。 不同观点： • **支持 SQL 优于 DataFrame API** - 认为 90% 的用例更适合用 SQL（如 AWS Athena、DuckDB、Snowflake），因为 SQL 更易于开发、调试、共享和迁移。 - 举例：分析师无需关心底层实例类型（如 m6.xlarge vs. c6g.large）。 • **支持 Polars 优于 Pandas** - Polars（尤其是 LazyFrames）在非交互式大规模计算中性能显著优于 Pandas（20 倍速度提升）。 - 认为 Polars 在 Python 生态中更具竞争力，但希望其 Rust 原生库更易用。 • **质疑 Polars 的实用性** - 对大规模数据集，DuckDB 表现更好，且 SQL 在 AI 辅助下更易编写。 - 提问：若最终用 SQL，为何从 Polars 开始？ • **对 Polars Cloud 的疑问** - 分布式 Polars 是否支持自托管（非云）？当前答案是否定的。 - 计费模式：用户是与 AWS 还是 Polars 签订合同？ - 期望抽象化底层实例类型，自动选择性价比最优的资源（如 spot 实例）。 补充讨论： - **工具命名调侃**：Snowflake、DuckDB、FireDuck 等名称被吐槽，引发对数据库产品命名趋势的玩笑（如预测下一款为 "IceDuck"）。 - **混淆澄清**：Polars（DataFrame 库）与 Polar（支付服务）名称相似易混淆。 - **与其他工具对比**：用户询问 Polars 与 FireDucks 的比较，但未展开。 - **生态竞争**：质疑 Databricks 过度投资 Spark，而 Polars/DuckDB 对初创公司已足够。 争议焦点： - Polars 是否适合大规模分布式场景？ - SQL 与 DataFrame API 的优先级之争。 - Polars Cloud 的灵活性与用户控制权（如自托管、资源选择）。
