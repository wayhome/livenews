PHP's Oddities

作者: thejoeflow | 评分: 128 | 评论数: 38 | 发布时间: 2026-05-19 20:41
文章摘要

这篇文章讨论了作者使用PHP五年后发现的两个主要问题： **1. 数组不是真正的数组**：PHP的"数组"实际是有序键值字典。看似普通数组，但执行过滤、删除等操作后，数字索引会变得不连续，导致访问`$array[0]`时出错。必须用`array_values()`重新索引才能修复，这是个容易引发bug的设计缺陷。 **2. 类属性类型系统混乱**：PHP7引入类型系统后，属性有三种声明方式（无类型、强类型、可空类型），但行为不一致。无类型属性初始化为NULL，而有类型属性则处于"未初始化"状态，访问时会报错。这种不一致性容易造成困惑和错误。 作者认为这些设计虽然PHP已经成熟，但某些特性仍然反直觉且容易导致bug。

评论摘要
主要讨论点：PHP语言的优缺点及现代发展 不同观点： • **PHP现代化支持者**：认为现代PHP已大幅改进，拥有强大的语言特性、优秀性能、静态分析工具和活跃社区。特别适合简单应用（PHP+SQLite组合仅需十几个文件，而Node.js项目可能有49,000个文件）。Laravel等框架功能强大，开发效率极高。 • **PHP批评者**：核心问题是基础设计缺陷——需要三等号运算符（===）本身就说明普通相等运算符（==）设计失败；类型强制转换不直观；运行时行为依赖配置，导致不确定性。这些问题迫使开发者为最基本的操作查阅文档。 • **务实派**：承认PHP有诸多怪异之处（loose comparison、numeric-strings等），但认为文章提到的问题被夸大。SplFixedArray可解决数组问题，typed properties的未初始化状态有其设计理由（如对象水合、防止访问未就绪的值）。实际开发中这些问题并不常见。 • **从其他语言转来的开发者**：从Java转PHP者欣赏PHP的灵活性但怀念编译时安全；从TypeScript转来者希望PHP支持结构化类型对象和类型别名。 补充讨论：PHP 9将禁止动态属性添加，泛型可能即将实现。多数负面评价来自15年前的刻板印象，现代PHP已显著进化。

.NET (OK, C#) finally gets union types

作者: ingve | 评分: 177 | 评论数: 21 | 发布时间: 2026-05-22 12:28
文章摘要

这篇文章介绍了 C# 15（.NET 11）中新增的联合类型（Union Types）特性。联合类型允许一个变量表示多种不同的类型，这在函数式编程语言中很常见。 文章通过操作系统类型的例子展示了如何使用 `union` 关键字定义联合类型，例如 `public union SupportedOS(Windows, Linux, MacOS)`。使用时可以通过隐式转换创建实例，并用 `switch` 表达式处理不同的类型分支，编译器会强制检查所有可能的类型。 这个特性解决了以往需要用基类继承、object 类型或枚举标记来处理多类型数据的问题，提供了类型安全且简洁的解决方案。联合类型实现了 `IUnion` 接口，可通过 `.Value` 属性访问内部值。

评论摘要
主要讨论点：C# 即将引入联合类型（union types）功能 不同观点： • **积极支持派**：sedatk、glimshe 等认为这是期待已久的功能，赞赏团队努力。C# 在保持易用性的同时逐步增加性能优化特性，让开发者可以按需选择 • **F# 对比派**：rohitsriram、munchler 指出 F# 早已具备此功能数十年，C# 只是在缓慢追赶。尽管 F# 引领创新，但 C# 仍占据主流市场 • **跨语言借鉴派**：caioricciuti 认为 TypeScript 和 Rust 已证明类型级别的"或"建模能让代码更清晰，关键在于库作者是否会在公共 API 中采用 • **技术批评派**：ComputerGuru、bartwe、moomin 指出实现缺陷——默认会对值类型装箱（boxing），且无法定义 Either 这类同类型联合 补充讨论： cubefox 详细解释了"标记联合"（tagged unions）与"非标记联合"（untagged unions）的根本区别。C# 实现的是标记联合（代数数据类型），但命名容易与 TypeScript/Scala 3 的集合论式非标记联合混淆。hahn-kev 强调此功能对跨语言互操作的价值。jdw64 借机吐槽 C# 生态系统（如 MAUI）不够成熟。
