Arbitrary code execution in Unity Runtime

作者: andygmb | 评分: 84 | 评论数: 9 | 发布时间: 2025-10-03 13:21
文章摘要

2025年10月，安全工程师RyotaK发现Unity Runtime中存在一个高危漏洞(CVE-2025-59489)，影响2017.1及以后版本构建的游戏和应用。该漏洞允许攻击者通过控制命令行参数加载恶意共享库(.so文件)，实现任意代码执行。在默认配置下，本地恶意应用可劫持Unity应用的权限；特定情况下还能远程利用。Unity已为2019.1及以后版本发布补丁，建议开发者立即更新并重新编译发布应用。文章详细分析了漏洞的技术细节（包括Intent处理机制和xrsdk-pre-init-library参数的利用方式）及攻击场景，强调及时修复的重要性。

评论摘要
主要讨论点：[Unity漏洞的安全性影响及跨平台威胁模型] 不同观点： • [第一种观点] 该漏洞仅在Android平台上有效，因此“depending on the platform”的说法不准确。 - 论据：Intents是Android特有的机制，其他平台不受影响。 • [第二种观点] Windows平台也存在类似问题，但方法不同（如通过dx9 dll或同名dll注入代码）。 - 论据：Windows上已有常见的代码注入方法，漏洞新颖性存疑。 - 补充：URI处理可能是更严重的攻击向量。 • [第三种观点] WebGL平台的安全性未提及，可能存在风险。 - 论据：Unity官方对WebGL问题的回应不充分。 - 例子：https://discussions.unity.com/t/webgl-project-running-only-i... • [第四种观点] 漏洞的实际威胁性存疑，需依赖其他条件才能实现RCE。 - 论据：浏览器漏洞受SELinux限制，现实攻击可能性低。 • [第五种观点] 游戏软件常牺牲安全性以加快开发速度，但远程攻击链不明确。 - 论据：Android浏览器攻击场景的可行性未知。 补充讨论： • 争议焦点：漏洞的实际威胁性和跨平台影响是否被夸大。 • 其他讨论：用户对Unity的替代方案（如Godot）的兴趣。
