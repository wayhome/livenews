Stoolap 是一个用 Rust 编写的嵌入式 SQL 数据库，具有 MVCC 事务支持，提供内存和持久化两种存储模式，并保证 ACID 特性。主要功能包括： 1. 事务支持：提供读已提交和快照隔离两种隔离级别 2. 时间旅行查询：可查询历史数据 3. 多种索引类型：B树、哈希、位图等 4. 窗口函数、CTE(包括递归)、高级聚合等分析功能 5. 子查询支持 项目提供库和命令行两种使用方式，采用 Apache-2.0 许可协议，具有现代数据库的典型特性。

评论摘要
主要讨论点：[Stoolap作为新兴的嵌入式SQL数据库的性能、功能、命名争议及与其他数据库（如SQLite）的比较] 不同观点： • 支持与期待： - 项目受到关注，特别是其纯Rust实现、高性能和完整的功能集（如ACID事务、MVCC、并行查询等）。 - 用户对时间旅行查询功能表示好奇，尽管对其存储完整事务历史的成本表示疑问。 - 有人对与SQLite的性能比较表示兴趣，认为这有助于评估其实际应用价值。 • 质疑与批评： - 项目非常新，提交历史短暂（仅两天），引发对其成熟度和稳定性的担忧。 - 命名争议较大，多名用户指出“Stoolap”听起来像“stool app”（与“粪便”相关），认为这是一个糟糕的选择。 - 缺乏详细的性能基准测试和数据，用户希望看到与SQLite和PostgreSQL的具体比较。 • 技术细节讨论： - 用户询问时间戳的分辨率（毫秒、微秒、纳秒）以及对大数据BLOB的支持（如PostgreSQL的TOAST）。 - 有人关注是否支持并发写入（SQLite的弱点之一）以及是否为单文件数据库及其格式稳定性。 补充讨论： - 项目的作者背景和动机尚不明确，但有人发现作者之前有一个类似的Go实现项目，表明这并非首次尝试。 - 一些用户认为项目可能是“vibecoded”（即基于兴趣而非严谨开发），对其生产环境适用性表示怀疑。 - 尽管功能丰富，但用户更关注实际性能和数据支持的细节，希望看到更多实证数据。
