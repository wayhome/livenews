Tuning LLVM's SLP Vectorizer Cost Model

作者: matt_d | 评分: 6 | 评论数: 0 | 发布时间: 2026-05-28 16:44
文章摘要

这篇文章讨论了LLVM编译器SLP向量化器的性能回归问题。作者发现一个LLVM补丁将标量浮点加法链替换为有序向量归约指令后，在RISC-V目标上导致性能下降89%。 问题根源在于：新代码虽然使用了向量归约指令（vfredosum.vs），但每次迭代都需要先将标量值存储到栈上（fsd指令），再加载到向量寄存器，这个构建向量的开销未被正确计入成本模型。结果导致指令数增加26%，执行周期增加48%。 作者通过分析汇编代码和LLVM IR，定位了引入这些低效指令的位置，为修复这个成本模型缺陷提供了基础。

A New Typst Template for Pandoc (2025)

作者: ankitg12 | 评分: 110 | 评论数: 11 | 发布时间: 2026-05-26 05:08
文章摘要

文章介绍作者因 Typst 与 Pandoc 升级导致旧模板失效，于是重建了一套新工作流：改用 Pandoc 默认 Typst 输出模板，并通过 `-V template=article.typ` 调用真正的 Typst 模板。新模板能读取 Markdown 元数据，提供页眉页脚、字体排印、引文、代码块、图片标题、脚注、标题层级、epigraph 与参考文献等样式，结构更清晰，也更利于长期维护。

评论摘要
主要讨论点：关于使用 Pandoc 将 Markdown 转换为 Typst 再生成 PDF 的工作流程 不同观点： • **支持 Markdown+Pandoc 工作流**：多位用户认为这种方式很实用，特别是需要同时输出多种格式（PDF、Word）时，便于与习惯 Word 的合作者协作；有人已成功应用于设计文档和咨询工作，可实现交叉引用、图表、目录等功能 • **质疑 Markdown 必要性**：认为 Typst 语法本身已经足够简单（不比 Markdown 难），直接用 Typst 编写更合理，无需引入 Pandoc 这个中间环节；一位开发者创建了直接在 Typst 中导入 Markdown 的库，认为单一构建步骤、无中间文件更有优势 • **Typst 体验极佳**：多位用户从 LaTeX 转向 Typst 后体验显著提升，编译时间从 10 秒降至 10 毫秒，生产力大幅提高；从零构建模板的时间从数天缩短到不到一天 补充讨论： • 版本兼容性问题：作者提到模板在 Typst 和 Pandoc 多次升级后失效，这是该工作流的潜在风险 • 文章展示不足：有读者希望看到具体的 Markdown 格式示例和输出 PDF 效果 • 对工作流理解困惑：有人不理解为何需要 Typst 参与 Markdown 到 PDF 的转换

文章摘要

这篇文章分析了五个前沿AI模型在事实核查任务中的一致性表现。主要发现： **核心数据：** 67%的声明中至少有一个模型与多数意见不同，仅33%达成完全一致。34%的声明存在实质性分歧（判断相差2个等级以上，如"真实"vs"误导性"）。 **模型间差异：** 不同模型对间的一致率在53%-75%之间。Gemini 3 Pro与其搜索增强版一致性最高（75%），Claude Opus 4.7与Gemini系列一致性最低（53%）。 **误差下限：** 假设多数意见正确，至少67%的声明中有模型判断错误，45%的声明中至少两个模型出错。 文章强调这些分歧反映了AI在无标准答案的复杂判断任务中的局限性。
