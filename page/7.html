Using Git's rerere feature to escape recurring conflict hell

作者: ankitg12 | 评分: 92 | 评论数: 9 | 发布时间: 2026-06-01 07:06
文章摘要

这篇文章介绍了 Git 的 `rerere` 功能（Reuse Recorded Resolution，重用已记录的解决方案）。当合并分支时遇到重复的冲突，`rerere` 可以记住你之前如何解决冲突，并在相同冲突再次出现时自动应用相同的解决方案。 启用方法：运行 `git config --global rerere.enabled true` 工作原理：首次遇到冲突时，`rerere` 会记录冲突状态和你的解决方式。当相同冲突再次出现时，Git 会自动应用之前的解决方案，无需手动处理。这大大减少了在合并或变基过程中反复解决相同冲突的痛苦。

评论摘要
主要讨论点：Git 工作流中 merge 与 rebase 的使用策略，以及如何避免冲突和回归问题 不同观点： • **严格单向流动派（dools）**：坚持"远离 main 时 rebase，朝向 main 时 merge"的原则。所有冲突都发生在特性分支上，main 分支永远不会有冲突。这种方法彻底解决了静默回归问题。 • **最小化 rebase 派（jstimpfle）**：认为频繁 rebase 会导致中间提交无法构建，历史记录失去意义。主张只在独立特性分支上做简单的 rebase -i 操作，其他情况直接 merge。强调 HEAD 指向的提交最重要，过度清理历史是浪费时间。 • **严格分支隔离派（adithyassekhar）**：倡导开发者之间不直接合并分支，只从 master 拉取已完成的代码。多环境部署遵循单向流动：feature > dev > staging > master。认为需要他人未完成代码是规划问题。 • **工具辅助派（0123456789ABCDE, barchar）**：推荐启用 rerere（自动记忆冲突解决方案）等 Git 配置来简化冲突处理。提到 rerere-train 脚本可从现有合并中预填充冲突解决方案。 • **工具替代派（mamcx）**：在团队强制使用 rebase 时 rerere 效果有限，后转向 jujutsu 工具，认为它能更好适应他人的工作流程。 补充讨论：多人提到 Git 配置技巧（如 zdiff3、autoSquash）和 ORIG_HEAD 等恢复机制的重要性。

文章摘要

Cloudflare Turnstile（人机验证系统）最近开始要求通过WebGL进行设备指纹识别，导致基于WebKit-GTK的浏览器无法通过验证而陷入无限循环。WebKit多年来一直屏蔽此类指纹追踪技术，但Cloudflare声称需要浏览器指纹来验证用户身份，认为阻止指纹识别的隐私工具会让浏览器看起来像机器人。这实际上封禁了所有WebKitGTK浏览器（Safari除外）。文章还指出Firefox的WebGL指纹保护存在漏洞，即使启用严格隐私保护也未默认开启`privacy.resistfingerprinting`选项，未来可能也会受到影响。

评论摘要
主要讨论点：Cloudflare Turnstile 要求启用 WebGL 进行指纹识别，导致启用隐私保护的 Firefox 用户无法通过验证 不同观点： • **理解但批评方**：理解 Cloudflare 需要防机器人，但指纹识别破坏隐私，应提供 PoW（工作量证明）等替代方案。Turnstile 声称注重隐私却要求 WebGL 指纹识别，与其宣传矛盾 • **隐私优先方**：反对任何形式的指纹识别，认为这是"对抗机器人战争"导致互联网封闭化的开始，将网络变成只允许"批准"浏览器的围墙花园。"AI 爬虫"只是制造共识的借口 • **实用主义方**：Firefox 的 `privacy.resistfingerprinting` 功能会导致网站异常（时区错误、字体问题、视频播放失败），不适合默认启用。`fingerprintingProtection` 是更平衡的选择 • **阴谋论方**：怀疑 Google 与 Cloudflare 合作迫使用户使用 Chrome，同时削弱 Chrome 的广告过滤能力 补充讨论：小众浏览器（Cromite、Konform）受影响严重，Cloudflare 要求加入需签 NDA 的开发者计划才能解决兼容性；Mozilla 工程师表示难以复现问题，怀疑 Cloudflare 使用复杂的风险评估系统；部分用户报告在匿名社交账号发表敏感言论后被 Turnstile 锁定，引发监控担忧。
