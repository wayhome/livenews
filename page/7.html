Disposable Code Is Here to Stay, but Durable Code Is What Runs the World

作者: mooreds | 评分: 39 | 评论数: 3 | 发布时间: 2025-09-11 19:46
文章摘要

这篇文章探讨了软件开发领域的两种代码类型：一次性代码（disposable code）和持久代码（durable code）。一次性代码主要用于快速原型、实验等场景，成本低且无需维护；而持久代码则用于银行、医疗等关键领域，需要高可靠性和长期维护。作者指出，AI生成代码虽然提高了开发效率，但对持久代码来说，测试、可观测性和反馈循环仍然至关重要。文章强调，真正的软件成本取决于维护标准，持久代码的核心在于建立信任，而这需要时间和严谨的开发流程。

评论摘要
主要讨论点：AI是否能生成持久、高质量的代码，以及现有关键系统代码的现状。 不同观点： • **现有关键系统代码质量堪忧** - cbdumas指出，银行、医疗、航空等关键系统的代码虽然持久，但质量低劣，充满临时解决方案和漏洞（如依赖Excel）。 - 论据：实际生产代码通常“丑陋”但有效，说明“持久”不等于“良好”。 • **AI可以生成高质量代码** - Arn_Thor认为，AI和“氛围编程”并不妨碍生成健壮、持久的代码，关键在于开发者需谨慎设计功能，避免让LLM添加冗余功能。 - 论据：开发者的审慎态度是决定代码质量的核心，而非工具本身。 • **AI未来可能超越人类编码能力** - mfro反驳了“AI无法生成持久代码”的假设，认为AGI（通用人工智能）将写出远超人类能力的代码，问题只是时间。 - 论据：人类追求AGI的趋势不可逆，其代码能力将呈指数级提升。 补充讨论： - 争议焦点：AI生成代码的“持久性”是否受限于当前技术，还是未来必然突破。 - 隐含问题：代码“持久性”的定义——是否应以功能性（当前讨论）或可维护性/扩展性为衡量标准。
