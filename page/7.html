Web Server for AoE 1, 2 and 3 DE supporting LAN multiplayer 100% offline

作者: apitman | 评分: 421 | 评论数: 20 | 发布时间: 2025-04-02 23:10
文章摘要

Age LAN Server 是一个支持《帝国时代》1、2、3决定版进行局域网（LAN）多人游戏的离线 web 服务器。它允许玩家在没有互联网连接的情况下进行游戏，即使官方服务器维护或关闭，LAN 功能仍可使用。该项目目前处于维护状态，仅修复错误和更新依赖项。要完全离线游玩，玩家需要自定义启动器来绕过游戏的联网限制，并可能使用 Steam 模拟器。 支持功能包括场景模式、地图传输、游戏恢复、模组支持、大厅聊天和跨平台联机（Steam 和 Xbox）。但也存在一些限制，如无法进行排名比赛、无法观战、好友列表显示所有在线用户等。此外，成就、排行榜、玩家数据等功能在离线模式下无法使用。 服务器最低系统要求包括 Windows 10、Linux kernel 2.6.32 及以上、macOS Big Sur 等，客户端则需对应游戏的特定版本。

文章摘要

文章解释了作者为何避免与朋友讨论政治。主要原因有二：首先，大多数人并没有独立的政治观点，而是依赖于政治部落的集体立场。形成独立政治见解需要掌握广泛的知识并克服偏见，这是一项非常困难的任务，因此人们倾向于简化问题，依赖群体文化。其次，许多人并不愿意摆脱部落主义，因为部落归属感能带来关系和情感上的安全感，即使这以牺牲理性讨论为代价。政治讨论常被用来验证对群体文化的忠诚，而非真诚的知识交流，这让真诚参与讨论的人容易遭遇社交上的尴尬。因此，作者选择不与朋友讨论政治，以避免这些矛盾和冲突。

An open source, self-hosted implementation of the Tailscale control server

作者: quyleanh | 评分: 277 | 评论数: 13 | 发布时间: 2025-04-03 00:23
文章摘要

Headscale 是一个开源、自托管的 Tailscale 控制服务器实现，专为自托管爱好者和小型开源组织设计。Tailscale 是一个基于 Wireguard 的现代 VPN，其控制服务器负责交换节点间的 Wireguard 公钥、分配 IP 地址、管理用户边界、共享机器以及暴露节点路由。Headscale 旨在提供一个单一的 Tailscale 网络（tailnet），适合个人或小型组织使用。项目文档提供了功能、客户端支持和运行指南等详细信息。开发者需使用 Go 和 Buf 工具，并遵循特定的代码风格和格式要求。项目与 Tailscale 公司无关，但有维护者在 Tailscale 工作并贡献代码。

评论摘要
主要讨论点：Headscale与Tailscale的安全性、功能性、开源性及其实际应用的讨论 不同观点： • **SuperShibe的观点**：对Headscale的安全性表示担忧，特别是Tailnet lock和安全审计的进展缓慢。他认为Headscale虽然成功绕过了防火墙，但在提供足够的安全措施上有所不足。同时，对Tailscale的控制服务器无法让用户了解或否决其指令表示担忧。 • **infogulch的观点**：建议Headscale允许实例间的对等/联合，并提出具体的IPv6和ULA范围的方案以解决地址冲突问题。不过，该建议之前被项目维护者认为超出了当前范围。 • **Happily2020的观点**：推荐自我托管的Netbird作为Tailscale的替代方案，强调Netbird的控制服务器是开源的，并提供与付费版本相同的功能和GUI。 • **1vuio0pswjnm7的观点**：指出Headscale允许用户通过阅读、编辑和编译源代码来理解或否决控制服务器的指令，而Tailscale则不允许。他认为不是所有用户都需要或想要编辑第三方软件的能力，有些用户可能更信任由风投资助的公司。 • **pilif的观点**：提醒大家注意Tailscale官方客户端维持设置控制服务器能力的重要性，担心如果Tailscale公司出现问题（如资金不足或被收购），该功能可能会消失。 • **3abiton的观点**：质疑Headscale相对于Wireguard + OpenWrt设置的附加价值，要求明确其优势。 补充讨论： • **aborsy的风险担忧**：询问如果Tailscale协调服务器被攻破并启用了Tailnet lock的情况下，设备被 compromised 的风险有多大。 • **mountainriver的积极反馈**：表示Headscale在生产环境中表现出色，非常满意。 • **snvzz的长期使用体验**：认为Headscale在半年的使用中非常出色，已经离不开它。 • **udev4096的实际应用问题**：关心Headscale在通过Jellyfin/Plex流媒体传输视频时的表现。 • **pluto_modadic的疑问**：关心自我管理Headscale时的一些bug是否已经解决。 争议焦点： • Headscale与Tailscale在安全性、开源性和控制权上的对比，特别是用户是否需要编辑、理解和否决控制服务器指令的能力。 • Headscale的功能扩展（如实例对等/联合）是否应纳入项目范围。

Minimal CSS-only blurry image placeholders

作者: ChiptuneIsCool | 评分: 234 | 评论数: 21 | 发布时间: 2025-03-30 11:11
文章摘要

这篇文章介绍了一种通过纯CSS实现模糊图片占位符（LQIP）的技术，只需一个自定义属性，无需额外标记或JavaScript。具体方法是使用一个整数类型的CSS自定义属性（如`--lqip: 192900`），通过位打包将图片信息压缩进该整数中，再通过CSS的`calc()`函数和模运算解码，生成一个非常模糊的占位图。该技术利用20位整数存储图片信息，包括一个基础颜色和6个亮度成分，形成3×2的网格。尽管非常模糊，但该方法极简且不侵入HTML结构。CSS整数的取值范围在-999,999到999,999之间，提供约200万种不同的LQIP配置。这种方法被称为“哈希”是因为它将任意大小的图片数据映射为固定大小的值。

评论摘要
