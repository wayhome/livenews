Martin Fowler探讨了生成式AI，尤其是大型语言模型（LLMs），对软件开发的深远影响。他认为，LLMs带来的变革堪比从汇编语言到高级编程语言的转变，但这次不仅是抽象层次的提升，还引入了非确定性工具的编程问题。过去，高级语言（如Ruby）使编程变得更加直观和高效，但本质上仍是以传统方式与机器对话。而LLMs的非确定性特性意味着，使用提示词与机器交互将带来根本性变化，每次输出的结果可能不同，无法通过版本控制确保一致性。这种非确定性是软件开发历史上前所未有的，虽然带来挑战，但也蕴含着尚未被完全理解的机遇，令人兴奋。

The right thing for the wrong reasons: FLOSS doesn't imply security (2022)

作者: transpute | 评分: 4 | 评论数: 0 | 发布时间: 2025-06-29 01:01
文章摘要

本文探讨了开源软件（FLOSS）的源代码可用性与安全性之间的关系，强调源代码的可用性并不直接等同于软件的安全性。作者指出，虽然源代码对于用户自由至关重要，但许多人以错误的理由支持源代码公开，例如认为源代码是确保软件透明度和安全性的唯一途径。实际上，源代码描述的是软件的设计意图，而非其实际行为，漏洞发现通常通过逆向工程和模糊测试完成，而非依赖源代码。源代码在安全修复过程中有助于理解问题，但对漏洞的发现和初步分析并不必需。此外，编译器优化、操作系统问题和代码混淆等因素可能使源代码无法准确反映程序的真实行为。作者总结，源代码的不可用并不意味着不安全，其公开也不自动保证安全性。

文章主要讨论了在C++11中正确初始化随机数生成器（RNG）的挑战，尤其是种子的质量问题。C++11提供了`std::seed_seq`来改善种子数据，但其设计存在缺陷，可能将高质量的种子数据“变差”。文章指出，使用单一32位整数作为种子是非常不可取的，因为它仅能提供约40亿种可能的初始状态，容易被预测和攻击。 更糟糕的是，这种方法还可能导致偏差，影响随机数的均匀分布。例如，在大规模应用（如Twitter应用）中，使用低质量种子可能导致大量设备生成相同的随机数序列，造成严重问题。尽管一些脚本语言（如JavaScript、Python）依赖操作系统提供高质量随机种子，C++的`std::random_device`访问操作系统随机性却不容易直接用于初始化RNG，因为C++生成器仅接受`std::seed_seq`或单个整数作为种子。 总之，文章强调了在C++中正确初始化RNG的困难，并警告开发者避免使用低质量种子。

c4wa – C compiler for Web Assembly

作者: 90s_dev | 评分: 77 | 评论数: 9 | 发布时间: 2025-06-24 15:52
文章摘要

**c4wa** 是一个将 C 语言的简化子集编译为 Web Assembly (WASM) 的编译器。它生成的 WASM 输出精简且高效，没有额外的嵌入库或不必要的开销，并且与任何 WASM 运行时完全兼容，不依赖 JavaScript 或 node。该编译器充分利用 WASM 的线性内存模型，支持动态内存分配，并且可以输出文本格式的 WAT，便于理解和手动编辑。 **c4wa** 支持 C 语言的基本特性如循环、条件、指针、结构体、数组和动态内存分配等，适用于日常编程任务。与其它编译器相比，它避免了生成臃肿的 WASM 代码，提供了一种介于高级语言和手写 WAT 之间的中间方案。 该工具需要 Java 11 或更高版本，使用预处理器时需要外部 C 编译器如 gcc。生成的 WASM 文件跨平台，可以在任何支持 WASM 的运行时中执行，包括浏览器。
