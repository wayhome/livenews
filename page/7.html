GitHut – Programming Languages and GitHub (2014)

作者: tonyhb | 评分: 69 | 评论数: 14 | 发布时间: 2025-11-20 21:33
文章摘要

GitHut 是一个可视化分析 GitHub 上编程语言使用情况的平台。它通过 GitHub Archive 的数据，展示了不同语言的活跃度（按仓库活动量而非创建量统计），帮助开发者了解语言流行趋势。平台采用季度更新，数据来源于 GitHub API 和 Google BigQuery。由于很多仓库未标注语言类型，GitHut 选择以代码提交活动量作为主要评估指标。项目还参考了维基百科的编程语言年表，所有方法论和数据都在 GitHub 开源，采用知识共享许可协议。

评论摘要
主要讨论点：[GitHut 项目的数据更新问题及编程语言相关讨论] 不同观点： • **数据更新需求** - [ethmarks] 指出项目数据仅更新至2014年，而GitHub现有数据已大幅增长（2025年约5亿仓库），建议社区利用开源代码和公开的GitHub Archive数据（更新至2024年）重建项目。争议焦点：数据更新是否可行及工作量评估。 - [steveklabnik] 补充存在GitHut 2.0（更新至2024年），但未回应是否覆盖全部需求。 • **编程语言分析争议** - [kodablah] 关注语言与"pushes per repository"的关联性，认为C++、Rust等语言因调试需求高频提交。 - [ivanjermakov] 批评数据分析未按仓库流行度（如star数）加权，认为现有方法不科学。 - [into_ruin] 提出Swift语言流行度疑问，猜测可能与开源项目较少有关。 • **可视化工具改进建议** - [akerl_] 希望支持按列排序并优化线性展示，同时确认数据仅覆盖2012-2014年。 补充讨论： - 语言历史回顾：[jonny_eh] 和 [irfn] 提及1995年是语言爆发年（JavaScript/Java/Ruby/PHP）。 - 遗漏语言质疑：[miguel_martin] 询问Nim、Zig等语言未纳入的原因。 - 项目状态推测：[ethmarks] 认为原项目可能已废弃，但未获其他用户直接回应。

Exploring the Fragmentation of Wayland, an xdotool adventure

作者: viraptor | 评分: 69 | 评论数: 13 | 发布时间: 2025-11-16 02:00
文章摘要

本文回顾了xdotool工具的开发历史及其在X11系统下的功能实现，重点讨论了Wayland取代X11时带来的功能碎片化问题。作者指出，Wayland以安全为由移除了X11的许多核心功能（如窗口管理、输入模拟等），导致十多年后仍缺乏统一解决方案。不同桌面环境（如GNOME和KDE）各自采用临时方案，造成功能实现碎片化，用户体验不一致，且权限提示信息模糊不清。文章批评了Wayland生态发展缓慢，怀念X11时代稳定统一的标准（如EWMH），并指出当前虚拟输入等基础功能仍需依赖root权限或复杂变通方案，远未达到X11的成熟度。

评论摘要
主要讨论点：[Wayland与X11的比较及其在自动化工具、键盘布局和用户体验方面的优缺点] 不同观点： • **支持X11的观点**： - X11在键盘布局自定义（如Xmodmap）、自动化工具（如xdotool）和虚拟机兼容性方面更为成熟和灵活。 - Wayland的解决方案（如keyd）复杂且脆弱，用户体验较差。 - X11的技术债务虽多，但用户效率更高。 • **支持Wayland的观点**： - Wayland通过分离关注点解决了X11的安全性和可维护性问题。 - X11是一个庞大的、难以维护的项目，开发者已转向Wayland。 - Wayland的协议正在逐步完善，未来可能会解决当前的兼容性问题。 • **中立或批评Wayland的观点**： - Wayland的协议虽然存在，但各合成器实现不一致，导致工具（如xdotool）行为不一致。 - Wayland在UI自动化和无障碍功能方面进展缓慢，部分原因是资金和技术复杂性。 - Wayland的生态系统碎片化严重，缺乏统一的共享约定。 补充讨论： - **争议焦点**： - Wayland是否真的解决了X11的安全问题，还是以牺牲用户体验为代价。 - Wayland的碎片化是否阻碍了Linux桌面的发展。 - Wayland的未来发展是否需要更多的资金和开发者协调。 - **其他讨论点**： - 国际键盘支持在X11和Wayland中均不理想。 - Wayland的协议设计是否过于保守，缺乏对3D和网络图形的前瞻性支持。 - X11的兼容层（如XWayland）在Wayland中的表现和局限性。

文章摘要

评论摘要
主要讨论点：[C++中对象移动语义的复杂性及其与其他语言的比较] 不同观点： • [amluto的观点]：C++的移动语义（尤其是destructive move）与语言的其他特性（如变量类型的有效性保证）紧密相关。他指出C++可以引入一种新的对象类型，既不支持复制也不支持非破坏性移动，但支持破坏性移动。同时，他对比了Go和Python的处理方式，认为Go倾向于允许变量可能无效，而Python可能通过类型检查强制要求在使用前验证变量的有效性。 • [staplung的观点]：通过引用Herb Sutter的报告，指出C++26中由于发现了一个无法修复的关键bug，决定移除“trivial relocatability”特性，暗示C++在移动语义上的复杂性可能难以解决。 • [CosmicZombie的观点]：认为C++过于复杂，尤其是在学习Rust之后，C++的复杂性显得不必要。他将C++比作地心说，而Rust则是更简单的日心说，表达了对C++设计的不满。 补充讨论： • [andrewmcwatters的观点]：虽然未直接参与核心讨论，但对某位评论者的语法表示赞赏，可能暗示对简洁语法的偏好。 争议焦点： • C++的移动语义是否过于复杂且难以修复，尤其是在与其他语言（如Go、Python、Rust）的对比中，这一问题引发了关于语言设计复杂性和实用性的讨论。

《Chrono Divide》是一款基于网页技术的粉丝自制游戏，旨在复刻经典RTS游戏《红色警戒2》。该游戏无需安装插件，直接在浏览器中运行，支持跨平台游玩（包括移动设备），并已实现多人联机、原版地图等功能。项目最初是技术实验，现目标是与原版功能完全一致。游戏提供现代客户端体验，支持模组安装，兼容部分原版模组。开发者呼吁玩家通过捐赠支持服务器和开发成本。目前Beta版已开放，推荐使用Chrome等主流浏览器体验。
