Unauthenticated Remote Code Execution in Erlang/OTP SSH

作者: kimi | 评分: 184 | 评论数: 11 | 发布时间: 2025-04-17 13:29
文章摘要

CVE-2025-32433 是指 Erlang/OTP 库中的一个安全漏洞。在 OTP-27.3.3、OTP-26.2.5.11 和 OTP-25.3.2.20 之前的版本中，SSH 服务器存在漏洞，可能允许攻击者执行未经身份验证的远程代码执行（RCE）。利用 SSH 协议消息处理中的缺陷，攻击者可以未经授权访问系统并执行任意命令。该问题已在上述版本中修复。临时解决方法包括禁用 SSH 服务器或通过防火墙规则限制访问。该漏洞的 CVSS 3.1 评分为 10.0（严重），属于 CWE-306 认证缺失漏洞。

评论摘要
主要讨论点：Erlang/OTP SSH库的漏洞及其影响 不同观点： • [aftbit] 认为该漏洞影响使用Erlang/OTP SSH库进行远程访问的服务，特别是在OT/IoT设备和边缘计算设备中。他引用了The Hacker News的文章来说明该漏洞的严重性。 • [throwawaymaths] 指出大多数Elixir部署可能不受影响，因为SSH默认是关闭的。他提供了Paraxial博客的文章来支持他的观点。 • [marioflach] 分享了他使用Erlang内置SSH库实现Git over SSH的经验，并提供了GitHub项目的链接，展示了具体实现。 • [qwertox] 关注该漏洞对ejabberd服务器的影响，并询问该服务器最近的升级是否包含对该漏洞的修复。 • [aposm] 提到他们正在内部推广一个基于Elixir的项目，虽然该漏洞可能不会直接影响Elixir，但可能会增加项目推广的难度。 • [formerly_proven] 详细解释了漏洞的技术细节，并提到该问题是由RUB的研究人员发现的，他们从事协议实现的验证研究。 • [bilekas] 对在可能即将关闭的存档网站上阅读到这篇文章感到不安。 • [rramadass] 提供了Erlang Ecosystem Foundation安全工作组的指南，作为对Erlang/BEAM语言安全方面的参考。 • [r3tr0] 建议使用自定义XDP程序和工具如yeet来解析和阻止该漏洞的 payload。 补充讨论： • 争议的焦点在于该漏洞的实际影响范围。一些评论者认为大多数Elixir部署不受影响，而另一些评论者则担心特定设备和应用场景下的风险。 • 技术细节方面，漏洞的成因和修复方法被详细讨论，特别是通过具体代码和补丁说明问题。 • 提供了多个外部资源链接，用于进一步了解漏洞详情和相关安全指南。

All-in-Memory Stochastic Computing Using ReRAM

作者: rbanffy | 评分: 26 | 评论数: 1 | 发布时间: 2025-04-14 20:14
文章摘要

本文提出了一种基于ReRAM的全内存随机计算（All-in-Memory Stochastic Computing）方法，以应对嵌入式和边缘设备对低功耗高效计算的需求。传统随机计算（SC）依赖于随机比特流（SBS）进行近似运算，但生成这些比特流通常消耗大量功耗和面积。本文利用ReRAM器件的特性，实现了在同一位置生成SBS、执行SC操作以及将SBS转换回二进制数的全流程。尽管ReRAM单元的可靠性较低，SC的容错性有效弥补了这一缺陷。实验结果显示，该方法在吞吐量和能耗方面较现有方案有显著改进，吞吐量提升1.39至2.16倍，能耗降低1.15至2.8倍，同时在图像处理任务中的图像质量仅下降约5%。

评论摘要
主要讨论点：对IRAM的商业成功性、内存控制器的简化以及在多核CPU中增加RAM芯片的趋势的讨论。 不同观点： • [anon6362] 质疑当前的项目是否只是对IRAM的更多步骤的重复。IRAM项目是否在商业上取得成功存在疑问，因为没有明显的证据显示其商业化成果。 • [anon6362] 提出是否存在一种趋势，通过在多核CPU中增加更多的RAM芯片来简化或消除内存控制器。他认为SoC（系统级芯片）的发展方向是包含固定数量的RAM。 补充讨论： • [anon6362] 对IRAM项目的有效性和其在商业领域的应用提出质疑，特别是其是否真正带来了实际的商业价值。 • 关于内存控制器的讨论中，[anon6362] 提到了一种技术趋势，即通过在CPU中集成更多RAM芯片来简化系统设计，而不是依赖复杂的内存控制器。这暗示了一种可能的技术发展方向，旨在提高系统效率和集成度。 • 关于SoC的评论指出，当前的设计趋势似乎更倾向于将固定数量的RAM直接集成到芯片中，这可能反映了行业内对简化设计和提高性能的需求。 争议焦点：IRAM项目的商业成功与否及其在现代计算中的应用价值是主要争议点。此外，关于内存控制器简化与RAM芯片集成的技术路径也存在不同的看法和潜在的技术路线分歧。

An intro to DeepSeek's distributed file system

作者: sebg | 评分: 566 | 评论数: 17 | 发布时间: 2025-04-17 12:50
文章摘要

** summary ** 3FS是DeepSeek发布的分布式文件系统，旨在提供大规模数据存储和高吞吐量。分布式文件系统将文件分布在多个机器上，但对用户而言操作如同本地文件系统。3FS包含四大核心组件：Meta管理文件元数据，Mgmtd管理集群配置和节点发现，Storage存储实际文件数据，Client负责与各节点交互。Mgmtd通过心跳机制监控节点状态，Meta使用FoundationDB存储元数据，Storage节点使用Rust编写的ChunkEngine管理数据块。3FS具有高容错性和冗余性，适合大规模并行处理和机器学习等应用。

Using –/.ssh/authorized keys to decide what the incoming connection can do

作者: jandeboevrie | 评分: 46 | 评论数: 3 | 发布时间: 2025-04-18 04:17
文章摘要
