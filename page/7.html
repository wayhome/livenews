Don't Read This If You Have a Security Clearance (2023)

作者: greyface- | 评分: 34 | 评论数: 11 | 发布时间: 2025-06-22 00:10
文章摘要

1969年，克格勃成功进行了一次 clever 的欺骗行动，通过在美国真实战争计划泄露中夹杂伪造文件，试图挑拨美国与北约盟友的关系。50多年后，作者提议在美国情报机构的培训中使用1969年泄露事件作为识别伪造文件的练习，但被官员拒绝，因为这些材料仍可能被归类为机密。尽管这些文件自我们出生前就已公开，情报人员仍不允许查看。 2013年，爱德华·斯诺登事件后，五角大楼发布新规，要求员工若发现可能属于机密的信息，必须立即报告。此规定旨在防止员工故意寻找或传播这些信息，违者将受制裁。这项政策让联邦雇员或承包商在看新闻、浏览社交媒体、搜索谷歌甚至读书时都面临风险。 尽管这些泄露有时会导致重大地缘政治问题或危及生命，但也提供了丰富的资料，帮助专家理解美国及其对手的间谍技术。然而，美国政府禁止安全机构人员查看这些已公开的泄露文件，即便公众和敌对国家已在研究它们，这显得荒谬。特别是在2016年Shadow Brokers泄露后，国防部网络防御人员面临无法研究对手使用NSA黑客工具的困境。

评论摘要
主要讨论点：关于处理泄密信息和安全保密政策的争议 不同观点： • Zak认为，禁止确认或否认泄密信息的政策是有道理的，但一旦信息被公开，再假装 otherwise 是荒谬的。 • ggm提出，应减少对普通事实的安全分类，降低敏感性，并质疑安全设施（SCIF）在信息管理上的实质性改进。 • anonymousiam以其40年的安全保密经验指出，未解密的文件应继续受到访问控制，即使是持有保密许可的人，未经授权访问也是违规行为。 • mmsc对泄密信息的真实性和完整性提出质疑，认为可能缺少重要背景或被编辑。 • mrlatinos以讽刺口吻表示，付费墙可以保护公众免受泄密信息的影响。 • helsinkiandrew以讽刺方式提问，是否通过散布泄密信息可以保护自己的隐私。 • atlgator指出，保密政策适用于所有持有保密许可的人，而不仅仅是国防部员工。 • bell-cot批评文章对政策的简单化攻击，强调泄密问题的根源在于机构防止泄密的能力不足，并指出解密决策的复杂性和潜在风险。 补充讨论： • 关于解密过程的复杂性和实际操作中的困难，bell-cot指出解密决定由职业国家安全人员做出，且历史上没有人因解密信息而获得晋升。 • 对互联网环境和公众反应的担忧，bell-cot认为解密信息可能会引发不必要的公众恐慌和误解。 • 讨论中还涉及到对学术界在国家安全政策讨论中的角色和责任的质疑，特别是对那些只关注自身不便而不考虑全局改进的学者。 争议焦点： • 保密政策的合理性和有效性。 • 解密过程的实际操作和潜在风险。 • 泄密信息对公众和国家安全的影响。 这些观点展示了在处理泄密信息和保密政策上的多方面争议，包括实际操作、政策效果以及学术和公众讨论的责任。

Verified dynamic programming with Σ-types in Lean

作者: rck | 评分: 77 | 评论数: 6 | 发布时间: 2025-06-17 14:28
文章摘要

本文介绍了如何使用记忆化（memoization）技术在Lean中解决一个动态规划问题，并验证其正确性。问题名为“Bytelandian金币问题”：给定一枚金 coin n，它可以被兑换为 n/2、n/3 和 n/4 三个整数金 coin（向下取整），也可以直接按1:1兑换为美元。目标是计算这枚金 coin 能换取的最大美元数。 解决方案采用递归关系定义：当 n ≤ 8 时，直接兑换为 n 美元；否则，选择 n 与 n/2、n/3、n/4 兑换后总和的最大值。为了优化计算，采用记忆化技术缓存子问题结果。 文中首先给出了直接递归实现作为规范，随后展示了记忆化实现，利用哈希表缓存子问题结果。最后，提出正确性证明的挑战，即证明记忆化实现与规范实现结果一致。证明的难点在于确保哈希表正确存储和查询子问题结果。文章邀请读者尝试证明，并指出证明中的关键在于理解数据结构的不变性。

评论摘要
主要讨论点：Lean语言中的类型理论、子类型概念及其在证明和算法中的应用 不同观点： • **gugagore** 指出Lean中的"subtype"概念与面向对象编程语言中的子类型概念没有太大关联，并强调了类型理论和集合理论之间的关键区别：在类型理论中，一个元素恰好属于一个类型。 • **CSMastermind** 表示对学习Lean感兴趣，但对某些复杂语法感到困扰，例如`let rec helperMemo : Nat → HashMap Nat Nat → Nat × HashMap Nat Nat`，认为这种语法难以解析，容易忽略重要细节。 • **Gehinnn** 分享了使用经典证明方法（通过强归纳法）的实例，并指出了在算法中进行证明的优点，即不需要复制外部证明的分支结构。同时，Gehinnn提到在Lean中处理变量和语法细节（如r.fst/r.snd与r=(fst, snd)的区别、.get? k与[k]?的混淆）时遇到的困难。 补充讨论： • **jeremyscanvic** 对某个技巧表示了兴趣，但没有深入展开。 • **almostgotcaught** 认为该证明是通过穷举法实现的，指出这种证明方法可以在任何支持递归的语言中实现，并提到如果不使用递归，可以转化为自底向上的公式。 • **xnacly** 提到了sigma类型，但没有进一步展开讨论。 争议焦点： • CSMastermind对Lean的复杂语法表示不满，而其他用户如Gehinnn则更关注在Lean中进行证明和处理具体细节时遇到的挑战。这反映了对Lean语言学习曲线的不同看法。
