Next.js version 15.2.3 has been released to address a security vulnerability

作者: makepanic | 评分: 216 | 评论数: 34 | 发布时间: 2025-03-22 21:19
文章摘要

Next.js发布了15.2.3版本，修复了一个安全漏洞（CVE-2025-29927）。该漏洞允许跳过Middleware，导致关键安全检查（如授权cookie验证）被 bypass。自托管的Next.js应用，尤其是使用`next start`和`output: 'standalone'`的，应立即更新。漏洞不影响托管于Vercel或Netlify的应用，以及静态导出的应用。修复版本包括：15.x的15.2.3、14.x的14.2.25、13.x的13.5.9和12.x的12.3.5。若无法更新，建议阻止含有`x-middleware-subrequest`头的请求。Next.js团队还将改进与合作伙伴的沟通，并开设了合作伙伴邮件列表。

评论摘要
主要讨论点：Next.js 中间件系统的设计缺陷与安全问题 不同观点： • **[dminik]** 认为 Next.js 的整个中间件系统设计糟糕，存在多个问题。首先，无法官方便捷地链式调用多个中间件，必须将所有功能塞进单个函数或自行实现链式逻辑。此外，主要功能如 `next()`、`redirect()`、`rewrite()` 等作为静态成员存在于导入对象上，导致第三方中间件可能会自动执行错误操作并破坏链式功能。再者，中间件与路由处理器之间的通信机制不完善，通过 headers 传递数据既不安全也可能导致缓存失效。最后，部分请求属性被隐藏或混淆，如 `request.hostname` 始终为 `localhost`，需要从 "Host" header 中手动获取实际主机名。 • **[ratorx]** 指出，Next.js 中间件使用与用户请求相同的机制进行通信，这使得代码编写和请求验证分离，容易导致安全隐患。此外，允许用户发送除白名单外的任意 headers 也可能造成潜在问题。框架的设计似乎鼓励了不良的服务器设计模式，特别是允许跨越认证边界的递归请求可能导致安全隐患。 • **[smlx]** 提到 Next.js 历史上存在类似漏洞，并引用了一个具体的补丁（https://github.com/vercel/next.js/pull/73482/files），其中通过添加特定 header 可以触发 SSRF 漏洞。同时，批评 Next.js 团队对漏洞信息的披露不透明，且仅对部分版本提供补丁支持。 • **[mikeocool]** 认为 Next.js 增加了前端开发的复杂性，但对于大多数应用而言提供的价值有限。文件路由和服务器端渲染在某些场景下可能有用，但整体上带来的复杂性不值得。 • **[ashishb]** 认为 Next.js 的基础前提存在根本性缺陷，即浏览器和后端代码运行环境不同，安全策略应有所区分。前端代码是不可信的，后端代码是可信的，因此应分离关注点，分别编写前端和后端代码。 • **[impulser_]** 推荐使用 Tanstack Start 作为 Next.js 的替代方案，认为其在开发体验和配置简便性上更具优势，且支持全栈应用开发和多平台构建。 补充讨论： • **安全问题**：多位评论者（如 [ronbenton], [makepanic]）关注到具体的安全漏洞，尤其是通过添加 `x-middleware-subrequest: true` header 可以绕过认证，这被认为是极其严重的安全漏洞。 • **维护与披露**：[ronbenton], [smlx] 对 Next.js 团队在漏洞披露和修复时间上的表现不满，认为关键安全漏洞的响应时间过长（16天才开始处理）。 • **框架选择**：[dvektor], [butterlettuce], [ramoz] 等人对 Next.js 的设计和维护表示失望，并考虑或推荐其他替代方案。 争议焦点： • Next.js 中间件系统的设计复杂性与安全隐患之间的矛盾。 • Vercel 团队在漏洞披露和修复过程中的响应速度与透明度问题。

A Brief History of the Miracle Bacterium

文章摘要

《奇迹细菌小史》一文介绍了**粘质沙雷氏菌**（*Serratia marcescens*）的科学历史及其对现代科学的影响。这种细菌因其酷似血液的红色外观，常用于研究细菌传播。1904年，英国医生M. H. Gordon在英国议会大厦前进行实验，试图通过议员靴子传播细菌以研究通风系统缺陷，但未成功。随后，他通过在议会厅内漱口并朗诵莎士比亚作品，证明了细菌可通过 speech 传播。 粘质沙雷氏菌最早在1819年因其在玉米粥上形成红色斑点而引起关注，当时被误认为是真菌。尽管其某些菌株对人类有害，但该细菌仍被广泛用于研究微生物传播。文章还提到，随着对其危险性的认识增加，这种细菌逐渐不再用于实验，但仍是生物医学研究的重要对象。

评论摘要
主要讨论点：关于1969年一篇有关细菌的文章及其历史背景的讨论，特别是与毕达哥拉斯学派和古代哲学相关的趣味内容。 不同观点： • [dr_dshiv] 分享了一篇1969年的文章，强调了其中关于毕达哥拉斯学派对豆类禁忌的描述，引用了公元170年卢奇安的讽刺作品《出售信条》中的对话，展示了古代哲学与科学的联系。特别指出文章追溯了“血液效应”与毕达哥拉斯学派之间的关系，并以幽默的方式称毕达哥拉斯为“生物学家”。 • [melagonster] 对此表示兴趣，认为内容非常有趣，并表示会尝试寻找更多关于这一类群的信息，显示出对进一步探索和了解相关知识的积极态度。 • [profsummergig] 认为这种科学探究方式是传统的英国做法，并指出类似的实验在今天是 unlikely（不太可能）被允许的。表达了一种对现代科学探究方式的反思，认为现代科学在某些方面失去了过去的一些探索精神。 补充讨论： • 争议焦点可能在于现代科学与传统科学方法的对比上。一方面，传统方法可能包含更多的哲学和文化元素，另一方面，现代科学更强调伦理和实验规范。 • 讨论中还涉及了古代哲学与科学之间的联系，特别是毕达哥拉斯学派的神秘主义与早期科学思维的交织。 • 引用的卢奇安作品为讨论增添了历史和文学的维度，展示了古代对自然现象的解释方式。

Lua, a Misunderstood Language

作者: soapdog | 评分: 46 | 评论数: 6 | 发布时间: 2025-03-24 17:27
文章摘要

本文讨论了对Lua语言的误解，特别是针对一些人抱怨Lua缺乏“内置电池”（即标准库功能不足）的问题。作者认为，Lua本质上是一种提供机制而非策略的工具包，开发者可以根据需求自由扩展和定制，而不是让语言本身提供过多预设功能。Lua的设计初衷是嵌入到其他应用程序中作为脚本语言使用，其核心优势在于灵活性和可嵌入性，而非作为独立的全功能语言。作者还回应了关于Lua数组采用1基索引的批评，指出这种设计更符合人类习惯，而非像C语言那样基于内存偏移量的0基索引。总体而言，Lua的力量在于其简洁和灵活，只有将其嵌入到其他语言编写的软件中使用时，才能真正体会其独特之处。

评论摘要
主要讨论点：Lua编程语言的优缺点及其适用场景 不同观点： • **Norir的观点**： - Lua在代码行数少于10k的程序中表现出色，启动延迟低，解释器速度快，能够提供接近即时的反馈。这种快速反馈使得开发者可以高效迭代，减少对高级功能的需求。 - 缺点在于缺乏类型系统，使得重构变得困难，某些语法也不尽如人意。 - Norir通过使用Lua编写编译器，创建了一种新语言来解决这些问题，最终不再使用Lua。 • **Lasher的观点**： - Lua在特定应用场景中表现优异，例如在Aardwolf MUD中将"mobprog"脚本替换为Lua，使得游戏构建者能够创造出超出预期的体验。 - 通过将40个左右的Lua函数集成到C代码库中，提供了对房间、物体、玩家和NPC的基本访问，构建者能够制作出完整的子游戏。 - 虽然不会用Lua构建完整应用程序，但在特定用例中，Lua是完美的选择。 • **Vitiral的观点**： - 完全同意Lua的出色表现，正在使用Lua编写整个技术栈，并提供了相关链接以展示其工作。 补充讨论： • **Gowld的观点**： - 提到Lua团队或LuaRocks团队不会像Elm社区那样干涉开发者的工作，引用了相关的讨论链接。 - 强调了Lua社区的稳定性和无争议性，与其他语言社区（如Elm）形成对比。 争议焦点： • 关于Lua的类型系统和语法问题存在争议。Norir认为这是Lua的缺点，并通过创建新语言来解决这些问题。而Lasher则认为在特定用例中，Lua的优点远超过其缺点。 • 对Lua在不同场景下的适用性存在不同看法。Norir侧重于Lua在小规模程序和快速反馈上的优势，而Lasher则强调了Lua在特定大型项目（如游戏）中的应用价值。

文章摘要

这篇文章讨论了经典科幻游戏《家园2》（Homeworld 2）的背景艺术，特别分析了其独特的艺术处理方式。作者和团队对游戏的背景艺术十分钦佩，特别是其草图风格和细节处理。通过使用模组工具提取游戏数据并分析.HOD文件，作者发现背景采用了顶点颜色渐变技术，而非传统贴图。这种方法避免了DDS纹理压缩带来的瑕疵，同时确保背景不会过于抢眼，保持了前后景的清晰区分。文章还提到这种技术在其他游戏如《暗黑3》（Diablo 3）中也有出色表现，并提供了进一步技术分析的参考。最后，文章提到其他开发者如何受《家园》背景艺术的启发应用于个人项目中。

评论摘要
