Cross-Compiling Common Lisp for Windows

作者: todsacerdoti | 评分: 67 | 评论数: 6 | 发布时间: 2025-06-27 23:55
文章摘要

本文介绍了如何在Linux环境下进行Windows程序的交叉编译和开发，具体包括以下内容： 1. **交叉编译C代码**：使用mingw-w64工具链编译Windows可执行文件。 2. **链接DLL**：演示如何编译并使用Raylib的DLL文件。 3. **安装SBCL**：通过Wine在Linux上安装Windows版的SBCL，并配置使其在Emacs中作为REPL运行。 4. **加载DLL文件**：在Lisp环境中加载Windows DLL。 5. **构建可执行文件**：将Lisp程序编译为Windows的.exe可执行文件。 6. **路径处理**：讨论Linux和Windows下路径的差异，并介绍处理路径的便利工具。 7. **在Emacs中使用Wine-based SBCL**：通过配置SLY或Slime，在Emacs中使用通过Wine运行的SBCL。 通过这些步骤，开发者可以在Linux环境下顺利开发和测试Windows应用程序。

文章摘要

本文讨论了恶意软件如何通过检查虚拟机中通常未模拟的硬件组件（如CPU风扇）来逃避安全研究人员的分析。具体而言，恶意软件会通过WMI查询`Win32_Fan`类来检测CPU风扇的存在。作者尝试在Xen虚拟机中模拟CPU风扇，通过修改SMBIOS数据来欺骗此类检测。尽管初始尝试未成功，因Xen不允许覆盖某些预定义的SMBIOS结构类型，作者最终通过修改Xen源代码解决了问题。该方法可以扩展到其他硬件组件，以增强虚拟机的仿真能力。

主要讨论点：通过技术手段对抗恶意软件（antimalware tactics）以及虚拟机（VM）与真实硬件环境之间的检测与反检测 不同观点： • **购买无风扇电脑作为反恶意软件策略**：wkat4242提到，通过购买无风扇电脑（被动冷却PC）和设置俄语键盘作为反恶意软件的策略，基于某些恶意软件会检测运行环境来决定是否执行。 • **虚拟机环境伪装策略**：Grimblewald建议，可以让操作系统看起来像虚拟机，任何需要访问资源的程序都必须获得许可，以此增加恶意软件分析的难度。 • **SMBIOS与硬件不一致问题**：AshamedCaptain指出，消费者主板的SMBIOS信息往往与实际硬件不符，恶意软件可能会通过时间检测而非SMBIOS信息来判断是否为虚拟环境。 • **静态分析与API检测**：lpapez认为，恶意软件调用 obscure API 可以被静态分析检测到，并且这些调用如果没有经过混淆处理，很容易被杀毒软件标记为可疑。 • **恶意软件蜜罐的复杂性**：ChuckMcM提到，信息安全领域中构建高度逼真的恶意软件蜜罐需要大量工作，包括模拟各种硬件设备。 • **虚拟环境仿真进阶**：userbinator和andix讨论了通过仿真更多硬件信息，例如温度传感器和电源供应，使虚拟机更像真实PC，增加恶意软件分析的难度。 • **反向伪装用户端为虚拟环境**：ajd555建议，可以让用户设备看起来像虚拟机，以迷惑恶意软件，提供额外的保护。 补充讨论： • **社会工程学与隐私问题**：photon_garden指出在讨论中避免使用涉及人身攻击的语言。 • **历史视角与早期恶意软件**：djmips分享了早期制作Apple II恶意软件的经历，通过简单的修改来防止感染。 • **对抗监控资本主义的策略**：benreesman提出通过发送 plausible but wrong 信息来对抗跟踪器，扰乱数据收集，并讨论了集体行动的可能性。 • **技术实现可行性**：marcosscriven对修改恶意软件检查机制的可行性以及KVM完全模拟真实PC的可能性提出了疑问。 争议焦点： • **DLL hooking的有效性**：rustybolt质疑对DLL hooking技术的批评，认为该技术在某些情况下可能有效。

文章摘要

文章主要讨论谷歌搜索引擎的演变及其未来方向。最初，谷歌通过简单的搜索引擎迅速满足用户查找信息的需求，并通过嵌入广告实现盈利。随着时间推移，谷歌搜索变得复杂，成为决定网站生死的重要工具，尤其是对于小众网站而言。然而，为了持续增长，谷歌引入零点击结果（Zero-Click Results），通过LLM（大语言模型）直接在搜索结果中提供最佳答案，导致许多网站流量下降。 谷歌此举可能是为了应对OpenAI等竞争对手的威胁，并计划将搜索过程内化，形成闭环系统。公司将可能付费成为不同类别的“答案”，而谷歌则继续利用外部数据，如Reddit，来提供新数据。尽管这种策略引发了一些网站的恐慌和反对，但由于谷歌在市场上的垄断地位，替代方案难以成功。美国政府尽管试图通过反垄断诉讼来制约谷歌，但效果可能有限。未来，消费者可能更倾向于接受AI提供的“足够好”的答案，而非切换平台。

**NativeJIT** 是一个开源、跨平台的C++即时编译库，用于高性能编译涉及C数据结构的表达式。该库轻量且快速，仅依赖标准C++运行时，支持Linux、OSX和Windows系统。其生成的代码经过优化，尤其注重寄存器分配。该工具由Bing团队开发，用于Bing搜索引擎中的文档评分过程，根据查询关键词自定义表达式并编译成x64代码，分布式执行。NativeJIT适用于运行时才能确定的表达式，并在大规模查询处理中保证低延迟和高吞吐量。它支持多种算术、逻辑、指针、数组操作及条件语句等。构建NativeJIT需要CMake (2.8.11+) 和现代C++编译器（如gcc 5+、clang 3.4+或VC 2015+）。
