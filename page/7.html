Someone used my open source project to phish people

作者: andrejsshell | 评分: 82 | 评论数: 15 | 发布时间: 2026-05-29 13:18
文章摘要

作者运营开源项目管理工具Kaneo的云版本，某天发现有人利用其开放注册功能进行钓鱼攻击。攻击者在三小时内创建了942个账户和工作空间，通过作者的验证域名向14,520人发送钓鱼邮件。攻击没有利用任何漏洞，只是利用了开放注册+已验证邮件域名的组合。作者意识到云版本的威胁模型与自托管版本完全不同：云服务需要为所有陌生用户的行为背书。事后作者添加了验证码、一次性邮箱拦截、速率限制等防护措施，并反思开源项目托管版本面临的独特安全挑战。

评论摘要
主要讨论点：免费服务平台遭遇垃圾邮件滥用后的防护策略与经验教训 不同观点： • **滥用不可避免论**：只要免费服务的价值大于防护成本，恶意用户就会持续套利。例如转售免费额度、利用平台信誉发送钓鱼邮件等。一旦被标记为垃圾邮件源，产品基本报废（eggbrain, comrade1234） • **过度防护的两难**：开发者因担心滥用而不敢公开服务，只能设置严格登录限制或只读模式，甚至只分享源码让用户自行部署，这损害了产品可用性（fg137, dddddaviddddd） • **技术防护建议**：应使用OAuth认证、设置滥用联系方式、部署专门的安全工具。但有人指出验证码对真实用户体验有害，且无法防御人工操作的诈骗者（sandeepkd, autoexec, reconnecting） • **对LLM生成内容的批评**：多位评论者直接批评博文使用AI生成，认为"令人不适"，要求作者亲自撰写（no_multitudes, mplewis） 补充讨论：有人担忧LLM辅助的漏洞挖掘会降低攻击门槛，使小项目更易被自动化滥用。另有人指出屏蔽一次性邮箱域名的做法很烦人，因为越来越多正常服务也会变成垃圾邮件源。整体共识是"互联网不是高信任社会"，开发者必须从一开始就严防滥用。

The California state assembly has passed the 'Protect Our Games Act'

作者: TechTechTech | 评分: 223 | 评论数: 24 | 发布时间: 2026-05-29 19:55
文章摘要

加州议会通过了《保护我们的游戏法案》(AB 1921)，这是"停止杀死游戏"运动的重大进展。该法案要求数字游戏发行商在终止服务后仍需保持游戏可访问性。法案规定：2027年1月1日后发售的数字游戏，停服前需提前60天通知，并须提供替代版本、补丁或退款。该运动源于2024年育碧关闭《飙酷车神》服务器事件。法案尚需加州参议院和州长批准才能生效，但在游戏公司云集的加州通过具有重要象征意义，预计将影响整个美国游戏行业的服务政策。

评论摘要
主要讨论点：加州AB 1921法案要求游戏公司在终止服务前提供60天通知，并确保玩家能继续访问游戏或提供退款。 不同观点： • **支持立场**：认为这是消费者保护的重大胜利。指出服务器架构转换技术上可行（去掉负载均衡和匹配系统即可），开发者应提前规划。强调游戏是文化遗产，应像实体游戏一样可传承，社区自建服务器已有成功先例（如Battlefield 2通过BF2Hub复活） • **技术担忧**：质疑发布服务器代码的可行性，因为许多公司使用第三方专有中间件，不拥有全部代码。担心合规成本和法律复杂性 • **规避策略预测**：认为公司会转向订阅制、免费游戏等豁免模式来规避法规。有人担忧会像电影业一样为每款游戏成立空壳公司，关闭时无人可追责。也有人建议公司可能只保留1台服务器"技术上"维持服务 • **反对立场**：批评加州过度监管会扼杀游戏产业（类比好莱坞外迁）。质疑谁来承担持续运营服务器的成本 补充讨论：法案仅适用于2027年后数字销售的游戏，排除订阅服务和免费游戏。有人呼吁将保护扩展到订阅游戏和数字商品继承权。也有开发者关心跨州管辖问题。

Local Git remotes

文章摘要

这篇文章介绍了如何设置本地 git 远程仓库。主要步骤包括： 1. 使用 `git clone --bare` 创建裸仓库作为远程仓库 2. 通过本地路径或 SSH 协议添加远程仓库：`git remote add local [路径]` 3. 设置默认分支并进行推送和拉取操作 作者分享了使用本地远程仓库的好处：当异地远程仓库不稳定或访问延迟高时，本地远程仓库提供了快速可靠的备份方案。这样既能享受本地推送的零延迟，又能保持异地备份，且无需依赖大型科技公司的服务。

评论摘要
主要讨论点：Git 本地远程仓库的实际应用场景和价值 不同观点： • **实用派**：认为本地远程很有价值。用于同一机器多个克隆间共享对象、离线备份（`git push /mnt/backup/repo.git --all`）、通过 USB 或 Rclone 挂载的文件系统同步加密仓库、使用 Syncthing 同步个人项目、在容器中隔离 agent 操作 • **历史延续派**：指出这是 Git 分布式特性的体现，早于 GitHub 时代就在共享计算机上使用，认为现代开发者因依赖 GitHub 而"重新发现"了 Git 的分布式本质 • **质疑派**（mystifyingpoi）：不理解必要性，认为本地分支就够了，等网络恢复再推送即可 • **技术扩展派**：提到相关技巧如 `git clone --reference` 节省空间、`git remote set-url --add --push` 实现一次推送到多个目标、使用 bare repo 搜索邮件列表 补充讨论： 有人提到 AI 检测到 PII 时可以阻止推送到云端但允许本地推送的安全场景。还有评论指出文章页脚包含 Anthropic 的模型拒绝触发字符串。并发问题在单人使用场景下可接受。

主要讨论点：开源开发者Justine的求助帖引发的争议，涉及其技术贡献、政治立场、心理状态和募捐请求的合理性。 不同观点： • **同情支持派**：认可Justine的技术贡献（llamafile、redbean等），认为如此优秀的开发者找不到工作反映了软件行业的问题。呼吁给予理解和支持，认为其遭受的负面评价不公平。 • **质疑政治立场派**：指出Justine过去发表过新反动主义言论（2014-2015年）、支持Eric Schmidt担任"美国CEO"、推荐Curtis Yarvin等争议观点，以及对无家可归者和奴隶制的不当评论。认为在募捐前应澄清这些立场，否则难以支持可能伤害弱势群体的人。 • **心理健康担忧派**：从文章的写作风格（话题跳跃、被害妄想、夸大自我）判断作者可能处于躁狂发作或自闭症超聚焦状态。特别质疑"用私人飞机环游世界"的募捐目标过于荒诞，不确定是讽刺还是认真的。 • **务实建议派**：建议Justine"做个普通人"，停止将自己置于争议中心，接受高薪工作机会，减少政治化表达。认为过度追求被拒绝可能源于自我厌恶或想成为社会的镜子。 补充讨论：有评论指出Internet Archive取消演讲邀请的主要原因是政治言论而非llama.cpp事件，但文章回避了这一核心问题。版权分配政策（要求贡献者转让版权而非CLA）也引发质疑，被认为是为保留闭源选项。
