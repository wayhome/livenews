Lore – Open source version control system designed for scalability

文章摘要

Lore是Epic Games维护的下一代开源版本控制系统，专为处理代码和大型二进制资产的项目（如游戏和娱乐）设计。它采用内容寻址存储和Merkle树架构，支持按需下载、数据去重和轻量级分支，可无缝扩展以适应大型团队和海量数据。系统提供CLI和多语言SDK（C/C++、C#、Rust、Go、Python、JavaScript），具有不可篡改的修订链保证数据完整性。Lore以MIT许可证完全开源，旨在通过社区协作构建未来的版本控制系统。

评论摘要
主要讨论点：Epic Games 开源的 Lore 版本控制系统，专为游戏开发设计，作为 Perforce 的竞争者 不同观点： • **支持者观点**：游戏开发需要专门工具处理大型二进制文件（纹理、3D模型、音频），Git 不适合这类场景。Lore 提供文件锁定、权限管理等关键功能，且有望获得 Unreal Engine 的一流支持，这是 Perforce 的核心优势。用户界面比 Git 更友好，输出信息更清晰易懂。 • **质疑者观点**：Epic 的工具历史记录不佳，代码质量存疑（"vibe-coding"产物）。版本控制系统需要 99%+ 的可靠性，而非 97%。项目可持续性存疑——Epic 可能随时放弃这个非核心业务，不像 Perforce 这样的专业公司有长期承诺。 • **技术对比**：已有成熟的数据版本控制系统（Pachyderm、LakeFS、Oxen 等），Lore 并非首创。Git LFS 虽是替代方案，但团队规模超过 3-4 人时，游戏开发者仍偏好 Perforce。PlasticSCM 曾是优秀竞品，但被 Unity 收购后管理不善。 补充讨论：桌面客户端仅提供二进制文件引发"开源"质疑；不支持完全本地/离线模式；AI 和游戏行业面临相似问题但缺乏跨领域交流；Lore 实际上已在 UEFN 中使用，并非全新项目。

文章摘要

安全研究公司Paradigm Shift发现了影响苹果A12和A13芯片的新BootROM漏洞，并发布了名为"usbliter8"的概念验证利用程序。该漏洞存在于芯片硬件中，无法通过软件更新修复，影响iPhone XS至iPhone 11系列设备。 漏洞利用USB控制器的缺陷，通过发送特定的小数据包序列操纵内存指针，从而写入本不应访问的内存位置。A13芯片因有指针认证码(PAC)安全功能而更难攻破。成功利用后可降低设备安全设置并启动未签名软件。A11及A14之后的芯片不受影响。研究机构已向苹果报告并协调披露。
