文章摘要

英国诺丁汉大学开展的一项临床试验显示，通过咀嚼特制口香糖可以恢复新冠后遗症导致的嗅觉和味觉丧失。44岁的Paul Wicks在2022年感染新冠后失去嗅觉和味觉，参加试验后仅6周就开始恢复感官。这些口香糖含有辛辣、薄荷、酸甜等超强味道，旨在刺激大脑中与嗅觉和味觉相关的神经连接修复。试验为期12周，16名参与者中67%嗅觉改善，83%味觉改善。研究团队正寻求资金进行更大规模试验。

评论摘要
主要讨论点：COVID-19导致的嗅觉/味觉丧失及其影响，以及通过特殊口香糖进行感官训练恢复的新疗法 不同观点： • **先天性嗅觉缺失的困扰**：andix分享朋友案例，指出长期影响包括饮食单调（只喜欢肉类、油炸和甜食）、持续焦虑（担心自己或衣物有异味）、安全隐患（无法察觉煤气泄漏、食物变质） • **COVID后遗症的普遍性**：多位用户（MrDresden、foo12bar、nkrisc等）分享亲身经历，症状从完全丧失到部分减弱不等，恢复时间从数周到数年，有人即使接种疫苗仍反复感染并持续受影响 • **恢复过程的特殊性**：nkrisc和jnwatson提到恢复不均匀现象——某些特定气味（如特定香水、咖啡/巧克力）完全消失或恢复缓慢，恢复期间味觉会再次变得"奇怪" • **辣味感知的疑问**：graypegg质疑文章中"能吃最辣咖喱"的说法，认为辣是痛觉而非味觉，理论上不应受嗅觉影响 补充讨论： • 治疗方法包括精油训练（layman51）、类固醇+单克隆抗体（anilgulecha针对息肉引起的嗅觉丧失） • 有人质疑研究样本量统计（16人无法得出67%或83%） • 甚至有人好奇正常人使用这种口香糖是否能开发"超级感官"

We Reverse-Engineered Docker Sandbox's Undocumented MicroVM API

作者: yakkomajuri | 评分: 77 | 评论数: 7 | 发布时间: 2026-05-21 14:50
文章摘要

Docker 悄然推出了基于 microVM 的 Sandbox API，用于安全运行 AI 编程代理的不受信任代码。与共享内核的容器不同，microVM 提供独立内核隔离，安全性更高。作者逆向工程了这个未公开的 API，发现可通过 `/vm` HTTP 端点创建和管理虚拟机，每个 VM 拥有独立的 Docker 守护进程。这为不受信任代码执行、AI 代理、多租户插件等场景提供了类似 Docker 容器的统一管理方式，但目前仅支持 macOS/Windows 且需要嵌套虚拟化。作者基于此构建了开源的 Sandbox Agent SDK。

评论摘要
主要讨论点：Docker Sandboxes 的技术实现、跨平台支持和 AI 代理安全隔离方案 不同观点： • **Docker 官方进展**：pploug 指出文章过时，Docker 已发布独立的 sbx 二进制文件（50MB），无需 Docker Desktop • **Linux 支持质疑**：nyrikki 和 whimblepop 认为 Linux 不支持的说法不准确。Docker 在 Linux 上完全支持 KVM 虚拟化，只是默认不启用以避免性能开销。Podman 通过 libkrun 也能在 Linux 上透明启动 microVM • **替代方案推荐**：nyrikki 建议尝试 Podman，因为可以 SSH 进入虚拟机查看内部；cedws 更看好 Microsandbox 的 SDK 优先体验，认为它比面向代理的 sbx 更灵活 • **安全性根本质疑**：andix 质疑容器隔离是否真正解决了 AI 代理的安全问题。即使有 VM 隔离，代理仍可能通过植入后门代码、滥用访问令牌等方式造成危害 补充讨论：技术实现上，这些方案本质都是在非 Linux 平台启动独立的 Linux VM 实例，而非共享 VM。争议焦点在于 VM 级隔离对 AI 代理安全的实际价值。

GitHub confirms breach of 3,800 repos via malicious VSCode extension

作者: Timofeibu | 评分: 1010 | 评论数: 82 | 发布时间: 2026-05-20 13:43
文章摘要

GitHub确认其内部约3,800个代码仓库遭到泄露，原因是一名员工安装了恶意的VS Code扩展程序。GitHub已从市场移除该扩展并隔离受感染设备。黑客组织TeamPCP声称窃取了GitHub源代码和约4,000个私有仓库，要价至少5万美元。GitHub表示目前仅涉及内部仓库泄露，客户数据未受影响。此事件再次凸显VS Code扩展的安全风险，近年来已多次出现恶意扩展窃取开发者凭证和敏感数据的案例。GitHub后续将此次攻击关联到TanStack npm供应链攻击事件。

评论摘要
主要讨论点：VSCode扩展和开发工具的安全漏洞问题，由GitHub内部仓库被未授权访问事件引发 不同观点： • **安全模型缺失派**：VSCode扩展缺乏权限系统和沙箱机制是根本问题。扩展默认拥有文件系统、token和环境变量的完全访问权限，这种"ambient access"模式极其危险。建议Microsoft优先实现沙箱功能和显式权限系统 • **供应链风险派**：现代开发环境从IDE、包管理器到构建流水线都在拉取大量未经审计的代码，攻击面巨大。开发者安装扩展过于随意，很难区分官方扩展和恶意扩展，即使是百万级下载量的扩展也可能被攻陷 • **操作系统层面派**：问题不仅在应用层，操作系统本身的安全模型就有缺陷。应用默认能访问所有文件和网络是不合理的，需要从OS层面进行根本性改变。Linux上的沙箱实现尤其困难（如Electron的SUID问题） • **实用主义派**：部分开发者转向Zed等使用WASM扩展和dev-container隔离的替代方案，或只安装官方扩展，或将MCP服务器改为本地脚本而非npm包以控制访问范围 补充讨论：此次攻击链为Tanstack → Nx Console → GitHub，暴露出密钥轮换的困难性。即使发现风险，全面轮换所有密钥也是巨大工程，容易遗漏。
