本周，Armbian开发团队推出多项重要改进，包括用户体验提升、引导程序升级和系统支持扩展。特别值得一提的是，OpenMediaVault首次加入Armbian的软件安装器，使用户能够将单板计算机转变为网络存储设备，并通过armbian-config界面简化安装与配置。此外，修复了未启用无线热点时的冗余提示，提升了初次启动时的网络配置体验。硬件方面，Orange Pi 5 Max现使用主线U-Boot引导，PocketBeagle2则迁移至extlinux进行引导配置，均增强了系统标准化。Rockchip64平台新增了电压和频率调节支持，提升能效和稳定性，并移除了过时的无线固件修复程序。同时，团队清理了过时的构建文件，并为新功能测试做好准备。更新文档已纳入Armbian软件用户指南。

Making PyPI's test suite faster

作者: rbanffy | 评分: 113 | 评论数: 8 | 发布时间: 2025-05-08 20:54
文章摘要

Trail of Bits与PyPI合作多年，致力于提升Python打包生态系统的功能和安全性。本文聚焦于测试套件性能的优化，这对于软件安全至关重要。随着测试覆盖率增加，执行时间变长，影响了开发效率。通过一系列优化，Warehouse（PyPI后端）的测试执行时间从163秒减少到30秒，而测试数量从3,900增加到4,700以上，实现了81%的性能提升。 关键优化步骤包括： 1. 使用`pytest-xdist`并行执行测试，减少67%的时间。 2. 利用Python 3.12的`sys.monitoring`实现更高效的覆盖率检测，减少53%的时间。 3. 通过优化测试发现和配置，减少不必要的导入，降低启动开销。 这些优化对拥有不断增长的测试套件的Python项目尤为适用，显著改善了测试性能，而无需额外成本。当前，Warehouse测试套件在32核机器上的执行时间约为30秒，较之前的161秒有了显著提升。 优化过程中解决了数据库夹具和覆盖率报告等挑战，确保了并行测试的有效性和准确性。这些改进显著提升了PyPI贡献者的测试体验。

评论摘要
主要讨论点：针对使用 `pytest` 及其相关工具（如 `pytest-xdist`）进行测试优化的不同观点和建议，包括对测试速度、数据库处理、mocking 技术以及对 Python 测试框架的更广泛讨论。 不同观点： • [boyd] 认为使用 `pytest-xdist` 进行并行化测试是低成本高效益的优化方式，但 CI 管道中的额外开销（如 Github Actions 的 43 秒开销）使得进一步优化变得困难。他提到正在开发一个项目，旨在自动进行这些优化，并减少“第一次测试失败时间”到约 10 秒。 • [nine_k] 建议将测试数据库放在 RAM 磁盘（tmpfs）上，以加速所有与数据库相关的测试操作，如事务、fixture 加载和迁移。他认为这是未被提到的一个有效方法。 • [qznc] 主张避免完全使用 mocking，但承认在加速测试时，mocking 是合适的。他举例说明在他们的测试中 mocking `time.sleep` 和文件系统访问显著提高了速度，并强调单元测试应关注应用逻辑而非操作系统行为。 • [cocoflunchy] 对 `pytest` 的测试收集速度感到困惑，他们的 Django 应用测试套件需要约 15 秒收集测试。他们通过 ripgrep 工具创建了一个实用程序来加速这个过程。 • [NeutralForest] 认为隔离数据库操作是一个挑战，使用不同实例或模式可以有效隔离角色和操作，但实践中存在困难。 • [throwme_123] 提问 Trail of Bits 是否正在脱离“加密”领域，并提到他们是优秀的智能合约审计者，可能寻找更大的市场。 • [ustad] 询问使用 Python 内置的 `unittest` 是否有类似的优化建议。 • [bgwalter] 对 `pytest` 的“魔法”特性表示担忧，认为高安全性应用的测试套件应简单直接。他批评 Python 和 PSF 开发过程的复杂性和非正式性，并引用了一个泄露的 GitHub 链接来支持其观点。 补充讨论： • 争议焦点之一是 `pytest` 的复杂性和速度问题。一些评论者（如 [bgwalter]）认为其“魔法”特性导致速度慢且不适合高安全性应用，而其他评论者（如 [boyd] 和 [qznc]）则关注如何在现有框架内进行优化。 • 另一个值得注意的讨论点是对具体优化技术的建议，如使用 RAM 磁盘加速数据库测试（[nine_k]）、mocking 技术（[qznc]）以及实用程序加速测试收集（[cocoflunchy]）。 • 对 `unittest` 的使用建议也是一个讨论点，显示出社区中对不同测试框架的偏好和需求。

ToyDB rewritten: a distributed SQL database in Rust, for education

作者: erikgrinaker | 评分: 123 | 评论数: 8 | 发布时间: 2025-05-11 19:49
文章摘要

toyDB是一个用Rust编写的分布式SQL数据库，作为教育项目从头构建。它使用Raft算法实现线性一致的状态机复制，支持基于MVCC的快照隔离ACID事务，并提供可插拔的存储引擎（BitCask和内存后端）。其查询引擎基于迭代器，支持启发式优化和时间旅行查询，SQL接口包括连接、聚合和事务等功能。项目旨在简明易懂，而非追求性能、可扩展性和高可用性。使用Rust编译器可以构建并启动一个本地五节点集群，并通过命令行客户端执行SQL操作。toyDB的架构类似于典型的分布式SQL数据库，主要通过Golden脚本进行测试，并附带一个用于运行各种工作负载的基准工具。
