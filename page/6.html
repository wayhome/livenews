Another Crack in the Chain of Trust: Uncovering (Yet Another) Secure Boot Bypass

作者: vitplister | 评分: 88 | 评论数: 8 | 发布时间: 2025-06-10 19:55
文章摘要

Binarly Research团队发现了一个影响大多数支持UEFI设备的Secure Boot bypass漏洞，编号为CVE-2025-3052。该漏洞源于一个使用微软第三方UEFI证书签名的模块，攻击者可利用其内存损坏漏洞在启动过程中运行未签名代码，从而绕过Secure Boot，危害系统信任链。漏洞的根本原因是不安全处理NVRAM变量，导致任意内存写入。微软在2025年6月10日的Patch Tuesday中通过向dbx数据库添加14个新哈希来缓解此问题。Secure Boot通过验证操作系统加载器的完整性和真实性来防止此类攻击，但此漏洞使其失效，可能导致早期攻击和系统防御被破坏。

评论摘要
主要讨论点：UEFI、Secure Boot与BIOS的安全性和控制权问题 不同观点： • **baxtr**：认为UEFI和Secure Boot在防止攻击者安装bootkits和破坏操作系统安全防御方面有优势。强调了在操作系统加载前阻止恶意代码执行的重要性。 • **jrm4**：对UEFI/Secure Boot相较于传统BIOS的优势表示怀疑，认为用户拥有硬件就应该有完全的控制权。同时提到对不同操作系统（如Windows和Linux）的信任问题，认为用户需要自行判断和选择信任的软件。 • **db48x**：将问题归因于NVRAM变量的不安全处理，暗示这是由于技术上的 incompetence（无能）造成的，而不是UEFI或Secure Boot概念本身的问题。 • **fsflover**：提出使用开源的替代方案——TPM与Heads（https://osresearch.net/），认为这是一个有效的解决方案，并表示这个方案对自己有效。 • **jerhewet**：简单表达了对传统BIOS的怀念，希望恢复使用BIOS，显示了对新技术的不满或不适应。 补充讨论： - **技术安全性与用户控制权的争议**：评论中既有人关注技术上的安全性（如baxtr和fsflover），也有人强调用户对自己设备的控制权（如jrm4和jerhewet）。这反映了在技术进步与用户自由之间的张力。 - **开源解决方案**：fsflover提供的开源替代方案（TPM与Heads）显示了在技术社区中，开源工具常被视为一种透明且可信的解决方案。 - **责任归属**：db48x将问题归咎于技术处理上的 incompetence，暗示问题可能源于开发者的失误，而非技术本身的缺陷。 争议焦点：UEFI/Secure Boot是否提供了足够的安全优势，以及这些优势是否值得用户牺牲对硬件的完全控制权。

Sophie Germain Prime Project

作者: snoofydude | 评分: 17 | 评论数: 1 | 发布时间: 2025-06-07 19:43
文章摘要

Sophie Germain Prime Project旨在收集、分析和分发Sophie Germain质数，这些质数满足条件：若p是质数，则2p+1也是质数（称为安全质数）。项目还分类了安全质数和Blum质数（p=3 mod 4）。Sophie Germain质数广泛用于公钥加密和素性测试。尽管猜想这些质数是无限的，但仍未被证明。根据V. Shoup的估计，Sophie Germain质数的数量约为2Cn/ln(n)^2。 项目由Kamila Szewczyk维护，最初为研究Blum-Blum-Shub随机数生成器而创建。大质数（如4096位）用于BBS生成器以满足安全要求，但寻找这些质数耗时且不可预测。API允许查询和提交质数，并提供过滤选项。滥用API会导致IP永久封禁。当前，项目正在进行32位Sophie Germain质数的穷举搜索并存入数据库。贡献者可以通过表单或邮件提交质数。

评论摘要
主要讨论点：生成特定类型素数对的难度及其实现方法 不同观点： • throwaway81523 认为生成这些素数对并不像所说的那么困难。他解释说，通过生成随机奇数 n，并进行快速的试除测试，可以较快地判断 n 和 2n+1 是否都为素数。由于这些测试通常会迅速失败，所以大部分计算可以很快被排除。对于剩下的候选者，可以进行伪素数测试。他估算在现代中端 x86 计算机上，每秒可以进行约 1000 次伪素数检查，因此在不到一分钟内可以生成一个 4096 位的素数对。 • throwaway81523 对某个 C 程序表示不满，认为其过于复杂且不必要。他建议使用更简单的 Python 包装器，因为大部分计算时间将花费在 mpz 库上，而语言的选择对性能影响不大。 • throwaway81523 提到，如果需要更快的速度，可以考虑使用 SIMD 或 GPU 来并行化试除测试。 • throwaway81523 指出，在现代密码学中，这类素数已不再重要，现在更常用的是椭圆曲线。 补充讨论： • throwaway81523 提供了具体的概率估算，指出对于 4096 位素数对，成功概率约为千万分之一。尽管如此，由于可以快速排除大量无效候选者，实际需要进行的伪素数检查次数相对较少。 • 讨论中涉及了实现语言的选择，throwaway81523 认为 Python 等高级语言可以胜任此类任务，而不必使用复杂的 C 程序。 • 提到了现代计算硬件的利用，如 SIMD 和 GPU，以进一步加速计算过程。 • 强调了现代密码学实践的变化，指出椭圆曲线在当前应用中的重要性。

Containerization is a Swift package for running Linux containers on macOS

作者: gok | 评分: 729 | 评论数: 48 | 发布时间: 2025-06-09 20:53
文章摘要

Apple的容器化（Containerization）项目是一个Swift包，用于在macOS上运行Linux容器。它利用Virtualization.framework，支持管理OCI镜像、与远程注册表交互、创建ext4文件系统、优化Linux内核以实现快速启动，以及生成轻量级虚拟机和容器化进程等功能。该项目专为Apple Silicon设计，支持通过Rosetta 2运行linux/amd64容器。主要特性包括为每个容器创建专用IP地址，以及通过vminitd子项目提供GRPC API来管理容器环境。构建和运行该包需要Apple Silicon Mac及较新的macOS和Xcode版本。用户还可以自定义Linux内核配置以适应不同工作负载。
