How Claude Code works in large codebases

作者: shenli3514 | 评分: 161 | 评论数: 28 | 发布时间: 2026-05-15 04:15
文章摘要

文章介绍大型代码库中采用 Claude Code 的最佳实践：它通过本地文件遍历、grep 和引用追踪工作，而非依赖易过期的索引。成功关键在于搭建好“harness”：CLAUDE.md、hooks、skills、plugins、MCP、LSP 和子代理，逐层提供上下文、自动化改进与团队规范支持。

评论摘要
主要讨论点：围绕 Claude Code“像工程师一样浏览代码库、无需索引”的说法是否合理，以及其在大型代码库、工程实践和质量保障中的真实效果。 不同观点： • 反对“无需索引”：多位评论者认为工程师实际依赖 LSP、IDE 索引、自动补全、符号跳转和记忆；IDE 索引在 JetBrains 等工具中已被证明有效，Claude 也应能利用本地索引，而不是从零遍历文件。 • 支持/补充替代方案：有人提出代码依赖图或 AST 分析比简单读文件更有效，可回答“改这里会影响什么”，并减少 token 和工具调用；这与“纯 agentic search”形成对比。 • 对代码质量存疑：有用户举例 Claude 曾只读取每个文件前 40 行，后来才修正为 AST 分析；认为它能修复局部明显错误，但难以处理由许多看似合理的小决策累积出的系统性低质量。 • 对脚手架与配置困惑：多人询问 CLAUDE.md/AGENTS.md、skills、LSP 插件到底如何有效使用；质疑如果某些提示能稳定提升性能，为何不内置到系统提示中，并希望看到可复制的优秀示例。 • 对宣传语和成功标准怀疑：评论认为文章空泛、缺少实证；质问“大型代码库成功模式”的衡量标准是什么，如团队速度、代码寿命、生产事故减少等。 • 使用体验分歧：有人表示常用且喜欢 Claude Code；也有人称它漏读关键代码、幻觉完成情况，并认为很多团队已转向 Codex。 补充讨论：还有人质疑“本地可复制的 monorepo 是否算大型代码库”、Claude 是否把大量代码上传给模型，以及为何 C/C++/Java/PHP 被特别强调为“不常关联 AI 编码工具”的语言。

Ontario auditors find doctors' AI note takers routinely blow basic facts

作者: sohkamyung | 评分: 258 | 评论数: 16 | 发布时间: 2026-05-14 22:37
文章摘要

安大略省审计发现，获准医疗使用的20款AI病历记录系统常遗漏关键细节、编造内容并写错用药信息：60%混淆处方药，17款漏记心理健康问题。报告批评采购评分过度重视本地 presence，准确性仅占4%，存在医疗安全与隐私风险。

评论摘要
主要讨论点：围绕医疗/会议场景中AI记笔记与摘要的可靠性、风险及采用条件展开。 不同观点： • 谨慎/质疑派：LLM虽在创意、概括等方面“很神奇”，但会在基础事实和关键细节上出错，如汤匙茶匙换算、会议承诺被捏造、医疗诊断被写成骨质疏松等，说明其并非真正理解，继续扩大模型未必能解决根本问题。 • 医疗风险派：多位评论者强调AI医疗记录错误后果严重，可能影响后续治疗、费用和合规；LLM不是普通语音转文字，会插入未出现的症状、诊断或治疗建议，因此必须核对原始记录。 • 有条件支持派：AI可用于简单、结构化场景，如初诊记录身高体重、主诉等；若医生逐条复核并修正，或系统提供录音与时间戳链接，风险可降低，并可能减轻医疗系统负担。 • 采用质疑派：有人认为报告缺少样本量和错误率，难判断问题严重程度；也有人疑惑为何医院/政府会采购高错误率系统，并关注审批供应商质量。 • 比较视角：有人指出人类医疗记录本来也常出错，需比较AI与人工错误率，不能只看AI失误。 • 责任/法律派：AI摘要可能引发责任问题，甚至有人建议会议中声明“AI解释不代表真实承诺”。 补充讨论：争议焦点在于AI记笔记究竟应只做可核验转录，还是可直接生成摘要；以及在高风险场景中，AI效率收益是否足以抵消事实幻觉和责任风险。

文章摘要

作者开发了“GlyphBlaster”：用 Raspberry Pi Pico 2 替换/劫持 IBM CGA 显卡字体 ROM，把文本模式字形读取当作 1bpp 帧缓冲，通过 VSYNC 同步，在未改动 CGA 的情况下显示位图，并进一步尝试用 Wi‑Fi 串流 60fps 视频。

评论摘要
主要讨论点：利用现代可编程硬件/补丁设备“反向增强”复古主机，实现原本硬件做不到的图形效果与数据注入。 不同观点： • 多数人认为这是很巧妙的黑科技：用 Pi Pico、插入式设备或 ROM 替换，在老机器上跑出超出时代的效果，甚至像“让CGA当显示器”。 • 有人联想到类似项目，如 NES 的 bus stuffing、C64 Ultimate 上 48MHz 演示、8088 MPH，强调现代硬件能突破旧平台限制。 • 也有人脑洞升级路线：下一步做 2D/3D sprite 引擎、OpenGL，甚至调侃“让 IBM PC 跑 Crysis”，体现夸张式赞叹。 • 讨论中也有技术推演：若替换 RAM 或属性显存，可能实现彩色叠层、单行刷新、甚至用属性色做 8x1 单元；争议焦点在于不同平台（如 C64/CGA）到底能细到什么分辨率、是否能按行重取数据。 • 总体情绪偏正面，有人称赞“creative hack”，也有人从老机迷角度感慨这类作品让人重新发现旧硬件潜力。
