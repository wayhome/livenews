Unpacking Packed Executables

作者: ingve | 评分: 6 | 评论数: 0 | 发布时间: 2025-04-27 19:51
文章摘要

本文讨论了如何解包被压缩的Windows 32位可执行文件（EXE），特别是用于Demoscene竞赛中的小体积程序。这些程序通常使用如UPX之类的工具压缩，以满足文件大小限制。解包的目的是恢复原始程序，以便进行静态分析。 解包的核心挑战在于找到程序解压完毕但尚未执行主要代码的时机。由于解压后的代码地址在解压过程中是动态生成的，直接定位较为困难。可以通过手动或自动方式识别解压后的跳转地址（some_address）。 另一个问题是恢复 imports（导入表）。压缩的EXE通常只包含最小依赖，解压时动态加载实际依赖。为进行静态分析，需要重建这些依赖，使分析工具（如Ghidra）能正确识别程序调用的系统函数。 作者通过retrowin32实现了这一过程，成功解包了一个压缩EXE并解决了上述问题。

Pkg.pl: An experimental package manager for Scryer Prolog

作者: triska | 评分: 3 | 评论数: 0 | 发布时间: 2025-04-27 21:52
文章摘要

`pkg.pl` 是一个为 Scryer Prolog 设计的实验性包管理器。该项目旨在探索如何为 Scryer Prolog 实现包管理功能，目前仍处于早期阶段，存在安全漏洞（如远程代码执行）。其主要文件 `pkg.pl` 同时作为依赖管理器和包加载器。使用时，需将 `pkg.pl` 复制到项目中，并通过命令下载依赖到 `scryer_libs` 目录。包的定义通过 `scryer-manifest.pl` 文件实现，包含包名、主文件和依赖等信息。当前版本不处理传递依赖。用户可通过创建 issues、提交 pull requests 或发起讨论参与贡献。项目遵循 Unlicense 协议。

文章摘要

本文探讨了编译器引入的安全漏洞（CISB）问题。尽管编译器保证优化后的代码在语义上与原始代码等价，但它们可能引入安全漏洞，因为安全属性超出了翻译正确性的范畴。这些漏洞难以发现和预防，尤其是在责任归属不明确的情况下。作者通过分析4,827个潜在漏洞报告，整理出CISB的分类，并通过用户研究了解用户对编译器行为的看法。研究表明，编译器引入的安全漏洞普遍且可能造成严重影响，期望用户完全理解和遵循编译器假设是不现实的，尤其是“无未定义行为”假设已成为CISB的主要原因之一。

本文主要讨论了硅谷如何成为全球科技中心，并超越了曾经的竞争对手——波士顿的128号公路科技区。作者通过自己参加多个硅谷重要活动的经历，展示了硅谷强大且重叠的创新网络，如TiE（原为“印度企业家”，后更名为“企业家”组织）等。这些网络不受传统或保守规则限制，吸引了大量外部人才，推动了创业成功。相比之下，尽管1980年代波士顿128号公路科技区曾是科技中心，但因其较为封闭的企业文化、缺乏流动性及保守的网络结构，逐渐被硅谷甩在后面。加州大学伯克利分校教授AnnaLee Saxenian在其1994年著作《区域优势》中详细分析了这一变化，指出硅谷的开放文化、人才流动性及信息共享是其成功的关键。

Open-source interactive C tutorial in the browser

文章摘要

learn-c.org是一个免费的互动式C语言教程网站，面向所有希望学习C语言的用户，无论是否有编程经验。网站无需下载任何软件，选择章节即可开始学习。目前网站仍在建设中，提供从基础到高级的C语言教程，包括变量、数组、循环、指针、结构体、递归、链表等内容。用户也可以贡献教程。同时提供了练习和赞助选项。网站包含使用条款和隐私政策。

评论摘要
主要讨论点：C语言交互式教程的有效性、技术准确性、学习工具的选择及广告影响 不同观点： • Borzadaran认为交互式教程有助于降低入门门槛，但技术准确性对初学者至关重要。他建议坚持使用单一C标准（如C99），正确涵盖结构体和指针等重要主题，并推荐使用`_Bool`而不是宏定义布尔值。 • Atiedebee指出教程中存在一些不准确之处，例如整数定义、宏定义布尔值的问题，以及对结构体和指针作为高级主题的处理不当。他还提到教程没有详细说明如何编写头文件，并认为这对实际使用C语言非常重要。 • Eigenvalue和Anovikov都提到广告对教程使用体验的影响，认为广告过多使得教程在移动端几乎无法使用。 • Herewulf强调学习C语言时使用GCC或LLVM的重要性，认为这些工具对学习C语言非常有帮助，尤其是对那些希望超越简单程序的开发者。 • Alabhyajindal对比了教程和《Head First C》这本书，认为后者更具趣味性且内容组织更有效。 • Fuhsnn指出教程中信息混杂，尤其是关于`_Bool`和`long long`的描述，可能是为了兼容旧版MSVC。 • Larfus认为教程存在不一致性和缺乏清晰度的问题，并表示书籍是学习C语言的更好选择。 • Kubb对教程的作者表示支持，并认为尽管有许多新语言出现，C语言在未来几十年内仍将占据重要地位。 • Buttons840和Codr7提供了其他相关资源和教程链接，认为更多的教程对学习者有益。 补充讨论： • Doublerabbit提到教程常常忽略细节解释，例如没有说明`%d`的作用，这对初学者可能造成困惑。 • Dbacar指出该教程网站还托管其他语言的学习资源，表明这是一个多语言学习平台。 争议焦点： • 教程的技术准确性和内容组织方式存在争议，尤其是对初学者有误导风险。 • 广告对教程使用体验的影响也是一个主要争议点。
