Sci-Hub has been blocked in India

作者: the-mitr | 评分: 207 | 评论数: 23 | 发布时间: 2025-08-28 04:47
文章摘要

印度法院近日下令封锁学术网站Sci-Hub和Sci-Net，这是由爱思唯尔、威利和美国化学学会等国际出版商推动的。自2020年起，这些出版商就试图在印度阻止免费获取学术论文。尽管2021年曾有法律团队为Sci-Hub辩护，但法院迟迟未作裁决。2025年，出版商又以违反2021年禁令为由要求封锁Sci-Net，尽管两者是不同项目。文章批评此举侵犯知识获取权，损害印度科研发展，呼吁抵制这种阻碍科学传播的行为。

评论摘要
主要讨论点：[科学知识的获取壁垒及印度对Sci-Hub的封锁] 不同观点： • **支持Sci-Hub的观点** - 科学知识应免费获取，付费墙阻碍科研进展（如[megaloblasto]提到每年2万美元的阅读成本）。 - 开放获取是长期解决方案，研究者应坚持开源出版（[the-mitr]）。 - 封锁Sci-Hub损害印度自身利益，使其他国家更具优势（[hnhg]）。 • **对印度司法和封锁的批评** - 印度司法系统效率低下，裁决常受主观影响而非法律事实（[sieve]、[wtmt]）。 - 封锁无效，用户可通过VPN/Tor绕过（[wtmt]、[tim333]）。 - 政府行为矛盾，虽封锁Sci-Hub但推出“One Nation One Subscription”计划（[dartharva]、[the-mitr]）。 • **国际封锁的普遍性问题** - 西班牙、英国等地也存在类似封锁（[diggan]、[torh]）。 - 需通过.onion链接或VPN访问（[Aachen]、[tim333]）。 补充讨论： - **争议焦点**：封锁是否真正保护版权，还是阻碍知识传播（如[faangguyindia]强调知识不应受限）。 - **替代方案**：印度政府通过集体订阅期刊提供部分解决方案（[dartharva]），但效果受质疑。 - **技术对抗**：用户普遍倾向使用技术手段绕过封锁，凸显禁令的局限性。

About Containers and VMs

作者: Bogdanp | 评分: 72 | 评论数: 9 | 发布时间: 2025-08-25 07:58
文章摘要

本文介绍了Incus支持的两种实例类型：系统容器和虚拟机。系统容器利用Linux内核特性（如命名空间和cgroups）实现软件隔离，只能运行Linux系统，资源消耗少；虚拟机则依赖硬件虚拟化技术，可运行不同操作系统，但资源消耗较大。文章还比较了应用容器（如Docker）与系统容器的区别，指出应用容器适合隔离单个应用，而系统容器可模拟完整操作系统环境。最后建议根据需求选择：如需兼容主机内核的功能且追求性能，选用系统容器；如需不同操作系统支持，则使用虚拟机。

评论摘要
主要讨论点：[容器与虚拟机的技术差异及安全性比较] 不同观点： • **虚拟机与容器的技术差异** - hliyan：虚拟机让操作系统以为自己独占机器，容器让进程以为自己独占操作系统。 - mappu：虚拟机不一定需要硬件虚拟化，MMU即可实现隔离，例如Alibaba的PVM和QEMU的TCG。 • **容器管理工具的用户体验** - scottyeager：Incus为虚拟机提供了类似容器的体验，支持便捷的文件操作和Shell访问，提升了使用体验。 • **容器安全性争议** - reilly3000：询问系统容器是否比应用容器更安全。 - Ericson2314：批评内核设计导致用户层“中间件”泛滥，希望Capsicum等提供更安全的默认配置以减少“安全剧场”。 • **技术实现的误解与澄清** - jiggawatts：指出页面表格中的错误，例如容器不仅限于Linux（Windows容器存在），且容器可以托管多个应用（尽管不推荐）。 补充讨论： - **域名争议**：skywhopper和jiggawatts质疑“linuxcontainers.org”域名被Incus/LXC独占使用是否合理。 - **工具比较**：worik以幽默方式强调Docker的优先级（无实际论据），而kottapar提到BootC的不可变性与Incus类似。 争议焦点： 1. 容器与虚拟机的技术边界（是否需要硬件虚拟化）。 2. 容器安全性的实际表现（系统容器 vs 应用容器）。 3. 技术文档的准确性（如容器功能描述）及域名使用的合理性。

Pausing Insect Activity

作者: surprisetalk | 评分: 19 | 评论数: 1 | 发布时间: 2025-08-25 11:23
文章摘要

这篇文章主要探讨了昆虫的滞育现象（diapause），即昆虫生命周期中一种可逆的发育停滞状态。文章指出，滞育不同于其他休眠形式，是昆虫特有的发育暂停机制，能在不同生命周期阶段（卵、幼虫、蛹或成虫）被触发。这种机制帮助昆虫应对季节性变化，在温带地区尤其显著，可长达9个月。 文章强调了研究滞育的重要意义：昆虫生物量巨大（约10^19个体），了解滞育机制对农业、林业和疾病防控具有重要价值。滞育类似于"时间胶囊"，使昆虫能预判环境变化并提前应对。文章还提到，休眠机制在不同生物中普遍存在且可能具有相似的生理基础，而昆虫滞育因其规模庞大而尤为突出。 最后，文章指出滞育研究历史悠久，最早可追溯到18世纪法国博物学家对蜜蜂冬季行为的研究。

Malicious versions of Nx and some supporting plugins were published

文章摘要

主要讨论点：[软件供应链安全、依赖管理、攻击防御措施] 不同观点： • **禁用安装脚本**：建议通过 `npm config set ignore-scripts true` 禁用 npm 安装脚本，以减少供应链攻击风险。认为当前大多数合法包无需安装脚本即可运行，对于需要脚本的包可单独处理。 • **减少依赖**：主张在添加新依赖前仔细考虑，尽可能自己编写简单功能。举例通过 LLM 生成一个简单的进度条代码，避免了引入复杂依赖。 • **安全机制缺失**：指出当前包管理器缺乏必要的安全机制，如代码签名、MFA、令牌管理等，认为这是行业整体失败，需要建立类似建筑规范的强制安全标准。 • **沙盒环境**：建议在虚拟机或容器中运行不信任的代码，特别是对于具有高风险的应用程序（如 NodeJS 应用、通过 shell 脚本安装的工具）。 • **包管理器改进**：提出包管理器应引入“最小年龄”设置，忽略新发布的包以减少风险。同时建议操作系统限制应用程序的默认文件系统访问权限。 补充讨论： • **新型攻击方式**：讨论了使用本地 LLM 通过提示词进行攻击的新形式，这种攻击绕过传统静态分析，难以防御。 • **实际案例**：提到 Grafana 的安全事件，以及 VS Code 插件通过运行 `npx` 命令被攻陷的案例，显示攻击的普遍性和易发性。 • **行业反应**：批评 Anthropic 在宣传其 AI 防犯罪能力的同时，其工具本身存在多个安全漏洞，显得 hypocritical。 • **潜在威胁**：担忧开源软件供应链攻击可能比已知的更普遍，特别是国家行为体可能利用广泛使用的依赖注入后门。 争议焦点： • **责任归属**：部分评论认为攻击成功是由于包管理器和开发者的安全措施不足，而另一些则强调攻击者的创新手段（如利用 LLM）使得传统防御无效。 • **解决方案的有效性**：禁用脚本和减少依赖是否足以应对日益复杂的攻击，还是需要更根本的系统性改革（如强制安全规范）。

Researchers find evidence of ChatGPT buzzwords turning up in everyday speech

作者: giuliomagnifico | 评分: 59 | 评论数: 23 | 发布时间: 2025-08-27 21:27
文章摘要

佛罗里达州立大学的研究发现，ChatGPT等AI聊天机器人的流行正在改变人们的日常用语。研究表明，自2022年ChatGPT发布后，"delve"、"intricate"等AI常用词在口语中的使用频率显著增加，而它们的同义词则没有类似增长。研究人员分析了2210万个口语词汇，发现约四分之三的AI高频词使用量激增，部分词汇使用频率甚至翻倍。这项首次针对AI如何影响人类口语系统的同行评审研究指出，AI不仅被当作工具使用，其语言模式可能正在"渗透"进人类语言系统，引发关于AI偏见可能影响人类行为的伦理担忧。

评论摘要
主要讨论点：LLMs（如ChatGPT）对语言使用习惯的影响，尤其是某些词汇（如“delve”“intricate”）的过度使用是否导致其成为“AI标志词”，以及人类是否会无意识地模仿AI的写作风格。 不同观点： • **反对将“delve”等词简单归为AI标志** - [milancurcic]认为“delve”是个人长期使用的词汇，不能因AI滥用而否定其合理性，强调语言学习背景的多样性。 - [tasty_freeze]指出这些词并非“流行语”（buzzword），只是使用频率较低的普通词汇，过度标签化会误导。 • **支持AI对语言习惯的显著影响** - [esafak]和[nowittyusername]从人类模仿天性出发，认为AI比社交媒体更易改变人类行为模式（如词汇选择、标点习惯）。 - [lukeinator42]和[_1]通过实际观察，证实AI相关词汇（如“delve”）和格式（如加粗、列表）的传播现象。 • **讽刺与实用主义应对** - [mrbonner]和[willquack]通过故意拼写错误或规避AI常用词来“自证人类身份”，反映对AI介入写作的焦虑。 - [abraham]用反讽句式集中使用争议词汇，调侃AI检测的荒谬性。 补充讨论： - **争议焦点**：词汇使用频率上升是否应归因于AI，还是自然语言演变（如[anigbrowl]调侃为“美国文化水平提高”）。 - **文化因素**：[freehorse]提出“meticulous”在中文翻译中的高频出现可能源于语言或工具偏好，需进一步验证。 - **行为模仿深度**：[nowittyusername]借黑猩猩实验类比，强调人类对AI的模仿可能远超预期。
