Foam: A free Roam alternative for VSCode

作者: AbuAssar | 评分: 47 | 评论数: 5 | 发布时间: 2025-06-04 22:57
文章摘要

Foam 是一个基于 Visual Studio Code 和 GitHub 的个人知识管理与分享系统，受 Roam Research 启发。它可以帮助用户组织研究、记录可重新发现的笔记、撰写长文，并可选择将内容发布到网络。Foam 是免费开源的，具有高度可扩展性，用户可以完全掌控自己创建的信息，并自由分享与协作。 主要功能包括： - 图形可视化：通过图形展示笔记间的联系。 - 链接自动补全：帮助创建笔记间的连接。 - 文件重命名时同步链接：保持笔记的一致性。 - 跨目录唯一标识符：支持同名文件在不同目录中存在。 - 链接预览与导航、笔记嵌入、章节支持、链接别名、模板、反向链接面板、标签浏览面板等功能。 - 支持孤立和占位符面板，帮助管理无链接或无内容的笔记。 - 语法高亮、每日笔记、生成 Markdown 引用等。 Foam 提供了多种命令和快捷方式，帮助用户高效管理知识库，并支持通过图形和反向链接发现笔记间的联系。用户可以根据指南创建一个 Foam 工作区，使用 Markdown 文档记录想法，并通过 Wiki 链接进行连接和浏览。

评论摘要
主要讨论点：Foam与类似笔记工具（如Org-roam、Obsidian）的比较，主要围绕功能、使用场景和特定插件的缺失展开讨论。 不同观点： • [senkora] 提出 Org-roam 也是一种类似的工具，但它是为 Emacs 设计的，使用 Org 模式。这表明 Foam 和 Org-roam 都是受 Roam Research 启发的工具，但适用于不同的编辑器（VS Code 与 Emacs）。 • [sputknick] 分享了个人经验，提到自己曾从 Foam 切换回 Obsidian。原因在于 Foam 的强项——VS Code 集成——对非软件开发相关的笔记使用场景并不友好。约三分之二的笔记是非开发相关的，因此频繁进入 VS Code 感觉笨重。他指出，如果笔记几乎全是与软件开发相关，Foam 是一个很好的选择。 • [metayrnc] 关注 Foam 的功能缺失，特别是缺乏类似 Obsidian 中 Dataview 的插件。这表明从 Obsidian 切换到 Foam 的用户可能会因为缺少某些功能（如数据查询和展示功能）而犹豫。 • [fouc] 引用了 Foam 的定义，强调它是一个受 Roam Research 启发的知识管理系统，并且是基于 Visual Studio Code 构建的，这与 Org-roam 在 Emacs 上的实现形成对比。 补充讨论： - Foam 的 VS Code 集成是讨论的焦点之一，部分用户（如 sputknick）认为这对非开发相关的笔记使用场景不太方便。 - Obsidian 的特定插件（如 Dataview）是用户考虑切换工具时的重要因素，Foam 目前缺乏类似的功能可能是其劣势。 - 不同工具（Foam、Org-roam、Obsidian）适用于不同的用户需求和工作流，特别是开发与非开发场景的区别在讨论中被强调。 争议焦点：Foam 的 VS Code 集成的优劣以及功能缺失（如 Dataview）是否会影响用户体验和选择。

The Right to Repair Is Law in Washington State

作者: doener | 评分: 341 | 评论数: 19 | 发布时间: 2025-06-04 15:00
文章摘要

华盛顿州通过了维修权法案，确保居民能够获取工具、零件和信息来修理个人电子设备、电器和轮椅。该法律得到多个组织支持，包括谷歌、微软等企业以及环保和消费者权益倡导者。此外，残疾权益组织成功将轮椅纳入法案。美国陆军也发布备忘录，要求在合同中加入维修权条款，以解决因知识产权限制导致的维护问题。该法律反映了人们对自主维修的需求，已在全美获得广泛关注，目前所有50个州都已考虑类似的立法，华盛顿是第八个正式通过的州。

评论摘要
主要讨论点：华盛顿州维修权法案（SB 5680）的实施及其影响 不同观点： • [支持观点] walterbell指出，从2026年1月1日起，制造商将不能再使用部件配对来阻止这些设备的自助维修，这意味着用户自行更换屏幕时不会出现“未知部件”的提示，也不会因为自行维修手机而降低相机或指纹传感器的功能。该法案还进一步涵盖了轮椅用户的权益，要求制造商提供部件、工具以及常被用来进行数字锁定的固件和嵌入式软件。 • [质疑法案有效性] net01认为该法案类似于德克萨斯州的版本，存在漏洞，例如要求出售组件部件（如带铰链和摄像头的屏幕）而非仅显示屏，这使得维修成本更高。 • [扩展应用讨论] drdaeman好奇该法案是否能用于请求协议文档以整合不同供应商的系统产品，尤其是解决物联网设备中私有“枢纽”或“云服务”带来的问题。 • [具体案例] rkagerer提到Axis在其IP摄像头中锁定某些有用功能，除非安装Axis品牌的SD卡，质疑该法律是否对此类商业行为有影响。 • [例外与豁免] pnw认为尽管该法案是进步的，但它已被华盛顿政客淡化，提到了视频游戏机豁免，并指出其他更改。 • [具体产品讨论] CrimsonCape指出华盛顿法案排除了电动工具，而德克萨斯法案没有，这意味着在德克萨斯可以自行更换锂电池。 • [法案局限性] devwastaken认为该法案无实质作用，因为卖方有权通过让用户同意更晦涩的条款来免责，主张应激励市场制造可维修产品，并建议彻底取消软件和硬件专利。 补充讨论： • [法案执行与地区限制] divbzero关心公司是否会被强制设计在任何州都可以维修的产品，或者是否存在方法可以限制在没有维修权法的州进行维修。 • [加密与软件权利] GnarfGnarf和avodonosov分别询问该法案是否适用于加密文件格式以及是否包括反编译和修改软件的权利。 • [现实案例与联邦影响] 0xbadcafebee提到基本设计的 generator 维修问题，Yhippa则开玩笑提到是否可以去华盛顿调校受加密保护的 Audi S5，而 lenerdenator 预测该法案可能成为联邦游说努力的焦点，以减少所谓的繁琐州 regulations。 • [企业过度控制] froggertoaster对John Deere等公司过度控制产品维修权表示不满，乐见监管风向变化。
