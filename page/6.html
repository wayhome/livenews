这篇文章探讨了"失落技术"这一流行于奇幻作品中的概念在现实中的真实性。作者通过分析历史上所谓的"失落技术"案例，发现真正完全失传的技术非常罕见。文章主要分为两部分：首先定义了"技术失传"的概念（指完全失去制造某种过去技术的能力和知识）；然后通过具体案例（如19世纪意大利科学家Segato的遗体矿化技术）说明技术失传通常要么是由于知识仅掌握在个别人手中而随其死亡失传，要么是出于某种故意行为。作者最终得出结论：在现实中，真正重要且有价值的技术很少会完全失传。

评论摘要
主要讨论点：技术是否会遗失以及遗失的原因和影响 不同观点： • **技术遗失是可能的**：现代技术依赖于全球供应链和高度专业化的知识，一旦供应链断裂或知识无法传承，技术就可能遗失（如磁传感器案例）。 • **历史上有技术遗失的先例**：古代文明如埃及和印加的石材切割技术、罗马混凝土的配方等，这些技术在一段时间内完全失传（eigencoder、simne）。 • **技术遗失的原因多样**：包括经济因素（供应链中断）、政治因素（专利保密、贸易中断）、知识传承问题（专家去世、文档散失）以及技术进步本身带来的“副作用”（如材料纯度提高导致旧工艺失效）（mitthrowaway2、kccqzy、beerandt）。 • **现代文明的脆弱性**：尽管现代技术保存手段先进，但全球基础设施（如互联网、电网）的崩溃可能导致技术无法重建（thorum、oaiey）。 • **技术遗失的分类争议**：有人区分“发明”、“技术”和“知识”的遗失，认为讨论中混淆了这些概念（alberth）。 补充讨论： • **争议焦点**：技术遗失是否真的存在，还是只是知识暂时未被使用或重新发明（antman、reedf1）。 • **未来风险**：全球化逆转和地缘政治冲突可能加剧技术遗失的风险（kccqzy）。 • **社会影响**：某些技术（如汽车、空调）一旦发明便难以“退回”，即使带来负面影响（LeifCarrotson）。

XSLT的工作原理：通过XSLT样式表将XML转换为HTML格式，但这种方法可能在未来不再可用。 3. 替代方案： - 使用CSS直接样式化XML文档，但功能有限 - 建议在服务器端或构建过程中将XML转换为HTML，这是最佳实践 - 对于特殊情况，提供了客户端转换的替代方法 4. 作者建议保持XML和HTML作为两个独立资源，通过标签关联它们。

[jact]: I've seen people argue against XML/XSLT saying JSON and JavaScript is easier and more modern. But XML/XSLT has advantages like being able to transform the same data into different formats (HTML, PDF, etc.) without changing the backend code. That seems more maintainable to me than having separate endpoints or client-side rendering. 主要讨论点：[后端数据处理方式的选择：XML/XSLT vs JSON/JavaScript] 不同观点： • 支持XML/XSLT的观点： - 可以通过内容协商/headers从同一URI返回多种格式(xml, json, HTML) - 使用XSLT或xQuery转换同一数据到不同格式(HTML, PDF等) - 不需要修改后端代码，更具可维护性 - 不需要单独端点或客户端渲染 • 支持JSON/JavaScript的观点： - 更简单现代 - (隐含观点)可能更适合当前主流开发方式 补充讨论： • 争议焦点在于哪种方式更简单易用和可维护 • XML/XSLT支持者认为其一次配置即可支持多种输出格式的优势被低估 • 讨论中提到Python等其他项目也采用了类似后端处理方式
