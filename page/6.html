CONL: "Markdown" for your config files

作者: kretaceous | 评分: 51 | 评论数: 18 | 发布时间: 2025-04-27 01:18
文章摘要

本文介绍了一种新的配置文件格式——CONL，旨在解决JSON、YAML和TOML在实际使用中的痛点。CONL的设计目标是易读、易编辑、易实现，并且尽量简化语法以避免混淆。它采用类似JSON的数据模型，支持键值对、列表和映射，但不支持JSON中的null、number等复杂类型，以保持简洁。CONL避免了TOML中[]和[[]]的混淆问题，也不需要像JSON那样管理逗号，因为每个键值对独占一行，用换行符作为自然分隔符。CONL还从Markdown中获得灵感，支持多行字符串。尽管简化的模型导致无法完美地来回转换JSON类型信息，但其极简的特性使得实现和使用非常方便。目前，CONL已有Rust和Go的实现，并提供了规范和测试套件供开发者使用。

评论摘要
主要讨论点：各种配置文件格式的优缺点及是否需要新格式 不同观点： • [nickm12] 认为 JSON 在支持注释和尾随逗号方面存在不足，推荐使用 JSON5 或类似格式。他还提到 CONL 使用 scalar|list|map 的数据模型，但对类型定义不够清晰。同时，他赞扬 TOML 区分整数和浮点数的做法。 • [0xbadcafebee] 怀念过去配置文件不以易于解析为目的，而是以方便人类配置软件为主的时代，暗示当前趋势过于注重计算机便利性。 • [EasyMarion] 喜欢 CONL 的哲学，认为其在人类可编辑和机器可解析之间找到了平衡，不倾向于使用编程语言。 • [simonask] 认为 KDL 在可读性和友好性方面无与伦比，希望其得到更广泛的应用。 • [networked] 提到一篇关于 TOML 的批评文章，并指出其因引用Postel法则而受到批评。 • [martypitt] 推荐 HOCON，认为其是强大的配置文件格式，支持注释、环境变量处理和变量引用等功能。 • [rsyring] 认为使用已有广泛支持的格式比发明新格式更实际，并推荐 StrictYAML。 • [aburdulescu] 提到自己正在开发一个配置格式，并请求反馈，但表示该项目仅为个人使用，不打算广泛推广。 • [kiitos] 对 CONL 使用缩进表示结构表示担忧。 • [Rucadi] 分享使用 NIX 作为可编程配置文件，并输出 JSON 供应用程序读取的经验。 • [qznc] 推荐 NestedText，因其不试图变得“聪明”，所有内容都是字符串。 • [stared] 建议创建一种以分号表示注释的格式，但对其外观表示疑虑。 • [throwaway150] 质疑是否每个人都在尝试创建以自己命名的配置文件格式。 • [Hyperlisk] 表示自己也在开发类似的配置语言，并邀请其他人参与讨论。 • [dcreater] 怀疑新格式是解决现有格式问题的答案，对新格式的必要性表示高度怀疑。 补充讨论： - 讨论中涉及的格式包括 JSON5、CONL、TOML、KDL、HOCON、NIX、NestedText 等。 - 争议的焦点在于是否需要新配置格式，以及现有格式如 JSON、TOML 等的优缺点。 - 不同开发者对配置文件的可读性、易用性、以及对人类和机器的友好性有不同看法。 - 一些开发者支持使用已有格式，而另一些则在探索和推广新格式。

Lossless LLM compression for efficient GPU inference via dynamic-length float

作者: CharlesW | 评分: 400 | 评论数: 22 | 发布时间: 2025-04-25 18:20
文章摘要

这篇文章提出了一种名为Dynamic-Length Float (DFloat11) 的无损压缩框架，用于减少大型语言模型（LLM）的体积，同时保持输出结果与原模型完全一致。DFloat11利用BFloat16权重表示中的低熵特性，通过熵编码为权重分配动态长度编码，实现近似信息最优的压缩。文章设计了自定义GPU内核以支持高效的在线解压缩，包括将内存密集的查找表分解为紧凑表、协调线程读写位置等方法。实验表明，DFloat11可在不损失精度的情况下将模型大小减少30%，并在多个最新模型上验证了其有效性，显著提高了吞吐量和上下文长度。文章代码和模型已开源。
