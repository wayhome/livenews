Hyper-Markdown – Markdown for knowledge graphs

文章摘要

Hyper-markdown (.hmd) 是 Markdown 的超集格式,在保持完全兼容 CommonMark 的基础上,增加了三层能力: **基础层**继承完整的 CommonMark 语法,任何 .md 文件都是有效的 .hmd 文件。 **富文本层**支持表格、脚注、任务列表、TeX 数学公式、D2 图表等扩展功能。 **超链接层**是核心创新,通过 `[[tokens]]` 语法实现基于名称(非路径)的文档引用和嵌入,支持引用整个文档、标题或命名块,并可通过 `![[]]` 语法将内容嵌入到其他页面。 配套工具包括 Python CLI(lint/render/graph 功能)、MkDocs 插件和 VS Code 扩展。整个格式有明确的规范文档定义,工具实现需遵循规范而非自定义行为。

评论摘要
主要讨论点：Hyper-Markdown项目的文档质量和AI生成内容的使用 不同观点： • **反对AI生成文档派**：认为AI生成的文档比无意义文字更糟，因为难以辨别真伪，耗时解析且无法验证正确性。项目首页应该手写，这关系到项目的可信度和质量印象（Planktonne, haburka） • **项目作者立场**：介绍Hyper-Markdown是在普通Markdown基础上增加可视化和知识图谱功能，强调向后兼容，欢迎反馈和贡献（divingstar） • **技术对比观察**：有用户指出该项目与Obsidian的Markdown格式相似，暗示可能缺乏创新性（0x696C6941） 补充讨论：有用户关心多语言实现的规划（Python和TypeScript之外），另有讽刺性评论直接点名"感谢Claude"，强化了文档由AI生成的质疑。核心争议在于：使用AI生成项目文档是否会损害项目的专业形象和可信度。

ChatGPT starts blocking direct requests to copy an author's style

作者: Eloissssss | 评分: 63 | 评论数: 14 | 发布时间: 2026-08-09 02:01
文章摘要

OpenAI的ChatGPT现已开始拒绝直接模仿知名作家风格的请求。当用户要求以某位作家（如斯蒂芬·金、狄更斯等）的风格写作时，ChatGPT会婉拒，转而提供一个融合该作家"广泛特质"但保持独特声音的回应。 这一调整可能与OpenAI正面临的多起版权侵权诉讼有关。虽然美国版权法通常不保护作家的风格，但如果AI生成内容与原作"实质相似"，仍可能构成侵权。 不同AI模型对此处理方式各异：Google的Gemini会配合模仿请求，而Perplexity AI则一律拒绝。这一变化也给一些依赖特定风格提示的长期用户带来了使用困扰。

评论摘要
主要讨论点：AI模型限制模仿著名作者写作风格的政策及其影响 不同观点： • **反对限制派**：认为这种限制过度且令人沮丧（nicbou提到"说服机器做工作很挫败"），影响正常使用体验。部分用户希望继续使用特定作者风格来改善AI输出质量（at1as用Orwell风格去除"Why It Matters"等套话） • **技术绕过派**：分享规避方法，如先让AI描述作者风格，再在新对话中使用该风格描述而不提作者名（Mountain_Skies），或用"祖父是某作者"等提示词绕过限制（ButlerianJihad） • **能力质疑派**：认为LLM根本写不好，无法模仿普通人更别说著名作者（malshe），这种限制是多余的 • **版权伦理派**：指出AI训练时已"窃取"所有作者风格（lethologica），暗示限制的虚伪性 • **竞争力担忧派**：认为过度限制让美国AI公司失去竞争优势，DeepSeek等国际竞争者没有这些限制（raincole, quotemstr） 补充讨论：有人质疑限制的边界问题（如公共领域作品、未完成作品、失传作品的风格是否也被限制），以及这种政策早已存在的事实（super256提到很久前就遇到限制）
