Show HN: A Raycast-compatible launcher for Linux

作者: ByteAtATime | 评分: 182 | 评论数: 19 | 发布时间: 2025-07-13 16:57
文章摘要

**Raycast-Linux** 是一个为 Linux 开发的、受 Raycast 启发的开源启动器。它旨在重现 Raycast 的核心功能，包括可扩展命令面板、支持 Raycast API 的扩展、智能计算器（由 SoulverCore 驱动）、剪贴板历史记录、文本片段和 AI 集成等。由于 macOS 和 Linux 之间的差异，部分 Raycast 扩展可能不兼容，尤其是依赖 macOS 特有 API 或二进制文件的扩展。 用户可以通过 GitHub Releases 页面下载最新的 **.AppImage** 文件，并通过命令行赋予执行权限后运行。该应用需要 glibc 2.38 及以上版本，并建议 Wayland 用户配置 udev 规则以启用全局文本片段功能。若要从源代码构建，需安装 Rust、Node.js、pnpm、Tauri 及 Swift 工具链。

评论摘要
主要讨论点：Linux平台上的Raycast替代品及其相关技术讨论 不同观点： • Imustaskforhelp认为该AppImage文件过大，与其预期不符，特别是考虑到Tauri框架本应带来更小的体积。此外，他在Wayland环境下遇到EGL显示错误，并表示自己使用dmenu（fuzzel）和自定义键绑定（hyprland）作为替代方案。 • runjake对项目表示赞赏，但建议更改名称以避免潜在的商标问题。他还提到其他可扩展的Linux启动器，如KRunner和Albert。 • a022311对项目表示高度赞赏，并建议使用Deno作为运行时以解决扩展启动慢的问题，同时推荐Numbat作为Soulver计算器的替代方案，以及参考Project Gauntlet项目。 • ksynwa引用了维基百科上关于Raycast的定义，强调其最初是为macOS开发的。 • mynegation和flipcoder都提到名称问题，认为可能会引发法律纠纷，建议尽快更改名称。 • jraph提到KRunner作为另一个可扩展的Linux启动器选项。 • Sophira关注Wayland环境下的安全问题，质疑添加udev规则是否会削弱Wayland对键盘访问的保护机制。 • _seiryuu_表示项目在cosmic shell环境下表现有些异常，但在其他环境下运行良好。 • imcritic对项目的价值提出质疑，认为增加更多软件未必能显著提升效率。 • ddaletski和hiyer都表示自己正在开发类似的项目，但看到该项目后考虑贡献代码而不是继续自己的项目。 • evertedsphere的评论较为调侃，没有提供实质性意见。 • regularjack对项目开发者的年龄表示赞赏，并鼓励其继续努力。 补充讨论： • 项目的名称问题引发多次讨论，多数意见认为需要更改以避免商标纠纷。 • 关于技术实现，特别是运行时和计算器实现的选择，a022311提供了详细的建议和参考链接。 • Wayland环境下的安全机制及其可能的绕过问题引起了Sophira的关注和质疑。 • 项目在不同Linux环境下的兼容性和表现也被多位用户提及，显示出对跨平台支持的关注。

Monitoring My Homelab, Simply

作者: Bogdanp | 评分: 118 | 评论数: 20 | 发布时间: 2025-07-10 11:28
文章摘要

文章介绍了一种简化的家庭实验室监控方案，作者开发了一个小型程序来进行HTTP、DNS、TLS等检测，并通过https://ntfy.sh发送通知。该方案旨在满足以下需求：出现严重故障时通知、持续故障时重复提醒、修复后通知以及易于添加检测器。程序通过一个循环运行检测器，失败时发送通知，并每小时提醒一次。作者提供了TLS检测器的示例代码，并说明了如何处理故障和恢复通知。程序设计简单，避免复杂的状态管理，且易于部署和维护。作者的目标是捕捉明显的系统问题，而非解决所有潜在故障或提供详尽的历史数据分析。

评论摘要
主要讨论点：各类监控解决方案的比较与选择 不同观点： • reboot81 推荐使用 https://healthchecks.io 并提供了针对不同操作系统（Windows、MacOS、Linux）的脚本链接，强调其易用性。 • Jedd 提到使用两个“死开关”（dead man switches）进行监控，并通过个人经历强调日志聚合的重要性，指出家庭实验室中日志聚合的简便性及其潜在的多重好处。 • Evidlo 推荐使用 updown.io，因其价格低廉且易于使用，特别适合单台机器的监控。 • Scaevolus 使用 Prometheus + Prometheus Alertmanager 组合，强调其功能丰富和报警表达式的可视化优势，且可通过容器化简化部署。 • danesparza 强调家庭实验室中应监控的具体指标，如RAID健康状态、磁盘空间、备份作业运行情况和SSL证书到期等。 • justusthane 计划开发一个Python程序作为监控解决方案，强调其可扩展性和插件化设计，但提到开发进度缓慢。 • Havoc 认为 Uptime Kuma 最简单，尤其因为其提供了Python API包，便于批量操作和编辑。 • compumike 自荐其团队开发的监控和报警解决方案 https://heiioncall.com/，强调其功能全面和灵活的静音设置。 • bonobocop 推荐 Cloudprober，因其易于配置和扩展，适合与Go语言集成。 • Spooky23 使用 node exporter 到 Prometheus 和 Grafana 的组合，并通过 Uptime Kuma 和 Pushover 实现报警，强调其易于设置和实用性。 • JZL003 使用 Node Express 服务器结合多个免费监控服务进行监控，通过Promise.all管理状态，并利用免费监控服务发送邮件报警。 • frenchtoast8 在工作中使用 Datadog，但认为其对于家庭实验室过于昂贵，推荐 NewRelic 和 Grafana Cloud 的免费计划，但指出学习成本问题。 • loloquwowndueo 质疑 reboot81 的方案是否重新发明了 Monit，并提到 Prometheus + Alertmanager 的Docker容器化部署简单且稳定。 补充讨论： • 争议焦点之一是解决方案的复杂性和成本之间的平衡。例如，Jedd 和 frenchtoast8 强调了高成本工具如 Datadog 在家庭实验室中的不适用性，而 Evidlo 和 Havoc 则推荐了更廉价且易用的替代方案。 • 另一个讨论点是日志聚合和历史数据的重要性，Jedd 通过个人经历强调了这一点，而其他评论者如 Spooky23 则通过具体案例说明了监控系统的实际效益。 • 可扩展性和易用性也是重要讨论点，justusthane 提出的自定义Python程序和 Havoc 对 Uptime Kuma 的API批量操作的推荐都反映了这一点。 总体而言，讨论围绕监控工具的选择展开，涉及成本、功能、易用性和扩展性等多个方面。

Bypassing Google's big anti-adblock update

作者: deryilz | 评分: 960 | 评论数: 72 | 发布时间: 2025-07-12 19:06
文章摘要

本文介绍了作者如何发现Google Chrome在MV3更新中绕过广告拦截限制的漏洞。MV3更新取消了`webRequestBlocking`权限，导致广告拦截器无法正常工作。作者发现，尽管`chrome.webRequest` API在MV3中不再支持`blocking`功能，但由于JavaScript绑定实现的漏洞，可以通过伪造事件并利用`opt_webViewInstanceId`参数绕过权限检查，从而恢复广告拦截功能。该漏洞的根本原因在于Chrome对JavaScript绑定的处理不当，使得扩展程序能够绕过安全验证。作者在2023年报告了此漏洞，并认为这是他遇到的最有趣的漏洞之一。

MV3政策对广告拦截器的影响是争议的焦点，尤其是它对用户体验和开发者社区的影响。 3. 讨论中多次提到使用非Chrome浏览器（如Firefox和Brave）作为绕过Google政策的方法，并提供了具体的技术建议和链接。 4. 对广告内容的控制和Google的垄断地位是用户不满的主要来源，尤其是对YouTube广告的不满。 5. 用户对不同浏览器的PWA支持和隐私保护功能表现出关注，尤其是Firefox在这方面的不足被提及。

文章摘要

Axon Enterprise’s Draft One是一款生成式人工智能产品，用于根据警察随身摄像头音频自动撰写警察报告。电子前沿基金会（EFF）的调查发现，该技术缺乏透明度和问责机制，无法有效审计其使用情况。审查显示，报告中无法区分哪些部分由AI生成，哪些由警察撰写。尽管声称能革新警务，但该技术没有提供足够的数据来评估其对司法系统的影响。Draft One使用ChatGPT变体处理音频生成报告，但报告需警察编辑和确认。然而，编辑过程无记录保存，报告完成后草稿即消失，使得外界难以判断报告中的错误或偏见来源。这种设计缺乏透明度，可能掩盖AI或警察的责任，影响司法公正。
