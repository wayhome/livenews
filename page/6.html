OneDrive File Picker Flaw Provides Apps Full Read Access Entire OneDrive

作者: ano-ther | 评分: 10 | 评论数: 2 | 发布时间: 2025-06-01 20:31
文章摘要

微软的OneDrive文件选择器存在一个安全漏洞，导致网站可以访问用户的整个OneDrive内容，而不仅仅是用户选择上传的文件。该漏洞影响数百个应用程序，包括ChatGPT、Slack、Trello和ClickUp，可能导致数百万用户的OneDrive数据面临泄露风险。漏洞的原因包括OneDrive文件选择器请求过度的读取权限以及OAuth范围不精细，加上微软提示信息不明确，使用户容易意外授予全盘访问权限。敏感的访问令牌还可能被明文存储在浏览器中，增加风险。为减轻风险，用户应检查并撤销不必要的第三方应用访问权限，开发者应避免使用刷新令牌，并考虑使用更安全的文件共享方式。微软正考虑改进这一问题。

评论摘要
主要讨论点：OneDrive文件选择器的OAuth权限管理及安全问题 不同观点： • pawanjswal认为，到2025年OneDrive文件选择器仍然没有细粒度的OAuth权限范围，这是难以相信的。他指出，为了上传一个文件而允许对整个驱动器的读取权限，违反了最小权限原则。 • mchenier提出了一种避免此问题的方法，通过创建一个虚拟的OneDrive账户，并共享主账户中的一个文件夹给该虚拟账户，从而限制第三方应用只能够访问特定文件夹。这种方法可以显著减少攻击面，避免第三方应用访问整个主驱动器。 补充讨论： • pawanjswal关注的是权限的细粒度控制，认为应从技术设计上实现更精细的权限管理，以符合安全原则。 • mchenier的建议侧重于通过操作上的变通方法来解决权限过大的问题，这种方法虽然有效，但需要用户进行额外的账户和管理操作。 • 争议的焦点在于，用户是否应依赖变通方法来解决权限问题，还是应期待技术提供方（如OneDrive）从根本上改进权限管理系统。 这个讨论反映了用户在面对权限管理不足时的两种应对思路：一是期望产品改进以提供更安全的内置功能，二是通过外部操作技巧来弥补当前功能的不足。

Oniux: Kernel-level Tor isolation for any Linux app

作者: marcodiego | 评分: 153 | 评论数: 9 | 发布时间: 2025-05-31 20:46
文章摘要

**摘要：** 文章介绍了一款名为 **oniux** 的小型命令行工具，它通过 Linux 命名空间为任何 Linux 应用程序提供 Tor 网络隔离。oniux 使用内核提供的隔离功能，将应用程序置于独立的网络命名空间中，并通过自定义网络接口路由流量，确保数据不会泄露。与传统的 torsocks 相比，oniux 更安全，因为它不依赖于动态链接的 libc，且能防止恶意应用程序泄露数据。oniux 需要在 Linux 系统上安装 Rust 工具链，并通过克隆系统调用创建隔离的子进程。用户可以通过简单的命令行操作实现应用的 Tor 隔离，例如 `oniux curl https://example.com`。 **关键特性：** - 使用 Linux 命名空间实现隔离。 - 比 torsocks 更安全，防止数据泄露。 - 支持隔离整个 shell 和图形应用程序。 - 基于 Arti 和 onionmasq，用 Rust 编写。

文章主要讨论了AI模型在不同环境下的性能表现，特别是DeepSeek-V3这类模型在规模化服务时速度快且成本低，但在本地运行时却速度慢且成本高的问题。这主要源于**批量推理**（batch inference）的机制，以及**吞吐量**和**延迟**之间的权衡。 GPU擅长处理大规模矩阵乘法（GEMMs），一次处理大量数据比多次处理小数据效率更高。这是因为每次GPU操作都有一定的开销，且频繁的内存读取会降低效率。因此，推理服务器通常会将多个用户请求进行批量处理，以提高吞吐量，但这也增加了延迟。 对于像DeepSeek-V3这样的混合专家模型（mixture-of-experts），由于其结构包含多个子网络（专家），导致GPU计算效率低，必须依赖批量处理来提升实用性。这类模型在低批量情况下表现不佳，因此在本地运行时速度慢且成本高，而在规模化服务中通过批量处理能达到高吞吐量和较低成本。
