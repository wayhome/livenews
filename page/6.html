主要讨论点：[开源软件维护者的责任与用户期望之间的冲突] 不同观点： • [第一种观点]（foxrider和nevon）：开源项目维护者没有义务提供技术支持或持续维护，项目是“扔出来”供他人自由使用的。他们认为维护者有权选择不提供支持，尤其是当项目没有产生收入时。foxrider强调项目是为自己而做，nevon甚至建议明确声明项目无支持且不接受贡献。 - 论据：维护开源项目可能导致 burnout（nevon），用户应自行解决问题（foxrider）。 • [第二种观点]（j1elo）：问题的核心在于维护者未准备好应对用户的社会行为，而非开源本身的问题。他认为任何公开项目（如开源或免费赠送）都会遇到“ entitled”用户，维护者需提前做好心理准备并设定明确边界。 - 论例：建议在 README 中明确项目状态（如 Valetudo 的“This project is a garden”），类比免费雨伞发放中的冲突。 • [第三种观点]（metasim）：开源的本质是自由，维护者无需承担维护责任，其他人可以自行接管。 - 论据：开源许可允许他人 fork 或维护。 补充讨论： - 争议焦点：维护者是否应承担用户支持的责任，以及如何平衡个人精力与社区期望。 - j1elo 的观点与其他两人形成对比，强调社会行为准备而非责任豁免。 - metasim 从开源许可的角度补充，淡化维护者的强制性角色。
