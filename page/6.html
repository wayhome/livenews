Rocksky 是一个基于 AT Protocol 的去中心化音乐记录与发现平台。它支持 Last.fm、ListenBrainz 兼容的 scrobbling API，可记录播放历史、展示实时动态、统计每日收听数据，并提供热门艺人、曲目、专辑等个人榜单。平台集成 Spotify、Jellyfin、Pano Scrobbler、WebScrobbler，支持 MeiliSearch 搜索。项目主要使用 TypeScript 和 Rust 开发，未来计划加入 Webhooks、个性化推荐、Last.fm 同步、远程播放、自建音乐库播放等功能。

评论摘要
主要讨论点：围绕一个基于 AT Protocol 的音乐发现/Scrobbling 服务，讨论其隐私、推荐能力、API/认证、迁移门槛与生态支持。 不同观点： • 隐私担忧：有人认为 Last.fm 的公开收听时间会暴露自己何时在电脑前，希望提供“打乱/偏移 scrobble 时间”的选项；自托管可能更安全，但也希望兼顾公共平台体验。 • 看好产品潜力：多位评论者称赞项目有趣、很酷，认为 Last.fm 曾带来优秀音乐发现体验，若该项目能改进社交音乐平台和推荐模型，有机会做大。 • 推荐系统是关键：有人指出 Last.fm 的核心价值在推荐模型，询问该项目使用什么推荐算法、是否有 AI；争议焦点在于它能否达到 Last.fm 的推荐质量。 • API 与认证摩擦：开发者反馈已集成到播放器，但 v1 API 有限，v2 API 和文档尤其是认证体验仍需改进；也有人询问是否需要用户手动获取 Rocksky API key，缺少类似“Sign in with Bluesky”的 OAuth 流程可能影响 iOS 原生应用体验。 • 迁移与兼容性：有评论认为能否导入 Last.fm 历史、继续使用现有 scrobbling 客户端，是用户迁移的关键；另有人希望 Plex/PlexAmp 未来支持。 • 与现有平台关系：开发者比较 Last.fm、ListenBrainz 与该服务的集成方式，关注 API key、token、端点兼容性；有人好奇 scrobbling 如今是否还能吸引新用户，还是主要服务老用户。 补充讨论：部分评论是轻松吐槽，如把 AT Protocol 误解成 GSM modem 的 AT Commands，或调侃服务名像斯拉夫姓氏；也有人直接询问“发现的新音乐要在哪里听”。
