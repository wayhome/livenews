Wttr: Console-oriented weather forecast service

作者: saikatsg | 评分: 129 | 评论数: 23 | 发布时间: 2025-07-17 06:05
文章摘要

**wttr.in** 是一个面向控制台的天气预报服务，支持多种信息表示方式，如终端使用的ANSI序列、网页的HTML以及图形查看器的PNG格式。该项目最初是一个展示控制台服务力量的小型项目，现已发展为每日处理数千万次查询的流行服务。 使用方法： 1. 通过`curl wttr.in`获取当前位置天气，如`curl wttr.in/London`。 2. 使用三字母机场代码查询机场天气，如`curl wttr.in/muc`。 3. 查询特殊地理位置，如`curl wttr.in/~Eiffel+Tower`。 4. 通过IP地址或域名查询，如`curl wttr.in/@github.com`。 支持的输出格式包括ANSI、纯文本、HTML、PNG和JSON。可通过URL参数自定义单位和语言，如`curl wttr.in/Amsterdam?u`用于美制单位，`curl wttr.in/Amsterdam?m`用于公制单位。PNG格式可通过`_`连接参数，如`wget wttr.in/Paris_0tqp_lang=fr.png`。 详细帮助可通过`curl wttr.in/:help`查看。

评论摘要
主要讨论点：围绕wttr.in这一天气预报服务的功能、优缺点及技术问题的讨论。 不同观点： • **功能赞赏**： - [Duanemclemore]: 认为这是一个很酷的想法，并将其与历史上的CEEFAX进行类比，强调其在终端中展示天气信息的独特性。 - [yoavm]: 提到基于wttr.in的wttrbar工具，强调其在Waybar中展示详细天气信息的实用性。 - [krylon]: 提到Emacs中也有使用wttr.in的包，认为这是值得赞赏的服务。 - [chrismatheson]: 表达了对该服务带来的愉悦体验的赞赏。 • **数据准确性问题**： - [Langdal]: 指出该服务对某些城市（如Trondheim, Norway）的天气预报不准确，与当地国家气象预报服务的数据存在较大差异。 - [voidUpdate]: 提到不同视图（normal view, v2, ?format）下的天气数据不一致，认为正常视图更接近实际天气。 • **技术实现与用户体验问题**： - [rollcat]: 批评wttr.in在文本文件中输出ANSI控制代码，建议至少应使用isatty函数判断输出是否为终端，并提出终端技术应被更现代的REPL和轻量级GUI工具取代。 - [jagrsw]: 提出终端打印任意输出可能带来的安全风险，特别是控制字符和转义序列的处理，指出即使是xterm也存在安全漏洞。 - [pvdebbe]: 提到时间 zones 的问题，指出服务在处理用户所在时区时存在UX上的问题。 • **服务实现与商业化建议**： - [edarchis]: 提到该服务因访问量过大导致经常超出API配额的问题，建议推出付费版本以支持服务运行。 - [mixcocam]: 同样担心该服务的性能问题，担心高流量会带来高昂的费用。 • **其他功能问题**： - [hliyan]: 期望更直观的用户体验，如直接查询某城市某时段的天气，而非当前的文本输出形式。 - [PhilippGille]: 指出三字代码机场标识符查询功能存在问题，因为同名城市优先于机场查询。 补充讨论： • 争议的焦点主要集中在wttr.in的数据准确性和技术实现问题上，部分用户对其预报准确性、API配额以及终端输出控制代码的处理方式提出质疑。 • 用户对服务的技术细节、用户体验优化和商业化可能性也提出了建议，显示出对该服务未来发展的关注。

Molecule produced by gut bacteria causes atherosclerosis

作者: raphar | 评分: 91 | 评论数: 12 | 发布时间: 2025-07-17 16:21
文章摘要

西班牙科学家团队15年前宣布了一项长期研究计划，旨在深入研究马德里桑坦德银行员工的心血管疾病起因。研究发现，肠道细菌产生的一种分子——咪唑丙酸（C₆H₈N₂O₂）——不仅诱发而且导致动脉粥样硬化，即脂肪和胆固醇在动脉中的积累，可能引发心脏病和中风。这一发现揭示了微生物与心血管疾病之间的因果关系，表明该疾病不仅由脂肪引起，还涉及炎症和自身免疫反应。研究人员还发现了一种可以阻断咪唑丙酸作用的药物，成功减缓了实验鼠的动脉粥样硬化进展。该研究发表在《自然》期刊上，为心血管疾病的早期诊断和治疗提供了新方向。

评论摘要
主要讨论点：Imidazole propionate (ImP) 与动脉粥样硬化等疾病的关系，以及饮食与肠道菌群对健康的影响。 不同观点： • **nextos**：认为当前研究的价值在于通过实验证明了ImP对动脉粥样硬化的因果关系，但媒体夸大了其新颖性。因为ImP与其他肠道菌群代谢物已被证实与糖尿病、心衰和动脉粥样硬化有关。 • **BruceEel**：指出富含蔬菜、水果、全谷物、鱼类、茶和低脂乳制品饮食的人血液中ImP水平较低，认为这是令人鼓舞的发现。 • **pretzellogician**：强调越来越多的“生活方式疾病”被归因于生物因素而非个人选择和意志力，并列举了如溃疡和动脉粥样硬化的例子，认为生活方式的影响程度值得讨论。 • **tmaly**：质疑饮食对肠道微生物的影响程度。 • **elektor**：提到西班牙科学家发起的长期研究项目，并询问美国是否有类似项目可以参与。 • **searine**：指出该研究主要由欧盟资助，美国国立卫生研究院（NIH）和桑坦德银行有少量贡献。 • **wslh**：提供原始研究的链接，供进一步阅读。 • **epicureanideal**：认为发现ImP与动脉粥样硬化的关系可能是增加健康寿命的重要进展，是迈向长寿的关键一步。 • **ck2**：提到本以为讨论的是三甲胺N-氧化物（TMAO），并提供相关研究的链接，指出营养学研究的复杂性。 • **lkuty**：质疑研究如何与食肉饮食（高脂肪、高胆固醇）相协调，并提到托马斯·考恩关于结构化水和排除区的理论，认为营养是一个复杂的问题。 补充讨论： • 评论中涉及多个相关研究和资源链接，提供了进一步阅读和研究的线索。 • 争议的焦点包括ImP新发现的实际新颖性、饮食对肠道微生物及健康的影响程度，以及不同饮食模式（如食肉饮食）与动脉粥样硬化之间的关系。 • 研究资助来源和普通公众参与科学研究的渠道也被提及，显示出对这些方面关注。

Running TypeScript Natively in Node.js

作者: jauco | 评分: 45 | 评论数: 6 | 发布时间: 2025-07-17 20:41
文章摘要

本文介绍了从Node.js v22.6.0开始，通过使用`--experimental-strip-types`标志，可以直接运行包含可擦除类型注释的TypeScript代码，而无需事先转译。从v22.7.0起，通过`--experimental-transform-types`标志，还支持处理如`enum`和`namespace`等TypeScript特有语法。从v23.6.0起，类型剥离功能默认启用，可以直接运行支持的TypeScript代码。不过，对于需要转换的代码，仍需使用`--experimental-transform-types`标志。未来版本的Node.js计划无需命令行标志直接支持TypeScript。当前的实验性支持有一些局限性，建议查阅API文档以获取更多信息，并使用TypeScript 5.7或更高版本以配合Node.js行为。

评论摘要
主要讨论点：Node.js 与 Deno 以及 TypeScript 相关的工具和生态选择 不同观点： • **Steve_Adams_86** 认为 Deno 具有吸引力，因为其低开销、合理的默认设置以及便携式二进制文件的构建能力。尽管 Deno 有时会有兼容性问题，但 Node.js 的主要优势在于其成熟的生态系统和兼容性。他个人更喜欢 Go 语言，但为了团队协作，还是会选择大家都熟悉的语言。 • **Normal_Gaussian** 支持使用 Node.js，尤其强调了 Node.js 中 `node:test` 的改进以及结合 esbuild 构建管道，可以减少对测试框架的依赖，从而使项目测试运行更快且依赖更少。他提到需要对类型导入进行注解并使用文件扩展名，但整体上对当前 Node.js 的工作方式表示满意。 • **Jadbox** 对 Node.js 团队决定构建自己的类型剥离器而不是直接使用 `tsc` 或 `swc` 表示质疑。他认为这可能会导致 Node.js 在 TypeScript 添加新类型构造时出现延迟修复的 bug，从而影响项目稳定性。 • **Russellbeattie** 对 TypeScript 持批评态度，认为微软和 TypeScript 爱好者应该将其发展为独立的编程语言，而不是继续在 JavaScript 生态中扩展。他建议 TypeScript 可以像 C++ 对 C 那样，成为 JavaScript 的超集，这样可以避免转译问题，并且如果需要在浏览器中运行，可以打包成 WebAssembly。 补充讨论： • **Gabrielsroka** 提供了一个6个月前的相关讨论链接（https://news.ycombinator.com/item?id=42630790），可能用于参考当时社区对类似问题的看法。 • **ChrisArchitect** 提供了一个今年1月发布的 Node.js 版本更新日志链接（https://nodejs.org/en/blog/release/v23.6.0），为讨论提供了更新的背景信息。 争议焦点： • Node.js 和 Deno 的选择：Steve_Adams_86 更倾向于 Deno，而 Normal_Gaussian 则支持 Node.js，二者基于不同的需求和体验得出结论。 • TypeScript 在 JavaScript 生态中的角色：Russellbeattie 对 TypeScript 作为 JavaScript 生态的一部分持否定态度，认为应独立发展，而 Jadbox 则关心 Node.js 对 TypeScript 新特性的支持速度和稳定性。
