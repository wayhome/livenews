New Rule Forbids Gnome Shell Extensions Made Using AI Generated Code

作者: turrini | 评分: 9 | 评论数: 0 | 发布时间: 2025-12-14 00:54
文章摘要

GNOME.org宣布新规，禁止托管使用AI生成的GNOME Shell扩展代码。新指南规定，虽然允许开发者使用AI作为学习工具或代码补全，但提交的扩展必须由人工编写，开发者需能合理解释代码逻辑。包含大量冗余代码、风格不一致或明显AI生成特征的提交将被拒绝。此举源于近期AI生成扩展数量激增，影响了扩展库质量。不过用户仍可在本地使用AI生成的扩展。GNOME同时公布了其他非AI相关扩展更新。

这篇文章回顾了50年来证明助手（proof assistants）的发展历程，重点讨论了学术和政府在计算机技术进步中的作用，驳斥了“科学停滞”的论调。文章从1975年的Edinburgh LCF开始，介绍了其核心设计原则（如自然演绎推理规则、目标导向证明）及其局限性。随后提到作者参与的Cambridge LCF项目，虽然未流行但为后续系统（如HOL88）奠定了基础。文章还指出早期系统缺乏数学表达能力，并提到硬件验证的突破。全文强调了学术研究对计算领域进步的关键贡献。

评论摘要
主要讨论点：[科技进步与停滞的感知] 不同观点： • PaulHoule认为在基础物理领域50年来没有显著进展，但在生物学、化学和符号AI领域有明显进步，例如金属有机框架、RNA结构预测和SAT/SMT求解器的工业应用。 • Animats提到浮点运算验证的历史案例，强调形式验证在硬件设计中的重要性，并指出AMD通过形式验证避免了类似Intel的FDIV错误。 • juliangamble强调了Nada Amin在程序验证和多阶段编程方面的工作，特别是Dafny和VerMCTS等工具的应用。 • mnky9800n从社会和政治角度分析了“停滞感”的来源，认为这种感知更多是由于政治僵局、注意力经济和社会文化因素，而非实际技术进步不足。 补充讨论： • Agingcoder和hamiecod分别提到了对形式验证编译器（如Cakeml）和系统规范（如TLA+）的兴趣，显示了对形式方法在不同领域应用的关注。 • polskibus和ratmice讨论了Lean4在数学和AI中的流行，以及LCF（Logic for Computable Functions）的历史意义。 • adyashakti提到了Advaita Vedānta的形式化验证，展示了形式方法在非传统领域的应用潜力。 争议焦点： • 实际技术进步与社会感知的“停滞感”之间的差异，特别是在基础物理与其他科学领域的不同表现。 • 形式验证在不同领域（如硬件设计、程序验证、哲学）的应用和重要性。
