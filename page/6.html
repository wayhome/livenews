Technical issues of separation in function cells and value cells (1988)

作者: Jtsummers | 评分: 10 | 评论数: 1 | 发布时间: 2025-08-05 18:13
文章摘要

这篇文章讨论了Common Lisp中函数和值的分离技术问题。背景是1981年Common Lisp社区借鉴了Scheme的一些理念，但未采用其函数和值共用一个命名空间的方案。1986年，部分欧洲Lisp社区成员建议Common Lisp引入这一范式，引发了争议。文章详细解释了相关技术术语，如函数、标识符、符号、变量、绑定、词法变量和特殊变量等。文章重点讨论了两个命名空间：值命名空间和函数命名空间。值命名空间用于关联变量和其值，而函数命名空间用于关联变量和函数。Lisp的评估规则需要根据环境和命名空间来解释标识符的意义，以确定如何计算表达式。文章旨在澄清这些技术问题，以便在做出任何改变决定前提供清晰的文档。

评论摘要
主要讨论点：Lisp 1.5中函数名和变量名的区别以及设计者的意图。 不同观点： • 第一种观点：设计者认为函数名和变量名是不同的，函数名被视为符号的属性。Lisp 1.5解释器首先查看命名原子符号的属性列表，因此可以认为函数是符号的一个属性。设计者使用了“stands for”来描述符号与函数的关系，而“refers to”来描述变量与值的关系。 补充讨论： • 这一观点强调了Lisp 1.5设计中对函数和变量的区分，可能暗示了设计者在语言设计时的哲学或技术选择。 • 可以进一步探讨这种区分是否在现代Lisp实现中仍然存在，或者是否已经被其他设计选择所替代。

Little-known leguminous plant can increase beef production by 60% (2022)

作者: littlexsparkee | 评分: 65 | 评论数: 9 | 发布时间: 2025-08-08 23:20
文章摘要

一项为期四年的研究发现，一种鲜为人知的豆科植物**卵叶 Desmodium**（Desmodium ovalifolium）可以显著提高牛肉生产效率。在与**布拉奇亚草**（Brachiaria brizantha）混种的情况下，该植物能使放牧牛的体重增加60%，并将屠宰时间缩短30%，从而降低农民成本和温室气体排放。这种豆科植物能改善牛的消化，减少甲烷排放，还能替代每年每公顷150公斤的氮肥，减少一氧化二氮排放。此外，它能在牧场中持续存在九年以上，无需频繁更新，降低了种子的成本和劳动投入。该研究已发表在《Grass & Forage Science》期刊上。

Json2dir: a JSON-to-directory converter, a fast alternative to home-manager

作者: alurm | 评分: 42 | 评论数: 7 | 发布时间: 2025-08-08 18:46
文章摘要

`json2dir` 是一个将 JSON 转换为目录结构的工具，能够快速管理 dotfiles，是 home-manager 的替代方案。它通过解析 JSON 文件来创建目录、文件、符号链接和可执行脚本。对象表示目录，字符串表示文件内容，数组可以表示符号链接或可执行文件。使用时需注意 JSON 的 UTF-8 编码限制，以及在创建文件时防范 TOCTOU 攻击。该项目使用 Nix 和 Rust 构建，提供了 flake.nix 用于打包，并可在 json2dir.cachix.org 使用 Nix 缓存。项目文件包括构建脚本和示例配置等。

评论摘要
主要讨论点：围绕 json2dir 项目及其相关技术实现的优缺点讨论 不同观点： • [tadfisher] 认为 NixOS 及其相关工具（如 home-manager）通过激活脚本在文件系统中散布配置文件，破坏了配置的原子性，增加了出错机会。他主张使用包装脚本和程序命名空间技术（如 bwrap）来避免这些问题，但承认共享库是该方法的弱点。 • [bapak] 提出了一种跨平台的命令序列方案，直接使用 shell 命令（如 echo, mkdir, ln 等）来实现配置文件的管理，而不是使用 JSON 格式。 • [thayne] 反对使用 JSON 作为配置语言，指出 JSON 不支持注释和多行字符串，这使得脚本编写和维护变得困难。 • [Rucadi] 支持通过覆盖或修补软件包本身来处理配置文件（dotfiles），认为这样可以更好地控制配置，并便于在不同机器上迁移应用。 • [netsharc] 倾向于使用传统的 shell 命令（如 echo, cat, ln, mkdir 等）来实现配置管理，而不是引入新的工具或格式。 • [mdtrooper] 提出了 dir2json 的可能性，即反向将目录结构转换为 JSON 格式，但没有进一步展开讨论。 • [jauntywundrkind] 分享了一个通过 JavaScript 代理项目来自动持久化更改的方案，强调了可视化和可脚本化状态的优势。他还认为使用层次文件系统来存储数据比使用复杂的 JSON 格式更好，支持更直观的终端用户编程。 补充讨论： • 争议的焦点主要集中在 JSON 作为配置语言的适用性，特别是在可读性（注释和多行字符串支持）和操作便利性方面。 • 另一个讨论点是关于如何有效管理配置文件和目录结构，包括使用包装脚本、命名空间技术、shell 命令，以及直接修补软件包等不同方法的优缺点。 • 有些参与者（如 [jauntywundrkind]）还提出了对更直观的文件系统使用和终端用户编程的期望，认为当前依赖复杂数据格式的做法可能并不理想。
