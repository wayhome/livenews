I told them forced consent was unlawful. 5 years later it cost Elkjop €1.8M

文章摘要

这篇文章讲述了一起GDPR违规案件：2021年，作者发现北欧零售商Elkjop的会员俱乐部强制会员接受营销邮件，要退订就必须取消会员资格。这违反了GDPR第21条关于直接营销的绝对拒绝权，以及第7条关于自由同意的规定——同意不能与其他服务捆绑。作者向瑞典数据保护机构投诉，案件后转至挪威监管机构Datatilsynet。2026年6月，Datatilsynet对Elkjop处以2000万挪威克朗（约180万欧元）罚款，认定其同意无效、未充分告知用户，且未经评估就将会员数据用于广告和转化追踪等其他目的。

评论摘要
主要讨论点：围绕挪威数据保护机构对企业“以加入会员换取营销资格”做法的处罚，讨论隐私权执行、监管效率、法律理解及欧美权利环境差异。 不同观点： • 支持维权与处罚：不少评论认为结果“很爽”“应当如此”，赞赏当事人对“要么接受要么放弃”的企业做法强硬追责，也认可GDPR和欧洲隐私法的保护力度。 • 赞赏监管但批评效率：有人结合对挪威DPA的印象，称其立场一向偏向用户、裁决质量好；但多位评论指出流程太慢，5年才出结果，且监管机构未按GDPR第77(2)条持续告知投诉人进展，也是明显问题。 • 质疑案件表述/技术细节：有评论不理解争议句子的逻辑，认为“想收营销必须入会”和“入会必须同意接收营销”并不完全等同，怀疑存在措辞或翻译偏差；也有人讽刺文章像“法条技术性胜利”的迷恋。 • 延伸到更广泛滥用场景：有人提到招聘场景中企业强迫候选人接受“反隐私政策”，授权公司及第三方任意使用数据、声音和图像，认为类似问题同样值得被追究。 • 欧美对比与现实无力感：部分评论感叹美国缺少类似权利保障，日常坚持读文件、主张权利反而会“惹人烦”并处于劣势；也有人希望英国ICO能像挪威一样执法。 补充讨论：争议焦点主要在两点——企业是否把法定权利变成“入场费”，以及监管机构虽最终重罚，但是否也失职于信息告知与处理时效。另有人关心罚款是否足以覆盖企业5年来的获利。

Microsoft new Outlook takes 10 seconds to do what Outlook Classic does instantly

作者: Adam-Hincu | 评分: 380 | 评论数: 70 | 发布时间: 2026-06-18 12:19
文章摘要

微软新版Outlook存在严重的通知响应问题。点击Windows 11的邮件通知后，新Outlook需要约10秒才能显示对应邮件，而经典版Outlook几乎即时打开。更荒谬的是，直接打开Outlook应用手动查找邮件只需5秒。 问题根源在于新Outlook基于WebView2构建，本质上是个浏览器窗口加载Outlook.com。它在任务管理器中运行10个独立进程，每次交互都需要初始化web层、认证和渲染。虽然新Outlook的冷启动速度已接近经典版，但通知响应的性能差距暴露了web架构的局限性。微软已推迟企业强制迁移至2027年3月，显示该应用尚未完全就绪。

评论摘要
主要讨论点：微软Outlook及Windows应用性能严重退化，尽管硬件性能大幅提升，软件反而变得更慢更臃肿。 不同观点： • **技术架构问题派**：新Outlook基于WebView2导致性能差，加载顺序错误、渲染冗余数据。对比Fastmail等Web邮件客户端证明Web技术本身不是问题，是实现质量差。过度依赖Web可移植性论证，引入大量非确定性延迟。 • **历史对比派**：Windows XP时代512MB内存+40GB硬盘就能流畅运行，现在8GB内存都不够。记事本启动需3-4秒，计算器加载都要等待。过去20+ Gbps SSD都无法弥补软件效率低下。引用"我的超能力是我老了，所以记得电脑曾经很快"。 • **组织文化归因派**：微软曾发明"dogfooding"并强制使用Exchange直到修复所有bug，现在质量控制缺失。90年代至2000年代初微软工程师水平远超今天。管理层为短期利益牺牲工程文化，对性能问题不在意（如员工建议"买英特尔股票，用户会升级电脑"）。 • **产品膨胀派**：成熟产品为保持收入被迫添加功能导致臃肿。安全合规标准也不断堆叠，忽视生产力和性能影响。 补充讨论：具体案例包括Yahoo-微软搜索合作中欧洲请求需经4次跨大西洋跳转导致1500ms延迟，微软工程师对此无动于衷；Teams新旧版本对比视频反而暴露新版启动需9秒；移动端打开通知先显示旧邮件，数秒后才切换到正确邮件。

Migrating from GNU Stow to Chezmoi

作者: speckx | 评分: 82 | 评论数: 21 | 发布时间: 2026-06-18 17:09
文章摘要

作者从GNU stow迁移到chezmoi来管理dotfiles配置文件。Stow使用符号链接方式，在多台设备上维护时容易出现冲突和同步问题。Chezmoi采用复制而非符号链接的方式，将配置文件存储在`~/.local/share/chezmoi`源目录中，通过`chezmoi add`添加文件、`chezmoi apply`应用更改。这种方式让配置变更更可控，避免了意外修改。作者用它管理三台Mac（工作MacBook Pro、个人MacBook Air和Mac Mini服务器）的shell配置、git配置、终端配置和AI代理技能文件等，通过模板和脚本实现跨设备的差异化配置。

评论摘要
主要讨论点：dotfiles（配置文件）管理工具的选择和使用体验 不同观点： • **GNU Stow 阵营**：认为 Stow 简单够用，但也承认其符号链接的双向特性存在问题——每次编辑都会直接写入 git 仓库。有用户通过精心设计文件结构（如将本地配置分离到不被追踪的文件）来规避这个问题，将双向特性视为功能而非缺陷。 • **Chezmoi 支持者**：认为 Chezmoi 是社区宠儿，功能强大（支持模板、按机器配置、秘密管理）。配合 mise 工具可以用 2-3 条命令快速配置新机器。但也有人觉得其模板和文件命名规范不够直观，工作流需要适应（常忘记先调用 `chezmoi edit`）。 • **Nix/Home Manager 进阶派**：认为 Chezmoi 只是过渡方案，最终应该升级到 Nix——"既然都爬到山顶附近了，为什么不登顶？"可以声明式管理跨平台（macOS/Linux）配置。 • **极简主义者**： - 自己手写 POSIX shell 脚本（6 年未变），追求完全理解和掌控 - 直接用 Git 仓库 + 符号链接 + Fossil，"低技术、低戏剧性" - 用 rsync 同步整个家目录，视笔记本文件为临时性 • **其他工具倡导者**：yadm（轻量简洁）、Syncthing（自动实时同步 git 目录）、Ansible（重建整个桌面环境） 补充讨论：社区对工具复杂度有分歧——有人认为 Git 仓库就够了（可能是对 git 不够熟悉），有人则认为需要更强大的功能；Atuin 也被提及但未详细讨论。

The room the economy can't see

文章摘要

这篇文章探讨了一个经济学看不见的价值问题。作者以斯德哥尔摩一个青少年游戏俱乐部为例，指出这类"第三空间"（非家非工作场所）正在消失。这些空间创造真实的社会价值——缓解孤独、建立社区联系，但无法通过市场盈利，因此只能依靠公共资助才能存在。文章认为，探访亲人、陪伴孩子、维系友谊等无偿活动同样在减少，因为工资是获取生活资源的唯一途径，人们被迫将时间投入有偿劳动。这种"劳动压力"导致了广泛的社会孤独问题。核心矛盾在于：许多有价值的社会活动因为无法商业化而被经济体系忽视。

评论摘要

Lore – Open source version control system designed for scalability

文章摘要

Lore是Epic Games维护的下一代开源版本控制系统，专为处理代码和大型二进制资产的项目（如游戏和娱乐）设计。它采用内容寻址存储和Merkle树架构，支持按需下载、数据去重和轻量级分支，可无缝扩展以适应大型团队和海量数据。系统提供CLI和多语言SDK（C/C++、C#、Rust、Go、Python、JavaScript），具有不可篡改的修订链保证数据完整性。Lore以MIT许可证完全开源，旨在通过社区协作构建未来的版本控制系统。

评论摘要
主要讨论点：Epic Games 开源的 Lore 版本控制系统，专为游戏开发设计，作为 Perforce 的竞争者 不同观点： • **支持者观点**：游戏开发需要专门工具处理大型二进制文件（纹理、3D模型、音频），Git 不适合这类场景。Lore 提供文件锁定、权限管理等关键功能，且有望获得 Unreal Engine 的一流支持，这是 Perforce 的核心优势。用户界面比 Git 更友好，输出信息更清晰易懂。 • **质疑者观点**：Epic 的工具历史记录不佳，代码质量存疑（"vibe-coding"产物）。版本控制系统需要 99%+ 的可靠性，而非 97%。项目可持续性存疑——Epic 可能随时放弃这个非核心业务，不像 Perforce 这样的专业公司有长期承诺。 • **技术对比**：已有成熟的数据版本控制系统（Pachyderm、LakeFS、Oxen 等），Lore 并非首创。Git LFS 虽是替代方案，但团队规模超过 3-4 人时，游戏开发者仍偏好 Perforce。PlasticSCM 曾是优秀竞品，但被 Unity 收购后管理不善。 补充讨论：桌面客户端仅提供二进制文件引发"开源"质疑；不支持完全本地/离线模式；AI 和游戏行业面临相似问题但缺乏跨领域交流；Lore 实际上已在 UEFN 中使用，并非全新项目。
