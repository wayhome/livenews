斯隆数字巡天(SDSS)发布第20版数据,黑洞映射器(BHM)项目取得重大突破。此次发布首次包含南半球光学光谱观测,共释放超过330万个光学光谱数据,覆盖50万个星系和150万颗恒星。 核心亮点是SPIDERS项目,结合SDSS光学光谱与eROSITA X射线巡天,为约20万个X射线源提供光学识别,成为史上最大规模的X射线源光谱追踪。研究发现,早期宇宙中快速增长的巨型黑洞比预期更普遍,且70-90%的超大质量黑洞增长发生在浓密尘埃遮蔽下。通过多时段观测,项目可直接测量不同红移处的黑洞质量,揭示黑洞在宇宙历史中的成长轨迹。

From One Seed to a Thousand Leaves – Merkle's Authentication Tree

作者: denismenace | 评分: 34 | 评论数: 2 | 发布时间: 2026-08-04 14:21
文章摘要

这篇文章介绍了数字签名的发展历史和Lamport-Diffie一次性签名方案的工作原理。 文章指出传统手写签名易被复制，而数字签名可以解决这个问题。1979年Merkle改进了Lamport-Diffie签名方案。其核心思想是：使用单向函数生成公私钥对，发送者为消息的每个比特位预先生成密钥对，签名时仅透露消息中为1的比特位对应的私钥。接收者通过单向函数验证这些私钥的真实性。 为防止接收者篡改消息(将1改为0)，方案要求在消息末尾附加补码，这样任何修改都需要透露额外的私钥,从而被检测出来。文章用Alice和Bob买卖股票的例子生动地解释了整个签名和验证过程。

评论摘要
主要讨论点：量子抗性签名方案在区块链中的实现与演进 不同观点： • **实践派观点**（socketcluster）：6年前在区块链项目中实现了有状态的Merkle-Lamport签名方案，认为相对简单可理解，但未采用SPHINCS+是因为复杂度高且当时缺乏良好实现。有状态签名的优势在于可以改变密码短语，实现钱包转让（如将DPoS delegate权益出售） • **技术演进观点**（Retr0id）：强调Merkle树不仅是区块链基础，更重要的是在量子安全领域的持续演进——从最初的Lamport签名到现在的SLH-DSA（SPHINCS+的NIST标准化版本），体现了该技术路线的标准化进程 补充讨论：两位讨论者实际上互补而非对立。第一位从工程实践角度说明了为何停在有状态方案，第二位则指出该技术路线已发展到标准化的无状态版本（SPHINCS+），暗示了技术成熟度的提升。核心共识是Lamport-Merkle体系在量子抗性密码学中的重要地位。

Making Postgres 300x faster for analytics: batching, operator fusion, and SIMD

文章摘要

pgrust 0.2 版本实现了显著的性能提升：在分析型查询基准测试 Clickbench 上比 Postgres 快 300 倍，甚至超过了 Clickhouse。文章指出，Postgres 诞生于磁盘 I/O 是主要瓶颈的年代，但现代硬件趋势（数据集可放入内存、NVMe 固态硬盘的普及）使 CPU 和内存速度成为新的性能关键。 通过一个简单的求和查询示例，文章展示了 Postgres 查询引擎的性能瓶颈：处理 5 亿行数据需要 20 秒，而等效的 Rust 代码仅需 358 毫秒，快了 55 倍。文章随后介绍了 Postgres 使用的 Volcano 模型查询引擎的工作原理，并暗示将通过批处理、算子融合和 SIMD 等优化技术来大幅提升性能。

评论摘要
主要讨论点：pgrust项目（Postgres的Rust重写版本）的可信度、技术价值和实用性 不同观点： • **作者立场**：强调正确性优先，通过形式化验证和模糊测试已证明1000+函数逻辑一致，甚至发现了Postgres本身约20个bug（如四叉树浮点舍入问题） • **信任质疑派**：认为即使技术更优，pgrust也难以被采用，因为缺乏Postgres官方团队的背书和长期可靠性保障 • **严厉批评派**：指出项目只有2个提交，第一个提交是150万行AI生成代码（提交信息为"hey claude, do a breakthrough"），批评作者缺乏诚实，用"我们"假装团队作业，"bus factor为1且不可信" • **技术怀疑派**：质疑项目必要性，认为已有更快的替代方案（如kdb）或混合方案（Postgres+ClickHouse），Postgres本身在其适用场景已足够优秀 • **实测反馈派**：有用户测试遇到错误和崩溃，认为"还没准备好"；另有人对窗口函数实现和具体技术细节（IO调度器、自适应规划）表示关注或担忧 补充讨论：核心争议在于项目的真实工程质量与宣传之间的巨大差距——声称"300倍性能提升"和严格验证，实际却是AI快速生成的代码，引发对HN内容质量下降的担忧。

新墨西哥州法院判决Meta公司支付5.67亿美元，用于设立基金应对其社交媒体平台对儿童心理健康造成的负面影响。这是今年3月里程碑式诉讼第二阶段的判决。此前，陪审团认定Meta故意伤害儿童心理健康并隐瞒平台上的儿童性剥削问题，判罚3.75亿美元。新判决使Meta总赔偿金额达到9.42亿美元。 款项将主要用于为新墨西哥州青少年提供治疗服务、预防教育和筛查服务。法院还要求Meta改进年龄验证机制、加强隐私保护、增设警示信息等。Meta表示不同意判决并计划上诉。尽管赔偿金额巨大，但相比Meta 2025年约600亿美元的年利润，这只占其中很小一部分。

主要讨论点：新墨西哥州法院判决 Meta 因社交媒体平台危害儿童心理健康支付 5.67 亿美元罚款，引发关于罚款力度、平台责任、政府监管合理性的多方争议。 不同观点： • **罚款力度评估存在分歧**：有人认为相对新墨西哥州 200 万人口和该州 Meta 约 15-20 亿美元的五年总收入，这笔罚款占其收入的一半到三分之二，实际是严厉的威慑；但也有人认为这对 Meta 全球业务来说只是"做生意的成本"。 • **平台成瘾性争议**：有用户分享亲身经历，认为 Instagram Reels 和 TikTok 如同"数字海洛因"，会让人无意识地浪费数小时；删除这些应用后睡眠和精神状态明显改善。 • **责任归属的哲学分歧**：核心争议在于这是 Meta 的设计责任，还是用户自控力问题。一方强调家长应承担监护责任，使用内容过滤服务而非依赖政府监管；另一方质疑这些平台给孩子带来什么实际益处。 • **法律先例的担忧**：有评论警告此判例可能削弱《通信规范法》第 230 条、言论自由和端到端加密保护。批评者认为，以"保护儿童"为名的法律可能被各州检察长滥用，切断 LGBTQ+ 青少年获取在线资源的渠道。有人甚至认为这是政府向科技公司施压使其配合官方宣传的手段。 补充讨论：评论中提到新墨西哥州自身在贫困人口心理健康治疗方面表现糟糕的讽刺；法律依据是该州公共妨害法；多数人预计此判决将经历漫长上诉过程。

Oracle bans AI-generated code from OpenJDK

作者: delduca | 评分: 510 | 评论数: 64 | 发布时间: 2026-08-07 17:36
文章摘要

Oracle宣布禁止向OpenJDK项目提交AI生成的代码,理由是存在安全性和知识产权风险。虽然开发者可以私下使用AI工具进行调试和代码审查,但不得在代码库、拉取请求等项目渠道中提交AI生成的内容。 这一政策与Oracle内部实践形成鲜明对比。联合创始人Larry Ellison近期曾宣称AI模型已在为Oracle编写代码,联席CEO Mike Sicilia也表示AI工具使小型工程团队能更快交付成果。 此外,Oracle今年在数据中心扩张上投资700亿美元,导致信用评级机构标准普尔因投资回报不确定性将其评级下调至BBB-,仅高于垃圾级一档。

评论摘要
主要讨论点：Oracle禁止向OpenJDK提交AI生成代码引发的多角度争议 不同观点： • **法律自保论**：Oracle需保留起诉他人AI洗代码的权利，接受AI贡献会削弱自身法律立场 • **质量与负担论**：AI代码增加审查压力，产生"vibe coding"、版权不清、bug责任不明等问题；成熟项目应优先稳定性而非快速迭代 • **双标质疑论**：Oracle高层力推AI、内部使用AI，却禁止开源贡献使用AI，被指虚伪和自相矛盾 • **务实辩护论**：这是零风险选择，内外部标准本就不同；Oracle无需为开源项目增加人力，选择规避所有潜在风险很合理 • **行业趋势论**：Rust等项目也采取类似政策，这是开源项目应对AI贡献的普遍做法 补充讨论：政策细节值得注意——禁止基于LLM的工具，但允许传统IDE的拼写检查和自动补全功能，边界定义模糊（如Cursor的tab补全是否算AI）；Oracle作为"带科技业务的律所"的戏谑定位反映社区对其动机的不信任。
