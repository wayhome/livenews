The FIPS 140-3 Go Cryptographic Module

作者: FiloSottile | 评分: 178 | 评论数: 11 | 发布时间: 2025-07-15 20:42
文章摘要

Go语言团队在Go 1.24版本中引入了原生FIPS 140-3支持，以解决在受监管环境中使用Go时的合规问题。新的FIPS 140-3验证的Go加密模块（v1.0.0）已集成到标准库中，使得Go程序能够轻松满足FIPS 140要求。该模块通过`GODEBUG`选项启用FIPS 140-3模式，自动使用NIST标准算法，并进行自检。此外，通过设置`GOFIPS140`环境变量，开发者可以构建基于旧版本验证模块的程序。该模块解决了以往非官方方案在安全性、开发体验和功能上的问题，且不影响跨平台编译性能。Go团队计划定期更新模块验证，以保持合规性并应对潜在漏洞。

cppyy: Automatic Python-C++ Bindings

作者: gjvc | 评分: 60 | 评论数: 7 | 发布时间: 2025-07-16 12:39
文章摘要

cppyy 是一个自动的 Python-C++ 绑定生成工具，能够在运行时实现 Python 与 C++ 的互调，支持跨语言调用、延迟加载、模板实例化、异常映射等功能。它基于 C++ 解释器 Cling，无需语言扩展或手写代码，支持大型 C++ 项目，并能无缝集成如 Boost 等复杂 C++ 库。cppyy 适用于 CPython 和 PyPy，具备高性能，支持 STL、回调和跨继承等特性，简化了 C++ 库在 Python 中的使用。通过预编译头文件和动态加载等技术，cppyy 可以处理包含大量类和代码的 C++ 项目。

评论摘要
主要讨论点：Cppyy 作为 Python 和 C++ 结合的工具，其功能、性能及实际应用的讨论。 不同观点： • [rich_sasha] 认为 Cppyy 类似于已经废弃的 scipy.weave，可以结合 C++ 和 Python。他关注 Cppyy 是否能替代 scipy.weave，尤其是性能方面是否能超越 Numba 和 Cython。他指出 Cppyy 通过 Cling 解释 C++ 而不是生成真正的二进制文件，并质疑其在 CPython3 上的性能表现。虽然找到了一些基准测试，但这些测试并没有直接对比 Python 实现。 • [ashvardanian] 提供了一个使用 Cppyy 的实际用例，展示如何通过 Cppyy 结合 C++ 内核与 Python 进行实验，还提到了 Numba 和 PeachPy 等其他工具，展示了 Cppyy 在实际项目中的应用场景。 • [f1shy] 提出了 Cppyy 与 LLM（大型语言模型）在“AI 编程”中的对比，表示自己在使用 Cppyy 时得到了不错的效果，询问其他人的使用体验。 • [dang] 提供了一个相关的讨论链接，指向 2019 年关于 Cppyy 的讨论，引导读者参考之前的讨论内容。 • [actinium226] 关注实际应用中的分发问题，担心如果在项目中使用 Cppyy 并打包成 pip 包，用户是否需要自行安装 C++ 编译器，或者 Cppyy 是否自带编译器。 • [wslh] 推荐了 SWIG 作为另一种支持多种编程语言的绑定工具，暗示 SWIG 可能是 Cppyy 的一种替代方案。 补充讨论： • [bogeholm] 对项目名称进行了幽默评论，没有涉及技术讨论。 争议焦点： • Cppyy 是否真正能替代 scipy.weave，尤其是在性能和实用性方面。 • Cppyy 在实际项目分发中的可行性，特别是对用户环境的要求。 基准测试和性能对比是讨论的核心，尤其是对 Cppyy 在 CPython3 上的性能表现缺乏明确的答案。
