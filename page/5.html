文章摘要

本文介绍了Tauri框架与Verso浏览器的实验性整合。Verso是一个基于Rust的Servo引擎的浏览器，旨在简化Servo复杂API的使用。通过新的自定义运行时**tauri-runtime-verso**，开发者可以轻松切换运行时并继续使用Tauri的功能。虽然目前该整合尚未如Tauri的其他后端那样强大，但已支持基本窗口操作、React框架、Tauri命令行接口等功能。未来计划包括发布预构建的Verso可执行文件、支持更多窗口特性、以及改进初始化脚本处理方式。该整合旨在降低使用Servo的门槛，并增强Tauri的功能和灵活性。示例代码和演示可参见相关GitHub仓库。

Show HN: JavaScript PubSub in 163 Bytes

作者: hmmokidk | 评分: 85 | 评论数: 15 | 发布时间: 2025-03-31 01:37
文章摘要

本文介绍了一个名为"pico-pubsub"的极小PubSub库，仅有149字节，零依赖。它通过使用EventTarget实现发布-订阅功能，提供简单的`pub`和`sub`函数用于发布事件和订阅事件，订阅者可以轻松取消订阅。该库比其他类似库如"nano-pubsub"和"tiny-pubsub"更小，分别只有194字节和401字节。文章还提供了使用示例和压缩方法，并邀请用户提出进一步优化建议。同时提到未来可能会增加TypeScript支持。

评论摘要
主要讨论点：关于一个小型 pub-sub 库的实现及其 API 设计的讨论，包括对使用 CustomEvent、代码简化、类型支持等方面的不同看法。 不同观点： • [sltkr] 认为当前的 API 设计有问题，不应该将 CustomEvent/EventTarget 的实现细节暴露给用户。每个回调都需要手动解包 CustomEvent 对象，增加了代码复杂性。相比之下，nano-pubsub 的实现更简洁，且支持类型。 • [arnorhs] 也不喜欢使用 CustomEvent，尤其是在互操作性方面存在问题。他提出了自己的实现，利用了泛型和 Set 数据结构，并提供了类型支持，避免了 CustomEvent 的使用。 • [zeroq] 提出了一个极简的 KV 存储实现，仅用 22 字节的代码展示了一种极简主义的设计思路。 • [thewisenerd] 分享了自己以前为避免 prop-drilling 而实现的 pub-sub 方案，并提供了 gist 链接供参考。 • [test1072] 建议通过动态调用字符串来减少字节数，进一步简化实现。 • [giancarlostoro] 提出了一个对比，询问为何不使用 BroadcastChannel，表明可能有其他更合适的通信机制。 • [pjc50] 指出这个 pub-sub 实现是应用于本地应用内的，类似于 C# 的 'event' 关键字。 • [nsonha] 质疑这种实现的必要性，认为如果仅仅是为了小而小，完全可以不用包装。 • [h1fra] 讽刺地回应了 [nsonha] 的评论，指出移除整个包确实能减小体积。 • [lerp-io] 甚至质疑这种代码片段是否应该作为一个包存在，暗示其实现过于简单。 • [blatantly] 提供了一个更加简化的 23 字节版本的实现，展示了进一步压缩代码的可能性。 • [tipiirai] 对使用 `new EventTarget()` 表示赞同，并计划在 Nue 项目中采用。 补充讨论： • 争议的焦点主要在于 API 设计的合理性，特别是使用 CustomEvent 是否合适。一部分开发者认为这种设计增加了不必要的复杂性，而另一部分开发者则提出了自己的简化方案或不同意见。 • 代码简化是一个重要讨论点，[zeroq]、[test1072]、[blatantly] 等人展示了极简实现的不同方式。 • 类型支持也是一个讨论要点，[arnorhs] 和 [sltkr] 都提到了类型在 pub-sub 实现中的重要性。 • 对 pub-sub 实现的必要性和实际应用场景也有一定讨论，[giancarlostoro] 和 [pjc50] 提出了不同的技术选择和应用场景。

Why F#?

作者: bozhidar | 评分: 156 | 评论数: 29 | 发布时间: 2025-04-01 12:34
文章摘要

本文介绍了作者在阔别.NET平台15年后，重新关注F#语言的经历和初步印象。F#是一种由微软开发的函数式编程语言，属于ML语言家族，具有简洁、高效、跨平台和开源的特点。它提供了轻量级语法、默认不可变性、类型推断、高阶函数、模式匹配和异步编程等功能。F#起源于微软研究院的“Caml.NET”项目，并在2005年发布了1.0版本，最新版本为2024年发布的F# 9.0。作者提到选择尝试F#的原因包括.NET的开源和可移植性、对F#相较OCaml优势的好奇以及对F#开发工具的兴趣。文章还通过代码示例展示了F#的基本语法和特性，如函数定义、条件表达式、循环、记录和区分联合等。总体而言，F#对熟悉OCaml、Haskell或Lisp的程序员来说较易上手，同时也为其他开发者提供了强大的功能和灵活性。

评论摘要
主要讨论点：F# 编程语言的优缺点及其在实际应用中的情况 不同观点： • **支持F#的观点**： - **功能强大且适合函数式编程思维**：raphinou 认为F# 非常适合函数式编程思维，相比 Haskell、Ocaml、Scala 更易上手，且拥有丰富的库和框架支持（如 FsHttp、Fli、WebSharper）。 - **独特的功能特性**：jonsagara 强调了F# 的类型提供器（type providers）在处理不同格式CSV文件时的优势，能够快速实现类型安全。 - **成功案例**：pimbrouwers 分享了他们的团队在6年前从C# 转到F# 的成功经验，认为F# 语言虽然难学，但值得投入，写出的程序更简洁、快速、健壮。 • **对F# 的批评和疑虑**： - **生态和就业机会有限**：rockyj 指出，尽管函数式编程语言（如F#、Elixir、Clojure）在技术上很有吸引力，但就业市场需求有限，尤其是在印度和部分欧洲地区，难以找到高薪工作。 - **学习曲线和平台依赖性**：7thaccount 提到，F# 对C# 的依赖使其学习难度加大，尤其是对不熟悉C# 的开发者。systems 进一步指出，F# 作为托管语言，需要一定的C# 基础，限制了其独立性。 - **C# 竞争**：twodave 认为，随着C# 不断引入F# 的优势特性（如模式匹配、记录类型等），F# 的独特优势正在减弱，使用C# 可能更为实际。 • **对F# 语法的不同看法**： - **语法特性**：lihaoyi 认为F# 的语法和IDE支持存在一些小问题（如管道操作符、数组查找语法），虽然语言本身不错，但与Scala相比，整体体验不够连贯。 - **对Lisp开发者的适应性**：a-french-anon 质疑F# 对Lisp开发者的吸引力，尤其是其对“中缀数学运算符”的依赖，而不是像Lisp那样使用函数调用语法。 • **其他值得注意的观点**： - **IDE和工具链问题**：raphinou 和 protonbob 提到F# 的工具链和IDE支持（如Visual Studio与VS Code）存在不足，尤其是编译速度和热重载问题。 - **学习建议和应用场景**：eknkc 对F# 表现出兴趣，询问学习建议和应用场景，特别是如何在已有.NET经验的基础上快速上手。 - **混合语言项目经验**：gwbas1c 询问了F# 和C# 在同一项目中的共存情况，包括各自的优势和实际使用中的成功或失败案例。 补充讨论： - **社区和管理问题**：raphinou 提到F# 社区虽然友好且乐于助人，但其管理方式显得过于企业化，如需要加入F# 软件基金会才能访问官方Slack频道。 - **个人情感因素**：nickpeterson 以幽默的方式表达了对F# 的强烈支持，认为反对者“已经没救了”。 总体而言，讨论围绕F# 的技术优势、学习难度、就业市场和工具支持展开，支持者和批评者都有各自的论据和实际经验支持其观点。

Tailscale Enterprise Plan 9 Support

作者: donatj | 评分: 5 | 评论数: 0 | 发布时间: 2025-04-02 01:30
文章摘要

Tailscale宣布为其Enterprise计划增加对Plan 9操作系统的支持。通过集成WireGuard技术，Plan 9用户可以实现全球范围的无缝、安全连接，如同在同一局域网内，且无需手动配置。该集成支持全局命名空间、无密码SSH连接、ACL配置以及Plan 9的原生IPv6支持。Tailscale对Plan 9的实现免费开放，并提供企业支持服务。现有用户可以通过多种方式获取和安装Tailscale，包括使用ftpfs或从CVS服务器获取源代码。Tailscale还提供了基于网页的模拟器和QEMU环境供评估。更多详情可访问tailscale.com/plan9。
