Dockerfmt: A Dockerfile Formatter

作者: spicypete | 评分: 124 | 评论数: 16 | 发布时间: 2025-04-09 01:21
文章摘要

`dockerfmt` 是一个现代化的 Dockerfile 格式化工具和解析器，基于 BuildKit 内部解析器构建。它提供命令行工具，用于检查和格式化 Dockerfile，支持设置缩进、添加尾部新行等。目前不支持 RUN 命令中的分号和组命令，也不处理长 JSON 命令的换行。该工具使用 `mvdan/sh` 格式化 Shell 命令，并支持简单的 heredocs 和内联注释。JS 绑定可在 `js` 目录中找到。该项目遵循 MIT 许可，用户可以通过 GitHub 贡献代码。

评论摘要
主要讨论点：Dockerfile 的格式化、工具支持、多阶段构建及替代工具 不同观点： • [grandempire] 认为一个真正的软件工程项目应该有大量的配置文件（dot files）来支持格式化、包管理、代码检查和持续集成，并质疑谁来格式化这些配置文件，暗示项目复杂度高且维护困难。 • [jensenbox] 对源代码中没有 Dockerfile 表示失望，认为 Dockerfile 的缺失使得试用项目变得困难，尤其希望通过 Docker 容器运行项目。 • [urxvtcd] 和 [nikeee] 支持在多阶段 Dockerfile 中通过缩进使结构更清晰，认为不这样做就像其他语言中不缩进函数体一样不合理。 • [travisgriggs] 以幽默的方式提出 Dockerfile 格式化工具的递归问题，认为随着选项增多，最终可能需要一个“格式化格式化工具”的工具。 • [xyst] 认为 Dockerfile 格式化工具应由项目自身提供，而不是第三方工具，并举例 Go 和 Rust 内置格式化工具，减少了关于“最佳实践”的无谓讨论。 • [QuarterDuplex] 提出是否可以分层组合 Dockerfile，区别于 Docker Compose，希望找到一种优雅的方式来组合不同 Docker 镜像的层次。 补充讨论： • [yjftsjthsd-h] 对 RUN 命令支持 `&&` 但不支持 `;` 提出疑问，认为这两种写法在逻辑上相似，不应该有区别。 • [mdaniel] 提到一个被删除的评论，暗示该产品缺乏 QA，并表达了对特定格式化工具的不满，认为自己的写法更符合习惯。 • [righthand] 提到使用 YAML LSP（语言服务器协议）来处理 Dockerfile 格式，指出其通过 schema.org 查找 Containerfile 格式。 • [PantaloonFlames] 提出一个侧重点，询问为什么继续使用 Dockerfile 而不是 Podman，暗示 Podman 可能是更好的替代方案。 争议焦点： • Dockerfile 是否应该有内置的格式化工具，还是依赖第三方工具。 • 多阶段 Dockerfile 的缩进和结构清晰性是否重要，以及是否应成为规范。 • RUN 命令中 `&&` 和 `;` 使用的区别是否合理。 • 是否有比 Dockerfile 更优的工具如 Podman。
