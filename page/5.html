Show HN: I built a Rust crate for running unsafe code safely

作者: braxxox | 评分: 101 | 评论数: 19 | 发布时间: 2025-04-06 13:28
文章摘要

`mem-isolate` 是一个 Rust crate，旨在通过使用 `fork()` 系统调用安全地运行不安全代码。它会在子进程中执行用户提供的函数，确保该函数不会影响父进程的内存状态，实现内存隔离。主要特点包括： 1. **内存纯净性**：即使函数存在内存泄漏或堆碎片化问题，也不会影响主进程。 2. **跨进程通信**：通过管道在父子进程间传递结果，使用序列化（如 `serde`）处理数据。 3. **性能开销**：每次调用引入约 1ms 延迟，适合对内存安全要求高的场景。 4. **系统支持**：仅支持 POSIX 系统（如 Linux, macOS），不支持 Windows 和 WebAssembly。 该工具适用于运行可能导致内存问题的代码，如 FFI 调用或不安全代码，通过隔离确保主程序的稳定性。

评论摘要
主要讨论点：Rust中的内存安全与隔离方法，尤其是在处理不安全代码时的技术和工具选择 不同观点： • woodruffw认为，"safe" Rust不仅仅意味着避免空间内存错误导致的崩溃，还包括空间和时间上的内存安全。仅仅检测那些不会导致异常退出的内存不安全行为是不够的。Rust的安全性比仅仅避免崩溃要强得多。 • nextaccountic提出了一种通过将不安全代码编译为WebAssembly然后再转换为C代码的方法，以实现内存安全。这种方法将原本未定义的行为转换为逻辑错误，避免了内存损坏问题，类似于Firefox中的做法。 • destroycom和Svetlitski指出，在多线程应用中使用fork()存在风险，特别是在fork和exec之间执行的代码需要是异步信号安全的，否则可能导致死锁或内存问题。 • pjmlp主张从一开始就设计多进程应用，使用操作系统IPC和沙箱API，而不是依赖即时的伪沙箱技术，后者可能带来自身的问题。 • wavemode质疑牺牲性能来运行不安全代码的必要性，认为如果可以接受这样的性能损失，那还不如直接使用带有垃圾回收机制的语言。 • djha-skin认为fork()在某些情况下可能成本过高，应谨慎使用这种技术。 • slashdev对需要使用这种复杂技术的情况表示好奇，想知道是哪些糟糕的库或代码导致这种需求。 • TheDong指出，这种方法可能会导致函数行为不符合预期，特别是涉及内部可变性的代码，可能导致不正确的结果。 • null_investor认为，这种技术仅在处理确实无法改进的不安全代码时有用，但频繁使用可能丧失Rust相对于Python或Ruby的性能优势。 • cryptonector建议在处理大内存集的进程时使用vfork()而不是fork()，以提高速度。 • dijit提到在Windows环境下调用Win32 API时面临的内存调试困难，并寻求适合的工具帮助。 • kelnos强调在多线程程序中使用fork()的危险性，建议在crate中添加明确警告。 • corank质疑这种方法是否适用于需要内存可变的代码，例如双向链表的实现。 • jesprenj对使用管道而非共享内存进行通信的原因表示疑问。 补充讨论： - 各种方法的性能权衡，包括fork()的成本与多进程设计的优劣。 - 针对不同操作系统（如Windows和Linux）的特定工具和调试方法。 - 对内存安全和代码纯度的不同需求及其对设计的影响。

1997 Albanian Civil Unrest

作者: vinnyglennon | 评分: 3 | 评论数: 0 | 发布时间: 2025-04-07 12:00
文章摘要

1997年阿尔巴尼亚内乱源于庞氏骗局（金字塔骗局）的崩溃，导致经济问题和民众大规模抗议。动乱始于1997年1月，民主党政府倒台，抗议者要求赔偿损失。2月起，示威活动升级，总理亚历山大·梅克西辞职，总统萨利·贝里沙宣布进入紧急状态。3月，巴什基姆·菲诺出任总理，但动乱持续，尤其在南部地区，叛军和犯罪团伙控制了局势。多国展开撤侨行动，联合国安理会授权7000人维和部队协助恢复秩序。至4月，多国部队发起“ Alba行动”，7月底恢复法治。内乱后，部分武器流入科索沃战争。此次事件常被描述为内战或无政府状态。
