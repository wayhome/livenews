文章摘要

Mado 是一个用 Rust 编写的高速 Markdown Linter，兼容 CommonMark 和 GitHub Flavored Markdown。它支持多数 markdownlint 规则，性能约比现有工具快 49–60 倍。可通过 Homebrew、Nix、Arch、Scoop、WinGet 或预编译二进制安装，也支持 GitHub Actions 集成。配置可使用本地或全局 `mado.toml`，项目提供测试、基准、性能分析和模糊测试等开发流程。

The occasional ECONNRESET

作者: zdw | 评分: 107 | 评论数: 8 | 发布时间: 2026-05-17 17:09
文章摘要

文章通过一个本机 TCP 客户端/服务器复现实验，分析客户端偶发 ECONNRESET。客户端若先发送少量数据再读，服务器发送 60 万字节后立即 close，tcpdump 显示服务器发出 RST；strace 表明程序无崩溃且 sendto 成功，问题源于 TCP 关闭与未读数据交互。

评论摘要
主要讨论点：TCP 连接在“有未读数据时关闭”为何要发 RST，而不是 FIN，以及旧式 FIN 关闭会带来什么问题。 不同观点： • 多数人认为 RST 是正确做法：当一方发送了数据但对方没读就 close，说明数据丢失，应通过 RST 告知对端，而不是走正常 FIN 四次挥手。 • 反对/疑问点主要在于“FIN 的坏处是什么”：评论给出的答案是，FIN 会让对端误以为数据已完整送达，导致协议状态混乱、等待更久，甚至出现 ECONNRESET、连接复用失败等异常。 • 有人补充经验例子：Windows NT 与某些 Unix 上曾出现一边读到 ECONNRESET、另一边行为不同；Go 服务里因关闭前没读完响应，HTTP/TCP 连接无法复用。 补充讨论： • 还有人引用 RFC 2525 和 Apache 的 lingering close 说明这是长期存在的 TCP 语义问题。 • 争议焦点其实不是“要不要 RST”，而是“发送 FIN 会不会更温和”；评论普遍认为不会，反而会掩盖数据丢失。

Illusions of understanding in the sciences

作者: sebg | 评分: 106 | 评论数: 17 | 发布时间: 2026-05-14 19:49
文章摘要

文章指出，科学家常误以为自己已深刻理解现象成因，但实际理解多为不完整的“理解幻觉”。数学模型和计算模拟因预测精确，更易强化因果错觉。作者以线性回归为例说明深层理解之难，并探讨这种幻觉如何影响实验设计、理论检验、推理、交流与教学。

评论摘要
主要讨论点：论文关于“科学家也会因模型预测成功而产生理解幻觉”的论断，引发了对预测、因果解释、科学模型与“真正理解”的讨论。 不同观点： • 支持/延展观点：有人认为科学本质上也是一种人类可用的心智模型；模型能预测不等于揭示真实因果结构，“所有模型都是错的，但有些有用”。真正理解应承认完美预测不可能，并明确可接受的信息损失。 • 批评论文贡献不足：有人认为文章跨统计、机器学习与科学哲学，但不够聚焦，原创性有限，更像综述，可能两边读者都不满意。 • 科学哲学批评：评论指出作者似乎忽视既有文献，重新发明轮子；应参考杜恒-奎因论题、欠/过度决定、最佳解释推理、古德曼悖论，以及波普尔、库恩、拉卡托斯等传统。 • 实用主义立场：有人认为这是过度思考。归纳、演绎都无法绝对证明新知识，但科学通过长期、多重观察收敛出有效因果理论；现代医学、工程等表明体系总体可行。 • 预测与理解的争议：一方认为更强预测力始终是好目标，且在信息论意义上预测能力编码了理解；另一方强调正确输出不等于理解，尤其类比到AI提示得到答案的现象。 • 文章表达问题：多名评论认为文章冗长、重复、缺少具体和近期案例；尤其在生物学中已有建立因果的规范方法，如科赫法则，论文未充分区分学科差异。 补充讨论：有人分享“学得越多越发现原理解很粗浅”的体验；也有人质疑文中辛普森悖论例子是否成立，并提出“模型是什么”本身也取决于抽象层级。

The Third Hard Problem

作者: surprisetalk | 评分: 152 | 评论数: 26 | 发布时间: 2026-05-14 13:00
文章摘要

文章提出“树映射”是继命名、缓存失效后的第三个难题：人类偏好用层级树组织信息，但现实中的思想、文件、代码等更像相互交织的网。将网强行嵌入树会带来失真与取舍，如文件分类、软件包布局和代码仓库组织中的矛盾。

评论摘要
主要讨论点：taxonomy/层级分类是否存在“唯一正确”的设计，以及层级、标签、扁平/图结构各自优劣。 不同观点： • 原帖认为“没有唯一真分类法”，层级树每层只能按一个维度切分；应先给每层写清rubric，让非专家也能稳定归类；若已有可用分类法，就别轻易重造轮子，优先用标签系统让多人各自叠加分类。 • 支持层级局限的观点：树本质是高维问题的降维/聚合，很多问题只能近似解决，别追求完美；接受“不精确但有用”。 • 另一派主张干脆去层级化：很多场景用扁平结构、标签、超文本或图更合适，尤其当单一树无法表达多重关系时；多重继承也是把DAG硬压成单一层级的痛点。 • 怀疑/批判层级者指出，层级会扩展成默认权威，渗入文件系统、权限、治理等场景，非层级能力常被迫“打补丁”；但图/关系模型虽更灵活，也带来精确定义、性能和一致性成本。 • 折中观点：层级仍有用，例如 dominator tree、问题分解、源码组织；但它更适合“组织/解释”，底层分析常已转为图或IR。 补充讨论：争议焦点在于“分类的唯一性”与“表达能力/可维护性”的权衡，以及标签、扁平结构、图结构能否替代树。

作者: cdrnsf | 评分: 81 | 评论数: 18 | 发布时间: 2026-05-18 01:39
文章摘要

两项研究显示，美国公众对AI普遍焦虑且不信任：专家较乐观，但民众担心失业、缺乏控制权，并不信任政府和企业监管。Gen Z虽高频使用AI，却担忧其影响批判性思维；清晰规则有助提升信任。

评论摘要
主要讨论点：围绕公众为何不信任AI、AI行业是否通过金钱影响监管，以及这种不信任是否源于更广泛的制度信任危机。 不同观点： • AI行业应为不信任负责：有人认为AI支持者拒绝“合理监管”，反而花钱支持不愿监管的政客，形成监管俘获；公众看到本地利益流向少数科技富豪，因此反感AI。 • 就业替代是核心恐惧：多条评论指出，AI的现实目标被理解为取代“有机员工”，一旦人们感到工作不安全，不信任会迅速升级。 • AI/科技公司本身不值得信任：有人认为“不信任不可信者”是理性表现；另有人把AI与Facebook、Twitter、Amazon、Google等平台近年变差联系起来，认为AI由同一批科技精英控制，所以遭抵触。 • 不信任并非AI独有：一条长评论认为，美国社会自20世纪60年代起整体退出并怀疑各类机构，涉及政府、媒体、警察、教师、宗教等；AI恐慌只是长期制度信任下降的一部分。例子包括《Bowling Alone》、阳光法案、国会委员会改革及其效率下降。 • 政治行动不足：有人认为如果公众真担心AI，应投票支持愿意监管的政党和政客。 补充讨论： • 有评论提醒文章日期为2025年4月8日，并称原帖可能有误导性。 • 也有人讽刺：尽管很多人不信任AI，但他们仍在使用它。
