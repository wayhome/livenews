Defeating Git Rigour Fatigue with Jujutsu

作者: ikesau | 评分: 93 | 评论数: 22 | 发布时间: 2026-05-24 18:39
文章摘要

这篇文章介绍了使用 Jujutsu 版本控制系统解决"Git 严谨疲劳"的技巧。 **核心问题：** 开发大功能时，很难保持提交历史整洁。实际开发中常产生混乱的提交序列，后续提交会覆盖早期工作。 **解决方案：** 先创建理想的空提交结构（按功能模块划分），然后将所有实际改动合并到一个"大杂烩"提交中，最后用 `jj squash -i` 交互式地将相关改动分拣到对应的空提交里。 **优势：** 比开发过程中维持严格提交规范更轻松，避免了 `jj absorb` 的误判和 `jj split` 的反复操作，最终状态保证无冲突。 **缺点：** 无法保证每个提交都能编译通过。

评论摘要
主要讨论点：Jujutsu (jj) 与 Git 的工作流对比，特别是关于提交历史管理和分支处理的不同方式 不同观点： • **反对 jj 的立场**：y1n0 认为 jj 的分支管理极其繁琐，在多人协作场景下需要手动维护分支指向正确的提交，这对于同时维护多个分支的工作流来说不可行。Git 的命名分支机制简单易用。 • **支持 jj 的立场**：nozzlegear 和 xyzsparetimexyz 等用户完全转向 jj，认为其工作流更符合人体工程学。特别是 `jj new` 创建新变更的方式更符合心智模型，`jj split` 等交互式工具比 `git add -p` 体验更好。 • **实用主义观点**：drdrey 表示已接受 squash PR 的做法，认为追求"完美提交"是浪费时间；jadar 使用 `git reset --soft` 在推送前重写历史；codemog 建议让 AI 代理处理 Git 操作。 • **工具辅助派**：singiamtel 指出 lazygit 已经很好地解决了 Git 的痛点，但 jj 的类似工具 lazyjj 还不够成熟；mcookly 提到 Magit 可能也能高效完成类似操作。 补充讨论：everybodyknows 强调每个提交都应该能编译通过，这是结构性标准；nextaccountic 希望 VCS 能同时保存真实历史和清理后的历史；关于 `jj absorb` 的智能程度存在技术细节讨论。

Childhood Computing

作者: blenderob | 评分: 232 | 评论数: 50 | 发布时间: 2026-05-24 12:07
文章摘要

作者回忆了自己90年代在小镇学校机房接触电脑的童年经历：用软盘启动老式IBM兼容机，在极少的上机时间里学习Logo、靠纸笔写程序并与同学“模拟开源”式分享代码，也接触了《Space Invaders》《Digger》《Grand Prix Circuit》等游戏。这些有限却深刻的体验，点燃了他对计算与编程持续数十年的热爱。

评论摘要
主要讨论点：早期个人电脑与编程启蒙经历，及其与当代儿童接触计算机方式的差异 不同观点： • 早期设备的“可探索性”最能激发兴趣：多人提到 C64、Tandy、DOS、老式网页源码、RPG Maker、Turbo Pascal 等，因能直接改代码、看即时反馈、甚至调磁带头/内存/IRQ，促成从“玩机器”到“学编程”。 • 基础原理越早理解越重要：有人强调一旦理解变量、BASIC、HTML 等基本概念，后续进步会很快，也更容易理解计算世界如何运作。 • 旧环境比现代平台更适合入门：支持者认为早期系统简单、抽象少、一步步可见；相比之下，现代 Python/JS、GNOME、图形库和当代软件栈“选项太多、封装太厚、限制太强”，削弱了掌控感与乐趣。 • 当代环境也有现实阻碍：有人把问题归因于商业和平台限制，如微软当年授权昂贵，导致孩子只能用 QBASIC、网页和 JS 曲线入门，而难以做 Windows 程序。 • 关于孩子是否应接触屏幕存在分歧：一派担心短视频社交媒体，但希望孩子接触 Apple II、树莓派模拟器、老游戏等“低干扰”计算环境；另一派则对“反屏幕”风潮感到矛盾。 补充讨论：争议焦点在于“今天的计算机是否比过去更不利于培养创造性探索”。怀旧不仅是情感，也包含具体论据：即时反馈、低门槛修改、对系统细节的可见性，更容易让人从消费者转为创造者。

文章摘要

《Mastering Dyalog APL》是学习 Dyalog APL 编程语言的权威书籍。第一版出版于2009年，由 Bernard Legrand 编写。由于技术快速发展，该书正在更新中。新版本由 Rodrigo Girão Serrão 改编，基于 Jupyter Notebooks 制作，提供在线交互式学习体验和静态网页版本，未来还将推出纸质版。新版在保留原书内容基础上进行了更新和扩充，增加了2009年后 Dyalog APL 的新特性。目前在线版本仍在完善中，欢迎通过 GitHub 或邮件反馈意见。

评论摘要
主要讨论点：关于APL编程语言的学习价值、商业模式和实用性的讨论 不同观点： • **批评APL的实用性**（gobdovan）：认为APL过于小众，主要实现需要企业授权而非开源。APL的简洁性更像是"折磨线性代数运算符的智力游戏"，效率往往不高。推荐TLA+作为更好的替代品，能真正帮助清晰思考而非解谜。用素数生成器例子说明APL代码虽简洁但算法低效（O(N²)而非埃拉托色尼筛法）。 • **肯定APL的学习价值**（raghavchamadiya, meken）：认为交互式Jupyter笔记本形式降低了学习门槛，符号记忆是主要挑战。有人通过LLM辅助和在线编程题库（Kattis）学习APL，认为这种方式能提供即时反馈和渐进式难度提升。 • **商业模式批评**（xvilka）：强烈反对商业编译器模式，认为现代应该将编译器开源免费，仅IDE收费，或将APL集成到GCC/LLVM中。 • **实用性存疑**（UltraSane, Pay08）：质疑学习APL的投资回报率，以及APL对学习Matlab等非严格数组语言的帮助程度。 补充讨论：有人分享了学习资源（现代APL教程、PDF版本）和开发工具（Emacs的Dyalog APL模式），显示社区仍有活跃的学习者。
