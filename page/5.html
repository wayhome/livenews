Void: Open-source Cursor alternative

作者: sharjeelsayed | 评分: 850 | 评论数: 69 | 发布时间: 2025-05-08 16:35
文章摘要

Void是一个开源的代码编辑器，作为Cursor编辑器的替代品，支持在代码库上使用AI代理、可视化变更以及本地部署各种模型。Void直接向服务提供商发送消息，不保留用户数据。该项目是VSCode仓库的分支，包含完整的源代码，并提供贡献指南和社区支持。用户可以通过Discord参与每周会议，或通过邮件联系团队。项目遵循Apache-2.0许可证，并包含未知许可证的文件。主要技术栈包括TypeScript、CSS、JavaScript、Rust等。

Usenix ATC Announcement

作者: eatbitseveryday | 评分: 105 | 评论数: 7 | 发布时间: 2025-05-09 03:18
文章摘要

USENIX将于2025年庆祝成立50周年，并宣布其历史最悠久的年度技术会议（USENIX ATC）将在2025年7月后结束。自1975年成立以来，USENIX一直是高级计算系统社区创新者的重要聚集地。其年度会议在1995年合并为单一的年度技术会议（ATC），并持续了30年。然而，随着更多专注特定主题的USENIX会议加入日程，ATC的参会人数逐渐减少，无法维持必要的研究者和从业者群体。因此，USENIX董事会决定结束ATC。 ATC曾见证了许多行业“首次”，如1979年ONYX UNIX硬件、1983年Sendmail、1985年NFS等重要发布。然而，随着社区和技术的演变，其他会议如USENIX Security和FAST等逐渐吸引了更多关注。尽管ATC的结束是一个艰难的决定，但USENIX认识到变革的必然性，并感谢ATC对协会及社区的重大贡献。

评论摘要
主要讨论点：USENIX ATC（Annual Technical Conference）的现状及其在学术和工业界中的地位变化 不同观点： • [mjb] 认为，随着OSDI变为年度会议，NSDI接受更多广泛的系统研究，ATC陷入了一个困难的定位。然而，ATC仍然为一些“更具黑客性质”的系统工作、工业系统的论文以及不太量化的研究提供了有价值的平台。他希望OSDI以及SOSP和Eurosys等会议能接受更多类似的工作。他也提到自己曾在ATC获奖，并得到积极反馈，但该论文曾被另一个会议拒之门外。 • [aoki] 指出，尽管仍有大量研究论文提交至ATC，但社区已经演变，更多人选择参加其他会议。他提到ATC的参会人数从2000年的1,698人下降到2024年的165人，并认为ATC变成了一个“只写不读”的会议。 • [zinekeller] 关注ATC的资金问题，并提到2025年ATC的黄金赞助商是国家科学基金会。他讨论了近期白宫事件的影响，并质疑这是否是一个长期存在的问题。 • [throw0101c] 指出，尽管ATC不再如从前，USENIX仍有其他会议。他提供了一些相关链接。 • [jamesblonde] 认为ATC多年来是一个伟大的会议，但其参会人数下降是因为缺乏想象力。他建议可以像其他顶级系统会议一样，将会议地点移到美国和湾区之外。 • [ferfumarma] 简单表示，这篇文章记录了一个令人遗憾的里程碑。 补充讨论： • ATC的定位和价值受到其他会议变化的影响，如OSDI和NSDI。 • 有评论提到ATC参会人数下降的现象，并对其未来表示担忧。 • 有人质疑ATC的资金问题及其对会议的影响，并讨论了可能的外部因素。 • 有建议提出可以通过改变会议地点来提升ATC的吸引力和参与度。 争议焦点：ATC的当前价值和未来发展方向，包括其在学术和工业界的定位问题。

Fui: C library for interacting with the framebuffer in a TTY context

作者: Bhulapi | 评分: 151 | 评论数: 14 | 发布时间: 2025-05-08 22:05
文章摘要

`fui` 是一个用于帧缓冲区（framebuffer）的 C 语言库，能够在 tty 环境下进行图形界面操作。它支持： 1. 向多个图层绘制像素，然后合成并渲染到帧缓冲区。 2. 基本的图形绘制功能，如线、矩形和圆。 3. 使用位图字体进行文本渲染。 4. 利用 `libevdev` 处理键盘和鼠标事件，并实现了一个通用事件系统。 5. 使用 ALSA 实现简单的音频播放功能。 安装步骤包括运行 `make` 和 `sudo make install`，库是静态链接的。由于需要 root 权限访问视频和输入设备，建议将用户添加到 `video` 和 `input` 用户组。示例代码和简单的游戏（如 `asteroids`）包含在项目中。该项目使用 MIT 许可证。

评论摘要
主要讨论点：终端实验及相关技术概念 不同观点： • abnercoimbre对终端实验表示兴奋，认为该领域需要进化，并提到自己之前做过的类似实验，该实验引起了正反两极的反应，但他会继续关注类似项目，如"Fui"，并考虑其在未来Linux构建中的应用。 • RetroTechie建议这种终端实验最好在裸机环境下运行，或者使用小型实时操作系统，而不是依赖复杂的Linux驱动栈。 • antirez提到与该实验相关的不同抽象层技术，如Kitty图形协议和Ghostty终端模拟器。 补充讨论： • markisus询问"framebuffer"的概念，特别是它是否是Linux特有的全局桌面帧缓冲，引发了对操作系统图形处理的讨论。 • clbrmbr和yazantapuz回忆起早期的编程经历（QuickBasic、Pascal、MSDOS），并表达了对全屏图形编程的怀旧和困惑。 • kristianp询问"in a TTY"的具体含义，澄清其与终端窗口的不同。 • nimish提出将LVGL图形库移植到该项目中以实现完整GUI的可能性。 • cellis认为该项目小到足以让人全面理解，表示赞赏。 • actionfromafar关心项目的许可证问题。 • mouse_提供了一个使用framebuffer和dd命令的演示，展示如何在TTY中进行截图和随机图形显示，但同时也警告不要随意执行网上看到的命令，特别是涉及root权限时。 • anthk提到类似技术SVGAlib和libggi，将它们与FUI进行类比。 • speed_spread以幽默方式提到TempleOS，暗示对该类实验的兴趣。 争议焦点： • abnercoimbre的实验在社区中引起了50-50的正反评价，显示出对新终端实验的不同态度。

Robotics meets the culinary arts

文章摘要

瑞士和意大利团队合作研发了RoboCake，一种可食用的机器人婚礼蛋糕，展示了机器人食品研究的新进展。这是欧盟资助的RoboFood项目的一部分，由EPFL和意大利技术研究所（IIT）的研究人员与EHL的食品专家和糕点厨师合作完成。RoboCake上装饰着两个完全可食用的机器人泰迪熊，由EPFL的智能系统实验室（LIS）制作，材料包括明胶、糖浆和色素，通过内部气动系统实现运动。IIT研究人员还开发了首款可食用充电电池，由维生素B2、槲皮素、活性炭和巧克力制成，可为蛋糕上的LED蜡烛供电。这些创新不仅旨在创造新的烹饪体验，还试图减少电子废物和食物浪费，并探索在紧急营养和医疗领域的应用。该项目展示了食品与机器人技术结合的潜力，开启了互动和美味的烹饪体验。

Podfox: First Container-Aware Browser

作者: pierremenard | 评分: 106 | 评论数: 7 | 发布时间: 2025-05-08 22:19
文章摘要

文章介绍了作者因端口冲突问题，决定 abolish 容器端口转发，开发了一种让浏览器直接与容器通信的解决方案，即 "Podfox"。文章首先讨论了容器的普遍使用，尤其是在开发环境中的应用，如使用 Docker Compose 启动多个服务。作者遇到的问题是，两个项目都需要使用 RabbitMQ，导致端口冲突（EADDRINUSE）。 为解决此问题，作者设想并实现了一种 "容器感知浏览器"（Podfox），它无需修改端口即可直接访问容器的网络。具体实现并非修改浏览器本身，而是在后台运行一个简单进程，利用 Podman 的 rootless 网络功能。Podman 使用 slirp4netns 和 pasta 等工具实现 rootless 容器的网络通信，通过创建虚拟网络接口对（veth pair）连接容器与主机的网络命名空间。 最终，作者通过进入容器的网络命名空间，使浏览器能够直接访问容器服务，从而避免端口冲突问题。

评论摘要
主要讨论点：通过不同工具和方法管理SOCKS代理及反向代理的技巧，以及使用容器化技术（如Docker、Podman）的便利性。 不同观点： • [CGamesPlay] 提出可以使用Traefik作为反向代理，结合`lvh.me`（将所有子域解析到localhost）来实现类似SOCKS代理的功能，并提供了一个曾经的实现示例链接。 • [hobofan] 推荐使用FoxyProxy浏览器插件来管理SOCKS代理设置，并提到该工具适用于Firefox和Chrome，方便与同事共享配置。 • [jbverschoor] 表示直接使用Orbstack就能让一切正常工作，容器有独立的IP、DNS和HTTPS证书，简化了配置。 • [depingus] 对原帖内容表示赞赏，认为其中包含了许多对不可变操作系统用户有用的技巧。 • [amarshall] 反馈在iOS Safari上页面完全空白，暗示可能存在兼容性问题。 • [sureglymop] 关注于如何在无根模式的Podman中简单地通过SSH转发容器端口，询问是否有类似Docker中那样的一键解决方案。 • [sibilantcinder] 认为文中的代理功能应该成为Podman的内置特性，以增强其功能。 补充讨论： • 评论中涉及多种工具和方法的比较，如Traefik反向代理与SOCKS代理的对比，以及不同用户对工具简便性和功能性的需求。 • 争议焦点并不明显，但[amarshall]的反馈指出了一个潜在的页面显示问题，可能影响用户体验。 • 部分用户如[sureglymop]对无根模式容器管理中的特定功能有进一步需求，表明该领域可能存在功能不足或缺乏简便解决方案的问题。
