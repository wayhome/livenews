文章摘要

英国消费者权益组织Which?调查发现，Tripadvisor的AI评论摘要功能严重误导用户，掩盖了食物中毒、性骚扰和卫生问题等重大安全隐患。 调查显示，佛得角五星级Riu Palace酒店的AI摘要称其"一尘不染"，但实际有102条食物中毒投诉，412名游客发起集体诉讼，自2023年来已有7人死亡。其他案例中，墨西哥和多米尼加的酒店存在霉味、污水味、断水等问题，但AI摘要仍给出积极评价。 土耳其某酒店多名客人报告遭男性员工性骚扰，AI却将其轻描淡写为"服务失误"。Tripadvisor的AI助手Ollie在被直接询问时，也错误地称食物中毒"不太可能发生"。 Tripadvisor回应称正在调查相关案例，但承认该AI产品仍在开发中。

评论摘要
主要讨论点：TripAdvisor使用AI生成评论摘要引发的信任和安全问题 不同观点： • **法律责任担忧**：AI内容由TripAdvisor控制和生成，公司需承担内容责任，类似Google面临的问题 • **系统性偏见质疑**：怀疑TripAdvisor刻意配置AI偏向正面评价，批评其"让用户自己看原始评论"的回应是推卸责任，应从根本上修复系统 • **安全信息被掩盖**：当存在数百条正面评论时，AI摘要可能埋没关键的安全问题，用户盲目信任AI摘要存在风险 • **AI"有毒正面性"特征**：质疑所谓"摘要"实际上是AI生成的恭维话术，指出LLM天然倾向于产生过度正面的内容 • **透明度缺失**：LLM生成内容的不确定性未向用户展示，且公司普遍滥用AI功能 补充讨论：评论者普遍对企业强行植入AI功能持批评态度，认为这种做法优先考虑技术炫耀而非用户安全和信息准确性。

Pandoc Lua Filters

作者: ankitg12 | 评分: 110 | 评论数: 4 | 发布时间: 2026-07-03 09:52
文章摘要

Pandoc Lua 过滤器是一种用于操作 Pandoc 抽象语法树（AST）的机制。相比传统的 JSON 过滤器，Lua 过滤器具有显著优势： **核心特点：** - Pandoc 2.0+ 内置 Lua 5.4 解释器，无需外部依赖 - 直接处理 Pandoc 数据类型，避免 JSON 序列化开销 - 性能接近原生速度（基准测试显示几乎无额外开销） **工作原理：** Lua 过滤器是一个表结构，以元素名为键、处理函数为值。遍历文档时，匹配的元素会被传递给对应函数处理。函数可返回 nil（保持不变）、新对象（替换）或对象列表（替换/删除）。 **使用方式：** 通过 `--lua-filter=文件名.lua` 参数调用，可链式应用多个过滤器。

评论摘要
**主要讨论点：** Pandoc 工具的发展演变、Lua filters 的实用性与兼容性问题 **不同观点：** • **实用场景分化**（kalcode）：Lua filters 适合处理 Markdown 到 DOCX 的转换问题，但对于 PDF 生成，切换到 WeasyPrint 引擎后就不再需要 Lua filters • **工具膨胀担忧**（lifthrasiir）：认为 Pandoc 日益臃肿，十年前使用 Lua filters 的经验与现在文档完全不同，担心不同版本间的 Lua 脚本兼容性问题 • **功能演进澄清**（leephillips）：指出 Lua filters 并非新功能，真正的新进展是 Pandoc 支持在浏览器中运行，提供了详细文章链接说明当前状况 • **未来发展设想**（chaoxu）：提出响应式更新的可能性，希望实现从 Markdown 到 AST 的增量更新机制，考虑利用 LLM 技术来实现这一想法 **补充讨论：** 评论间没有明显对立，更多体现了不同用户群体的关注点差异——实践者关注工具选择、老用户关注兼容性、信息提供者补充背景、前瞻者探索新方向

文章摘要

这是一个将2003年经典RTS游戏《命令与征服：将军 零点时刻》移植到苹果设备（Mac、iPhone、iPad）的开源项目。该移植版本原生运行于Apple Silicon架构，无需模拟器，通过DXVK和MoltenVK将DirectX 8渲染转换为Metal图形API。 项目基于EA官方GPL v3源代码，在社区先前工作基础上实现了iOS/iPadOS移植，并为触屏设备设计了RTS专用操控方案（点选、框选、长按、双指滚动、缩放）。 移植过程克服了iOS只读文件系统、渲染管线转换、进程生命周期管理、触控输入适配等技术挑战。这是人类与AI（Claude Code）协作完成的项目，人类负责需求定义和测试，AI负责C++编程和交叉编译实现。 用户需自备游戏资源文件（可从Steam购买）。

评论摘要
主要讨论点：使用AI（声称是Fable）将《命令与征服：将军》移植到iOS/iPadOS的项目，但存在严重的标题误导争议 不同观点： • **标题严重误导派**（主流观点）：项目README明确说明macOS/Linux移植的"重活"已由fbraz3/GeneralsX完成，当前项目仅添加iOS/iPadOS支持。Fable只贡献了19/2000个提交，从macOS到iOS的移植工作量远小于从零开始的跨平台移植。甚至可能使用的是Opus而非Fable • **AI逆向工程乐观派**：认为LLM+Ghidra工作流正在revolutionize游戏逆向工程，未来10年将看到大量游戏被逆向。强调这是巨大的时间节省器，团队协作配合LLM可在数月内完成以往需要数年的工作 • **AI应用理性派**：承认这是AI的合理应用场景（低风险、可迭代、主要为乐趣），但批评AI生成文本的风格问题，并对比其他不负责任的AI应用案例（如Bun项目） • **技术质疑派**：对AI的实际能力持怀疑态度，认为任何decent LLM都能完成此类移植，Anthropic的声明存在频繁误导。实测发现Fable与GPT的表现不相上下 补充讨论：技术细节方面，有人对5层渲染API转换栈（DirectX→DXVK→Vulkan→MoltenVK→Metal）表示惊讶；有人注意到AI生成文本喜欢创造复合名词的语言特征
