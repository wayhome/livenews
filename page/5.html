这篇文章介绍了 `css-extras` 这个开源项目，它是一个基于 CSS 新特性 `@function` 规则的实用 CSS 自定义函数集合。主要内容包括： 1. **功能特点**：提供了约 50 个 CSS 自定义函数，涵盖数学运算、颜色操作、排版、布局、动画等多个类别，无需构建步骤，可直接复制使用。 2. **使用方法**：支持通过 npm 安装或直接链接 HTML 文件，并在 CSS 中调用函数，例如 `--fluid-type` 实现流体排版。 3. **浏览器支持**：目前仅 Chrome 141+ 支持，其他浏览器将逐步跟进。 4. **示例**：展示了响应式卡片组件、布局和主题感知组件的实现。 5. **许可证**：采用 MIT 和 CC0-1.0 双许可证。 该项目适合前端开发者简化 CSS 开发流程。

评论摘要
主要讨论点：[CSS新功能@function的优缺点及影响] 不同观点： • **支持观点**： - [spankalee] 认为CSS Modules的浏览器支持正在改善，可以通过JS模块导入CSS，提升开发效率。 - [chris_wot] 对负面评论表示困惑，认为新功能看起来不错，不理解为何被认为有害。 - [solaraQuill55] 提到CSS正在变得更强大，类似于JavaScript的演变。 • **反对观点**： - [rrgok] 批评CSS的变量命名约定（如双短划线前缀）丑陋，认为PHP相比之下更好。 - [christophilus] 对CSS的复杂性增加表示担忧，认为这会带来更多混乱，并批评Chrome在标准制定中的主导地位。 - [bilekas] 对新功能的长期影响表示怀疑，并质疑是否需要将其作为npm包发布。 • **中立或技术性讨论**： - [dmix] 指出新功能在Firefox和Safari中尚未支持，提供了技术限制的论据。 - [cluckindan] 建议使用预处理器来优化计算，避免客户端重复计算。 - [gampleman] 希望看到更多“杀手级”用例，而不仅仅是减少代码重复的小优化。 - [ape4] 和 [ulrischa] 以幽默方式讨论CSS的功能扩展，如“CSS是否图灵完备”或“是否能用CSS运行Doom”。 补充讨论： - **争议焦点**：新功能的实用性与复杂性之间的平衡，以及Chrome在推动标准中的角色。 - **技术限制**：浏览器兼容性（如Firefox和Safari不支持）是主要障碍。 - **未来展望**：部分用户期待更多创新用例，而另一些人则担心过度复杂化。
