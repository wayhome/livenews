文章摘要

backon 是一个现代化的 Python 重试库，零依赖、纯标准库实现。它提供四种 API 风格：装饰器（@on_exception、@on_predicate）、函数式（retry()）、上下文管理器（Retrying）和可调用对象（RetryingCaller），原生支持同步和异步代码。 核心特性包括：完整类型提示、全局开关控制、多种退避策略（指数、常量、斐波那契等）、抖动支持、丰富的回调机制（on_success、on_backoff、on_giveup等）。高级功能涵盖断路器模式、对冲请求、Prometheus/OpenTelemetry 指标集成、测试工具套件和 Trio 框架支持。支持运算符组合、迭代器 API 等灵活用法，是 backoff 库的现代化替代方案。要求 Python 3.10+。

It's not me, it's the compiler

文章摘要

这篇文章讲述了作者在重构 Rust 编写的 JavaScript 引擎解析器时遇到的一个神秘 bug。作者将一个带有条件分支的函数 `consume_test` 重构为更简洁的版本，使用 `x as u32` 进行类型转换来替代 if-else 分支。重构后，解析 for 循环语句时出现了错误。但当作者明确使用 `if x { 1 } else { 0 }` 替代 `x as u32` 时，代码又能正常工作了。 作者对此感到困惑，因为 `bool as u32` 应该是标准的类型转换方式。在排除了自己的代码问题后，作者怀疑这是一个罕见的编译器 bug。文章标题"It's not me, it's the compiler!"反映了程序员常说但通常是错误的抱怨，而这次作者相信自己遇到了真正的编译器问题。

评论摘要
主要讨论点：Rust编译器出现的严重错误编译（miscompile）bug及其影响 不同观点： • **优化策略争议**：norir认为编译器应该极度保守，死代码消除应仅在链接时优化阶段进行，优化建议应以警告形式呈现让程序员自行决定，而非静默执行可能出错的优化 • **bug严重性评估**：rtpg强调这是最危险的编译器bug类型（仅7个同时标记p-critical和i-miscompile），违反了程序员与语言的契约，破坏了安全代码的保证；bayesnet特别关注此bug容易在安全代码中触发 • **技术层面分析**：rtpg推测编译器优化本身极易出错，多数错误优化能在早期被发现才避免了更多问题；bayesnet对MIR优化管道这种应该严格审查的后期阶段出现问题表示意外 • **实用主义观点**：recursivedoubts认为原始的if语句代码虽长但更清晰易调试；多位开发者（bitwize、jackmott42）分享类似经历，表明编译器bug虽罕见但确实存在 补充讨论：评论中体现出对Rust编译器团队处理流程的好奇和对报告者勇气的肯定，同时有人分享了从"总是怀疑自己"到"确认编译器有bug"的心路历程

文章摘要

这是一个x86裸机RAM转储工具，可从USB启动并将系统内存直接写入启动介质。该工具最初用于冷启动攻击实验：通过将笔记本RAM冷冻至-60°C并快速重启，可在数据衰减前转储冻结的内存内容，提取加密密钥等敏感信息。 工作原理：使用两阶段引导，stage1加载stage2，后者通过BIOS中断查询内存映射，进入unreal模式访问1MB以上物理内存，以32KB块循环读取RAM并写入磁盘LBA 64扇区起始位置。 需要NASM编译，生成boot.bin后写入USB驱动器。**警告：会从扇区64开始覆盖数据，请使用专用空白U盘。**启动时需启用Legacy BIOS/CSM模式。
