Firefox 147将支持XDG基本目录规范，解决了一个存在21年的旧问题。该版本将遵循规范，将用户数据、配置文件等存储在Linux系统标准路径（如~/.config）中，而非默认的~/.mozilla目录。这一改动使Firefox更符合Linux应用惯例。该功能已在代码中合并，预计在147版本正式发布。

主要讨论点：[Mozilla Firefox 是否遵循 XDG Base Directory 规范，将配置文件从 ~/.mozilla 迁移到 ~/.config/mozilla] 不同观点： • **支持迁移并认可其重要性** - [darkamaul] 认为这是重要的一步，Firefox 的采用可能鼓励其他软件跟进 - [enriquto] 称赞这是减少主目录下点文件的举措，并推荐了 xdg-ninja 工具 - [ndegruchy] 认为 Linux 缺乏标准，遵循 XDG 是合理的进步 - [johnisgood] 强调所有软件都应遵循 XDG 规范 - [butz] 希望其他开发者能因此受到启发 • **对迁移细节的质疑** - [amiga386] 提出具体问题：是否支持旧目录迁移、是否强制要求 `MOZ_LEGACY_HOME`、是否区分 `~/.cache` 和 `~/.local/share` - [sam_lowry_] 担忧是否会像 Chrome 一样因 XDG 实现不当引发问题（如 `XDG_DESKTOP_DIR` 和 `XDG_DOWNLOAD_DIR` 冲突） • **其他相关讨论** - [PaulDavisThe1st] 调侃 XDG 配置路径的冗余性（如硬编码 `~/.config` 而非使用 `XDG_CONFIG_HOME`） - [andriamanitra] 肯定 Firefox 近期的改进（如 .mkv 支持），但指出硬编码快捷键仍是痛点 - [ksec] 询问 Firefox 是否还有其他长期未修复的 bug 补充讨论： - **争议焦点**：迁移是否彻底解决了 XDG 兼容性问题，以及是否可能引入新问题（如 Chrome 的目录冲突）。 - **历史背景**：该功能延迟了 21 年（[shevy-java]），原始 bug 报告可追溯至 2005 年（[phoronixrly]）。 - **社区影响**：Arch Wiki 等文档需要更新（[darkamaul]），用户对规范性软件的期待普遍较高（[enriquto]）。
