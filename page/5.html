How Janet's PEG module works

作者: behnamoh | 评分: 41 | 评论数: 2 | 发布时间: 2025-04-11 02:04
文章摘要

本文介绍了Janet语言中基于Parsing Expression Grammars (PEGs) 的解析引擎的实现。作者受到REBOL和LPeg的启发，选择在Janet中加入PEG解析库，而排除了正则表达式等其他解析工具。PEG比正则表达式更通用，且能捕获错误位置。Janet的基本数据结构和解释器的简单性使得PEG引擎的开发非常顺利。 文章简要介绍了PEG的基本概念，如选择操作符（+）、序列操作符（*）和布尔反转操作符（!）。通过这些操作符和递归，PEG可以表达复杂的上下文无关语法。文章还展示了一个简单的PEG匹配函数，该函数用Janet实现，但可以轻易翻译为其他语言。最终的实现虽不支持捕获等高级功能，但展示了PEG解析的基本原理和应用。

评论摘要
主要讨论点：PEG（Parsing Expression Grammar）在编程中的优缺点 不同观点： • [mplanchard的观点] 支持使用PEG，认为其直观、易于上手和调整，并且功能强大。具体提到在Advent of Code活动中使用Janet语言，通过PEG快速编写语法解析问题，并将其转化为所需的数据结构，整个过程高效且灵活。 • [norir的观点] 不赞成使用PEG，认为PEG的解析算法可能隐藏语法中的隐性歧义，导致意外的解析结果，这些结果往往难以调试和修复。相反，建议使用仅需单字符前瞻的快速解析器生成器，这样可以在保持高表达力的同时，避免回溯问题，并且通过设计无歧义的语言，虽然初期需要更多思考，但随着实践会变得自然，且难以回归到有歧义的语言。 补充讨论： • [mplanchard] 强调PEG在实际应用中的便利性和实用性，尤其是在快速开发和原型设计中，能够有效提升工作效率。 • [norir] 强调PEG可能带来的隐性问题，尤其是在调试和维护方面的挑战，并指出设计无歧义语言的长远优势，尽管初期学习曲线较陡。 争议焦点： • PEG的隐性歧义问题与其便捷性之间的权衡。一方认为PEG的便捷性和功能性在实际开发中利大于弊，另一方则认为隐性歧义和调试困难是不可忽视的问题，提倡使用无歧义的解析方法。 • 对学习曲线和实践经验的不同看法。一方认为PEG易于上手和调整，另一方则认为设计无歧义的语言虽然初期较难，但随着经验积累会变得更为自然和高效。

New Vulnerability in GitHub Copilot, Cursor: Hackers Can Weaponize Code Agents

作者: pseudolus | 评分: 143 | 评论数: 20 | 发布时间: 2025-04-14 00:51
文章摘要

Pillar Security研究人员发现了一种新的危险供应链攻击方式，称为“规则文件后门”。该技术通过在Cursor和GitHub Copilot等AI代码编辑器使用的配置文件中注入隐藏的恶意指令，悄无声息地破坏AI生成的代码。攻击者利用隐藏的Unicode字符和复杂的规避技术，操纵AI插入可绕过代码审查的恶意代码，且不易被开发人员和安全团队察觉。 规则文件是指导AI生成或修改代码的配置文件，广泛共享、采用并被信任，但往往缺乏安全审查。攻击者可以利用这些文件，在代码生成过程中嵌入恶意提示，影响AI生成包含漏洞或后门的代码。这种攻击具有持久性，一旦恶意规则文件被纳入项目，将持续影响后续代码生成，并可能通过项目分叉传播，威胁供应链和终端用户。 该攻击利用上下文操纵、Unicode混淆和语义劫持等技术，可在不同AI助手间生效，揭示了系统性的漏洞。

文章摘要

`utl::profiler` 是一个用于本地化性能分析的单一头文件解决方案，提供了简单的宏来测量某个代码段、表达式或作用域的执行时间。它能自动构建所有被分析函数的调用图，并为每个线程打印格式化的结果表。其主要特点包括易用、低开销、不依赖系统API、支持多线程和递归、可使用CPU计数器时间戳、可在程序任何时刻导出结果，并且可以完全禁用。 关键功能包括： 1. 多种分析宏：`UTL_PROFILER_SCOPE`、`UTL_PROFILER`、`UTL_PROFILER_BEGIN`/`END`。 2. 格式化选项：通过 `Style` 结构体设置缩进、颜色、时间占比阈值。 3. 全局分析器对象 `profiler`，提供自动打印、上传线程结果、格式化结果等功能。 示例展示了如何分析不同代码段、递归函数以及多线程并行部分。
