Show HN: Offline JavaScript PubSub between browser tabs

作者: l1am0 | 评分: 68 | 评论数: 13 | 发布时间: 2025-04-03 14:09
文章摘要

TabSub 是一个通过浏览器本地存储实现的跨标签页发布-订阅（PubSub）机制的 JavaScript 工具。它无需服务器，所有消息通过 localStorage 共享，仅在同域下有效。作者测试了 10 个并发写入，未出现消息丢失或顺序错误，但不能保证大规模并发安全，使用需自担风险。TabSub 提供了 `publish`、`subscribe` 和 `state` 等函数来发布消息、注册监听和获取主题当前状态。示例展示了如何同步多个标签页中的音频播放。TabSub 已在 GitHub 开源，采用 MIT 许可。

评论摘要
主要讨论点：对 `subscribe()` 实现的优化、跨浏览器通信方案、安全性问题以及不同技术选择的比较和应用 不同观点： • **对 `subscribe()` 实现效率的看法**： - [sltkr] 认为当前实现对多个主题（topic）不够优化，因为每个主题都会安装一个事件处理器，即使只有一个主题需要响应变化，所有主题的处理器都会被调用。他建议只安装一个处理器并根据主题分发事件。 - 提供的优化代码示例通过检查事件键的后缀来确定是否触发相关主题的回调。 • **跨浏览器通信方案**： - [Lerc] 提到在不同浏览器标签之间进行通信时遇到困难，最终使用 localStorage 作为信号机制来建立专用消息通道。但仍有一些连接问题未解决，比如不同时间加载的标签之间的消息拒绝问题。 - 建议对纯 localStorage 回退方案进行基准测试，但预计高流量时表现不佳。 • **其他技术选择的提及**： - [sisk] 指出 `BroadcastChannel` API 可能解决类似问题，提供了一种替代方案。 - [qudat] 分享了他们使用基于 SSH 的 PubSub 系统在生产环境中的经验。 • **对安全性的关注**： - [nottorp] 对使用 localStorage 是否存在安全漏洞表示担忧，尤其是在离线状态下不同站点的访问控制问题。 • **对代码简洁性和实用性的赞赏**： - [edweis] 对代码的简单性表示赞赏，并提供了相关代码库链接。 • **历史经验的分享**： - [EGreg] 提到十年前在他们的框架中实现了类似功能，但最终移除。他们的主要用途是缓存数据以避免每个标签都请求服务器，但最终由于架构变化而放弃。 补充讨论： • 对于使用 localStorage 作为通信手段的性能和扩展性存在争议，特别是在高流量和多标签场景下的表现。 • 对不同技术实现（如 `BroadcastChannel` API 和基于 SSH 的 PubSub 系统）的实际应用和优缺点进行了对比和分享。 • 安全性问题也是讨论的一个焦点，尤其是对 localStorage 使用中的跨站点访问控制问题。

Dijkstra On the foolishness of "natural language programming"

作者: nimbleplum40 | 评分: 134 | 评论数: 25 | 发布时间: 2025-04-03 03:30
文章摘要

文章讨论了“自然语言编程”的不可行性。作者认为，从早期计算开始，人们抱怨编程需要精确和严谨，希望机器能自动纠正错误指令。虽然高级编程语言和错误提示改善了部分问题，但机器仍会忠实执行无意义指令。有人提议用自然语言编程以简化操作，但这会增加机器的复杂性。作者质疑这种观点，指出历史上数学的发展得益于形式符号的使用，而非自然语言。希腊和穆斯林数学的停滞正是因为缺乏符号化，而西方数学的进步则归功于形式化符号。因此，形式符号实际上是一种有效工具，帮助排除错误和无意义的内容。自然语言的“自然性”反而使其易于产生无意义陈述。文章最后推测，若从一开始就用自然语言与计算机交互，计算机科学可能难以发展。

评论摘要

Multi-Token Attention

作者: fzliu | 评分: 86 | 评论数: 10 | 发布时间: 2025-04-02 22:20
文章摘要

本文提出了一种新的注意力机制——多 token 注意力（Multi-Token Attention, MTA），以解决传统注意力机制仅依赖单个查询和键 token 向量相似性的局限性。MTA 通过在查询、键和头之间应用卷积操作，使相邻的查询和键能够相互影响注意力权重，从而利用更丰富、更细致的信息来提升模型性能。实验表明，MTA 在多种基准测试中表现优异，尤其在需要处理长文本信息的任务中，优于传统的 Transformer 模型。

评论摘要
主要讨论点：Transformer架构的改进及其在处理大上下文大小音频数据分类问题中的应用 不同观点： • rakejake：尝试将MultiHeadAttention层引入到CNN中以替代GRU层，获得了比CNN-GRU混合模型更好的结果。虽然训练速度更快，但内存消耗较大。 • bionhoward：将该方法与Byte Latent Transformer (BLT) 进行比较，指出BLT在嵌入时使用注意力机制，而本文方法在嵌入后使用卷积。 • kouteiheika：指出该方法在实际应用中存在问题，尤其是对注意力机制的修改使其无法与Flash Attention等优化库兼容，且FlexAttention目前也存在较多bug。 • bigdict：质疑通过增加计算资源是否能真正提高性能，尤其是在每单位计算性能上的提升。 • bob1029：提出对注意力机制中查询和键的乘法增加可能会导致内存带宽瓶颈的问题。 • cgearhart：对引入局部窗口的必要性提出质疑，认为注意力机制原本就是为了解决长距离依赖问题，重新引入局部窗口似乎是倒退。 • curiousfiddler：质疑卷积方法是否能比多头注意力提取更多语义信息，并将其与CNN使用多种滤波器类比。 • fabmilo：认为应超越tokenization，认为当前在RL优化中的工作只是局部优化，呼吁更大突破。 • jwilber：支持卷积操作在LLM中的 comeback，提到最近使用conv-based hyena operator的striped hyena2架构的成功。 • antonkar：提出一种全球安全的AI解决方案，建议将GPU集中在云端由国际科学家控制，以防止AI被不当使用。 补充讨论： • 讨论焦点之一是新方法是否能真正提高性能，尤其是在计算资源增加的情况下。 • 另一个焦点是新方法在实际应用中的可行性，尤其是与现有优化库的兼容性问题。 • 对局部窗口和长距离依赖的处理也是讨论的重要方面，部分评论者认为局部窗口可能会削弱注意力机制的优势。 • 有评论者提出应从更高层次上改进AI架构，而不仅仅是在现有框架上进行局部优化。
