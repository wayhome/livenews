Evolution of Rust Compiler Errors

作者: ingve | 评分: 140 | 评论数: 17 | 发布时间: 2025-05-16 13:22
文章摘要

本文介绍了作者在参加RustWeek活动后，受到启发对Rust编译器错误信息演变进行的考古式研究。作者编写脚本下载了自1.0版本以来的所有稳定Rust版本，并通过包含错误的简单程序生成和收集各版本的错误信息。通过可视化工具，展示了错误信息在不同版本中的变化，如变量移动、字段错误、借用检查错误等。文章指出，Rust 1.0.0的错误报告已经相当可靠，后续版本不断改进，如Rust 1.2.0引入错误代码，Rust 1.26.0引入彩色错误信息及`rustc --explain `提示。尽管有些变化是微小的甚至反复的，但整体显示出错误信息质量的持续提升。文章强调，这些改进是数百名贡献者多年设计、实现、审查和测试的结果，展示了使错误信息变得优秀的努力过程。最后，作者提供了脚本链接，鼓励读者进一步测试和分享有趣的错误信息例子。

New 'Superdiffusion' Proof Probes the Mysterious Math of Turbulence

作者: rbanffy | 评分: 39 | 评论数: 6 | 发布时间: 2025-05-16 17:08
文章摘要

文章主要讨论了湍流这一复杂的流体动力学现象及其数学研究进展。湍流一直是科学界的未解难题，尽管流体流动的方程已有两百年历史，但当流动变得湍急时，这些方程无法准确描述流体的行为。湍流会产生不同尺度的漩涡，这些漩涡互相影响，使得预测流体粒子的运动变得极为困难。 文章提到1906年巴黎气球比赛中的气球被湍流吹散的事件，启发了科学家刘易斯·弗莱·理查森对湍流的研究。他发现湍流能高效地散布物体，并提出了一个至今仍未完全证明的普遍规律。 最近，三位数学家首次在一个简化的湍流模型中证明了“超扩散”现象，即粒子在湍流中分散的速度比预期快。这一发现被认为对湍流的数学研究具有重大意义，并可能推动相关数学技术的发展。

墨西哥拥有68种官方认可的土著语言，近700万人使用，包括玛雅语和纳瓦特尔语。然而，由于城市化、全球化以及西班牙语和英语的主导地位，许多土著语言正面临消亡的威胁。为保护这一丰富的语言遗产，墨西哥政府启动了土著语言课程和双语课程的计划。在尤卡坦州，约35,000名学生可以选择学习尤卡坦玛雅语。墨西哥城将有78所学校开设纳瓦特尔语课程。尽管资源有限和方言差异等挑战依然存在，学生和社区的热情日益增长，显示出土著语言在墨西哥身份认同中的持久价值。同时，土著语言还面临着历史遗留的歧视问题，保护这些语言不仅是保存词汇，更是维护土著人民的尊严和身份。

Show HN: SQL-tString a t-string SQL builder in Python

作者: pgjones | 评分: 77 | 评论数: 13 | 发布时间: 2025-05-16 12:48
文章摘要

SQL-tString 是一个用于构建 SQL 查询的 Python 库，类似于 f-string，但能防止 SQL 注入。它通过 `t-strings` 来插入变量，并将这些变量转换为 SQL 占位符，同时支持预定义的表和列名。使用 `sql_context` 可以限制允许的列和表名，防止注入攻击。如果变量设为 `Absent`，库会自动移除相关参数，适用于可选更新或条件语句。此外，还支持 `IsNull` 和 `IsNotNull` 来处理 SQL 中的 `NULL` 条件。默认使用 `qmark` 参数样式，但也支持其他如 `asyncpg` 样式。对于 Python 3.12 和 3.13，可通过 `locals()` 使用该库。该项目基于 MIT 许可证，目前有 43 个星标。

评论摘要
主要讨论点：T-strings 和动态 SQL 查询的实现与优化 不同观点： • [hombre_fatal] 认为这种方法比传统的通过 if-statement 构建 where 子句的方式更清晰，可以直接写出完整的 SQL 语句，并通过一些技巧移除可选的条件表达式，避免复杂的调试过程。 • [bvrmn] 作为 sqlbind 的作者，肯定了这种方法在处理动态查询时的创新性，特别是可以根据条件删除部分查询语句，但也指出在支持如 ClickHouse 这样的扩展 SQL 功能时可能存在困难。 • [schultzer] 关注实现细节，建议基于 BNF 语法构建词法分析器和解析器，并提供了相关的参考实现和测试工具。 • [caturopath] 解释了 `sql_context` 的使用，指出其依赖于先前定义的变量，并讨论了集合作为参数传递时的行为。 • [jitl] 对 SQL 重写和模板化的实现表示关注，特别是如何在复杂查询中安全地使用这些功能，同时提到在其他语言如 TypeScript 中类似的用法。 • [badmonster] 提出了如何组合较大的查询片段同时保持占位符的安全性，避免手动字符串拼接的问题。 • [ilyagr] 建议允许更复杂的表达式直接在 t-strings 中使用，类似于 Rust 的 `format!`。 • [bencyoung] 对 Absent 功能表示担忧，认为容易误删整个 where 子句，导致查询出错。 • [sirfz] 指出这种方法通过参数化查询增强了安全性，并可以为不同数据库客户端提供统一的接口。 • [owlstuffing] 强调编程语言应通过编译时类型安全来处理内联 SQL，并提到 Java 的 manifold 项目作为实现示例。 补充讨论： • [90s_dev] 对 t-strings 使用词法作用域进行占位符查找的设计表示不满，认为应通过显式传递字典来实现，以提高代码的可读性和安全性。 争议焦点： • 动态 SQL 查询中如何安全、有效地组合和重写查询语句，特别是 Absent 功能的使用及其潜在风险。 • t-strings 使用词法作用域进行占位符查找的设计是否合理。

Methodical Banality

文章摘要
