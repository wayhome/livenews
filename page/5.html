Using floating point numbers as hash keys (2017)

文章摘要

这篇文章探讨了浮点数作为哈希表键的问题。虽然理论上任何类型都可以作为哈希键，但浮点数存在精度问题，可能导致意外结果（如0.1+0.2≠0.3）。文章指出浮点数作为哈希键的主要挑战包括：近似相等的概念难以与哈希函数的精确性兼容；需要处理特殊值（如正负零、无穷大和NaN）；以及不同语言对浮点键的处理存在显著差异。作者建议避免使用浮点键，但在某些情况下（如无精度损失时）仍可使用。最后讨论了设计浮点哈希函数的基本要求，特别强调要正确处理特殊值（如+0/-0应映射相同哈希值，NaN的处理则更具挑战性）。

评论摘要
主要讨论点：[不同编程语言中浮点数的相等性比较和哈希处理] 不同观点： • Java处理方式： - 回忆Java中将基本类型float装箱为Float对象，使用其equals()和hashCode()方法 - 指出Float的hashCode()方法返回一个与浮点数字节1:1对应的整数值，除了NaN被规范化为一个标准形式 - 强调HashMap实现中没有针对Float的特殊处理代码 • JavaScript处理方式： - 介绍JavaScript的SameValueZero相等性定义 - 指出除了0和-0被视为相等外，其他值都是按位比较 - 举例说明Map中-0和0被视为相同键，NaN可以正确存储 - 表示不理解为何不使用能区分-0和0的Object.is(SameValue)比较 补充讨论： • 争议焦点：为什么JavaScript选择SameValueZero而不是SameValue作为默认比较方式 • 未解答的问题：C++中如何处理浮点数相等性和哈希（用户表示想自己研究） • 语言特性对比：展示了Java和JavaScript在处理这个问题的不同设计哲学
