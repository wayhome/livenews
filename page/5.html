1Password CLI Vulnerability (2023)

文章摘要

这篇文档披露了1Password CLI工具中的一个安全漏洞。作者于2023年10月通过BugCrowd进行了负责任的漏洞报告，并于2024年1月获准公开披露。该漏洞允许在用户解锁保险库后，任何从父进程派生的子进程都能保持活动会话访问权限，存在供应链攻击风险。作者提供了两个可能的攻击路径（IDE扩展和npm包管理），并附上了PoC证明代码，展示了恶意代码如何利用该漏洞窃取保险库数据。建议用户注意相关风险。

评论摘要
主要讨论点：[1Password CLI 的安全性问题和权限管理] 不同观点： • **安全性担忧** - [troad] 认为 CLI 访问权限过于宽泛，缺乏细粒度控制，违反了最小权限原则，尤其在供应链攻击频繁的背景下存在风险。 - [starburst] 强调密码管理器的核心是保护数据加密，即使代码被执行，也应限制明文数据的暴露范围，而非一次性解锁全部凭证。 • **漏洞的严重性争议** - [TheDong] 认为如果攻击者已获得用户级别的任意代码执行权限，其他安全措施（如 keylog 或二进制替换）同样会失效，因此 CLI 权限问题并非关键漏洞。 - [krater23] 支持类似观点，认为一旦机器被入侵，任何本地存储的密码都不安全，建议完全避免在机器上存储重要密码。 • **功能改进建议** - [starburst] 提出 CLI 应像 SSH Agent 一样按程序请求逐个授权，而非全局解锁。 - [oulipo2] 询问当前 `op` CLI 的默认行为是否仍存在此问题，暗示对现状的关注。 • **其他相关讨论** - [e40] 质疑漏洞披露时间过长（2年），可能影响修复效率。 - [woadwarrior01] 批评 1Password 的技术栈（Electron）导致性能问题，引发对产品整体质量的担忧。 补充讨论： - **社区反应**：[lucasqueiroz] 表示将禁用 CLI 集成，反映部分用户对安全问题的实际应对。 - **技术对比**：[hollow-moe] 将 CLI 权限问题类比为 `sudo` 的临时密码豁免，引发对权限模型的深入思考。 - **争议焦点**：是否 CLI 权限设计是真正的漏洞（如 [starburst] 强调的“最小暴露”），还是用户机器被入侵后的必然结果（如 [TheDong] 的“ airtight hatchway”理论）。
