Recreate famous water profiles using supermarket bottled water

作者: smugglerFlynn | 评分: 93 | 评论数: 16 | 发布时间: 2026-05-18 19:51
文章摘要

这是一个通过混合超市瓶装水来重现世界著名水质配方的服务。用户选择目标水质配方（如皮尔森啤酒用水、墨尔本咖啡用水、那不勒斯披萨用水等），系统会告知需要购买哪些超市瓶装水（通常只需2种），然后按指定比例混合即可使用。 涵盖五大应用场景： - **咖啡/茶**：伦敦、墨尔本、东京等地水质 - **烘焙**：蒙特利尔贝果、那不勒斯披萨、旧金山面包等 - **酿酒**：皮尔森、慕尼黑、都柏林等经典啤酒产地水质 - **水族**：非洲慈鲷、水草缸、观赏虾等专用水质 - **园艺**：食虫植物、兰花等 无需化学知识，简单混合即可获得专业级水质。

评论摘要
主要讨论点：关于一个水质配方网站的可信度、实用性和水质对饮品制作的影响 不同观点： • **数据准确性质疑**：amiga386指出爱丁堡水质数据错误，实际硬度仅为30 mg/L（软水），而网站显示332 mg/L（硬水），误差达10-20倍，质疑整个网站可信度 • **AI生成内容存疑**：fishtoaster和epgui认为内容明显由AI生成，缺乏科学依据，需要验证数学计算和声明 • **实用性争议**：goobatrooba认为发达国家应直接用自来水配合过滤器，瓶装水不如本地水源；fishtoaster指出5加仑瓶装水成本过高，家酿啤酒通常直接用自来水加添加剂 • **技术方法问题**：TrueSlacker0指出让气泡水静置脱气的方法无效，因碳酸会改变pH值（从7降至4），即使脱气后碳酸仍残留，建议用RO反渗透水重建水质 • **积极尝试者**：jaggederest分享自制矿泉水经验，mrten提到Khymos博客有计算添加盐类的Excel表格；LeoPanthera希望能复制斐济水的味道 补充讨论：部分用户（bsimpson、getcrunk）对水质差异的味觉敏感度表示好奇，另有人提到特定用途如披萨面团、啤酒burtonisation工艺等专业应用场景。

这篇文章讲述了作者开发的WASM运行时Epsilon被AI代理发现的安全漏洞。AI发现了20多个漏洞，多数是DoS攻击，但有几个是严重的沙箱逃逸漏洞，允许恶意WASM模块突破隔离访问其他模块的私有状态。 文章详细介绍了三个有趣的漏洞： 1. **零值非空漏洞**：Go的clear()函数将funcref局部变量初始化为0而非null(-1)，导致攻击者可调用存储索引0处的私有函数。 2. **幻影块参数漏洞**：验证器在处理带参数的block时错误地消耗了栈顶值，使得null funcref下方的i32常量0暴露出来，被误当作有效函数引用调用。 3. 第三个漏洞文章未完整展示。 这些漏洞源于运行时依赖验证器的类型检查，执行时funcref用int32表示，安全性完全依赖验证阶段的正确性。

评论摘要
主要讨论点：使用LLM（大语言模型）进行代码安全审计的效果和意义 不同观点： • **技术乐观派**（NitpickLawyer）：LLM可通过链式组合实现更好效果，类似GAN训练机制，通过"生成-验证-修复"循环不断改进，关键在于组合能力的解锁和迭代训练 • **质疑动机派**（rashar）：作者自称Google工程师，批评自己写的代码可能是为迎合AI热潮获得晋升，这是AI支持者的流行策略 • **实用主义派**（xeyownt, vachanmn123）：认可这是一个实用案例，展示了发现过程和可复现性；对Anthropic屏蔽安全相关提示感到意外，计划尝试中国模型 • **价值怀疑派**（keybored）：认为对业余项目发现20个bug不值得大惊小怪，应该关注广泛使用的项目才有讨论价值 补充讨论： • r0ze-at-hn建议将发现的问题贡献到官方WASM测试套件 • jcarrano从Go语言角度讨论了零值作为默认值的潜在问题 • shandilyaharsh对Anthropic的"Mythos"营销表示怀疑 • jedisct1推荐了Swival审计工具

Reviving old scanners with an in-browser Linux VM bridged to WebUSB over USB/IP

文章摘要

这篇文章介绍了 yes-we-scan.app 网页应用的开发背景和技术原理。作者为了让旧 USB 扫描仪重新可用，利用 v86 在浏览器中模拟 x86 机器运行 Alpine Linux 和 SANE 扫描软件。技术架构包括：用 C 程序连接扫描仪并传输数据，通过 USB/IP 将 USB 数据转为 TCP 包，用 tcpip.js 处理网络协议栈，最后通过 WebUSB API 连接实体 USB 设备。扫描数据实时压缩为 JPEG 或 PNG 格式。该应用理论上支持数百款扫描仪型号，目前仅在作者的 Canon 扫描仪上测试过。

评论摘要
主要讨论点：关于在浏览器中通过 WASM 模拟 Linux 来支持旧扫描仪的技术方案评价 不同观点： • **过度工程派**：认为在浏览器中运行完整的 WASM 模拟 Linux 内核过于复杂，SANE 本身已有原生跨平台前端，无需通过浏览器实现 • **技术赞赏派**：认为这是有趣的概念验证，展示了 Web 平台和 WebUSB 的能力，emulating Alpine Linux 是合理的轻量级方案 • **实用主义派**：指出已有成熟替代方案——Linux 上 SANE 开箱即用，macOS 可用 Homebrew 安装，或直接购买 VueScan 等商业软件 • **网络扫描方案派**：推荐使用 AirSane + 树莓派将扫描仪改造为网络设备，通过 AirPlay 协议集成到 macOS 补充讨论： • **开源合规争议**：ValdikSS 指出项目未按许可证要求开源之前的代码，可能包含其贡献的 CUPS/SANE 代码，涉及法律风险 • **技术可行性探讨**：有人质疑为何不直接将 SANE 编译到 WASM，或探索将 Linux USB 驱动单独移植到 WASM 的工作量 • **应用场景扩展**：有评论询问能否将此方案推广到其他旧设备的支持
