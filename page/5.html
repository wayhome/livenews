Some bits on malloc(0) in C being allowed to return NULL

作者: ingve | 评分: 41 | 评论数: 8 | 发布时间: 2025-06-25 06:15
文章摘要

文章指出，由于大量高流量的爬虫程序（特别是用于LLM训练的数据采集）使用旧版浏览器用户代理（尤其是Chrome），作者在其博客"Wandering Thoughts"和wiki "CSpace"中实施了反爬虫措施。如果用户使用被认为可疑的旧浏览器访问，可能会被阻止。若用户确实在使用当前浏览器版本却被误拦，可以联系作者提供浏览器信息以解决问题。特别提到，使用archive.*（如archive.today, archive.ph）的用户也会被误认为恶意爬虫，建议使用行为更规范的archive.org进行存档访问。

评论摘要
主要讨论点：malloc(0) 的行为及其合理性 不同观点： • [bobmcnamara] 支持 malloc(0) 返回 -1 并增加计数器，认为这有助于检测内存泄漏。这种实现方式通过 free(-1) 来减少计数器，从而追踪内存分配问题。 • [Lvl999Noob] 质疑为何需要多次分配大小为 0 的内存，并建议如果需要唯一地址，可以使用 malloc(1) 代替。同时认为 malloc(0) 应返回常量值如 NULL 或 -1。 • [randomNumber7] 认为分配 0 字节内存没有实际用例，且不关心返回的指针值，因为无法解引用。因此觉得 malloc(0) 应返回 NULL。 • [tptacek] 认为可以通过封装 malloc 来实现所需语义，例如返回 NULL 或某个哨兵指针，以解决标准复杂性问题。 • [AaronDinesh] 主张 malloc(0) 应始终返回 NULL，质疑返回有效指针的合理性。 • [a-dub] 对 0 页在不同系统中的处理方式感兴趣，暗示可能存在不同的行为。 • [eesmith] 提到曾在 AIX 系统上遇到 malloc(0) 返回 NULL 导致程序失败的问题，并通过总是分配 size+1 来解决。 补充讨论： • [carra] 对标题中使用 "some bits" 感到困惑，认为容易引起误解。 • 争议焦点在于 malloc(0) 的合理行为，包括是否应返回 NULL、有效指针或常量值，以及是否有必要支持多次分配大小为 0 的内存。

Shifts in diatom and dinoflagellate biomass in the North Atlantic over 6 decades

作者: PaulHoule | 评分: 58 | 评论数: 3 | 发布时间: 2025-06-26 17:36
文章摘要

这篇文章分析了连续浮游生物记录仪（CPR）的数据，重建了过去60年中北大西洋表层海洋硅藻和甲藻生物量的变化。研究发现：1）除东部和西部大陆架区域外，整个北大西洋的硅藻和甲藻生物量每年减少约2%；2）从1960年到2017年，除北极地区外，硅藻生物量相对于总生物量的比例每年增加1-2%。结果证实了水体变暖时硅藻被甲藻取代的普遍报道，但不支持逐渐海洋变暖会导致十年际尺度上硅藻向甲藻转变的假设。预测气候变化的影响可能需要考虑整个群落的变化、多重环境变量的同步变化以及浮游生物种群的进化潜力。

评论摘要
主要讨论点：海洋中浮游植物（如硅藻和甲藻）生物量的变化及其对生态系统和气候的影响 不同观点： • **[octaane]** 认为浮游植物生物量的减少是一个严重问题，尤其是在气候变化的背景下。他指出，硅藻和甲藻在全球的淡水和咸水水体中广泛存在，它们的减少不仅影响碳封存（它们死后壳体下沉并埋在海底），还会影响整个海洋食物链。他强调，许多海洋动物直接或间接依赖这些浮游植物，如果它们的数量大幅变化，将导致食物链上下层的物种难以适应。他还认为，除非采取重大措施应对气候变化，否则问题不会改善。 • **[thymine_dimer]** 没有详细讨论科学问题，只是表达了对浮游植物话题短暂出现在公众视野中的感慨。 • **[matthewmcg]** 提供了进一步的阅读建议，推荐了Helen Czerski的《The Blue Machine》一书，认为这本书对理解海洋问题（包括浮游植物的变化）提供了有价值的背景信息。 补充讨论： • 争议的焦点在于浮游植物数量变化对海洋生态系统的深远影响，尤其是对食物链和碳封存的影响。这不仅仅是单一的生态问题，还涉及到气候变化的广泛背景。 • **[octaane]** 特别提到，如果硅藻和甲藻的数量在不同区域发生变化，可能会导致海洋生态系统的碳转移和生物量传递发生变化，这将对全球海洋生态系统产生长期影响。 • **[matthewmcg]** 的评论提供了扩展阅读的建议，帮助有兴趣的读者深入了解相关问题。

A new pyramid-like shape always lands the same side up

文章摘要

数学家们发现并构建了一种特殊的四面体，这种形状总是会以同一面朝上稳定下来，证实了一个几十年来的猜想。传统的正四面体具有四个相同的三角形面，而这种新的四面体通过不均匀的重量分布，实现了单稳态特性，即无论怎样放置，它最终都会翻转到同一稳定的面。这一发现由布达佩斯科技经济大学的Gábor Domokos及其团队实现，他们成功制造出一个物理模型，验证了该理论。这种形状的制造需要极高的精度，其设计结合了轻质材料和重金属以实现精确的中心 of mass控制。这一成果解决了约翰·康威在1966年提出的一个未解问题。

Muvera: Making multi-vector retrieval as fast as single-vector search

作者: georgehill | 评分: 88 | 评论数: 5 | 发布时间: 2025-06-26 10:29
文章摘要

MUVERA是一种先进的检索算法，旨在将复杂的多向量检索问题简化为单向量最大内积搜索（MIPS），从而提高检索速度。传统的多向量模型（如ColBERT）使用多个向量表示每个数据点，通过Chamfer相似度计算更精确的检索结果，但这种方法计算量大、效率低。MUVERA通过构建固定维度编码（FDEs）将多向量检索转化为单向量问题，利用高效的MIPS算法进行初步候选筛选，再通过精确的多向量相似度重新排序。该方法在保持准确性的同时，大幅提升了检索效率。MUVERA的实现代码已在GitHub上开源。

评论摘要
主要讨论点：Muvera等多向量嵌入方法的优劣及其实现细节 不同观点： • trengrj：Muvera通过将多向量转换为单个固定维度向量，解决了多向量模型（如ColBERT）带来的高成本问题。Muvera不需要特定的索引结构或聚类假设，能实现更低的延迟，比PLAID方法更好。 • nighthawk454：虽然多向量比较在性能上具有挑战性，但完全转向单一向量会丢失一些信息。Muvera的方法通过随机分区和平均池化将多向量压缩为固定长度向量，这是一种折中方案。动态聚类可能更好，但会导致可变数量的嵌入。 • lawlessone：对神经嵌入的查询是否像传统SQL查询一样可靠，还是更模糊？嵌入查询的结果是否能像SQL查询一样明确返回所有符合条件的数据。 • dinobones：Muvera的方法相当于一个“嵌入的嵌入”，通过将多个嵌入压缩为一个来减少维度并提高性能。这表明多个嵌入可能有大量重叠信息，单个嵌入能代表它们说明额外嵌入的边际价值较低。 • bobosha：Muvera与生成嵌入的特征哈希（如从多到单的嵌入缩减）有何不同？是否可以使用UMAP等技术来减少到单个向量？ 补充讨论： • 讨论中提到了多向量模型在性能和成本上的挑战，Muvera作为解决方案被提出，但也有人质疑其信息保留和性能平衡的问题。 • 有人对嵌入查询的可靠性提出疑问，与传统查询的明确性进行对比。 • 不同技术如k-means风格聚类、特征哈希和UMAP等被提及，作为可能的替代或补充方案。 • 总体来看，讨论焦点在于如何在保留信息的同时，有效减少维度并提高性能。
